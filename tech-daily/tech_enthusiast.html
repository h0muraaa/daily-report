AI 代理之间怎么“聊天”？MCP、A2A、ACP 正在抢标准

故事引入：你让 AI 助理安排一次出差，它需要先查天气、再看日历、然后订票。如果每个 Agent 都在说自己的“方言”，结果就是互相听不懂，任务卡在半路。

原理解释：ByteByteGo 的解读把这三个协议做了分工：MCP 像 Agent 的“USB-C 接口”，让 AI 能调用外部工具和数据；A2A 是 Agent 与 Agent 之间的即时通讯协议；ACP 则更偏向交易层面，强调服务发现、报价和可信凭证。

实际应用：比如一个物流 Agent 可以通过 Xweather 的 MCP 接口获取实时天气风险，再通知另一个调度 Agent 改路线，整个过程不再需要人类手动写一堆 API 胶水。

未来展望：如果协议标准真能统一，未来可能出现“Agent 应用商店”——你的 AI 能自动发现、购买并使用其他 AI 服务，就像今天下载 App 一样简单。

来源：ByteByteGo Newsletter

AI 找漏洞像“开挂”，但真正难的是收尾

故事引入：过去安全研究员一个月找几十个漏洞就算高产，现在 Anthropic 用 AI 一次扫描就能报出几千个潜在问题。但新的烦恼来了：哪些是真 bug？哪些该优先修？怎么让上游开发者接受补丁？

原理解释：当前的工作流一般是：先做威胁模型，再用 LLM 扫描代码，匹配规则过滤，然后人工复核，最后提交补丁。AI 擅长“大海捞针”，但判断漏洞是否可利用、会不会误报，仍需要人类经验。

实际应用：普通开发者也可以借鉴这套思路，在本地用 LangChain、Ollama 等免费工具做自动化安全评估，既能减少 API 费用，也能让代码在上线前多一道防线。

未来展望：下一步可能是“AI 安全助手”自动修 bug 并提交 PR，但人类始终需要担任最后的审核员，决定什么值得信任、什么该被忽略。

科普小课堂

PDF 红涂：不是贴张黑条就安全

它是什么：红涂（Redaction）是指在分享 PDF 前，把敏感信息永久删除的处理方式。常见场景包括隐藏合同里的身份证号、发票里的账户信息、病历里的个人隐私等。

为什么重要：很多人以为用黑框框住文字就万事大吉，但如果只是把黑色矩形盖在原文上方，别人仍可能通过复制粘贴或解析底层数据看到被遮盖的内容。真正的红涂会生成一份新 PDF，把对应区域的文字和图像数据彻底移除。

怎么用：选择支持红涂的工具，框选敏感区域，确认“永久删除”，再导出为新文件。freeCodeCamp 的教程还展示了如何直接在浏览器里用 JavaScript 实现多区域、跨页的红涂。

未来趋势：结合 AI 后，红涂工具可能会自动识别“看起来像隐私信息”的区域并给出建议，让普通用户也能一键安全脱敏。

来源：freeCodeCamp
