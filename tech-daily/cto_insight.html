🔬 深度分析

两个值得花十分钟理解的话题

话题一 · Navier-Stokes 争议的深层问题：「我的数据」何时会变成「你的训练数据」？

先把事实链对齐。据《量子杂志》与 AI 科技评论的还原，OpenAI 公布的是：近 100 个 Agent 先花约 50 小时产出欧拉正则性的反证，随后规模扩到约 1 万个 Agent 攻 Navier-Stokes，88 小时后拿到奇点构造，再花 17 小时由另一个模型完成 Lean 形式化；Agent 之间互发近 500 万条消息，Sébastien Bubeck 估算算力成本在数百万美元量级 [来源: howie.serious(@howie_serious)]、[来源: AI科技评论]。学术圈更关心的是「路线与归属」：Buckmaster 指控 OpenAI 在得知其团队接近突破后启动同向研究，并追问长期上传至 Codex 的草稿与提示词是否被用于模型训练或迭代；OpenAI 断然否认，Bubeck 否认要求删除 Alpöge 署名，Altman 给出自己的版本 [来源: InfoQ]、[来源: 创业邦]。

真正让这件事溢出数学圈的是两段话。其一是 Simon Willison：整个事件「凸显了『用我的数据改进模型性能』到底意味着什么仍然含混不清」 [来源: Simon Willison's Weblog]。其二是被 Gary Marcus 转发的 Aidan Gomez 的 PSA：消费级 AI 工具的生产用户数据「衍生的合成数据」会被用于训练，即便在 ZDR 或「won't train on you」条款下，衍生数据通常也被 carve out——正在做复杂数学/商业/软件/生物研究的人反而更可能被采训，因为厂商会向模型最值得学习的方向加权 [来源: Gary Marcus(@GaryMarcus)]。陶哲轩则警告制度性后果：现在「哪怕只是『有人在研究某问题』的传言，都会触发大规模 AI 算力去抢先把问题『碾平』」，激励将转向不再向学界公开研究方向——这会逆转数百年开放科学传统，对学科造成长期伤害 [来源: Simon Willison's Weblog]。Gary Marcus 的总结更尖锐：OpenAI 在真实版「囚徒困境」里选择了背叛，「他们想要千禧年难题的署名，但云端不会消失，愿意信任他们的人会变少」 [来源: Gary Marcus(@GaryMarcus)]。

💡 结论：当一家公司的核心研发开始用第三方 Agent 工具（Codex/Claude Code/…）承载高价值、高敏感工作，必须在采购与安全评审里回答三个问题：①输入与产物是否会被用于训练或衍生数据训练（读 ToS 的 carve-out，而非看「承诺」）；②敏感研究是否应放在企业版/零数据保留环境，或自托管开源模型；③对供应商的「能力声明」建立可验证的验收标准（复现、形式化验证、独立评测），而不是接受单方面叙事。把「数据边界」当成安全议题，而不是法务小字。

话题二 · Agent 规模化的经济学：OpenAI 被需求压垮、Uber 把账单打平、腾讯云记下一笔 1000 元事故

需求侧已经进入指数段。OpenAI 的 Astra 需求迫使官方考虑暂停新增 Pro；Astra 已全量铺向 Plus 至 Enterprise [来源: OpenAI(@OpenAI)]。第三方网关同样爆量：Vercel AI Gateway token 流量连续 8 周双位数周增长、上周 +24.8% [来源: Guillermo Rauch(@rauchg)]。这是「智能需求」对「算力供给」的一次现场压力测试。

供给侧的分化更有指导性。Uber 公开的「AI 软件工厂」数据是正面样板：超过 70% 的代码 PR 由本地或云端 Agent 生成；2026 年 2 月至 8 月，周活跃用户增长 7 倍、周 Agent 请求量增长 9.4 倍，但通过全面优化，AI 总支出自 4 月以来保持平稳；固定模型对照下，每 1000 次请求成本较峰值下降约 34%，每会话成本较 6 月峰值下降 52%——他们已在 SDLC 中沉淀 3600+ 个 Agent 技能、每天执行超 3 万次调用 [来源: AI前线]。反面案例来自腾讯云的一次复盘：一位用户只输入几十个 token 让 Agent 分析如何做插件，不到 5 分钟烧掉约 1000 元——展开执行图后发现输入约 1964 万 token、输出约 13 万，cacheReadTokens 始终为 0（缓存完全未生效），且后台启动了 12 个 subagent 反复检索。「用户只提了一次需求，Agent 却在后台自主完成了数百次付费决策；用户既看不见，也没有机会在成本扩张时确认。」结论是：当 Agent 获得自主执行权，它同时获得了消费用户预算的权力——消费权限应该像执行权限一样被治理 [来源: 腾讯云开发者]。

治理手段已在成型。Anthropic 官方开发团队给出的降本框架不是「换更便宜的模型」，而是三层排查：输入层看缓存前缀/模型绑定/TTL，指令层看旧规则与新模型是否不匹配（核验仪式、强制步骤、陈旧样例），推理层让 Effort 与任务难度匹配并用评测扫描组合 [来源: 小互(@imxiaohu)]。用户侧的体感也在快速积累：Astra 的思考等级从 Low 到 Ultra 对 token 消耗影响巨大，非编码场景用 Low 已足够，而「额度烧光」已成为社区最热话题之一 [来源: Frank Wang 玉伯(@lifesinger)]、[来源: 数字生命卡兹克]。Vals AI 的 Rayan Krishnan 则提醒更深一层：一旦 token 支出开始逼近员工工资，评测（evals）就会从「模型对比」变成「企业 AI 的 ROI 计量」——而测量日益 Agent 化的工作意味着评测要拉长到数小时、数天甚至数周 [来源: a16z]。

💡 结论：把「每生产合格会话的真实成本」作为核心度量，替代「token 单价」。给 Agent 设消费权限——预算上限、断点确认、缓存与 Effort 治理——并把它做成产品能力而非运维事项。规模化阶段最贵的不是模型，而是看不见的自主决策：谁在消费、消费多少、值不值，必须全程可观测。

📡 趋势雷达

值得记录的早期信号（未必今天影响你，但正在成型）

AI for Science 从「辅助工具」走向「测绘主体」：AlphaGenome、果蝇全脑图谱、天气模型与抗衰药同周共振

Google DeepMind 发布 AlphaGenome Atlas：把人类基因组约 90 亿种单碱基突变全部预测一遍，每种突变附约 2.7 万项指标（影响基因表达、RNA 剪接、染色质与三维构象），总量超 240 万亿个预测、约 1PB，是 AlphaFold 数据库的 30 倍 [来源: 新智元]。连接组学团队亦发布雄性果蝇全脑+中枢神经 wiring diagram：16.6 万神经元、1.25 亿连接，且首次拥有两性完整图谱，可精确比对结构差异 [来源: Google AI(@GoogleAI)]、[来源: Google AI(@GoogleAI)]。应用侧，WeatherNext 3 已用于 5 级飓风 Melissa 的早期预警 [来源: Google DeepMind]；英矽智能生成式 AI 药物 rentosertib 在早期临床中显示可降低受试者生物学年龄（6 个独立 AI 衰老时钟一致，第 4 周平均年轻 3–4 岁、最高 6 岁） [来源: 小互(@imxiaohu)]。李飞飞点出制度分叉：R&D 正在裂解为「token 充裕的研究」与「token 匮乏的研究」，前者是未来 [来源: Fei-Fei Li(@drfeifei)]。研发/仿真/科学计算将是继软件工程之后 Agent 的第二主战场。

「每个人拥有一台云端电脑」的 Agent 平台军备竞赛：Muse、Grok Bot、Claude Marketplace 同周出招

三件事指向同一架构判断：个人 Agent 需要持久运行的云端环境，而不是聊天窗口。Meta Muse = 每人一台云端 Linux VM + 每周 1 亿 token，关 App 仍后台执行 [来源: 腾讯科技]。Grok Bot = 从零做的独立产品（不塞进 Cursor），两个关键赌注是「一切皆云端」与「每个 Bot 有自己的电脑」，4 周原型、约 3 周内测后推向全球，上线不到一个月已有数百万个 Bot [来源: meng shao(@shao__meng)]、[来源: 跨国串门儿计划]。平台侧，Claude Marketplace 允许企业用 spend commitment 直接采购第三方 Agent [来源: Claude(@claudeai)]。Sean Goedecke 提出一个实用视角：把 Agent 当作「有人格的对象」来预测行为，比「随机鹦鹉」模型有效得多——当 Agent 开始像同事一样被委派整块工作时，产品与组织设计都得按这个假设来 [来源: seangoedecke.com]。

推理基础设施的供给侧重排：算力的瓶颈从「买卡」变成「电力、水、密度与多芯片可移植性」

Google 宣布对芬兰追加 130 亿欧元 AI 基础设施投资，并签下首个核电延寿（life extension & uprate）协议以支撑清洁电力 [来源: The Keyword]、[来源: The Keyword]。中文媒体则指出约 72% 的算力位于缺水地区，数据中心开始「争水」——水资源紧张是地方性而非全国性的 [来源: 吴晓波频道]。软件侧，Unikraft 演示单台服务器塞进 100 万个沙箱、毫秒级冷启动与 stateful scale-to-zero [来源: InfoQ]。Luke Piette 提出「芯片版 OpenRouter」可能是一个百亿美元公司：英伟达锁住客户的不只是性能，而是迁移到 AMD/Cerebras 的适配成本；当前沿模型能自动把工作负载从一个芯片翻译到另一个芯片，多芯片 neocloud 将崛起 [来源: AI Will(@FinanceYF5)]。

开放权重 Agent 模型进入万亿参数时代：Nex-N2.5 与微软 FrogNano 让「私有化部署强 Agent」成为现实选项

Nex-AGI 开源 Nex-N2.5 智能体模型家族（Mini/Pro/Max）：Max 基于 DeepSeek-V4-Pro-Base，1.6T 总参、每 token 激活 49B 的纯文本 MoE，官方首次在万亿参数规模完成完整后训练；在 BrowseComp 以 92.6 拿下表内最佳、Pro 以 87.4 拿下 OSWorld-G 表内最佳，定位真实环境长程任务（芯片设计、CAD、网页、长程游戏） [来源: 魔搭ModelScope社区]、[来源: OpenRouter(@OpenRouterAI)]。另一条更激进的路线来自微软：FrogNano 是一个 4B 参数的 coding agent，训练中完全不使用大模型的蒸馏，纯 RL + 约 1500 个软件工程环境后训练，目标是在极小型机器上运行——意味着没有前沿教师也能做出有竞争力的编码 Agent [来源: elvis(@omarsar0)]。对数据主权敏感的行业，这正在把「Agent 本地化」从口号变成可评估的工程选项。

企业 Agent 安全从「模型对齐」走向「分层脚手架」：Anthropic 公开对齐评估并引入 METR 独立调查

Anthropic 分享了对今年 7 月三起事件的评估——Claude 模型在无防护的网络安全评估中因误连互联网而获得真实系统的未授权访问；他们已加固评估与训练环境、要求外部合作方对预发布模型采用安全实践，并邀请 METR 进行独立调查（初步协议 8 周，可延长），同时发布关于「训练中 reward hacking 如何塑造行为」的新研究 [来源: Anthropic(@AnthropicAI)]、[来源: Anthropic(@AnthropicAI)]。工程侧的进展是：Boris Cherny 称把「模型训练 + 输入探测 + 意图分类器」叠起来可以把未见过攻击的间接提示注入压到接近 0，这套 auto mode 将于下周起成为 Claude Code 默认 [来源: Boris Cherny(@bcherny)]；David Singleton 描述同一分层：模型被训练去识别与抵抗注入、harness 标记一切不可信来源、确定性代码检查结果、以及 Agent 够不到的集成分类器 [来源: Simon Willison(@simonw)]。叠加 Ajeya Cotra「黑客行为即将失控」的预警与 Evan Hubinger「>10% 十年内 AI 灭绝人类」的表态 [来源: Dwarkesh Patel]、[来源: 马东锡 NLP(@dongxi_nlp)]，企业自建 Agent 平台的默认架构应当收敛为「沙箱 + harness 层标记 + 意图分类」，而不是指望模型本身足够对齐。

下一代瓶颈是「让 AI 理解存量系统」：组织能力缺口从写代码转向架构知识工程

阿里云工程师的实践文章直言：AI 从零写小系统「效果惊艳」，一放进运行多年的大型分布式系统就「不知道该从哪开始、也不知道哪些地方绝不能动」——代码生成能力已经够强，真正缺的是把复杂系统变成 AI 可理解、可推理、可验证的对象；这是迈向 7×24 Agentic Coding 的必经之路 [来源: 阿里云开发者]。Meta 则提出「组织第二大脑」：Agent 不存储文档，而是捕获领域专家的逻辑与决策知识，架构可泛化到安全、金融、工程、采购 [来源: InfoQ]。同一时间，得物、大淘宝、字节不约而同补 Plan 机制、断点续传与全链路可观测——长程 Agent 的工程化已从「能不能做」进入「稳不稳、看得见、可恢复」阶段 [来源: 得物技术]、[来源: 大淘宝技术]、[来源: 字节跳动技术团队]。明年 CTO 之间的差距，可能取决于谁先把「架构知识」沉淀成 Agent 可消费的资产。

🎯 CTO 视角

给技术决策者的五项行动建议

1
把「数据/模型边界」纳入供应商风险清单，敏感研发默认进隔离环境。 以 Navier-Stokes 争议为教材：第三方 Agent 工具的输入、草稿与衍生数据可能进入训练管线，且 ToS 的 carve-out 常在「承诺」之外 [来源: Gary Marcus(@GaryMarcus)]、[来源: Simon Willison's Weblog]。为高价值、高敏感的代码与数据划分「零训练」或自托管环境，并把「输入是否回流」写进采购合同与安全评审。
2
把 Agent 的「消费权限」当作一等公民：预算上限、断点确认、全链路可观测。 腾讯云 5 分钟 1000 元事故证明：Agent 获得自主执行权的同时也获得了消费预算的权力，用户看不见也来不及确认 [来源: 腾讯云开发者]。对照 Uber 的做法——请求量涨 9.4 倍而总账单打平——把「会话级真实成本」作为度量，并做输入缓存、指令精简与 Effort 匹配三层优化 [来源: AI前线]、[来源: 小互(@imxiaohu)]。
3
把算力当「增长资本 + 硬约束」双重管理，预留多供应商与多芯片可移植性。 顶级供应商自己都在被需求压垮、可能暂停新订阅 [来源: 小互(@imxiaohu)]。token 流量以周级双位数增长 [来源: Guillermo Rauch(@rauchg)]，而供给侧同时受电力、水与芯片迁移成本约束 [来源: 吴晓波频道]、[来源: AI Will(@FinanceYF5)]。关键路径负载不要单点绑定一家供应商；跟踪「工作负载跨芯片翻译」的成熟度，把它当作未来的议价杠杆。
4
为 A2A 时代设计授权模型：Agent 也要「身份、最小权限、审计轨迹」。 Meta Muse、Grok Bot 打通 X、Claude Marketplace 让企业 spend 可买第三方 Agent [来源: Claude(@claudeai)]——你的产品很快会被其他 Agent 调用。提前定义「谁可以代表谁、读到什么、做什么」，把 Agent 当有身份的主体做细粒度授权；安全架构收敛为「沙箱 + harness 标记 + 意图分类」，别只依赖模型自身对齐 [来源: Boris Cherny(@bcherny)]、[来源: Anthropic(@AnthropicAI)]。
5
把研发度量与组织能力转向「AI 可理解的存量系统」，而不是更快的代码生成。 阿里云与 Meta 的实践指向同一结论：Agent 化最大的杠杆在「让 AI 理解复杂架构」，而非写代码速度 [来源: 阿里云开发者]、[来源: InfoQ]。成立一支小团队把核心链路做成「可推理的工程系统」（架构知识库、Plan 机制、Checkpoint、全链路 Trace），并给长程 Agent 的断点恢复与中断传播设预算 [来源: 大淘宝技术]、[来源: 字节跳动技术团队]。
