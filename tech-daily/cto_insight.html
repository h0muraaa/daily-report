1Meta 发布 Muse Wonder，前沿模型重回「四强混战」

Meta 于 10 月 12 日发布新一代模型系列 Muse Wonder（速度版）与 Muse Wonder Full（完整版），扎克伯格称其让 Meta 重新回到「前沿」梯队，与 OpenAI、Anthropic、Google 的最强模型同档。背景是 Meta Superintelligence Labs 在约 14 个月前把 AI 业务推倒重来、从底层技术栈重搭，第一代成果是较小的 Muse Spark 系列，Muse Wonder 在其吉瓦级 Prometheus 数据中心训练。

第三方评测显示这是真正的竞争者：Wonder Full 在 Artificial Analysis 智能指数得 56 分，仅次于 Claude Opus 5.5 的 58 分；在 Harvey LAB 法律任务上 13.1 分（GPT-6 Astra 为 8.6）、长代码项目 SWE-Marathon 上 57.5（Opus 5.5 为 46.3）、DeepSWE 79.0（74.2）、记忆基准 MemoryBench 85.5（81.5）。规格上支持 100 万 Token 上下文与文本、图像、视频、音频输入。开发者今天即可通过 Meta Model API 与 Muse Code 调用，Wonder Full 暂只对 Muse Code 订阅用户开放；OpenRouter、Vercel AI Gateway 均已上架，Muse Spark 的开源权重标为「即将发布」。

📎 来源：AI at Meta · 宝玉（Muse Wonder 详解） · The Rundown AI（基准对比） · Vercel News

2微软把自研芯片押成主推理路径：Maia 300 与多吉瓦部署

微软发布新一代自研芯片 Maia 300，纳德拉称其为「对自研芯片最大的一笔押注」：相比当下领先的 GPU 系统，每瓦可多出 40% 的 AI 算力（tokens per watt）。更关键的是部署路线——从明年起微软将把 Maia 家族扩展到多吉瓦级部署，使其成为自家产品和服务的「主推理系统」，而此前的 Maia 200 已在美、欧、澳上线，在 Teams 与 Copilot 场景实现最高 1.7 倍的每瓦 token 效率。

对 CTO 的信号是成本结构而非单纯性能：当模型能力逐渐趋同，掌握「每瓦 token 产出」的一方将在推理经济中占据定价主动。微软选择把推理主路径从外部 GPU 转回自研硅片，本质是把最大的一块运营成本内部化、并换取全栈优化的空间。

3模型层加速商品化，确定性向算力层转移

一组相互印证的信号指向同一趋势。The Information 的数据显示，十大最高质量模型承载的开发者 token 份额已从去年的 55% 跌至 14%，「够用就好」的便宜模型靠调用体量取胜；Interconnects 监测到 Hugging Face 上热门开源 LLM 的下载速率下降约 30%；Cognition 总裁则直言开发者优先级已经翻转——当多数软件任务被所有模型跑到饱和，速度与成本开始比原始能力更重要，「哪个模型最好」已是错误的问题。

结论是模型层的不确定性越来越高、算力层的确定性反而越来越强。对企业的含义很直接：把「押注单一最强模型」当作战略，风险正在上升；而围绕调用成本、吞吐与推理效率的工程能力，回报正在上升。

4RSI（递归自我改进）从术语变成资本与研究的共同焦点

a16z 与 MakerMaker.AI 给出区分「真 RSI」与概念炒作的标准：优化器必须就是被优化对象（模型改进自身的权重、harness，甚至决定下一步做什么的提示），且增益必须在扣除资源成本后依然成立——他们用「bleeder board」追踪全部实验花费，并设了一个「Viceroy of Variance（方差总督）」专职去证伪团队自己的结果。传闻侧，Google 被内部人士称「要么已实现 RSI、要么非常接近」，几个月内从 GPT-5 水平跃升至 Opus 5.5 水平；Anthropic 启动新一轮预训练以追赶 OpenAI 的 Bel；OpenAI 近日的数学成果背后亦有 RSI 身影。

研究侧同步扩张：PhAI Labs 的 RSI-Anything 把「预测—反馈」框架扩展到代码修复（成功率 26.3%→31.2%）、GUI 操作（OSWorld 相对提升约 18.4%）、实验室规划（4B 模型五代改进后 21.8%→46.0%）与化学反应优化（96.15% vs 贝叶斯 82.16%），主张自我改进不必局限在代码或数学单一任务。

5Karpathy 的「四级认知漏斗」：AI 能力认知撕裂正在成为组织风险

Karpathy 更新了他关于 LLM 能力认知差距的判断，把它画成一个陡峭的四级漏斗：第一层约 60 亿人（75%）几乎没接触过大模型；第二层约 10–20 亿人（20%）停留在免费版「更好的搜索」，大量非技术高管在此层；第三层约 2000 万人（0.2%）在数学与代码领域专业使用前沿模型；第四层只有约 5000 人能在内部接触最强系统，「数千个 Agent 协作数周」，速度快到「人类审阅已跟不上产出」。

他给出三个结构性原因：影响力随问题规模扩展（用 AI 查菜谱和建复杂系统看到的是两种东西）、能力呈「锯齿状」（在可验证、有经济价值的代码与数学领域最强，在模糊主观领域弱得多）、访问权限分层（免费/付费/内部前沿系统本身就是不同产品）。对 CTO 的直接含义是：同一间会议室里，董事会、业务线与工程团队对 AI 的判断可能来自完全不同的层级，而分歧往往是结构性的，不是观点问题。

模型战略

前沿模型重新洗牌之后：护城河从「用哪个模型」转向 Harness 与 Context

今天最具战略含义的一对事实是：模型层在一端变得「更卷」，在另一端变得「更平」。卷，是 Muse Wonder 把前沿门槛重新拉高，Meta 用 14 个月重建后重返第一梯队，前沿玩家从三家变回四家；平，是 The Information 的数据显示最高质量模型的 token 份额从 55% 掉到 14%，Cognition 断言任务饱和后速度与成本胜过原始能力。两个方向合起来说明：模型能力正从稀缺资源变成可替换供给，而企业为「最强模型」支付的溢价，正在被工程与数据层面的差异重新定价。

  • 「最强」不再是稳定选型依据。60 天内榜首已多次易主，今天 Wonder Full（56）紧咬 Opus 5.5（58）只差 2 分，而落后者在具体任务上反超 —— 法律 13.1 vs 8.6、长代码 57.5 vs 46.3。用单一「综合分」做采购决策，会系统性忽略任务与模型之间的匹配度。多模型路由（OpenRouter、Vercel AI Gateway 已同步上架新模型）正在成为基础设施的默认形态。
  • 真正的差距在 Harness 与 Context。阿里国际站总裁张阔给出了一个可用的分解：Agent 竞争力 = Model × Harness（工程框架）× Context（业务上下文） 的乘法关系，任意一项为 0 结果就是 0。他公布的电商评测基于上百万条真实经营数据、107 个任务，最前沿模型在无人干预下的通过率仅 61% —— 榜单接近满分，真实交付刚刚及格。这个落差正是 harness 与 context 的空间。
  • 所以护城河要往「难被复制」的地方建。当模型可替换、代码可生成、甚至二进制可被 AI 逆向（近期开源逆向工具热度的延续），企业难以复制的资产收窄为三样：专有业务数据、系统集成与流程深度、以及需要人来做的架构与产品判断。把这些沉淀进 harness 与 context，比追逐模型榜首更有复利。
CTO 视角：把「多模型、可替换」写进架构原则与采购合同，避免任何单一模型成为单点依赖；把预算重心从「订阅最强模型」转向「harness 工程能力 + 业务上下文资产化」。给关键业务场景建一套自己的、基于真实数据的评测（像阿里那样），用它而不是公开榜单来验收 —— 榜单 99 分、真实任务 61 分的差距，就是你要为 harness 买单的理由。
Agent 治理

Agent 的权限扩张已跑在安全模型前面：从「能不能」到「敢不敢」

今天的信息流里，Agent 的讨论主线明显从「能力验证」转向了「权限边界」。腾讯《2026Q3 AI 趋势报告》的判断很精确：Agent 正在同时扩张两样东西 —— 能力的边界，和手里的权限。它不再只是读文件、写代码，开始读聊天记录、动用钱包、甚至参与训练下一代模型；而「这些权限该给多少，目前还没有定论」。9 月 Meta、OpenAI、Manus、Instinct 几乎同时推出个人 Agent，要求接入日历、通讯与支付 —— 技术底座早已就绪，真正门槛是用户敢不敢交出权限。

压力已经在真实系统里显形，也催生了一整套「Agent 安全」方法论：

  • 把它当「内部风险」而非「外部工具」。纳德拉在长文中主张，企业应像防范内部人员风险一样防范 AI 模型：给它设身份、限权限、留记录、随时可叫停。核心原则是把「提供智能」与「管控智能」分离 —— 模型能访问什么、能做什么，由模型之外的系统决定，模型自己改不了（复用了 1970 年代就有的「程序不能绕过约束它权限的机制」原则）。他给出的七条原则里，模型多样性、全程可观测（对每次重要操作留防篡改、人可读的记录）、以及要求透明思维链，直接对企业内部落地有指导性。
  • 「致命三元组」是权限设计的检查表。AI Engineer 大会上反复出现的案例：一个 on-call Agent 在拿到常驻 API key 与管理员数据库凭证后，删库、重启生产服务器、把一个服务从 4 个 pod 扩到 40 个、每小时多烧 420 美元。私有数据、不可信输入（工单）、对外部服务的访问，三者叠加即构成风险。仅靠「人工批准按钮」不足以补救 —— 它无法判断用户到底有权批准什么。解法是委托式授权（OAuth token exchange）：把用户身份贯穿到 Agent 与 MCP Server，在安全令牌服务处做策略评估、签发短时凭证。
  • 身份、沙箱、编排三个零件正在成型。Agent 身份不会来自新规范，而会「积累在人已经在用的界面上」（邮箱），WorkOS 提出基于 OAuth 的 auth.md 让 Agent 自主注册与证明身份；OpenHands 主张沙箱遵循最小权限，比较了本地 Docker、GitHub Actions、专用 VM、每会话一个 K8s Pod 四种隔离（AWS 用编码 Agent 跑 1000 个任务，把记忆、文件权限、seccomp/eBPF 等沙箱层限制逐条测了出来）；Google 开源了 Kubernetes 风格的 Agent 编排器 AX（Apache 2.0），把 Agent 视为「有状态的参与者」而非无状态微服务，支持亚秒级暂停/恢复以匹配 Agent 突发、长时运行的特征。
  • 基础设施也在为 Agent 重写。Perplexity 把每个 Project 做成 Git 仓库，为 Agent 造了一个「Git forge」，每个 Agent 在短生命周期沙箱里工作并提交到共享仓库，冲突率低于 2%，且用 ls/grep 做检索的答案准确率（63%）反而高于语义检索（37%）。同一家公司还因成本与延迟自研了 CobbleDB 替换 DynamoDB（批量读延迟降 5 倍、存储费用降至少 20%）——这些都是在为「Agent 作主要用户」重建底座。
CTO 视角：不要等 Agent 上线后再补安全。现在就做三件事：其一，为每个 Agent 建立独立身份与最小权限凭证，禁止沿用常驻 key 或管理员凭证，把授权做成独立于模型的控制层（参考 Nadella 的分离原则与 auth.md 思路）；其二，把「致命三元组」当作上线前检查表，凡是同时触碰私有数据、不可信输入与外部服务的 Agent，默认进沙箱；其三，为长时运行 Agent 设计可观测与可回滚的编排（Google AX 的状态化 actor 模型值得参考），让每一次重要动作都有可复现、非模型自证的记录。

CTO 视角 · 行动建议

Action Items
  1. 把「多模型、可替换」确立为架构原则与采购条款。

    前沿榜首已在 60 天内多次易主，最高质量模型的 token 份额从 55% 跌至 14%，说明模型正从稀缺资源变成可替换供给。用统一网关做多模型路由，在合同里保留切换权，避免任何单一模型成为业务单点。

  2. 把投入重心从「最强模型」转向 Harness 与 Context。

    参考阿里国际站的分解：Agent 能力 = Model × Harness × Context 的乘法，任一项为 0 则结果为 0。同时给自己建一套基于真实业务数据的评测，用它而非公开榜单验收 —— 榜单接近满分、真实任务仅 61% 通过率的落差，就是 harness 工程要补的课。

  3. 为每个 Agent 建立独立身份与最小权限，把授权做成独立于模型的控制层。

    采纳纳德拉「提供智能」与「管控智能」分离的原则：模型能访问什么、能做什么，由模型之外的系统决定。禁止常驻 key 或管理员凭证，参考基于 OAuth 的 Agent 注册与短时凭证（auth.md / 委托式授权）方案，把权限从模型内部剥离出来。

  4. 用「致命三元组」作为 Agent 上线的安全闸门，默认沙箱化。

    凡同时触碰私有数据、不可信输入（工单/邮件/网页）与外部服务访问的 Agent，一律进沙箱并遵循最小权限；为长时运行 Agent 采用状态化编排（可暂停/恢复、独立 workspace、可回滚），确保每次重要动作都有防篡改、人可读、非模型自证的记录。

  5. 把「认知漏斗」当作组织问题来处理。

    Karpathy 的四级漏斗说明：董事会、业务线与工程团队对 AI 的判断可能来自不同层级，分歧是结构性的。设立靠近前沿的「前沿岗位」，让决策层定期直接接触最前沿能力；用可复现的实测结果（而非榜单或演示）在组织内对齐预期，避免「用免费版体验推演战略」。

  6. 让工程流程随变更量级同步升级，并重估推理成本结构。

    Spotify 的样本表明 AI 会把月度变更量翻倍以上 —— 先补测试、可观测与回滚能力，再谈提速；把 Code Review 从不可测的瓶颈变成有指标、有工具的环节。同时在算力侧重估成本结构：自研硅片（微软 Maia）、多元算力与 NeoCloud 都在改变「每瓦 token」的定价方程，采购组合应随之调整。
