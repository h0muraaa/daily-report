安全 · 风险

AI 挖出的漏洞，第一次让多国政府在同一天关站

OpenAI「Patch the Planet」项目的安全研究员 Ryan Austin（Calif）在 8 月用 GPT-5.6 Sol 发现 PHP2Shell；Wiz 团队则用 Gemini 4 Argon、GPT-5.6 Sol 与自研 Atlas 独立发现同一组漏洞。两个漏洞的 CVSS 均为 9.2，影响 PHP 5.4 以来的版本，而约 69.4% 的网站后端使用 PHP。补丁信息提前泄露后，美国 NSA、英国 NCSC 与日本首相公开要求打补丁或下线；芬兰、荷兰、法国、德国、比利时等政府网站，以及维基媒体、任天堂、niconico、pixiv 等主动停服。OpenAI 此前已设立 10 亿美元的 Daybreak 计划，为防御方补贴网络模型访问。

判断：漏洞发现正被 AI 从「稀有事件」变成「持续供给」，而修复仍依赖人工排期。安全边界不再是有没有被发现，而是从披露到修复的吞吐能力。

组织 · 效能

决定 AI 编码产出的不是模型，而是工程师个体与验证环节

Jellyfish 对 447 家公司、约 5 万名工程师的数据显示：当 Cursor 把大量用户迁移到 Grok 时，合并 PR 数量几乎没有变化。工具本身解释不到 1% 的产出差异，技能使用约 3%（重度使用者约高出 30%），token 使用约 9%，公司与团队约 12%，其余大部分由工程师个体解释；AI 之前的高绩效者，之后基本仍是高绩效者。哈佛对 718 家企业的研究进一步指出，AI 提高了代码产量，却没有带来等量的完成工作量，评审等下游环节成为新瓶颈。GitHub 同期允许 Copilot 的审查结果计入分支保护规则，与一名人类审批共同满足合并条件。

判断：继续把预算押在「换更强模型」上的边际回报正在下降。CTO 更该投资评审吞吐、测试自动化与高绩效者的杠杆，而不是用代码行数证明 AI 的价值。

平台 · 交付

Agent 正在成为生产流量的主要来源，交付基础设施开始不够用

Vercel CEO Guillermo Rauch 披露，平台上由编程 Agent 发起的部署占比从年初的 3% 升到 60%；Vercel 用十年做到 10 亿次部署，随后十个月又增加 15 亿次，约 80% 的 token 来自开源模型。Anthropic 的代码合并量从 5 月每天约 2,500 次增至 9 月每天超过 30,000 次，每天 CI 检出约 2,500 万次；其版本控制、构建与 CI 按人类规模设计，已成为瓶颈，团队不得不重写相关基础设施。Uber 则在 1,000 人试点后，把 ChatGPT Work 推广到 3 万多名员工。

判断：Agent 不是「更快的开发者」，而是一类新的高并发负载。CI 并发、代码托管、评审队列与审计日志的容量模型都要重算。

资本 · 竞争

DeepSeek 百日内融资 1500 亿元，开源模型的定价权上升

DeepSeek 第二轮融资锁定约 1000 亿元人民币（约 150 亿美元），投前估值维持约 5000 亿元；融资目标从 500 亿两次上调至千亿。加上 6 月的 510 亿元首轮，四个月内累计超过 1500 亿元。腾讯与宁德时代各追加约 100 亿元，新进方包括中芯聚源、石溪资本、CPE 源峰、君联资本与吉利。梁文锋在投资者会议上称年化营收已突破 10 亿美元，API 涨价后客户并未流失。资金将主要投向模型研发与算力，公司也在筹备科创板重组。

判断：开源与低价模型不再只是「备选」，而开始具备价格与生态的双重议价能力。企业应保留可切换的开源推理路径，并把 API 涨价条款纳入合同评审。

算力 · 供给

算力供需缺口被拉到十年尺度，采购要按多年期规划

Intel CTO 在 Dwarkesh Patel 的访谈中给出的数字是：过去十年 AI 算力需求每年增长约 3 倍，而用现有全球芯片制造工具，Intel 只能把先进制程晶圆产能提升约 1 倍。Google CEO Sundar Pichai 表示，Gemini 4 Argon 上线 72 小时 token 使用量接近 25 万亿；公司宁愿放弃部分云业务短期营收，也要优先保证前沿模型研发，因为今天的算力取决于 2024 年的决定。同期，AI 基础设施公司 Modal 年化收入突破 10 亿美元，以 160 亿美元估值完成 7.5 亿美元 D 轮。

判断：算力不是可即时扩容的公用事业。容量规划、供应商集中度与单位推理成本，需要进入董事会级别的多年期资本计划。

深度分析

Deep Dive

当 AI 开始找漏洞：修补速度就是新的安全边界

发现侧已被 AI 加速一个数量级，处置侧仍按季度运转。

PHP2Shell 的意义不只在 CVSS 9.2。它是首批由模型深度参与发现、且由两个团队独立复现的核心语言运行时漏洞之一：OpenAI 的 Patch the Planet 项目用 GPT-5.6 Sol 在 8 月发现，Wiz 用 Gemini 4 Argon、GPT-5.6 Sol 与自研 Atlas 独立发现，随后进行了约两个月的协调披露。漏洞影响 PHP 5.4 以来的版本，约七成网站、超过 3300 万个站点使用 PHP；PHP 官方紧急发布四个安全版本，美国 NSA 甚至建议无法立即修复的网站先下线。

更值得警惕的是响应链条的失速。补丁信息在发布前意外泄露，导致攻击窗口提前打开；随后芬兰关闭所有对外网络服务，荷兰国家网络安全中心撤下自己的官网，鹿特丹港、荷兰足协、多家医院、法国内政部下属网站、德国联邦 IT 服务商、比利时外交部、维基媒体与任天堂等相继停服。这是第一次，一个由 AI 挖出的漏洞让多个国家的政府在同一天主动断网。

攻击侧的加速同样明显。CrowdStrike CEO George Kurtz 指出，攻击者已经在使用 AI Agent，最快的攻击以秒计；Agent 正在「压平」攻击者金字塔，让低技能攻击者获得过去只有高手才具备的战术能力。CrowdStrike 与 NVIDIA 正在共建前沿安全模型实验室。Axios 的报道则显示，美国银行高管已因 AI Agent 发起的攻击而收紧系统访问权限，因为 AI 的推进速度超过了金融机构的响应速度。

环节 过去 AI 放大后 CTO 应对
漏洞发现 稀有、依赖少数专家 持续、可规模化、可跨语言 假设漏洞终会被发现，按「必然失陷」设计
利用门槛 需要高级技巧与时间 低技能攻击者获得高级 tradecraft 零信任、最小权限、短时凭证
修复节奏 季度或月度窗口 需要在小时级完成虚拟补丁 72 小时 SLA、紧急变更通道、回滚预案
检测与分诊 人工告警、按天响应 秒级攻击、告警量激增 机器速度分诊、WAF、运行时隔离

未来 30 天的处置清单

  • 资产清单：覆盖容器镜像、无服务器运行时、托管 CMS 与第三方 SaaS 中的 PHP 组件，而不只是自建主机。
  • 补丁机制：把高危漏洞 SLA 压到 72 小时，预设无需逐级审批的紧急变更通道与自动回滚方案。
  • 争取时间：用 WAF 与虚拟补丁先挡住已知利用路径，但不能替代根因修复与版本升级。
  • Agent 权限：对访问生产系统的 Agent 实施最小权限、短时凭证与人机双审，避免 Agent 成为新的横向移动通道。
  • 演练：每季度做一次 AI 辅助红队演练，验证从检测到隔离的实际耗时，而不是只检查策略文档。

AI 编码的收益，正在被验证环节吃掉

生成变便宜之后，评审、测试与决策带宽成为新的稀缺资源。

Jellyfish 的数据给「模型决定论」泼了一盆冷水：在 Cursor 将大量用户迁移到 Grok 的天然实验中，合并 PR 数量几乎没有变化。工具只解释了不到 1% 的产出差异；技能使用约 3%，重度技能使用者约高出 30%；token 使用约 9%；公司与团队约 12%；其余大部分由工程师个体解释。哈佛对 718 家企业的研究则从另一侧印证：AI 让代码产量上升，但完成的工作量没有等比例增加，因为 AI 生成的代码把负担转移到了评审、测试与集成环节。

这与交付侧的数据互相呼应。Vercel 的部署量从年初 3% 由 Agent 发起升至 60%，Anthropic 每天合并超过 3 万次代码变更、每天约 2,500 万次 CI 检出，原有版本控制与构建系统按人类规模设计，已成为瓶颈。Uber 把 ChatGPT Work 推给 3 万多名员工，说明 Agent 正从工程扩展到知识工作全流程。与此同时，西班牙一名年薪 2.6 万美元的系统管理员在公司裁掉两名高薪工程师后，只接受了 2 小时 Claude Code 培训就接手多个项目——这类「用 AI 换人头」的做法短期看似可行，长期却把系统风险集中到最缺乏经验的人身上。

因素 对 AI 编码产出的解释力 说明
工具 / 模型 <1% Cursor 将用户迁移到 Grok，合并 PR 几乎不变
技能使用 约 3% 重度技能使用者约高出 30%
Token 使用量 约 9% 用量是相关因素，但不是主因
公司与团队 约 12% 组织环境、流程与协作方式差异
工程师个体 其余大部分 AI 前后的高绩效者高度重合

三条组织动作

  • 换指标：用交付周期、评审等待时间、变更失败率与缺陷逃逸率替代代码行数、PR 数与 token 消耗量。
  • 投人不投模型：给高绩效工程师更高的 Agent 配额与工具自由度，把有效用法沉淀为可复用的技能包与内部 playbook。
  • 把节省的工时投回验证侧：优先扩充评审、测试、平台与安全能力，而不是直接把 AI 节省的时间换算成裁员指标。

多 Agent 上生产，坑在业务逻辑与验证

CTO 视角：接下来 30 天做什么

Action Items

72 小时内完成 PHP2Shell 暴露面复核

盘点所有 PHP 运行时，包括容器镜像、无服务器运行时、托管 CMS 与第三方 SaaS；能升级的立即升级，不能升级的先上 WAF 虚拟补丁并限制外网访问。把「高危漏洞 72 小时修复」写进制度，并预设紧急变更与回滚通道。

把研发效能指标从产出量切换到端到端交付

停止用代码行数、PR 数或 token 消耗量证明 AI 价值，改用交付周期、评审等待时间、变更失败率、缺陷逃逸率与回滚率。先测出 AI 代码在评审与测试环节的真实负担，再决定是否扩大使用面。

建立 Agent 治理平面

统一管理 Agent 的身份、可用模型、工具权限、数据边界与预算上限；高风险动作保留人工审批，后台任务必须有审计日志与可中断机制。可参考 Google Agent Compute Engine 的沙箱隔离与 JetBrains Air Governance 的预算治理思路，但不要把治理绑定在单一厂商。

模型与算力保持多源，并把单位经济学纳入架构评审

至少保留一条开源权重模型的推理路径，建立覆盖核心业务的评测集，使换模型成为配置变更而非重写。跟踪每百万 token 的完全成本、缓存命中率与 GPU 利用率；在合同中明确涨价上限、退出条款与数据可迁移性。

用 3–7 人前沿小队做组织实验

让一个小团队专门测试新模型与 Agent 工作流，把有效实验产品化为内部工具，再向全公司推广；避免全员各自摸索。把 AI 节省下来的工时优先投入评审、测试、平台与安全，而不是直接换算成人头缩减。
