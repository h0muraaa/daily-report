01支出结构

企业 AI 支出一年放大 5.4 倍，Agent 成为最大“用户”

Menlo Ventures 第四份企业 AI 报告（Morning Consult 2026 年 9 月调研近 400 位美国企业决策者，按年化收入估算）显示，企业 AI 支出达到 1768 亿美元，为去年的 5.4 倍。更关键的结构变化是：OpenRouter 上 80% 的 token 由 Agent 产生，每周 130.9 万亿，约为人类用量的 7 倍；Agent 流量在 Opus 4.5 发布后一周翻三倍，此后增长 37 倍。支出加速向头部集中：Anthropic 在企业 API 支出中的份额从 40% 升至 55%，OpenAI 从 27% 升至 31%，Google 从 21% 降至 9%；三家合计拿下 69% 的企业部署支出（1227 亿美元），Anthropic 与 OpenAI 合计占企业 API 支出的 86%。企业实际支出是原计划的 2.5 倍（实际 4.7 倍 vs 计划 1.9 倍），新增支出的 55% 来自全新预算。对 CTO 的含义很直接：预算模型要从“按人头”改为“按任务”，并把供应商集中度列为治理指标。

02安全经济学

OpenAI 把漏洞挖掘变成“每漏洞 1000 美元”的流水线

OpenAI 安全研究团队用一条自主的漏洞发现、利用与补丁流水线，在单次运行中验证并为 948 个 Linux 内核本地提权漏洞生成补丁，API 成本 120 万美元，约合每个漏洞 1000 美元；过程中还发现并使用了至少 10 种此前未知的利用技术。团队正与 Linux 维护者和 Patch the Planet 合作提交报告与补丁。Suhail 的判断是，7×24 小时扫描并“自我攻击”将成为企业合规要求；Google Cloud 也直言，人工评审已跟不上机器速度的提交与未审查依赖，被动防御不再可行。安全预算的重心将从“买扫描工具”转向持续验证、隔离与治理。

03工程体系

代码生成已不是瓶颈，版本控制、评审与“交付验证”才是

Anthropic 在四个月内把日均合并量从约 2500 次推到 3 万次以上，为此在五个月内同时建了自研版本控制 Scion、评审平台 Antique、代码搜索与权限系统；OpenAI 的 Pando 把中位推送延迟降到原来的约五分之一、日均传输近 1 PB Git 数据，此前可靠性一度跌破 90%，并收购 Pierre 补上 Trees、Diffs 等看代码/审代码组件。另一面，Google 与 Mercor 的 PLE 评测显示，Claude Opus 5.5 在单项约束上平均满足 91%，但只有 41.3% 的交付设计满足全部硬性安全与可行性要求。产出放大 10 倍后，瓶颈从“写”转移到“证明可交付”。

04采购战略

模型采购进入“组合拳”阶段：自托管、开源权重与路由同时成熟

英国金融科技公司 Revolut 在部分工程师月耗 1000 至 1 万美元后，转向用 56 张 B200 自托管智谱 GLM；不到一年推理成本下降约 90%，约 2000 名工程师编码时间缩短 60%，需求到合并周期缩短约 70%。同期，Kimi K3.1 Pro 以 2.8 万亿总参数、1040 亿激活参数开放权重，在 Agent Arena 位列开源第一、总榜第 13；腾讯 Hy4 以 770B MoE、1M 上下文、视觉与 Computer Use 进入开源第一梯队，并坦承与顶尖闭源仍有差距。Fireworks Nexus 路由在 1222 个任务上以 89.3% 对 86.8% 超过 Claude Opus 5.5，成本低 17%；Ramp 用后训练 Qwen 3.5 在金融问答上以 Haiku 级延迟超过 Opus 4.6。采购标准应从“单模型最强”转为“组合最优 + 可迁移”。

05资本与组织

资本与组织同时转向纪律：算力周期进入“算账”阶段

Anthropic 以约 2 万亿美元估值冲刺 IPO，300 多页招股书里 90 多页是风险提示；有分析指出其模型保鲜期约 6 个月、服务器折旧 6 年、GPU 却按 8 年折旧，收入与算力承诺的错配是核心争议。市场端，CoreWeave 触及 52 周低点，本周 39 项已完全计票的地方数据中心公投中 38 项反对（非官方结果），另有 6 项部分计票也领先反对。一级市场，a16z 数据显示 PE 支持的软件收入增速仅 3-7%，低于公开软件的 10-16% 和 VC 支持公司的 18-30%，科技买断交易占比从 2023 年的 34% 降至 2026 年 Q1 的 11%。组织端，Google 在加拿大、法国、德国、日本和瑞士推出自愿离职补偿，瑞士方案为每工作一年一个月工资、最多 12 个月；DeepMind 不在瑞士这轮名单内，Cloud 与 DeepMind 过去几轮也未被纳入。技术战略必须开始内含资本周期与社区/监管约束。

Menlo 报告里最值得 CTO 注意的不是 1768 亿美元这个总量，而是花钱的主体变了。Agent 已经贡献 OpenRouter 上 80% 的 token，每周 130.9 万亿，约是人类用量的 7 倍；拐点出现在 2025 年 11 月 Opus 4.5 发布后，Agent 流量一周翻三倍，2026 年 2 月 Opus 4.6 与 GPT-5.3-Codex 发布后超过人类，此后 Agent 流量增长 37 倍，人类使用只增长 5 倍。Agent 可以并行、可以无人值守，支出不再跟员工人数走，而是跟完成的工作量走。企业原计划把 AI 支出提高到去年的 1.9 倍，实际平均花了 4.7 倍，中位数也从计划的 1.8 倍变成 2.2 倍；新增支出中 55% 来自全新预算，只有 22% 来自原有软件预算。这意味着 AI 预算不再是 IT 预算的重新分配，而是一个新的、尚未被财务模型覆盖的成本中心。

供给侧的集中度同步上升。Anthropic、OpenAI、Google 拿走 69% 的企业部署支出，共 1227 亿美元，去年这个比例是 50%；三家的支出一年涨 7.5 倍，其他所有公司合计只涨 3.3 倍。企业 API 支出中 Anthropic 与 OpenAI 合计占 86%，Google 的份额从 21% 跌到 9%——消费端的强势并没有自动转化为企业 API 的强势，旗舰模型节奏和价格策略才是决定因素。对采购方而言，这既是议价风险，也是架构风险：当两家供应商掌握 86% 的 API 支出，任何涨价、限流或条款变化都会直接传导到产品毛利。

替代方案正在变得可信。Revolut 的案例给出了一个完整的成本曲线：早期用 Gemini 和 Claude Code，部分工程师每月烧掉 1000 至 1 万美元，ROI 不明显；设置 token 预算后，工程师反而不敢把 AI 用在调试、工单和文档上，因为“额度要留给复杂代码生成”。转向 56 张 B200 自托管 GLM 后，不到一年推理成本下降约 90%，约 2000 名工程师编码时间缩短 60%，需求到合并周期缩短约 70%。但这不是免费的午餐：GPU 折旧、机房、运维、模型升级和安全合规都必须计入总成本。真正的启示是，token 配给会抑制使用，而使用不足又会掩盖 AI 的真实价值——成本治理必须和采用率、交付周期一起看。

模型侧的可替代性也在增强。Kimi K3.1 Pro 开放权重，2.8 万亿总参数、1040 亿激活参数、896 个专家、每 token 激活 16 个，支持 1M 上下文，在 Agent Arena 的开源模型中排名第一、总榜第 13，较 K3 提升 5.1%；Ollama Cloud 提供美国托管与零数据保留。腾讯 Hy4 以 770B MoE、1M 上下文首次加入视觉与 Computer Use，在 579 个真实金融任务上得分 3.04（四分制），高于 DeepSeek-V4.1-Flash-1017 的 2.97 和 Kimi K3.1 Pro、GLM-5.3 的 2.68；搜索幻觉率从 15.76% 降到 5.45%，猜测出错率从 23.1% 降到 5.6%，权重计划近期开源。混元团队同时明确承认与顶尖闭源模型仍有较大差距，这种坦诚反而让选型更容易做。

路由和蒸馏正在把“组合最优”变成可运营的能力。Fireworks Nexus 在 1222 个任务上以 89.3% 对 86.8% 超过 Claude Opus 5.5，成本低 17%，其工程流量每次编码会话成本下降 53%；Ramp 用后训练 Qwen 3.5 在金融问答上以 Haiku 级延迟超过 Opus 4.6，并用 KV cache “弹匣”把 20 至 30 倍的上下文预打包进 Agent。Agent Arena 的数据还显示，在成本最高的 5% 会话中，Google Gemini 4 Argon 与小米 MiMo 进入前沿位置，过去两周有超过 1000 个会话单次成本超过 100 美元。任务难度与成本高度非线性，固定使用单一旗舰模型，既贵又未必最优。

商业模式的另一端，钱正在绕过“卖软件”直接买下服务。红杉在 AI Ascent 2026 的判断是：云计算扩大了软件市场，AI 扩大的是服务市场，下一批巨头卖的可能是“工作本身”，对应约 10 万亿美元的服务生意。Thrive Holdings 融资 20 亿美元，专买会计师事务所和 IT 服务公司，已收购 70 多家，估值 120 亿美元；其会计板块有 50 多家事务所、2000 多名从业人员，OpenAI 在 2025 年 12 月入股并派员工进驻。作为对比，2026 年前 10 个月美国纯软件类 AI 应用一共 131 笔种子轮、合计 16.3 亿美元，Thrive 一笔就超过总和。对技术高管而言，如果产品本质是某个工作流，单纯卖工具的定价权会持续被拥有客户关系和业务结果的一方挤压。

中国模型厂商的财务现实也值得纳入供应商评估。智谱、MiniMax 上半年收入翻了几倍，但仍分别拖着超 20 亿元人民币和近 3 亿美元的亏损；Coding 是少数“需求刚性、产出可衡量”的场景，但价格战与研发开支让毛利承压。融资端，2026 年 Q3 仅 43 笔超 10 亿元人民币的融资就卷走全市场近一半资金，企业服务领域平均单笔融资已缩水至约 3300 万元。选型时只看 benchmark 不够，还要看供应商的现金流、算力承诺和续约能力。

给管理层的三个判断：
  • 未来 12 个月，企业 AI 预算的超支将主要来自 Agent 的并行调用，而不是员工人数增长；预算模型必须从“席位”迁移到“任务量 × 单价 × 重试率”。
  • 单一供应商占比超过 70% 的关键工作负载，应建立可切换的开源权重或第二供应商方案；切换能力本身就是议价能力。
  • 如果 AI 让服务成本下降，价值会更多留在拥有客户关系和交付责任的一方；纯工具型产品需要尽快向“结果计价”或“嵌入工作流”迁移。

代码产能的提升速度已经超过配套工程系统的承载能力。Anthropic 的日均合并量在四个月内从约 2500 次增长到超过 3 万次，为此在五个月内同时完成 Scion（自研版本控制）、Antique（代码评审平台）、代码搜索和权限系统的建设。OpenAI 则选择重构 Git 后端：Pando 在保持协议兼容的同时，把中位推送延迟降到原来的近五分之一，每天传输近 1 PB Git 数据；在此之前，内部系统的可靠性一度跌破 90%。OpenAI 还收购了 Pierre，把 Trees（文件浏览）、Diffs（差异展示与就地编辑）、Highlights（流式语法高亮）和 Code Storage 纳入 Codex，目标是覆盖从第一个分支到上线的完整流程。

但“能生成”不等于“能交付”。Google 与 Mercor 发布的 PLE 评测用 85 项机械、电气、土木与结构工程任务量化了差距：在 56 项隐藏测试中，Claude Opus 5.5 搭配 Claude Code 得分 48.3%；在 41 项人机共同创作任务中，它平均满足 91% 的单项约束，但只有 41.3% 的交付设计满足全部硬性安全与可行性要求。剩下的 9% 往往不是靠更强算力就能补上的，因为工程约束彼此耦合——解决一个问题会生成新的问题。这与软件交付高度相似：单个测试通过、单个 PR 合并不等于系统可交付。

金融行业的实践更能说明“验证”有多难。NatWest 的 Cora 助手服务 1900 万客户，每天约 10 万次对话，正在从脚本式回答迁移到 AI Agent。其 AI 工程负责人提到，构建 Agent 是容易的部分，证明它安全才是难点：他们用路由漏斗限制进入模型的内容，用多个分数而不是单一分数衡量质量，并发现 83% 的整体通过率掩盖了 54 个百分点的群体差距；一个 LLM judge 给出的分数远高于人工评分，且几乎不相关。最终他们用影子部署和 feature flag 控制灰度。Langfuse 在为一家前五银行做部署门禁时也得出类似结论：银行不认证模型，只认证应用，要求本地化、门禁和气隙隔离；一个在数字上只有 60% 准确率的小模型，在接入计算器工具后越过了 85% 的门槛。

安全侧的变化同样剧烈。OpenAI 的自主流水线用 120 万美元 API 成本发现并修复 948 个 Linux 内核提权漏洞，约 1000 美元一个，还发现了 10 种此前未知的利用技术；Ramp 用 1 万个并行 Agent 对自身做渗透测试，发现 7 个高危漏洞，较便宜的开源权重模型也能捕获接近数量的漏洞；Mistral Large 4 用 133 个 Agent 在 Django CVE 上完成代码测绘、漏洞搜寻、攻击验证和补丁。Docker 的判断是，Agent 的自主性让传统应用安全控制失效，隔离与治理比单纯改进模型更关键。Suhail 则把 7×24 小时扫描与“自我攻击”视为企业合规的入场券。安全不再是发布前的一次性门禁，而是持续运行、可观测、可追责的工程能力。

这也解释了为什么“黑灯工厂”式的全自动交付仍然遥远。代码可以由 AI 生成，但目标由谁定义、质量由谁证明、事故由谁负责、下一代工程师如何成长，仍然没有自动化答案。Inkitt 的一键 PR 生成器提供了一个务实样例：事件驱动编排器持久化工作流状态，协调短生命周期的编码 Agent 容器，限制重试次数，强制权限约束，并在合并前保留人工审核。Weave 则从度量侧切入，用模型衡量人类与 Agent 的产出，并与 AI 支出对比，其 Weave Router 根据不同编码任务选择模型。两者的共同点是：把 Agent 放进可观测、可回滚、可问责的流程，而不是假设它会自动正确。

值得持续跟踪的早期信号

CTO 视角

接下来一个季度可以落地的五件事

  1. 建立“按任务”的 AI 单位经济学，而不是只看总账单

    把 AI 成本拆到每个合并 PR、每张工单、每次客服会话和每个 Agent 运行，记录 token、缓存命中、重试、人工复核和返工成本，并与交付周期、缺陷率一起看。Menlo 数据显示企业实际支出可达计划的 2.5 倍，Revolut 则证明过度配给 token 会抑制使用、掩盖真实价值。预算护栏应该控制“每个成功任务的成本”，而不是简单封顶调用量。

    度量：单任务成本、AI 支出/交付周期、采用率与返工率

  2. 把“模型组合 + 可迁移性”写进架构标准

    为关键工作负载建立路由层，按任务难度、延迟、成本和合规要求选择模型；至少保留一个开源权重或第二供应商的可用路径，并定期做切换演练。Kimi K3.1 Pro、腾讯 Hy4、Fireworks Nexus 和 Ramp 的后训练小模型都证明，“非旗舰模型 + 路由 + 工具”可以在特定任务上达到甚至超过旗舰效果。合同层面要争取零数据保留、权重托管、价格上限和退出条款。

    度量：单一供应商占比、模型切换耗时、单位任务成本下降

  3. 把验证层当作平台投资，而不是流程补丁

    建设统一的 Golden set、多维评分、LLM judge 校准、沙箱隔离、工具权限、审计日志和人工复核队列。不要用一个总通过率做发布决策——NatWest 的 83% 通过率掩盖了 54 个百分点的差距，LLM judge 与人工评分几乎不相关；PLE 的 91% 单项约束满足率也只换来 41.3% 的完整交付。门禁应该认证“应用 + 工具 + 权限”的组合，而不是模型本身。

    度量：评测与人工一致性、门禁漏放率、越权拦截率、回滚时间

  4. 按 10 倍代码吞吐量重做交付系统

    Anthropic 日均合并量从 2500 次涨到 3 万次、OpenAI 日均 1 PB Git 流量，说明版本控制、CI、评审和权限系统会先于模型成为瓶颈。提前评估代码托管、增量构建、测试选择、评审路由和所有权模型；对低风险变更可以自动化，但必须保留可追溯的责任人和回滚路径。不要在没有验证层的情况下追求“黑灯工厂”。

    度量：评审等待时间、变更失败率、MTTR、每千行变更的缺陷数

  5. 同步重构组织与安全边界

    AI 压缩了协调层，中间管理层的价值需要从“汇总信息”转向“定义问题、设计约束、承担结果”；哈佛的 Lakhani 提到，他会解雇用“AI 给我的”解释交付物的人，说明问责机制必须前置。安全侧要把 7×24 自我攻击、依赖审查、Agent 隔离和事件响应纳入常态，并针对 Google 自愿离职、核心人才流动等信号做好关键岗位继任计划。

    度量：关键岗位继任覆盖率、安全扫描覆盖率、平均响应时间、Agent 越权事件数
