安全推理防护

"窃取思维链"论文刷屏：Anthropic/OpenAI/Google 的加密推理轨迹被可复现地解码，防蒸馏护城河告破

2 个重要话题

① Harness 层竞争：模型越强，Harness 反而越"厚"

今天的多个信号指向同一个结论：Agent 时代的技术制高点正在从"模型能力"向"模型与 Harness 的协同"转移。微软把 Harness 做成受支持的生产运行时；DeepSeek 开设了"DeepSeek Harness 团队"公众号，把 Harness 列为官方组织架构的一部分；MiniMax 则明确提出"模型在自己的 harness 里训练，通过 harness 服务用户，用户行为变成训练信号反哺下一个模型"的闭环设计，强调 harness 端的 system prompt、工具调用组织与错误处理，直接影响推理端的缓存命中率、调度效率与 token 消耗。

关键数据：Pi + DeepSeek 组合的缓存命中率说明问题

开发者用 Pi 调用 DeepSeek V4 Flash 处理近 10 亿输入 token，缓存命中率达到 99.93%，最终仅花费 2.65 美元（同等用量无缓存估算约 132 美元）；同一模型在其他 Harness 中命中率通常为 94%–97%。在 Composio 的公开对比中，Pi 以 30 项任务通过 20 项（66.7%）的完成率跑赢 Claude Code。缓存命中率 5 个百分点的差异意味着成本相差数十倍——这正是 Harness 工程价值的量化证据。Raft 创始人 RC 的判断值得反复琢磨：模型能力增强是"阴"的扩张，会内化底层 Harness；但每上一个台阶，又会解锁更复杂的场景，催生更上层的 Harness 需求——复杂没有消失，只是从"能力层"转移到了"协作层"。

行动建议

给技术高管的五条行动建议

  1. 把 Harness 当成一等基础设施来评估。 微软已把 Agent 运行时标准化，DeepSeek 组建了 Harness 团队，MiniMax 强调模型-harness 闭环。建议在 Q3 内完成一次"自有 Harness vs 托管运行时"的选型与技术安全基线评审，别让 Agent 在无治理的裸环境中扩张。
  2. 重算推理成本曲线，把"缓存命中率"设为核心 KPI。 Pi+DeepSeek 的案例证明，同一模型在不同 Harness 下缓存命中率相差 5 个百分点、成本相差数十倍。把 prompt 复用、上下文压缩与路由策略纳入成本治理，是当下性价比最高的工程投入。
  3. 重新评估推理链的安全边界。 思维链可被注入重放复现，敏感代码与数据一旦进入推理 token 即视为可泄露。建议对现有 LLM 网关增加推理轨迹审计、敏感信息剥离与密钥轮换机制，并复核 BYOK 场景。
  4. 明确"自有权重/数据资产"战略。 "Not your weights, not your product"——至少在核心业务链路上设计数据资产与模型选择空间（开源权重 + 路由），避免被单一上游在定价与能力上卡脖子；同步跟踪英伟达算力融资平台带来的新采购结构。
  5. 为"AI 原生研发组织"做准备。 Vercel 的软件工厂与 Ramp 的自动触发 Inspect 已证明"无人值守研发"可规模化。建议设立小规模试点：让 CI/告警自动拉起 Agent 修 bug 提 PR，把工程师从"接单"转为"审核与定义质量"，同时配套制定 AI 生成代码的评审与追责规范。
