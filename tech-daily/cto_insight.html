字节 EdgeBench 发现 Agent 的 Scaling Law

字节 Seed 团队发布 EdgeBench，一个让 Agent 在陌生环境中持续运行至少 12 小时的评测平台。134 个任务横跨科学/ML、软件工程、组合优化等六大领域，5 个前沿模型累计运行约 38,000 小时后，团队得出一个关键结论：Agent 的能力提升存在类似 LLM 的 Scaling Law，但衡量的不是参数量，而是“在真实环境中从反馈中学习并持续改进”的能力。

这对 CTO 的核心启示在于：当前大多数企业评估 AI 的方式可能选错了指标。静态 benchmark 衡量的是模型出厂能力，而生产环境中更重要的是模型在长周期任务中的自我改进速度、错误恢复能力和探索效率。如果企业正在将 Agent 投入客服、研发、运营等长周期工作流，评估框架需要从“一次问答准确率”转向“持续运行后的累积产出质量”。

成本结构

开放模型以 1/10 成本逼近闭源前沿

NVIDIA 与 LangChain 联合宣布，基于 Nemotron 3 Ultra 的 Deep Agents 在 harness 调优后达到 aggregate score 0.86，推理成本仅 4.48 美元，而最接近性能的闭源模型成本高达 43.48 美元。几乎同时，Cognition 发布 SWE-1.7，称其在软件工程任务上接近最强前沿模型，但成本显著更低，并支持 1000 token/s 的 lightning 模式。

这两条消息共同指向一个趋势：推理成本正在以数量级速度下降，且开放权重模型正在从“可玩可用”走向“企业可用”。对于 CTO，这意味着 AI 预算规划需要重新建模——过去以 API token 计费为中心的预测方式，可能很快会被“自托管开源模型 + 专用推理优化”的混合模式取代。同时，模型选型逻辑也应从“谁最强”转向“在特定任务和成本约束下谁最划算”。

安全治理

Elastic：Agent 治理必须内嵌于架构

Elastic 提出，自主安全 Agent 的治理不能是事后补丁，而应从架构层面解决四个关键问题：推理与执行的隔离、持续评估、渐进式信任，以及大规模 Agent 专属遥测。随着 Agent 被赋予更高自主权和工具调用能力，传统安全边界被打破，CTO 需要在设计阶段就把可观测性、权限最小化和审计追踪纳入 Agent 平台，否则规模化部署将伴随不可接受的合规与运营风险。

CTO 视角 · 行动建议

  1. 重新评估 AI 基础设施供应商：AI 基础设施正在快速专业化，Gartner 等第三方评估已开始将其作为独立品类。建议在下一轮云/算力采购中，把 agentic 推理优化、模型-芯片协同、能耗与成本透明度作为核心选型维度，而非仅比较 GPU 单价。
  2. 建立面向“长周期 Agent”的评估体系：静态 benchmark 已不足以评估生产级 Agent。建议针对客服、研发、运营等长周期场景，建立包含持续学习能力、错误恢复、任务完成率和累积成本的动态评估框架。
  3. 审视模型使用成本结构：开放权重模型与优化后的 harness 正在将推理成本压缩一个数量级。建议对高流量场景做“API vs 自托管开源模型”的 TCO 建模，尤其关注自身 GPU 利用率是否达到 50% 以上的盈亏平衡点。
  4. 关注模型供应链的地缘风险：中国开源模型的政策取向可能发生变化，建议对核心依赖的模型来源做风险评估，并准备多模型/多供应商的 fallback 方案。
  5. 把 AI 治理纳入架构设计早期：随着 Agent 自主性提升，安全、审计、权限和可观测性需要从“事后补丁”变为“架构原生”。建议在 Agent 平台设计阶段就引入治理层。
