  4. Agent 进入生产系统的关键判据：它是分布式系统，不是「更聪明的聊天框」

    TikTok 站点可靠性工程师 Salman Munaf 提出了一个工程上极其有用的框架：Agent 调用退款接口遇到网络超时时，「超时从来不意味着失败，而意味着未知」。若没有请求标识符、幂等键与状态查询，Agent「先重试再说」的本能就可能导致同一笔退款被执行两次。他认为一旦模型开始调用外部服务，问题就不再是模型问题，而是分布式系统问题，会遭遇这个领域几十年来已反复研究和命名的各种故障模式——他进一步给出两条原则：当上下文能影响行动时它就是状态，而状态会过期、会与权威数据冲突；因此记忆应当被当作缓存对待，可失效、带来源。日志也不够用了，必须记录 Agent 每一步看到什么、据此做什么、为什么认为这样是对的。

02深度分析Deep Dive

Deep Dive 01

容量即战略：当「售罄」成为前沿模型的新常态

今天有三条看似独立的新闻，拼起来是一条完整的因果链。第一，OpenAI 停售 Pro 20X，把「供不应求」第一次变成了公开的订阅政策。第二，Anthropic 已宣布的算力容量超过 11.5GW，但实际运行估算只有 1–2GW，全部建成后年支出可能到 1150–1200 亿美元。第三，OpenAI 正就新一轮融资初步接触投资者，估值可能达 1.2 万亿美元或更高（上一轮 1220 亿美元、估值 8520 亿美元），IPO 已推迟到明年或更晚；而竞争对手 Anthropic 的 IPO 预期估值据称将达 1.5 万亿美元或更高。

把三者放在一起看，逻辑就清楚了：前沿模型的供给能力，是其商业模型的硬约束；而资本市场的估值，本质上是对未来算力承诺的贴现。这也解释了为什么「减速」议题在技术圈获得认同，却在商业层面迅速受阻——已宣布的容量与已谈定的估值，都需要持续的算力消耗来支撑。黄仁勋的反对、特朗普的表态、马斯克的「让中国暂停行不通」，本质上不是技术判断之争，而是这条资本链条上各方的位置之争。

对企业采购方来说，这件事有非常具体的含义。模型层的能力差距仍在，但可获得性正在成为同等重要的变量：当最贵档位可以被停售，说明「无上限使用顶级模型」这件事从来不是合同保证，而是容量富余期的红利。因此，把模型层当成可替换组件、而非基础设施依赖，是更稳健的架构姿态。这也正是 OpenRouter 数据的意义——支出结构在快速变化：GPT-6 Astra 拿走了最多的钱，开源权重实验室的支出增长超过 10 倍，而纳德拉明确判断模型层不会长期拿走全部经济价值。当模型成本持续下降、开源替代持续可用，应用层的毛利空间才会真正打开。

对技术决策的含义：把「模型可获得性与配额上限」写进架构风险清单，而非只看能力榜单。为关键工作流准备至少两家供应商 + 一个可自托管的开源备选，并据此重新评估推理成本预算——今天看似稳定的价格与额度，都可能是容量富余期的临时状态。 📎 AI Will · Anthropic 算力账单 📎 InfoQ · 停售 Pro 20X 📎 AI Will · OpenRouter 支出反转 📎 OpenRouter · 开源权重 10x 📎 有新Newin · 纳德拉访谈 📎 Z Potentials · OpenAI 新一轮融资
Deep Dive 02

Agent 生产化：从「能跑」到「能生产」，缺的是四个工程命题

过去一年，Agent 的 demo 门槛被持续压低——可视化编排加上 Vibe Coding，几周的工作可以压缩到几天。但企业生产环境的门槛没有同步下降，今天集中出现的几篇实践文章，恰好覆盖了四个过去被忽视的命题。

第一，幂等与状态一致性。TikTok SRE 的「超时=未知」是最精炼的表述。Agent 一旦能产生副作用（支付、退款、下单、改配置），就必须具备分布式系统的基本装备：请求标识符、幂等键、状态查询、补偿逻辑。他还提出一个常被忽略的观点——上下文能影响行动时它就是状态，而状态会过期、会与权威数据冲突，因此记忆应按缓存管理：可失效、带来源。

第二，执行边界与沙箱。蚂蚁集团的分享点明了这个矛盾的尖锐性：Agent 要写代码、跑代码、操作浏览器与桌面、读写文件、装依赖、调内部系统，一个「无害的模型」在能执行不安全操作时就会变得危险。Google Antigravity 同日的产品更新是同一个方向的产业印证：新权限系统让命令在严格隔离于项目、默认无网络的环境中自动执行，用沙箱换自主度。

第三，评测基础设施化。美团图灵团队的经验是评测必须服务于真实业务的研发、上线、回归、优化与规模化落地，而非离线打榜。LangChain 对语音 Agent 的评估框架把问题拆成三个独立维度：执行（是否按规范调用工具、遵守政策）、结果（用户的任务是否真的被解决）、体验（轮次结束延迟等对话质量指标）。其中最关键的提醒是——指令遵从性 ≠ 结果有效性，执行维度满分不能推出结果维度合格，因此两个维度必须独立评估，且结果维度应尽量度量真实世界的下游信号（预约时间是否正确、工单是否重开、转接是否被接听）。

第四，经验的沉淀与验证。字节 OpenViking 的洞察是「做过」不等于「学会」——聊天记录告诉你上次说了什么，日志告诉你工具返回了什么，但 Agent 真正需要的是「这类任务应先确认哪些条件、哪套执行顺序更可靠、哪些路径失败过、最后检查什么」。小红书 MemPro 把记忆流水线本身变成可演化程序。这里有一个必要的冷静提醒：AI2 与华盛顿大学的研究《Rethinking the Evaluation of Harness Evolution》指出，当「自我进化」的 Agent 得分提高时，很难区分它是真的学会了更好的工作方式，还是仅仅比普通 Agent 多获得了几次尝试机会——许多 harness evolution 的收益，甚至不如简单地把同一道题多跑几遍。

对技术决策的含义：Agent 的设计评审应当按分布式系统进行，而非按 prompt 工程进行。建议把「幂等键 + 请求 ID + 状态查询 + 补偿事务 + 记忆失效策略」列为上线前的强制检查项，把评测从打分动作升级为持续运行的基础设施，并默认以最小权限、默认无网络的沙箱承载执行。 📎 AI前线 · TikTok SRE 📎 AI前线 · 蚂蚁 QCon 实践 📎 阿里技术 · 垂类 Agent 📎 美团技术团队 · Agent 评测体系 📎 字节跳动技术团队 · OpenViking 📎 小红书技术 · MemPro 📎 Google Antigravity · 权限与沙箱 📎 meng shao · 语音 Agent 评测三维度 📎 机器之心 · Harness Evolution 论文

标准 · 与现实脱节

「为 Agent 重建 Web」尚未奏效：约半数网站发了 llms.txt，几乎没有 Agent 去读

MCP Apps 规范作者 Liad Yosef 团队的实测结果颇具警示性：约一半受测网站已发布 llms.txt（告知 Agent 如何与自己协作的事实标准），但他们跑过的 Agent 几乎没有读取它——Agent 直接去文档页、再去首页，少数打开 llms.txt 的还是因为文档里提到了它。他的结论是：我们一直在按「我们认为 Agent 需要什么」写规范，而唯一可靠的办法是观察成千上万个 Agent 实际怎么做。对正在投入 Agent 可发现性改造的团队，这是一个应当被验证而非默认的前提。 📎 AI Engineer · Rebuilding the web for agents

前沿 · 被高估的曲线

RSI 的真实进度：75% 的研究仍停在 Level 1–2

30 多位研究者的 75 页论文把 AI 自我改进分为 5 级，从「由人类决定改什么」（Level 1）到「由 AI 改写创造下一代 AI 的过程」（Level 5）。他们梳理了 491 篇论文，结论是 75% 仍停留在 Level 1–2，达到 Level 5 的不到 6%。行业的现实进展是另一种形态的「慢速 RSI」：Anthropic 披露截至 2026 年 5 月，合并进生产代码库的代码超过 80% 由 Claude 编写；OpenAI 也承认早期模型曾「参与创造自身」。真实的瓶颈不在算力，而在「一开始就找到正确的目标」这类研究品味问题。 📎 AI Will · RSI 五级论文 📎 Founder Park · RSI 走到哪一步

合规 · 工程化

可观测性正在从最佳实践变成监管要求

CISA 发布了面向 OMB M-26-14 的日志参考架构（LRA），联邦机构需据此完成各自的日志规划。这类要求的意义超出公共部门：当日志架构被监管化，日志的采集范围、留存周期与可查询性就从运维议题上升为合规议题。结合 Agent 天然需要「记录每一步看到了什么、据此做了什么、为什么认为这样是对的」，可观测性的投入回报率正在被双重抬高。 📎 Elastic · CISA 日志参考架构

供应链 · 估值重估

国产 GPU：需求增长 162%，股价却集体腰斩

2026 年上半年，四家国产 GPU 公司合计收入 52.42 亿元、同比增长约 162%，其中增速最慢的沐曦也有 44.7%。但 7 月以来国产 GPU 集体腰斩，沐曦、天数智芯最大回撤分别达 55% 和 64%，且反弹乏力（同期光模块龙头反弹 9%–27%，港股 MiniMax 反弹近 25%）。原因被归结为两点：标的稀缺性消失——不到一年公开市场从几乎没有纯国产 GPU 标的变成五家，且解禁与基石锁定期相继到期；同时规模还未大到能摊薄研发，盈利逻辑尚未跑通。对采购方而言，这意味着供应商财务可持续性应当成为选型评估的显性维度。 📎 硅基观察Pro · 国产 GPU 估值回调

04CTO 视角Action Items

针对技术高管的下一步行动建议。

  • 1. 把「模型可获得性」纳入架构风险清单，而不是只看能力榜单

    OpenAI 停售 Pro 20X 说明顶级模型的使用额度不是合同保证，而是容量富余期的红利。建议为关键工作流准备至少两家供应商和一个可自托管的开源备选，并在容量规划中显式标注各供应商的配额上限与降级路径；把「模型层不可用」纳入与机房断电同级的故障演练。 📎 InfoQ · 停售 Pro 20X 📎 AI Will · OpenRouter 支出反转 📎 OpenRouter · 开源权重 10x

  • 2. 重新计算「自建 vs 托管」的临界点

    Perplexity 用 2 名工程师 + 数百个 AI Agent 在两个月内建成 4 万行 Rust 存储层，读延迟降约 5 倍、成本降至少 20%；NousResearch 用 1393 个子 Agent 削减 34.4% 存量代码，成本约为人工的 1%–13%。过去「买托管」的默认结论建立在人力成本假设上，而这个假设已经变了。建议对高延迟敏感、高账单占比的存储、检索、解析层做一轮自研 ROI 复算，注意其成功前提是先把工程规范沉淀为可复用的 Skills。 📎 meng shao · Perplexity CobbleDB 📎 meng shao · Hermes 重构

  • 3. 把 Agent 的设计评审按分布式系统来做

    把「幂等键 + 请求标识符 + 状态查询 + 补偿事务 + 记忆失效策略」列为上线前的强制检查项。核心原则是：超时意味着未知而非失败；任何能产生副作用的工具调用都必须可被安全地重放或撤销；上下文能影响行动时它就是状态，因此记忆必须可失效且带来源。 📎 AI前线 · TikTok SRE

  • 4. 把评测从「打分动作」升级为持续运行的基础设施

    评测要随代码、Prompt、工具链、模型版本一同纳入 CI。至少区分三个独立维度——执行（是否按规范调用工具与政策）、结果（真实任务是否被解决）、体验（延迟与对话质量），并尽量采集真实下游业务信号（预约准确率、工单重开率、升级率）而非从对话中推断。注意区分「自我进化带来的提升」与「仅仅是多跑了几次」，否则优化投入会被系统性高估。 📎 美团技术团队 · Agent 评测体系 📎 meng shao · 语音 Agent 评测三维度 📎 机器之心 · Harness Evolution 论文

  • 5. 沙箱与权限先行，再逐步放开自主度

    默认无网络、项目级严格隔离、最小权限，是当前主流的安全基线（蚂蚁的企业级实践与 Google Antigravity 的新权限系统指向同一方向）。企业级 Agent 的难点不在「能不能做」，而在稳定性、可控性、可审计性与业务闭环——这四项才是决定 Agent 能否进生产的门。 📎 AI前线 · 蚂蚁 QCon 实践 📎 Google Antigravity · 权限与沙箱

  • 6. 对「安全叙事」保持独立判断，用自身风险模型做采购决策

    当模型厂商既是安全标准的倡导者、又是能力销售的最大受益者时，其立场的双重性值得被计入判断。Amodei 的「把控前沿节奏」、Altman 的声援、黄仁勋的反对、以及「AI 末日机器」式的资本关系质疑在同一天并存，本身就是信号。采购与合规决策应回到自身的风险敞口、审计证据与数据主权要求，而不是被任何一方的叙事牵引。 📎 AI前线 · 三人同台 📎 AI Will · 特朗普电话 📎 AI Will · 黄仁勋表态 📎 创业邦 · 「AI 末日机器」质疑 📎 硅星人Pro · 谁在制造 AI 焦虑
