上下文工程 · Agent 架构

从“规则堆叠”到“证据驱动”：Claude Code 的上下文工程新法则

Anthropic Claude Code 团队发文披露，面对 Claude Opus 5 与 Fable 5，他们删除了超过 80% 的系统提示词，编码评测却未出现可测量损失。这一结果挑战了当前许多企业部署 Coding Agent 时的默认假设：越多规则、越多约束、越多示例，模型表现越稳定。事实恰恰相反，过度约束会限制模型的判断空间，导致其机械执行而非真正理解上下文。

对企业 CTO 而言，这意味着在构建内部 Agent 时，应重新审视 CLAUDE.md、Skills、系统提示词与自动记忆的职责边界。新的最佳实践倾向于：用清晰的工具接口和高质量的参考材料替代冗长规则；让模型基于 surrounding context 自主判断；通过 Eval 持续验证删减规则后的表现。这不仅能降低上下文成本，也能让 Agent 更快适应新模型版本，避免每次升级都需要重写一本人肉手册。

腾讯开源三大具身基座模型，机器人 Agent 框架需要原生重构

腾讯 Robotics X 在 WAIC 2026 期间开源 Hy-Embodied-VLM-1.0、Hy-Embodied-RxBrain-1.0 与 Hy-Embodied-VLA-0.5 三款基座模型，并推出原生机器人智能体框架 TairosAgent。据首席科学家张正友介绍，通用智能体框架 OpenClaW 移植到机器人后效果极差，因为浏览器可以等待数十秒响应，机器人不能。TairosAgent 将上层任务理解与智能体交互压缩至 2–3 秒，而涉及碰撞、失衡的身体反应则需要更快的实时闭环。
