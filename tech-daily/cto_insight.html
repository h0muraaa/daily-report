AI落地AI的企业级ROI：从"生产力幻觉"到可量化收益

这两个看似矛盾的信号指向同一个判断：AI的价值实现高度依赖场景选择和组织适配。NHS的成功在于其针对高重复性、高时间成本的文档和行政工作，且有清晰的度量体系。而对许多企业来说，AI仍停留在"让团队更快地产出更多半成品"的层面，缺乏端到端的价值闭环。

知识管理Anthropic内部Skills体系公开：工程知识资产管理的新范式

Anthropic首次公开其内部团队使用Claude Code Skills的完整方法论。其核心观点纠正了一个常见误解：Skill不是"几段提示词"，而是一个围绕任务组织的文件夹，可包含SKILL.md、参考文档、脚本、模板、示例、hooks，甚至可被后续任务读取的数据。

Anthropic将内部Skills分为9类，覆盖从知识补充(library/API reference)、产品验证(product verification)、数据获取，到代码生成、部署、排障和运维的完整软件工程生命周期。其中"产品验证"类Skills尤为值得关注——它负责在无头浏览器中完整跑通注册和结账流程，确保AI生成的代码在实际环境中可工作。

更深层的信号是：Anthropic代码库中超过80%的代码已经由Claude编写。CEO Dario Amodei所称的"递归自我改进"(Recursive Self-Improvement, RSI)不再是理论推演，而是正在发生的工程现实。这意味着AI公司的竞争力将越来越取决于"AI能多好地改进自身"。

CTO视角 · 行动建议

本周值得推进的三件事

1. 启动"隐性知识"盘点项目
选择1-2个关键业务领域，组织资深工程师将其决策逻辑、常见陷阱和最佳实践整理为可复用的Skill/文档资产。目标不是产出更多文档，而是让AI助手能在这些知识的加持下产生更高质量的输出。

2. 建立AI产出的"质量-数量"双轨度量
为每个AI试点项目同时追踪"产出量"(代码行数、文档数、响应数)和"质量指标"(bug率、回滚率、用户满意度)。避免团队陷入"用AI做得更快"但"做得更差"的陷阱。

3. 评估模型供应商的多元化策略
Notion禁用Anthropic的事件是一个警示：单一模型供应商依赖在生产环境中是不可持续的。评估在核心产品功能中引入模型fallback机制的技术可行性，并制定至少两家供应商的并行接入计划。
