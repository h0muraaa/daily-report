02深度分析

"Agent = Model + Harness"：开源 Harness 正在重定义 AI 应用层，模型不再是唯一战场

把今天关于 Agent 基础设施的几条消息拼在一起，能看到一个清晰的战略信号：模型正在商品化，而承载模型的"Harness（运行时/编排层）"正在成为新的护城河。DeepSeek Harness 以 MIT 协议开源，微内核 + 可热重载，最新版已支持多模态与子 Agent 调度——它的设计目标不是给白领做办公工具，而是让 coding agent 自己能修改、进化这套运行时（海外独角兽称之为"自进化 Agent 的基石"）。另一边，OpenAI 把开源 Codex harness 推向企业场景：Codex SDK 支撑思科 App Builder、税务申报试点用 Codex 处理 7000 份申报、把准备时间压缩约三分之一，Asana 用 Codex 两周完成前端测试迁移（此前按年计）。CopilotKit 则推出了 Grok Bot 的开源替代 OpenBot，主打"动作发生前先拍板、发生后全程留痕"的企业治理；MiniMax Design 把多模态模型 H3 变成"从操作像素到操作语义"的创作 Harness。

对企业 CTO 而言，这个格局意味着三件事。其一，Agent 运行时已成为独立的选型维度——是否可观测、可审计、可热重载、支持多模型与子 Agent 编排，比"用哪个模型"更能决定交付质量；LangSmith Preview Builds（每个 PR 自动起一个生产近似环境测试 agent 改动）与 InfoQ《给 Agent 做 CT》所代表的 Agent 可观测/质量保障体系，正是这一需求催生的新工程层。其二，开源 Harness 把基础设施议价权交还给了企业——DSH 的 MIT 协议、Codex 的开源 harness、OpenBot 的全开放，意味着企业可以在自有技术栈内长出自己的 Agent 平台，而不是被某个封闭 SaaS 锁定。其三，国产办公 Agent 正在形成正面竞争——扣子桌面端上线、云盘双向同步、自动识别本地 Codex CLI / Claude Code 接入多 Agent 协作，字节"三英战吕布"式的办公 Agent 卡位战已经打响。

AI 经济的"管道化"再确认：从 Stripe 收购 OpenRouter 到任务级成本经济学

今天最值得深读的一条价值线索，是资本与数据同时指向"AI 经济管道化"：钱与竞争正在向算力、路由与成本治理层集中，任务级成本正在取代 Token 单价成为企业的采购基准。Stripe 以 75 亿美元收购 OpenRouter，是把"模型路由 + 结算"收编进支付帝国——OpenRouter 作为"高性能、中立的模型路由层"，恰好卡在模型供给与企业需求的中间，成为 AI 时代的"汇兑层"。Agent Arena 的数据给出了同样的经济学：DeepSeek-V4-Pro 在开源模型里排名第 2，中位任务成本仅 0.21 美元，正在"重塑 Agent 竞技场的经济性"；即便在前 5 名内，单任务成本也从 Kimi K3 Max 的 0.62 美元到更低的区间不等——性价比而非绝对值，成为模型选型的核心变量。

更进一步的信号来自"以验证器换性能"的实验：斯坦福团队给 DeepSeek V4 Flash 套上开源验证框架（先生成 5 套方案、再让 AI 选出最可靠的一版），竟在 Terminal Bench 2.1 上反超 Fable 5，成本上涨约 8 倍后仍只有 Fable 5 的 1/11，框架登顶 GitHub 热榜第二。这与 GLM-5.3"不换基座、纯靠后训练把编码能力提升 50%"（743B MoE、激活约 40B）共同构成"后训练 Scaling Law"叙事：唐杰称之为"参数的死亡"——决定智能水平的不再是参数量，而是后训练数据、方法与验证机制。对技术管理者，启示有两点：一是把"验证器/评估器"作为基础设施投资，它可以显著放大低价模型的可用性能，是当前性价比最高的成本杠杆；二是战略上把路由/网关/成本治理层当作自建资产——它既是控本工具，也是未来与模型供应商议价的支点。

04CTO 视角 · 行动建议
  1. 把"模型路由 / 网关 / 成本治理层"当作自建资产，而非采购单品。Stripe 收购 OpenRouter 证明模型路由是 AI 经济的关键汇兑层；Agent Arena 的中位任务成本（0.21–0.62 美元）与 DeepSeek 调价事件则说明成本曲线波动剧烈。建议：自建或引入任务级路由网关，统一多模型接入、限流、计量与成本核算，把它作为控本与议价的支点，同时为任一供应商的时间表与定价波动预留冗余。 [来源: 小互] · [来源: Arena.ai]
  2. 把 Agent Harness 纳入独立选型维度，评估标准聚焦"可观测、可审计、可热重载、多模型"。DeepSeek Harness 开源、Codex harness 进企业、OpenBot 主打治理，说明运行时层正在成为差异化战场。建议：为关键 Agent 工作负载建立 Harness 评估矩阵，考察其对长任务的中断恢复、子 Agent 编排、工具调用审计与版本热更新的支持，并优先选择不绑定单一模型供应商的方案。 [来源: InfoQ] · [来源: Berryxia.AI]
  3. 把"验证器 / 评估器"作为基础设施投资，用低成本模型兑现高可用性能。斯坦福团队用开源验证框架让 DeepSeek V4 Flash 以 1/11 成本反超 Fable 5；GLM-5.3 纯后训练 +50% 编码能力。建议：在推理流水线中引入"生成多方案 + 模型自验证"的验证层，建立任务级评测集（覆盖至少 2 家高能力供应商 + 1 个开源/端侧模型），让性价比而非绝对值成为选型基准。 [来源: AI前线] · [来源: 宝玉]
  4. Agent 治理先行：把"代码冻结/权限边界/审计留痕"从口头指令变成可执行机制。Rootly 因 AI 写码而废止小 PR 规则、Decawork 点明"指令不是边界"、OpenBot 主打"动作前拍板、动作后留痕"。建议：为 Agent 建立身份、权限、凭证与审计的统一治理面，让 AI 生成的代码走与人类同级的评审与测试流水线，并预先定义"Agent 可自主执行/需人批准"的边界矩阵。 [来源: AI前线] · [来源: Martin Fowler]
  5. 在技术栈中为"开源 + 端侧"模型留出位置，应对数据主权与成本约束。DeepSeek-V4-Pro 开源榜第 2、Qwen3.8-Max 前端代码榜压过 Claude Fable 5、企业支出加速转向 open-weight。建议：将开源/端侧模型纳入评估（数据主权、离线、高并发优先），关注后训练能力（GLM-5.3 同基座 +50%）与推测解码等推理加速技术带来的成本红利，形成"开源高性价比 + 闭源前沿能力"的组合供给。 [来源: Arena.ai] · [来源: a16z]
  6. 关注"验证型 AI"在高价值实体产业的窗口：AI for Science 的组织能力要提前布局。Moderna mRNA-4157 三期成功，核心是 AI 参与新抗原筛选的"一人一药"范式在千人级试验被验证；OpenAI 也在把 Codex 用到税务申报等严肃场景。建议：审视自身行业中"模型编排 + 独立验证"的新工作流机会——科学/医疗/制造等领域，可复现的验证机制就是可规模化的竞争壁垒。 [来源: 网易科技] · [来源: Greg Brockman]
