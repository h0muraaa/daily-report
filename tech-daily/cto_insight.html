02单位经济

企业 token 用量涨 65%，支出只涨 1.5%：AI 正在变成通缩型商品

企业财务软件公司 Ramp 的数据显示，从 8 月初到 10 月中，企业消耗的 token 增加约 65%，而花在 token 上的钱只多了 1.5%；月度支出环比从 7 月的 +42% 骤降到 8 月的 +1%、9 月的 +0.2%。原因有三层：模型厂商主动降价（9 月 GPT-6 Sol 输入价格从每百万 token 4 美元砍到 2 美元；Anthropic 称 Fable 5.1 让常见任务成本降约 25%、Opus 5.5 每任务成本比 Opus 5 低约 40%）；企业学会了设预算并把任务路由给更便宜的小模型；以及 Jev 等新一代廉价模型入场。结果是 OpenAI 与 Anthropic 的综合单价在 9 月下旬到 10 月下旬一个月内从每百万 token 0.76 美元降到 0.56 美元。对 CTO 而言这是采购侧的利好，但也是供应商收入模型的结构性风险——用量增长不再自动等于支出增长，按 token 计价的合同需要重新设计。

03估值重定价

Anthropic 估值一周内从 2 万亿跌向 1 万亿，S-1 暴露“成本长租、收入短租”

据 WSJ 与 Bloomberg，三家计划参与 Anthropic IPO 的大型投资者表示估值需要下调，其中一家认为可能接近 1 万亿美元，较一周前的 2 万亿美元预期接近腰斩。更值得技术高管关注的是招股书里的运营数据：收入同比增速从 Q2 的 144% 降至 Q3 的 45%；净收入留存率高达 900% 但基数太小参考价值有限；云厂商分成约 37%；长期算力合同总额接近 9000 亿美元。晚点聊的拆解指出，真正的风险不在合同总额而在刚性——成本是长租、收入是短租，形成类似 WeWork 的期限错配。这意味着未来 12 个月模型厂商会更强硬地推动企业长约、预付费与结果定价，CTO 在谈判桌上应把“降价传导条款”和“退出/缩容权”写进合同。

OpenAI 发布基于 GPT-6 Astra 的网络安全专用模型 GPT-6 Cyber，在 ExploitGym 基准上成功率从上一代 GPT-5.6 Cyber 的 32.1% 提升到 48.5%（相对提升约 51%），RemoteExploitBench 完成 95% 任务，并被 OpenAI 在 Preparedness Framework 下评为最高档 Critical（前代为 High）。真实战果包括：在 Mozilla 已用前沿模型审查数月的 Firefox 中仍找出 81 个此前未知的高危漏洞，并把 30 个已知问题的严重级别上调；在 Linux 内核中从 2308 条候选收敛到 1724 个可复现漏洞、948 个可用的本地提权利用，整轮 API 成本约 121 万美元、折合每漏洞约 1279 美元。模型仅通过 Daybreak Red 计划向审核通过的安全团队开放，不开权重，不面向普通用户。安全团队的工作重心将从“人工写规则做筛查”转向“验证机器提交的漏洞与补丁”。

05组织形态

“局部更快、整体不快”：企业 AI Native 的瓶颈已经不在工具

阿里云智能集团副总裁、CIO 蒋林泉复盘三年 AI 实践，给出一个反潮流的判断：AI 生码率飙升，端到端交付却没有变快；通用 Agent 提升了办公生产力，整体业务效能却未同步提升。他因此把 AI Native 定义为组织问题而非工具问题——需要 CIO 与 CPO 联动，同时在系统侧和组织侧发生改变，工具定义能力边界，组织决定能力能否进入真实工作。这一判断有一线数据佐证：Perplexity 的人均 agent-hours 比 9 月增长了 7 倍，五分之一员工每周已达 40 小时以上（相当于多一个完整工作周）；但 AI Engineer 峰会上的观察是，给每个员工一个 Agent 并不等于有了流程，两个缺口分别是“用户被迫管理 Agent 的复杂度”和“每个员工自创一套 workflow”。沃顿教授 Mollick 的说法更直接：程序员的新工作是“经理”，监督 AI 比派任务更难，不能把 Agent 当“一键完成”。

供给侧的定价逻辑正在被自己打破

过去两年，模型厂商的估值模型建立在一个简单假设上：token 用量会持续指数增长，而单价保持稳定或缓慢下降，于是收入随用量线性放大。Ramp 的数据直接证伪了这个假设的后半段。企业侧的用法已经成熟：会设预算、会把长任务从最贵的模型路由到便宜的小模型、会用路由工具按任务难度分配算力。Ramp 首席经济学家 Ara Kharazian 的说法是，AI 用得越熟的公司，越不会让所有任务都跑在最贵的模型上。这意味着降价不是短期促销，而是需求侧结构性行为变化的结果——即使厂商停止降价，支出也不会按用量的斜率增长。

厂商自己的降价还在加速这一过程。9 月 GPT-6 Sol 的输入价格直接砍半；Anthropic 在招股书中承认 Fable 5.1 让常见任务成本降约 25%、Opus 5.5 每任务成本降约 40%。一边是收入增速从 144% 掉到 45%，一边是近 9000 亿美元的长期算力承诺——成本是长租、收入是短租，这正是 WeWork 式期限错配的经典结构。晚点聊的拆解把这个风险讲得很清楚：真正的风险不在合同总额，而在刚性。当需求不及预期，长租合约不会随收入一起缩水。

资本开支侧的政治约束开始显性化

同一时间，a16z 的统计显示，自 2023 年一季度以来 Alphabet、微软、亚马逊、Meta 的资本开支增长了 5–8 倍，而苹果比 AI 热潮前还少花 20%。这种分化原本被视为“谁更敢下注”的问题，现在变成了“谁更能承受反噬”的问题。中期选举后，56% 的选民表示 AI 与数据中心是他们投票时的重要或关键因素；数据中心密集的社区开始把上涨的电费、紧张的水资源与基础设施负担转化为具体的政治诉求。资本开支从财务决策变成了需要地方政府、社区与监管共同签字的公共决策——建设周期会变长，选址成本会上升，长租算力的隐含风险也随之放大。

对技术高管的三个判断

  • 不要用“用量增长”为长约背书。你的用量会涨，但你的账单不会同比例涨；按 token 承诺最低消费的合同，等于把厂商的期限错配风险转移到自己身上。
  • 把“降价传导”写进合同。模型单价在一年内可能再降 30%–50%，合同必须约定价格随公开价下调、或至少保留按季度重新议价的权利。
  • 建立多供应商的推理路由层。今天腾讯 Hy4 在 Agent Arena 的中位任务成本是 0.57 美元，DeepSeek Harness 日耗 92 万亿 token，Kimi K3.1 Pro 已进入 Devin 的工具链——成本对冲的选项比一年前多得多，缺的是把它们工程化接入的组织能力。
一句话总结：AI 的单位成本正在像带宽和存储一样走向通缩，而供给侧的资本结构却按“永不降价”的假设搭好了。这个错配会在未来 2–4 个季度持续释放，采购方的议价能力正在上升。

“发现后修复”这条路径正在失效

a16z 给出的时间序列很直白：以模型能可靠完成的最长网络安全任务衡量，2024 年底是 5.5 分钟，2026 年初是 40 分钟，2026 年 4 月是 4.8 小时——一年多扩大约 52 倍，翻倍周期 4–5 个月。与此同时，漏洞利用的加速并没有带来修补速度的同步提升：从公开补丁到可用 exploit 被压缩到数小时，而企业打补丁仍以周计；很多老旧路由器、摄像头、超市冷柜永远等不到修复。医疗行业的例子最能说明后果——2018 到 2024 年确认的勒索攻击增长约 6 倍，单次攻击导致的平均停机天数从 4 天升至 18 天。

架构上的三个转向

  • 从“发现即修补”转向“隔离与分段”。a16z 的结论是：问题不是如何更快打补丁，而是如何不再需要打补丁。当 exploit 的生成速度快于补丁的分发速度，网络层的分段、最小权限和运行时隔离比“等厂商发版”更可靠。
  • 从“静态凭证”转向“按请求授权”。Edera 新发布的 Object Capability Bounded Authority 用 hypervisor 强制的能力边界，把 Agent 或 MCP Server 的权限与其背后的凭证分离，凭证不再存放在工作负载里；首批覆盖受限命令执行与工作负载身份，后续才做凭证代理的 API 访问。
  • 从“工具采购”转向“持续验证”。AWS Continuum 已 GA，做法是在沙箱里真正跑 exploit 来证明可利用性，再自动开 PR 修；按“处理的 finding 数 + 代码行数”计价，业界正在追问的是“什么条件下才敢让它自动合并修复”。GitHub Actions Lockfiles 已 GA，GitLab 19.5 把 MCP Server 与外部 Agent 纳入受治理的 DevOps 平台——供应链与 Agent 权限正在成为同一张治理图。
给你的安全团队一个具体动作：把“AI 红队”纳入 SDLC 的常规环节，并对每一个高危资产问三个问题——它的爆炸半径有多大？在没有补丁的情况下能否被隔离？凭证是否能在分钟级失效？如果三个答案都是否定的，这个资产就是本轮攻防曲线变化中最先失守的部分。

04

CTO 视角

未来一个季度可以落地的六件事

  1. 重谈 AI 供应商合同：把“降价传导”和“缩容权”写进去

    模型单价一个月降 27%、收入增速从 144% 掉到 45% 的背景下，按 token 承诺最低消费的长约等于替厂商承担期限错配。优先争取随公开价下调的条款、按季度重新议价的权利，以及明确的退出与缩容机制。

    衡量指标：单位任务成本（$/任务）而非 $/百万 token

  2. 把 KPI 从“token 消耗量”换成“单位任务成本 × 完成率”

    Ramp 已经证明用量增长与支出增长可以脱钩，继续用 token 消耗量考核 AI 投入会误导资源分配。建立按业务任务归集的成本与成功率看板，才能判断该加码还是该换模型。

    衡量指标：每个业务任务的全链路成本与一次通过率

  3. 安全架构前移：隔离、分段、按请求授权

    当 exploit 的生成速度超过补丁分发速度，“发现后修复”不再是可行策略。优先改造爆炸半径大的资产：网络分段、运行时隔离、分钟级失效的凭证，以及能证明备份可恢复的演练机制。

    衡量指标：高危资产的隔离覆盖率与凭证有效期

  4. 给 Agent 建治理，而不是给每人发一个 Agent

    “每个员工自创 workflow”是熵增的典型来源。设立 Agent 的预算、权限、日志与复用标准，指定负责人维护共享的 Agent 目录，把个体经验沉淀为组织流程，而不是让复杂度转移到使用者身上。

    衡量指标：复用型 Agent 占比与人均 agent-hours

  5. 算力与选址：多云 + 推理路由，避免单一长租锁定
