设计趋势洞察

从「复制网页」到「Agentic Web」：AI 正在重写界面设计的入口

Figma 的新 Chrome 扩展让「复制任意网站到可编辑图层」成为可能，设计师再也不用从零开始复刻参考站点。这一功能背后，是 AI 时代界面生产流程的进一步前置：参考 → 解构 → 编辑的周期被压缩到一次粘贴。

与此同时，Google 的 WebMCP 标准提案进入 Chrome 149 源试用阶段。它允许网站向浏览器内 AI Agent 暴露工具（如 JavaScript 函数和 HTML 表单），让 Agent 能够可靠地模拟用户行为，而不是依赖昂贵且不可靠的屏幕阅读或 DOM 抓取。这意味着未来的「界面」不再只是给人看的，也是给 AI 消费的。

设计洞察：设计师需要开始思考「双用户」体验——人类用户与 AI Agent 用户。组件语义化、可访问性、清晰的表单与动作边界，将成为 Agent 能否正确理解界面的关键。

产品体验点评

GitHub Copilot：Agent 不是越勤快越好

GitHub 最近在博客中分享了 Copilot CLI 的「smarter subagent delegation」改进。他们发现，在 Agentic 系统中，更多委托并不总是更好：不必要的子代理交接会带来协调开销、工具调用和等待时间，反而让简单任务变复杂。

新策略让主代理直接处理聚焦工作（查找、阅读、编辑、验证），只在需要独立上下文、广泛探索或并行执行时才委托子代理。结果是工具失败率降低 23%、搜索失败率降低 27%、编辑失败率降低 18%、P95 等待时间降低 5%。

UX 启示：AI 助手的「主动性」需要精细校准。过度热心的代理会把帮助变成摩擦；好的 Agent 交互应当「从最小有效路径开始，在复杂度或不确定性真正创造价值时再升级」。

来源：The GitHub Blog

阿真简历生成器：把「排版焦虑」压缩到一个页面

作者阿真为正在求职的弟弟做了一款 AI 可视化简历生成器，解决的核心痛点是：简历内容已经写好，但从 Word 模板到可投递成品之间，还要反复调整字号、裁头像、调模块顺序、压缩到一页、导出 PDF 后格式又不对。

工具的交互路径被压缩为一句话：「左边选风格，上方选布局，中间直接改内容，右边调细节，顶部负责导入和导出」。它把导入、编辑、排版、AI 优化、保存、导出放在同一页面，并支持基于目标岗位 JD 优化文案，降低求职者从「有内容」到「能投递」的心理成本。

UX 启示：很多工具看似在解决「生成内容」，真正拖慢用户的其实是「最后一公里」的格式与排版。把导出、预览、微调放在同一视图，能显著减少任务切换和焦虑。

研究方法论

当 AI 成为「认知拐杖」：Anthropic 研究揭示技能退化风险

Anthropic CEO Dario Amodei 提到，Anthropic 的研究证实：粗心使用 AI 模型会导致可测量的技能退化。这引出了一个用户研究和人因工程都必须正视的问题——当 AI 承担越来越多认知任务时，人类用户的判断力、注意力和专业能力如何在长期协作中保持？

与此同时，Dario 也指出，最具长期价值的职业将是「以人为中心」的职业——混合了人、物理世界和分析技能的工作。对于 UX 与用研从业者而言，这意味着研究方法本身需要升级：不仅要评估「AI 能做什么」，更要持续追踪「AI 如何改变人的能力、习惯与自我效能感」。

方法建议：在研究 AI 辅助产品时，除了可用性测试，建议加入「认知负荷测量」与「长期技能跟踪」。例如对比用户在依赖 AI 前后，独立完成任务的成功率、自信心和错误恢复能力。

创始人出镜：产品信任的最小可行单元

Zara Zhang 在 X 上分享了一个观察：病毒式传播的产品往往有一个能被看见、被听见的创始人；创始人的屏幕录制胜过企业宣传片或功能墙。这条推文被 Marc Lou 引用，他在自己的产品传播中同样强调「Show your face」。

从用户研究角度看，这验证了信任建立的一条路径：当用户能看到真实的人，产品就不再是冷冰冰的机构，而是一段可被理解的关系。对于独立开发者和小团队而言，创始人 persona 本身就是产品体验的一部分。

方法建议：在品牌与增长研究中，可以把「创始人可见度」作为一个实验变量，测试不同类型的产品介绍（真人演示 vs. 功能清单 vs. 企业宣传片）对转化率、信任度和 NPS 的影响。
