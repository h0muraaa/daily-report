1AI 正在模糊"设计师"与"工程师"的边界

Anthropic 设计负责人 Meaghan Choi 公开演示了内部设计师如何用 Claude Code 完成从原型到代码提交的全流程。她的核心洞察是：产品节奏越来越快，但工作方式还没跟上。设计师不再只是画稿的人，而是需要具备"用 AI 把想法变成可运行产品"的能力。她使用的 Prompt 结构也值得借鉴：先调用自定义 /prototype Skill 生成 5 个不同实现方案，再让 AI 评估优劣，最后迭代到可交付状态。

2Airbnb 创始人入局 AI 设计模型，"设计品味"成为新赛道

Brian Chesky 正在筹备创建一个新的 AI Lab，专门构建用于 UI 和设计的模型。Airbnb 的设计能力在业界有口皆碑，这次从"用好设计"转向"让 AI 学会设计品味"，意味着设计能力的 AI 化可能进入新阶段。对 UX 从业者而言，这不仅关乎工具效率，更关乎"AI 是否能理解和复制人类的设计直觉"这一根本问题。

[来源: meng shao @ X]
3从"写代码"到"看见代码"：AI Coding 工具的交互范式跃迁

今天有多款产品在同一天推出可视化能力：OpenAI Codex 发布 Build iOS Apps 插件，让开发者在对话窗口内直接查看 iOS 模拟器运行画面和 SwiftUI 预览；Cursor 推出 Design Mode，支持在浏览器中直接点击、圈选、语音修改 UI；Cursor Canvases 则可以一键创建仪表盘、报表等内部工具。这标志着 AI Coding 从纯文本交互进入"所见即所得"的图形化闭环阶段，对设计师来说意味着更短的"设计 → 实现"反馈回路。

5AI 生成设计如何避免"AI 味道"？社区正在形成共识

多位独立开发者和设计师在社交媒体上分享了一套避免 AI 生成设计同质化的方法论：不要直接用 GPT 生成设计、使用 Design.md 建立设计规范、用参考图片引导视觉方向、在 Agents.md 中设定 design rules。这套流程的本质是将"设计品味"从模型内部的黑箱中提取出来，变成可复用、可迭代的设计资产。对 UX 团队来说，这意味着设计系统的价值在 AI 时代不降反升。

💡 设计趋势洞察

趋势

AI 终端的交互范式重构：手机正在等待一场"原生 AI 体验"革命

爱范儿在 AIDONE 第五期中提出一个核心观察：过去半年 AI Agent 的主战场在桌面端，但 AI 要真正进入一个人的生活，最终一定会来到手机上。手机拥有摄像头、麦克风、位置、日历、通讯录，装载着用户几乎全部的"上下文"，更重要的是它"一直在你身边"。

然而现状是：用户已经在用语音、截图、拍照、录音来调度 AI，但终端系统、交互方式和底层能力并没有跟上。这形成了一个有趣的"民间智慧领先于系统设计"的局面 — 最敏锐的 AI 用户正在用飞书等工具拼出属于自己的移动终端工作流。

从 UX 视角来看，这提出了一个关键问题：当用户不再打开单个 App 完成任务，而是通过语音/截图/拍照直接调度 AI 时，"应用"本身的边界在哪里？手机厂商和操作系统设计者需要回答的不是"如何加一个 AI 功能"，而是"如何重新定义人与手机的交互关系"。腾讯与华为、荣耀、小米、OPPO、vivo 合作的 A2A（Agent-to-Agent）助手能力，正是这种探索的一个信号。

[来源: 爱范儿] · [来源: 爱范儿早报]
趋势

从 Figma 到 AI 原生设计：设计工具的范式正在转移

过去两年，设计工具的主线是"协作"（Figma 的多人实时编辑）和"系统"（Design Token、组件库）。但今天的信号表明，下一个范式可能是"AI 原生生成"。Replit Canvas 让用户用 AI 创建 UI 设计、生成资产（通过 GPT-Image 2 和 Seedance），再一键转为可发布的应用。Cursor Canvases 则可以创建仪表盘、报表和内部工具并直接分享给团队。

这背后的用户洞察是：大量的"内部工具"和"简单应用"需求长期被压抑，因为设计和开发成本太高。当 AI 可以打通"设计 → 代码 → 部署"的完整链路时，这些被压抑的需求会快速释放。对设计团队而言，这意味着工作重心可能从"画界面"转向"定义设计规则和标准"，让 AI 在规则的约束下生成符合品牌调性的界面。

🚀 产品体验点评

产品

Codex for Sales Teams：AI 如何重构 B2B 客户体验

OpenAI 分享了一个有趣的用例：销售团队使用 Codex 来加速客户问题响应。具体场景包括：5 分钟内拉取客户查询所需的数据、为客户对话创建演示和原型、发送包含账户特定信息的 Slack 更新、用销售人员的语气撰写沟通内容。

从客户体验视角看，这解决了一个长期痛点：B2B 客户的问题响应速度和质量往往取决于销售人员的个人能力和信息获取效率。当 AI 可以快速聚合账户信息、生成个性化回复甚至搭建演示原型时，客户感受到的"被重视程度"和"服务专业性"会显著提升。关键是"用销售人员的语气撰写"这一点 — 它体现了 AI 在保持品牌人格一致性方面的价值。

[来源: OpenAI]
产品

TinyShip：独立开发者的"用户驱动迭代"样本

独立开发者 Viking 的 TinyShip 项目即将上线推广返佣功能，这个功能来自"几个用户一直要求"。这是一个典型的用户驱动产品迭代的案例：开发者快速响应真实用户需求，设置动态/固定比例返佣，同时把 KYC 和提现功能开放给用户自行选择实现方式，而不是写死一套流程。

这种"核心功能标准化 + 边界功能模块化"的设计思路值得产品团队借鉴：它既满足了大多数用户的核心需求（推广返佣），又保留了灵活性，让有能力的用户可以按需扩展。对 UX 研究者来说，TinyShip 的迭代路径也是一个观察"小团队如何基于用户反馈快速试错"的生动样本。

[来源: Viking @ X]
产品

Kami AI 排版设计系统：AI 时代的内容呈现工具

Tw93 分享的 Kami AI 排版设计系统最近更新了多个功能模块：网页落地页生成、Marp 幻灯片模式（Markdown 转 PPT）、多语言支持（新增韩语）、品牌 Logo 导入、代码自动语法高亮。一个有趣的细节是：Kami 虽然被归类为 Skill，但 70% 的底层都是代码而非 Markdown。

从用户研究视角来看，Kami 解决了一个真实但容易被忽视的需求：AI 生成的内容越来越多，但"好内容值得好版面"的呈现需求并没有被很好满足。很多 AI 生成的报告、文档在视觉呈现上仍然很粗糙。Kami 的定位是"让工程师也能做出好看的内容"，这正好契合了"Vibe Coding"时代非设计背景用户的设计需求。

方法

Vibe Usage：量化你的 AI 使用行为

当 AI 工具越来越多地嵌入日常工作流，一个基础但重要的问题浮现出来：你真的知道自己把 AI 用在了哪里吗？稀土掘金上介绍的 Vibe Usage 工具试图回答这个问题 — 它追踪用户使用 AI 的过程数据，包括 Token 消耗分布、项目维度统计、工具对比、模型效率分析等。

对 UX 研究者来说，这个思路可以扩展到更广泛的研究场景中。当我们谈论"AI 使用体验"时，不能仅依赖定性访谈，也需要行为数据的支持。Vibe Usage 提出的核心问题具有普遍研究价值：你是在变得更高效，还是只是更习惯性地把问题丢给 AI？你花掉的 Token 最终换来了什么？这些问题对于评估 AI 工具的真实用户价值至关重要。

[来源: 稀土掘金技术社区]

Anthropic 的"人类反馈工程"：AI 产品设计中的隐性基础设施

InfoQ 报道了 Anthropic 通过约 1000 名人类软件工程师（时薪 280 美元）来提升 Claude Code 表现的"Marlin"项目。这个项目的核心目标不是让模型"会写代码"，而是让输出"更接近专业开发者的真实工作方式"。承包商需要对两个模型生成的代码进行 A/B 对比评估。

这对用户研究实践的启示是：高质量的 AI 产品背后，往往有大量被隐藏的人类判断工作在支撑。A/B 对比评估、专业领域的偏好标注、输出质量的细粒度评级 — 这些工作本质上就是"把人类专家的隐性知识转化为模型可学习的信号"。对于正在引入 AI 功能的产品团队来说，建立类似的"人类反馈回路"可能比单纯优化模型参数更有价值。

[来源: InfoQ]
方法

MetaSkill：当 Agent 技能过多时，如何智能编排？

花叔在探索 Agent Skill 的过程中发现一个新问题：当技能越来越多，Agent 如何自主挑选、组合、按顺序接力？他在 GitHub 上的 OpenSquilla 项目（2.4k+ stars）中发现了 MetaSkill 的概念 — 让 Agent 自己决定使用哪些 Skill、以什么顺序调用。

从用户研究角度看，这触及了一个深层问题：当用户面对一个拥有数百个技能的 AI 助手时，"知道它能做什么"本身就是一个巨大的认知负担。MetaSkill 的思路 — 让 AI 自己管理技能调用 — 本质上是在降低用户的认知负荷。这与经典的"渐进式披露"设计原则一脉相承：用户不需要了解所有功能，只需要在需要的时候获得合适的能力。

腾讯 AI 下半场：Context 即护城河，产品即反馈源

腾讯 AI 产业应用大会上，汤道生与姚顺雨的对谈释放了一个关键信号：AI 行业下一阶段的核心竞争力不再是模型参数，而是模型如何进入真实场景、获得真实反馈。姚顺雨指出"Context 正在成为新的护城河"，腾讯丰富的产品场景与真实业务上下文是其他公司难以复制的壁垒。

AhaCreator 3.0：AI 原生双边平台的 UX 启示

AhaCreator 更新到 3.0，作为海外达人营销的 AI 原生平台，其核心思路是把品牌方、达人和营销全流程搬到同一个平台。值得 UX 研究者关注的是它的"AI 原生双边平台"设计：AI Agent 负责 7x24 小时执行标准化流程（筛选达人、建联、议价、催稿），人类则专注于策略判断。

这种人机协作的权责划分 — AI 做"长链路的重复性工作"，人做"需要判断和策略的工作" — 可能是未来很多 B2B 平台的设计模板。当 AI 可以处理双边市场中大量的匹配和沟通工作时，平台的核心价值会从"撮合效率"转向"策略支持"。

信号

IAA 产品的"买量陷阱"：用户体验与商业变现的张力

一篇关于 IAA（应用内广告）产品的深度分析揭示了一个反直觉的现象：头部 IAA 产品赚的其实是同行的买量费。文章拆解了两个极端案例：一方把 CPI 压到一分钱全球无差别投放，结果是买来的都是机刷流量和低价值用户，eCPM 连成本都盖不住；另一方通过 VPN 伪装印度流量为美国流量赚取 eCPM 价差。

这对 UX 和产品设计的警示是：当买量成本被过度压缩时，用户体验和用户质量往往是第一个被牺牲的东西。真正的可持续增长来自于"找到愿意为你的产品付费（或贡献注意力价值）的真实用户"，而不是在流量数字上做文章。这个洞察对任何依赖广告变现的产品都有参考价值。
