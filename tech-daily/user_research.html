当界面开始自己生长，设计师要守住什么

1

今日要点

五条可以带进需求评审与用户研究会议的判断。

01

年度最成功的个人 Agent，把“信任”当成了发布门槛。Meta 的 Muse 从树莓派上的周末原型走到正式上线用了约七个月，远比原型“能跑通”所需的时间长。产品负责人 Mona Sarantakos 的判断是：一个能碰到你邮件、日历和信用卡的助理，犯错的代价和聊天机器人完全不同，所以“让人敢把事情交给它”比“让它会做事”难得多。

02

Agent 编排界面正在成为一套新的交互范式。Google Antigravity 用一次彻底重设计，把界面重建成“并行调度多个 Agent 的工作表面”，目标是让用户即时看到多个任务的状态，并保留完整控制权。当产品从“一个对话框”变成“一群同时在干活的代理”，可见性、控制感与中断成本就成了首要的设计变量。

03

设计系统开始同时服务“人”和“AI”两类读者。Revolut 的设计团队用 Codex，把积累了七年的设计系统文档在一天内转成 AI 可读的格式，过程中还反过来发现了模板里的空白与含糊之处。与此同时，Vercel 推出了专门给 Agent 使用的组件库 UI SDK，可按技术栈生成 Prompt——设计规范的第一读者，正在从新同事变成模型。

04

小城商家是被长期忽略的 AI 新用户。美团数据显示，近一个月三线及以下城市使用美团 AI 助手的商家数量环比增长超 200%，主动发起的对话量增长约 3 倍；OpenAI 也在 11 月上线 “Businesses in ChatGPT”，让商家认领资料。对小店老板而言，AI 有没有用不取决于能不能聊天，而取决于是否懂本地生意、能帮上管钱管货管客流。

05

生成式界面从实验品走向可用产品。Runway 预告了 Diffusion-UI：模型会在用户点击或输入时实时生成界面；Google 的 Gemini Notebook 则支持一句 “make me a site”，把资料直接变成可交互的网站、数据仪表盘与讲解页面。界面不再只是被设计一次，而可能在每次交互中被重新生成——这对“一致性”和“可预期性”提出了新问题。

2

设计趋势洞察

两个正在成形的方向：界面从“被设计”走向“被生成”，以及主动型 Agent 必须学会“克制地出现”。

趋势一 · 生成式界面

从固定布局到实时生成：界面本身成了模型的输出

Runway 预告的 Diffusion-UI 是一个研究型应用：用户每点一下、每输入一次，模型就实时生成对应的界面，而不是从预先设计好的页面里选择跳转。它和 Gemini Notebook 的 “make me a site” 指向同一个方向——把“整理资料 → 生成可交互页面 / 仪表盘 / 讲解”压缩成一句话。Qwen4-Max 的实测也提供了侧证：同一主题下，一句话提示词只能复刻页面结构，而带有明确场景、翻页、放大镜、导出等约束的详细提示词，才能产出内容与交互都更完整的成品。

对设计师来说，这不只是“AI 帮忙画图”。当界面是按需生成的，传统意义上“设计一次、处处一致”的交付物被拆成了两件事：定义生成规则与约束，以及定义什么算“生成得好”。Qwen4-Max 的测试者给出的建议很朴素——先让模型把设计计划想清楚再动手，这其实是在把设计评审前置到生成之前。

实践建议：把“设计计划”当成新的设计交付物：明确场景、组件约束、交互边界与验收标准，再交给模型生成；同时为用户保留可预期、可回退的稳定外壳，避免每次生成都像换了一个产品。

趋势二 · 主动型 Agent 的克制

“有用但不烦人”：主动性也需要一套体验规则

LangChain 分享了一篇关于主动型 Agent 的文章，核心问题不是“Agent 能不能主动做事”，而是如何用记忆与 UX 让它在主动介入时“有用但不烦人”。这背后是一个经典的人机交互权衡：主动提示能降低用户的认知负担，但每一次不合时宜的打断都在消耗注意力与信任。什么时候开口、以什么形式出现、用户能否预判和关闭，都会直接影响它是助手还是噪音。

skwir 提供了另一面的答案：当人和 AI Agent 抢同一批文件容易“互相踩”时，它把每个操作都做成可撤销、可审核的计划，人和 Agent 从同一个命令入口下发指令。这与“克制”并不矛盾——好的主动，建立在可预期和可撤回之上。让用户随时能看到 Agent 打算做什么、能一键收回，才敢把更多主动权交出去。

研究课题：把 Agent 的“主动时刻”当成独立触点来测：介入时机、打断频率、关闭成本、误判挽回路径。衡量指标不应只是任务完成率，还要看用户对“被打扰”的容忍度是否随时间下降。

3

产品体验点评

两个值得逐帧拆解的产品案例：一个在回答“用户凭什么敢用”，一个在回答“用户凭什么看得懂一群 Agent”。

案例一 · 信任设计

Muse：用七个月，换用户“敢交出第一件事”

Muse 的起点极其个人化。Mona Sarantakos 在树莓派上装了早期的 OpenClaw，只写了几句指示，让程序翻学校通知并生成每日简报；那个最容易手忙脚乱的周一早上，它把当天要留意的事和一周活动整理好了。真正的产品化却花了约七个月——团队原本甚至计划 2026 年底到 2027 年再做个人智能体，是这次实验让他们决定立刻动手。

这七个月最大的投入方向不是功能，而是“信任”。Mona 的两句话点出了关键：“你不信任这个智能体，就根本不会用它”，以及“大家写第一条指令时会卡住”。前者意味着可靠性与犯错成本必须前置解决；后者则是一个被低估的体验断点——首次使用时的空白与不确定，往往比功能缺失更早劝退用户。购物需求的意外浮现，也说明用户会自然地把 Agent 带进真实生活，产品要为这些“计划外但高频”的场景提前设计好安全边界。

设计启示：大众市场不缺更强的 Agent，缺的是“不会让我不安的 Agent”。把首次指令引导、失败可撤回、结果可核对当作核心体验指标，可能比多十个能力更能决定留存。
📎 来源：晚点再听LaterCast · Muse 复盘 📎 来源：深思圈 · Muse 负责人访谈
案例二 · 编排界面

Antigravity 重设计：把“多个 Agent 并行”做成一目了然

Google 的 Antigravity 本周做了一次彻底重设计，官方说法是“从底层重建为一个用于并行编排多个 Agent 的表面”，核心诉求是让用户获得即时可见性和完整控制。Varun Mohan 也确认这是“step change”级的界面改进，并点名了设计负责人。这条更新的价值不在于视觉更好看，而在于它回应了一个正在扩散的新场景：用户同时让多个 Agent 干活，却不知道谁在做什么、卡在哪一步。

当工作单元从“一个会话”变成“一群并行任务”，界面要解决的是状态的总览与可干预性——哪些任务在跑、进度如何、失败在哪、能不能暂停或接管。这与过去单线程聊天式界面的心智模型完全不同。可以说，Agent 产品的竞争正在从“模型多强”转向“用户能不能看懂、能不能控制”。

体验启示：为多 Agent 场景建立“任务总览层”：用统一的状态语言（运行 / 等待 / 失败 / 需确认）和可下钻的操作入口，降低用户管理并行任务时的认知负荷。

研究方法论

两种值得纳入研究工具箱的做法：用盲测与 Elo 量化主观偏好，用业务 Benchmark 把“像不像”换成“任务是否真的完成”。

方法一 · 盲测偏好测量

Avatar Arena：让用户“不知道哪个是自己的”来做评判

HeyGen 公布了 Avatar Arena 的结果：在盲测中，参与者要么克隆自己的形象、要么选择预设主播，两个供应商拿到同一段脚本，投票者在不被告知哪段来自谁的情况下选更好的结果，结果显示“投票者分不出哪个是我们的，却还是把 Avatar 6 选为两个榜单第一”。两个排行榜分别覆盖个人形象（1,197 Elo）与预设主播（1,237 Elo），并对 Creatify、Veed、Captions、Runway、Tavus、Jogg、Synthesia 等做了横向对比。

这套方法的可借鉴之处在于用盲测剥离品牌光环，用 Elo 把主观偏好变成可比较的序数。做体验研究时，我们常被“用户说喜欢”困住，而盲测 + 成对比较能更接近真实感知差异；对生成类产品（头像、配音、界面）尤其适用，因为它衡量的正是“用户无法命名、但一眼能感知”的质量。

落地建议：对主观质量强的功能，优先设计成对盲测而非绝对打分；用 Elo/胜率替代“1–5 分满意度”，并在同一脚本、同一任务的公平条件下比较，减少解释成本。
📎 来源：HeyGen · Avatar Arena 盲测结果
方法二 · 业务 Benchmark 闭环

美团 Agent 评测白皮书：判断“能不能上线”，要看整条任务链

美团技术团队发布《Agent 评测白皮书》业务实践篇，以“商家广告助手”的巡检任务为例，讲如何构建业务 Benchmark、校准评测器、做错误分析，并借助持续回归与模型选型形成闭环。文章强调一个关键转向：判断 Agent 能否用于生产，不能只看最终回答“像不像对的”，而要验证整个任务——意图与时间范围是否理解准确、数据与工具调用是否正确、关键规则是否遵守、最终账户状态或交付物是否符合预期。

这对用户研究很有启发：把“可用性”从单点回答质量，扩展到端到端的任务达成。公开 Benchmark 只能复用其任务设计、环境构造与判定方法，具体业务仍需建立自己的 Task 集与 Rubric。本质上，这就是把过去“观察用户走完流程”的可用性测试，翻译成可规模化、可回归的 Agent 评测——先找问题，再用人类研究解释“为什么”。

方法提示：为每个 Agent 任务写清“成功标准 + 判定 Rubric + 执行环境”，把错误分析结果反哺到评测集与产品设计；对关键链路上的规则遵守（如权限、审批、预算）做硬约束，而非只写进提示词。
📎 来源：美团技术团队 · Agent 评测白皮书 02

UX 雷达

今天值得收藏、暂时还不用下结论的早期设计信号。

01

Gemini Notebook：一句话把资料变成可交互网站

Gemini Notebook 新增能力：在聊天框输入 “make me a site”，描述想要的页面，再点 “Open in a new tab”，就能打开或分享生成的网站。它不只生成文字摘要，还能做数据仪表盘和可视化讲解页面。值得关注的是它对“研究产出物”的重新定义——从一份静态报告，变成可交互、可分享的解释性页面，可能改变研究交付的形态。

📎 AI Will
02

Vercel UI SDK：第一个“为 Agent 设计”的组件库

Vercel 推出面向 AI 的设计组件库 UI SDK，页面底部可按技术栈生成对应 Prompt，也可以直接让 Agent 访问站点获取组件信息。社区反馈的用法很务实：想避免 AI 生成界面时的“Slop 味”，就用 Vercel 式黑白灰配色，别让模型随意发挥或使用系统默认丑组件。设计系统的消费者，第一次明确地包含了模型本身。

📎 向阳乔木 · UI SDK 📎 向阳乔木 · 避免 AI Slop 味
03

skwir：人机抢文件时，把操作变成可撤销的计划

一款用 Rust + GUI 构建的跨平台文件管理器，直面一个正在变普遍的问题：人和 AI Agent 操作同一批文件时容易互相踩。skwir 的做法是把每个操作做成可撤销、可审核的计划，人和 Agent 从同一个命令入口下发。这是一种很值得借鉴的“人机协作交互”——不是让人躲开 Agent，而是让双方的动作都进入同一个可审计的轨道。

📎 Geek
04

iOS 27.3 给 iPhone Duo 补上 2D 面部解锁

据 9to5Mac 报道，iOS 27.3 为 iPhone Duo 新增面部解锁。社区观察认为，这很可能是大量用户反馈 Touch ID 难用后临时加上的 2D 解锁，类似安卓方案；但展开内屏时仍无法使用面部、只能退回 Touch ID。这是一个典型的“用户反馈驱动的补丁式设计”案例：快速响应了痛点，却也暴露出跨形态体验一致性的裂缝，值得在产品评审中作为反面参照。

📎 歸藏 (guizang.ai)
05

鸿蒙实践：把“技术清单”翻译成“用户用得上的体验”

在人人都是产品经理的鸿蒙开发者沙龙上，四位一线嘉宾从应用平滑升级、新特性选型，到户外场景创新与 AI Agent 落地，讨论了 HarmonyOS 7 的能力如何转化为用户真正用得上的体验。其中一个很实用的判断是：升级决策应从用户版本分布出发，先确认新能力是否对应核心场景。把系统能力翻译成可感知价值，正是产品与设计最该做的“最后一公里”。

06

当天提需求、当天上线：一个产品经理的反馈闭环体感

开发者向阳乔木在内测中感慨：“做产品经理这么多年，第一次体会到当天用户提需求、当天上线的感觉。用户爽，自己也开心。”这句话背后是一个正在成形的产品节奏——小团队借助 AI 把反馈到上线的周期压缩到以天计。对用户研究者而言，这意味着访谈与观察可以更快进入验证循环，但也提醒我们要分清“响应快”与“方向对”，别让高频反馈掩盖了真实需求。
