核心洞察

Figma 推出 Design Agent，AI 从「设计工具」升级为「设计协作者」

Figma 正式发布内置于画布的设计 Agent，能够直接在 Figma 环境中理解设计系统、执行重复性任务、并行运行多种设计探索方案、维护设计库的一致性，并支持样式与布局的 Remix。这标志着 AI 设计工具从「辅助生成」迈向「主动协作」——Agent 不仅懂 Figma 的原生语法，还能参与评论和团队协作流程。

对 UX 团队而言，这意味着设计师可以把更多时间投入到策略性思考和用户洞察上，而将大量执行性工作交给 Agent。但同时也带来新挑战：如何定义人机协作的边界？如何确保 AI 生成的设计决策符合品牌调性和用户认知模型？

核心洞察

AI 社交产品 shapes 解决「开口第一句话」痛点，MAU 半年增长 6 倍

AI 社交应用 shapes 近期宣布完成 800 万美元种子轮融资，并披露 MAU 已超 40 万，半年内实现 6 倍增长。与其他 AI 社交产品不同，shapes 的核心创新在于将 AI 角色嵌入真人社交场景——用户进入陌生群聊后，AI 角色会主动接话、引导话题、回应你的发言，让你在没有熟人的环境中也能自然聊起来。

这一案例揭示了用户研究中的一个关键发现：团队在产品立项前花费约 300 小时与用户深度沟通，得出核心判断——90% 的用户有社交意愿，但被「第一句话」卡住。 shapes 没有试图用 AI 替代真人社交，而是用 AI 作为「社交催化剂」，降低用户破冰的心理门槛。这一设计思路对任何涉及社交互动的产品都有借鉴意义：AI 的最佳角色可能是「桥梁」而非「替代」。

核心洞察

豆包语音输入法通过「键盘联动」优雅解决专有名词痛点

豆包语音输入法在 Mac 上的新体验引发关注。传统语音输入的最大痛点是专有名词（如品牌名、技术术语）的识别错误——用户需要反复在词库中维护这些词汇。豆包的解决方案是将语音输入与键盘输入深度融合：当语音识别出错的专有名词被用户手动修正一次后，系统会自动记忆，后续语音输入即可正确识别。

这是一个典型的「多模态交互」设计案例——不是简单地叠加语音和键盘两种输入方式，而是让它们在数据层面互通，实现 1+1 > 2 的效果。产品体验上，实时转录、中英文混说等基础能力已较为成熟，真正形成差异化的是这种跨输入模式的智能学习机制。对设计师的启发：多模态交互的核心不在于提供更多输入选项，而在于打通不同模态之间的数据流和认知模型。

[来源: 有机大橘子] | [Orange AI 体验分享]
核心洞察

Miro Canvas 26 展示 AI-Native 协作工作流：Agent 成为团队「隐形成员」

Miro Canvas 26 大会呈现了一个重要趋势：AI 正在从「产品里的功能」演变为「团队中的协作者」。与会者观察到的最有趣转变不是「更好的 AI 工具」，而是人类与 AI Agent 如何在产品开发全流程中协同工作——从需求梳理、原型设计到用户测试反馈分析，Agent 被当作团队的「隐形成员」而非外部工具。

这对 UX 团队协作模式有深远影响。传统的设计流程中，设计师、研究员、产品经理之间的信息传递存在大量摩擦。AI-Native 工作流可能重塑这些协作边界，但同时也需要重新定义「谁对最终用户体验负责」——是人、是 Agent，还是两者的某种混合决策机制？

[来源: yobi321 / Miro Canvas 26]

📈 设计趋势洞察

趋势

AI Design Agent 时代到来：设计工具正在重新定义「设计师」的角色边界

随着 Figma Design Agent、Recraft 等 AI 设计工具的密集发布，设计行业正站在一个范式转换的节点。这些 Agent 不再是「帮你画图的助手」，而是能够理解设计系统语义、维护库一致性、并行探索多种方案的「设计协作者」。

从用户体验视角看，这一趋势带来三个关键问题值得研究团队关注：

  • 认知负荷转移：当 AI 接管执行层工作，设计师的认知负荷从「如何画」转向「判断什么是对的」。这要求设计师具备更强的用户洞察能力和设计策略思维。
  • 设计决策的可解释性：AI 生成的设计选择如何向团队和利益相关者解释？「Agent 觉得这样更好」显然不够——需要建立 AI 设计决策的透明度机制。
  • 设计系统的进化：传统设计系统（Design System）基于人工维护的组件库，而 AI Agent 可能催生「动态设计系统」——能根据上下文自动调整、适配的活的系统。这将对设计系统的治理和使用方式产生根本性改变。

实践建议：UX 团队应开始建立「AI 设计决策日志」，记录 Agent 的设计选择及其依据，逐步积累可解释的设计知识库，为未来的人机协作设计流程打下基础。

[来源: Figma(@figma)] | [Recraft AI 设计]
趋势

从「功能导向」到「情绪导向」：AI 宠物硬件赛道的产品体验转型

AI 宠物产品赛道正在经历从功能导向到情绪导向的转型。过去，宠物科技的核心竞争点集中在自动喂食、远程监控、健康记录等基础功能；而现在，围绕「情绪反馈」与「陪伴互动」的新一轮产品尝试正在涌现——从「宠物翻译器」到「智能陪宠机器人」，产品开始尝试理解宠物情绪、建立互动关系。

Market Data Forecast 数据显示，2025 年全球宠物科技市场规模约 199.8 亿美元，预计到 2034 年增长至 1477.9 亿美元。但比规模更重要的是产品体验逻辑的转变：AI 从「替代照护」走向「建立关系」。宠物情绪 AI 公司 Traini 完成 750 万美元融资，标志着资本市场对「情绪 AI」方向的认可。

对 UX 研究者的启示：当 AI 进入情感陪伴领域，传统的功能性可用性测试框架可能不再足够——需要引入情感计算、长期关系建模、依恋理论等跨学科方法，来评估和优化用户（及宠物）与 AI 产品的情感连接质量。

[来源: 白鲸出海]

💡 产品体验点评

案例

shapes：AI 作为「社交催化剂」的产品设计策略

shapes 的产品设计值得深入剖析。团队通过 300 小时的深度用户访谈发现，阻碍年轻人社交的不是「不想社交」，而是「不知道如何开始」。基于这一洞察，shapes 没有走「AI 替代真人」的路线（如 AI 恋人、AI 分身），而是选择将 AI 角色嵌入真人社交场景中——当你进入一个陌生群聊，AI 会主动接话、引导话题、回应你的发言，让你在没有熟人的环境中也能自然聊起来。

用户体验设计亮点：

  • 渐进式社交暴露：AI 的存在降低了用户发言的心理门槛，用户可以先和 AI 互动，再逐步融入真人对话。
  • 情境感知回应：AI 能根据群聊上下文做出合适回复，不是机械地重复欢迎语，而是真正参与话题。
  • 文化圈层匹配：产品面向游戏、动漫、同人等亚文化圈层用户，AI 角色的语调和知识库与目标用户群的文化语境高度契合。

对 UX 研究的启发：shapes 的案例证明，解决「用户痛点」不一定要通过复杂的功能堆砌——有时候一个精确的洞察（「被第一句话卡住」）加上一个优雅的介入点（AI 主动接话），就能创造巨大的产品价值。用户研究的价值在于发现那些用户自己也说不清楚的「隐性阻碍」。

[来源: 白鲸出海]
案例

京点点 Oxygen Vision：AI 重构跨境商品视觉生产流程

京东零售推出的「京点点 Oxygen Vision」是一个典型的 AI 驱动设计生产工具，针对跨境电商商家的商品图制作痛点——高昂成本（单 SKU 数千元）、漫长周期（数天至数周）、多语种适配复杂、平台合规要求严苛——提供了一站式 AI 生成解决方案。

用户体验设计策略分析：

  • 极简操作路径：将传统需要摄影师、设计师、翻译多方协作的流程压缩为「上传商品图 → 选择模板 → 一键生成套图」三步，极大降低了使用门槛。
  • 语境感知适配：系统自动适配不同电商平台的规范要求和目标市场的文化偏好，解决了「一套素材走天下」的转化低效问题。
  • 成本与质量的平衡：通过 AIGC 技术将单 SKU 视觉制作成本从数千元降至近乎零边际成本，同时保持商用级别的输出质量。

这一案例对 B2B 产品设计的启示：AI 工具类产品的核心竞争力不在于技术有多先进，而在于它是否能精准切入用户的「高频痛点场景」，并将复杂的技术能力封装为符合用户心智模型的简单操作。

[来源: 京东技术]
案例

黑神话悟空 3DGS 数字存档：沉浸式体验的技术与情感双重突破

FUNES 团队将《黑神话：悟空》中「既见未来，为何不拜」场景的原型——山西临汾隰县小西天——制作成了可漫游的 3D Gaussian Splatting 数字存档。团队实地拍摄 3,811 张照片（206 GB），通过 Gaussian Splatting 技术重建，没有手工建模，尽可能保留真实悬塑和圆塑的密集金色空间、细节和光感。

从用户体验角度看，这个案例的价值在于它解决了文化遗产数字化的一个长期难题：平面印刷无法展示悬塑的空间震撼，而 3DGS 技术让观众可以在屏幕前「慢慢看」。重轻为模型专门配乐的细节也体现了跨感官体验的整合设计思路。

UX 启示：技术进步（3DGS、空间音频）正在打开新的体验维度，但真正的用户体验突破来自于「技术+叙事+情感」的融合设计。产品设计师需要与技术团队更紧密地协作，在技术可行性边界内寻找最能触达用户情感的体验方案。

[来源: Berryxia.AI]

🔬 研究方法论

方法论

从「聊天框」到「操作系统」：产品经理的 AI 工作流设计思路

欧洲 AI PM 领域影响力作者 Pawel 分享了一套完整的「Claude PM 操作系统」，核心思想是将日常工作拆分为可积累、可复用、可验证的系统，并让系统在下一次任务中带着记忆继续工作。关键理念包括：

  • CLAUDE.md 作为路由层：不是堆知识，而是负责调度——决定什么任务交给哪个 Agent、什么时候调用什么工具。
  • 多 Agent 调度：PM 不再依赖单一对话，而是同时调度多个 specialized agents（Cowork、Claude Code、Dispatch、Skills 等），每个负责不同工作模块。
  • 自我改进知识库：每次任务完成后，系统自动总结经验教训并更新知识库，实现「越用越聪明」的复利效应。
  • 角色边界模糊化：产品经理、设计师、工程师的传统分工正在被打破——PM 可以用 Claude 做原型、跑测试、写 release notes、基于设计系统生成界面。

对 UX 研究的映射：用户研究员同样可以借鉴这套「系统思维」——将访谈分析、用户画像更新、可用性测试报告等流程模块化，用 AI 辅助完成数据整理、模式识别和报告初稿，而把核心精力投入到洞察提炼和策略建议上。关键是设计好「人-AI」的协作边界，确保研究的深度和同理心不被自动化稀释。

[来源: 晚点再听LaterCast]
方法论

Vibe Coding 中的交互设计技巧：先画 ASCII 布局图

一个被开发者社区验证有效的 Vibe Coding 技巧：让 AI 先画一个 ASCII 码布局图，再开始实际开发。这个看似简单的技巧背后，有一个重要的交互设计原理——在没有视觉参考的情况下直接生成代码，AI 往往会做出不合理的布局决策；而先通过 ASCII 图建立信息架构和视觉层次的共识，可以显著提升最终交互设计的合理性。

对 UX 研究的启示：这个技巧实际上是一种「低保真原型优先」的 AI 时代变体。在传统的 UCD 流程中，我们先画线框图、再做高保真、最后开发；而在 AI 辅助开发的新范式下，「AI 生成」本身成了新的高保真阶段，容易跳过信息架构的验证环节。ASCII 布局图作为一种极低成本的结构化沟通工具，帮助在人（产品经理/设计师）和 AI 之间建立对页面结构的共同理解。

这提示 UX 团队：在 AI 驱动的产品开发流程中，需要重新设计「设计评审」环节——不再是人评审人的设计稿，而是人评审 AI 的设计意图，并用结构化方法（如 ASCII 图、信息架构图）来确保双方对需求的理解一致。

[来源: 向阳乔木(@vista8)]
方法论

vivo VAPD AgentKit：可组合 Agent 前端的设计原则

vivo 互联网项目团队围绕笔记、知识库、项目管理三大场景，设计了一套可组合的 AI Agent 前端能力框架。其设计原则对 AI 产品体验设计有普适性参考价值：

  • 协议无关的 Runtime Adapter：只要后端能以流式输出事件，前端即可通过统一 Adapter 转为标准消息模型渲染——这意味着前端交互设计可以独立于后端技术栈演进。
  • 统一消息模型：将工具调用、Agent 回合循环、事件流与 UI 交互组合在一起，为历史记录和检查点能力预留扩展空间。
  • 即插即用的可组合 Hook：不同业务线不需要重复造轮子，同一套可组合组件可以按需接入。

UX 视角：这个框架体现了 AI 产品前端设计的一个重要趋势——从「一个聊天界面」走向「分布式的 AI 能力嵌入」。用户不需要打开专门的 AI 对话窗口，而是在原本的工作场景中自然获得 AI 辅助。这种「无感嵌入」的设计思路，可能是比独立 AI 应用更贴近用户真实工作流的方案。

[来源: vivo互联网技术]

🚀 UX 雷达

早期信号

Paperboy 探索 Agent 的「连续协作」新界面范式

YC 孵化的 Paperboy 团队（12 人，10 位工程师，融资 470 万美元）正在探索一种不同于现有 Claude Code / Codex / Manus 的 Agent 交互范式。创始人 John Yang 的核心观点：「人类和 AI Agent 配合工作的最佳方式，很可能还没被发明出来。」

Paperboy 提出的创新方向包括：

  • 从 Session 到连续流：现有产品都是「打开窗口 → 输入 prompt → 等待完成 → 关闭」，每次从零开始；Paperboy 探索让 Agent 通过观察用户用电脑来自主学习，建立长期记忆。
  • 用 IM 组织对话：不是专门的 Agent 窗口，而是像和同事聊天一样在 IM 中与 Agent 协作。
  • 主动找你，而非等你 prompt：Agent 可以主动推送信息、提醒任务，而不是被动等待指令。

这些探索对未来的人机交互设计有深远影响——如果 Agent 从「工具」变成「同事」，那么交互设计需要从「命令-响应」模型转向「关系-协作」模型，这对用户心理模型、信任建立、权限边界等都提出了全新课题。

[来源: 十字路口Crossing]
早期信号

Lovable 给 AI Agent 添加「发泄机制」：当 Agent 心情不好时

Lovable 团队为他们的 AI Agent 增加了一个 send_feedback 工具——字面意义上的「发泄机制」，让 Agent 在遇到困难时可以「vent 出来」。这看似是一个有趣的工程彩蛋，但背后反映了 AI 产品设计中一个新兴的思考维度：如何为 AI 系统建立「情绪表达」和「自我诊断」机制。

从用户体验角度看，当 AI Agent 在复杂任务中卡顿时，传统的做法是静默重试或输出错误信息；而 Lovable 的做法让 Agent 能够表达「我现在遇到了困难」，这不仅帮助开发团队调试，也可能在未来为用户提供更可理解的系统状态反馈。这是「可解释 AI」在用户体验层面的一个有趣延伸。

[来源: Lovable(@lovable_dev)]
行业动态

阿里云发布 50+ 项 Agent 新品，「千问云」首秀

2026 阿里云峰会可能是阿里云成立以来释放信号最密集的一场发布会。阿里云宣布完成「芯片-云-模型-推理」全栈 Agent 化升级，推出搭载自研 AI 芯片真武 M890 的超节点服务器、旗舰模型 Qwen3.7-Max、以及全新 AI 产品「千问云」等超 50 项新品。

核心看点包括：32 项 Agentic Cloud 新品覆盖运行时、编排、治理、安全、记忆、数据平面六大能力；云产品进行 Skill 化、MCP 化和 CLI 化改造，让 Agent 像调函数一样调用云能力。这意味着企业级 AI 产品的用户体验正在从「应用层」下沉到「基础设施层」——未来的产品设计师需要理解 Agent 如何调用底层能力，以及如何在更抽象的层面上设计用户与 Agent 的交互。
