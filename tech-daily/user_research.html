为什么 Claude Code 团队开始抛弃 Markdown？

Anthropic 工程师 Thariq Shihipar 在 X 上发布的文章《Using Claude Code: The Unreasonable Effectiveness of HTML》引发了 AI 圈的广泛讨论。他提出一个反常识观点：自己几乎不再让 AI 输出 Markdown，几乎所有任务都改成让 Claude Code 生成 HTML。

为什么现在是转折点？回到 GPT-4 时代，模型的上下文窗口只有 8192 token，HTML 标签语法要比纯文本多吃好几倍 token。在「寸 token 寸金」的年代，Markdown 是「没得选的选择」。但今天的模型上下文窗口已经大幅扩展，HTML 的 token 成本不再是一个问题。

HTML 带来了什么 Markdown 无法提供的体验？Thariq 做了 20 个示例，涵盖 code review、架构图、设计稿、报告、研究文档等场景。HTML 支持丰富的视觉层次、交互元素、内嵌样式和结构化数据展示——这些是 Markdown 的语法极限无法实现的。对于需要「交付物」而非「对话」的场景，HTML 提供了更接近最终产品的体验。

对 UX 设计师的启示：AI 生成内容的格式选择，本质上是「信息呈现方式」的设计决策。当 AI 从「聊天工具」变成「工作伙伴」，用户对输出物的要求也从「可读」升级到「可用、可交付」。这要求设计师重新思考 AI 产品的信息架构和输出格式策略。

告别 Prompt 抽卡：AI 游戏的「机制化迭代」框架

机器之心报道了一个让 AI 游戏真正「机制化迭代」的框架，直指当前 AI 生成游戏的核心痛点：让 GPT 写一个小游戏，它能在几分钟内输出像模像样的代码，但要求它在此基础上迭代到第四代时，问题就开始暴露——它可能忘了第一代的核心玩法，可能把好不容易调通的物理引擎又改崩了。

核心设计洞察：现有的 AI 游戏生成停留在「视觉换皮」层面，而非真正的玩法创新。框架提出了一种「自我进化」的玩法设计机制，让 AI 不再是一次性生成，而是基于明确的规则系统进行迭代演化。

对用户体验设计的意义：这个框架提醒我们，AI 产品的用户体验不能仅靠「生成质量」来维系，必须建立清晰的反馈回路和迭代机制。用户需要的不是一次性的惊艳输出，而是可预期、可控制、可持续改进的交互体验。这与传统产品设计中「MVP → 反馈 → 迭代」的逻辑一脉相承。

Granola 的教训：一个 prompt 无法服务所有用户

Granola 在其会议笔记应用中上线聊天功能后，产品工程师 Mehedi Hassan 分享了一段坦诚的复盘。他们发现，「一次性搞定」的诱惑很大——一行代码调用 web search，一个 prompt 服务所有用户，一次部署就完成。但现实很快打破了这种幻想。

用户角色的差异化需求：同一个聊天功能，销售期望得到「交易摘要」，工程师期望得到「阻塞项和 Linear ticket」，HR 经理期望得到「行动项」——三种完全不同的信息需求，根本不可能用一个 prompt 满足。Granola 的解决方案是为不同角色定制个性化 prompt，但这带来了新的工程复杂度：context 爆炸、成本飙升（每次聊天 10p）、供应商更新静默降级结果。

UX 洞察：AI 产品的「个性化」不是锦上添花，而是刚需。设计师需要在产品早期就建立用户角色模型（persona），并为不同角色设计差异化的交互路径。更重要的是，用户需要「感知到」个性化正在发生——如果系统默默切换了 prompt 但用户毫无察觉，信任感会受损。

华为 Pura X Max：越贵卖得越好的反常体验逻辑

华为 Pura X Max 正式开售，10999 元起步，12999 元的典藏版比标准版贵 2000 元。十天后的第三方监测数据显示了一个反常画面：典藏版占首销总量的 55%，标准版只占 45%。越贵的版本，反而卖得更多。

用户心理洞察：在「涨价、收缩、分化」的行业基调下，一台万元起步的折叠屏旗舰不仅卖爆了，而且越贵的型号卖得越好。这揭示了高端用户的消费心理——价格本身成为了「筛选信号」和「身份标识」。对于目标用户群来说，「贵」不是门槛，而是价值的确认。

「阔折叠」形态的体验价值：余承东在北京车展上的原话是「卖爆了」。这种新的屏幕比例带来了不同于传统折叠屏的阅读和信息浏览体验。用户「用钱投票」的背后，是对创新形态的好奇和对品牌溢价能力的认可。

对 UX 设计的启示：定价策略本身就是用户体验的一部分。对于高端产品，过低的价格反而可能损害 perceived value。设计师需要理解：用户买的不是功能，是「自我表达」和「社会认同」。

高期望客户框架：让用户自己定义产品标准

Superhuman Mail CEO Rahul Vohra 在 Product School 的分享中提出了「High Expectation Customer Framework」——如何识别最挑剔的用户，并用他们自己的话来定义产品真正为谁而建。

核心方法论：不要问用户「你需要什么」，而是观察那些已经对现有解决方案极度不满、但仍在坚持使用的用户。这些人就是「高期望客户」——他们的痛点最真实，他们的标准最严格，他们的语言最准确。用他们的原话来做产品定位，比任何市场调研报告都更有效。

实践建议：在产品早期，与其做广泛的用户访谈，不如找到 10 个最挑剔的潜在用户，深度理解他们的工作流和痛点。让他们的语言成为产品的「价值主张」，让他们的标准成为产品的「质量底线」。

UI 调试的古法新用：录屏慢放

开发者 Tw93 分享了一个「古法代码阶段」常用的 UI bug 调试方案：录屏慢放调试。原理很简单——录下操作过程，慢放找到有问题的帧，截图给 AI，基本上比打日志、猜的方式排查效果好太多。

为什么这个方法对 UX 研究也有价值？这本质上是一种「微行为观察」方法。用户的很多交互问题发生在毫秒级别，实时观察很难捕捉。录屏慢放让设计者能看到用户「手指怎么滑、眼睛往哪看、界面怎么响应」的完整过程。这与眼动追踪研究的原理相通——用技术手段捕捉肉眼无法察觉的交互细节。

实践建议：在可用性测试中，除了观察用户的宏观行为，也可以尝试录制屏幕并慢放分析，特别是针对动画、转场、手势交互等精细交互场景。这些「毫秒级」的体验细节，往往决定了产品的「质感」。

「社交可见性」作为用户教育机制

Shopify 的 River agent 系统有一个独特的设计约束：只能在 Slack 公开频道使用，不允许私聊。CEO Tobi Lutke 的解释是——这样其他员工可以观察和学习别人如何使用它。

设计洞察：这与 Midjourney 早期仅在 Discord 开放的设计思路如出一辙。当用户可以在公开环境中观察他人的使用方式时，prompt engineering 这样的「隐性知识」会通过模仿和观察自然传播。这比任何教程都更有效。

对 AI 产品的启示：很多 AI 产品的用户教育成本极高，因为「好的使用方式」是一种难以言传的技能。通过设计「社交可见性」——让优秀的使用案例被公开看到——可以大幅降低用户的学习曲线。这是社区设计与用户体验设计的交叉点。
