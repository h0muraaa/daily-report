◈设计趋势洞察：AI 时代的输入层重构

从“点击窗口”到“多模态自然交互”

JetBrains 在《Code in Space》一文中指出，自鼠标-窗口范式在 1970-80 年代确立以来，人机交互可能正迎来 60 年来最大的一次变革。LLM 把对话引入软件工程，而 XR 硬件则提供了前所未有的输入表面：凝视、手势、语音、头部姿态、身体动作。对用户体验设计而言，这意味着界面不再只是屏幕上的像素，而是空间、声音与肢体动作的综合编排。

这种趋势已经在多款产品中显现：Aina Interface 融资 550 万美元，宣称要“为 AI 时代重新设计输入层”，其出发点正是观察到触控屏和键盘是为浏览与搜索时代设计的，而 AI 时代的数百次日常任务会带来巨大的认知负荷。与此同时，OpenAI 推出的 Codex Micro 实体键盘、Cua 团队利用操作系统可访问性层让 Agent 在不抢占用户焦点的前提下并行操作多窗口，都在探索同一个问题：当 AI 能主动完成任务时，人类应该如何优雅地介入与接管？

来源： [JetBrains Blog] [elvis(@omarsar0)] [AI Engineer]

服务场景中的语音交互：Amazon 餐厅电话 AI

AWS 发布了一份关于用 Amazon Bedrock AgentCore 与 Amazon Nova 2 Sonic 构建餐厅电话 AI 接待员的指南。其用户洞察非常具体：美国餐厅每月平均每店漏接 150 通电话，其中约 60% 是想订餐或订位的顾客；这些电话多发生在晚餐高峰，而这时前台正忙于接待到店客人。把员工从接电话中抽调出来，只会同时恶化到店与电话两种体验；App 或网站也无法覆盖只想打电话的顾客。

这个案例对 UX 设计的启发是：AI 语音代理的真正价值不只是替代人工，而是填补“数字化渠道遗漏的人群”与“高峰时段的服务缺口”。设计重点应放在语音对话的容错、确认机制与异常转人工路径，而不是单纯追求自动化率。

◇产品体验点评

Figma 与 Bolt：设计工程一体化的两条路径

Figma 最新功能允许用户把“代码实现的屏幕”复制并粘贴为带变量的设计图层，同时通过 Figma MCP Server 生成设计、通过 Chrome 扩展抓取网页为可编辑图层。这模糊了“设计稿”与“真实实现”之间的边界，对设计系统维护和跨团队协作有显著价值：设计师可以基于真实代码界面迭代，而不必手动重建状态。

另一边，Bolt 开源了 Bolt Slides，让 Claude Code、Codex、Cursor 等 Agent 都能一键生成响应式、可交互的幻灯片。它强调“从 prompt 到可发布网页”的闭环，适用于董事会汇报、客户报告等高频但低设计预算的场景。两者共同指向一个方向：AI 设计工具正在从“生成漂亮概念图”走向“产出可直接上线或演示的工程资产”。

[来源: Figma(@figma)] [来源: bolt.new(@boltdotnew)]

Kimi Coder 的“自动模式”体验：从模糊意图到可用产品

一位开发者分享了他使用 Kimi 3 在 Kimi Coder 中完成“博朗 3D 录音机”项目的完整体验。他先给出相对模糊的 prompt——“类似博朗 3D 录音机，可交互、UI 好、有 3D 效果”，模型进入较长的思考与调研阶段；随后自动启动 skills 做市场与竞品分析、撰写 PRD，并在多轮对话中让用户选择技术路线与实现效果。

进入名为 YOLO 的自动模式后，模型将任务拆解并分配给不同 Agent，过程中自行发现 bug 并修复，最终交付的网页可直接打开使用，作者表示“一次都没改”。这一案例揭示了 AI 编码助手的 UX 关键：用户愿意接受更长的等待时间，只要最终交付的是“可用状态”而非“半成品”；同时，透明展示后台 skills 执行过程，能显著提升用户对自动化的信任感。

[来源: Berryxia.AI(@berryxia)]

OpenAI 的“产品墙”：ChatGPT Live 与 Codex 为何互不通信

产品专家 Peter Yang 分享了一个典型用户痛点：ChatGPT Live 和 Codex 是两个很棒的产品，但彼此不打通。他在散步时用 ChatGPT Live 要求打开 Google Doc，得到的回答是“做不到”；手动触发 Documents 插件后，Live 才获得正确上下文。他认为，OpenAI 最大的错失机会在于：没有让 Live 语音助手调用 Codex 已有的插件、工具与浏览器能力。

这对产品设计者的启示是：在 AI 产品矩阵快速扩张时，用户旅程往往被切割在不同功能之间。与其继续堆叠独立能力，不如优先解决“身份、权限、上下文与工具集”的跨产品一致性，让语音、文本、代码三种交互形态共享同一套代理能力。

◉研究方法论

VIP-MINGLE：跨场景的群体互动多模态数据集

视频会议与面对面会议是两种截然不同的协作体验，但关于群体互动的研究长期受限于缺乏同时覆盖两者的数据集。arXiv 上的 VIP-MINGLE 数据集收录了 59 小时、32 组、105 位参与者的对照实验数据：同一批人在视频会议与面对面场景下分别进行小组讨论，数据集包含原始音视频、心理测量数据、说话人分离、面部表情、转录文本以及时间分辨率上的人工标注。

对 UX 与用户研究团队而言，这类多模态数据集的价值在于：它让“远程协作与现场协作的体验差异”从主观感受变成可量化、可建模的研究对象。未来在设计混合办公、在线课堂、远程用户访谈等产品时，可以借助类似数据更精细地理解眼神接触、话轮转换、肢体语言与空间距离对用户参与感的影响。
