今日要点

五条最值得用户研究员与产品设计师停下来想一想的信号。

1
平台生态 / 授权体验

豆包手机助手被 166 款 App 拒绝：Agent 的第一道体验墙，不是模型而是权限

10 月 21 日，豆包手机助手官网再次更新「拒绝操作应用清单」，被拒绝操作的应用从一周前的 155 款增加到 166 款。新增名单里既有 58 同城、Keep、华住会、虎扑、喜马拉雅、芒果 TV，也覆盖了酒店、招聘、运动健身、音乐、旅游等日常场景；加上此前已拒绝的微信、淘宝、支付宝，这份清单几乎成了一份中国移动互联网应用大全。豆包想替用户办事，先要面对的是一个个关上的门。

这并没有挡住行业押注 Agent 手机：10 月 13 日阶跃终端发布售价 3999 元的 STEPX Neo，华为小艺通过鸿蒙系统深度参与日常操作，Today AI 累计融资超过 2 亿美元，阿里千问 Go!、蚂蚁灵光、腾讯元宝助手也在加速；海外 Meta Muse、OpenAI Dots、Grok Bot、Anthropic Claude Duet 相继登场。所有玩家都在回答同一个问题：当 AI 要代替用户点击、填写、支付时，平台、用户与助手之间的权限该怎么分。

研究启示：把「能不能操作」换成「用户愿不愿意授权、授权后能不能随时收回、出错时能不能追溯」。Agent 体验的最小研究单元不是一次任务，而是一份可解释、可撤销、可审计的授权契约。
来源： 人人都是产品经理 · 豆包被 166 款 APP 拒绝，腾讯阿里怕什么？

留存 / 个人 Agent

Muse 40 天 1090 万下载、7 日留存 30%：下载是入口，留存才说明它进了日常

Sensor Tower 数据显示，Meta 的 AI 助手 Muse 自 9 月上线以来 40 天累计下载 1090 万次，其中 1020 万次来自美国，成为少数达成这一上线里程碑的应用。更值得产品团队看的是留存：Muse 在美国的 7 日留存率为 30%、14 日为 23%，而 ChatGPT、Claude、Grok 等竞品的 7 日和 14 日平均留存分别为 19% 和 16%。分析人士把它的增长归因于 Meta 的应用生态与跨平台导流能力。

把这组数字放回 Personal Agent 的竞争里，会发现「首周留存」正在变成比下载更诚实的指标：用户第一次打开是被入口推动，第七天还回来，才说明助手真的接管了某件重复发生的事。与此同时，Otter.ai 以 4000 万累计用户、超过 1 亿美元 ARR 拿到 3.2 亿美元融资，但公司没有披露月活与流失率，也被点出「会议记录类产品竞争激烈，留存是切实挑战」——增长故事的另一面，仍是同一个问题。

研究启示：为 Personal Agent 建立「第二价值时刻」研究——用户在第 3 到第 7 天因为哪件事回来？如果答案是「收到一条简报」，留存很可能只是通知惯性；如果答案是「它替我把一件事收尾了」，才值得放大。
来源： 创业邦 · Muse 持续霸榜，上线头 40 天美国下载量超 1000 万 · Z Potentials · Otter.ai 获 3.2 亿美元融资

主动性 / 授权界面

Claude Duet 上岗：主动性越强，确认与撤销的界面越重要

10 月 21 日，Anthropic 以研究预览版推出主动式 Agent Claude Duet，基于 Opus 5.5，提供 iOS、Android 与网页版，首批面向美国 Pro、Max 订阅用户开放候补，并与 Claude 其他功能共享额度。它会每天整理跨应用的重要事项、主动提醒需要处理的问题，并在用户离开后继续执行被委托的任务；官方称可接入超过 6000 个连接器和插件，能安排会议、整理业务信息、制作数据看板、生成财务预测，甚至开发 Web 应用。

更值得注意的是它给「主动」划的边界：发送消息、付款、签署文件或删除内容前，必须由用户确认。稀土掘金的评测也指出，它仍处于早期预览，任务优先级判断与执行可靠性还有改进空间。这和豆包的「166 款 App 拒绝」是同一枚硬币的两面——能力越强，用户越需要一个能看懂、能打断、能反悔的授权界面。

研究启示：主动 Agent 的核心体验指标不该只有「完成了多少任务」，还应包括「打断是否恰当」「确认是否可理解」「误操作是否可逆」。建议用「打断预算」做日记研究：记录一周内 Agent 主动出现的时机、用户当时的注意力状态，以及确认动作带来的摩擦。
来源： 稀土掘金 · Claude Duet 开始替你干活 · 创业邦 · 首个 Claude Duet 上岗 · 极客公园 · 极客早知道

需求真伪 / 用户价值

朱啸虎泼冷水：Personal Agent 缺真实需求，「省时间」可能不如「消磨时间」

在 10 月 21 日开幕的 ACC 2026 AI 创造者嘉年华上，金沙江创投主管合伙人朱啸虎直言「不明白 Personal Agent 能干嘛」，认为这一形态缺少真实需求；他给出的增长标尺是 AI 产品一年增长 5 倍才算及格，并判断「帮助用户节省时间的生意，可能远不如帮助他们消磨时间有前途」。他还表示，开源模型的 Token 消耗量终将超过闭源模型，中国 AI 应用将出现年化收入 10 亿美元的公司，但「再来一次补贴大战，投资人不会支持」。

这套判断和今天的产品热度形成了有价值的对照：Claude Duet、Muse、Dots、Grok Bot 都在争夺「整个工作日」，但用户是否真的愿意把工作日交出去，取决于助手能否嵌入既有习惯，而不是能力清单有多长。另一条来自 Vercel 的数据也提醒我们「行为已经先于叙事」：其 CEO 称平台上来自编程 Agent 的部署占比已从年初的 3% 升到 60%，十个月新增 15 亿次部署。需求不是被说服出来的，是被工作流自然带出来的。

研究启示：把「能力演示」与「重复性需求」分开验证。用两周日记法记录用户真实触发场景、频率与替代方案；如果一周用不到两次，就不该按「日常助手」设计信息架构。
来源： 硅星人Pro · 对话朱啸虎 · 深思圈 · Vercel CEO：60% 的部署已经来自 agent

新形态 / 软硬结合

iPhone Duo 一周体验：把折叠角度做成 API，新形态的体验由软件和开发者决定

爱范儿用一周时间体验 iPhone Duo 后给出的结论是：它无疑是第一梯队的产品，但「Duo 虽好，稍晚两个月再买，体验会更好」。这款折叠 iPhone 的独特性主要来自软件与软硬结合：机身传感器把折叠角度作为 API 提供给系统功能和开发者，展开瞬间的过渡动画让手机的物理存在「宛若透明」；但作为初代新形态，它也存在初代产品常见的问题。首批 10 月 23 日交付，晚下单要等到 2027 年 1 月。

同一时间，苹果新任 CEO 特努斯表态「设计依旧是苹果第一要务」，认为硬件、软件设计师和工程师互相理解才是苹果的独特优势，公司不会跟风硬追技术热点，坚持体验优先。把这两条放在一起看，iPhone Duo 的真正设计资产不是铰链，而是「角度」这个可被开发者调用的交互原语——它决定了展开、悬停、半折这些状态能不能长出新的使用场景。

研究启示：评估新形态硬件时，少看参数，多看它是否提供了新的交互原语，以及开发者有没有能力在 6 个月内把它用起来。初代产品的「体验时差」应被纳入研究计划：上市首月测新奇与摩擦，第三个月测习惯与生态。
来源： 爱范儿 · 我们用了一周的 iPhone Duo · 创业邦 · AIGC 日报：苹果新 CEO 表态设计优先
02

设计趋势洞察

两个正在成形的转向：交互契约从「命令」走向「意图」，体验瓶颈从「生成」移向「审阅与授权」。

交互契约

从「下命令」到「被理解」：意图捕获需要新的确认与纠错界面

Founder Park 把 Personal AI 的变化概括为交付形式的变化：过去的通用 Agent 是「单次任务交付」，用户必须先想清楚要什么、给出明确指令；今天的 Personal Agent 则试图在用户自己还没想清楚时捕捉模糊意图，主动拆解动作、规划方案。文章也解释了企业 AI 的困惑：给每个人配一个 Copilot，只是把问答塞进原工作流，流程本身没有改变，所以「公司并没有因为 AI 更高效」。

上海期智研究院 PI 李彪给出了更锋利的表述：世界上从来没有 Personal Agent，只有 Context + Agent——同一个 Agent 接上工作上下文就是 Work Agent，接上生活上下文就是 Personal Agent。他以千问办公开源的 MyContext 为例：把钉钉、飞书里的聊天与协作记录整理成持续更新的工作档案，每条标明来源与时间；信息对不上时系统先判断，拿不准就问用户，用户确认过的结论模型不能自行修改。他举的订票例子很关键：电梯里随口答应客户「走之前再见一面」，这个约定既不在日历也不在邮箱，模型再强也猜不出，只能事先知道或来问。

设计含义意图捕获不是「更聪明的猜」，而是「更诚实的问」。界面需要三件东西——上下文出处（这句话从哪来）、假设显式化（我按什么理解执行）、低成本纠错（改一次就能教会它）。研究上应统计「首次理解正确率」与「纠正一次后的稳定率」，而不是只看任务完成率。
来源： Founder Park · Personal AI 都在谈的「意图捕获」 · 创业邦 · 从来就没有什么 Personal Agent
下游摩擦

当生成变便宜，审阅、授权与收尾成为体验瓶颈

哈佛大学基于 Jellyfish 平台对 718 家企业的研究发现：AI 编程助手与 Agent 提高了代码产量，却没有带来等量的已完成工作，部分原因是 AI 生成的代码增加了开发后段的工作量，尤其是代码审查。Vercel CEO 则给出另一组行为数据：平台上来自编程 Agent 的部署占比从年初的 3% 升到 60%，十年累计 10 亿次部署之后，十个月又新增 15 亿次。生成侧越便宜，审阅侧越拥挤。

这与 Personal Agent 的授权问题同构。Claude Duet 把「发消息、付款、签署、删除」设为必须确认的动作；豆包则被 166 款 App 拒之门外。用户真正感知到的效率，不是「AI 生成了多少」，而是「从想法到结果的总时长」，其中包含阅读、判断、确认、返工与收尾。Otter.ai 的留存压力也说明：把会议录下来只是入口，把语音转成可执行的下一步才是价值。

设计含义把设计资源从「生成界面」转向「审阅界面」——diff、来源、置信度、批量确认、异常高亮、撤销栈。研究上改用端到端指标：time-to-outcome、每任务确认次数、返工率、放弃率，而不是生成速度或 token 数。
来源： InfoQ · AI 生成代码未提升生产力，瓶颈在下游 · 深思圈 · Vercel CEO 访谈 · 稀土掘金 · Claude Duet
03

产品体验点评

两个案例：一个用交互原语打开新形态，一个用限制与感官反馈把输入变成仪式。

交互原语

iPhone Duo：先用一个过渡动画建立「物理消失」，再把角度交给开发者

折叠屏面世七年，iPhone Duo 是少有的在中英文互联网同时激起讨论的设备。爱范儿一周体验后的判断是：硬件参数不是它的主角，软件和软硬结合才是；展开瞬间的过渡动画让物理形态「宛若透明」，而机身传感器把折叠角度作为 API 开放给系统与开发者。

这带来两个设计层的机会：一是「签名时刻」——用一个无法被参数表描述的瞬间建立新形态的感知；二是「交互原语」——角度、悬停、半折这些状态一旦可被调用，开发者就能创造视频通话支架、半折输入、双屏协作等场景。评测同时提醒，初代产品仍有常见问题，晚两个月买体验更好，首批 10 月 23 日交付、晚下单要等到 2027 年 1 月。

体验判断：新形态的第一仗是「让人相信这不是一台更贵的直板机」，第二仗才是「让开发者在上面长出独占场景」。前者靠一个瞬间，后者靠一套原语和至少半年的生态窗口。研究计划应把「首周惊叹」与「首月习惯」分开测量：前者看情绪与分享意愿，后者看半折/悬停状态的使用频次和放弃原因。
来源： 爱范儿 · 首发｜我们用了一周的 iPhone Duo
情感化设计

Platen：用纸张、机械声和删除线，把打字变成一种仪式

Platen 试图在 iPhone 上还原传统打字机的书写体验：纸张纹理的书写页、黑色导轨与胶囊滑块、随文字变化的墨迹、机械打字声与触感反馈。它甚至提供平面与弯曲两种纸张形态——打字时纸张弯曲，查阅时恢复平直。

更细的设计在于「保留痕迹」：用户可以直接擦除错误，也可以保留删除线，让修改痕迹成为页面的一部分；夜间模式长按打字机部件即可点亮一盏小灯，还能调节亮度、扩散与范围。它没有用 AI 炫技，反而用 3000 字符的单篇上限把产品定义成「短篇、日记、随笔」；丰富的部件、轨道、字体、页边距、墨迹、纸张与装饰自定义，则把「仪式感」做成了可配置的个人风格。

体验判断：当大多数输入工具在争夺「更快」，Platen 证明了「更慢」也可以是价值主张——前提是它服务的是反思、记录与情绪，而不是效率。研究方法上，这类产品的成功指标不是任务完成时长，而是「写完后的满足感」「一周后回访意愿」「修改痕迹是否被保留」。删除线尤其值得研究：它把「纠错」从隐藏的失败变成了可见的创作过程。
来源： 少数派 · Platen：把 iPhone 变成一台复古打字机

研究方法论

三套可以直接迁移到 AI 产品研究中的方法：改版复盘、Agent 评估与失败驱动评测。

01

改版失败后的「四线复盘法」：先还原假设，再谈对错

人人都是产品经理用一个订单售后页改版案例，给出了一套避免「甩锅大会」的复盘框架。第一步不是争论需求、研发、指标谁的问题，而是把上线前的原始假设原样抄出来，与上线后的可观察结果并排对比。案例中三个假设——用户看到明确状态和更新时间会少问「退款到哪一步」；页面能让用户更早发现异常，客服更快接手；信息透明会缩短退款从申请到到账的总时间——分别需要咨询原因、异常入口使用与人工处理记录、后台流程与渠道耗时来验证，不能共用一个「退款处理时间」指标。

  1. 还原原始假设：逐条写下「当初为什么认为这件事会有效」，不要事后改写。
  2. 对齐可观察结果：把「效果不好」拆成具体现象，例如咨询量、异常入口使用率、各环节耗时。
  3. 沿四条线查因：原始假设、指标口径、实施范围、外部变化，逐条排除。
  4. 给出可验证的下一步：继续、调整还是停掉，并明确下一次用什么指标判断。
来源： 人人都是产品经理 · 一次产品改版失败，是需求、指标还是协作出了问题？
02

Personal Agent 五维体验评估：用「账号覆盖」预判上限

AI 博主卡尔的 AI 沃茨在 X 上收集了 1505 条、覆盖 11 类的真实用例，把 12 个 Personal Agent 都跑了一遍，最后总结出五个评估维度：Computer Use（电脑操作自动化）、多端联动、信息获取、记忆与主动性。他提出一个很实用的先验判断：Agent 好不好用，不取决于模型，而取决于「你拥有的账号与它能提供的服务重叠有多高」——平时用的 App 越多、越能通过 skill、MCP、CLI 或内置方式接上，Agent 的上限越高。他也据此放弃了 OpenAI Dots 与 Meta Muse，把工作流切到 Today 与 Grok Bot。

  1. 先画服务覆盖图：列出用户高频 App 与 Agent 可连接的服务，算重叠率。
  2. 每个维度选 2–3 个用户自己的真实任务，而不是厂商 demo。
  3. 记录五项：覆盖、完成、纠正成本、时延、失败后的恢复。
  4. 跨端验证：手机发任务、电脑执行、结果回传，观察上下文是否断裂。
来源： 卡尔的AI沃茨 · 用完 12 个 Personal Agent 后，我找到了决定好用上限的五个标准
03

用 1368 起 AI 失败事件，反推评测该测什么

AI Engineer 的一场分享把公共 AI 事故库中的 1368 起事件，按技术强度、部署控制、业务影响三个维度、13 个子领域做了归类，覆盖约 98% 的事件。一个重要发现是：人工复核、监控等「弱部署控制」与伤害结果的关联最紧。分享者据此提出按风险高低排序用例、先检查评测器本身、用 build–break–fix 循环主动「证明系统是错的」，并以一个给错退款政策的航空客服机器人为例。

  1. 为每个 AI 功能列出可能的用户伤害，而不只是准确率。
  2. 检查部署控制：人工复核、监控、告警、逃生通道是否真的存在。
  3. 按「一旦出错谁受损、损失多大」排序测试用例。
