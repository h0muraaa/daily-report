信任设计AI Agent 不会说"我不确定"，信任成为新的设计对象

Upside.tech 的 Alex Bauer 在 AI Engineer 大会的演讲中指出：两年前人人担心的"幻觉"并没有消失，而是"长大了"——今天的 AI 会把一个错误的营收数字以完全正确的样子交到你手上。他给出的解法不是更强的模型，而是设计模式：每个 Agent 行动前必须咨询的"图书管理员"、对高风险判断启用"陪审团+法官"机制、以及识别"这个模型就是不够聪明、该换人了"的分层策略。

研究员视角："让用户信任 AI"正在从文案问题变成交互架构问题。可验证性、多人复核、能力分级，这些原本属于组织管理的人类机制，正被翻译为产品里的 UI 与流程模式——这是未来一年 Agent 产品最值得投入的设计方向。

信息架构ChatGPT 变成"超级 App"的第一周：用户被 36 个模型变体搞晕了

OpenAI 把 Chat、Work、Codex 塞进同一个桌面应用后，用户的困惑立刻显现。Simon Willison 直言"GPT-5.6 最令人困惑的一点就是搞不清该用哪个模型、配哪个推理强度"；Latent.Space 统计 API 用户面对多达 36 个 GPT-5.6 变体。讽刺的是，OpenAI 此前收购 Statsig、高调宣传"自动路由、消灭模型选择器"，如今却亲手把选择权（和认知负担）还给了用户。宝玉整理的"Chat 回答问题、Work 帮你干活、Codex 帮你写代码"Q&A 之所以被大量转发，恰恰说明官方信息架构没有替用户想清楚。

研究员视角：产品扩张期最容易牺牲的就是心智模型的清晰度。当用户需要第三方"说明书"才能理解你的产品矩阵时，说明入口设计已经超载。OpenAI 官方已承认"我们把使用最高算力档做得太容易了"，并承诺把聊天和项目列表以更熟悉的方式移回侧边栏——这是一次典型的"发布后才做用户反馈闭环"。
📎 [来源: Simon Willison] · [来源: Latent.Space] · [来源: 宝玉]

行为洞察配额重置正在重写用户的作息：5 小时循环成了新的"打卡"

向阳乔木观察到，身边很多朋友的生活节律已经被 Codex 和 Claude Code 的 5 小时额度重置机制"控制"：重置前开足马力烧 Ultra 档，烧完退回中档"希望能持久点"。andrew chen 则点破了这门生意的本质："Agentic coding 拥有史诗级的订阅+追加销售定价模型——写代码、烧光 token、再买、循环往复。这是一个带油门踏板的订阅制，计价器从不停。"

研究员视角：这是一个教科书级的"商业模型塑造用户行为"案例。配额窗口创造了类似手游体力的节律感和稀缺焦虑，既提升粘性也制造挫败。对设计师而言，值得追问的是：这种"被重置支配"的体验是长期可持续的，还是正在透支用户的信任？
📎 [来源: 向阳乔木] · [来源: andrew chen]

设计工具"Design Skills"生态爆发：设计知识正在被封装成 AI 可调用的模块

本周设计圈最热的不是某个新软件，而是一批"设计技能包"：Emil Kowalski 把 Apple WWDC 历年视频提炼成 17 条设计与动效原则的 /apple-design skill（附代码示例）；Meng To 开源的 Skills 仓库聚合了生成 dither 背景、嵌入 Unicorn Studio 设计等"解决具体问题"的能力；yetone 则做了"kill AI slop"——一个识别蓝紫渐变、左侧弧形边框等 AI 生成套路的图鉴与清理工具。三条线索指向同一件事：设计品味与规范正在从"人脑里的经验"变成"机器可执行的知识库"。

研究员视角：对设计系统团队，这意味着"设计规范"的交付物形态变了——不再只是给人类阅读的文档，还要给 Agent 阅读的结构化规则。Viking 的提醒值得记住：风潮会轮回，全交给 AI 生成、一点都不改，才是真正的风险。

研究伦理"问卷里选'非常需要'的，全是给了代金券的调研用户"

一位十年产品经理的避坑长文里，最扎心的一条是"把用户调研当打卡"：几十份问卷、漂亮的数据图表，上线后功能却只有 1% 的使用率。复盘发现，勾选"非常需要"的受访者是被代金券激励来的——他们根本不是真实用户。文章将其总结为"伪需求 = 错误样本 × 形式主义流程"。

研究员视角：激励偏差、样本偏差、为证明需求而做的"表演式调研"，是用研岗位最常见也最隐蔽的失效模式。在 AI 能一键生成问卷和分析报告的时代，"调研的流程合规"会变得越来越廉价，而"样本是否真实、问题是否诚实"反而成为唯一稀缺的判断力。
📎 [来源: 人人都是产品经理]
设计趋势洞察 深度分析

趋势一：Agent 产品的"可监督性"设计——从黑盒执行到在场感

三个看似无关的发布，指向同一个设计趋势。OpenAI 为 Computer Use 上线 Live Picture-in-Picture：Agent 操作电脑时，用户可以开一个画中画小窗"盯着它干活"，多任务的同时保持监督。Notion 的 Geoffrey Litt 在 AI Engineer 主题演讲中提出 "理解才是新的瓶颈"：大多数 Agent 任务仍然需要人类判断，而指导 Agent 的前提不是验证结果对错，而是真正理解它在做什么——他把教育学的旧理念与 Agent 能力结合，给出"保持在线、高效建立理解"的具体技巧。再加上前文 Upside 的"信任设计模式"，一条清晰的脉络浮现出来：

"自主循环很火，但现实是大多数 Agent 任务仍需人类判断。" —— Geoffrey Litt, Notion

Agent 产品的体验竞争正在从"它能不能完成任务"转向"用户能不能以合理的认知成本监督它"。画中画、过程可追溯、行动前确认、失败可解释——这些"在场感"设计将决定用户敢不敢把真正重要的事交给 Agent。Ethan Mollick 对 ChatGPT Work 的批评也佐证了这一点：对比 NotebookLM 对同一问题的回答，后者"以过程和来源为中心，而不只是输出结果"，这才是知识工作者真正需要的形态。

实践建议：如果你在设计 Agent 类产品，把"监督成本"作为与"任务成功率"同等重要的一级指标：用户需要多少次点击才能搞清 Agent 在做什么？出错时能否回溯到具体的决策点？进度是否可被打断和纠偏？
📎 [来源: OpenAI] · [来源: AI Engineer - Geoffrey Litt] · [来源: NotebookLM / Ethan Mollick]

趋势二：人机沟通的"共同词汇表"——动效命名学的兴起

一个不到 1 分钟的视频本周在设计圈流传：作者 meng shao 整理了 13 类常见 Motion 动效的中英文标准名称——Push Slide（页面切换）、Staggered Entrance（错落进入）、State Morph（状态形变）、FLIP Reorder（布局重排）、Drag + Spring（拖拽弹簧）等。起因是一个非常具体的痛点："为了让 Agent 做出想要的动画，你写了很长一段描述，结果它还是理解错了。很多时候，不是描述得不够详细，而是缺少双方都能准确理解的动效名称。"

这与 design skills 生态是同一个趋势的两面：当执行者从人类工程师变成 AI Agent，模糊的自然语言描述正在让位于结构化的专业词汇。就像设计师与工程师之间曾靠"设计系统"对齐，现在设计师与 Agent 之间需要一层新的"语义接口"。知道名字之后，"少写一大段模糊描述，用一个明确的名称，让所有人更快理解"。

实践建议：设计团队可以开始沉淀自己的"动效/交互词汇表"，既用于内部沟通，也作为给 AI 工具的 prompt 组件库。这会像当年的设计 token 一样，成为设计系统的新基建。
📎 [来源: meng shao]
产品体验点评 案例分析

反面案例Claude Code 桌面版：新功能亮眼，基础体验却"翻车"

Claude Code 桌面版本周上线了应用内浏览器，能让 Claude 直接读取、点击、交互网页。但资深用户宝玉毫不客气地指出两个"相当糟糕的设计"：其一，右侧 Panel 布局不合理，经常把浏览器压缩到只剩一点点可见区域；其二，任务完成后生成的结果文件不可点击，用户需要手动复制文件名去搜索——而竞品 Codex 的生成结果点击即可预览或在 VSCode 打开。

体验教训：这是一个经典的"功能先行、细节欠债"案例。Agent 产品的核心体验闭环是"产出→查看→使用"，产出物无法一键触达，等于在最后一步把流畅感打断。对比评测中 Claude Code 与 Codex 的差距，往往不是模型能力，而是这类"最后一厘米"的交互完成度。
📎 [来源: 宝玉]

对比评测ChatGPT Work vs Claude Cowork：两种"把活干完"的体验哲学

硅星人Pro 用三个真实场景对两者做了同 prompt、不救场的对比实测（GPT-5.6 Sol 极高强度 vs Fable 5 Extra 档）。以"WAIC 会前功课"为例：ChatGPT Work 用 18 分 50 秒交出一份可翻页的交互卡片，给出"每天只跑一个片区"的狠安排和明确的"跳过清单"（排队超 12 分钟的机器人表演、只放预录视频的展台一律放弃），每个展位只给 10 分钟。两者底层路径也不同：Cowork 跑在隔离的 Linux 虚拟机沙箱里，ChatGPT Work 则用操作系统原生隔离（macOS Seatbelt / Windows Sandbox）加内置浏览器。

体验洞察：两家产品在"交付物形态"上分出了性格：Work 倾向于交付"可直接使用的成品"（文档、表格、网页），Cowork 更像一个与你并肩工作的同事。值得注意的是，OpenAI 从 Anthropic 1 月开创这个品类到 7 月追上，只用了半年——而评测者认为"这次真追上来了"的依据，恰恰是交付物体验而非模型跑分。对知识工作者来说，"输出一个链接可分享的网页"比"输出一段需要复制粘贴的文字"是代际差异。
📎 [来源: 硅星人Pro] · [来源: 宝玉 - 桌面端对比]

细节之美那些"坚持旧体验"的产品决策，为什么反而赢得人心

一个开源的自托管 Evernote 替代品本周获得大量关注，它的卖点不是功能颠覆，而是"保留经典三栏笔记体验"，再叠加 AI 原生、API 与 MCP 开放。无独有偶，Simon Willison 对 ChatGPT 改版的最大期待，是"把聊天和项目以更熟悉、可定制的方式移回侧边栏"，别再藏进奇怪的小浮窗里。

体验洞察：在 AI 产品疯狂重塑交互范式的当下，"熟悉的结构"本身就是一种体验资产。用户的肌肉记忆和心智模型迁移有真实成本，创新的正确姿势往往是：交互骨架保守，能力内核激进。

研究方法论 方法与工具

组织方法Axon CPTO：把"批评者"和研究员直接嵌入产品小队

Axon（执法科技巨头）的 CPO 兼 CTO Jeff Kunins 分享了一个反常识的组织实践：把社会活动家和研究员直接嵌入产品经理小队，而不是把他们放在"评审环节"的下游。他的观点是：这样做让你做出更好的产品，而不是更慢的产品——因为最尖锐的用户视角（尤其是来自批评者的视角）在需求形成的那一刻就在场，而不是等产品成型后再来"挑刺"。

方法迁移：多数公司的用研是"服务台"模式——产品团队提需求、研究员交付报告。Axon 的做法提示了另一种可能：研究员作为小队的常驻成员，让"用户证据"从阶段性交付物变成持续在场的决策依据。对高敏感度、高风险的产品领域尤其值得尝试。
📎 [来源: Product School]

工具观察Replit Community Profiles：把"agent 使用记录"变成可展示的个人档案

Replit 上线 Community Profiles，为 vibe coder 生成 agent 使用量和检查点的活动热力图（类似 GitHub 的贡献图），并为 Pro 用户提供 Power Ranking，用户可挑选代表项目展示。

方法视角：这是"量化自我"在产品设计中的新应用——当创作过程由 agent 协同完成，"过程数据"（调用量、checkpoint、活跃度）成为新的身份凭证。对研究者的启发是：这类行为日志同时也是天然的纵向研究数据源，可以用来观察 AI 辅助创作的熟练度曲线与使用习惯演化。
