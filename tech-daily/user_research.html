Claude 把 Chat 与 Cowork 合并成一个入口：用户不该为「该用哪个产品」做决策

Anthropic 今天把后台任务模式 Cowork 与日常聊天合并为同一个入口，同时把此前独立的设计产品 Claude Design 连同 Docs、Slides 一起塞进每一段对话，底层由重构后的 Artifacts 平台支撑。产品团队给的理由非常「用户研究」：「很多人反馈说，他们不想为任何任务去挑选该用哪个 Claude 产品。」随着模型能力变强，路由被交还给系统——你说一句「帮我写个周报」「做五页幻灯片给领导汇报」，Claude 自己判断该快速回答还是深度执行、该输出哪种形态的成果物。控制权仍在用户手里：可以随时打断、重定向、或手动调节投入程度。

外部反馈几乎一致叫好。Peter Yang 的判断尤其值得产品人记下来：「Chat 和 Cowork 分开本来就是一种 anti-pattern……Tabs is the new hamburger menu（标签页成了新的汉堡菜单）。」The Rundown AI 也指出这个分裂「一直是个尴尬的鸿沟，用户没有清晰的理由要活在其中一边」。对研究者而言，这是一个教科书级的案例：产品矩阵的「丰富」在某些条件下会转化为用户的认知负担。当两个入口的心智模型无法用一句话讲清差异时，用户就会在两个入口之间反复试探——这类「任务归类困难」正是最值得做可用性测试的摩擦点，而 Anthropic 选择的解法不是更好的引导文案，而是直接消灭选择。

「我测过体验最好的个人 AI Agent」：Muse 靠 onboarding、权限模型和活动流赢了

How I AI 花了几小时把 Meta 的新个人 AI Agent Muse 做了一次真实首测——覆盖引导流程（onboarding）、日历管理、目标设定、一次性生成家庭晨报、浏览器购物，以及一个出乎意料好用的动画头像。作者给出的结论很直接：Muse 是他测过体验最好的个人 Agent，并逐条列出了「好在哪」：一次成型、Claude 与 Codex 都没能做出来的家庭 PDF；一套与所有其他 Agent 都不同的权限模型；以及一个他「立刻希望 Codex 和 Claude Code 也有」的活动流（activity feed）。

真正值得研究员注意的是这件事的评测方式：不是跑分，而是把 Agent 放进真实的日常任务里跑一遍——从早上给家人做一份通讯，到让它去买东西，再到为睡眠训练设一个目标。节目里也保留了失败案例，并以此讨论「这类产品的边界在哪」。同一位作者另有一段短评把标准说得很清楚：「那份晨报 PDF 是一次真正意义上的设计成品，那就是个人 Agent 应该达到的门槛。」当 Agent 从演示走向日常，「它能不能一次做对一件真实的事」正在取代「它能调用多少工具」，成为体验评价的核心指标。

Hinge CPTO：一款「为了被删除而设计」的产品，北极星是好的约会而不是使用时长

Product School 的播客请到了 Hinge 首席产品与技术官（CPTO）Ben Celebicic。他在 Hinge 待了 11 年，从 2015 年那次重新发布算起。这期的核心张力非常清晰：大多数 App 优化的是屏幕使用时长，而 Hinge 优化的是「你离开」——它的北极星指标是「好的约会」而非 engagement，同时仍然在追逐十亿美元营收。节目把这个问题摊开来讲：一个以「让用户成功卸载自己」为目标的产品，要如何设计留存、如何定义成功、如何向投资人解释这套逻辑。

另一个对产品组织有直接参考价值的点，是他把 CPO 直觉（快速上线、鼓励创新）与 CTO 直觉（保护质量与基础设施）放进同一个人身上去平衡。对用户研究员而言，这个案例的价值在于它提供了一种与主流相悖的指标设计范式：当产品目标本身就是「让用户不再需要我」，用户旅程的终点就不是留存曲线，而是那个「被删除」的时刻。值得把它当作反直觉指标设计的讨论素材。

Typeless 把免费额度从每周 8000 字砍到 2000 字，用户感到「被背刺」

语音输入产品 Typeless 今天宣布下调免费用户额度，每周免费字数从 8000 砍到 2000，引发大量用户吐槽。小互的评论抓住了问题的本质：「Typeless 的用户被背刺了。」他同时指出，目前基本所有模型厂商都自带了语音输入能力（海外有 Codex、Claude，国内有微信输入法、豆包语音输入、千问输入法、网易「叭哥说」），其中网易叭哥说更是直接宣称终身免费、支持 100+ 语种与中文方言。另一位用户 Ding 的描述补上了迁移决策的真实过程：看到 Typeless 下午降额度，他当即去下载了网易的产品，发现「速度和准确度非常好，而且产品形态一样都是纯语音输入，迁移成本最低」。

这里有一条对做订阅与免费额度设计的人非常实用的洞察：用户对免费额度的敏感点不只是「多少」，更是「会不会变」。额度被追溯性收紧带来的情绪损失，往往远大于同等幅度的初始额度差异——它破坏的是可预期性，而可预期性是信任的基础。小互给出的另一条建议也值得记下：面对大厂用模型能力快速抹平体验优势的赛道，早期产品更应该用数据沉淀和习惯培养把用户留住，而不是单靠体验上的微弱领先。

腾讯会议 × 影石墨水屏录音硬件：19.7 克的「电子工牌」，把身份标识做进了可穿戴设备

腾讯会议与影石联合发布了一款带墨水屏的 AI 录音硬件，内测用户给出的评价是「做得非常漂亮」。最特别的设计是那块六色墨水屏：在腾讯会议 App 里可以随时替换屏幕上的图案，比如把大会 Logo 换上去然后磁吸在衣领上，「戴起来就像一个小小的电子工牌」。对访谈与现场活动场景，这带来一个很实用的巧思——把媒体 Logo 挂在胸前，既能录音，又能很自然地告知对方自己的身份，在一场同时有好几家媒体的活动上尤其有用。

但真正值得用户研究员记下的是它的可穿戴第一性原理：整机只有 19.7 克，比一节 5 号电池还轻，作者从早戴到晚「几乎无感」。他给出的判断很朴素也很准确：这类 AI 硬件最后拼的其实就是小、轻、省电——因为只有你愿意戴，它才有机会持续把线下发生的沟通留下来，最后变成 AI 可以用的 Context。这是一条关于「情境数据采集」的设计约束：采集能力再强，如果佩戴负担高，数据管道在源头上就是断的。对做现场研究、访谈记录、用户旅程观察的人来说，这个形态很可能是下一步的工作工具。

设计趋势洞察

Trend Deep-dive

趋势一：AI 产品的入口正在「收敛」——从多产品矩阵回到单一入口，路由权交给模型

今天最强的信号来自 Anthropic：Chat / Cowork 不再分家，Claude Design 也从独立产品降级为对话内的一种能力。这不是一次简单的功能整合，而是对「产品矩阵即产品力」这一默认假设的否定。此前业内普遍相信：能力越复杂，越应该切成多个清晰的产品让用户自行选择。Peter Yang 用一句设计史梗点破了这个思路的代价——「Tabs is the new hamburger menu」：标签页曾经是解决导航复杂度的标准答案，如今却成了把复杂度推给用户的典型反模式。

对研究者来说，这里有三条可以立刻用起来的判断标准：其一，如果两个入口的差异无法用一句话向用户解释，那这个分裂就是认知负担而非赋能；其二，当系统有能力自行判断意图时，「让用户选」带来的不是控制感，而是决策疲劳——Anthropic 的解法是把路由交给模型，同时保留用户随时打断和手动调节投入程度的权力，这实际上是「自动路由 + 可撤销控制」的组合；其三，这类变更的验证指标不该只看使用量，而应看用户在两个入口间反复横跳的次数是否下降。值得注意的是，同一天 xAI 也在把 Grok Bot 从「编程 Agent」重新定位为「一支可复制的 AI 团队」，并为工程、客服、GTM、产品、设计等角色公开了对应的工作流与模板——行业的组织方式正在从「一个产品一个场景」转向「一个入口多种角色」。

趋势二：设计工具与「审美」正在被 agent 重构，交付物的及格线在抬高

今天有两条互补的信号。第一条来自工具侧：Sketch 团队推出了一款深度结合 AI 的设计软件 Elyx，它的自我定位是「A better source of truth for design engineers and agents」——注意后半句，设计系统的「唯一真相源」现在要同时服务设计师、设计工程师和 Agent。Figma 这边也在同一方向上动作：更新了文件夹（可预览文件内容、颜色更易区分、支持复制），并主推 Weave 系列能力——用文字提示生成概念草图、把图片重新想象成不同材质、把一张图扩展到任意画幅，且都能直接在画布上完成、再发布到 Community。同一天，「How I AI」演示了 Grok Bot × Figma MCP 的组合：把品牌手册丢给 Bot，它直接把多份符合品牌规范的设计稿落进 Figma。

第二条来自能力评测侧：「审美」正在成为模型的一等评测维度。卡尔的AI沃茨对豆包新模型 Seed 2.1-pro 做了一轮实测，第一批 case 就是「审美与手感」——让模型用 Three.js 在单个 HTML 文件里复现一座 3D 体素风格的浮空樱花岛，考察的正是最容易翻车的地方：材质太硬、打光很乱、比例不协调。人人都是产品经理的作者则把 WorkBuddy + DeepSeek-V4.1-Flash + Ardot 的组合用于真实交付：丢进几张 Pinterest 参考图和内容大纲，13 分钟产出一版「95% 满意度」的海报初稿，作者只花了 5 分钟改文字就定稿，之后又用同样的组合输出原型图。

把两条线并起来看，对设计团队的含义是双重的：一方面，设计资产的组织方式要为「机器可读」重新设计（规范、组件、品牌手册都要能被 Agent 直接消费）；另一方面，AI 交付物的评价标准正从「能不能生成」转向「审美是否过关、是否一次成型」。研究员的对应课题也很明确：当模型能产出一个「95% 满意度的初稿」，设计师的评审与修改动作会发生什么变化？用户的期待基线会被抬到哪里？

vivo OriginOS 7 / 蓝心小 V Pro：从「刚认识的实习生」到「记住你的熟人」

少数派的上手体验给这篇系统评测起了一个非常用户视角的标题：用户正在成为那个迁就机器逻辑的人——设置菜单越挖越深，交互入口越藏越隐蔽，AI 助手的实用性甚至取决于你能不能再像写代码一样严谨地组织 Prompt。作者把大多数手机 AI 的疲惫感归因得很准：不是底层模型算力不够，而是交互形态被困在「被动唤起的单次对话框」里——每次打开都像面对一个刚认识的实习生，没有昨天的记忆，不了解你的生活背景，也给不出一件真正办妥的事。

OriginOS 7 的核心突破被归纳为两个维度：「更懂你」与「更贴心」。最精彩的是一组压力测试：给出一个苛刻的家庭画像——老人腿脚不便要顾及体力、5 岁小孩完全不能吃辣、爱人热爱摄影必须留出傍晚的落日机位——然后让蓝心小 V Pro 规划重庆三日游。过去 AI 出的出行建议多是千篇一律的网红景点堆砌，而这次的结果让人印象深刻。这个 case 的方法论价值大于结论本身：它展示了如何用「带约束的复杂真实场景」而不是通用问题来检验 AI 助手的理解深度。对用户研究员来说，这是一套可以直接复用的测试设计——把真实用户的矛盾性需求（多个互相冲突的约束条件）作为任务输入，比问「你觉得这个助手好用吗」有效得多。

豆包手机助手消费者版：一颗橙色 AI 按键，把 Agent 装进了物理入口

折腾了九个多月后，搭载豆包手机助手消费者版本的努比亚 Navix Ultra 正式开售（12+512GB 定价 5999 元，国补后 5499 元）。评测者提前拿到真机，认为硬件层面在外观、续航（7100mAh）和影像（2 亿像素主摄）上都做了全面升级，但最值得聊的还是侧边那颗非常显眼的橙色 AI 按键。这个细节引出一个被长期低估的设计问题：Agent 能力再强，如果唤起它的动作需要解锁、找到图标、长按、等到对话框弹出，用户就不会在真实场景里用它。

物理按键本质上是在降低「意图表达」的启动成本——它把「我要让 AI 帮我做件事」这个念头与「按下按键」这个动作绑定成条件反射，绕过了一整套界面导航。同一时期还有两条相关的形态信号：Ding 提到他试过的另一款产品可以连接苹果健康以及许多苹果自带工具，体验「甚至比 Grok Bot 更好」；而 ElevenLabs 推出了面向小企业的 AI 接待员平台 Reception，主打「每一个未接来电都可能是一个流失的客户」，只要填个网址，几分钟就能配置完成——接电话、回答问题、预约、发确认短信。这一批产品共同说明，Agent 的竞争重心正在从「能不能做」转向「在真实场景里能否被最省力地唤起和信任」：物理按键、健康数据接入、一个网址即完成配置，都是同一种降低摩擦的努力。

研究方法论

Methods & Tools

方法一：语音 Agent 的三维评估框架——执行 / 结果 / 体验，且三者不可互相推导

meng shao 总结了 LangChain 关于「如何评估语音智能体」的分享，这套框架的清晰度值得直接搬进研究工具箱。它把评估拆成三个必须独立评估的维度：执行（智能体是否按规范执行：工具是否以正确参数、正确顺序调用，是否遵守隐私与披露政策，是否在行动前确认了必要信息）、结果（用户的根本问题是否真的被解决）、体验（对话对用户是否顺畅）。

  • 最反直觉也最重要的一条：指令遵从性 ≠ 结果有效性。一个容易被忽视的失败模式是——智能体完美遵守了所有指令，用户的任务却失败了。执行维度的满分完全推不出结果维度的合格，这正是两个维度必须独立评估的原因。结果评估的定量层尤其值得学习：尽量度量真实世界的下游业务信号，而不是从对话里推断——排程场景看预约时间与时区是否正确，客服场景看工单是否重开，转接场景看目的地是否接听；核心指标是预订成功率、解决率、升级率、重开率、放弃率。
  • 体验维度里的关键感知指标是「轮次结束延迟」——从用户说完话到智能体开口之间的间隔。这里有一条极其实用的诊断方法：要分段测量管道各组件（VAD、STT、模型推理、工具调用、TTS）各自的 P50/P95/P99，因为同一段尴尬的停顿可能来自模型慢、工具阻塞或 TTS 在等待完整响应，只有 trace 才能定位到具体组件。这是把「用户觉得卡」这类模糊反馈，转化为可归因工程指标的范本。
  • 评估手段上，分享也给出了分层原则：可机器验证的硬性规则用确定性评估器（代码），语义性要求（如「是否清楚解释了下一步」「是否对模糊请求提出澄清」）用 LLM-as-judge。

📎 来源：meng shao — 语音智能体如何评估（LangChain）

方法二：观察数千个 Agent 的真实行为，而不是猜测他们需要什么

AI Engineer 大会的一场分享提供了一个极佳的方法论隐喻。Liad Yosef 的团队测试了大量网站，发现大约一半的站点发布了 llms.txt——这是告诉 Agent「该怎么和你协作」的事实标准；但他们跑过的几乎没有一个 Agent 真的去读它。Agent 们径直走向文档页，然后是首页；少数确实打开了 llms.txt 的，也只是因为文档页里提到了它。这个结果彻底改变了问题的定义：我们一直在写「我们认为 Agent 需要什么」的规范，而唯一可靠地了解它们需要什么的方式，是看着成千上万个 Agent 去试。

这几乎就是用户研究方法论本身：不要从假设出发写规范，要从观察真实行为出发修正假设。把它和今天另一条观点放在一起看会更有意思——小互转述了 a16z 的 Josh Elman 对「AI 能自己写代码后，产品经理还剩下什么」的回答：代码的构建成本确实在大幅下降，但做出正确产品判断的成本，一分钱都没有降低。两条合起来，正好回答了「当 AI 能自动生成一切时，研究还有什么价值」：生成越便宜，判断越贵，而判断的原料只能来自对真实行为的持续观察。

Early Signals
  • 「弱回应」的陪伴玩偶：用 AI 的克制，服务被忽视的情感需求。 四川团队 Chongker 的做法在当前 AI 热潮里相当反常——旗下产品大多数没有配备语音交互，只提供细微的动作反馈。但它恰好以极低的「学习成本」满足了老年人、独居者等人群长期被忽视的情感陪伴需求，在毛绒玩具均价 20 美元的大众市场里建立起均价 100 美元的产品矩阵，并成长为国内 TOP 5、海外亚马逊高客单价 TOP 1。对包容性设计与适老化设计的研究者来说，这是一个难得的反例：不是所有情感产品都需要更强的交互能力，降低交互门槛本身就是产品力。 📎 白鲸出海 — 做「弱回应」的陪伴玩偶，四川团队把单价做到上百美元
  • 设计系统的「唯一真相源」要同时服务人和 Agent。 Sketch 团队的新产品 Elyx 把定位写得很直白：「A better source of truth for design engineers and agents」。这句话标志着设计资产的组织方式正在发生代际变化——组件、规范、品牌语言不再只为人服务，还要能被 Agent 直接消费。配套信号是「How I AI」演示的 Grok Bot × Figma MCP：把品牌手册丢进去，多份符合规范的设计稿直接落进 Figma。值得提前思考的是：当 Agent 成为设计系统的主要消费者之一，设计规范该如何写、如何结构化？ 📎 Ding — Elyx · How I AI — Grok Bot 把品牌手册变成 Figma 卡片
  • 86% 的人知道容器查询，只有 41.4% 在用：认知与采纳之间的鸿沟。 Smashing Magazine 的文章指出，CSS 容器查询的浏览器支持已经到约 94%，但根据 State of CSS 调查，86% 的开发者知道它，实际使用的只有 41.4%。作者观察到很多人（包括他自己）的第一反应是「已经有媒体查询了，为什么还需要它」。这是一条典型的设计系统落地信号：能力的可用性与采用率之间隔着认知重构的成本——光有好的工具不够，还需要有人解释「为什么旧的思维模型不再适用」。同样的逻辑适用于任何内部设计系统或研究工具的推广。 📎 Smashing Magazine — Stop Treating CSS Container Queries Like Traditional Media Queries
  • Agent 正在从「单个对话」搬进「群聊」，上下文与记忆成为新的体验战场。 有用户发现了一款名为 Teamily AI 的工具，定位是「把 Agent 直接丢进群聊的 AI 原生即时通讯工具」。几个设计点值得研究：上下文做得很彻底——所有对话、文档、应用的信息汇到一个活的上下文里，跨群组也不用重复交代背景；自带记忆系统，从所有对话中持续学习你的习惯、偏好与人际关系，用得越多越懂你；语义路由器自动匹配最合适的模型组合，在速度、成本与质量之间找平衡，不用手动切模型；对话框还自带会议纪要、截图、语音转文字等常用功能，创建群组时提供大量预置场景，也可以 fork 别人分享的 Agent 直接用。 📎 Ding — Teamily AI
  • AI 正在接管小企业的「第一触点」，且配置成本被压到近乎为零。 ElevenLabs 发布了基于 ElevenAgents 的 AI 接待员平台 Reception，主张「每一个未接来电都可能是流失的客户」，产品能做到接听每一通电话、回答问题、预约服务并发送确认短信，配置只需填一个网址、几分钟完成。同期 HeyGen 把 MCP 接入医疗场景，让一次提示词就能生成覆盖各种就诊类型、手术和患者问题的视频库，并在所有内容中保持同一个面容与声音。对研究者而言，这类产品提出了一个新的评估课题：当 AI 成为用户与品牌接触的第一个界面，「未被设计过」的服务体验会带来什么样的信任与情感后果？ 📎 ElevenLabs — Reception · HeyGen — healthcare videos via MCP
