设计趋势洞察

深度分析
趋势一 · 界面分层

从「操作界面」到「委托界面」：Agent 产品的设计问题正在换题

今天多条新闻拼在一起，能看到一个清晰的结构变化：界面没有消失，而是被拆成了三层。第一层是“委托层”——用户用自然语言或语音说出目标，TRAE 宝的统一入口、豆包工作的“演示一遍就能学会”、VoicePad 的听写键，都在降低表达成本。第二层是“监督层”——工作台、任务列表、进度与产物、远程查看与接管，TRAE 宝把最近任务和产物集中展示，豆包工作支持锁屏继续与手机接管，都是在回答“我不在电脑前时，怎么知道它在干什么”。第三层才是“结果层”——A2UI 与 CopilotKit 所代表的生成式 UI，让 Agent 根据任务现场渲染界面，而不是预先设计所有页面。

这三层对应三种完全不同的设计能力：委托层考验的是意图澄清与歧义处理，监督层考验的是状态可见性与控制感，结果层考验的是生成界面的质量下限与一致性。过去我们习惯用“完成率、任务时长、错误率”衡量界面，现在还需要一组新指标：委托清晰度（用户是否知道该说什么）、上下文连续性（跨项目、跨会话的记忆是否可信）、可中断与可撤回性（说错、做错时能否立刻刹车）、结果可验证性（用户能否快速判断产出对不对）。皮查伊的表态与 Anthropic 的争议，本质上都在提醒：当 Agent 越来越自主，人的位置不是退出，而是被重新安排到“关键决策点”上。

对研究的启示
访谈中不要只问“好不好用”，要追问“你什么时候不确定它在做什么”“你上一次想打断它是什么时候”“你怎么确认结果是对的”。这些时刻才是委托式体验真正的痛点。
可落地动作
为 Agent 功能补一张“三层界面地图”：委托入口、监督面板、结果呈现各自有哪些触点；再为每层定义 1–2 个可观测指标，先于视觉稿完成体验度量设计。

趋势二 · 实时交互

语音的第二春，难点不在“听懂”，而在“不乱插嘴”

UIUC、CMU、哥伦比亚大学等机构的新综述梳理了 349 篇工作，提出把“全模态智能”与“全模态交互”作为两个相互关联的部分。它描述的典型场景很具体：当用户让 AI 分析屏幕上的图表，又突然补充“等一下，看右边那条曲线”，系统需要停止旧回答、更新目标，并检查后台计算是否仍然有效。实时交互的难点就藏在这些瞬间——不是把语音转成文字，而是轮流、打断、目标更新与修复。

这与今天的产品信号互相印证。Qwen Audio Agent 明确把“打断语音回答、构建中途改需求、取消后台任务”作为演示重点；Genspark VoicePad 把“开口”当作入口，而不是把语音当作键盘的替代；讯飞输入法的回温说明，用户愿意在“表达意图”的第一现场使用 AI。再加上 XREAL AURA 这类 95 克的分体式 Android XR 眼镜，交互正在从“屏幕内的点击”扩展到“空间中的说话与注视”。对用户研究员来说，这意味着经典难题重新回到中心：turn-taking（话轮转换）、barge-in（打断）、repair（修复）——这些原本属于对话分析的概念，正在变成产品可用性测试的必测项。

对研究的启示
语音体验测试要专门设计“打断脚本”：用户说到一半改需求、在 AI 回答中途插话、让 AI 停止并回退。观察系统是否真的停下、是否保留上下文、用户是否知道如何纠正。
可落地动作
把“开口前的意图”纳入旅程地图：用户在什么场景、什么姿态、什么情绪下更愿意说而不是点；VoicePad 的“用户本来就要开口的地方”是一个值得复用的场景筛选原则。

产品体验点评

案例拆解

TRAE 宝：把“助理”放在导航栏里，是一次交互范式的迁移

用户痛点

随着使用时间变长，项目和会话会不断累积。用户想继续某个项目，往往要先找到项目、翻出旧会话或新建任务；项目一多就容易搞乱，甚至把 A 项目的指令发到 B 项目。更深层的痛点是：跨项目的任务需要用户自己拆分、分配、重读上下文、逐个检查进度，最后再手工汇总。

设计解法

TRAE 宝用一个“人格化入口”承接这些协调工作：左侧独立入口降低发现成本，中间对话区承接意图，右侧工作台把最近任务与产物变成可扫视的状态面板，桌面悬浮窗则保留了低打扰的常驻形态。配合跨项目上下文、自动任务拆分与多 Agent 协调，它把用户从“调度者”变成了“委托人”。通过微信、飞书远程管理，则把监督层延伸到了离开电脑之后。

体验风险

助理越能干，越容易成为单点：如果它误解了需求，错误会被放大到多个子任务；如果它不展示“为什么这样拆分”，用户会失去控制感。设计上需要优先解决三件事——任务拆分的可解释、关键节点的确认、以及一键回退到“我自己来”的路径。

豆包工作 + 即梦短剧工作室：把“专业流程”压缩成“可演示的技能”

用户痛点

普通人每天在采购网、政策库、行业标准站点里反复搜索、点选、跳转、下载附件；程序员写自动化脚本，也常被表单嵌套和弹窗拦截折腾。创作者侧则面临另一类复杂：几十上百个镜头如何保持人物、服装、场景一致，改一段剧情能否同步调整后续分镜，几秒钟不满意是否要全部重生成。

设计解法

豆包工作升级了操作电脑能力，屏幕点击精度与速度提升，并支持把电脑操作录制成技能：用户演示一遍、边操作边讲，豆包把操作流程和讲解整理成个人技能，下次直接调用；开启“允许锁屏时工作”后，Mac 锁屏也能继续执行，人离开电脑后可用手机下达任务并查看结果，回到电脑前再接管。即梦短剧工作室则把剧本创作、角色与场景资产管理、3D 导演台、智能预演、片段重拍与超分串成一条完整创作流，支持从一句灵感、小说 IP 或完整剧本进入。

体验风险

“录制即技能”极大降低了自动化门槛，但也带来两类风险：录屏可能包含敏感信息，技能在不同站点/版本上可能泛化失败。产品需要把“录制范围、数据留存、失败回退”讲清楚，否则用户第一次踩坑就会放弃。创作工具的风险则是“能力过载”——功能越全，新手越不知道从哪开始，渐进式引导比功能堆叠更重要。
