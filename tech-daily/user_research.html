当软件开始「为 Agent 而设计」：
人退到验收席

Claude Artifacts 把协作对象从「人」换成「Agent」，a16z 提出「B2A 经济」；另一边，「AI 味」界面被逐条解剖，UX 研究岗位一年缩水 45%。今天的信号指向同一个转变：设计的主体、协作的伙伴、乃至被衡量的价值，都在重新排位。

今日要点 KEY INSIGHTS

  1. 软件的使用主体变了，界面形态也就跟着变

    宝玉用一个类比点破了 Claude Artifacts 的意义：当年 Google Docs 颠覆本地 Office，核心是从「单机」变成「云端」；如今 Artifacts 代表的，是软件从「给人用」变成「给 Agent 用、人来审查微调」。他给出三处具体的设计转向——协作对象从「人—人」变为「人—Agent」，且 Agent 的操作与历史全程可见、可用评论对话；交互从「人直接操作」变为「标记 + 评论」，把复杂操作交给自然语言；生产从「人主导」变为「Agent 采访人后实施」。当使用软件的主体改变，软件的形态必然被重写。
    📎 来源: 宝玉 (@dotey) · 宝玉：软件从「给人用」到「给 Agent 用」

  2. a16z：互联网的主要用户已不是人，而是 Agent

    a16z 的 Olivia Moore 与 Justine Moore 提出「B2A 经济」（Business-to-Agent）：随着 Agent 从「回答问题」走向「完成任务」，它们会越来越自主地决定用哪些产品、订阅哪些服务、以及替我们花多少钱。这意味着产品设计不止要照顾人的阅读与点击，还要照顾机器能否发现、理解、调用——信息架构、接口语义、可信度信号，都会成为新的体验接口。
    📎 来源: a16z (@a16z)

  3. 「AI 味」第一次被拆成了可修的清单

    设计作者「酸梅干超人」专门解释了 VibeCoding 生成界面的「塑料感」从何而来，并把它归纳为三类可定位的问题：其一是规范错误，比如状态栏、底部导航的尺寸位置不对，字体字号不合规，按钮尺寸不符合移动端标准——AI 用网页标准去模拟 App，没把平台规范真正用进去；其二是圆角泛滥，移动端屏幕把圆角感知放大，大小不一的大圆角会叠加负面观感；其三是字体滥用，AI 缺乏克制、随手换字体。把模糊的「AI 味」变成可逐条校验的问题，本身就是设计评审方法的一步。
    📎 来源: 超人的电话亭

  4. UX 研究岗位一年 −45%，设计岗创历史新低

    Lenny Rachitsky 的《2026 科技就业市场》报告给出刺眼数字：科技公司开放岗位 28.1 万+、同比 +17%，但 PM、工程、设计岗位合计只增长 2%；其中设计岗 −28%（创历史新低）、UX 研究岗 −45%、前端 −51%。增长几乎全部来自硬件、供应链与现场服务等「实体」岗位。报告同时指出「PM 正在 AI 时代胜出」「每个岗位都要求 AI 技能」。对用户研究员而言，这不是行业衰退的结论，而是角色必须向「懂 AI、能验证、能落地」迁移的强信号。
    📎 来源: Lenny Rachitsky · 就业市场全景 · 增长最快的工程角色

  5. 无障碍的黄金标准：让使用者参与设计与测试

    Apple 宣布为 Apple TV 应用加入手语翻译功能，11 月 13 日随电影《Being Heumann》全球上线，F1 也将提供美国手语与英国手语版本，年内扩展到更多 Apple Original 作品。更值得记录的是流程：手语演绎由聋人及以手语为母语的使用者参与设计和测试；用户可在设置中启用，并在播放时选择手语按钮，还能搜索「with ASL」查找相关内容。这不是「为残障用户补一个功能」，而是把目标用户放进设计闭环的范例。
    📎 来源: 少数派

设计趋势洞察 DESIGN TRENDS

趋势一：新的设计中心，是「验收者」而不是「操作者」

当 Agent 动手、人看结果，界面要解决的是「如何让人放心地点头」。

宝玉的观察值得展开：即使让 Agent 去操作软件，人终究要看结果，于是软件设计的重心从「怎么操作」转向「怎么让人更好地验收」。他以 Claude Artifacts 为例列出三条可复用的模式。第一，协作可见：过去 Google Docs、Figma 强调人与人协作，能看到谁在操作与历史；现在则是人与 Agent 协作，Agent 的当前操作与全部历史都可见，用户可以在设计稿上留言，Agent 改完还会回复。第二，从直接操作转为标记与评论：传统视频剪辑要在时间轴里放大波形、手动标记静音段再删除，而在 Claude Motion 里，用户只需框选大致区间、写一句「帮我把静音部分剪掉」，Agent 自己去找并处理。第三，从人主导转为 Agent 采访人：写 PPT 不再要求人先想清楚，Agent 可以先提问、再实施。

这条趋势与 a16z 的「B2A 经济」是同一枚硬币的两面：一端是 Agent 成为产品的实际使用者与采购者，另一端是人退居「目标设定 + 结果审查」。对体验设计而言，这意味着一批新的基础组件——操作历史的可读呈现、可追溯的变更、自然语言批注与回执、以及「人能否快速判断对不对」的验证视图。

给研究员的启示：评测 Agent 产品时，别只问「它能不能做完」，还要问三个验收问题——用户能否看清它做了什么？能否只改想改的地方？能否在不确定时叫停并接管？「可验收性」应当成为独立于「完成度」的体验指标。

📎 宝玉：软件设计重心转向验收 · a16z：B2A 经济

趋势二：生成速度超过了设计规范，「AI 味」成为新的可用性债

能生成 ≠ 能上线，中间隔着一整套平台规范与审美克制。

当 VibeCoding 让「先做出来」变得廉价，问题就从「能不能做」转向「做出来能不能用」。「酸梅干超人」把 AI 界面的通病拆成规范错误、圆角泛滥、字体滥用三类，本质是同一个根因：模型在用网页的通用模式去套具体平台，缺少对 iOS/Android 设计规范的约束。这类问题不像崩溃那样显眼，却会持续拉低产品的专业感与信任度，是一种典型的「可用性债」。

反面的正面样本同样出现在今天：Lovable 做了一次克制的侧边栏重设计——项目放上面、最近对话放下面，用一句「没人喜欢乱糟糟的侧边栏」说明动机。它没有炫技，只是重新安排了信息优先级。两者对照恰好说明：AI 可以快速铺出界面，但「哪些信息该在上、圆角该多大、字体该不该换」这类决策，仍然需要人来定规则。设计系统与 design token 的价值，正在于把这些判断前置为可执行的约束。

设计检查清单：评审 AI 生成的界面时，先过四关——平台规范（导航/状态栏/按钮尺寸）、圆角体系是否统一、字体是否克制、信息层级是否匹配任务。把这些写成可复用的规则，比每次重抽更省事。

📎 超人的电话亭：AI 做的界面错在哪 · Lovable 侧边栏重设计

产品体验点评 PRODUCT TEARDOWN

案例一 · 人机协作

Claude Artifacts：把「验收」做成一等交互

Artifacts 的设计价值不在生成能力，而在于它重新定义了人和 Agent 的分工界面。过去协作软件关注「谁改了什么」，现在还要回答「Agent 正在做什么、做过什么、我如何让它改」。宝玉列举的三种模式——可见的 Agent 操作历史、用评论/标记替代复杂的手动操作、以及让 Agent 先采访人再动手——共同构成了一个「人设定目标、Agent 执行、人审查微调」的闭环。

其中视频剪辑的例子最能说明问题：传统时间轴要求用户具备「放大波形、识别静音、打标记、删除」的专业操作链；而在 Claude Motion 里，这一切被压缩成「框选区间 + 一句话」。复杂度的转移不是消失，而是从用户身上转移到 Agent 身上——设计的关键，是让人依然能看懂、能纠偏、能确认结果。

可见Agent 当前操作与历史全程透明
可改评论/标记替代复杂手动操作
可控Agent 先采访人，再实施

📎 来源: 宝玉 (@dotey) · 宝玉：软件主体之变

案例二 · 数据源选择

Marissa Mayer 的 Dazzle：把「相册」当作最低摩擦的个人数据

大多数 AI 助手盯着你的收件箱和日历，Marissa Mayer 的新创业 Dazzle 却选择了相册。她在 Product School 的播客里解释了这个反直觉的选择：相册是最丰富、摩擦最低的个人数据源；更关键的洞察是——约 40% 的相册照片其实是「待办事项」，而不是「回忆」。Dazzle 试图从照片里学习你的品味，再据此采取行动。

这个案例对用户研究有两层启发。其一，数据源的选择本身就是体验设计：越贴近用户已经自然产生、无需额外录入的数据，冷启动和持续使用的成本越低。其二，「40% 是任务而非回忆」是一个典型的重新框定——同一批数据，换个视角就从「记忆」变成「需求」。好的研究往往不发明新数据，而是重新解释已有数据。

📎 来源: Product School · The Product Podcast

研究方法论 RESEARCH METHOD

调研 · 行业问卷

LangChain 的年度《State of Agent Engineering》调查

Harrison Chase 宣布启动 LangChain 一年一度的「State of Agent Engineering」调查，希望了解社区究竟如何构建 Agent、以及大家最关心的问题。它的方法论价值不在结论，而在提问框架：当 AI 领域变化极快、缺乏稳定基线时，用一份结构化问卷定期采样「实践者的真实做法」，是建立行业参照系的低成本方式。

对用户研究员而言，这是一个可迁移的模板——把「大家怎么做」变成可比较的年度面板，而不是一次性访谈的零散洞见。设计问卷时，应把「行为」与「态度」分开提问，并保留开放题以捕捉尚未被命名的新实践。

📎 来源: Harrison Chase (@hwchase17)

流程 · 验收闭环

Meta Forum：把「做完」的标准接进执行过程

Meta 工程团队复盘了如何用小团队 + Agent 从零构建 Facebook Groups 的独立应用 Forum。核心不再是「生成更多代码」，而是让规划、实现、测试、修正持续运转：需求写成精确、机器可读的规格；构建结果、单元测试与界面对照持续反馈给 Agent；导航 Agent 操作正在运行的应用做回归验证；提交审查时附上构建、测试结果和验证录像。能编译不等于完成，每项上线仍需工程师批准。

他们最重要的结论是：最大收益来自改造代码和工具，而不是反复调提示词——让模块结构更清楚、让 Agent 直接读取模拟器的实时界面层级，而不是依赖文字描述。团队用八周实现了与 Facebook Groups 的核心功能对等，压力测试还帮助发现并修复了内存问题（修复后内存占用与缺页次数约减半）。这对研究流程的启示是：与其反复「教育」Agent，不如把「怎样算完成」变成环境里可执行的检查。

📎 来源: meng shao (@shao__meng)

流程 · 确定性验证

Shopify：30 人 12 周重建商家 App，功夫花在「怎么快速检查对错」

Shopify 工程团队把面向商家的 App 从 React Native 重建为 iOS 与 Android 原生，覆盖 300 多个页面。Agent 写了大部分代码，但并非一次性生成；真正费功夫的，是围绕「怎样快速、可靠地检查代码对不对」重新设计架构、工具与流程。过去 Agent 每改一次都要编译、开模拟器、看截图，一轮几分钟；现在多数页面能在终端里做确定性检查，几乎立刻得到反馈。

他们试过先写详细规格再交给 Agent，但规格很快过时；最终改为把正在运行的旧版 App 当作参照，用内部工具 Helix 读取旧实现、把迁移拆成便于审查的小步骤，再拿新页面与原应用对照验收。约 30 人两人一组、每人同时指挥多个 Agent，每个 PR 都必须由人审查。这提示用户研究：当生成加速，研究的重心会从「定义需求」前移到「设计验证」——可对照、可复现的验收标准，比一份详尽但易过期的规格更有价值。

📎 来源: meng shao (@shao__meng) · Shopify Engineering

洞察 · 重新框定

从「相册」读行为：一个重新框定数据的样本

Dazzle 的「约 40% 相册照片是任务而非回忆」是一个值得写进研究手册的洞察。它没有发明新数据，也没有做大规模采集，而是对用户已经自然产生、几乎零摩擦的存量数据换了一个解释框架——从「记忆/情感」转向「待办/意图」。这种重新框定往往比新增问卷更能揭示真实需求，因为它绕开了用户的自我报告偏差。

把它转成可操作的研究动作：盘点用户已经在产生、但尚未被产品利用的「副产品数据」；对这些数据尝试至少两种解释框架；再用小样本行为验证哪种框架更能驱动有价值的动作。这也是 AI 辅助研究最该发挥的地方——不是替代人做判断，而是帮人更快地尝试多种解释。

📎 来源: Product School · Marissa Mayer on Dazzle

UX 雷达 EARLY SIGNALS

● 对话式 Agent

ElevenLabs Interaction Engine：按复杂度调度模型

ElevenLabs 预览的 Interaction Engine 会编排会话 Agent 背后的多个模型：简单请求用便宜模型，退款等复杂任务才调用前沿模型，以在不过度消耗 token 的前提下拿到正确结果。这提示语音/对话体验的一个新维度——响应的「成本与延迟分层」，而不只是单次回答质量。

📎 来源: ElevenLabs

● 信息架构

Lovable：没人喜欢乱糟糟的侧边栏

Lovable 做了一次小而克制的重设计——项目在上、最近对话在下。它没有增加功能，只是重新安排了信息优先级。这类「减法式改版」往往最能体现设计判断：当 AI 能快速堆功能，知道什么该放上面反而更难。

📎 来源: Lovable

● 输入范式

MacBook Pro 首块触控 OLED 屏

新款 MacBook Pro 换上 Mac 史上首块 OLED 屏，也是首块支持触控的屏幕，同时更轻更薄（16 英寸减重约 320 克）。对交互设计而言，桌面与触控的边界继续模糊，未来跨端一致性设计需要重新考虑「手指 vs 光标」的混合场景。

📎 来源: 少数派

● 情感化设计

索尼复古耳机：卖的不是参数，是记忆

售价约 300 元的索尼 MDR-3R 没有降噪、不隔音，却借《怪奇物语》热度迅速售罄，二级市场一度溢价近一倍。它复刻 1979 年 Walkman 原装耳机的造型，只把线头换成 Type-C。这是情感化与怀旧设计的强案例：用户购买的是身份与记忆，而非功能清单。

📎 来源: 爱范儿

● 界面认知负担

Duet 桌面端：能力变强，入口却更绕

Peter Yang 肯定了 Duet 进入桌面端、能查看并评论 Claude Code 线程，但也直言界面「仍然很怪」：Code 标签页里找不到 Duet 选项、channels/threads 的心智模型不直观、为什么要在桌面端加载一整套新界面？这是「功能可用」却「结构不友好」的典型反馈，值得做 Agent 工具的人警惕。

📎 来源: Peter Yang (@petergyang)

● 人的价值

Dan Shipper：自动化之后，稀缺的是「非共识视角」

在 Every 的 Thesis 大会闭幕演讲中，Dan Shipper 提出：当智能变得廉价而普及，最稀缺的是人的视角——你的「非共识」判断，以及你对某个领域的责任，才是发现机会的来源。这为用户研究提供了一个价值锚点：研究的产出不应只是「大家都同意的事实」，而是能形成差异化判断的洞察。

📎 来源: Every · Dan Shipper

反面信号 · 值得警惕

AI 功能的成本冰山：API 费只是最小的一块

一位 AI 产品经理提醒：很多 PM 看一眼 API 账单就以为成本可控，但数据标注、人工审核、知识库维护、流程调整与坏案例兜底加起来，通常是 API 费的 3 到 5 倍。文中以 Klarna「裁掉 700 人又招回 400 人」的教训为例，强调在决定做 AI 功能前，应把四项成本算清楚。

这对以「降本 / 自动化」为卖点的用户研究同样适用：当体验设计过度依赖自动化，被砍掉的往往正是「人工兜底」这一环，而它恰恰是用户在出错时最后的信任来源。评估 AI 功能时，应把「异常路径的人工接管成本」显式计入，而不是只看理想路径的调用费。

📎 来源: 人人都是产品经理
