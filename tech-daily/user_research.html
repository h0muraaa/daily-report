01AI 产品正在集体从"聊天框"毕业，进入"委托式"交互时代

过去 24 小时里，三条新闻拼出了同一个趋势：OpenAI 把 ChatGPT 与 Codex 合并、让近十亿用户直接接触到能"实际干活"的 Agent；Anthropic 的 Claude Cowork 扩展到网页和移动端，合上电脑任务仍继续执行，手机变成"管理 Agent 工作的控制台"，遇到需要人类判断的节点才推送通知请你决策；腾讯 WorkBuddy 则把同类能力做成"更适合国人体质"的本土产品。这意味着用户体验的核心问题正在从"AI 答得好不好"转向"我敢不敢把任务交给它、我如何监督它"——信任建立、进度可见性、中途干预点是新一代 AI 产品的体验主战场。

设计洞察：当产品从"问答"变成"委托"，用户需要的不是更快的回复，而是对执行过程的可感知与可撤回。Anthropic 强调"邮件发送、文件交付等最终动作仍需用户审查批准"，这正是委托式交互的信任锚点，值得每个 Agent 产品抄作业。
📎 来源：Riley Brown · InfoQ · 爱范儿

02"Claude 变笨"风波：一次设置项引发的用户信任危机

今年 3 月起，大量开发者抱怨 Claude Code 突然"变笨"：该读的文件不读、任务半途而废。AMD 的 AI 负责人 Stella Laurenzo 甚至翻出 6852 个会话日志，实测模型思考量下降 67%，公开质疑其工程可靠性。Anthropic 近日亲自下场澄清：问题出在用户混淆了"模型选择（Model）"与"努力度（Effort）"两个选项——为压低延迟，官方曾悄悄调整默认 Effort，而用户的第一反应是花更多钱换更贵的模型。这是一场典型的"系统变更不透明 → 用户错误归因 → 信任受损"的体验事故。

设计洞察：对用户不可见的默认行为变更，比功能缺陷更伤信任。当产品存在多个影响输出质量的"隐形旋钮"时，界面上必须让当前状态可见、变更有告知，否则用户会用脚投票——或者用钱包投错票。
📎 来源：新智元

03年度从业者情绪调查：AI 把科技圈人群"几乎精确地"切成两半

Lenny's Podcast 与研究负责人 Noam Segal（曾任职 Airbnb、Meta、Twitter、Figma 等）发布第二年度的 Tech Worker Sentiment Survey。这项覆盖产品、工程、设计、研究、市场、数据、销售等数千名从业者的大型定量研究发现：AI 已把科技从业者几乎对半分成"正在腾飞"和"深感动摇"两个阵营，并归纳出四种情绪原型。对于做用户研究的人来说，这份报告本身就是一份关于"研究者/设计师群体自身处境"的珍贵样本——我们研究的用户在变，我们自己也在变。

研究提示：这是目前少有的、连续两年的科技从业者 AI 情绪纵向数据，适合作为团队内部分享和职业路径讨论的素材，也提醒我们：设计 AI 产品时，"对 AI 焦虑的那一半人"同样是目标用户。
📎 来源：Lenny's Podcast

04OpenAI 招聘"家庭产品经理"：AI 的下一个体验战场是客厅

据极客公园报道，OpenAI 正通过招聘家庭产品经理将关注重心从个人用户扩展至家庭用户。ChatGPT 发布三年多后，头部 AI 公司开始认真回答"AI 如何进入多成员、多年龄段、共享设备的家庭场景"。家庭场景意味着账号体系、儿童保护、隐私边界、代际数字素养差异等一整套全新的体验命题——这与个人生产力工具是完全不同的设计坐标系，也是用户研究可以提前布局的方向。

📎 来源：极客公园

05"UI 是面子，代码是里子"：一场关于 AI 生成物双重标准的讨论

宝玉在 X 上的一句吐槽引发共鸣："为什么你们对 AI 味的 UI 设计嗤之以鼻，反而对 AI 味的代码甘之若饴？"——没人在乎衣服是什么棉花做的，但人人在乎衣服好不好看、有没有撞衫。同一周，GPT-5.6-sol 登顶 Code Arena 前端榜，Peter Yang 随即抛出一个尖锐问题："你怎么 benchmark 设计品味（design taste）？"这两条看似随意的社交动态，实则戳中了 AI 时代体验设计的核心难题：视觉输出的"品味"无法像代码正确性一样被客观度量，而这恰恰是用户最直接感知到的部分。

📎 来源：宝玉 (@dotey) · Peter Yang (@petergyang)

设计趋势洞察
值得写进趋势报告的两个设计信号。

趋势一：反效率设计——会"回信"的魔法日记 Riddle

交互范式情感化设计

当几乎所有 AI 产品都长成一个样子——左边历史记录、中间聊天窗口、底部输入框——GitHub 上一个约 1.4k Star 的开源项目 Riddle 走了一条完全相反的路。它复刻了《哈利·波特》中汤姆·里德尔的日记：你看到的是一张空白纸，用 reMarkable 手写笔写下一句话，停笔几秒后，页面"吞掉"你的墨迹，然后用手写动画一笔一画地把回复"写"出来。技术上，它把手写页面转成灰度 PNG 交给视觉模型识别，再用 Dancing Script 字体做路径追踪，按笔画动画回显到电子墨水屏。

作者明确说：它不追求快，也不追求信息密度，追求的是一种完整的错觉——"你不是在操作一个 AI 工具，你是在和一本奇怪的日记通信"。在 AI 能力日趋同质化的今天，Riddle 的出圈证明了一件事：氛围感本身就是产品差异化。当"AI 已经很会回答问题"成为基线，让回答变得有仪式感、有情绪温度，可能成为下一代消费级 AI 产品的体验壁垒。这也回应了今日要点 05 的争议——用户能一眼认出"AI 味 UI"，恰恰说明体验层的品味稀缺而值钱。

📎 来源：逛逛GitHub · 项目地址 github.com/MaximeRivest/Riddle

趋势二："控制台模式"——手机成为 Agent 的监督与审批终端

多端协同信任设计

Claude Cowork 登陆移动端最值得注意的设计决策，不是"在手机上也能聊天"，而是角色分工的重新洗牌：桌面端是任务的下达与执行场所，手机则成为异步监督与关键节点审批的控制台——任务在远程环境持续运行，Agent 遇到需要人类判断的问题时推送通知到手机，用户做出决策后 Agent 继续工作，而最终动作（发邮件、交付文件）必须经过人工批准。InfoQ 指出，这一定位变化"可能比模型升级更重要"。

腾讯 WorkBuddy 的万字复盘文章则从工程侧印证了同一方向：Agent 产品是否可用，模型只决定上限，上下文组织、权限边界、结果验证、反馈纠正这些 harness 层设计才决定能否落地。两端结合看，一种新的体验架构正在成形："后台长任务 + 移动端轻干预"。对设计师而言，这意味着需要设计全新的界面类型——任务时间线、审批卡片、中断与接管机制，而不是又一个聊天窗口。

📎 来源：InfoQ · Founder Park

产品体验点评
本周值得拆解的两个产品体验案例。

案例一：腾讯 WorkBuddy——"水土不服"是最好的本土化需求清单

爱范儿的深度体验指出，Codex 这类海外本地 Agent 在中国用户场景里"水土不服"：网络环境、账号体系、权限配置、本地路径，"这些细节只要卡住一次，普通用户的耐心基本就被消耗掉了"。WorkBuddy 的解法不是弱化能力，而是保留 Agent 拆任务、调工具的硬核内核，同时替普通人卸下所有折腾环境的包袱——下载安装即用。界面采用经典三栏：左侧任务与历史管理、中间对话区展示 Agent 的拆解过程与执行结果、底部输入区可切换模型、调用技能、连接应用、附加文件或工作文件夹。配合混元 Hy3 模型限时免费，快速形成了试用热度。

体验启示："卡住一次就流失"是非技术用户对 Agent 产品的真实容忍度。WorkBuddy 最值得学习的不是功能，而是它把竞品用户的挫败点逐条转化为自己的设计 checklist——这是用户研究中"竞品流失用户访谈"价值的完美例证。另外，"展示 Agent 拆解过程"这一设计，本身就是建立信任的关键手段：让用户看见思考，而不只是看见结果。
📎 来源：爱范儿 · Founder Park

案例二：iPod 之父的提醒——好产品卖不动，往往是"用户选择"环节出了问题

人人都是产品经理转载的这篇文章复盘了 Tony Fadell 在 Lenny 访谈中的观点：即便是 iPod 这样的突破性产品，也经历了三代艰难迭代才打开市场——第一代只服务 Mac 极客（当时 Mac 市占率仅个位数），真正的转折点是支持 Windows 并推出 iTunes，把目标用户群整个换掉。Fadell 的结论是：产品创新 ≠ 商业成功，从研发阶段就必须把营销、销售、渠道、供应链整合进同一套 GTM 规划，而 GTM 的第一项就是"用户选择"。文章同时举了 Humane AI Pin 作为反面案例。

研究启示：对用户研究员来说，这个故事最有价值的部分是："为谁设计"的决定往往比"设计成什么样"更早、更深地决定了产品命运。iPod 的拐点不是设计改良，而是目标用户的重新定义——这恰恰是用户研究最该介入、却最常被跳过的一环。
📎 来源：人人都是产品经理

研究方法论
本周可借鉴的研究方法与度量思考。

大规模纵向情绪调查：Tech Worker Sentiment Survey 的方法论看点

Noam Segal 与 Lenny 合作的年度调查已进入第二年，覆盖产品、工程、设计、研究、市场、数据、销售等职能的数千名科技从业者，量化追踪他们对工作、AI、职业倦怠与未来的态度变化。其方法论上有三点值得借鉴：一是纵向复访——同样的问卷连续做两年，让"情绪变化"本身成为可度量的信号，而非一次性快照；二是定量先行、归纳原型——从大样本数据中提炼出"四种情绪原型"，再反哺定性访谈提纲；三是研究者即社区成员——调查依托 Lenny 的产品社区发放，样本天然覆盖高活跃从业者，招募成本与应答质量兼得。

📎 来源：Lenny's Podcast

如何度量"设计品味"？——Code Arena 前端榜引出的度量难题

GPT-5.6-sol 登顶 Code Arena 前端榜、与 Claude Fable 5 并列第一，靠的是人类偏好投票式的竞技场排名。Peter Yang 的追问——"你怎么 benchmark design taste？"——点破了 UX 度量在 AI 时代的尴尬：代码有测试用例，设计没有。目前业界实际采用的路径是"大规模人类偏好对比 + 领域细分榜单"（该榜已细分出数据分析、品牌营销、消费品、游戏等维度）。对用户研究者而言，这既是威胁也是机会：偏好投票的本质就是极简化的用户测试，而研究者的价值在于回答投票背后"为什么"——哪些视觉特征、交互细节驱动了偏好，这正是传统可用性研究可以补位的地方。

📎 来源：Peter Yang (@petergyang)

田野里的洞察：共享菜园热潮教我们的需求分层

一个看似与科技无关的案例，实则是用户需求分析的绝佳教材。盒马在上海上线"沪上共享菜园"：20 平米地块年租 1298 元、30 平米 1598 元，含冠名权、耕种采摘权、管理权；北京丰台一处农场 600 多个客户、地块早已全数租出。知危的分析指出，这门生意同时踩中了两层需求：表层的食品安全焦虑，与深层的情绪疗愈——都市中产"试图用劳作换取一些确定性的疗愈"，并衍生出托管服务、合租模式等平台化玩法。对研究者而言，这个案例示范了如何将一个消费现象拆成"功能性需求 + 情绪性需求 + 社交货币"三层结构，并识别出哪一层才是用户真正付费的理由——同样的框架可以直接迁移到任何新产品的需求验证中。

📎 来源：人人都是产品经理 / 知危
