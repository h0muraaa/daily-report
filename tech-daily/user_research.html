用户理解 / 个性化

AI 时代最大的 UX 痛点，是"每次都要重新认识你"——网易蜜蜂AI给出的解法

网易传媒在 8 月 18 日发布统一的 AI 能力底座「蜜蜂 AI」，率先放进年轻人社区产品网易小蜜蜂里，走了一条与再造通用 AI 产品不同的路线：让 AI 进入社区、内容和人与人的关系之中。网易传媒副总裁张智敏提到一个典型场景：第一次提问说得不完整，结果不满意；补充条件后方向依然偏差，用户大量时间消耗在调整 Prompt 上。传统的互联网产品先认识账户再认识用户——淘宝知道购买记录、抖音知道停留时长、网易云知道循环歌单——而生成式 AI 让这套关系倒了过来：用户面对的是一个能力极强却经常"失忆"的对象。蜜蜂 AI 的思路是把用户关系和内容理解能力向前延伸：在用户授权下参考学校、专业、经历、关注方向，再结合持续补充的材料、时间、预算和偏好完成任务，从"找到信息"走向"采取行动"。这给用户研究员一个清晰的信号：个性化不再只是"行为标签"，而是一次需要用户主动授权的、持续的"重新认识"过程。

📎 来源：爱范儿

信任设计 / 透明度合规

Claude 为所有 AI 文字加水印，全球用户"彻底怒了"——透明合规与体验的张力

为响应欧盟《人工智能法案》Article 50(2)——自 2026 年 8 月 2 日起所有生成合成文字/音/视频的 AI 系统必须确保输出含机器可读标记——Anthropic 宣布现有 Claude 生成的文字将带水印，新版本模型从发布第一天起内置。这次使用的是参考谷歌 SynthID-Text 的"统计水印"：按密钥让模型"有规律"地挑选同义词，文本足够长后形成可机器识别的特征，与年初针对中国用户采用的字符水印不同。媒体的叙事很直接：用户感到被"当爹"、被强制、缺少选择。这是一个教科书级的"透明合规 vs 用户体验"冲突样本——当监管要求为 AI 内容打上不可见的烙印，品牌如何让合规不变成对用户的冒犯，正是信任设计要回答的问题。

📎 来源：爱范儿

消费级AI / 社交网络效应

Benchmark 合伙人：下一个爆款 AI 产品将具备社交功能——从"我和机器"到"人们彼此学习"

Benchmark 合伙人、Pinterest 最早 30 名员工之一的 Sarah Tavel 提出：模型在榜单上多拿几分，很少直接改变普通人的使用习惯，真正的网络效应会出现在多人产品里。她观察到今天的消费级 AI 仍以单人体验为主——一个人打开聊天框，自己摸索提示词、项目和自定义指令；熟练用户已用它处理健康、写作和决策，而更多人仍把 ChatGPT 当搜索框。她认为这个落差藏着下一批创业机会：真正有产品直觉的团队，会把高手的用法变成可发现、可验证、可直接复用的公共能力，让 AI 从"我和机器"走向"人们彼此学习"。这其实是对消费级 AI 的一次"用户分层"判断——大众用户缺的不是更强的模型，而是把专家用法产品化的中间层。

📎 来源：晚点再听LaterCast

跨设备 / Agent App 体验

豆包越来越像 Codex：手机指挥电脑、虚拟桌面"人与 AI 同时操作"的本土化 Agent 体验

宝玉在长文里拆解了豆包这波更新为什么让他觉得"越来越像 Codex"：从 GUI 电脑操作到手机远程操控，很多设计思路能看到 Codex 的影子，有些地方还做了本土化超越。最打动他的场景很具体——他老婆人在国内、电脑在美国，直接用手机上的豆包指挥美国那边的电脑找出文档、发到飞书。他特别点出豆包 Windows 版 GUI 操作的巧思：通过豆包虚拟桌面让人和 AI 同时操作电脑、互不干扰，不像 Claude Code 一旦用 Computer Use 就得等它操作完才能继续干活。手机指挥 Agent 成了他日常高频功能：通勤路上随时看任务进度、中途插话调整，回家直接看结果。对用户体验研究而言，这是"跨设备 Agent"体验的绝佳案例——学习成本、异步操控、并发协作这些设计维度，正在成为 Agent 产品体验的新度量标准。

📎 来源：宝玉(@dotey)

人机协同 / 权限设计

Aravind Srinivas：构建 Agent 时仍要让人类保留"方向盘"——Allow / Always Ask / Deny

Perplexity CEO Aravind Srinivas 明确表态：构建 AI Agent 时，重要的是仍要给人类保留主导权（agency），让用户能随时把手放在方向盘上、必要时干预。与之配套，Perplexity Computer 新增了细粒度权限：每个连接器工具都可设为 Allow（允许）、Always Ask（总是询问）或 Deny（拒绝）；用户可以只批准单次操作，也可以允许该工具在整条对话线程内生效，定时运行的会话会遵循该线程的授权。这是"人在回路"（human-in-the-loop）从理念落地成具体交互控件的又一实例——权限设计的颗粒度（单次 vs 线程）直接决定了用户的安全感与信任建立速度。

📎 来源：Aravind Srinivas(@AravSrinivas)

交互范式 / 实时媒介

趋势一：实时生成式视频——从"提示—等待—拿到文件"到"边看边操控"的新交互形态

两条来自 AI Engineer 大会的信号指向同一个方向。uRun 的 Keegan McCallum 给出一个把"实时"变成日常的换算：十美元现在能买大约三小时的连续生成视频，五十美元能买十五小时；他认为生成式视频有意思的轴早已不是质量——实时生成与需要几分钟的生成相比，慢的剪辑运动更细腻，但成本高约百倍，真正的解锁是"不同的交互形状"：网络摄像头成为可实时操控的生成界面。Reactor 的 Ahmed Ahres 用 GPS 和取景器类比把论点推到更本质：实时是媒介的变化而不是速度的提升——GPS 之前你查的是别人画好的地图，之后你的位置成了可以连续行动的坐标；取景器让你边拍边调，才有了 Instagram 和 TikTok。而今天的生成式视频还停在"你提示、你等待、拿到一个文件、然后无事可做"的那一侧。他的世界模型定义不是更长片段，而是可交互、近乎无限、快到可以操控的视频。对设计师与用户研究员来说，这是值得跟踪的交互范式信号：当产出从"静态产物"变成"可连续调控的实时流"，用户的心智模型、错误恢复与反馈设计都要随之重写。

📎 来源：AI Engineer · uRun · AI Engineer · Reactor

商业形态 / 界面消亡

趋势二：结账页面终将消失，AI Agent 成为买家——设计价值从"执行"转向"判断"

Stripe 产品与业务总裁 Will Gaybrick 在 a16z 访谈中给出一个让交易体验设计师坐不住的判断：结账页面终将消失——不是结账流程变简单了，而是这个页面从根本上就不该存在；AI Agent 将成为互联网上最主要的买家。他的逻辑是：当"实现成本趋近于零"，真正稀缺的不再是执行力，而是判断力。这背后是整个软件行业的底层重构——从怎么造产品、怎么组建团队，到商业交易的形态本身。对产品与用户研究而言，这个趋势把设计问题从"如何让表单更好填"推到了更上游：当购买动作由 Agent 代劳，人机界面的重心从"操作执行"转向"意图表达、授权边界与结果确认"——设计稀缺资源转移到判断层、信任层与决策支持上，而不是执行层的像素。

📎 来源：深思圈

垂直场景 / 个性化

实测飞猪 AI「飞猪帮帮」：当 AI 走出代码的"封闭数字环境"，进入充满不确定性的旅游

AI 科技评论对飞猪升级后的消费级 AI「飞猪帮帮」做了实测复盘。文章点破一个关键差异：AI Coding 之所以能快速商业化，很大程度得益于封闭纯粹的数字环境——代码环境确定、结果可客观校验、容易形成 Agent 迭代闭环；而旅游是落地难度极高的垂类，用户需求高度个性化、服务链路冗长、信息繁杂零散，还受制于实时供给、线下履约与现实环境的各类变量。文章同时给出产业背景：传统 OTA 的旧商业模式已走到边界，用户对同质化平台服务失去新鲜感，OTA 转型重构从选择题变成必答题。对产品与用户研究员来说，这是一个观察"AI 在物理世界垂类落地"的切口——个性化需求越强、链路越长的场景，越考验 Agent 对用户意图的理解、对实时信息的组织，以及对"线下承诺能不能兑现"的兜底设计。

📎 来源：AI科技评论

竞品体验 / 横向评测

Grok Bot vs Hermes vs ChatGPT Work：三款 Agent 产品的体验横向评测

Peter Yang 以"用户视角"对三款 Agent 产品做了对比评测，对产品/UX 研究很有参考价值。Hermes：开源、可高度定制，但需要在 Mac Mini 或 VPS 上 DIY 部署；ChatGPT Work：浏览器操作与语音功能同类最佳、适合重度用户，但痛点在于 Chat/Work/Codex 三套界面让 UX 变得混乱，且浏览器还不能登录你的常用应用；Grok Bot：内置持久云电脑，UX 简单、聚焦、令人愉悦，但灵活度较低（想在同一 bot 上开多线程时受限制），且起步价 $200/月——而 ChatGPT Work 花 $20/月就有不错用量。他的结论是：仍以 ChatGPT 为日常主力，但赌 OpenAI、Anthropic 等很快会跟进 Grok Bot 的持久云电脑路线。这则评测把"学习成本、跨模块一致性、价格与价值感知"三个维度摆进了 Agent 产品体验的核心度量。

📎 来源：Peter Yang

眼动追踪 / 认知对比

当 AI 逐帧复现人类的眼动轨迹：foveated MLLMs 与人类视觉搜索的对照实验

一篇 arXiv 新论文把"眼动追踪"这一经典可用性方法延伸到了 AI 上。人类视觉搜索是串行的：中央凹（fovea）必须落在候选目标上才能确认，这些落点构成一条 scanpath。研究者将三种通用多模态大模型（MLLM）与人类眼动轨迹做对照，在目标导向搜索任务（COCO-Search18）中，用人类匹配的 foveated 视图逐 fixation 驱动模型，并从三个轴评估：目标是否存在判断、到达目标的效率、以及凝视过程本身。结果很有信息量：三轴是分离的——在判断与目标获取上，模型匹配甚至超过人类，但"凝视过程"与人类明显不同。这意味着眼动数据既可以用来研究 AI 是否像人一样"看"，也提示用户研究者在用眼动做体验评估时，要区分"结果指标"与"过程指标"——AI 能给出一样的答案，不代表它经历了和用户一样的注意过程。

📎 来源：cs.MM updates on arXiv.org

决策支持 / 对话设计

"钢人论证法"Prompt：让 AI 辅助决策更全面的一套对话结构

数字生命卡兹克分享了一个底层很扎实的 Prompt 方法，源自 Reddit 上一句英文原话——"Stop asking it for answers. Ask it to steelman your problem first."（别让它直接给答案，先让它用钢人论证法重述你的问题）。所谓"钢人论证"（steelman）是从"稻草人谬误"（straw man）反向造出来的词：不是树一个最弱的靶子来打，而是把对方的观点重构到最强再回应。具体的 Prompt 结构是四步：1) 用最完整、最有力的方式重述你真正想解决的问题；2) 用钢人论证分别给出支持你当前想法、以及反对它的最强论证；3) 找出双方真正的分歧，以及最可能改变结论的关键变量；4) 只问你一个最关键的问题，等你回答后再给出判断、理由与下一步行动。对用户研究员而言，这套结构既是 AI 决策支持产品的对话设计范本，也可迁移到深访提纲的设计——先确认"用户真正的问题"，再暴露观点对立面，最后收敛到最关键的单一追问。

📎 来源：数字生命卡兹克

需求挖掘 / 定性洞察

Reddit 是一个巨大的"需求池"：用户不说"想买什么"，只说"被什么折磨"

一篇文章把 Reddit 定义为创业者的需求金矿，方法论值得用户研究员借鉴。关键洞察是：用户在 Reddit 上并不会说"请给我做一个 AI 自由职业者合同审查 SaaS"，而会说"客户拖了我三个月的钱，因为我当时根本没看懂合同里的这一条"——后者才是更有价值的需求信号。截至 2026 年第二季度，Reddit 日活独立用户达 1.303 亿、周活 5.146 亿，几乎每一种足够具体的兴趣、职业和生活状态都有对应社区。文章从中提炼出六个已被产品落地的方向：帮成年人找到真朋友、给自由职业者配 AI 律师、宠物跨国旅行指南、数字遗产管理、短信 AI 助手、反刷屏应用。对用户研究来说，这示范了一条低成本的"需求发现"路径——把社区抱怨当作非结构化的用户日志来编码、聚类与验证，是从吐槽里长出产品机会的标准动作。

📎 来源：人人都是产品经理

AI身份 / 用户信任

AI 虚拟大一新生闯入 Bama Rush：被认出是假的后，人们为什么还在看

一位 AI 生成的虚拟新生参加了今年全美最受关注的大学女生联谊会招募活动 Bama Rush，一周内涨了 1200 粉丝、近百万播放，还拿到了品牌合作与媒体关注；她在 48 小时内就被识破是 AI，但人们依然持续观看。这个案例把"用户如何对待已知是假的 AI 内容"摆上了台面——信任与内容消费并不总绑定在同一件事上，识别出造假并不等于停止观看。对研究 AI 内容体验与平台治理的团队，这是一个值得追踪的早期信号。

📎 来源：Justine Moore(@venturetwins)

人机协作 / 设计工具

Remotion Skills 2.0："AI 生成 → 人工微调 → 再交给 AI 迭代"的创作闭环

Remotion 发布 Skills 2.0，三个更新都很戳创作工具的痛点：子技能化（从"一个大文件塞满最佳实践"改为 router 加 12 个专项技能，只把相关信息送进上下文）；可交互（AI 生成的代码可以直接在 Studio 里拖拽编辑——移动位置、缩放、旋转、调缓动，编辑会写回源码而不是临时预览）；审美中立（把设计决策权还给用户）。这构成了一个清晰的人机协作工作流：AI 搭结构、人做审美判断、再把微调结果交回 AI 继续迭代。它示范了工具设计从"AI 替代人"转向"AI 初稿 + 人精修"的产品范式。

📎 来源：meng shao(@shao__meng)

设计评审 / 品味自动化

Tastelint：把"设计品味"装进 PR 的自动评审 Agent

Sahil Lavingia 的观察是"代码基本解决了，但设计还没有"，于是推出 Tastelint——一个跑在每个 PR 上、主动给出设计反馈的 Agent。这条推文引发 586 条回复与 12 万+ 阅读，说明"设计评审自动化"触到了很多团队的痒处。它抛出的问题是：设计品味能否被 Agent 化？如果能，设计评审流程、设计系统的落地方式，乃至设计师在研发流程中的位置都会改变——这是值得放进 UX 雷达的早期职业与工具信号。

📎 来源：Sahil Lavingia(@shl)

健康科技 / 消费行为

DUSQ 电击助眠贴片爆卖：用户愿意为"没被说出口的痛点"买单

印度班加罗尔团队做的一枚 12 克神经刺激贴片 DUSQ，在 Kickstarter 30 天众筹到 123 万美元（4326 人支持，早鸟价 229 美元起），刷新印度健康科技公司在 Kickstarter 的纪录。它处理的是一个大多数人不知道的问题：睡着后交感神经每晚可能出现二三十次"涌动"，自己察觉不到，但每一次都可能把人从深睡拉回浅睡——这就是"睡够八小时依然疲惫"的原因之一。产品整夜监测神经信号，用皮肤电传感器识别"涌动"，再在几秒内施加微电流刺激迷走神经与耳后前庭神经。这个案例提醒用户研究员：对"用户不知道自己有问题"的隐性痛点，产品教育本身就是核心体验设计。

📎 来源：创业邦

AI人格化 / 设计细节

blobatar：从任意字符串生成确定性头像——给 Agent 一个稳定可见的"脸"

一个小巧的设计工具引起了注意：blobatar 能从任意字符串（用户名、邮箱、ID——任何有名字的东西）确定性生成一个头像，同一输入永远得到同一张脸，不需要存储、不需要上传，纯前端实现约 3.7KB。当越来越多的 Agent、机器人账号、AI 联系人出现在 IM 和协作工具里，一个低成本、稳定、可辨识的视觉身份就成了"AI 人格化"的基础设计细节——这也是评论里"适合 agent im 的默认头像"的共鸣点。

📎 来源：Yangyi(@Yangyixxxx)
