“去 AI 味”从文案技巧变成产品策略

Tw93 给出一套做“不丑且易用”产品的排序：能解决问题 > 易于使用 > 好看。他的方法很具体——把自己当成完全不懂技术的小白，完整走一遍主链路，找出卡点和讲不清的地方；文案要符合当地人的说话习惯，而不是干巴巴的翻译；能用产品本身表达清楚的，就不要再加一段说明。另一边，量子位观察到“去 AI 味”已经催生新行为：有人刻意把文章写得粗糙、不工整，以此作为“这是人写的”信号。文章也提醒，文风并不是可靠的身份证据。两件事放在一起看，用户对“过于顺滑”的文本已经产生审美疲劳与信任折扣，设计需要重新为“不完美”留出位置。

AI 面试：效率工具正在变成求职者的体验黑箱

创业邦旗下「定焦 One」记录了今年秋招的一个新常态：简历刚投出，限时测评和 AI 面试邀请就到了。屏幕里一张仿真人脸念题、计时、追问，低头可能被弹窗提醒，回答太短可能扣分。有求职者投了 600 份简历、面了 15 场 AI 面试，只见过 7 次真人面试官，至今 0 offer；也有人面了 30 场 AI、真人面试只有 5 场左右。更让人无所适从的是评分维度不透明——应聘机械工程师却被追着问 C++，有人被要求脱下外套上传全身照，还有人入职后才知道仪容仪表也计分。求职者的应对是“用 AI 打 AI”：让一个模型扮演面试官陪练，或在 AI 提问时让另一个模型生成答案照念。企业省下了筛选成本，候选人却失去了反馈与申诉的入口。

无障碍正在成为 Agent 时代的“公共接口”

Browser Use 分享了一个浏览器 Agent 技巧：不要再截图找按钮，而是直接向 Chrome 要无障碍树——通过 CDP 调用 Accessibility.getFullAXTree 拿到每个元素的 role、name 和 node id，筛出链接、按钮、输入框，再用 DOM.getBoxModel 算出中心点点击。在 Hacker News 页面上，1,764 个节点里有 227 个可点击元素，视觉 token 消耗为零。同一时间，宝玉在复盘 GPUI 时点破另一面：GPUI 性能好、跨平台、AI 友好，但 Accessibility 支持不太好，支持键盘操作会比较麻烦。他最终换回 Electron，一个重要原因是 Electron 应用能被 Agent 内置浏览器直接打开验证。无障碍不再只是合规清单，它同时决定了机器能不能理解界面、人能不能不靠鼠标操作界面。

02

设计趋势洞察

Design Signals
趋势 01

生成式 UI：界面从“预先画好”走向“按需生成”

Vercel 的 Guillermo Rauch 给出了一个明确的判断：把 AI SDK、Chat SDK 和 json-render 组合起来，可以让模型直接生成 UI，在 Slack、Teams 这类平台上从 LLM 一步走到界面，他认为这将成为人机交互（HAI）的主导形态。AI SDK 的更新也印证了这条路线的工程化：开发者可以先搭一个 Agent，再挂上 json-render，让它按对话需要生成界面，而不是预先为每种情况写死页面。

产品侧的动作更快。Devin 上线了 Inline HTML Artifacts，让按需生成的交互界面直接出现在回复里；Element Picker 允许用户点选一个 UI 元素，再告诉 Devin 要改什么——把“指哪儿改哪儿”变成了 Agent 的输入方式。ChatGPT 的 Remix 面向 Business 和 Enterprise 推出：同事做了一版网站，你可以用自然语言说出想改的地方，生成自己的副本，再继续在对话里编辑。Notion 则把 Agent 放进评论区，让它像同事一样发布进度、和页面浏览者并排出现。

速度已经不是瓶颈。向阳乔木用 Opus 5.5 加 Codex Goal 完成开源录屏工具 Capwise 的第一版，一次 Goal 指令运行 6 小时，补上了音频降噪、素材库、封面帧、片头片尾管理等模块，计划“边用边打磨”。但速度也带来新的设计问题：当界面是按需生成而非预先设计，设计系统要从“定义每一个屏幕”转向“定义可被生成的组件语法与约束”。seangoedecke 的观察值得警惕——他认为一个团队里超过一个设计师就容易出问题，并对设计系统抱有复杂的负面看法。生成式 UI 会把这个张力放大：约束太松，界面失去一致性；约束太紧，生成又失去意义。

研究启示：评估生成式 UI 时，除了“生成得像不像”，更要测三件事：同样的意图是否会稳定生成可预期的结构；用户是否知道如何纠正生成结果；纠正之后系统是否记住。设计系统的价值将从“视觉一致性”扩展到“可生成性”和“可纠正性”。

趋势 02

把“过程”设计出来：Agent 的可观察性与可纠正性

Notion 的做法是让 Agent 的进度直接出现在评论区，和页面浏览者并排——用户不需要猜它做到哪一步，也不需要切到另一个界面看日志。Devin 的进度更新和 Element Picker 同理：把“正在做什么、需要你指哪里”变成界面的一部分。这些看似零散的功能，共同指向一个设计命题：Agent 的能力越强，用户越需要看见过程，否则信任只能建立在结果上，而结果一旦出错就无法定位。

Anthropic 公开的 Claude 记忆设计提供了更完整的结构。记忆被分成四层：会话记录保留经历，笔记提炼值得记的内容，wiki 组织知识之间的关系，少量启动上下文告诉下一次会话该去哪里找。后台的 “dreaming” 不是让模型睡觉，而是把整理经验与眼前任务分开，专门回看、纠错、去重、补链接、建知识库。meng shao 转述的实验数据很关键：在约 35 万份文件、4.2 亿 token、25 个评测问题的内部语料里，单靠搜索的评分标准覆盖率是 53%；知识库结合搜索后，随着整理轮次增加从 54% 提升到 61%，每题少用约 2 万 token。研究团队的结论也很克制——后台整理能改善部分任务，但不是检索的替代品，也未必总能抵消维护成本。

对体验设计来说，这意味着“记忆”不该被包装成一个不可见的魔法功能，而应像文件系统一样可查看、可编辑、可删除。用户需要知道 Agent 记住了什么、为什么记住、什么时候会用到；也需要能纠正一条错误笔记，而不是只能推翻整个会话。可观察性不是调试工具，它本身就是信任界面。

研究启示：做 Agent 研究时，增加“过程回看”任务：让用户在一段任务结束后指出 Agent 哪一步理解错了、希望它记住什么、哪些记录应该删除。观察用户是否能在不读日志的情况下理解 Agent 的状态，是比满意度更前置的体验指标。

产品体验点评

Product Experience
案例 01

Brainrot：把“少刷手机”变成一只会受伤的数字宠物

用户场景

创始人 Yoni Smolyar 原本是软件工程师，自己也沉迷 Instagram、YouTube 和 X。他做过几个没起势的小项目，Brainrot 最初只是为自己做的工具，2025 年夏天上线，主要卖年订阅。用户先选出容易刷过头的 App；花在这些应用上的时间越长，宠物“大脑”的状态就越差。应用能按时段拦截指定应用，也能查看每天的时间花在哪里。据他在访谈中披露，月收入从约 1 万美元增长到约 40 万美元。

设计动作

最关键的设计不是“锁应用”，而是在冲动与行动之间插入一次微摩擦：点开 Instagram 时，先弹出一通视频来电，来电显示写着“你的大脑”。趁这几秒钟，用户可以问自己：刚才是有事要看，还是又顺手点了进去？把抽象的“自控力”外化成一只会变差的宠物，让后果持续可见，而不是等到月底看一份冰冷的使用报告。

体验启示

反成瘾产品的核心不是更强的限制，而是给用户一个“暂停键”。Brainrot 用拟人化状态提供持续反馈，用一次轻量摩擦替代硬封锁，把“别刷了”变成用户对自己的提问。这套设计也有伦理边界：如果宠物状态被做成羞耻或负罪感来源，可能从帮助变成新的压力。评估这类产品时，除了留存和收入，还应观察用户是否感到被支持，而不是被审判。它的增长路径也值得研究团队借鉴——先解决自己的问题，再去找有同样问题且愿意付费的人，然后用行为与渠道数据决定下一步。

来源：晚点再听LaterCast（Starter Story）
案例 02

OPPO N6 的 181 度：用户感知到的是“平”，不是参数

体验观察

向阳乔木记录了一个很典型的聚会场景：朋友用 OPPO N6 折叠手机，大家都觉得屏幕“超级平”，甚至比 iPhone Duo 还好。直到另一位朋友发现秘密——这台手机展开是 181 度，屏幕是被“绷平”的。原以为是黑科技，结果朴实无华，但细想又挺巧妙。同一个帖子还提到，最近 OPPO 的产品口碑在变好，比如 AI 心力球、24 小时录音记录，让人“有点种草”。

设计洞察

多出的 1 度不是参数上的胜利，而是感知上的校准。用户不会拿量角器量折叠角度，他们只会看屏幕平不平、折痕明不明显、拿在手里是否踏实。工程师视角的“180 度是标准”，在体验视角里可能刚好差一点；把结构做到略有过盈，反而让视觉和触觉同时得到确认。更有意思的是传播机制：这个细节可以被一句话转述——“你知道它其实是 181 度吗？”——于是产品拥有了一个可复述的故事。

体验启示

体验设计要区分“规格真实”和“感知真实”。前者写在参数表里，后者发生在用户第一次展开手机的那一秒。好的硬件体验往往藏在这种“多一点点”的校准里：不是堆料，而是让用户可感知、可确认、可转述。同时也要看到另一面：24 小时录音、心力球这类 always-on 的感知能力，正是 Personal AI 所需的 Context 来源，但它必须处理好知情、可见与可关闭，否则“贴心”很容易滑向“被监视”。

研究方法论

Research Methods
方法 01

用户共构评测集：让“最想被帮的日常任务”定义成功

OpenAI 发布 LifeVal，一个衡量 AI 在“日常生活中真正重要的事情”上进展的基准。它的任务不是研究员拍脑袋想出来的，而是由数千名 ChatGPT 用户的反馈塑造——从找托儿服务、办理政府事务到管理个人财务，都是用户最希望个人助手帮上忙的场景。OpenAI 表示，过去一年里用 LifeVal 来衡量并改进模型处理这些日常任务的能力。这个做法对用户研究的意义在于：评测集本身就是一种用户研究产物，它把“用户在意什么”固化成了可持续追踪的标尺。

怎么做：在团队内部建立一份“用户日常任务库”，来源可以是访谈中的真实故事、客服工单、搜索词和社群讨论，而不是竞品功能清单。每个任务写清楚用户目标、当前替代方案、失败代价和成功标准。用它来做需求排序、模型选型和版本回归，会比“我们觉得用户需要”更可辩护。
来源：OpenAI
方法 02

让 AI 当审稿人，而不是写手：一套可迁移到访谈分析的流程

X 官方创作者账号发布了一份 Grok Bot 短视频指南，作者 Ethan Ng 在 SpaceXAI 增长团队做创作者营销。小互和 meng shao 都做了拆解，其中几条原则几乎可以直接搬到用户研究。第一，先喂上下文再开工：历史成片、过往脚本、改稿反馈、认可的爆款、后台数据，再加上用语音交代的口头禅和禁用套话，而且要聊好几轮，五分钟搞不定。第二，别让 AI 代写，让它挑刺：直接让 AI 写出来全是说明书腔；正确用法是你交草稿，它像教练一样批注“开头太慢”“讲道理讲得太早”“这句不像你”。第三，用行为数据定位问题：比如 0:18 留存掉了，让 Bot 给出三个可能原因——从讲故事切到讲解释、镜头一直没换、悬念已经揭晓——下一条再去验证。第四，保留两道人工把关：出剪辑方案后要人说 “I APPROVE” 才开剪，成片再审一遍。

迁移到研究：把访谈记录、研究框架、过往洞察和业务背景先交给模型，再让它标注“受访者可能在哪里失焦”“哪句回答与前面的表述矛盾”“哪些结论缺乏证据”。AI 的角色是提出可验证的怀疑，而不是替研究员下结论。留存曲线对应到研究里，就是关键节点的用户流失信号——先定位在哪一步，再回头解释为什么。
来源：小互 (@imxiaohu) 来源：meng shao (@shao__meng)
方法 03

步骤级评估：共情对话不能只看最后一句回复

新智元报道了香港中文大学与微软研究团队在 NeurIPS'26 的工作 EchoChat，问题意识非常贴近用户研究：多阶段推理中，局部误判会成为后续判断的前提，并持续影响后续步骤。这在共情语音对话里尤其突出——感知、心理状态推断与回应生成紧密关联，早期偏差最终可能导致对说话人需求的误解和不恰当的回应；即使后面逻辑连贯、表达得体，也可能建立在错误依据上。团队把这种现象称为“共情模仿”（empathetic mimicry）：回应听起来温暖，却与说话人真实的心理状态和需求不匹配。仅凭最终回复做整体评价，很难定位偏差来自哪一步。EchoChat 把感知、心智理论推理和回复生成纳入统一优化框架，用级联门控奖励约束阶段依赖，并通过步骤级信用分配提供针对性更新信号。

研究启示：访谈分析也可以拆成三段分别校验：我们听到的事实是什么（感知）、我们推断的需求是什么（心智理论）、我们给出的回应或设计是什么（回应生成）。在每一段标注证据来源和置信度，可以避免“洞察听起来很顺，但建立在一句被误读的话上”。做情感计算类产品时，别只测“用户觉得回复是否温暖”，还要测“回复是否对上了用户真正的问题”。

UX 雷达

Early Signals
交互范式 01

Frameboy：像玩掌机一样实时探索 AI 场景

李飞飞团队发布世界模型“模拟掌机” Frameboy，被描述为“像玩掌机一样实时探索 AI 场景”。它提示的是一种不同于聊天框的交互模型：用户不是在提示词里描述世界，而是在一个可操作的空间里边走边看。对于做空间、游戏、教育或沉浸式产品的团队，值得关注它如何在没有复杂手柄的情况下降低探索门槛。

来源：创业邦
设计工具 02

Craft Anything：先研究，再构建的“取证式”设计工具

曾开源 Photoshop、Office 替代品的团队把逆向本事做成了 Craft Anything：用户指定目标后，工具先收集外观、布局和行为信息，再交给编码 Agent 构建，并在三种屏幕宽度下检查成品与参考对象的差异。它提供 300 多个工具，支持 CLI 和 MCP；“净室模式”只用外部可见信息，“深度模式”才分析代码和脚本。是否越界仍取决于使用者对版权与授权的判断，但“先取证、再动手”的流程对设计研究很有启发。

Agent 界面 03

Rune：为 Agent 留出“观察窗口”的桌面应用

Viking 发现 OpenCode 的 Rune 颜值很高，更重要的是支持 headless 模式——不打开应用、不显示界面也能运行，并提供截图模式和元素树，供 Agent 调试与观察。传统桌面应用假设“人看着屏幕操作”，Rune 则假设“Agent 也需要看见界面”。这可能成为下一代工具类应用的基础能力：同一套界面，既能给人用，也能被机器读取。

细分需求 04

Bloom：纯文本、org 格式与“可迁移”的执念

少数派介绍的 Bloom 是一款原生支持 org 格式的笔记应用：纯文本、允许纯本地运行、可无缝切换平台，内置日记、快速笔记和任务笔记模板。笔记市场看似已经稳定，但仍有用户愿意为“我的数据不被锁死”付出学习成本。它对应的是一个稳定的细分人群：对排版要求不高，但对可迁移、可掌控、可长期保存极其敏感。

情境化工作流 05

DockSide：为“办公 / 摸鱼 / 设计”切换整套程序坞

DockSide 是 macOS 上的程序坞管理工具，支持快速切换多套工作区、添加间隔整理图标、快捷键调用，中文界面永久授权 39 元，可激活 3 台 Mac。它解决的不是“Dock 不够用”，而是“同一个人在不同情境下有不同工具组合”。当工作和生活的边界越来越模糊，让界面随情境切换，可能比让用户自己整理图标更符合真实行为。

信息架构 06

TED：健康信息搜得越多，人可能越害怕

前 WebMD 首席医疗官 John Whyte 在 TED 演讲中提出一个反直觉的问题：为什么在线搜索症状总是让人更恐惧？他多年相信“更多信息等于更健康”，直到看到过量信息如何让人陷入螺旋。在健康网红、算法和以留存为目标的 AI 工具包围下，他主张“清晰与上下文”才是更好的处方。对信息密集型产品来说，这是一条重要的设计提醒：给出答案之外，还要给出边界、概率和下一步。

注意力设计 08

注意力的两端：一边被榨取，一边花钱恢复

meng shao 对短剧和短视频发了一通很重的批评：推荐流把“让人多刷几个视频”做到一流，再通过金钱刺激创作者生产更抓眼球的内容，用户的时间被逐秒变现。几乎同一时间，吴晓波频道写到新中产周末花钱进山找“山大夫”，并引用注意力恢复理论——自然环境凭借远离感、延展性、迷人性与契合性，让人不费力地转移注意力。两端放在一起，产品设计多了一个可量化的伦理维度：这个功能是在帮用户恢复注意力，还是在消耗它？
