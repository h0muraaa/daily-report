🎨 设计趋势洞察

交互范式迁移

从对话框到画布：AI 设计工具进入“项目制”阶段

过去一年多，AI 设计产品的核心交互基本停留在“输入一句 prompt，生成一张图或一个页面”。但最近一周的信号显示，这个范式正在明显转向“画布 + 持续迭代”。昆仑万维天工 3.1 推出了 Skywork Design，把设计过程从对话框延展到可视化画布，支持多页面 UI 项目的持续修改；同时也有用户展示了 Codex 与 Excalidraw 结合后形成的“无限画布”工作流，可以直接用自然语言驱动原生白板内容。

这种转变的用户价值很直接：单次生成只能做 demo，真实业务交付需要处理多页面一致性、移动端适配、风格统一和版本修改。数据显示，天工的深度用户在单个 project 上平均交互超过 40 轮，复杂项目会横跨多次登录完成。这说明用户已经把 AI 工具当作项目协作方，而非一次性生成器。

UX 启示： 下一代 AI 创作工具的竞争焦点，将从“生成质量”转向“多轮协作中的上下文稳定性”。设计师需要的不只是更好的模型，而是更像 Figma 的图层管理、版本历史与组件系统。

微体验质量

AI 生成内容的“小瑕疵”正在拉低专业感

本周两条独立观察都指向同一个问题：AI 生成内容在微观层面的缺陷，会迅速被用户识别为“AI 味”。一条指出 AI 生成的 HTML 标题 line-height 常常过紧，只要换行就显得局促；另一条则用 Nano Banana 对 GPT-Image-2.0 生成的图片做超分放大，去除破碎纹理和无意义细节，让画面更锐利、文字更清晰。

这些细节本身不涉及模型能力，却直接影响用户对内容可信度和专业度的判断。当 AI 生成内容越来越普及时，“去 AI 味”的后期处理可能成为新的设计工序。

UX 启示： 产品团队应当建立“AI 输出 polish 清单”，把排版、间距、图像纹理、文字清晰度等微观指标纳入验收标准，而不是只看生成是否完成。

📱 产品体验点评

DockSide：把 macOS 程序坞的“边缘空间”变成文件中转站

《少数派》本期推荐了一款 macOS 效率工具 DockSide。它在程序坞两侧创建常驻的“置物架”，让用户随手拖放文件、图片、链接、文本和文件夹，在不同应用之间快速中转。与 Yoink、Dropover 等浮动面板不同，DockSide 选择锚定在 macOS 最核心的 UI 区域旁边，利用原本被忽视的边缘空间。

这个设计的巧妙之处在于“不增加新窗口”，把临时中转融入用户已有的视觉焦点区。左侧置物架可以放文件和临时笔记，右侧用于快捷取用。对多任务切换频繁的设计师和研究员来说，这种低打扰、高可达性的交互减少了窗口管理的认知负担。

体验洞察： 好的效率工具不一定创造新的工作区，而是把功能嵌入用户已经熟悉的视觉锚点。对桌面端产品而言，“屏幕边缘”仍是被低估的设计资源。

[来源: 少数派]

Spark Ring：用“双击录音”把灵感捕捉的摩擦降到最低

《创业邦》报道了一款由前字节大模型团队员工创业的 AI 语音戒指 Spark Ring。与大多数主打健康监测的智能戒指不同，它定位成“全球首款语音智能体”，通过双击录音、声纹识别、离线转写等功能，捕捉用户“想记却来不及记”的灵感。

戒指形态的核心体验价值在于“随时在场”。手机需要解锁、打开 App、找到入口，而戒指就在手指上，双击即可开始。这种把输入入口前置到身体末梢的设计，显著降低了记录的启动成本。对于用户研究场景来说，这类低摩擦的“即时 capture”设备，也可能成为日记研究或情境访谈的辅助工具。

体验洞察： 可穿戴设备的下一个机会，可能不在于“监测更多数据”，而在于“把高频但低意愿的输入动作变得毫不费力”。

🔍 研究方法论

包容性设计视角：ADHD 用户不是“不爱整洁”，而是需要明确的“物品默认位置”

本周一条关于 ADHD 与房间整理的推文引发大量共鸣。作者指出，很多 ADHD 患者的房间“物品乱但并不脏”，问题的根源不是懒惰，而是他们不知道每件东西该放哪里。对他们而言，收纳只有两个极端：要么为每个物件设计专门位置，要么完全不知道该放哪里。

这条洞察对工具设计和家居产品设计都有重要启发。当产品的默认状态没有给出清晰的“东西属于哪里”的暗示时，用户更容易陷入使用中断和放弃。这与日本收纳理念中“一物一位”的核心原则不谋而合，也解释了为什么很多效率工具需要提供模板、默认文件夹或自动分类。

研究应用： 在进行可用性测试或用户访谈时，可以特别关注用户如何处理“结束状态”——任务完成后，他们是否清楚内容、文件或对象应该归到哪里？这往往是产品留存的关键细节。

[来源: Susan STEM(@feltanimalworld)]

图标可用性的低成本测试法：缩到 App Store 尺寸再判断

独立开发者小耳分享了一套图标挑选方法，核心是把候选图标缩到 App Store 的真实尺寸去观察，而不是看设计稿大图。她还建议把图标放进现有图标堆里对比，避免和大厂“蓝蓝的一片”撞脸，同时确保颜色能跳出来、语义清晰、与产品调性一致。

这个方法本质上是一种“情境化快速验证”：把设计资产放回用户真正会接触到的环境，而不是在理想化的大图模式下评审。对于用户研究员和设计师来说，这是一种可以低成本复用的启发式评估方法。

研究应用： 在评审任何视觉元素时，都可以问自己：用户会在什么尺寸、什么上下文、什么竞争环境中看到它？把测试条件还原到真实场景，往往比专家评审更能发现问题。

[来源: Berryxia.AI(@berryxia)]
