◎设计趋势洞察

趋势一

从"设计原型"到"生产创作"：Figma 的全栈化跃迁

Figma Config 2026 释放出明确信号：设计画布不再只是 UI 原型的诞生地，而是向动效、代码、3D、生成式插件一体化的创作环境演进。Figma Motion 支持在熟悉的设计流程中直接制作复杂动效与发布影片；Code Layers 把代码能力直接嵌入画布；3D Transforms 让设计师可以在二维工具中探索三维空间；生成式插件允许用户用自然语言描述行为、控件和参数，由 Figma agent 生成专属工具。

对用户体验研究者而言，这一趋势意味着设计工具的能力边界正在模糊化。研究者需要关注：当"设计师"与"前端开发"的边界被打破，协作角色如何重新定义？当 AI 生成的设计元素可以直接发布为可用产品，设计评审、可用性测试和质量把控的介入点应该前移到哪个阶段？此外，Weave 工具进入画布也提示我们，设计系统正在从"组件规范"向"可编排、可生成的工作流"升级。

趋势二

"环境智能"：AI 从应用界面融入组织协作流

Claude Tag 的发布把 AI 交互从"打开聊天窗口"推进到"@一下工作群里的同事"。它常驻 Slack 频道，理解线程上下文，调用工具查询监控、代码、文档并返回结果，还支持 ambient 模式主动跟进。Andrej Karpathy 将这一变化概括为 LLM UI/UX 的第三次重大改版：第一代是去网站访问，第二代是下载桌面应用，第三代是成为组织内有持久上下文、有工具权限、与人类并肩工作的实体。

这一范式对 UX 设计的挑战在于：我们过去设计的是"用户与软件的交互"，现在要设计的是"人类团队与 AI 同事的协作"。关键体验变量包括：AI 在群聊中的可见性（它正在做什么、进度如何）、介入时机（什么时候主动发言、什么时候保持沉默）、记忆与权限边界（跨频道上下文如何隔离）、以及人类接管的顺畅度。这些都不是传统界面控件能解决的问题，而是需要建立新的人机协作礼仪与信任机制。

✎产品体验点评

Claude Tag：当 AI 成为 Slack 里的"队友"

Anthropic 把 Claude 以 @Claude 的形式嵌入 Slack，用户可以在频道中分配任务，Claude 会在线程中逐步完成并返回结果。它与临时呼叫机器人的最大区别在于：共享身份与上下文、支持多人接力、可持续学习团队工作模式，并能在 ambient 模式下主动跟进沉寂线程。

从用户体验角度，这种设计解决了三个长期痛点：信息碎片化——任务过程和结果都沉淀在原有协作线程中，无需切换工具；接力成本——同事可以在 Claude 做到一半时接着聊，无需重复背景；权限焦虑——管理员可以精确指定每个频道的 Claude 能访问哪些工具和数据。Anthropic 内部数据显示，产品团队 65% 的代码已由内部版 Claude Tag 生成，用途还扩展到查产品数据、处理客服工单、排查疑难 bug。

值得持续观察的风险是：当 AI 主动介入对话时，如何区分"有帮助的主动"与"打扰"？ambient 模式的触发阈值、通知频率与可预测性，将直接影响用户是否愿意长期把它留在频道里。

Genspark Design 与 Figma Make：AI 设计工具的"最后一公里"体验

Genspark Design 宣称覆盖 UI 原型、视频、HTML 动画、海报等多种设计产出，支持上传 Figma 文件保持品牌一致性，并能一键生成可用代码。Figma Make 则被设计师用来从提示词快速生成个人作品集网站，并可直接导入 Figma 画布进行手动精修、免费发布上线。

这两款工具的共性是：把"从想法到上线"的链路压缩到极致，让非专业用户也能产出看起来像专业水准的作品。但对 UX 研究者来说，真正的研究价值不在"生成"本身，而在"生成之后"：用户如何与 AI 协作迭代？品牌一致性在多大程度上依赖人工校验？生成结果中的可用性问题、无障碍缺陷和文化适配问题如何解决？当执行门槛消失，设计师的核心竞争力将从"会不会做"转向"判断好不好、为什么好、对谁好"。

Meta AI 眼镜：可穿戴多模态交互进入主流价位

Meta 发布自有品牌 AI 眼镜 Adventurer、Fury 和与 Kylie Jenner 联名的 Starfire，起售价 299 美元（约 1999 元人民币），比第二代 Ray-Ban Meta 便宜 80 美元。新品搭载 Muse Spark 多模态大模型，配备 1200 万像素摄像头、6 麦克风阵列、8 小时以上续航，以及可折叠充电盒。

从用户体验视角，这款产品的意义在于把"看即问、听即答"的多模态交互从早期尝鲜者推向大众市场。关键体验问题包括：公共场合拍照/录像的隐私信号设计、语音交互在嘈杂环境中的可靠性、长时间佩戴的舒适度与时尚感平衡，以及多模态输入下的反馈时机——用户何时需要语音回答、何时只需要视觉提示？对于研究可穿戴设备的 UX 团队，这是一个观察"社会接受度"与"日常可用性"如何共同演化的关键样本。

✚研究方法论

识别"AI 生成作品集"：招聘与用户研究中的真实性评估

Tom MacWright 在《Accidental anonymity》中指出，招聘者越来越多地看到由 LLM 共同撰写的求职申请、生成的作品集网站、LLM 生成的 GitHub 项目乃至自动生成的提交记录。这种"完美生成"的简历让他感到"对这些人一无所知"——他们没有表达任何真实的东西。

对 UX 研究者的启发是：当我们研究用户行为、进行用户招募或评估设计能力时，也需要建立识别"生成内容"与"真实表达"的能力。具体可以从以下几个维度入手：查看决策痕迹而非最终成品（如设计迭代过程、失败尝试、手写笔记）；关注个人化叙事与具体情境，而非泛泛的能力清单；在访谈中追问"为什么这样设计"，检验其是否真正理解用户与约束。对于正在使用 AI 辅助创作的用户研究，也要区分"AI 生成的洞察"与"研究者基于真实用户数据得出的洞察"。

来源: Simon Willison's Weblog

从 Feminist HCI 视角审视性别化语音 AI 设计

一篇 arXiv 论文从 Feminist HCI 视角研究了商业平台上"性化"的 AI 生成英语语音。研究者通过聆听实验结合定量形容词选择、定性自由文本反馈和声学分析，发现性别化脚本会放大并编码特定的性别权力不对称。新技术可能带来性赋权与性别表达多样性，但有毒的男性气质、异性恋规范以及对女性和 LGBTQ+ 群体的伤害仍然普遍存在。

这项研究为语音产品 UX 设计提供了重要方法参考：当设计虚拟助手、客服机器人或社交语音角色时，声音性别化不是中性选择，而是会激活用户既有的社会刻板印象。研究者可以借鉴该论文的多方法组合（量化形容词 + 定性反馈 + 声学分析），在自身产品中评估声音人设对用户感知的影响，并建立更具包容性的语音设计标准。

来源: arXiv eess.AS
