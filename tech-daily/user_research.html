用户留存 / 个人 Agent

40 天 1090 万下载：Muse 的用户成绩单，照出 Claude Duet 的“精致但慢”

Sensor Tower 数据显示，Meta 的 AI 助手 Muse 自 9 月上线以来，40 天累计下载量达到 1090 万次，其中美国市场 1020 万次；只有另外 11 款应用达成过这一上线里程碑，上一款还是 2023 年 7 月的 Threads。更值得产品团队注意的是，Muse 的用户留存表现优于 ChatGPT、Claude、Grok 等竞品——下载只是入口，留存才说明它是否进入了日常。

另一边，How I AI 对 Anthropic 新个人 Agent Claude Duet 的实测给出了另一种样本。Claude Duet 装在手机上，继承 Claude 的插件与连接器，面向小企业主和忙碌的专业人士。评测者称它是自己见过“最精致的 Agent 发布”：引导得体、任务清单清晰、artifact 是一等公民、还有 Slack 式频道。但在真实任务里——收件箱与 Slack、销售管道、Google Docs 销售材料、发布视频、给孩子找球票——它暴露出三个体验短板：任务闭环太慢、只适合单人使用、召回用户的方式仍停留在“又一份早间简报”。

研究启示：个人 Agent 的评估应从“下载/激活”转向“首周留存、每周主动任务完成数、任务平均闭环时长”。精致的 onboarding 能带来第一次惊叹，但决定留存的是“它多久能替我把事办完”，以及“它如何在不打扰的前提下把我叫回来”。

主动性 / 工作流

一次“没被安排”的主动推送：Personal Agent 的价值在协调，不在代劳

产品经理阿颖记录了自己重度使用 Today AI 近一个月的体验。它接入飞书、钉钉等日常办公工具，让移动端使用 Agent 的频率明显上升；起初她也觉得 Personal Agent 可能是伪需求，因为和已有的 Coding Agent 差别不大。真正改变判断的是一个中秋假期的瞬间：公司一个未上线产品的资源消耗突然上升，团队在群里一边讨论一边排查，排查到一半去吃午饭；回来打开手机，Today AI 已经主动推来消息，比对最新数据、标出主要消耗项和计算口径——她并没有给它安排这个任务。

同一天，AI 助理公司 Town 宣布完成 1.08 亿美元 B 轮融资，估值 10 亿美元。其产品方向是每位员工拥有自己的 AI 助理，助理之间可以相互询问、交接工作，帮助推进需要多人参与的项目。Menlo Ventures 描述的场景是：早上人还没开电脑，助理已整理好邮件与简报；到了周末，它还在跟进未完成事项。文章点出一个容易被忽略的问题：单项任务越快，人反而要在更多结果之间判断与协调，效率提升不会自动覆盖“为什么做、哪些已确认、接下来谁跟进”这部分工作。

研究启示：主动性不是“多推送”，而是“在正确时机、带着证据地接手协调”。值得研究用户如何设定主动边界、如何验证 Agent 的判断、以及一次误报之后信任如何衰减。
来源： AI产品阿颖 · 很多人压根没看懂 Personal Agent · 有新Newin · 当 Personal Agent 有了记忆

上下文 / 记忆

没有 Personal Agent，只有 Context + Agent：上下文正在成为体验资产

上海期智研究院 PI、智羽慧科技创始人李彪提出一个尖锐的判断：这个世界上从来就没有什么 Personal Agent，有的只是 Context + Agent——同一个 Agent 接上工作上下文就是 Work Agent，接上生活上下文就是 Personal Agent。他举了千问办公 8 月开源的 MyContext 为例：它把钉钉、飞书里的聊天与协作记录整理成一份持续更新的工作档案，每条记录都标明来源与时间；前后信息对不上时系统先自行判断，拿不准就来问用户，用户确认过的结论模型不能自行修改。这个设计的关键不是“记得多”，而是“记得有出处、可纠正”。

Every 评估负责人 Mike Taylor 则从另一个方向提醒上下文的风险。他关闭了 Claude 与 ChatGPT 的跨对话记忆，但仍然认为单条对话本身会随着任务推进不断累积旧指令、过时方案和错误结论，他把这种现象称为 Context Rot（上下文退化）。他的做法是：每接到一个新任务，就新开一条对话。对产品而言，这意味着“记忆”不是一个开关，而是一组需要被看见、清理、隔离和设置有效期的界面对象。

研究启示：把上下文当作可研究的界面：用户能否看见它、纠正它、删除它、限定它的作用域？访谈中可以追问“你最近一次发现它记错了是什么时候、你怎么改的”，比笼统询问“记忆好不好用”更能暴露真实问题。

信任设计 / ChatGPT

ChatGPT 同时加广告与“聊天锁”：信任设计进入深水区

OpenAI 开发者账号披露了 ChatGPT 广告的产品逻辑：符合条件的广告展示在回答下方，并标注为 sponsored；如果广告在回答完全生成后才到达，就不会在该轮展示，回答本身也不会等待广告。其 orchestrator 会把一段对话拆成多个意图，通过探索用户可能的需求来扩展广告匹配；嵌入检索找出候选广告，再经过资格与相关性检查收窄，最后由竞价工具完成选择与定价。广告不是简单的“贴一条”，而是被嵌入到对用户意图的实时推断里。

同一天，ChatGPT 还上线了两项与信任直接相关的功能。Slides 允许用户基于对话、上传文件或大纲生成演示文稿，支持模板、团队共享、实时协同编辑与评论，并能根据反馈自动调整幻灯片，导出 PDF 或 PowerPoint。Locked Chats 则允许用四位 PIN 锁定对话，支持设备上用 Face ID 或 Touch ID 解锁；锁定对话进入单独区域，不出现在历史、置顶和搜索结果中，记忆开启时拥有独立记忆。但 OpenAI 明确说明：锁定不等于端到端加密，也不会改变保留时长与训练设置；重置 PIN 会永久删除所有已锁定对话及文件。

研究启示：广告的“相关性解释”和聊天锁的“安全感 vs 技术安全”落差，都是可用性与信任研究的富矿。建议用可理解性测试检查用户是否真的明白“锁住”意味着什么，并用威胁模型访谈识别高风险场景下的错误预期。
来源： OpenAI Developers · 广告展示逻辑 · OpenAI Developers · orchestrator 与竞价 · 少数派 · ChatGPT Slides 与聊天锁

输入体验 / 微交互

紫毫 Hare：把“手指按偏了”当成一等公民

少数派体验了 iOS 端新上架的 Rime 输入法“紫毫 Hare”。它主打开箱即用，底层是 Rime 引擎与雾凇拼音词库，并针对移动端触屏重新适配：除了 26 键与九宫格，还为小鹤双拼单独设计键盘布局，在键位上直接标注对应韵母，减少初学者的记忆负担。更关键的是“双拼纠错”：它把手指触碰落点与拼音构词规则结合起来，单手盲打按偏到相邻键位时，能较好地纠正并识别整词。

长句输入上，紫毫首次启动会自动下载约 6.8MB 的“紫毫口语”模型，官方称其长句推断效果接近约 400MB 的完整版；模型只在整句输入时介入，打两三个字的短语依然利落。存储紧张的用户可切换到 1.9MB 轻量版、完整万象模型或八股文语法模型，也可以直接移除模型，回到纯码表。简繁输出、中英混输、Emoji 候选与快捷短语也都保留。

研究启示：移动输入的关键不是“模型多大”，而是“何时介入”。分层模型 + 场景触发，是低打扰智能的一个可复用模板；值得测量纠错的接受率、误纠带来的烦躁，以及新用户与 Rime 老用户之间的体验差异。

设计趋势洞察

两个正在成形的转向：主动性需要新的交互契约，产品定义正在回到小团队与真实问题。

Trend 01 · 主动性

从“响应式助手”到“注意力托管”：主动性需要一份新的交互契约

今天的 Personal Agent 竞争，已经从“能不能回答问题”转向“能不能在没人开口时做对事”。Today AI 的主动推送之所以打动人，是因为它带着上下文、数据对比和明确结论出现，而不是一条泛泛的提醒；Town 则把记忆、应用连接和主动通知组合成“团队助理之间互相交接”的产品假设。主动性正在成为差异化来源。

但主动性有代价。How I AI 对 Claude Duet 的连续吐槽很具体：任务闭环太慢会让人失去耐心；它需要更好的方式把用户叫回来，而不是“又一份早间简报”；Claire Vo 甚至说它“应该更烦人一点”——这句话的意思不是制造噪音，而是现有召回机制太弱、太可预测，无法在关键时刻把用户拉回任务。通知、提醒、升级与静音，正在从边缘功能变成 Agent 的核心界面。

Greg Isenberg 提供了一个更宏观的视角：Agent 是“一个拿着信用卡、只读你的网站而不看你的页面的顾客”。他把 Agent 与商家的关系拆成从 research、prepare 到 pay 的信任阶梯，并提到 Amazon 阻止 Meta 的 Muse、Delta 把外部订票 Agent 视为未授权自动化、Yelp 向 Agent 收费等摩擦。当 Agent 代替用户行动，产品不仅要为人设计，也要为“被代理的人”设计可读性、授权与追责路径。

对用户研究的含义 需要把“主动性阈值”作为可测量的设计变量：什么情况下应该主动、主动时带多少证据、用户如何暂停/静音/撤销、误报后信任如何修复。研究对象也从“一个人如何用”扩展到“一个人如何授权一个代理去代表自己”。

Trend 02 · 产品定义

好产品先于好设计：产品定义正在回到小团队与真实问题

Google Labs、Gemini 与 AI Studio 副总裁 Josh Woodward 给了一个反设计冲刺的观察：NotebookLM、Flow、AI Studio 和 Google Beam 都不是从 design sprint 里长出来的，而是来自“一小群停不下来的、着迷的人”。这不是否定结构化方法，而是提醒：当问题本身还没被定义清楚时，五天的流程只能加速错误的假设。

MrBeast 的首席产品与技术官 Shiva 提供了另一种流程样本：一个拥有 5.2 亿订阅、近 90 天 16 亿播放的频道，把每条视频都当作一次产品发布——发布前有评审，发布后有复盘，每天都有构建循环。因为这里的“产品”就是内容本身，团队可以深入到真实工作流里做改变，而不是只优化一个承载平台。AI 正在重写这套运营方式。

Codex 的万字复盘则说明产品形态与模型能力是耦合的。半年前很少有人相信 Codex 能追上 Claude Code；早期云端 Codex Cloud 迟迟找不到 PMF，工程负责人离职去了 Cursor；退回本地后，团队顶着“CLI 不够好用”的压力重写底层 Agent。准备做原生桌面端时，又纠结要不要内置代码编辑器，结果更强模型发布后，这个问题自己消失了。今天 Codex 桌面端周活突破 500 万，并在 7 月被改造成新的 ChatGPT 桌面 App。UDL 设计合伙人在播客里也给出同样的判断：技术门槛降低不等于好做，工业设计最难的前半程是如何定义一款产品；Rabbit R1 很酷，却很难让用户理解它的价值。

对用户研究的含义 把研究前置到“问题定义”阶段：用小样本深访、快速原型和真实任务验证替代“先做完整方案再测”。设计冲刺可以作为对齐工具，但不应被当作创新引擎；真正稀缺的是对问题的持续凝视，以及在模型能力变化时重新定义产品形态的判断力。

产品体验点评

两个案例：一个把“纠错”做成了输入体验的核心，一个把 AI 藏进会议场景的物理边界。

输入工具

紫毫 Hare：在“开箱即用”和“可调教”之间找平衡

Rime 一直是高阶输入法用户的乐园，但配置门槛也把它挡在了大众之外。紫毫 Hare 的选择是：保留 Rime 引擎与雾凇词库的能力，把默认体验调到“装好就能直接打字”，再让愿意折腾的人继续往下调。这个定位本身，就是对“专业工具如何走向普通用户”的一次回答。

三个设计决策值得借鉴。第一，为小鹤双拼单独设计键盘布局，并在键位上标注韵母，把学习成本从“记键位表”转移到“看一眼键盘”；第二，双拼纠错同时利用手指落点与拼音构词规则，把“按偏了”视为输入信号而不是用户错误，这对单手盲打尤其重要；第三，模型分层且按场景触发——6.8MB 口语模型只在整句输入时介入，短语输入不被拖慢，存储紧张还能切到 1.9MB 轻量版或直接移除。它没有把“更聪明”等同于“所有时候都更重”。

点评：这类产品的体验风险不在功能少，而在“聪明得不是时候”。建议用首周打字日志观察三类事件：纠错被接受、纠错被撤销、用户主动改回原词；再结合新用户与 Rime 老用户分组，比较他们对“自动纠正”的容忍度。对专业工具而言，可预测性往往比偶尔的惊艳更重要。
来源： 少数派 · 紫毫输入法体验
AI 硬件

Verso：把 AI 藏进一块 78 克的墨水屏

AI 硬件品牌 Flowtica 完成数千万元新一轮融资，由祥峰资本领投，源码资本、五源资本及清水湾基金等老股东跟投。其 AI 墨水屏产品 Verso 已在海外开启定金预售，计划 12 月交付首批。它是一块 78 克、6.5 毫米厚的磁吸墨水屏，贴在手机背面，定位是“墨水屏工作伴侣”——福尔摩斯身边的华生，而不是另一个抢注意力的主屏。

Verso 把场景收得很窄：会议前、中、后的闭环。开会时按一下开始录音，实时转写与总结，结束录音自动生成待办；过程中单击标记重点、双击生成待办，并在墨水屏上实时查看；按 Ask 键可以就当前上下文提问，也能直接交代任务。物理按键被保留下来，恰恰是为了减少“掏出手机、解锁、找 App”的上下文切换。它拒绝把所有上下文都塞进一个聊天窗口，而是把“记录、标记、追问”拆成几个低干扰的物理动作。

点评：这类产品的成败不在模型，而在三个体验细节：会议场景的录音知情与同意是否足够自然、多人对话的说话人归属是否可信、自动生成的待办是否让用户敢直接采用。建议用会议类型分层的日记研究，测量“瞥一眼就能理解”的比例、对摘要准确性的信任校准，以及设备吸附在手机背面时的长期佩戴意愿。

04

研究方法论

三套可以直接迁移到 AI 产品研究中的方法：接话时机、犹豫识别，以及把 Agent 当作用户来研究。

M1

SocialOmni：把“何时接话”从回答质量里拆出来

厦门大学等机构提出的 SocialOmni，评测的是多模态模型在多人对话中的社交交互能力，而不是单轮问答的正确率。它把“说话人归属、是否应该介入、如何自然续写”放在同一套诊断视角下，并公开逐条回答。论文中的一个案例很能说明问题：一场讨价还价已经以“好吧，拿去吧”结束，Gemini 3.1 Pro 回了一句“很高兴与你做生意”，而 Qwen3.5-Omni-Plus 却把之前的加码条件又重复了一遍。后者并不跑题，语法也没问题，但它没有跟上对话已经发生的变化；三位评委给前者 100 分，给后者 25、0、25 分。

这套方法对语音助手、会议 Agent 和客服 Agent 都直接适用。传统评测只看“开口之后说了什么”，会漏掉“该开口时没开口”和“不该开口时抢话”这两类更伤体验的失败。研究时可以把一次会话拆成若干“接话时机点”，分别标注是否轮到它、是否应该介入、介入后是否自然，再与内容质量分开打分。

  1. 用会话日志定位轮次边界，而不是只取单条回复。
  2. 把“该不该说”和“说得好不好”分成两个独立指标。
  3. 记录沉默、打断、重复前文等失败模式，做频次统计。
  4. 在多人场景中额外标注说话人归属与指代消解错误。
来源： AINLP · SocialOmni 多模态社交交互评测
M2

多模态“犹豫识别”：情感计算进入更细的行为颗粒度

arXiv 论文《Multimodal Ambivalence and Hesitancy Recognition with Bidirectional Audio–Text Cross-Attention》提出一个视频级的矛盾与犹豫（A/H）识别框架。它分别用多语言 BERT 和 wav2vec 2.0 编码完整转写与语音波形，把两者投射到共享表示空间，再用两层双向交叉注意力让语言 token 与声学帧互相“看”，不需要显式时间对齐；最后通过掩码平均池化聚合，并结合拼接、逐元素乘积与绝对差做二分类。

对用户研究而言，这类能力的价值在于辅助标注，而不是替代访谈。访谈录像里大量信息藏在“停顿、语气变弱、说了半句又改口”里，人工逐帧标注成本很高；模型可以先筛出疑似犹豫片段，再由研究员回看语境。但要注意生态效度：实验室视频与真实访谈的声学环境差异很大，文化背景也会影响犹豫的表达方式，模型分数不能直接当作“用户真实态度”。

  1. 把模型输出当作“待复核线索”，而不是结论。
  2. 在知情同意中说明视频与音频的分析方式与用途。
  3. 按语言、年龄、设备环境分层验证，避免单一数据集偏见。
  4. 结合访谈原文解释“为什么犹豫”，保留研究员的判断权。
来源： arXiv 2610.26868 · Multimodal Ambivalence and Hesitancy Recognition
M3

把 Agent 当作用户：用“信任阶梯”设计研究

Greg Isenberg 把 Agent 定义成一个“拿着信用卡、只读你的网站而不看你的页面的顾客”，并把 Agent 与商家的关系拆成从 research（研究）、prepare（准备）到 pay（支付）的信任阶梯。这个框架的价值在于，它把“Agent 能不能完成任务”换成“Agent 在每一步是否被允许、是否能理解、是否敢付钱”。今天已经出现的摩擦也很具体：Amazon 阻止 Meta 的 Muse，Delta 把外部订票 Agent 视为未授权自动化活动，Yelp 则向 Agent 收费。

做研究时，可以把“Agent 可用性测试”加入常规工具箱：让 Agent 去完成真实任务，观察它在哪里读不懂页面、在哪里被权限拦住、在哪里因为缺少结构化信息而做出错误判断；再回到人类访谈，理解用户对“让代理替我行动”的授权舒适度与追责预期。前者测机器可读性，后者测人的信任边界，两者缺一不可。

  1. 为关键任务设计 Agent 走查脚本，记录失败点与恢复路径。
  2. 检查页面/接口是否提供结构化信息、明确价格与库存状态。
  3. 梳理授权、支付、撤销与争议处理链路，标出用户需要确认的节点。
  4. 访谈用户对代理失误的容忍度，以及希望如何被通知与补偿。
来源： Greg Isenberg · The 9 Stages of AI Agent Adoption

Photoshop 把滤镜改成“可移动的效果层”

Adobe 正在重新设计 Photoshop 的滤镜逻辑：旧方案像“把滤镜印到照片上”，新机制则把滤镜变成可随时移动、调节和撤回的独立效果层。用户可以把滤镜拖到指定图层，参数从弹窗移到“属性”面板，画布上实时看到变化；不满意可以修改、隐藏、删除或更换，而不破坏原始照片。AI Assistant 还能根据描述生成带可调滑块的自定义滤镜，预计今年晚些时候推送。

研究机会：测量“可逆性”如何改变用户的探索行为，以及局部效果的可发现性。
来源：少数派 · Adobe 大改 Photoshop 滤镜逻辑

聊天锁的“心理安全”与真实加密之间

ChatGPT 的 Locked Chats 用四位 PIN 或生物识别把对话移入独立区域，不出现在历史、置顶和搜索中，开启记忆时还有独立记忆。但 OpenAI 明确表示锁定不等于端到端加密，也不改变保留时长与训练设置；重置 PIN 会永久删除所有已锁定对话及文件。用户很容易把“锁”理解为“只有我能看到”，这中间的预期落差值得警惕。

研究议题：用户对“锁定/隐私模式”的心智模型，以及误删风险下的确认设计。
来源：少数派 · OpenAI 为 ChatGPT 推出聊天上锁功能

小天才的“封闭社交”争议：儿童产品的网络效应与家长信任

小天才回应封闭社交争议时表示，跨品牌可以通话，但微聊和好友圈暂不互通。对儿童智能手表而言，社交功能既是留存引擎，也是家长与监管最敏感的触点：孩子需要和同伴连通，家长需要可控的边界，平台则在网络效应与合规压力之间取舍。这类产品的体验设计，往往不是“加不加功能”，而是“谁来管理关系、谁能看到什么”。

研究机会：家庭账户治理、同伴压力、跨品牌互通的用户预期与安全边界。
来源：爱范儿 · 小天才回应封闭社交争议

Sonos Beam Ultra：外观做减法，实体交互做加法

Sonos Beam Ultra 把电视回音壁、流媒体音箱和黑胶接入合到一套 Wi-Fi 系统里：接电视支持杜比全景声，关电视可通过 Sonos App 聚合流媒体，也支持 AirPlay 2、蓝牙 5.3 和 USB-C 唱机输入。它在 75 厘米宽的机身顶部保留内凹式音量滑条与播放控制，背部还加了独立蓝牙配对键。对多场景设备来说，物理按键不是落后，而是降低“临时点歌”这类社交场景的操作成本。

设计启示：多模式设备的实体控件，要围绕“谁在什么场景下最不想掏手机”来设计。
来源：爱范儿 · Sonos Beam Ultra 体验

用 AI 夺回电视界面：从“广告启动器”到自定义桌面

作者参考 CleanFrame 与 cleanyourtv 两个开源项目，给自己做了一个电视启动器，只展示常用应用（PS5、Apple TV、哔哩哔哩、投屏），并加入壁纸轮播。安装流程需要开启开发者模式、允许安装未知应用，AI 可以一步步引导，也能按用户需求修改壁纸或快捷方式。它反映的是客厅场景里长期被忽视的体验债：用户并不需要更多内容入口，而是需要一个不被广告打断的起点。

研究机会：广告疲劳、界面控制感与“自己动手维护”的长期成本。
来源：歸藏的AI工具箱 · AI 自定义电视启动器

购物 Agent 的“约束满足”：从一张房间照片到 250 美元预算

OpenAI 的购物 Agent 演示里，用户用语音和图片描述一个阅读角，Agent 推荐商品并生成房间预览，按 250 美元预算调整选择，补充一条搭配毛毯；结账后还能把“到店自取”改为“送货上门”。这个演示的重点不是生成图片，而是把预算、风格、尺寸等约束放进一段连续对话里，并在每一步给出可理解的取舍。

研究议题：用户如何表达与修改约束、如何验证总价、推荐失误后如何恢复信任。
来源：OpenAI · Shopping Agent Demo

陪骗子聊天的 AI：把“拖延”设计成一种保护服务

澳大利亚一家公司用一群 AI 人设假扮大爷大妈，与诈骗者长时间周旋：说年纪大了听不清、找不到眼镜、炉子上还炖着汤，让骗子着急却拿不到钱。这家公司融到了 815 万美元。它把反诈从“教育用户不要上当”转向“消耗诈骗的经济模型”，也提出了新的设计问题：如何避免误伤、如何评估实际拦截效果、如何让真正的潜在受害者愿意求助。

研究机会：诈骗发生前的犹豫时刻、家庭求助路径，以及“保护性拖延”的伦理边界。

AI 硬件的设计取舍：先讲清价值，再谈科技感

设计公司 UDL 与极客公园的对谈指出，AI Native 硬件的技术与制造门槛在降低，但产品定义反而更难。Rabbit R1 看起来很酷，却未必能让用户理解它的价值；Meta 选择先把感知做好，再考虑给眼镜加屏幕；Even Realities 则舍弃摄像头，换取另一种产品形态。好的设计不再需要靠外显的“科技感”证明自己，而是把技术藏进日常使用里。

研究机会：概念阶段的价值清晰度测试，以及“功能取舍”如何被用户感知为产品立场。
