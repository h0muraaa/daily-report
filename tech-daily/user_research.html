Agent 交互 Web 标准

WebMCP：让 Agent 从“猜界面”到“用接口”

Google Chrome 团队的 Tara Agyemang 在 AI Engineer 大会上介绍了 WebMCP，一项旨在简化 AI Agent 执行网页操作的新标准。当前 Agent 要买两张演唱会门票，需要解析 DOM、accessibility tree、截图、计算像素坐标，再冒着广告加载导致布局偏移的风险去点击。WebMCP 则让网站向 Agent 暴露一组命名、类型化、带描述的结构化工具，Agent 直接调用即可。

对用户体验设计来说，这是一个范式转换：如果未来大量用户任务由语音或 Agent 完成，那么“界面”可能从可视化 GUI 退居为可调用 API 的后备层。UX 设计师需要开始思考“无界面体验”的信息架构：当用户不再逐屏浏览，网站如何向 Agent 描述自己的能力和状态？这同时带来了新的包容性机会——依赖屏幕阅读器或运动障碍的用户，可能首次获得真正平等的自动化服务入口。

产品体验点评

AI 记忆 用户控制

Grok 记忆功能：把“黑箱 personalization”变成可协商的体验

Grok 上线了记忆能力，允许模型在对话中记住有用细节以提供更连贯的上下文，同时让用户可以随时查看、编辑或删除这些记忆。相比此前多数 AI 产品把记忆作为不可见的内部状态，Grok 选择将记忆外化为用户可审查的清单。

从用户研究视角看，这是一个值得关注的信任设计案例。用户对 AI 记忆的焦虑通常不是“被记住”，而是“不知道被记住了什么、无法修正”。透明且可编辑的记忆界面把控制权交还给用户，也降低了多轮对话中的“重复自我介绍”成本。建议在类似产品中引入“记忆预览”和“一键遗忘”机制，并通过用户测试验证不同人群（尤其是隐私敏感型用户）对记忆可见性的接受度。

对话式 UI 数据产品

Looker Dashboard Agents：静态仪表盘的用户体验升级

Google Cloud 的 Looker 推出 dashboard agents 预览版，将对话式数据 Agent 直接嵌入仪表盘。用户可以在看到数据后立刻追问“为什么华东区下降”“和上月比如何”，而无需跳转到分析工具或等待分析师响应。

这一设计解决了 BI 产品长期存在的“最后一公里”问题：仪表盘擅长回答“发生了什么”，但用户真正想追问的“为什么”和“怎么办”被留在了工作流之外。对 UX 研究而言，下一步可以关注用户如何形成追问习惯、Agent 回答的可信度如何影响决策，以及不同角色（高管、运营、分析师）对自然语言查询的接受差异。

开发工具 信任与许可

Cursor Auto-review：把“AI 自主权”锁进用户许可框架

Cursor 宣布 Auto-review 成为所有新用户的默认能力。一个分类器子 Agent 会在执行操作前评估上下文，决定是允许、阻止还是向用户请求批准。官方评测称其准确率达到 97%，误差主要集中在边界模糊的场景。

对 UX 设计有双重启示：一方面，它缓解了用户面对高自主权 AI 时的失控感；另一方面，“请求确认”的频率和时机需要精心设计——过多的中断会打断心流，过少又会让用户担忧。建议通过日志分析和访谈找出用户最愿意让渡控制权的任务类型，以及他们最希望被询问的“高风险动作”。

用户反馈闭环 自动化研究流程

从 Slack 反馈到自动 PR：用户研究智能化工作流的一瞥

Every 频道分享了 Cora（AI 邮件应用）团队如何将 Slack 中的用户反馈转化为可合并的代码改动。团队成员在 Slack 提交反馈，Claude Cowork 定时分析并生成结构化 PR，再由开发者批量审查与合并。Kieran Klaassen 用这一流程在单次 PR 中处理了 17 条反馈。

这展示了用户研究智能化工作流的一种可行形态：把分散、非结构化的用户声音，通过 Agent 自动聚类、提取需求并进入开发队列。对研究团队来说，关键不是完全自动化，而是建立“反馈→洞察→工单→验证”的闭环，并保留人工判断环节以避免 AI 对反馈的误读。可借鉴的实践包括：为反馈打标签以训练分类器、设置人工复核阈值、在上线后对同一批反馈来源做回访验证。
