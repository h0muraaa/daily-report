💡 今日要点
1

AI 输出格式正经历 Markdown → HTML 的范式转移

Claude Code 团队正式推荐使用 HTML 取代 Markdown 作为 Agent 与人类的协作输出格式。核心驱动力是信息密度与交互性的需求——当 AI 生成的内容超过百行、涉及表格、图表和交互控件时，Markdown 的表达力已明显不足。这标志着人机协作界面正在从"文本对话"向"富媒体体验"跃迁。

2

语音交互成为聊天 Agent 的下一个升级方向

ElevenLabs 提出"给聊天 Agent 加上声音"的愿景，认为语音不仅是速度的提升，更是全新交互范式的开启——覆盖电话热线、Zoom 通话、屏幕阅读器和环境界面等文本无法触达的场景。这要求 UX 设计师重新思考多模态场景下的信息架构与反馈机制。

3

AI 生成内容的评判标准转变：从"逼真度"到"情感共鸣"

AI 短片《纸手机》全网播放量超 4000 万，其最出圈的"名场面"竟是一个暴露 AI 生成痕迹的穿帮镜头。评论区没有批评，反而涌现"看到这里才发现是 AI 做的""完全不在意"等声音。这验证了一个关键洞察：当内容足够打动人时，用户对"完美无瑕"的执念会自然消解。

4

PDF 从"文件传输"进化为"体验传递"

Adobe Acrobat 推出 PDF Spaces，将传统文档转变为结构化流程（提案、演示、定价），并加入音频概述、阅读行为追踪等功能。文档类产品的用户体验正在从静态展示向动态交互和数据驱动演进。

5

AI 辅助设计的评价维度正在精细化

Arena.ai 基于 25 万+ Code Arena 提示词分析，推出 7 个前端开发细分排行榜（品牌与营销、参考设计、数据分析、消费产品、游戏、模拟、内容创作工具）。这标志着"AI 能否写好代码"的笼统问题，正在被拆解为"在特定设计场景下表现如何"的精细化评估框架。

交互范式

HTML 回归：AI 时代人机协作界面的"表达力革命"

过去一周，关于 AI 输出格式的讨论在技术社区引发了前所未有的关注。Claude Code 团队核心成员 @trq212 发布长文，明确提出Markdown 正在限制 Agent 的表达能力，并全面转向 HTML 作为对外分享的首选格式。几乎同时，歸藏 (@op7418) 提出了"数据与表现分离"的架构共识：以 Markdown 负责底层逻辑与记忆的纯净存储，用 HTML 实现对外的高密度交互与展示。

这场讨论的深层意义远超格式之争。Berryxia.AI 的回顾揭示了一个有趣的"天道轮回"：去年此时社区痴迷于用 HTML 做 PPT，9 月 NotebookLM 的 PPT 功能上线后"杀死"了这一赛道，所有人转向"香蕉模型"。但年底因可编辑性需求，HTML 工具再度回归。时至今日，Claude Code 官方背书让 HTML 成为 Agent 首选输出格式——从长文档、交互 Spec、设计原型到动态报告，全部用 HTML 呈现。

UX 洞察：这反映出用户对 AI 生成内容的核心诉求已从"能看懂"升级为"高效获取信息"。Markdown 的"易编辑"优势在"用户不再亲手编辑"的场景下已经失效，而 HTML 能提供的信息密度（表格、SVG、CSS、脚本、交互控件）和可读性（标签页、响应式布局）成为新的硬需求。对 UX 设计师而言，这意味着需要重新设计 AI 产品的输出模板系统——不再是纯文本的prompt工程，而是涉及信息架构、视觉层次和交互模式的完整设计工作。
来源：meng shao(@shao__meng) · Berryxia.AI(@berryxia) · 歸藏(guizang.ai)(@op7418)
设计美学

反"AI Slop"设计哲学：Anthropic 如何对抗生成式同质化

meng shao 在研读 Claude Design 的 System Prompt 时发现了一段颇具幽默感的"反 AI slop"条款。Anthropic 明确要求避免以下设计套路：渐变色背景的过度使用、非品牌场景下的 emoji 堆砌、圆角容器配左侧强调色的容器样式、SVG 手绘插图、过度使用的字体组合。这些恰恰是当前 AI 生成设计中最常见的"模板味"特征。

UX 洞察：当 AI 工具让"生成设计"变得零门槛时，设计同质化反而加剧。Anthropic 的这份 System Prompt 本质上是在建立 AI 生成内容的"审美护栏"——不是限制创造力，而是避免陷入低质量重复。这提示产品设计团队：在引入 AI 设计工具时，需要同步建立品牌设计规范和质量审核机制，否则用户将在海量"AI 味"内容中丧失对品牌的辨识度。

汽车 UX

理想 L9 Livis：李想的"边界感"设计哲学

理想汽车公布了新一代旗舰 L9 Livis 的内饰设计，起售价 55.98 万元。最引人注目的变化是老款双联屏消失，取而代之的是一块一体式超大中控屏，后排娱乐屏增加了前后移动功能以方便三排观影。二排独立座椅配上电动扶手，按键布局与 MEGA Home 版本保持一致以降低学习成本。车门新增电子开门按键，同时保留实体门把手并与音响罩做一体化融合。

李想的设计哲学非常清晰：外在追求比例姿态，内在追求"家"的感觉。他明确拒绝"高端会所式的富丽堂皇视觉冲击"，转而用精心挑选的皮质、木纹和恰到好处的细节来营造质感。菱形格纹皮革、原木饰条和专属刺绣在"细细填充内部的质感"。

UX 洞察：L9 Livis 的设计决策体现了一个重要的产品原则——克制比堆砌更需要勇气。在新能源汽车"屏幕越来越大、参数越来越卷"的同质化竞争中，理想选择回归东方文化中对"家"的情感诉求。从 UX 角度看，保留实体门把手、沿用成熟按键布局等决策，都是对"学习成本"和"安全感"的深度考量。二排屏幕的前后移动功能则是一个典型的"用户旅程优化"案例：考虑到三排乘客的观影需求，通过机械结构的微调解决了多人场景下的体验痛点。

内容体验

《纸手机》：一个穿帮镜头如何成为 AI 内容接受度的转折点

AI 短片《纸手机》全网播放量超 4000 万，创下 AI 影像作品的新高。但最被讨论的画面不是精湛的生成效果，而是一个明显的"穿帮"——旋转的老式电话中，拨号手指的位置不合逻辑，且片中的 iPhone 设定与老式电话机存在时代矛盾。

然而评论区没有出现预期的嘲讽，而是"看到这里才发现是 AI 做的""完全不在意""AI 又怎么样，又不影响我哭"。观众在明确知道这是 AI 生成之后，仍然被打动，而且主动承认感动。这个电话 bug"根本不在观众的评价维度里"——他们在意的是"一个不懂死亡的小男孩，攒了 15 块钱，想给去世的奶奶烧一部手机"。

UX 洞察：这个案例对 AI 内容产品的设计具有里程碑意义。长期以来，AI 生成内容的评价维度被"逼真度"绑架——模型迭代的速度被当作技术进步的刻度，每次发布都伴随着"这次终于分不出来了"或"还是一眼假"的争论。《纸手机》证明了一个反直觉的结论：情感共鸣的阈值远低于完美逼真的阈值。当内容触及用户的情感核心时，技术瑕疵不仅不会被放大，反而可能因"人类感"而增强真实感。这提示 AI 内容产品的 UX 策略需要从"追求零瑕疵"转向"讲好故事"——在叙事设计和情感节奏上投入更多精力，而非一味追逐像素级完美。

AI 研究工具

Perplexity Agent Skills 设计规范：当"Skill"不等于"代码"

Perplexity Agents 团队公开了其内部的 Agent Skills 设计与迭代规范，核心论点非常反直觉：写 Skill 不是写代码，而是为模型构建上下文。团队明确指出，把工程师写代码的本能直接套到 Skill 上，几乎一定会失败。

规范中提出了 Skill 的"四重定义"：1) Skill 是文件夹而非文件——复杂性是特性；2) 激活靠隐式模式匹配 + 渐进披露，而非显式调用；3) 每 token 都要榨出最大信号密度；4) Gotchas（陷阱提示）才是最高价值内容。与 Python 的"Simple is better than complex"不同，Skill 设计信奉"容易解释的，模型已经会了 → 删掉"。

UX 洞察：这份规范对 UX 设计师和研究员的启示在于：AI 时代的"设计系统"需要根本性重构。传统的组件库和样式指南假设使用者是人类设计师，而 Agent Skills 的受众是 AI 模型。这意味着 UX 团队需要掌握一种新的"提示工程化设计"能力——不是让设计更美，而是让设计更易被模型理解和执行。从用户研究角度，这也提出了一个新课题：如何研究和建模 AI Agent 的"认知模型"，以便设计出更高效的交互协议。
来源：meng shao(@shao__meng)
安全与信任

OpenAI Codex 四层框架：AI 操作体验的"零摩擦 + 可控性"平衡术

OpenAI 公布了一套用于管控 Codex Coding Agent 的四层安全框架：受限执行（沙箱 + 审批）、网络策略、身份治理和 Agent-Native Telemetry。核心原则是让低风险的日常操作零摩擦，让高风险操作必须显式停下来等审查。

其中最值得关注的新机制是 Auto-review 模式——一个独立的子代理负责审阅 Codex 的待执行动作和上下文，对低风险请求自动放行，仅在风险升高时才打断用户。这是"用 AI 审 AI"，把审批本身做成了智能层。

UX 洞察：这套框架对 AI 产品的信任设计具有重要参考价值。用户与 AI Agent 协作时最大的焦虑是"它会不会擅自做我不允许的事"。OpenAI 的解决方案不是简单的"全部拦截"或"全部放行"，而是基于风险等级的分层体验设计：低风险场景下保持流畅（零认知负担），高风险场景下强制中断（明确控制权）。这种"渐进式信任释放"的体验模式，可以成为所有 AI 自动化产品的设计范本。

语音交互

ElevenLabs：语音层是聊天 Agent 的下一个升级

ElevenLabs 的 Luke Harries 在 AI Engineer 峰会上提出，2025 年每个产品都添加了聊天 Agent，但"文本进、文本出"已经开始显得过时。语音不仅更快、更易用，还能开启文本无法触达的交互范式——电话热线、Zoom 通话、屏幕阅读器和环境界面。

值得关注的 UX 模式：语音交互的 UX 设计还处于非常早期的阶段。与图形界面相比，语音缺乏视觉锚点，用户更容易迷失。ElevenLabs 的切入点是"给已有聊天 Agent 加声音"，而非从零设计语音原生产品——这种渐进式升级策略可能更容易被市场和用户接受。
