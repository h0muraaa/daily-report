用户控制权 / 平台治理

一个开关关掉「摇一摇」：苹果把传感器权限交还给用户

苹果在 iOS 27.2 中新增「限制动作数据（Restrict Motion Data）」功能，路径是设置 → 隐私与安全 → 运动与健身 → 限制动作数据，用户可逐个勾选希望禁止读取陀螺仪与加速度计的 App。它的机制很直接：被列入名单后，系统在底层切断传感器数据，开屏广告里的小图标摇得再欢，应用也「看不见」手机在动。

爱范儿的实测给出了关键细节：未开启时，正常抬手或轻微晃动就会在不到半秒内跳转淘宝；开启后，部分 App 的开屏仍显示「摇动手机或点击了解更多」，但无论怎么剧烈摇晃页面都纹丝不动，5 秒倒计时结束后正常进入首页；另一些 App 检测不到传感器数据后，干脆回退成静态开屏广告。也就是说，这项功能掐断的是跳转通道，而不是广告本身。

研究启示：这是一次典型的「把控制权设计成功能」的案例，可测三件事：可发现性（四步路径是否足够浅）、可验证性（用户开启后能否确认真的生效）、代价透明度（广告变现与用户信任如何权衡）。建议加一条「感知控制」量表，并观察用户是否会因为「广告还在、只是不跳了」而觉得功能不完整。平台级开关的价值不在于消灭某类内容，而在于让用户对「谁可以读取我的设备」有最终决定权。

主动性 / Personal Agent

从「听指令」到「替你惦记」：灵光 2.0 把主动性摆上桌面

蚂蚁集团 10 月 27 日发布灵光 2.0，定位「能管事的个人 AI 助理」，成为国内大厂首批落地的 Personal Agent 产品。与过去一次性的问答不同，它会主动识别潜在需求、持续跟进长程事务，并在关键节点提醒：例如一句「下周去上海出差三天」，订票订酒店只是起点，之后会提醒出发与带证件，遇到航班延误还会自动重排酒店入住与会议行程。

多方实测提供了互补的视角。爱范儿把宠物保单、双 11 算价与周末旅行都交给它；AI 科技评论从盯机票价格、清理自动续费这类「要反复惦记」的琐事切入；卡尔的 AI 沃茨通过 Skill、MCP 与内置方式接入了 15 个国民级 App，并指出手机端 Personal Agent 的第一诉求其实是「配置方便、接上就长期有效」。阑夕的批评同样值得记录：Personal AI 的上限不低，但多数产品在易用性上仍不尽如人意，主动性若无节制，很容易滑向打扰。

研究启示：主动性是新的交互变量，需要新的度量语言。建议为每个主动行为记录三件事：触发依据是否可解释、打扰强度是否与收益匹配、误判后能否一键撤销并恢复信任。可以引入「打扰预算」概念——单位时间内允许主动打断的次数上限，与用户授权等级挂钩。首周日记研究应重点捕捉「第一次被主动帮助」的惊喜与「第一次被主动打扰」的失望，这两次事件往往决定留存。

可穿戴 / 全天佩戴

两副 AI 眼镜，同一个问题：用户凭什么愿意每天戴

Rokid 同日发布两条产品线。爱范儿提前一周体验的 Rokid Glasses 2 把重点放在「愿意戴出门」：被戏称为「雷霆大鼻托」的加大接触面与柔软材质提升了鼻梁舒适度，镜腿可向外扩开以适配更大头型，镜片比上一代更通透、反光更淡，方中带圆的框型不挑脸型；相机升级为 1200 万像素 CMOS，支持 HDR 与 RAW 14，视频可拍 2.5K HDR。另一款 Rokid Color 重量仅 55g，采用 0.16cc Micro LED 全彩光机，交互覆盖镜腿触摸板、语音、腕带/手表、眼动追踪与触控戒指，戒指可识别搓手指、打响指等微手势，售价 4999 元起，2027 年 4 月起交货。

两条产品线暴露了同一个研究难点：智能眼镜的功能表很长，但用户真正感知的是「戴三小时后鼻梁疼不疼」「在地铁里被注视的尴尬感」「抬手到位时能不能一次盲操成功」。Rokid Color 公布的交付时间也提醒我们，硬件体验的口碑往往在漫长的等待期里就被预售与退货政策先行塑造。

研究启示：可穿戴的第一指标不是功能数量，而是佩戴时长与社交可接受度。建议建立「佩戴体验三件套」：连续佩戴 2 小时后的舒适度评分、公共场景下的被注视焦虑、摘戴动作的顺手程度。多模态交互则要测「盲操成功率」与「模式切换成本」——用户无法在走路时读说明书，微手势必须一次到位。对期货式发布，还应把「等待期预期管理」纳入体验旅程。

本地化 / 屏幕感知

Siri AI 扩到五种语言：本地化不只是翻译，还有信任

苹果在 27.2 版本中为新一代 Siri AI 新增法语、日语、韩语、葡萄牙语和西班牙语支持，并计划在年底前加入繁体中文、挪威语、土耳其语与越南语。升级后的 Siri 能理解用户的个人情境，从信息、邮件、照片中查找资料，执行更多系统级操作；借助屏幕感知能力，它可以理解当前屏幕内容并回答问题或完成动作，同时调用广泛知识回答「几乎任何话题」。

这组能力叠在一起，构成了一个典型的体验张力：屏幕感知让 Siri 更「懂你此刻在做什么」，也让「被持续注视」的感觉更强。苹果在新闻稿中强调基于 Apple 智能、在保护隐私的同时提升能力，但对用户而言，隐私承诺最终要落到可感知的界面语言上——哪些内容被读取、什么时候读取、能否关闭，都需要在交互里被明确回答。

研究启示：多语言测试要拆成「语言能力」与「文化语用」两层：同一句请求在不同语言里的礼貌程度、称呼习惯与打断容忍度都不同。屏幕感知类能力应加测「理解感」与「被监视感」的差值，并验证隐私说明是否出现在用户真正会看的时刻，而不是埋在设置深处。繁体中文年底才到，也提示本地化路线图本身就是用户体验的一部分，需管理预期。

体验度量 / 数据反转

「AI 每周省十小时」的人从 68% 掉到 26%：自陈效率正在失效

Atlassian《2026 开发者体验状况》报告给出了一组值得所有研究团队警醒的数字：报告每周因 AI 节省十小时以上的开发者占比，从去年的 68% 降至 26%；只有 28% 的开发者感到工作摩擦比引入 AI 前明显减少；而工程负责人花在管理和纠正 AI 产出上的时间，比开发者本人还多。

这并不意味着 AI 没用，而是说明「效率」的测量方式出了问题。当 AI 把写代码变快，审查、合并、部署与返工这些环节并不会同步变便宜，节省下来的时间可能被新增的校正工作吃掉。对用户研究而言，这是一次关于「自陈数据」的经典提醒：用户对效率的感知会被新鲜感、任务类型与组织氛围放大或缩小，单靠问卷很难捕捉真实成本。

研究启示：把「节省时间」从单一自陈指标，升级为三件套：客观任务时长（同一任务前后对照）、返工率（AI 产出被修改的比例）、认知负担（切换、检查与决策的疲劳度）。同时区分「个人效率」与「团队吞吐」——个人更快不等于交付更快。做纵向追踪而非一次性问卷，才能识别新鲜感退潮后的真实曲线。

02

设计趋势洞察

两个正在成形的转向：生成式界面第一次有了工程化的成本与延迟答案；主动性则从卖点变成需要被治理的交互变量。

Trend 01 · 生成式 UI 工程化

设计系统正在变成「模型可调用的组件词汇表」

Google 的 A2UI 更新给出了生成式界面走向生产环境的关键信号：新增可替换的推理格式，其中 A2UI Express 允许开发者用紧凑的 Python 风格语法编写界面，再由 Agent SDK 编译成标准 A2UI JSON，官方称最多可减少 3 倍 token 并降低延迟；配合 TypeSafe 的 Jev 决策模型做受控生成，已知形态的屏幕可在 300 毫秒内渲染，同时让小模型并行流式输出文本。更重要的是，这些更新不要求改动前端渲染器或组件目录。

把这条消息与另外两条放在一起看，方向更清楚：Gemini 4 Argon 的示例里，「交互式设计」已经是一项原生能力；Genie 4 则把可探索、可实时改变天气与角色的世界模型推到台前。界面正在从「人预先画好、机器照着渲染」，变成「机器在既定组件语汇里即时组装，人负责定义边界」。这也解释了为什么「不改前端渲染器」如此关键——设计系统的稳定性，成了生成式体验可信度的地基。

设计含义把设计系统重新理解为三层：组件词汇表（允许模型说什么）、受控生成规则（允许它怎么说）、降级与兜底（说不出来时怎么办）。研究上应新增「生成一致性」测试：同一意图多次请求，界面结构是否稳定；「可预测性」测试：用户能否在生成前预判结果形态；以及「失败降级」测试：当模型给不出合法组件组合时，界面是否仍然可用。延迟与 token 只是成本指标，信任指标才是设计指标。
来源： Google Developers Blog · A2UI Express · The Keyword · Gemini 4 Argon 的 8 个案例 · 爱范儿 · Genie 4 发布
Trend 02 · 主动性范式

当产品开始「先开口」：易用性与授权效率才是普及门槛

Personal Agent 在这一周集中爆发：灵光 2.0 主打「管事」，Meta 的 Muse 面向非技术用户，OpenAI 的 Dots、Anthropic 的 Claude Duet 相继出现，垂直赛道里 Moras 则直接按成交结果向达人收费。阿里技术的对比分析指出，这一波产品与早期 Agent 的差别不在会不会调用工具，而在「主动感知」与「长期委托」；K2 Lab 创始人王铭的判断更直接：竞争的关键正在转向信任与授权的效率。

但主动性是一把双刃剑。阑夕在实测后写道，Personal AI 普及的前提除了实用价值，还必须有充足的易用性，而目前多数产品在这方面的表现仍不尽如人意；他还引用 Karpathy 对 Agent 的保留态度，提示「让 Agent 替你做越多，你对正在发生之事的理解就越少」。换句话说，主动性的收益是省心，成本是控制感与理解力的让渡，而这两者恰恰是用户研究最该测量的东西。

设计含义为主动式产品画一张新旅程：意图表达 → 授权确认 → 后台执行 → 关键节点汇报 → 异常干预 → 结果复盘。每一步都要回答「用户此刻知道多少、能改多少」。建议引入分级授权（只读 / 建议 / 代办 / 自动）与「打扰预算」，并把「撤销成本」作为核心体验指标。研究上可做「授权阶梯实验」：逐步放开权限，观察信任是随成功次数上升，还是随一次误判骤降。
来源： 阿里技术 · Personal Agent 对比分析 · Founder Park · 对话 K2 Lab 王铭 · 阑夕 · 灵光 2.0 实测
03

产品体验点评

两个案例：一个示范「主动管事」如何被普通用户接受，一个展示硬件体验如何从「参数表」回到「身体感受」。

主动式 Agent / 信任

灵光 2.0：把 AI 的起点从「对话框」前移到「发现需求」

过去两年，AI 助手的默认交互是「你问，它答」。灵光 2.0 想改的是这一步：在你还没想到要问之前，它先替你盯着。

从多方实测看，它接住的是一类过去 AI 很难办好的任务——时间跨度长、信息持续变化、需要反复记住前情。爱范儿记录的场景包括：出差行程订好后主动提醒出发与证件，航班延误时自动重排后续酒店与会议；AI 科技评论则从「机票订完还忍不住反复查价」「会员自动续费忘了关」这些日常焦虑切入，指出灵光把「跟进」这件事从用户手里接了过去；卡尔的 AI 沃茨把 15 个国民级 App 接进来后，最直观的体验是「定时任务会自己刷新值得关注的信息」。

但同一批实测也暴露了短板。阑夕认为多数 Personal AI 的易用性仍不理想，主动性一旦缺乏节制就会变成「爱管闲事」；他同时提醒，委托越多，用户对过程的理解越少。王铭从商业侧给出了另一种解法：先让用户用很少的投入拿到第一个结果，再在持续回报中赢得信任——信任不是一次性授予的，而是被一次次正确交付积累出来的。

体验判断：灵光 2.0 最强的资产是「第一次被主动帮到」的惊喜，最脆弱的是「第一次被主动打扰」之后的信任滑坡。建议做一次两周的日记研究，记录三类关键时刻：用户第一次意识到它在替自己盯着、第一次发现它判断错了、第一次主动调整它的授权范围。指标上，把「主动任务完成率」与「用户主动查看/干预率」并列看——前者高、后者低，说明信任建立；前者高、后者也高，说明用户仍不放心。另需注意，本文信息来自媒体实测，具体授权流程与撤销体验仍待更完整的交互材料验证。

可穿戴 / 身体感受

Rokid Glasses 2：先解决「愿不愿意戴」，再谈「能做什么」

一位平时不戴眼镜的评测者给出的标准很朴素：它得有多好用，才能让我愿意每天都戴着？这道题，比任何参数表都难。

Rokid Glasses 2 的回应几乎都落在身体感受上。鼻托接触面积加大、材质更软，架在鼻梁上更舒服；镜腿能向外扩开，头型偏大的人也能戴得自在；框型方中带圆，不挑脸型；正面只在摄像头处开孔，提示灯在不亮时几乎不可见；光机变小、镜片更通透，从正面看已不太容易认出是智能眼镜。影像上，1200 万像素 CMOS 配合 HDR 与 RAW 14，逆光下人脸不黑、天空保留细节，视频支持 2.5K HDR，最高可到 4K。

同场的 Rokid Color 走了另一条路线：55g 双目全彩，却提供了极其丰富的交互组合——镜腿触摸板、语音、腕带/手表、眼动追踪，以及可识别搓手指、打响指的触控戒指。这种「多模态冗余」对实验室很友好，对真实场景却是新的学习负担：用户在走路、通勤、与人交谈时，未必有余力记住五种操作方式。

体验判断：Rokid 这两款产品把可穿戴研究的优先级重新排了一遍：佩戴舒适度与社交可接受度是入场券，影像与交互是加分项。建议在真实场景（通勤、会议、户外）做「佩戴日志 + 情境访谈」，重点测：连续佩戴两小时后的鼻梁与耳后压力、在人群中使用的心理门槛、以及单手盲操成功率。多模态设计应遵循「一种主路径 + 若干捷径」，主路径必须零学习成本，捷径才允许有学习曲线。对 2027 年才交付的 Color，还应单独研究等待期的预期管理，否则首批口碑可能由交付焦虑而非产品力决定。

04

研究方法论

三套可以直接迁移到用户研究中的方法：让设计稿变成可审查的契约、把认知状态纳入注意力测量、以及重新分清「改进」与「假设」。

01

从 Figma 到 PRD：设计稿正在变成可执行、可审查的契约

Reddit 首席 UX 工程师 Blair Metcalf 演示了内部工具「feature capsule」：把 Figma 链接拖进来，工具会把每一个组件映射到生产实现，并自动生成一份带有验收标准的 PRD。这个流程的价值不在于「生成文档更快」，而在于它把设计意图、组件实现与验收条件放到了同一条可追溯的链路上。

对用户研究而言，这是一个可以借用的结构。研究洞察常常停留在报告里，无法进入评审与验收；如果研究结论能像组件映射一样，被绑定到具体的界面元素与验收标准上，它就有了被执行的路径。反过来，自动生成的 PRD 也带来新的审查责任：验收标准必须来自真实的用户证据，而不是模型的合理推测。

把「认知状态」纳入注意力测量：EEGaze 给视觉搜索补上生理信号

视觉搜索无处不在，从在凌乱的房间里找钥匙，到在杂乱的桌面上找图标。以往的计算注意力模型主要依赖图像内容预测「哪里显眼」，但心理学研究表明，用户的认知状态会显著影响注意力分配。EEGaze 的工作正是把脑电（EEG）记录下来，用基于 EEG 的显著性细化来改进视觉搜索中的注意预测，弥补了此前计算模型忽视 EEG、心理学研究又多使用抽象简化刺激的断层。

这项方法对产品研究的吸引力在于它的「可迁移性」：图标可发现性、信息架构的视觉层级、以及复杂界面中的搜索效率，都可以从「用户说找不到」升级为「注意力实际被什么吸引」。但落地时要清楚边界：脑电设备有成本与门槛，样本量通常有限，且信号解读需要专业支持；这类研究更适合作为小样本的机制解释，而非大规模验证。

改进还是假设？Mark Pincus 提醒团队别把「我们觉得更好」当成用户认可

Zynga 创始人 Mark Pincus 用 Zynga Poker、FarmVille 与 Hay Day 拆解产品决策时给出一条清晰的分界：改进是现有用户都会说「我就想要这个」的东西，而不是团队自己觉得更好；越是在平台变化的早期，越应该少做新东西，保留已经验证的体验。他同时强调，要分清「改进」与「新假设」，并用更小的测试判断值不值得继续投入。

这对研究团队是一个角色定位的提醒：研究的一部分职责是给「改进」提供既有用户的行为证据，另一部分职责是帮「假设」设计最小可行的验证，而不是让 roadmap 代替验证。可行做法是给每个需求贴上「改进 / 假设」标签，前者用现有用户数据与可用性测试快速确认，后者用小样本概念测试或灰度实验尽早证伪。

90% 准确率为何一换人就崩：情感识别需要「效度审计」

一项研究指出，语音情感识别（SER）基准常年报告 90% 以上的准确率，但在多样化说话人上部署或测试时却频繁失效。作者认为模型可能学到的是说话人身份与音色，而非通用的情感线索，并提出一套双条件审计协议：在架构、特征与训练配方完全一致的前提下，对比「常规划分」与「说话人留出」两种评测，量化性能有多少能存活下来。

语音助手该什么时候闭嘴：打断与回应的「对话节奏」

两篇语音交互研究指向同一个被忽视的维度——时机。一篇提出「最早可行动点」监督，让语音代理不必等用户说完就能调用工具，构建了 26,694 段对话、786 小时、覆盖 48 个领域的数据；另一篇则研究全双工对话中的打断（interruption）与回应（backchannel），指出序列级奖励会把分数错误地摊到「何时听、何时说」的决策上，导致模型对着沉默说话或干脆停止回答，并给出按窗口计算似然的改进方案。

研究切口：为语音界面定义「节奏指标」——过早响应率、错失插话率、无响应沉默时长，而不只是识别准确率。
