当界面变成可进入的世界，
用户的"意图"成了新的设计材料

今天的信号很清楚：输入正在从"打字"变成"表达意图"，Agent 正在从"写提示词"变成"示范一遍"，而界面本身正在从一页屏幕变成一个可以走进去、随时改动、还能对话的世界。对做用户体验的人来说，这既是新范式，也是一批新的可研究问题。

01

今日要点

从今天的新闻里挑出 5 条对用户体验与用户研究最有信息增量的信号。

1

界面正在"世界化"：从看视频到走进去

Google DeepMind 发布的世界模型 Genie 4，允许用户用键盘在实时生成的场景里自由行走，并随时用文字改变天气、添加人物、与 NPC 现场对话；单次交互体验最长约 2 分钟，原生音频也随场景一起生成。这意味着交互对象从"页面"变成了"可进入的环境"，设计师要回答的问题也随之变成：用户如何表达意图、系统如何在场景变化中保持一致、以及用户如何获得可控感。 [来源: 爱范儿] [来源: AI寒武纪]

2

输入从"表达"升级为"意图"

讯飞输入法 16.0 的「意图成稿」不再要求用户把话想清楚、说标准，而是通过任务级信息卡片与长程记忆，把散落在群聊、截图、小程序里的信息自动带入，用户只需说一句意图就能得到一份可直接修改的草稿。它真正改变的是输入的心智模型：从"人迁就机器"的逐字敲打，变成"机器迁就人"的意图捕捉。 [来源: 爱范儿]

3

Agent 开始"看你做一遍就会"

豆包工作的 Computer Use 上线录制回放：用户把电脑上的操作流程演示一遍，最长可录 30 分钟并边做边讲，AI 自动整理成可复用的技能；同时新增 Mac 锁屏继续工作与手机远程下发任务。它把"教 AI"的成本从反复写提示词，降到了"当面做一次"，这正是普通用户能接受的学习门槛。 [来源: 卡尔的AI沃茨] [来源: 硅基观察Pro]

4

录音正在变成结构化内容的入口

微信输入法上线「AI录音笔」，可把录音实时转写成重点清晰的结构化网页，自动剔除错别字和口水话、按上下文修正逻辑，还能匹配图表与交互原型，并支持多端同步与粤语、西安话、武汉话等方言。对用户研究员来说，这意味着访谈录音的整理环节可能被大幅压缩，但也提出了新的问题：自动结构化会不会抹掉那些"跑题却重要"的原始细节。 [来源: 少数派]

5

用户开始夺回"注意力主权"

iOS 27.2 新增「限制动作数据」，从系统层禁止名单内 App 读取陀螺仪和加速度计，让"摇一摇"开屏广告彻底失效；同期广电总局新规要求有线电视与 IPTV 不得播放开机广告、首页须设免费专区。两件事指向同一个体验趋势：靠劫持用户注意力换取转化的设计，正在被系统与监管从底层切断。 [来源: 爱范儿] [来源: 爱范儿]

02

设计趋势洞察

两处正在发生的范式位移：交互介质的变化，和 Agent 交互门槛的下移。

趋势一

从"生成内容"到"进入世界"：世界模型成为新的交互介质

Genie 4 最值得设计师注意的，不是画质，而是它把"下一步发生什么"交给了用户。用户按方向键、转视角、临时敲一行字改变天气，模型必须根据眼前画面继续生成，而不是播放一段已经定稿的视频。官方演示里，萨克斯演奏者所在湖面被要求"持续下大雪"，雪落在他的头发和肩上，演奏没有中断——这种"边玩边改、改了还能接住"的连续性，才是新介质的核心。

  • 意图映射成为主要设计对象。 没有固定菜单和按钮，用户用自然语言和方向键表达意图，设计要做的是让"任意意图"都能被理解并给出可预期的变化。
  • 一致性与记忆是体验底线。 镜头移开再回来，物体应该还在；刚改的天气应持续影响场景。空间记忆和事件因果，会成为世界化界面的"可用性"。
  • 可控感需要被显式设计。 用户可以随时改主意，系统要能"接住"，同时要让用户知道哪些改动可逆、哪些会破坏场景。
  • 注意力引导换了语言。 在可走入的环境里，镜头就是界面，视线与声音成为新的信息层级工具。
给团队的提醒：Genie 4 目前仍是研究预览，单次体验约 2 分钟，长期场景一致性仍有局限（稀土掘金）。但"生成式环境即界面"的方向已明确，现在就该把"意图—反馈—可逆性"写进设计规范，而不是等产品化再补。

参考：爱范儿 · AI前线（30 秒生成、24 帧实时交互实测） · AINLP（Gemini 充当大脑）

趋势二

Agent 交互门槛下移：从"提示词工程"到"示范 + 意图捕获"

过去一年，用好 Agent 的前提是会写提示词。今天出现的几个产品，正在把这个门槛拆掉：豆包工作让你演示一遍操作、边做边讲，AI 自己整理成技能；讯飞输入法让你只说意图，键盘负责整理；微信录音笔让你正常说话，系统负责去掉口水话并结构化。它们的共同点是——把"如何表达"的负担从用户身上转移到系统身上。

  • "示范"是新的输入方式。 录制 + 讲解比提示词更接近人类教人的方式，也更能承载"为什么这样做"的隐性知识。
  • 可中断与可修正比自动化更重要。 豆包在不同场景提供暂停或重试，用户按"本机还是远程"自行选择，说明协作节奏本身需要设计。
  • 记忆要可见、可改、可忘。 意图成稿依赖长程记忆，但用户需要知道系统记住了什么，并能一键纠正。

参考：卡尔的AI沃茨 · 硅基观察Pro · 爱范儿 · 少数派

03

产品体验点评

两个把"记忆"和"协作节奏"做进交互细节的案例。

讯飞输入法 16.0：把"长程记忆"做进键盘

输入体验
用户痛点
早高峰地铁里，一段话打了又删；语音转写满屏口水话，还得挪光标逐字删改；信息散落在群聊、截图和小程序里，每换一个聊天对象就要来回切屏、重复粘贴。
设计解法
「意图成稿」把处理过的文本或截图自动提炼成"任务级信息卡片"，存下时间、人物与要求；在任务期间切到任何聊天框，点开键盘顶部「交给 AI」说一句意图，系统就带入刚才的信息与长程记忆偏好，直接产出成稿。
体验亮点
它把"跨应用找信息"这个隐形的上下文切换成本，收进了键盘。用户不再需要记住信息在哪，只需表达"我要交付什么"，符合"机器迁就人"的方向。
风险与建议
记忆一旦不可见，就会变成不信任的来源。 建议提供"记忆检查器"：卡片可查看、可编辑、可删除，并明确跨应用信息带入时的授权提示；同时给出"本次不带记忆"的快捷开关，让用户对边界有掌控感。

📎 来源：爱范儿 · 实测讯飞输入法 16.0

豆包工作 录制回放：把"人机争抢同一块屏幕"变成设计问题

Agent 协作
用户痛点
重复流程教 AI 要反复解释每一步和特殊情况，换一批任务又要重教；更真实的问题是 Computer Use 会和你抢同一个窗口——你在录视频或跟另一个 Agent 对话时，弹出来的页面会打断操作，最小化重试往往失败。
设计解法
录制操作自动生成个人技能，最长 30 分钟并支持边操作边讲解"为什么这样选"；同时可授权 Mac 锁屏继续工作、用手机远程下发任务，把"必须守着电脑"的约束松掉。
体验洞察
暂停与重试哪种更好，取决于场景而非偏好本身：本机使用时用户希望自动暂停，别打断主要工作；远程 Mac mini 上跑则更愿意重试，因为不挡人。这说明"人机协作节奏"应该做成用户可理解、可切换的协议。
风险与建议
隐式打断是 Agent 产品最容易被低估的体验债。 建议把"何时让人、何时独占"显性化：用状态灯/交接提示/占用中的窗口标识，让用户预判 Agent 何时会接管屏幕，并提供一键让出与收回。

📎 来源：卡尔的AI沃茨 · 硅基观察Pro

04

研究方法论

今日最值得抄进方法工具箱的一条：把"能分辨"和"更喜欢"分开测量。

用成对偏好 + 三角测试，替代"打个分"

一篇关于语音增强（SE）感知评测的论文指出：现有评测多用客观指标和分类式主观听测，但这些结果并不能说明处理后的语音在感知上是否"不同"、以及日常听众是否"更喜欢"它。研究用众包三角测试与成对偏好测试比较四套 SE 系统与干净参考，发现听众的区分能力和是否存在系统性偏好，会随系统和声学条件显著变化。对用户研究的直接启示是：当产品差异很微妙时，单维 Likert 评分会把"听不出差别"和"听得出但无所谓"混为一谈；三角测试测"能不能察觉"，成对比较测"更想要哪个"，两个维度应同时进入研究设计。 [来源: arXiv · Perceptual Differences and Preferences in Speech Enhancement]

第一视角可穿戴传感：补足自我报告的偏差田野方法

研究者用随身音频传感系统记录混合办公者在家庭与办公室的日常沟通，实时提取声学特征、离线做前景说话人分离，得到"说话负荷"与"活跃度"等量化指标，用来理解环境如何影响沟通行为与情绪健康。相比问卷，它能在不打断工作的前提下捕捉真实发生的交流，适合研究"用户说他很忙"与"他实际被多少对话打断"之间的落差。 [来源: arXiv]

多用户语音 Agent：先解决"谁在说话"Agent 研究

论文指出声纹只是身份的"观察"，不是身份本身，并提出在线说话人记忆构建 EvoSpeakerMem：做因果的说话人路由、选择性更新声学状态，按身份分区读写记忆；同时发布 LoCoMo-ID 基准，包含隐藏说话人身份、说话人敏感查询与录音条件漂移。研究多人共用语音助手时，个性化记忆的评测必须先假设"历史可能归错了人"。 [来源: arXiv]

不确定性引导的多模态共识：别让某一模态带偏结论分析工具

UMC 方法先恢复各模态的连续伪标签，再在多模态之间形成"可靠性感知"的共识，避免把共享标签强加给每个模态、也避免在某模态不可靠时直接融合放大误差。对研究员的类比是：当访谈、行为日志、表情/语音数据互相矛盾时，不应简单投票，而应显式标注每条证据的可信度再做综合判断。 [来源: arXiv]

落地建议：下周做可用性测试时，可以试着把"你给这个方案打几分"换成"这两个方案你更想要哪个，为什么"，再补一轮"你能看出它们不一样吗"。对 AI 生成的访谈摘要，则保留原始录音的可回溯链接，避免自动结构化抹掉"跑题但重要"的细节。
05

UX 雷达

六个还早、但值得放进观察列表的设计信号。

Emoji 的代际语义正在分裂

一项针对微信 20 个笑脸 emoji 的问卷研究发现，「微笑」在老年人那里多表示喜悦与赞扬，在年轻人那里却常被读成讽刺，「再见」也出现相反的解读。跨代沟通产品不能假设统一语义，需要结合关系与上下文做校准。 [arXiv]

同处一室的 MR 对话，要考虑旁观者

Immersive Commons / Atmos Messages 用手势 + 语音转写生成"短暂的空间消息"，并配公开平面图让没戴头显的人也能感知现场。15 名参与者在两场实验中留下 236 条消息（含 48 条语音），反馈出现"好玩"与"社会觉察"。共享空间的旁观者体验，会是包容性设计的新议题。 [arXiv]

"先做朋友，再做助手"的 Tolan

用户可以自己命名、挑外形的 AI 角色，每天聊天并被记住，月活约 25 万、约 70% 为女性，新获 3000 万美元融资。创始人认为人们不想要很多个 AI 助手，只想要一个信得过的——信任关系可能比功能列表更决定留存。 [深思圈]

小红书 × Rokid：把社区经验搬进第一视角

「蜜薯」以随身眼镜为载体，在用户授权下按需感知现场，结合大模型与小红书社区经验给出当下建议，架构上由实时多模态全双工、Proactive 与 Memory 协同支撑，目标指向 Personal OS。它把"别人的分享"变成"与你有关的建议"，是环境式 AI 的典型体验路径。 [小红书技术]

小心"设计伙伴陷阱"

Rob Snyder 提醒：设计伙伴会给你反馈、认同你的愿景，但最终不买——设计伙伴本身可能是"真正需要产品的人"的负向信号。做产品发现时，要把"说得热闹"与"真的会用"分开验证，别把客气当需求。 [Lenny's Podcast]

小而具体的痛点，仍有独立产品的空间

中科大研一学生做的 Apple Watch 录音应用 Auday，上线一个月左右登上日本和美国 iOS 付费榜第一；高中生做的「口袋厨神」解决了"跟着视频做饭要反复拖进度条"的麻烦。这些产品的共同点是：把一个具体到不能再具体的摩擦，做到了极致。 [Founder Park]
