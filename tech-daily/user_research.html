设计趋势洞察

趋势一：Agent-First 开发的信任阶梯设计

VSCode 团队系统阐述了 Agent-First Development 的五大支柱，其中「Harness — Agent 的行动边界」设计尤为值得关注。Copilot 通过 Ask → Plan → Agent 三种模式构建了渐进信任阶梯：Ask 只对话不动文件（探索学习）、Plan 列出步骤等批准（方案讨论）、Agent 自主规划执行（落地任务）。

这一设计洞察的核心在于：从"我主导"到"它主导"的权力让渡必须是有节奏、可逆的。强行一上来就用 Agent 模式做模糊任务，等于让不了解情况的人替你做决定——失控是必然结果。这为用户研究提供了一个重要框架：在 AI 产品的信任设计中，用户的控制感曲线应该如何平滑过渡？每一步权力交接都需要明确的视觉反馈和撤销机制。

UX 启示：AI 产品的权限设计不应是二元开关（全开/全关），而应是一个可感知的渐进式信任构建过程。每个阶段的界面状态需要让用户清晰知道"AI 现在能做什么"、"下一步它可能要做什么"、"我如何随时收回控制权"。
[来源: meng shao / VSCode 团队]

趋势二：AI 互动内容正在重新定义「人与人的连接」

贝果（一款 AI 娱乐应用）的「现实 Online」模式展示了 AI 互动内容的全新可能：拿起手机随手一扫，办公室就被改造成了实时探索的游戏空间。创始人球球提出的三个核心特征值得 UX 研究者关注：

1. 不是单人对话，而是多人开放场景——AI 不再是对话对象，而是社交场景的「场域创造者」；2. 不是生成内容，而是边理解、边调度、边生成——实时响应用户行为和环境变化；3. 不是预设内容，是实时体验——每次交互都是独一无二的。

这种「心流体验」的营造对产品设计要求极高。测试者在体验中完全忽略了身边人的招呼，说明沉浸式 AI 互动已经达到前所未有的深度。这也带来了新的用户研究议题：如何在保证沉浸感的同时设计「防沉迷」和「现实感知」机制？

产品体验点评

Bloome：第一个让人类和 AI Agent 在同一个群聊里协作的消息应用

产品定位 · 协作体验创新

Bloome 的设计理念非常大胆：Multi-Agent · One Room。用户添加 Agent 的方式和添加同事一样——直接把前端 Agent、后端 Agent 拉进同一个聊天，它们已经在同一个 bug 上协作。这颠覆了传统的「人与 AI 一对一对话」模式，创造了一个混合团队协作的新范式。

UX 亮点：设计细节打磨非常细腻，几乎每天都有更新。产品把 AI 从「工具」重新定义为「队友」，这一角色认知的转变直接影响交互设计——Agent 不再只是等待指令的执行者，而是可以主动参与讨论、与其他 Agent 协作的团队成员。

UX 挑战：当多个 Agent 和人类在同一个对话流中交互时，如何区分谁说了什么？Agent 之间的协作过程是否需要对人类可见？信息过载如何避免？这些问题目前还没有标准答案，Bloome 的探索具有标杆意义。

[来源: Berryxia.AI / Bloome]

PettiChat：200 美元宠语翻译硬件背后的用户信任重建

硬件产品 · 用户信任 · 垂直场景

杭州创企 PettiChat 推出售价 198 美元的 AI 宠语翻译器，试图扭转「宠语翻译=伪科学」的用户认知。产品采用音频+视频联合训练，将宠物叫声与行为视频对应，在设备端完成推理（1.2 秒响应），猫狗识别准确率分别达 94.6% 和 92.3%。

UX 洞察：这是一个典型的「信任重建」案例。此前宠语 App 市场已被劣质产品严重破坏——同一句话录多次结果不同、宠物对播放的翻译毫无反应。PettiChat 的策略是：通过硬件形态（27 克项圈夹）建立「专业感」、端侧推理降低隐私顾虑、联合兽医团队打标建立可信度。对于 UX 研究者来说，这提示我们：在已经被「劣币驱逐良币」的市场中，产品设计需要额外的信任信号设计。

研究方法论

腾讯云 Agent Memory：如何用结构化记忆解决「上下文遗忘」问题

腾讯技术工程团队开源了 TencentDB Agent Memory，提出一种基于上下文卸载与结构化图表示的短期记忆压缩方案。核心思路是：将完整信息卸载至外部文件系统，同时利用 Mermaid 图语言把任务执行过程转化为可导航的结构化记忆。

实验结果显示：在超长 Session 中最高节省 61% Token，任务通过率从 33% 提升到 50%。这一方案为用户研究提供了重要启示——AI 的记忆系统设计应该借鉴人类的记忆机制：我们不是把经历原封不动地存储，而是将其压缩成「可展开」的结构化摘要。当需要细节时再「展开」调用。

对 UX 研究的启发：在设计 AI 产品的记忆系统时，可以参考「工作记忆 + 长期记忆」的双层模型。短期交互上下文类似工作记忆（容量有限、随时调用），用户偏好和历史行为类似长期记忆（需要索引和检索）。如何让用户感知并控制 AI 对自己的「记忆」，是一个亟待研究的新课题。

[来源: 腾讯技术工程]

JetBrains Rider 的「覆盖率感知 Agent」：让 AI 少做无用功

JetBrains 在 Rider 2026.2 EAP 中引入了一项降低 AI Agent token 消耗的创新：当 Agent 需要写测试时，Rider 使用已有的 dotCover 覆盖率数据来指导 Agent，让 Agent 知道「哪里已经测过了、测试风格是什么样的、新测试应该放在哪里」。

内部基准测试显示，这种方式减少了高达 50% 的 token 消耗。其 UX 价值在于：AI 不再盲目探索代码库，而是基于已有知识「有方向地行动」。这提示我们，在 AI 辅助工具中，上下文质量比上下文数量更重要——给 AI 一张「地图」比让它自己摸索效率更高。

[来源: The JetBrains Blog]
