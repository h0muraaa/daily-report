设计趋势洞察

Design Deep-dive
Atlassian 实测 DESIGN.md：给 AI 一页「设计语言」，能把 AI Slop 变成品牌风格吗？
📎 来源 meng shao(@shao__meng) · 原文：Atlassian Design 团队博客《DESIGN.md @ Atlassian》

当 AI 能一口气生成整页界面，设计团队开始面对一种新的「审美事故」：所有产品都长着一张 AI 脸——雷同的布局、圆角、紫蓝渐变与言之无物的文案，圈内称之为 AI Slop / AI 味。Atlassian 设计系统团队（ADS）过去一年做的事情，是把自己的设计系统改造成一台「人机双读」的上下文引擎：先是 ADS MCP server 与 Agent Skills——让编码 Agent 在生成 UI 时能实时读取真实的品牌 token、组件规则与排版规范，底层是一套同时服务人和 Agent 的结构化内容模型。而在这次实验里，他们又从同一条结构化内容管线自动生成了一份 DESIGN.md，想验证最轻量的「给 AI 一页设计说明」到底有没有用，并用两个真实场景做了对照测试。

两个场景给出了几乎相反的结论。场景一是「一次性原型」：Team '26 大会主题演讲的现场 demo，用 Figma Make 基于 Teamwork Graph 生成自定义仪表盘，要求一次成型、且不能依赖内部 MCP 服务。这里 DESIGN.md 表现良好——生成物从通用「slop」变成了可辨识的 Atlassian 风格，颜色、间距、形状、字体和层级都符合系统预期。作者认为这类高层指引特别适合去定制 Tailwind、Shadcn 这类通用 UI 库，或者从零生成界面。场景二是「生产代码库」：一个已有设计 token、组件库、严格 lint 与类型检查的真实仓库里，仅把 DESIGN.md 当作唯一设计上下文去完成一个登录页任务——结果它成为所有方案里表现最差的一个；对照中 ADS MCP（约 80% 设计系统上下文覆盖，3.75M tokens、5 分 1 秒、35.1 轮）最优，ADS Skill 接近 MCP，而无上下文的裸生成只有约 5% 的上下文覆盖、消耗 4.20M tokens 与 43 轮。

把两个场景合起来看，DESIGN.md 的定位不是 MCP/Skills 的替代品，而是「零依赖场景里的设计气质锚点」：外包、第三方工具、一次性原型、从零搭建时，一页好的设计语言能显著抬高生成质量的底线；可一旦进入有 token 与组件库的生产环境，精确的、结构化的设计系统接入仍然不可替代。对设计系统团队而言，这份实测真正的信号是——AI 生成界面的同质化，正在倒逼设计系统从「给人看的规范文档」升级为「人和 Agent 共用的结构化数据」，Design Token、组件语义与排版层级都将成为喂给 AI 的「设计语言」。

💡 UX 启示：「一次成型」与「生产级」是两条不同的 AI 生成路径——前者靠风格指引即可，后者靠结构化上下文；品牌想在 AI 时代不「撞脸」，就得先把设计语言变成机器可读的资产。
苹果终于要做触屏 MacBook？「冰箱与烤面包机」的交互契约正在松动
📎 来源 爱范儿

文章开头抛出一个很「用户」的两难：预算只够买一台设备时，你选「iPad + 键盘」还是同价位的 MacBook？iPad 屏幕素质顶尖、手指随时划拉缩放，但一旦坐下来做硬核生产力——多窗口对照排版、复杂表格精确定位、来回解压流转文件——各种别扭的限制会让人抓狂；可反过来选了 MacBook，每次下意识伸手想划一下网页、缩放图片，冷冰冰的玻璃面板又提醒你它只认键盘与触控板。苹果的潜台词一直是：两台都买。

这份「不妥协」背后是两套交互契约。早在 2010 年乔布斯就剖析过垂直触控的人体工学硬伤：把手臂悬在半空戳竖屏，演示两分钟很炫，日常超过十分钟就会带来「大猩猩手臂」般的肌肉疲劳——于是苹果把多点触控的全部筹码押在键盘下方那块触控板上；两年后微软携 Surface 掀起二合一浪潮，库克还在 2012 年财报会上泼冷水。而今天反转的信号同时来自硬件与软件：多方爆料显示一款带 OLED 触屏的高端 MacBook 已在路上，且 macOS 27 底层代码里已经为手指操作做好了全套交互铺垫——软件甚至比硬件更着急。

对设计团队而言，这可能是桌面端交互范式的分水岭：当「冰箱与烤面包机」两套契约开始融合，键鼠的精度与触屏的直觉将共存于同一块屏幕上。混合输入会带来新的设计命题——悬臂疲劳与目标尺寸的平衡、防误触与手掌误触的判定、hover 与 touch 状态如何统一，以及一个更基础的开放问题：桌面触屏到底该为哪些任务服务？这也是一个值得立刻开始观察与测试的真实用户研究课题。

💡 UX 启示：人体工学禁忌并非永恒——当苹果愿意为触屏修改自己坚持了 15 年的立场，说明「混合输入」已不是移动端专属，而将成为桌面产品体验设计的新常态。

产品体验点评

Product Experience
两周 Pixel 11 Pro Fold 实测：折叠屏最大的敌人不是硬件，是每天细碎的「生态摩擦」
📎 来源 Ado(@adocomplete)

一位连续使用 Pixel 11 Pro Fold 两周的用户直言自己「对折叠屏变得很空」（very bearish），并开出一份难得的每日摩擦清单：机身偏厚，随身携带是一件差事；外屏一侧是硬直角、另一侧却是圆角，视觉上就不协调；展开动作比想象中费劲得多；铰链几乎从每个角度都看得到，手指扫过折痕处还能清楚摸到一道凹陷。这些不是「参数问题」，而是每天都会反复触达感官的体验损耗。

更关键的是内屏的日常使用感受：屏幕确实变大了，但 UI 在真实日用里反而像是「巨大的妥协」——很多应用根本没有针对折叠视图优化，这种不适配会渗进每一天的细小操作里，反复打断心流。作者的结论很直接：更多屏幕面积不等于更好的体验，当软件生态还没准备好时，多出来的每一寸屏幕都在放大碎片感。

对做多形态产品的 UX 团队，这份吐槽给出了清晰的适配优先级：先覆盖用户「展开频次最高」的场景，再谈「更大屏的想象力」——否则折叠的价值会被每天的 paper cuts 一点点抵消。
开发者自荐 SmartScrollCapture：为什么 2026 年了，截一张好长图依然这么难？
📎 来源 少数派

这是少数派 Matrix 社区一篇「开发者自荐」合集，其中 SmartScrollCapture 是最典型的「小痛点做到极致」案例。作者先精确描述了两个场景下的长图之痛：在 Mac 上想截一段长代码、终端输出或网页局部，传统滚动截屏工具要么在快速滑动时出现果冻效应与错位断层，要么把固定的网页顶部导航栏重复拼进正文；在手机上想把一段微信聊天记录保存分享，得手动连截十几张再导入 App 拼接，发出去前还得手动打马赛克遮住姓名、头像和电话。

比操作繁琐更深的顾虑是隐私：截图往往包含聊天记录、财务报表、内部代码甚至身份证件，而市面上不少工具会把图片上传到云端处理——在隐私合规日益敏感的今天，把这类数据交给未知服务器让人难以安心。作者的解法是从底层重做：用 Swift + Metal + Vision 实现 100% 本地处理的长截图，把极致画质、无感自动化与隐私安全做成同一件事。

💡 UX 启示：「本地优先」正在从技术架构选择变成体验卖点——当用户对「数据去了哪」越来越敏感，处理发生在设备本地本身就是一种信任设计。

研究方法论

Research Methods
Sam Altman 万字访谈：AI 采用难在「行为改变」，解法是把产品放进真实世界
📎 来源 Z Potentials · 原始访谈：Founders 播客 × David Senra（2026-08-23）

这期访谈里最值得产品与研究团队记下的一句话是：「改变行为，比技术宅们意识到的要难得多。」Altman 认为，AI 是人类发明过最不可思议的技术之一，但社会与经济的适应会慢得多；我们现在处在「拥有全部技术拼图、却还没迎来那个彻底改变人与技术交互方式的 iPhone 时刻」的世界。对做采用研究的人来说，这是一条重要的校准——用户没有「一夜迁移」，技术可行性从来不等同于行为采纳。

他给出的产品方法论也相当朴素：把东西放到世界里，从真实客户那里获得反馈——这是做出好产品的方式，也是做出安全产品的方式。此外，他认为 AI 之后「与人有关的东西会变得更值钱」、即将看到有史以来最大的一次小企业创办潮；而 OpenAI 内部最难的一课，是学会杀掉像 Sora 这样的好点子，为更伟大的想法让路。把这句话翻译成研究语言，就是：需求组合要敢于「砍」，研究资源要留给那些能真正改变用户行为的方向。

💡 方法论要点：研究 AI 产品的采用，应当把问题从「技术行不行」改写为「用户在真实情境里改不改变行为」——用真实环境的行为证据（而非态度问卷）去衡量价值，并把早期真实用户反馈当作安全机制的一部分。
别让 AI 替你思考：两位 AI 产品负责人守住的那一种「原始写作」
📎 来源 Lenny's Podcast — Don't Let Claude Think For You · Why Writing Matters Now

两个来自 AI 公司内部高管的短视频切片，不约而同指向同一个主题：认知防萎缩。Anthropic 产品、研究与实验室负责人 Dianne Penn 说：「你不想要的是一个只会附和你（just agrees with you）的 AI。」她描述了自己用 Claude 打磨思考的方法——让 AI 扮演挑战者来帮她想得更锋利，但绝不让它接管判断。OpenAI 的一位产品负责人则谈到，她几乎把所有写作都交给了模型，唯独有一种写作从不委托——那是她用来防止自己思维萎缩的日常训练。

对每天与 AI 协作的用户研究员和设计师，这几乎是「职业防钝化」的直接提醒：当访谈纪要、用户画像、方案文档都能由 Agent 代笔时，保留一段必须由自己完成的「原始写作/原始分析」，是维持判断力的最低成本纪律。研究中需要 AI 承担的是收集、归纳与证据检索，而提出问题、交叉验证与下结论仍然值得「不假手于人」。

💡 方法论要点：认知卸载（cognitive offloading）有真实的钝化代价。为团队定一条规矩——关键结论的初稿必须由人写，AI 只负责挑战与补充，能同时保住思考质量与 AI 效率。

UX 雷达

Early Signals

儿童创作者出现：一句话为「咪咪小镇」加上 3D 室内

AI产品黄叔(@PMbackttfuture)

GPT-6 前端能力提升后，产品经理记录到孩子被界面吸引：给一张参考图、几轮对话就生成自己的「咪咪小镇」，再用一句话请求「让居民能走进去、每栋楼都要有」的 3D 场景。自然语言正在成为儿童也能驾驭的「界面」，儿童创作者是一个被严重低估的新用户群与研究样本。

产品经理用 GPT-6 把社群首页做成 3D，验证真实用户社交

AI产品黄叔(@PMbackttfuture)

作者用 GPT-6 把 AgentWork 首页调整为 3D 可视化：画面中每个人物都是真实社群用户，可被关注、可添加需求，把「社交关系」直接变成首页交互。他明言「挺初期，看社群用户反馈先」——用 vibe 原型在真实社群里做功能验证，正在成为轻量需求验证的新方式。

DeepSeek「深思熟虑」：思考时长成为推理产品的 UX 新变量

人人都是产品经理

V4 版本把 DeepSeek 的思考时间从十几秒拉长到上百秒——用户最直观的感受不是「更聪明」，而是「等得更久」；思维链细化被部分用户当作质量信号，同时也有「复读机」式无效思考的观感。等待体验（可见的思考、进度反馈、可打断性）正在成为推理型产品体验设计的新课题。

睡眠硬件 Somni：无屏、免学习，连续夜晚「越用越懂你」

创业邦

Fullive.ai 的 Somni 是一款没有屏幕、无需佩戴、也不要求用户睡前再学一套交互的床头设备：用毫米波雷达、麦克风阵列与环境传感器感知呼吸/心率/体动，再以声音、光线、气味做神经系统调节，并会在连续夜晚中学习用户响应、形成闭环。不打扰 + 自适应，是智能硬件体验设计的两条关键原则。

从 GUI 到物理世界：GPT-6 把「屏幕产物」变成可 3D 打印的实物

爱范儿（硬哲学）

GPT-6 发布片让一只黄色圆圈一步步变成可发给 3D 打印机的火箭模型，OpenAI 刻意把故事停在一台拓竹 P1S 上——AI 第一次不只是生成屏幕内容，而是产出可触摸的实体。文章点出「GUI 是 AI 理解世界的第一课」：当 Agent 开始把界面当世界来读，材料触感、形态取舍、按键排布这些「产品的人性细节」反而更值钱。

PageIndex Flash：用「文档结构即索引」重做 PDF 研究体验

meng shao(@shao__meng)

PageIndex Flash 是一个完全本地、开源的 PDF 树状索引引擎：直接读取 PDF 自带的排版结构（文字层、标题元数据、层级）来构建目录树，而不是让视觉模型「看」页面再推断大纲，因此更快、更便宜、结果更可预测。对常在长报告与论文里做 desk research 的研究者，这是「本地 + 结构感知」检索体验的早期信号。

「语音即输入/输出」：把 Agent 从图形界面中心主义里解放出来

Peter Yang(@petergyang)

Peter Yang 呼吁 OpenAI 推一款 Apple Watch App：直接对 Codex 线程语音口述，AI 也用语音回复，这样不必随身带手机、还能戒掉屏幕瘾。把「免提、免看屏」当成对抗屏幕依赖的设计手段，是 Agent 交互脱离纯 GUI 依赖的一个值得追踪的方向——尤其对移动与可穿戴场景。
