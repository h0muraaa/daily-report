设计趋势洞察

趋势一：从“AI 生成结果”到“AI 协作过程”的体验设计

过去半年，设计工具的竞争焦点从“能不能一键出图”转向了“能不能在反复修改中保持可控”。MemSlides 的研究团队指出，PPT Agent 真正难的并非第一版生成，而是用户在第 8 页要求局部调整时，系统不会顺带改掉第 3 页的配色或第 12 页的图表。他们提出的“分层记忆 + 局部修订 + 多轮验证”框架，其实揭示了所有 AI 生成类产品的一个共性设计命题：用户想要的不是一次性惊喜，而是可持续协作的确定性。

与此同时，Claude Code 团队工程负责人 Thariq Shihipar 发现，当 Agent 输出越来越长、越来越复杂时，Markdown 的可读性成为瓶颈，团队开始更多使用 HTML 作为人机协作的输出格式。HTML 的颜色、折叠、交互元素能显著降低复核阶段的认知负荷。这一信号表明：AI 产品的体验设计正在从“模型输出什么”深入到“人类如何消化与介入”。未来，信息呈现的层级、交互的可编辑性、以及人在回路中的反馈效率，将比单纯的结果质量更影响用户留存。

📎 来源：AINLP（MemSlides）、InfoQ（HTML vs Markdown）

趋势二：AI 产品的“解释力”成为核心体验指标

在 AI 产品供过于求的今天，用户面临的不是找不到工具，而是看不懂工具到底能为自己做什么。Veronica Hylak 的演讲《Your AI Product Will Fail Unless You Can Explain It》直指要害：如果普通用户无法在几秒内理解产品的价值，再强的技术也会流失。她过去帮助多个 AI 产品将复杂功能转化为用户可感知的故事，累计获得 700 万观看。

这与“约束”的哲学形成呼应：好产品不是功能越多越好，而是能让目标用户在具体场景中立刻识别出“这正是我需要的”。对 UX 研究者而言，这意味着用户访谈和可用性测试需要更关注“第一印象”与“价值感知”，而非仅验证功能是否可用。产品描述、 onboarding 流程、首屏信息架构，都应被纳入核心研究对象。

产品体验点评

案例一：豆包付费后月活持续下跌，微信“小微”灰度入场

根据 AI 产品榜 2026 年 6 月数据，豆包月活从 4 月的 3.36 亿连续下跌至 6 月的 3.24 亿，两个月累计流失约 1173 万 MAU。此前分析指出“豆包收费不是贵了，是早了”，6 月数据再次印证了这一点：当用户尚未形成足够强的付费心智时，商业化动作会直接冲击规模。

与此同时，微信原生 AI 助手“小微”于 6 月 20 日灰度上线，直接内嵌微信主界面，无需独立 App，可调用微信原生功能与小程序生态。这一路径选择的用户体验逻辑非常清晰：不制造新的使用场景，而是在用户 already 高频的场景里自然嵌入。对研究者来说，这是观察“超级 App 内 AI 助手”与“独立 AI 应用”两种分发模式用户接受度差异的绝佳窗口。

案例二：豆包、千问智能体功能下线背后的用户影响

豆包与通义千问相继宣布，智能体功能将于 7 月 15 日正式下线，用户可在数据保存期内查看并导出历史对话，10 月 15 日后统一清理。官方建议豆包用户迁移至猫箱 App 体验智能体功能。这一调整恰逢《人工智能拟人化互动服务管理暂行办法》施行，合规压力是直接诱因。

从用户体验角度看，智能体功能的下线是一次典型的“功能葬礼”：用户已经建立的对话历史、角色关系和使用习惯将面临中断。产品团队需要在合规与用户情感之间找到平衡——透明的迁移指引、情感化的告别文案、可导出的数据方案，都是减少流失信任损伤的关键。对 UX 研究者而言，这也是研究“AI 陪伴类产品用户依恋与流失”的重要节点。

研究方法论

人机协作研究的新焦点：Agent 时代的“认知负荷与信任校准”

Anthropic Claude Code 与 Cowork 产品负责人 Fiona Fung 在 Lenny's Podcast 中坦承，随着 Routines 上线，团队成员同时运行的 Agent 越来越多，有人一次跑二十个，checking in 和 review 的负荷肉眼可见上升。她的核心判断是：当编码不再是瓶颈，团队的最大变量变成了“能有多大野心”，而验证正在取代编写成为核心动作。

这对用户研究方法提出了新要求：研究者不仅要观察人如何使用工具，还要观察人如何与多个 Agent 分配任务、如何验证 Agent 输出、如何在错误发生时归因与修复。建议引入三类研究手段：一是认知走查，让被试实时讲述自己与 Agent 的协作决策；二是失败日志分析，收集 Agent 输出被人类否决的场景，提炼信任破裂模式；三是团队协作图谱，绘制人与 Agent 之间的任务流、信息回环与责任边界。

📎 来源：Datawhale · Claude Code 之父的老板访谈

“地图不是领地”：用未知盲区清单提升 AI 协作质量

Claude Code 团队成员 Thariq 提出了一个极具实操性的框架：将人与 Agent 之间的信息落差分为四类——已知的已知（prompt 中已写清）、已知的未知（你意识到自己没搞懂）、未知的已知（你懂但没写下来）、未知的未知（你根本没想到）。模型能力越强，越会在“未知的未知”处自行补全世界，最终导致结果偏离预期。

UX 团队可以把这个框架转化为协作前的自检清单：在启动复杂任务前，先让成员独立列出“我认为已经说清楚的事”和“我觉得模型可能会猜错的事”，然后对比汇总。这本质上是一种将隐性设计假设显性化的方法，既能减少返工，也能为后续的 Agent 训练数据积累高质量的问题样本。

📎 来源：AINLP · Fable 5 使用指南
