Claude Code Desktop的UX困境：TUI成功之后的GUI盲区

宝玉详细列举了Claude Code Desktop的四个设计问题：1）Plan mode状态会跨会话继承；2）Sidebar不会按Projects分组；3）右侧Panel相互挤占空间；4）Cowork和Code没必要分成两套产品。这些问题的背后是Anthropic的战略选择——Claude Code在TUI（终端界面）上的成功，导致团队不愿在Desktop GUI上投入足够的设计资源。

这形成了一个有趣的悖论：Anthropic抓住了Coding Agent的机会窗口，但在面向更广泛用户群体的GUI体验上被OpenAI的ChatGPT App拉开差距。正如宝玉所言，"Claude Code在TUI上太过成功以至于他们忽视了GUI"。结果Claude Desktop的设计问题（标签页合并、右侧面板等）被用户反复吐槽。

设计反思：产品成功有时会成为体验升级的阻碍——当核心用户群已经习惯于某种交互模式，产品团队可能会低估新用户的学习成本和扩展场景的体验需求。对设计师而言，需要警惕"成功盲区"：在庆祝一个用户群体的高留存时，不要忘记沉默的大多数可能正在因为体验问题而流失。

Rubrics综述：Agent时代如何定义"好答案"？

中国人民大学高瓴人工智能学院发布的Rubrics综述提出了一个核心问题：当大模型从简单问答走向深度研究、医疗咨询和多模态生成时，"好答案"的标准是什么？传统方法依赖单一正确性信号，而Rubrics将其拆解为多维度、可解释的质量标准——是否回答了用户问题、覆盖了关键信息、引用了可靠证据、论证是否清晰等。

这一框架对用户研究具有直接参考价值：我们评估用户体验时，是否也可以从"总体满意度"的模糊指标转向多维度、可解释的Rubrics体系？例如，一个"好的AI交互"可能需要同时满足：理解用户意图准确、响应时间可接受、输出内容可验证、出错时可纠正、学习成本可控等多个维度。每个维度都可以被单独测量和改进。

研究启示：传统的NPS或CSAT评分可能过于笼统。借鉴Rubrics的多维度拆解思路，我们可以设计更细粒度的用户体验评估框架——不仅知道"体验好不好"，还能定位"哪里不好"以及"如何改进"。

飞书+AI的"划线对话"阅读法：一种可复用的研究工作流设计

向阳乔木分享了一套有趣的AI辅助阅读工作流：将Epub电子书按章节写入飞书文档，人肉阅读时在感触处划线加粗并添加评论，然后让Codex读取标记和评论进行解释回复。这套流程的关键设计在于"人在回路"（Human-in-the-loop）——AI不替代阅读，而是在人产生疑问时提供即时解释。

对研究员而言，这种"先标记后追问"的模式可以延伸到多种研究场景：用户访谈录音转录后让AI提取关键片段并追问洞察、可用性测试视频标注后让AI分析行为模式、问卷开放性回答编码后让AI辅助主题归纳。核心原则是人类负责"发现问题"，AI负责"辅助解释"。

实践建议：将定性研究材料的标记-分析流程搬到协作文档中，让AI在特定标记处生成初步洞察，研究者在此基础上进行修正和深化。这可以大幅提升定性研究的效率，同时保留人类的专业判断。
