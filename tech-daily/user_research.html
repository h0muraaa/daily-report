✦今日要点

  • UX 与 AI 的关系需要重新校准：UX Magazine 新系列提出，AI 不会取代设计师，但会替代那些"本来就不是设计核心"的琐事。真正的竞争力从"做图速度"转向"研究设计、系统思维、伦理判断与组织影响力"。
  • 协作界面进入"环境智能"时代：Anthropic 推出 Claude Tag，让 AI 以共享同事身份常驻 Slack 频道，支持多人接力、持续学习、主动跟进与细粒度权限隔离。这意味着设计师需要为"人机混编团队"重新设计协作规则与信任机制。
  • 对话式 UI 向富交互演进：Microsoft 365 Copilot 通过 SharePoint Copilot Apps 把可操作的 UX 组件直接嵌入聊天画布，用户无需离开对话即可完成审批、预订、查看仪表盘等任务，"上下文即界面"成为新范式。
  • 自动化正在成为新一代"无障碍工具"：GitHub 高管 Ashley Willis 用约 40 个 Copilot 自动化处理会议准备、待办跟进、信息追踪等行政碎片，并坦言作为 AuDHD 人士，这些自动化帮她弥合了执行功能差距。
  • AI 协作催生新型 UX 岗位：Notion 公开招聘 AI Conversation Designer、CX Knowledge Architect、Model Behavior Engineer 等角色，显示对话体验设计、知识架构与模型行为调优正在成为独立专业领域。

◎设计趋势洞察

趋势一

从"工具"到"队友"：AI Agent 的协作体验设计

Claude Tag 的发布标志着 AI 交互从"打开一个聊天窗口问问题"转向"把 AI 当作频道里的常驻同事"。每个频道只有一个共享的 Claude 身份，所有人都能看到它正在做什么、接力继续对话；开启 ambient 模式后，它还会主动跟进沉寂线程、推送相关信息。这种设计把传统 bot 的"请求-响应"模式升级为了"共享上下文 + 异步协作"。

对 UX 研究者与设计者的启示是：当 AI 成为团队流程的一部分，体验设计的关键不再是单点交互效率，而是"可见性"（团队成员知道 AI 在做什么）、"可接管性"（人类可以随时介入或纠正）、"权限边界"（不同频道拥有不同数据与工具权限）以及"记忆归属"（哪些上下文可以跨频道迁移）。这些正是过去设计纯软件工具时不需要考虑的人机协作问题。

来源: Anthropic
趋势二

"上下文即界面"：聊天画布中的可交互组件

Microsoft 365 Copilot 过去擅长处理语言，但工作不只是文字。SharePoint Copilot Apps 允许企业将自定义的富交互组件直接嵌入 Copilot 画布：审批表单、数据图表、个人仪表盘、地图、新闻流等。用户用自然语言表达意图后，"对的 UX 组件会在需要的时刻出现"。

这一趋势对设计系统建设有深远影响：组件不再只属于某个 App 或页面，而是需要在聊天、SharePoint、Teams 等多个表面保持一致；组件必须支持任意 JavaScript 框架（React、Angular、Vue、Svelte），并内建企业安全。设计师需要开始把"组件库"升级为"可跨表面组合的微体验单元"，同时重新思考在异步、碎片化、多模态交互中的信息架构。

来源: Microsoft for Developers

✎产品体验点评

Claude Tag：当 AI 成为 Slack 里的"队友"

Anthropic 把 Claude 以@Claude 的形式嵌入 Slack，用户可以在频道中@它分配任务，Claude 会把任务拆成若干阶段在 Slack 线程中逐步完成并交付结果。它与此前 Slack 私聊或临时呼叫的最大区别在于：多人共享同一身份与上下文、能够持续关注频道对话并积累对团队工作的理解、开启 ambient 模式后可主动推送信息和跟进任务。

从用户体验角度，这种设计解决了三个长期痛点：第一，信息碎片化——任务过程和结果都沉淀在原有协作线程中，不需要切换工具；第二，接力成本——同事可以在 Claude 做到一半时接着聊，无需重复背景；第三，权限焦虑——管理员可以精确指定每个频道的 Claude 能访问哪些工具和数据，例如法务频道的 Claude 不会把信息带到工程频道。Anthropic 内部数据显示，产品团队 65% 的代码已由内部版 Claude Tag 生成，用途还扩展到查产品数据、处理客服工单、排查疑难 bug。

值得持续观察的风险是：当 AI 主动介入对话时，如何区分"有帮助的主动"与"打扰"？ambient 模式的触发阈值、通知频率与可预测性，将直接影响用户是否愿意长期把它留在频道里。

来源: Anthropic
来源: 宝玉 @dotey

GitHub Copilot CLI 新 TUI：开发者工具的界面再设计

GitHub 为 Copilot CLI 推出了新的终端用户界面（TUI），把 issue、pull request、gist 直接带到终端中，并采用 GitHub 原生配色、标签页与斜杠命令。开发者无需反复在浏览器与终端之间切换，就能分配任务、创建 PR、请求代码审查。

这一更新虽然面向开发者，但对工具类产品体验研究有通用启发：专业用户的工作流高度依赖于"保持心流"，每一次上下文切换都是成本。把平台能力下沉到用户 already-in 的环境（这里是终端），本质上是在做"交互表面收敛"的设计。研究者可以借鉴这一思路，审视自己产品中是否存在类似的高频切换点，并评估把动作前置到用户当前上下文中的可行性。

✚研究方法论

把 AI 当作"实习生"：UX Magazine 的协作框架

Tushar Deshmukh 在 UX Magazine 的"UX × AI"系列开篇中提出一个核心隐喻：AI 是一位"需要时刻盯着的、受过中等教育的实习生"。它很快、不知疲倦、读过大量设计文档，但从未与用户面对面坐过，也不能承担专业与伦理责任。这个框架帮助团队把讨论从"AI 会不会取代我"转向"我该把哪些工作交给 AI、如何交接、如何质检"。

文章引用了多项 2025 年研究：Nielsen Norman Group 指出 UX 专业人员的"不可替代门槛"正在提高；Optimal Workshop 发现 AI 消除的是繁琐工作（转录、编码、问卷综合），带来的是"重新分配而非替代"；McKinsey 则观察到集成 AI 的团队会把更多时间花在战略规划和综合研判上。作者还提出 LucyUX 框架在 AI 时代的映射：

  • Listen（倾听）：观察 AI 实际产出与营销承诺之间的差距。
  • Understand（理解）：建立实用心智模型——AI 是基于训练数据的模式匹配，而非从第一性原理推理。
  • Conceptualize（概念化）：有意识地设计 AI 集成工作流，而不是被动接受。
  • Yield（产出）：衡量"用户结果质量"，而非"设计流程效率"。

实践建议：本周选一个你 routinely 做的生成任务，与 AI 并行完成一次，然后对比——AI 在哪里省时间、在哪里遗漏、在哪里给出了"看起来对但感觉不对"的结果。

来源: UX Magazine

自动化作为"执行功能辅助"：从 GitHub 高管实践看包容性设计

GitHub 开发者关系高级总监 Ashley Willis 分享了如何用约 40 个 Copilot 自动化处理领导工作中的"隐形劳动"：晨会准备、产品发布追踪、每日成就回顾、消息承诺跟进、 stale work 发现、差旅安排等。她强调这些自动化没有取代人际连接，反而让她能把精力留给"真正的人类工作"。

特别值得关注的是，她将这些自动化视为自己的"无障碍工具"——作为 AuDHD 人士，自动化帮助她弥补了执行功能差距、保持一致性。这对用户研究的启示是：AI 辅助工具的受益者可能远比我们想象的更广泛。在研究这类工具时，除了关注效率指标，还应关注它如何帮助不同认知特征、工作负荷状态的用户维持工作节奏与心理安全感。

来源: The GitHub Blog
