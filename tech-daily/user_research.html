设计趋势洞察

"反 AI 味"设计：审美能力进入 Agent 工具链

当前最容易被一眼识破的 AI 产物，往往不是事实错误，而是那种"太顺了"的页面：卡片很多、渐变很稳、按钮很圆，但整体像是同一个模型从同一个抽屉里拿出来的东西。当 agent 开始真正参与产品设计、前端生成与代码维护时，审美问题正在转化为工程约束问题——agent 不仅要能写代码，还要知道什么时候该停下来问：这个页面是否有自己的节奏？这个组件是否只是套了模板？这个设计系统是否能在下一轮生成中保持稳定？

这一趋势在 Hallmark、Stitch Skills 与 Matt Pocock Skills 三个项目中呈现不同侧面：Hallmark 把"反 AI 味"写成 Claude Code、Cursor、Codex 可用的设计检查清单；Stitch Skills 围绕 Google Stitch MCP 提供设计、构建与工具插件；Matt Pocock Skills 则主张把真实工程经验沉淀为小型、可组合的 agent 工作协议。截至 2026-07-18，三个项目在 GitHub 上分别获得 12,228、7,632 与 175,827 stars，反映出开发者与设计师对"可复用品味"的强烈需求。对 UX 从业者而言，这意味着未来的设计系统不仅要规范组件，更要规范"何时偏离模板"的判断逻辑。

从高保真原型到可执行的"产品语言"

宝玉在实践 BaoCut 的开发过程中，逐渐形成了一套以 Claude Design 为核心的新工作流：先用 Claude Design 设计 App 的 UI 与 UX，交付 HTML + CSS + React + data.js，让设计系统的颜色、尺寸、组件结构与数据结构一目了然；随后将设计稿交给 Claude Opus 4.8 实现 MVP，先从纯 UI 功能开始，再逐步迭代。相比传统 Figma 稿，这种交付物对 AI 更友好——data.js 是常规设计工具不会产出、但对开发至关重要的中间产物；所有文件均为文本格式，可直接纳入 git 版本管理，用 diff 即可让 AI 理解设计变更。

这套流程的核心洞察是：高保真原型已经可以替代传统产品文档。可交互、带模拟数据、可快速修改的原型，比静态文档更直观，也能让 AI 在实现时还原九成以上细节。对产品经理与 UX 设计师来说，这提示了一种新的协作契约：设计交付物不再只是"给开发看的图"，而是可以直接被下游 AI 消费的"可执行规格"。

产品体验点评

ChatGPT 统一搜索：从"搜互联网"到"搜自己"

7月14日，OpenAI 给 ChatGPT 上线了一套全新的统一搜索，首次允许用户在一个入口检索自己账号内的历史聊天、项目、上传文档与生成的图片，Web、iOS、Android 三端同步，覆盖从免费版到企业版的所有计划。这并非补一个搜索框那么简单：过去四年，用户与 ChatGPT 的对话、稿件、代码、图片持续累积，但旧版侧边栏搜索几乎等于摆设，想找回三个月前的某次讨论往往要靠运气。

从体验角度看，这次更新完成了两个关键转变：一是将"个人与 AI 的交互历史"从成本变成了资产，让用户意识到真正值钱的不只是模型能力，而是自己沉淀下来的数据；二是将搜索范围从公开互联网收窄到个人上下文，这是一种全新的信息架构逻辑。对 UX 设计师和产品经理的启示在于：当 AI 产品从"工具"演进为"长期伙伴"，用户会越来越需要"找回记忆"的能力——而这背后涉及索引策略、隐私边界、结果排序与跨端一致性等复杂设计问题。

Moz2 商用服务机器人：亲和力是公共空间的第一道 UX 门槛

在 2026 WAIC 具身智能展区，千寻智能首次亮相了 Moz2 商用服务机器人。这款探索型产品采用浅色系柔感机身、圆角线条与自然挥手、比心等肢体互动，第一眼给人的感受是"软萌"而非"机械"。但 Moz2 的核心目标并不是立刻上线复杂任务，而是验证公域场景的人机交互形态——服务机器人进入商超、酒旅、办公楼宇等公共空间时，第一道门槛从来不是"会不会干活"，而是"人愿不愿意接近、敢不敢使用"。

与 Moz2 同台展示的 Moz1 则站在 1:1 还原的客厅场景前，仅凭一句"整理客厅"的指令就自主完成识别、规划、收纳、归位全流程。一萌一稳、一软一硬两台机器人同场出现，展示了千寻"用 Moz2 前置探索商服交互形态，用 Moz1 筑牢长程任务基本盘"的产品策略。对人机交互设计而言，这是一个值得关注的信号：在具身智能普遍炫技的阶段，率先把"情感接纳"作为设计第一性原理的产品，可能更快完成从 demo 到真实服务的跨越。

ITCH 活动：让真实商家替代虚构用户画像

旧金山一场名为 ITCH 的创业活动没有 pitch deck，也没有虚构的用户画像，而是让几位本地生意老板直接上台讲述他们每天到底卡在哪里。其中一位经营了四十年便利店的老板 Darren，另一位是精品咖啡 D2C 品牌创始人 Kurt——两人的背景截然不同，但都在描述那些"不性感但真实"的日常麻烦：手机半夜总在响、库存对不上、供应商审查繁琐、客户投诉找不到责任人。

对用户研究者来说，这种形式本身就是一个方法论提醒：当硅谷热衷于讨论 AI agent、估值与融资轮次时，真正有价值的产品机会可能藏在便利店老板的夜间通知、咖啡农的履约流程与小商家的合规焦虑里。ITCH 的逻辑是"创业点子不是靠头脑风暴想出来的，而是要去找那些真实存在的问题"——这与用户研究中的情境访谈、田野观察与 Jobs-to-be-Done 高度契合。在 AI 降低开发门槛的今天，能否找到足够具体、足够真实的用户痛点，可能比能否快速写代码更能决定产品生死。

AI 辅助用户研究的新工作流

正在形成的 AI 产品工作流，正在把用户研究、设计与开发压缩为一个更紧密的反馈闭环。Claude Design 与 Cursor 等工具让设计师可以用自然语言快速生成可点击原型；Codex 与 Opus 则负责将原型转化为可运行代码。这个闭环的关键变化在于：用户反馈可以更早、更便宜地获得——原型阶段就能进行快速测试，而不必等到完整开发完成。

对 UX 研究者而言，这意味着研究介入点正在前移。传统流程中，用研通常在需求明确后、设计启动前介入；而在 AI 辅助流程中，研究者可以与设计师一起用 prompt 快速生成多个方案变体，并在原型阶段就进行小范围可用性测试。同时，AI 也能帮助自动化处理访谈转录、情感分析、用户反馈聚类等研究后勤工作，让研究者把更多时间花在洞察提炼与策略建议上。这种"智能化研究流程整合"将成为下一阶段用户研究团队能力建设的重要方向。
