GitHub Copilot 远程控制正式发布：在任意设备上接管你的 Agent 会话

NEW

GitHub Copilot 的远程控制功能现已全面可用（GA）。开发者可以在 VS Code 或 CLI 中启动一个 Agent 会话，然后通过 /remote 命令在手机端的 GitHub Mobile App 或网页版 github.com 上继续操作。JetBrains IDE 也已支持该功能。

这一更新解决了多 Agent 并行场景下的核心痛点：过去离开工位就意味着丢失对所有会话的可视性。现在你可以让一个 Agent 在后台重构模块，另一个在调试测试，同时通过手机随时查看进度——真正的多表面（multi-surface）开发体验。

LangChain 开源 SmithDB 技术细节：DataFusion + Vortex 构建 Agent 可观测性数据层

ARCH

LangChain 工程师 Ankush Gola 披露了 SmithDB 的技术选型：基于 Rust 的 Apache DataFusion 作为可扩展查询引擎，配合 Vortex 可扩展文件格式。DataFusion 负责自定义执行计划和查询优化，Vortex 则提供列式存储的灵活编码和分块策略。

深度技术解读

小红书 CCD 感知编排：突破多核 CPU 向量搜索性能天花板

PERFORMANCE

小红书引擎架构团队在 ICDE 2026（数据库三大顶会之一）发表论文，提出了一种面向多核 CPU 的 CCD 级负载感知和线程编排向量检索框架。论文核心贡献在于解决了现代多核服务器上向量近似最近邻搜索（ANNS）的性能扩展瓶颈。

核心数据：在小红书搜推广真实负载下，吞吐量最高提升 3.7 倍，P999 长尾延迟降低 30%~90%，CPU 缓存未命中率降低 6%~30%，总 CPU 停顿时间减少 20%~80%。

技术要点：CCD（Core Complex Die）级缓存亲和性调度 + 冷热负载感知映射。现代多核 CPU 的 CCD 架构导致跨 CCD 访问内存时延显著增加，传统线程调度策略无法感知这种拓扑差异。小红书的方案通过将计算任务绑定到数据所在的 CCD，并动态调整线程数以匹配实际负载，系统性解决了这个问题。

对于正在做向量检索基础设施的开发者，这篇论文的工程实践价值很高。论文链接：arXiv:2605.10090

从 0 到 1：17 种 Agent 架构演进路线详细拆解

AGENT_ARCH

腾讯技术工程分享了一篇基于 GitHub 项目 all-agentic-architectures 的深度解读文章。原作者用 LangChain/LangGraph 实现了 17 种 Agent 控制流模式，而本文作者用更简洁的 agno 框架将其重写了一遍。文章最有价值的不是代码本身，而是对"为什么从架构 A 升级到架构 B"的逐层分析。

核心观点：Agent 架构的本质不是 prompt engineering，也不是某个框架的 DSL，而是控制流设计。真正决定 Agent 系统能否落地的，通常不是模型回答够不够好，而是：状态有没有被正确建模、控制流有没有被显式表达、错误能不能被局部截断、副作用能不能被关进闸门、系统知不知道自己什么时候该停。

17 种架构的演化路径可概括为：单次生成 → 反思闭环 → 工具交互 → 观察-行动循环 → 显式规划 → 验证驱动重规划 → 多 Agent 编排 → 长期记忆系统 → 搜索/模拟/涌现计算。每一代升级都用同一套六个问题来拆解：解决什么问题、State 定义、拓扑结构、控制边界、错误处理、终止条件。这种分析框架本身就可以复用到任何 Agent 系统的设计评审中。

BEST_PRACTICE

HTML vs Markdown：AI Agent 时代的技术规格文档应该用什么格式？

BEST_PRACTICE

Anthropic Claude Code 工程师 Thariq Shihipar 发表长文《The Unreasonable Effectiveness of HTML》，Karpathy 点赞转发。核心论点：在 AI Agent 时代，HTML 正在取代 Markdown 成为技术规格和规划文档的首选格式。

  • HTML 的优势：结构化更强、支持交互式元素（折叠/表格/图表）、视觉层次更丰富、AI 对 HTML 的理解精度高于 Markdown
  • Markdown 的优势：生态壁垒深（GitHub README、文档产品广泛支持）、人工编辑门槛低、Git diff 可读性好
  • 实际建议：Agent 中间产物可用 Markdown，最终产品/方案对比用 HTML；短期 Markdown 不可替代，长期 HTML 趋势明显
关键洞察：Markdown 的真正优势不是"人能读"，而是"AI 能高效处理"。但随着模型上下文窗口扩大到百万级，HTML 的标签开销不再是瓶颈。

大淘宝技术：RAG 全链路技术详解

RAG

天猫品牌行业架构团队发布的 RAG 实战指南，覆盖从文档加载到评估闭环的完整链路：

  • 文档加载：多格式解析 + 元数据提取
  • 智能切分：规则/语义/结构化方法，含 Meta-Chunking 原理
  • 索引构建：Embedding 模型选型、向量生成、分片策略
  • 检索优化：Query 改写、HyDE/Doc2Query、标签过滤、重排序
  • 生成调优：Prompt 设计、参数控制、SFT 微调
  • Graph RAG：多跳推理与全局摘要
  • 评估体系：Ragas 自动化评测（Context Precision/Recall、Faithfulness、Answer Relevancy）
核心理念："可测、可调、可信赖"的 RAG 工程化实践。Agent 的业务上限直接由 RAG 技术水平决定。
