① HydraFusion 架构拆解：混合路由 / 级联 / 批判式修订
HydraFusion 不是又一个新模型，而是一套"模型编排层"。开发者像选择普通模型一样选择它，背后它会在多个供应商模型之间做运行时路由。其核心包含三种工作流：
  • Single：简单任务直接用最合适模型一步完成；
  • Cascade：先用低成本模型尝试，不达标则级联到更强模型；
  • Critique：一个模型写方案，另一个模型审查与修正，形成双人复核效果。

从 GitHub 博客给出的指标来看，在 Terminal-Bench 2.1 上 HydraFusion 对比 Claude Opus 5 实现了 "4.9 个百分点更高的验证任务质量 + 67% 更低的估算成本"。这背后其实是语义路由——让不同类型的任务匹配最适合自己的执行路径，而不是用一个大模型包办所有事。项目定位是"自动语义路由"战略的一环，未来预计还会打通本地、云端与复合模型之间的调度。

② LangChain 全面拥抱 MCP 新规范：FastMCP v4 + interrupts

LangChain 昨日宣布在 main package 中正式支持新版 MCP 协议，这意味着 pip install 'langchain[mcp]' 即可用。此版本直接建立在 FastMCP v4 之上，协议协商、工具名冲突、连接生命周期、传输与身份认证等底层问题全部由 FastMCP 吸收。

最值得关注的两点：一是 elicitation——MCP 的 human-in-the-loop 概念通过 LangChain 的 interrupts 机制获得了支持；二是 list_tools 缓存，避免 Agent 每次循环都重新拉取工具表，会显著降低延迟。对正在做 MCP server / client 集成的团队，这是这周最重要的更新之一。

# 快速开始
pip install 'langchain[mcp]'

# FastMCP v4 现在同时支持 client/server/app 开发
