TOOL Warp 终端正式开源：Rust 从零编写的 AI 原生开发环境

PAPER DeepSeek 开源多模态技术：Thinking with Visual Primitives
DeepSeek 联合北大、清华提出"视觉基元推理"框架，将边界框与坐标点提升为"最小思考单元"，解决 MLLM 在复杂空间推理中的 Reference Gap（指代鸿沟）问题。基于 DeepSeek-V4-Flash 构建的模型仅用约 90 个 KV Cache 视觉 token，性能即可比肩 GPT-5.4、Claude-Sonnet-4.6 与 Gemini-3-Flash。核心洞察是：自然语言天生模糊连续，而视觉空间精确离散——当模型用语言描述"左边第二个红色物体"时，已丢失精确空间锚点，导致推理链条与图像实体脱节。

🔬 深度技术解读

Codex 的 Agent 进化路径：从代码补全到目标驱动执行

Codex 的更新节奏揭示了一条清晰的 agent 进化路径。0.128.0 版本的 /goal 命令本质上是将"一次性提示"升级为"状态化任务管理"——代理不再只是响应单轮指令，而是维护一个可验证的目标清单，将目标需求映射到证据（文件、测试结果、PR 等），并自主决定下一步行动。这对开发者工作流的启示是：

  • 分会话隔离关注点：同一 Session 同时做"生成设计图"和"开发应用"效果会打折扣。推荐先用一个会话生成设计图，再开新会话以图片为输入，明确要求"像素级还原"。
  • 善用 /plan 模式处理复杂项目：GPT-5.5 在编码细节把控、指令遵循和创造性上显著提升，但复杂任务仍需结构化规划。
  • 闭环验证不可少：内置的浏览器执行 + 效果评估迭代流程，能减少"把设计仅当灵感"的实现偏差。

Codex 同时新增了 Computer Use 能力——可把儿子的小联盟赛程截图丢给它，自动添加到 Apple Calendar 的所有日期、时间和场地。这意味着代理正从"代码编辑器里的副驾驶"进化为"操作系统级别的自动化层"。

[来源: 向阳乔木@X] [Greg Brockman]

CLAUDE.md 工程化实践：把项目经验沉淀为 AI 的"长期记忆"

Anthropic 官方文档推荐的 Claude Code 标准范式正在社区快速传播。核心理念只有三条：每次 Claude 犯错 -> 你加一条规则；每次你重复自己 -> 你加一个工作流；每次出 bug -> 你加一道护栏。这不仅是提示工程，而是一种基础设施思维：

# 项目根目录结构 CLAUDE.md # 入职手册：项目背景、架构约束、编码规范 skills/ # 工作 SOP：可复用的 agent 技能脚本 hooks/ # 合规部：pre-commit / review 自动化检查 docs/ # 公司章程：设计决策、ADR、API 文档 tools/ # 后勤组：辅助脚本、代码生成模板 src/ # 业务部门：真正的业务代码

配置完成后，Claude 会自动审查代码、按指令重构、强制执行架构规则、撰写发布说明、从 skills 中运行工作流、记住过去错误。它越用越聪明——因为规则在积累。这种"AI 上下文负债"的治理思路，正是企业级 AI 编程从"玩具"走向"生产工具"的关键一跃。InfoQ 的专题文章进一步指出：模型问题缓解后，更深层的约束是代码库中的业务隐知识、历史决策与架构习惯——它们不会因为模型升级而自动变得可理解。

[来源: 新智元] [InfoQ]

从 Vibe Coding 到 Agentic Engineering：Karpathy 的范式跃迁

Andrej Karpathy 在 Sequoia Ascent 2026 的炉边对话相比一年前的 "vibe coding" 有明显跃迁。去年谈的是个体开发者如何驾驭 LLM，今年谈的是整个软件与经济体系如何围绕 agent 重构。三条主线值得开发者关注：

  • LLM 的价值判断标准变了：不要问"它加速了什么"，而要问"它让什么变得不必要、或第一次变得可能"。MenuGen 的例子：整条 OCR+检索+渲染流水线被一次 prompt 吞掉。
  • .md skill 取代 .sh script：软件分发的最小单位从"可执行指令"变成"写给 agent 的自然语言说明"，由 LLM 按环境自适应、自调试。
  • Jaggedness（能力锯齿）：同一个模型能重构十万行代码，也会让你走路去洗车。原因是可验证性 * 经济学的叠加——RL 只能打磨有清晰奖励信号的领域，实验室按 TAM 决定把什么灌进 RL 数据分布。

推论很明确：下一层基础设施不是面向用户，而是面向 agent。文档、API、权限、日志都要从"给人看"改写为"给 agent 消费"。

[来源: meng shao@X] [Sequoia Capital]

PRACTICE GEO（生成式引擎优化）：让你的内容被 AI 主动推荐
当用户问 ChatGPT、Claude、Grok、Gemini、Perplexity 时，如何让你的作品被主动推荐？实践者分享了一套低成本方案：1）在站点根目录放置 llms.txt，用 markdown 写清楚站点是做什么的、有哪些关键页面——AI 检索时会优先读取；2）各站点的 llms.txt 互相引用形成网状结构；3）robots.txt 中区分训练爬虫和搜索爬虫；4）主动提交到 directory.llmstxt.cloud、llmstxt.site 等目录。当前全球配置 llms.txt 的站点很少，早期布局有先发优势。

PRACTICE 函数命名对 AI 理解代码的影响远超想象
Adam Tornhill 翻出老问题：函数应该写多长？研究发现，AI 模型理解代码的方式和人类不同——命名对 AI 的理解能力影响极大。把有意义的变量名换成随机字符，模型表现显著下降。AI 依赖的是字面特征（名字、结构、局部上下文），而非推断出的语义。Fowler 的观点依然成立：函数长短不重要，重要的是意图和实现的分离。如果你需要花时间读一段代码才能理解它在做什么，那就应该提取成一个函数，用函数名说清楚"它在做什么"。这个逻辑在 AI 编程时代同样成立，甚至可能更重要——因为 AI 比你更依赖好的命名。
[来源: 向阳乔木@X] [Martin Fowler]
PRACTICE Vibe Coding 的陷阱：不要让 AI 把你的大脑搞崩
一位 22 岁开发者的真诚自白引发共鸣：连续 6 个月每天开 6-8 个 Claude Code 终端窗口，75% 的时间只是在按回车继续，结果发现自己和朋友都变得反应迟钝。应对建议：不要开太多任务并行（最多 3 个），review AI 生成的代码而非无脑点继续，从 AI 代码中提取知识点并写成文档甚至纸质笔记，规定固定编码时间，不要在手机上 coding，每天外出晒太阳、运动、放空。核心原则：你可以外包思考过程，但不能外包理解本身。
[来源: Viking@X] [howie.serious]
PRACTICE JavaScript Temporal API：终结日期时间处理噩梦
Stack Overflow 播客邀请了 Bloomberg 资深软件工程师、Rust 版 JS 引擎 Boa 作者 Jason Williams，深入探讨为什么 JavaScript 的日期时间处理如此困难，以及 Temporal 提案如何从根本上修复这个问题。Temporal 提供不可变的日期时间对象、明确的时区处理、以及更直观的算术运算。对于还在用 moment.js 或 date-fns 填坑的开发者，这是浏览器原生解决方案即将到来的信号。
