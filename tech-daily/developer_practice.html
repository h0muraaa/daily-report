Agent工程

Anthropic 内部 Skills 用法首次公开：9 类实践完整复盘

Anthropic 团队公开了内部使用 Claude Code Skills 的完整经验，将 Skills 分为 9 大类：library/API reference、product verification、data access、code generation、testing harness、deployment、debugging、on-call 和 documentation。核心洞察是：Skill 不只是几段提示词，而是一个围绕任务组织的工作文件夹，包含 SKILL.md、参考文档、脚本、模板、示例、hooks，甚至可被后续任务读取的数据。

最值得投入的前三类是：给模型补知识（library/API reference）、补验证（product verification）、补数据（data access）。这个分类对正在搭建团队 AI 工作流的开发者有直接参考价值——与其写更长的 prompt，不如把验证过的做法、容易踩的坑、常用脚本整理成可复用的 Skill。

开源工具

ex-Meta L8 工程师开源 Agentic Engineering 三件套：日均 40 PR

前 Meta L8 工程师 Kun Cheng 公开了他的 Agentic Engineering 系统，现在每天能 ship 高达 40 个 PR。这套系统的核心是三件开源工具：Lavish（将 AI 计划渲染为可视化 HTML artifact）、gnhf（"good night, have fun"——让 agent 在你睡觉时朝着目标工作）、No Mistakes（AI 代码验证流水线，在合并前捕获错误）。

Kun 的实践哲学是："如果我花大量时间精心制定详细计划，agent 就能工作更久。"他的工具全部免费开源，对想要提升 AI 辅助编码效率的开发者来说，这是目前最接地气的一套可参考架构。GitHub 仓库已公开，可直接 fork 使用。

[来源: Peter Yang(@petergyang)] · Lavish · gnhf · No Mistakes
测试实践

用 AI 构建 E2E 测试体系：Spec → Code → Verify → Test → Green 五阶段流程

开发者 Viking 分享了一套在 monorepo 多框架项目中使用 AI 辅助 E2E 测试的完整实践。他的项目 TinyShip 同时支持 Next.js、Nuxt.js、TanStack Start 三套前端框架，以及 PostgreSQL 和 SQLite 两种数据库，每改一个功能有 6 种组合可能出问题。

他总结的五阶段流程是：Spec（定义测试规格）→ Code（AI 生成测试代码）→ Verify（agent-browser 验证）→ Test（运行 E2E 测试）→ Green（通过）。这套流程的本质是"E2E 驱动新功能开发"，把测试从验证后置变为开发前置。对于多框架、多数据库的组合爆炸场景，这是可落地的成本降低方案。

[来源: Viking(@vikingmute)] · 详细文章
成本优化

Netflix 开源 Headroom：砍掉 90% 冗余 Token，省下 70 万美元

Netflix 高级工程师 Tejas Chopra 开源了 headroom，一款在指令到达 LLM 之前以 token 为单位进行精简的工具。Chopra 估计高达 90% 的 token 对模型来说是冗余的，Headroom 已为用户节省了约 70 万美元，对应 2000 亿 token。

这个工具的诞生源于作者个人项目收到 Claude Sonnet 287 美元账单的"刺痛时刻"。Headroom 目前 v0.22 版本在 GitHub 上已获得 2000+ stars。对于使用 AI Coding Agent 的团队来说，token 成本优化正在从"可选项"变成"必选项"——尤其是当 agent 开始自主迭代、产生大量中间请求时。

范式转移

Coding Agent 技术全景图：Context Engineering、Subagents 与 Harness

Thoughtworks 全球 AI 辅助软件交付负责人 Birgitta Böckeler 在 QCon 纽约站深度解析了过去一年 Coding Agent 领域的范式转移。核心观点是：单纯靠"Vibe Coding"和 Prompt 调优无法撑起企业级软件开发，必须构建确定性的 Harness 作为安全网来约束非确定性模型产出。

关键洞察包括：Context Engineering 是双向放大器（既能放大好实践，也会放大坏结构）；风险评估永远离不开概率、影响、可检测性三个维度；未来的项目模板可能不再是 React/Vue 的选择，而是"有没有现成的 Harness"。对于正在引入 AI 编码的企业团队，这篇文章提供了从"尝鲜"到"工程化"的完整思考框架。

基础设施

Cloudflare 新增 Claude 托管代理支持：自有基础设施运行 AI Agent

Cloudflare 新增对 Claude Managed Agents 的支持，允许开发者在 Cloudflare 平台内运行和管理 Claude 代理，同时保留 Anthropic 平台上的编排工作。集成包括沙箱控制、日志功能、私有服务访问、浏览器会话监控、内置邮件功能和可自定义工具。

这意味着开发者不再必须将所有技术栈放在 Anthropic 提供的基础设施上，可以根据安全、合规或性能需求选择自有基础设施。对于需要满足数据主权要求或在特定区域部署的企业来说，这是一个重要的灵活性提升。同时支持自托管沙箱和 MCP 隧道。

数据工程

Meta 重构 PB 级数据摄取架构：零停机迁移数千条管道

Meta 工程团队完成了对日均数 PB MySQL 社交图谱数据摄取平台的迁移。团队用集中式、自管理的数据仓库服务取代了各业务团队独立维护的数据流转管道，通过反向影子部署、校验和持续监控等手段实现零停机。

迁移分为三阶段：影子阶段（用生产数据验证新系统）、反向影子阶段（切换生产权限并保留回滚能力）、清理阶段（一致性与性能检测通过后下线旧管道）。这个案例展示了超大规模分布式系统迁移的最佳实践——不是一次性替换，而是渐进式验证，每个阶段都有明确的回退策略和监控指标。

模型实测

Arena.ai 发布 Agent 能力实测榜：37 万次真实会话数据

Agent Arena 排行榜基于 373,431 次真实会话数据，对 18 个主流模型的 Agent 能力进行排名。排名依据是"净改进"（Net Improvement），用因果推断方法计算相对于随机基线的性能提升幅度。

战力榜首：GPT-5.5 High（+10.66%），Claude Opus 4.7 Thinking 第二（+9.47%）。分项指标更有意思：Claude Opus 4.7 Thinking 在"确认成功"指标上净改进 7.95%，是所有模型中最高的，说明它在把任务真正做完这件事上最稳。国产模型 GLM-5.1（智谱）以 +3.38% 排在第八，在 Bash 恢复能力上表现亮眼。对于正在选型 Agent 底层模型的团队，这是比 SWE-Bench 更接近真实工作场景的参考数据。

深度技术解读

AI 自进化：从"辅助编码"到"递归自我改进"的技术拐点

Anthropic 联创 Jack Clark 在 BBC 采访中透露了一个关键数据：Anthropic 代码库中超过 80% 的代码来自 Claude，且两年内可能达到 100%。这不是一个营销数字，而是标志着 AI 辅助开发正在跨过"辅助"到"自主"的边界。

递归自我改进（RSI）的核心机制是：AI 系统无需人类干预就能自主设计并改进自身。在代码领域，这意味着 Claude 不仅写业务代码，还在写改进 Claude 自身的代码。Meta 前 FAIR 研究总监田渊栋的 Recursive 实验室（估值 46.5 亿美元）正是押注这个方向。

对开发者的实际影响：

  • 短期（1-2 年）：AI 编码助手将深度集成到 CI/CD 流程，代码审查、测试生成、文档同步将自动化
  • 中期（2-3 年）：代码库的自维护将成为常态，开发者角色向"架构决策"和"目标定义"转移
  • 风险：Anthropic 呼吁全球联手建立 AI "刹车踏板"机制——失控的递归改进可能导致不可预测的系统行为

开发者现在可以做的：开始使用 agentic 工作流（如 Kun 的 gnhf 模式），让 AI 在夜间自主迭代；同时建立严格的验证 Harness（Headroom + No Mistakes 的组合），确保自主生成的代码质量可控。

实践指南

GUIDE 01
E2E 驱动的新特性开发流程
来自 Viking 的多框架 monorepo 实战经验。面对 Next.js + Nuxt.js + TanStack Start 三套前端框架和 PostgreSQL + SQLite 两种数据库的组合爆炸：

1. Spec：用自然语言描述新功能的用户场景和验收标准，让 AI 理解"要做什么"
2. Code：AI 基于 Spec 生成实现代码，覆盖所有框架/数据库组合
3. Verify：用 agent-browser 做快速功能验证，确认基本逻辑正确
4. Test：运行完整 E2E 测试套件，捕获跨框架/数据库的兼容性问题
5. Green：所有测试通过后合并

核心原则：把"人肉点击验证"替换为"自动化 E2E 覆盖"，让 AI 承担重复工作，开发者聚焦在 Spec 质量和异常处理上。
GUIDE 02
Skill 工程化：从 Prompt 到可复用工作材料
基于 Anthropic 内部实践的 Skill 设计方法论：

1. 不是 Prompt，是文件夹：Skill 应该包含 SKILL.md（核心指令）、reference/（参考文档）、scripts/（常用脚本）、templates/（模板文件）、examples/（示例输出）
2. 分类优先：先判断 Skill 属于 library/API reference、product verification、data access、code generation、testing harness、deployment、debugging、on-call 还是 documentation
3. 写好 gotchas：每个 library/API Skill 都必须包含"容易用错的规则和 gotchas"，这是模型最需要但文档最不写的
4. 可验证：Skill 应该包含如何验证输出是否正确的指引，最好是可执行的测试命令

参考 mattpocock/skills 的极简风格——大多数 Skill 只需几句话，但每句话都是真实开发中最有价值的经验。
GUIDE 03
Token 成本控制：从被动付费到主动优化
随着 AI Coding Agent 的使用深入，token 账单正在从"个人项目的小开销"变成"团队级别的成本项"。Netflix 的 Headroom 给出了一个思路：

1. 识别冗余：分析 agent 的提示中哪些是重复出现的上下文（如项目结构、编码规范），这些可以提取到 Skill 中一次性注入
2. 压缩中间产物：agent 生成的中间思考、草稿代码往往占据了大量 token，通过 summary 和截断策略减少传递
3. 分层调用：简单任务用轻量模型（如 Claude Haiku、GPT-4o-mini），只在复杂推理时调用旗舰模型
4. 缓存策略：利用 OpenRouter 等平台提供的 prompt caching，让重复调用的成本降低 50-90%

Headroom 的启示：token 优化不是"省小钱"，而是让 agent 在同等预算下完成更多次迭代。
