Google Genkit 引入中间件架构

Google 给开源的 AI Agent 框架 Genkit 加上了 Middleware 层——一个可编程的拦截层，能够包裹模型调用、工具执行和生成循环。这意味着你可以像写 Express/Koa 中间件一样，统一处理重试、安全过滤、日志、限流、可观察性等横切关注点，而不必把这些逻辑散落在每个 prompt 调用里。对于在生产环境跑 AI 服务的团队，这套机制天然适合做 token 计费、PII 脱敏、prompt 注入防御等工程化能力。

AWS MCP Server 正式 GA：基于 IAM 的 Agent 治理

AWS 把托管版 Model Context Protocol Server 推到 GA，给 AI 编码 Agent 提供了访问 AWS API、文档与运维工作流的标准接口。相比此前需要给 Agent 颁发宽泛 IAM 凭证的做法，这套 MCP 把权限收敛到一个可审计的中间层，结合 IAM 策略可以做最小权限调用、行为审计与会话隔离。对于把 Claude Code/Codex 接入企业 AWS 资源的团队，意味着不再需要自己写一层封装来做权限控制和审计日志。

编排OpenAI开源

OpenAI 开源 Symphony：用 Issue Tracker 作为 Agent 控制平面

OpenAI 工程团队开源了 Symphony——一个多智能体编排器，核心思路是把项目管理工具（如 issue tracker）当作 control plane 来调度 Coding Agent。开发者不再需要同时盯 3–5 个交互式编码会话，Symphony 持续监控任务看板，自动给每个进行中的任务分配 Agent；Agent 崩溃或停滞时由编排器重启，发现可重构点时还能反向创建新 issue。这种"任务 → 树状分解 → 跨 Agent 调度"的模式，把工作单元从 PR 解耦到 issue，是目前 Multi-Agent 工程化最值得参考的开源样本之一。

Claude Code工作流

Claude Code 的 #1 实用技巧：Auto Mode + Multi-Clauding

Anthropic 工程师 Boris Cherny 给出他认为最有价值的 Claude Code 使用建议：开启 auto mode（Shift+Tab 切换），跳过权限确认弹窗，从而实现"multi-clauding"——一个会话在跑长任务时，并行起另一个会话干别的活。Auto mode 现已下放到 Pro 计划，并同时支持 Sonnet 4.6 和 Opus 4.7。这条配置变化看似很小，但它实际上把人机交互模式从"轮流操作"变成"流水线作业"，是想充分压榨 Claude Code 配额的开发者必备开关。

SkillsCodexPrompt 工程

从 Codex 历史会话中"沉淀" Skills 与 Subagent

Codex 团队 @reach_vb 分享了一个非常实用的 prompt：让 Codex 回顾你过去的会话历史，识别重复出现的任务模式（比如"为什么 CI 挂了"、"帮我 review PR"、"生成 changelog"），自动产出可复用的 Skills 或 Subagent。区分原则很清晰：多步骤、有固定流程的工作流抽成 Skill；单一职责、可委派的角色任务抽成 Subagent。Prompt 设计上有几个值得学习的细节：基于真实会话作为数据源（不是凭空生成）、强制二分类（避免模糊产出）、领域聚焦（限定 CI/PR review/changelog/docs/release/debugging/test triage 七类）、显式质量约束（"only the useful ones, keep them simple"）。

Web 技术WebGPU前端

Liquid DOM：把 Apple Liquid Glass 视觉效果搬到 Web

@AndrewPrifer 开源的 Liquid DOM 把 visionOS / iOS 26 的"液态玻璃"效果落到了浏览器里，基于 WebGPU + 实验性的 HTML-in-Canvas API 做真正的光学合成（不是 backdrop-filter 那种近似）。技术前提苛刻：需要 WebGPU、需要在 Chrome 里开启 chrome://flags/#canvas-draw-element 标志，且必须使用 Three.js 的 WebGPURenderer。架构上 Scene → Container（光学单元）→ Glass（形状壳）+ Html（DOM 纹理节点）的分层设计很清晰。光学参数被分组到形状融合、模糊位移、折射（thickness/ior）三个真实物理概念，不是装饰性 CSS 变量。值得想做 Web 上高保真视觉效果的前端研究学习。

深度技术解读

📐 队列积压恢复：把"凭感觉等"变成"按公式算"

InfoQ 翻译了一篇极其实用的 SRE 文章。作者从一次真实事故讲起——DynamoDB 限流导致 Kafka 消费者积压 240 万条，事故"结束"后才是真正问题：什么时候能追平？大多数团队靠刷 CloudWatch 仪表盘和直觉判断。文章给出了可落地的公式体系。

三个关键数字：

  • λ：到达速率（消息/秒）
  • μ：单消费者处理速率（消息/秒）
  • c：消费者数量
utilization = λ / (c × μ)

当 utilization < 1 时队列稳定；超过 1 队列就会增长。基于此可以推导积压清空时间、消费者冗余容量、自动扩缩容触发条件等。文章特别提醒：80% 利用率看起来"没问题"，但已经接近爆发临界点——这是很多团队 capacity planning 翻车的地方。如果你负责消息系统、批处理或 Stream Processing，这套公式值得贴在 runbook 第一页。

📎 来源: InfoQ 中文

🧠 DeepSeek 的算力创新栈：在硬件封锁下的工程突围

面对 GPU 禁运，DeepSeek 没有走"堆算力"的路，而是从架构层做了一整套压缩与重构。技术栈值得做大模型推理工程的人系统理解：

  • MLA（V2）：把 KV Cache 压缩约 90%，1M 上下文只需约 5.48GB 显存
  • DSA / CSA / HCA（V3/V4）：在长上下文场景下计算量几乎不随长度线性增长
  • mHC（Manifold-Constrained Hyper-Connections, 2025.12）：27B 模型在 BIG-Bench Hard 上 +7.2 分，训练开销只多 6.7%
  • GRPO：替代行业通用的 PPO 算法；RLVR（Reinforcement Learning from Verified Rewards）让模型用"可验证答案"自我强化
  • Multi-Token Prediction：用于推测解码，把训练信号密度拉满
  • Engram（2026）：用 LPDDR 内存"换"算力——把权重/中间状态外存到便宜内存

对工程师的启发是：当硬件约束硬到无法突破时，模型架构本身的算法-系统协同设计才是真正的护城河。DeepSeek 的论文是 self-contained 的好读物。

🤖 AI Agent 全自动跑完 7nm 芯片设计：12 小时从 219 词到 GDSII

AI 芯片初创公司 Verkor 发布的 Design Conductor 系统第一次让大模型 Agent 跑通了从需求到 tape-out ready GDSII 版图的完整 CPU 设计流程。输入是 219 个英文单词的需求（RISC-V RV32I + ZMMUL、5 级流水线、顺序单发射、1.6GHz 目标频率、ASAP7 PDK），输出是 12 小时后的 GDSII 文件。整个过程涵盖需求理解、架构设计、RTL 代码、功能验证、时序收敛、物理版图，没有工程师参与任何单个环节。

这颗 VerCore 跑分仅相当于 2011 年的 Intel Celeron SU2300，且尚未流片，但工程意义在于：第一次证明 EDA 流程能被 Agent 端到端串起来。如果你在 EDA / 硬件设计自动化方向，这篇技术报告（arXiv 2603.08716）的工作流编排值得细读。

实践指南

① 不要"认知投降"：AI 写的代码你仍然要为它负责

Vercel 的 Lee Robinson 提出："Cognitive surrender——停止思考、盲目接受 AI 给的答案"是当前最大的工程风险。AI 可以帮你 triage prod logs、分析 errors、加速调查，但生产代码的决策必须由你拍板。如果你不理解正在调试的系统，AI 帮不了你太多。趋势是：减少依赖、把第三方库 vendor 到自己仓库里方便直接改、宁愿写更明确的代码也不引入复杂抽象。

📎 来源: Lee Robinson 📎 延伸: Addy Osmani

② Multi-Agent 并行的"反模式"：FOMAT 焦虑与同步陷阱

多数人开 3–5 个 Codex/Claude Code 会话同时跑，超过这个数量就会"FOMAT"——担心错过 Agent 的提问而频繁切换窗口。解法有两个层次：

  • 编排层：用 Symphony / 本地 Kanban 把会话状态可视化，把"持续盯着"变成"事件驱动"
  • 通知层：用 Cmd+Ctrl 类工具把 Agent 阻塞事件推到手机，离开终端时不会丢失上下文

核心思路：不要把人变成 Agent 的事件循环，让真正的事件循环在工具里跑。

③ AI 编程的 token 经济学：缓存命中率比模型选择更重要

本周 Codex 团队公开了一次复盘：用户额度"消耗变快"的根因，是一次针对长会话 compact 的优化导致 cache hit rate 下降。已经回滚并重置所有账号额度。这个事故提醒：当你的工作流横跨长会话时，缓存命中率是真正的成本来源。实践建议：

  • 把稳定的上下文（项目 README、关键约定）放在 prompt 最前面，避免变动
  • 动态信息（用户问题、当前文件）放后面
  • 避免频繁修改系统 prompt 中的"格式要求"，否则每次都失效缓存

④ <dl> 元素的现代用法：你可能一直用错了

Simon Willison 引用 Ben Meyer 的文章，整理了几个关于 HTML <dl> 元素的冷知识：① 一个 <dt> 可以跟多个 <dd>；② 可以用 <div> 包裹 <dt>/<dd> 组合（但只能是 div）来方便样式；③ 用 aria-labelledby 给整个列表加无障碍标签；④ 自 HTML5 2008 草案起，它叫 "description list"，不再是 "definition list"。一个合法的现代用法：

<h2 id="credits">Credits</h2>
<dl aria-labelledby="credits">
  <div>
    <dt>Author</dt>
    <dd>Jeffrey Zeldman</dd>
    <dd>Ethan Marcotte</dd>
  </div>
</dl>
