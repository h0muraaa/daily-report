OpenAI Agents SDK 重大升级：内置沙箱与 Harness 框架

OpenAI 的 Agents SDK 近日迎来关键更新，新增了内置沙箱执行环境和模型原生执行框架 Harness。这意味着开发者不再需要自己搭建文件读写、代码执行、依赖安装等底层基础设施，Agent 可以在统一受控环境中直接运行。沙箱支持 Cloudflare、Vercel、Modal、E2B、Daytona 等主流平台，并提供 Manifest 配置层来统一挂载本地或云存储（S3、GCS、Azure Blob），显著降低了从本地开发到生产上线的迁移成本。

Cloudflare 发布 Project Think：下一代 AI Agent 原语

Cloudflare 推出 Project Think，作为 Agents SDK 的下一代演进方向。它提供了一组构建长运行 Agent 的新原语，包括持久化执行（durable execution）、子 Agent（sub-agents）、沙箱代码执行和持久会话（persistent sessions），并配套一个 Opinionated 基类将这些能力串联起来。开发者可以按需使用底层原语进行精细控制，也可以直接基于基类快速启动项目。这标志着 Cloudflare 正在从边缘计算向 Agent 运行时平台深度转型。

CPU 与主板的隐喻：Agent 架构为何从"增重"转向"外挂"

李继刚在解读一篇最新综述时，用"CPU 与主板"的隐喻解释了当前 Agent 架构的范式转移。过去三年，行业信奉 Scaling Law，试图通过不断增加模型参数（从十亿到万亿）来解决一切问题——这相当于让"CPU"越来越重。但实践证明，模型本身再聪明，也解决不了选择性记忆更新、跨 Session 持久化、工具调用标准化和多 Agent 协作等工程问题。

于是行业开始转向"主板"思路：不再单纯堆参数，而是在模型外围搭建记忆库、技能库（Skills）、协议层（MCP）、执行沙箱和持久化存储。Auto-GPT、MemGPT、MCP、Claude Code 等产品的涌现，本质上都是在丰富这块"主板"上的组件。正如 CPU 性能再强也离不开主板上的内存、总线和外设，Agent 要真正落地，也依赖于外围基础设施的成熟。这一视角有助于开发者理解：为什么当前 Agent 开发的竞争焦点已经从"用什么模型"转向了"如何设计系统架构"。

[来源: 李继刚(@lijigang_com)]

MCP 正在消亡？CLI 才是 AI 工具未来的观点争鸣

前端早读课转载的一篇观点文章引发了技术社区的讨论。作者 Eric Holmes 认为，MCP（Model Context Protocol）正在迅速失去意义：它增加了新协议和服务端进程的复杂度，却未给 LLM 带来实质性的新能力。OpenClaw 和 Pi 等新兴产品均不支持 MCP，正是因为它们看到了这种复杂性带来的维护负担。

作者主张，CLI 工具凭借可组合管道（composable pipelines）、可复现调试、沿用既有认证机制和更少的"活动部件"，在可靠性和效率上更胜一筹。他建议企业优先投资高质量的 API 和官方 CLI，而不是为每个服务都维护一个 MCP Server。这篇文章为当前遍地开花的 MCP 生态提供了一个冷静的反思视角，值得在评估技术栈时参考。

[来源: 前端早读课]

开源依赖风险管理：从 SBOM 到自动化治理

InfoQ 分享的一场演讲中，Celine Pypaert 系统性地讨论了现代应用中的开源依赖风险管理。她提出了一个可落地的蓝图：利用可利用性数据（exploitability data）优先处理高风险漏洞、通过 SBOM（软件物料清单）提升透明度、并以自动化治理弥合 DevOps 与安全团队之间的责任鸿沟。对于正在建立供应链安全流程的技术团队，这套方法论具有很强的参考价值。

用 Sec-Fetch-Site 替代 CSRF Token：Simon Willison 的新方案

Simon Willison 在他的 Datasette 项目中发起了一个引人注目的 PR：完全移除基于 Token 的 CSRF 防护，改用 Sec-Fetch-Site HTTP 头进行保护。传统 CSRF Token 需要在每个表单中嵌入隐藏字段，并为外部 API 调用单独关闭保护，开发体验较差。而现代浏览器已广泛支持 Sec-Fetch-Site，它可以可靠地识别请求是否来自同一站点。这一实践为 Web 应用的安全设计提供了一个更简洁的现代化思路，但需要注意仅适用于面向现代浏览器的应用。

[来源: Simon Willison's Weblog]
