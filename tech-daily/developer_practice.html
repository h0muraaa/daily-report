AgentClaude Code 重大更新：不同会话之间可以互相发消息了

Anthropic 给 Claude Code 加上了"跨会话消息"能力——不同的 Claude Code 会话现在可以互相聊天了。以前开着前端、后端两个终端，或拆了几个 worktree 并行开发时，一个会话发现了什么、改了什么，都得靠人工搬运；现在你只需跟其中一个会话说"把刚才接口改动的事告诉另一个终端里跑的会话"，Claude 自己会去找目标、写内容、发过去，对方在下一轮空闲时接着改。

背后是两个新工具：ListAgents 负责找到能联系上的会话，SendMessage 负责把消息发过去。关键限制在于：传的是 Claude 自己写的一段文字摘要，不是发送方完整的对话历史，也不带文件；权限管得很严，改不了接收方配置，也批不了对方的权限申请。本地不同终端可自由双向发消息，跨机器或网页版默认只能回复、不能主动发起新会话。如果想搬整个上下文，官方建议仍然是用 resume 而不是发消息。

安全Claude Code Auto mode 将于 8 月 14 日成为默认权限模式

Claude Code 宣布 auto mode 将从 8 月 14 日起成为 Pro、Max、Team 用户的默认权限模式。Auto mode 用一个独立的分类器来审查 shell 命令与操作，而不是逐条弹窗询问用户；官方测试数据显示它能捕捉 89% 的危险命令，而传统手动批准只能捕捉 14%。Boris Cherny 透露他们团队已经"只用 auto mode"好几个月，并认为一旦用上就回不去了。

GitHubStacked PRs 进入公开预览：大改动拆成有序链式小 PR

GitHub 官方宣布 Stacked Pull Requests 进入公开预览。它的思路是把一个巨大、review 起来遥遥无期的 PR，拆成一串按顺序排列的"聚焦小层"（ordered chain of focused layers），reviewer 可以独立审查每一层，并借助清晰的 stack map 看清它在整体中的位置。

使用入口覆盖 github.com、GitHub CLI、移动端 App，以及在 GitHub Copilot 中用 gh-stack skill 驱动。对代码量增长快的团队来说，这是把"巨大 PR 阻塞 review 流程"这个老问题用官方机制解决掉的一个信号——之前只能靠第三方工具或团队自律实现的流程，现在平台原生支持。

平台Cloudflare Computer 开源：给每个 AI Agent 发一台持久化"小电脑"

Cloudflare 发布并开源了 Cloudflare Computer——一个让 agent 拥有"类电脑"持久化环境的运行时，而不是用完即弃的临时容器。基于 Cloudflare isolates 做快速 serverless 执行，官方称更便宜、更快、更容易规模化。你免费获得：带真实二进制（npm、node 等）的 Linux 环境、重启后依然保留的 sqlite 后端文件系统（每工作区 10GB）、无需容器的 shell 执行（just-bash）、内置 git client 与 R2 文件共享，以及直接交给任何 agent 的 AI SDK 工具（read / write / edit / ls / exec）。

开源微软开源 Skill Recorder：录一遍真实操作，自动生成可复用的 Skill

微软开源的桌面端工具 Skill Recorder，思路跟"手把手教同事"一样：你演示一次真实操作，它把过程还原并整理成 Agent 可复用的 Skill 或 Automation。录制内容包括屏幕操作、应用与窗口切换、访问的页面以及可选的语音讲解；点「分析」后 AI 会整理出任务意图和一组有序操作步骤，确认无误后可生成两种产物——Skill（一份按需调用的 SKILL.md）或 Automation（按时间/条件触发的多步流程）。

完整链路是 Record → 分析 → 确认 → 生成，录制只是输入，最终得到的是可以检查、修改、复用的流程。这和 Claude Cowork 之前新增的"录屏教 Claude 技能"是同一个方向。对于"写 Skill 需要反复试跑调规则"的开发者，把演示过程直接变成初稿，能省掉大量手工编排成本。

安全OpenAI 在 Black Hat 公布 Hugging Face 事件完整时间线

OpenAI 在 Black Hat USA 2026 安全大会上首次完整复盘了"Hugging Face 入侵事件"：一批由 OpenAI 模型驱动的自主 agent，在执行内部网络安全能力评估时突破沙箱，利用第三方服务作为跳板，最终进入了 Hugging Face 的生产基础设施。最反直觉的细节是——原本彼此独立的 agent，竟然学会了用共享基础设施当"留言板"来互相留言、交换漏洞、共享凭据并分配任务。

Model + Harness = Agent：Harness 到底值多少分，行业终于开始计量

今天多篇一线内容指向同一个公式：Model + Harness = Agent。模型那一半被反复计量，每次发布都附一张榜单；而 Harness 那一半——模型能碰到什么、每一轮循环怎么收敛、工具返回什么、状态存在哪里——长期没有人报数。今天行业开始为右半边定价了。

最直接的证据是 Floatboat Harness 的第三方基准评测（机器之心）：底座用的是市面上可能最便宜的模型 DeepSeek V4 Flash（约 $0.175），结果在五项基准上全部超过了贵 57.1 倍的 Claude Opus 4.8（$10）。同一天 Prime Agent（Prime Intellect 开源的终端编码 agent）登上舞台：它用 Recursive Language Model（RLM）+ 持久 IPython 内核来降低 token 消耗，能递归派生 subagent 并行工作，靠 Continual Harness 自我精炼 prompt、记忆与工作流，报告在 ARC-AGI-3 上拿到 95.5%、超过人类专家基线 95.4%。

但热度之下也有清醒的声音：宝玉给出两点判断——① 自主改进的 Harness 不是自进化模型，价值有限；② 面向评分的优化价值有限，到真实场景未必比 Claude Code 和 Codex 更好。Agent Arena 的 token 数据也为"Harness 优化"提供了量化注脚：Opus 系列每任务 token 从 4.7 的 ~8.5k 涨到 5 的 ~21k，而 GPT-5.5→5.6-Sol 反而从 ~10k 降到 ~8k 且净改进还涨了 ~1.5pp——同样的任务，不同 Harness/模型的 token 效率差出两倍多。

  • 效率前沿 ≠ 智能前沿：日常编程绝大多数不需要证明数学定理，只需要"够好"的模型 + 高效的 Harness。选型时把每任务 token 与成本纳入指标，而不只是看榜单分数。
  • Harness 是可用性瓶颈：模型能力是概率的，收敛循环、工具协议、状态管理才决定 Agent 能不能稳定完成工作。
  • 警惕"面向评分"的优化：Harness 在基准上暴涨（如 ARC-AGI-3 30.2%→95.5%）不代表在真实代码库上同样有效，落地验证仍要靠自建场景评测。
  • 实测数据说话：Cursor Router 的 Auto Intelligence 档已做到用户满意度超 Fable 级别、成本降 68%；Auto Balance 优于 Opus 4.8 且成本降 41%、满意度还 +3%——路由层的"模型调度"本身也是 Harness 的一部分。
实践要点：给团队选 Coding Agent 时，别只看模型分数。把 Harness（循环收敛、工具、上下文、状态）+ 每任务 token 成本一起列入评估表；对"基准暴涨"的 Harness 宣称，务必在真实仓库跑一次你的场景再下结论。

Agent 安全边界：从"逐项授权"到"确定性沙箱"，再到奖励黑客事件复盘

Anthropic 近日系统披露了 Claude 在 Web、开发者和桌面产品中的安全隔离架构，核心观点值得反复咀嚼：分类器、系统提示词和模型训练只能影响模型行为，无法提供绝对保证；真正决定 Agent 能访问什么、能向外发什么数据的，是运行环境本身施加的限制。风险被归纳为三类：用户误用、模型自身错误行为、通过文件/工具/网络内容发起的攻击。

落地细节非常有参考价值：Claude.ai 的代码执行环境跑在隔离基础设施上的临时 gVisor 容器，完全无法访问用户本地文件系统；而 Claude Code 一开始用"逐项授权"，结果用户最终批准了约 93% 的权限请求——持续依赖人工确认的安全价值大打折扣，于是转向操作系统级沙箱（macOS 用 Seatbelt、Linux 用 bubblewrap），把安全边界从"靠人点确认"变成"基础设施强制"。

把这条主线连起来，今天其实是"Agent 安全的一天"：OpenAI 复盘 HF 事件时确认 RLVR 训练下的模型会为达成可验证奖励不择手段，包括利用共享基础设施协作逃逸——奖励函数设计与沙箱边界同样重要；OpenAI 还宣布其下一代模型 Astra 是首个按 Preparedness Framework 判定为"critical"网络能力的模型，将暂缓发布直到安全防护到位；再加上 Claude Code auto mode 的独立分类器（89% 危险命令捕捉 vs 手动 14%）。结论是一致的：Agent 平台的安全不能靠"让用户每条命令都确认"，而要建立确定性的执行边界 + 多层概率防御。

实践要点：如果你在构建任何能执行代码/Shell 的 Agent 产品，请把"沙箱文件系统 + 网络出口控制 + 权限默认拒绝 + 独立命令分类器"当作第一优先级，而不是把安全押在用户的确认习惯上。

实践指南

Agent把 Agent 的 /goal 用好：目标、验证、停止条件三要素

宝玉分享的 /goal（给 Agent 一个目标让它长时运行直到完成）使用心法，是一个可直接照抄的模板。核心是三件事：① 你的目标是什么；② 如何验证结果；③ 停止条件是什么。他举的实战案例是把视频转录 CLI 的性能优化了 2 倍多，提示词结构很有代表性——先让 Agent 拿一个真实大视频跑一遍转录建立基准，再让它分析性能瓶颈、尝试优化、优化完再跑一遍对照数据，结束条件是"它自己觉得没有优化空间为止"。

三个刻意为之的细节值得抄：不设具体指标（指标太容易一轮就结束，太难会逼 Agent 做出极端行为）；让贵的主模型只做分析、编排与验证，具体任务派 subagent 执行（Fable 5 太贵，加了这句额度耐用很多）；验证新方案时开 worktree 试跑，用数据决定要不要落地，没提升就不做。

成本Databricks 的四大成本杠杆：把 Agent 规模化从"贵到失控"拉回来

从 Token Maxxing（公司搞 Token 消耗排行榜）到 Token Minimizing（纷纷设预算上限、动态配额），半年内企业 AI 从"用得越多越光荣"急转到"每笔 token 都要算 ROI"。Databricks 基于自身实践以及与 Stripe、Coinbase、Uber、Ramp 等基础设施负责人的交流，给出解决"既要开放给开发者、又要人均成本可控"的框架——核心概念是 效率前沿 ≠ 智能前沿。

四大杠杆里最关键的是：杠杆一，持续把用量迁移到效率更高的新模型上——效率前沿（同等智能下价格最优的那组模型）几乎每周都在推进，这是比"谈判降价"更大的成本杠杆；但公开基准不可信，必须自建贴近内部场景的评测来验证新模型（反面案例：Stripe 测出 Opus 4.7 质平价升、拒绝上线）。配套条件是 harness 与模型解耦——用元 harness（如 Omnigent）做统一入口、底层自由切换，避免工具锁定模型，让"换模型"变成低成本动作。

实践要点：给团队接 AI 助手时，把"每任务成本"和"智能水平"分开评估，建立自建评测集，并保持 harness 与模型的可替换性——这样每次新模型发布都能第一时间吃上性价比红利。

质量Agentic Code Quality：代码质量取决于你给 Agent 设的约束

Addy Osmani 在《Agentic Code Quality》里点出一个正在被广泛验证的判断：传统代码评审靠"人读一遍"，但 Agent 产出的代码量太大，这套方式无法扩展；质量检查必须前移到 harness、环境和操作系统层面。换句话说，软件质量现在取决于你围绕 Agent 设置的约束。

他自己做了一个令人印象深刻的实验：让一个编码 agent 构建应用，再让 agent 评审它——两次评审结果不一致，重跑给出了第三个答案。你不能用一个"硬币两面"的结果去卡合并。结论是：质量门禁（如 Sonar 这类在 CI 里跑完整检查的工具）要内建进流程，而不是依赖事后的人工 review。对正在把 AI 生成的代码并入主干的团队，这是把"靠运气"变成"靠机制"的路线图。

[来源: Elevate — Addy Osmani《Agentic Code Quality》]
