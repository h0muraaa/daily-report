AI Coding

Simon Willison 用 Fable 5 一次提示构建出 llm-coding-agent

Simon Willison 发布了一个实验性 Python 库 llm-coding-agent 0.1a0，核心亮点不是功能本身，而是它的构建方式：先让模型写一份 spec.md，再要求用红/绿 TDD 分阶段提交，每个 commit 都带测试和文档。整个过程几乎是一次性由 AI 完成的。这展示了把 LLM 当作“架构师 + 开发者”组合使用时，Prompt 工程、Spec 驱动开发与 TDD 可以如何结合，快速产出可维护的原型。

[来源: Simon Willison's Weblog]

Code Review

GitHub Copilot 推出中等深度代码审查预览

GitHub Copilot 的代码审查能力新增“中等深度”选项并进入公开预览。相比快速扫描，它会将 PR 路由到更高推理能力的模型，对复杂逻辑、安全敏感代码和跨服务变更做更彻底的分析。官方示例显示，它能发现整数运算顺序这类 subtle 的 bug。对于团队来说，这意味着可以把 AI 审查当作“第二双眼睛”嵌入工作流，但仍需保留人工最终把关。

[来源: GitHub]

Open Source

Milvus 开源 MFS：给多源数据一个文件系统式的统一命名空间

Milvus 团队开源了 MFS（Multi-source File-like Search），目标是让 Agent 像工程师一样在不同信息源之间穿梭。它能把 GitHub 仓库、Slack 线程、设计文档、Jira issue、CRM 笔记或数据库行，映射成带稳定 URI 的文件式命名空间。Agent 可以通过 CLI 或 Python/TypeScript SDK 进行语义搜索，再用 tree、ls、cat、head、tail 这类熟悉的命令逐层验证。这套“先定位、再确认”的架构，对构建企业级 RAG 和 Agent 记忆系统很有参考价值。

[来源: Milvus(@milvusio)]

Generative UI

Google 发布 A2UI v0.9：跨平台、框架无关的生成式 UI 标准

Google 推出 A2UI v0.9，试图为 AI Agent 定义一种声明式 UI 意图的标准，让同一个界面意图可以在不同平台渲染，而不需要生成任意代码。新版本提供了 Python SDK、改进的错误处理和多种传输方式，并强调与现有设计体系对齐。如果你在构建跨端 Agent 产品，这个标准值得跟踪，因为它可能减少“每个平台各自实现一遍 UI”的重复劳动。

[来源: InfoQ]

AI Agent

Browser Use 团队再开源 video-use：让 Agent 帮你剪视频

因 browser-use 而成名的团队，又开源了 video-use：一个可装进 Claude Code、Codex 等 Agent 的 AI 视频剪辑 Skill。你只需把原始素材扔进文件夹，说一句“剪成发布视频”，Agent 会自动扫描素材、提出剪辑方案、等你确认后生成 final.mp4。它最有意思的设计是避开直接处理视频帧，而是把音频转成带时间戳的文本，让模型基于文本结构做决策，从而把 20 分钟素材从数千万 token 降到可接受的成本。上线两个月已收获 1.3 万 Star。

[来源: 逛逛GitHub]

Serverless

CCOnline 的 Agent 存算分离实践：全部跑在 Cloudflare 上

CCOnline 是一个在浏览器里跑 Claude Code 的 Vibe Coding 工具，最新架构改为完全 serverless：不再为每个用户固定一个 sandbox，而是按会话隔离、动态挂载 sandbox 做 Agent 运算。对话记录落 D1，工作区文件存 R2，计算跑 Worker，整个链路都在 Cloudflare 上。这种“控制面 / 计算面 / 存储面”分离的架构，对想把通用 Agent 部署到边缘、降低长期持有成本的团队有借鉴意义。

[来源: idoubi(@idoubicc)]

Data Platform

Cloudflare 披露内部统一数据平台 Town Lake 与 AI 分析代理 Skipper

Cloudflare 分享了其内部数据平台 Town Lake 和 AI 分析代理 Skipper。Town Lake 基于 lakehouse 架构，使用 Trino、Iceberg、R2 和 DataHub，统一了运营、计费、安全和业务数据。有趣的是，计费查询占了总查询量的 53%，约 9.1 万次。Skipper 则提供自然语言访问能力。这个案例说明，企业内部数据平台的真正瓶颈往往不是“能不能跑 SQL”，而是如何让不同角色安全、快速地访问跨系统数据。

[来源: InfoQ]

CLI

Vercel CLI 新增 Flags segments 管理命令

Vercel Flags 的受众分群（segment）现在可以通过 vercel flags segments 命令在 CLI 中管理。segment 由 include:、exclude:、rule: 三种 token 组合而成，支持 --add/--remove 增量编辑，也支持 --data 全量替换为 JSON。所有命令都输出 --json 格式，方便在 CI 和本地工作流里脚本化。对于需要把功能开关纳入 GitOps 或 Agent 驱动的流水线团队来说，这是个小而实用的更新。

[来源: Vercel News]

深度技术解读

Architecture

从 AI Coding 到 Harness Engineering：Agent 工程化正成为新的软件架构范式

AI Coding 已经越过“代码补全”阶段，进入多文件修改、调试、测试、代码评审的完整任务链路。InfoQ 的《Agentic AI Architecture》迷你书和近期国内工程团队的实践分享，都在描述同一个趋势：Agent 工程化（Harness Engineering）正在成为一种新的软件架构范式。

它的核心不是让 AI 写更多代码，而是把“设定目标与边界 → 审阅 checkpoint → 判断转向 → 最终验收”的人类角色，与“代码生成、测试、修复、验证”的自动化动作，通过清晰的边界、可观测的 checkpoint 和可验证的闭环连接起来。腾讯应用宝活动平台团队分享了他们在系统重构中引入 Harness Engineering 的经验：在需求理解、方案调研、代码生成、运行验证、问题修复等阶段，让 AI 尽可能连续完成实施动作，人只负责目标设定和质量把关。

对开发者的启示是：未来区分“会用 AI”和“不会用 AI”的工程师，关键可能不在于 Prompt 技巧，而在于能否设计出让 Agent 稳定输出、可回滚、可验收的工程框架。这包括 Spec 驱动、TDD、小步提交、自动化验证、版本化记忆等已经被验证过的工程实践。

[来源: InfoQ] [来源: 腾讯技术工程]

RAG

本地私有 RAG Agent 的实践路径：LangChain v1 + Ollama + Qwen

freeCodeCamp 发布了一篇完整教程，演示如何用 LangChain v1、Ollama、Qwen 和 Python，在本地机器上构建一个面向个人文档的 RAG 问答 Agent。它的价值在于“完整可落地”：从安装模型、准备文档、编写 Agent 代码到运行并查看带引用来源的输出，每一步都有代码和说明。

A2A Workflow

Traycer Desktop：把多个 Coding Agent 放进同一个工作区

Traycer 发布了免费的桌面应用并开源，主打 BYOA（Bring Your Own Agent）。你可以把 Claude Code、Codex、OpenCode、Cursor 等 Agent 接入同一个 workspace，让不同 Agent 分工协作：一个负责规划、一个负责实现、一个负责审查。任务、聊天记录、文件、diff、产物和历史都保存在同一个上下文里。免费版仅本地运行，适合已经有多个 Agent 订阅的个人开发者。

API Gateway

OmniRoute：用 TypeScript 写的免费 AI 网关

OmniRoute 是一个用 TypeScript 编写的开源 AI 网关，提供单个本地端点 /v1 聚合 237 个 AI 提供商，其中 90+ 提供免费额度。核心特性是四层自动回退（订阅 → API Key → 便宜 → 免费）和 17 种路由策略，并通过 RTK + Caveman 堆叠压缩 token，号称可节省 15–95% 的 token 消耗。如果你需要在一个项目里同时对接多个模型厂商并希望自动 failover，可以部署试用。

实践指南

Best Practice

用户不需要更多工具，需要更好的无缝集成

Smashing Magazine 的一篇文章提醒开发者：大多数用户并不想要又一个“改变一切”的新工具，他们想要的是能力被无缝集成到已有工作流中，解决高频、高痛、高严重性的问题。文章区分了“AI-First”和“Quiet AI”：前者把 AI 当作产品核心卖点，后者把 AI 当作底层能力，让用户几乎感觉不到它的存在。

这对正在做 AI 产品或内部工具的开发者是一个重要提醒：与其追求一个全能的 Chat 界面，不如把 AI 能力嵌入到用户已经熟悉的终端、IDE、表单、审批流和通知系统里。MFS 把多源数据变成文件系统路径、Browser Use 把浏览器操作变成 Agent skill、video-use 把剪辑变成 Claude Code 命令，本质上都是在做同一件事——降低上下文切换成本。

今日实践 checklist：
  • 给你的 Agent 项目写一份 spec.md，让目标、边界和验收标准先落地。
  • 把 AI 能力从“独立聊天窗口”迁移到用户已有的 IDE / CLI / 工作流中。
  • 为 Agent 增加可观测的 checkpoint：每个关键步骤都能被审查、回滚和验收。
  • 优先用文本化/结构化表示（如转写稿、AST、日志）替代原始多模态输入，降低成本并提升信噪比。

[来源: Smashing Magazine]
