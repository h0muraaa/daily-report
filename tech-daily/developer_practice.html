有开发者通读了 Claude Code 全部 51 万行源码，提炼出五条贯穿全局的设计原则：工具即能力边界（Agent 能做什么完全由工具集决定）、Fail-closed 安全默认、Context Engineering > Prompt Engineering、权限即 UX（每条工具调用都有独立的权限确认 UX）、以及 React 终端渲染引擎的自研 Fork。

模块规模上，utils 占 35%（权限、bash 安全、git、MCP 等基础设施），components 占 16%（React 终端 UI），tools 占 10%（40+ 工具实现）。对想自建 Coding Agent 的开发者来说，这是目前最完整的架构参考。

OpenRouter 推出 Response Caching：测试和 Agent 重试的省钱利器

OpenRouter 正式上线 Response Caching 功能，免费可用。开发者可通过 X-OpenRouter-Cache-TTL 头设置缓存生命周期（1 秒到 24 小时，默认 5 分钟），用 X-OpenRouter-Cache-Clear 清除特定条目。缓存按 API Key 隔离，命中缓存的请求不会消耗提供商的速率限制。

对于频繁运行测试、Agent 反复重试相同请求的场景，这个功能能显著降低 token 开销和延迟。同时 OpenRouter 还推出了 -latest 模型别名（如 ~anthropic/claude-opus-latest），自动路由到各厂商最新版本模型，省去手动追踪版本号的麻烦。

DeepSeek V4 的"系统级耦合优化"意味着什么

DeepSeek 从 V2 的 MLA（Multi-head Latent Attention）到 V4 的 mHC，标志着一个重要转变：单点创新已经见顶，真正难的变成系统级耦合优化。用 UCLA 博士刘益枫的话说，"系统级耦合优化比单点创新更难"。

关键变化：
- V4 弃用 MLA，采用全新的 mHC 注意力机制，与 DeepSeek-ViT 视觉编码器和 CSA 机制深度耦合，实现 7056 倍视觉 token 压缩率。
- 对北大团队开源的 TileLang 深度使用，说明国产开源工具链正在进入大厂核心生产路径。
- 围绕 Muon 优化器的改进竞赛（字节 Seed -> DeepSeek -> Kimi）展现了开源社区的正反馈循环。
- 代码能力仍弱于 Opus 4.6 等闭源模型，但幻觉率大幅下降，这对生产环境的 Agent 部署是更务实的指标。

对于后端/Infra 开发者，V4 的技术报告提供了一个观察中国开源模型生态演进的最佳切片。相比"哪个模型更强"，更值得跟踪的是这些团队如何在系统层面做取舍：什么时候用稀疏化、什么时候做量化、如何把推理框架（如 SGLang）与模型设计协同优化。

架构 [来源: 晚点LatePost]

Claude Code 源码揭示的 Agent 工程范式

51 万行代码的 Claude Code 被完整拆解后，最值得关注的是它的工具-权限-UX 三位一体设计。每个工具都有明确的并发安全声明（isConcurrencySafe）、只读声明（isReadOnly）和权限确认 UX。这不是安全补丁，而是架构核心——Fail-closed 默认策略意味着所有安全相关的默认值都是最保守的。

可复用的设计原则：
1. 工具即能力边界：Agent 能做什么完全由工具集决定，新增能力 = 新增工具，没有后门。
2. Context Engineering > Prompt Engineering：与其花时间在 prompt 调优，不如把上下文结构做好。
3. 自研终端渲染引擎：Claude Code 没有依赖现成的 TUI 库，而是 fork 了 Ink 并深度定制，这说明复杂 Agent 的交互层需要高度定制。
4. bridge 模式：支持远程控制（本地机器作为 bridge 环境），12,613 行代码专门处理这个场景——Agent 的远程执行是真实需求。

如果你正在考虑自建 Coding Agent，建议直接对照 Claude Code 的模块划分来审视自己的架构：utils（基础设施）> components（UI）> services（API/MCP）> tools（工具实现）> commands（斜杠命令）。这个分层不是随意的，而是反映了 Agent 系统的真实依赖关系。

实践指南

Codex Computer Use 的正确打开方式

Computer Use 不是万能药，它的价值在于填补"结构化集成无法覆盖的 GUI 操作"。两条核心原则：

  1. 优先层级：本地 Web 应用优先用 Codex 自带的 in-app browser；目标应用有 plugin / MCP server 时优先走结构化集成；Computer Use 仅用于必须"视觉操作"的场景（如点 UI 改设置、跨多个 GUI 应用协作）。
  2. 自闭环验证：让 Agent 能自己验证自己的修改是 Computer Use 最有价值的用法——"操作 -> 改代码 -> 再跑同一流程"。

权限方面，macOS 系统权限（Screen Recording + Accessibility）和 Codex 内部权限是两层独立的系统。前者决定能不能感知/操作 GUI，后者决定能执行哪些操作。建议在生产环境中对内部权限做严格收敛。

AI CODING [来源: meng shao(@shao__meng)]
Skills 工程化：从 Prompt 玩具到可执行协议

当前市面上大量"Skill"本质上还是角色扮演 prompt 的变体。真正的 Skill 工程化应该把领域内的隐性经验、边界条件、工具链、失败处理、验收标准压缩成 Agent 可以稳定调用的可执行协议。

关键区分：
- ❌ 伪 Skill：换个语气说话、存一段 prompt、套一层人设
- ✅ 真 Skill：封装能力、约束、脚本、参考资料、验收规则和修复策略的可组合执行单元

传统 workflow（n8n/Zapier）擅长确定性链路，但遇到需要理解上下文、动态决策、局部修复的场景就会变成巨型流程图。Skills 的优势在于保持模块化的同时允许 Agent 动态决策——不是把流程画死在节点图里，而是把能力封装成可组合单元。

对于正在构建 Agent 系统的开发者，建议把 Skill 设计成"有输入契约、有输出校验、有失败回退"的三段式结构，而不是一段自由的 prompt。
