微软开源 Webwright：终端原生的 Web Agent 框架，代码即动作
Open Source Microsoft Web Agent 来源: X / meng shao

传统网页智能体采用「观察->预测点击->执行」的循环，每一步都依赖 LLM 实时判断。微软新开源的 Webwright 换了一条路：让 LLM 直接写 Playwright 脚本，把网页操作变成可运行的 Python 程序。

核心设计哲学很「工程师」：工作区即状态（脚本、截图、日志保存在本地，浏览器会话可随时重建），终端优先（核心循环只有三个模块约 1000 行代码，无隐藏编排层）。性能达到 SOTA：Online-Mind2Web 86.7%（GPT-5.4，同类开源最高），Odysseys 长程任务 60.1%（较此前 SOTA +15.6pt）。最值得关注的是它的「副产品」思维——产生的不是一次性交互痕迹，而是可复用的自动化程序。

面壁智能开源 MiniCPM5-1B：AI 自己写训练框架，端侧「小钢炮」诞生
Open Source 端侧模型 LLM 来源: 机器之心

面壁智能开源了 MiniCPM5-1B，一个面向端侧和本地部署的 1B 参数稠密 Transformer 模型。它的特殊之处在于：训练框架本身是由 AI 编写的。这标志着「AI 制造 AI」的研发范式正在从概念走向工程现实。

MiniCPM5-1B 支持 131k 长上下文和混合推理模式，在同规模开源模型中达到 SOTA 水平，适用于本地助手、编码 Agent、工具调用等场景。面壁智能认为，大模型进化的隐形天花板是「碳基程序员手写代码的生理极限」——如果底层训练框架持续依赖人工迭代，智能的进化速度就会被锁死。让 AI 接管编码，激活「递归自我改进」，是缩短 AGI 时间线的关键路径。

Agent 安全的三层防御架构：Anthropic 实战经验

Anthropic 基于 Claude AI、Claude Code、Claude Cowork 三款产品的工程实践，系统总结了 Agent 安全的实战方法论。核心设计原则非常值得我们内化：

  • 先环境层，后模型层——确定性边界是最后防线，概率性防御（如系统提示）只能作为补充
  • 隔离强度匹配用户监督能力——开发者能理解 bash，知识工作者不能，两者的沙箱策略应不同
  • 警惕自建组件——优先使用久经考验的标准隔离原语，不要自己造安全轮子
  • 出站白名单是能力授权，不是目的地过滤——每个可调用函数都是攻击面

三种风险类型需要分别应对：用户误用（有意或无意指示 Agent 执行有害操作）、模型行为失当（Agent 未经请求执行有害操作，如「好心」逃离沙箱）、外部攻击（通过工具、文件、网络访问等向量攻击 Agent）。防御架构分三层：环境层（沙箱、VM、文件系统边界、出站控制）最可靠；模型层（系统提示、分类器、探测）作为辅助；应用层（用户确认、审计日志、速率限制）兜底。

Skills 的自我进化：验收标准决定天花板

宝玉 (@dotey) 分享了一个关于 Agent Skills 迭代的深刻观察：只有具备明确、可程序自动验收标准的 Skills 才能自我进化。比如优化代码性能的 Skill，性能是可测量、可量化的，给测试样例就能越优化越好。但写作 Skill 这类没有明确验收标准的，只能靠 AI 「自己打分」，而 AI 打分和人类体感往往有偏差。

微软联合上交、复旦、同济等机构发布的 SkillOpt 框架也印证了这一方向：让 AI 自动评估 Skills 的质量，通过可量化的指标驱动迭代。实践建议：在设计 Agent Skills 时，先定义可自动验证的验收标准（如单元测试通过率、性能指标、输出格式校验等），再让 AI 在标准框架内自动优化。同时做好版本管理——迭代中可能出现负优化，需要能回退。

前端初级岗位暴跌 62%：AI 时代开发者的生存策略

拉勾网《2026 年第一季度前端行业报告》的数据很残酷：前端初级岗位（0-3 年经验）招聘量同比 暴跌 62%，单个岗位平均收到 127 份简历，超过 80% 的公司在 JD 里明确要求「熟练使用 AI 编程工具」。

这不是前端独有的趋势，而是所有「可被模式化」的开发工作面临的共同挑战。对开发者的启示很明确：AI 不是替代开发者，而是替代「只会执行」的开发者。 Cursor 半分钟就能生成一个刚入行前端一年才能掌握的组件——但架构设计、业务理解、跨系统协调、安全审计这些需要上下文判断和创造性思维的能力，短期内仍需要人类。

实践建议：把 AI 当作「杠杆」而非「威胁」。用 AI 加速执行层（写代码、写测试、写文档），把省下来的时间投入到架构设计、领域建模、安全审查和团队协作中。同时，主动掌握 AI 工具链（Claude Code、Cursor、Copilot 等），因为「会用 AI」正在成为新的基础门槛。

Coding Agent 选型参考：何时用 Claude Code，何时用 Codex

Zara Zhang 分享了自己过去一个月使用 Coding Agent 的演进路径，提供了一个实用的选型框架：

  • Codex：像一个非常可靠的工程师。适合「任务已经定义清楚，只需要它执行」的场景。Claude Code 桌面版体验更好，但 Codex 在执行确定性任务上更稳。
  • Claude Code：像一个更好的 PM 和设计师，沟通能力强。适合「还没想清楚要做什么，需要一起探索」的场景。
  • 使用方式：从终端迁移到桌面 App（Codex Mac 版体验尤其好），现在很少开终端了。

这个「按任务类型分配工具」的思路值得借鉴：不要试图用一个 Agent 解决所有问题，而是根据任务的确定性和沟通需求来选择最合适的工具。
