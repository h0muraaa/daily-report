Anthropic 电商 Agent 架构复盘：为什么「单 Agent + Skills」胜过子智能体

从开源 Commerce Agents 参考实现，拆解多意图业务 Agent 的真实工程取舍

一个反直觉的结论

Anthropic 在零售、旅行、电信、票务等企业场景落地后给出一个与主流直觉相反的结论：电商对话应该用「单 Agent + Skills」，而不是拆一堆子智能体（Subagents）。原因是电商对话是跨多意图、紧耦合的单一会话——购物车、偏好、历史必须全程共享。每一次移交给子智能体都是一次「有损状态传递」：多耗数倍 token、增加数秒延迟，还可能丢上下文。Anthropic 在多个部署对比中发现，单 Agent + Skills 在质量上持续优于「一个大 prompt」与「子智能体」两种方案，且成本与延迟通常更低。

子智能体只在两种情况下合理：一是作为工具调用的、自包含的深度研究任务；二是已有独立合规面的专属 Agent（如药房、金融），此时本质是「移交对话所有权」而非「委派」。

System Prompt 与 Skill 的划分阈值

官方给出的经验标准是「按使用频率划分」：约三分之一以上流量会用到的逻辑放 system prompt，其余拆进 skill。安全、法律、品牌约束与用户关键事实（如过敏史）则永远放 system prompt 或上下文顶部，不能被 skill 延迟加载。

参考实现里有什么

  • 两个 Agent：Shopping Agent（消费者导购）与 Merchant Agent（商家运营后台）
  • 10 个 Skills：两个 Agent 各 5 个，覆盖搜索、购买研究、客服、个性化、经营分析、库存、定价促销等
  • 4 个可运行行业示例（零售 ACME / 旅行 / 电信 / 票务），含消费者前台与商家后台
  • 3 种运行方式：Messages API、Claude Agent SDK、Claude Managed Agents
  • 7 个本地 Python 包、8 个 Web 应用、共享后端接口与前端组件、测试与部署脚本
  • Claude Code 插件 commerce-builder：/scaffold-commerce-agent、/add-commerce-flow、/author-commerce-evals、/review-commerce-agent

给你的落地建议

如果你的业务 Agent 是「多意图 + 单会话」形态（导购、客服、助手），先别急着拆子智能体，按「system prompt 放高频约束 + skills 放低频能力 + 少量工具型子智能体做深度研究」来组织，并把 Evals 当作一等公民（用 /author-commerce-evals 这类工具持续沉淀）。

同一个 Bug、同样修复，为什么有时贵好几倍？拆解 Claude Code 的成本模型

读完官方《Maximizing the value of your Claude Code sessions》，你按 /clear 和 /compact 的手会更勤

Anthropic 官方博客近期系统讲解了 Claude Code 的 token 成本结构。对天天跑 Agent 写代码的开发者，这是最直接的省钱攻略。

一个 token 的价格由什么决定

  • 模型：不同模型单价不同，effort 档位影响单次思考量
  • 输入 vs 输出：输出（decode）定价约为输入（prefill）的 5 倍，这是最大的成本杠杆
  • 提示缓存：命中缓存的前缀按低价计费；任何前缀变化都会让缓存 miss，整段前文重新按 prefill 计费

一个会话实际发送多少 token

核心认知是：没有任何东西只发送一次。上下文里的文件、工具结果、历史消息在每一轮都会被重新发送，回合越多、上下文越臃肿，开销指数级上涨。Subagent 拥有独立上下文，任务开始前需要重新交代子任务上下文——token 消耗更大，但若换成更便宜的模型，总价未必更贵（选择取决于任务与模型价差）。

优先检查这四处

  • 会话拖得太长而没有清理
  • 上下文塞了太多与当前任务无关的内容
  • 模型或 effort 高于任务所需（用 medium/low 平替）
  • 反复打破提示缓存前缀（例如随手改前文、乱序引入文件）

落地操作：勤用 /clear 与 /compact 压缩历史；用 @-mention 精确引入文件而非整目录；避免原地删改已发送的上下文；提示词里显式要求局部编辑、非破坏操作一气呵成。社区解读还强调：prefill/decode 的 5 倍价差意味着「少发无用的输入」与「减少重复输出」同样重要。

zg (zvec-grep)：给开发者和 Agent 的本地优先语义搜索

阿里 Zvec 团队开源的本地优先搜索工具，把语义检索、BM25、混合检索（RRF 融合）与 ripgrep 精确匹配收进同一个 CLI/MCP 入口。Agent 想查「恢复主题偏好」时不必反复猜词（对应实现可能叫 hydratePreferences），一次调用即可收敛。结构感知抽取按符号/章节切分内容、默认内置 11 个本地 Embedding 模型（默认模型仅约 32 MiB、无需 GPU），Django 仓库 3457 个文件在 M4 Pro 上索引不到 30 秒。zg install 可自动发现 Codex、Claude Code 等，零配置接入。

Weaviate 1.38 Boost API：Filter 排除，Boost 重排

新版本引入查询时重打分 API：当硬过滤条件太严格时，用 Boost 把「in_stock=true」这类条件从「剔除结果」改为「加权排序」——有货的排前面，同时保留其他相关结果。支持过滤条件、数值属性、时间衰减（recency）与目标值数值衰减，最多混合 20 个条件，还可用负权重降权而不排除。Boost 只对主检索召回结果重排，用 depth 参数控制候选规模。适合「宁可多召回、再精细排序」的生产搜索场景。

Anthropic 官方「去 AI 味」提示指南 + Fable 5.1 十六问

Anthropic 发布了一份针对 Fable 5.1 的官方提示指南，涵盖 16 条建议与避坑清单，核心诉求是「让 Claude 说人话」：在 system prompt 直接声明 Remove all mannered prose. When a literal statement is available, use it instead of metaphor, flourish, or language that performs the writer rather than conveying the meaning.（删除矫饰性表达，能直说就直说，不要用隐喻和漂亮话）。其他高频建议：算力档位默认 high，medium 可平替上一代且更便宜，low 甚至能越级；代码/电脑操作中先规划依赖、无依赖的工具一次性并发打出；给复杂任务立规矩——「非破坏性操作直接一口气跑完」防止半途求批准；上下文别原地删改前文，多用单轮即弃的系统消息；约束模型不要顺手改需求外的旧 Bug，文件修改优先局部编辑。

用 /claude-api 给你的 Agent 项目做「API 成本体检」

Anthropic 开源了一个内置到 Claude Code 的 skill——/claude-api，覆盖 Python/TypeScript/Java/Go/Ruby/C#/PHP/cURL 八种语言与 Messages API、Managed Agents 两个开发面。两个高频子命令值得立刻上手：cost-optimize 会分析项目实际的 API 用量模式，按优先级给出可逐条批准/跳过的省钱建议（缓存配置、token 冗余、批量机会、effort 档位与模型选择）；prompt-audit 扫描项目里的提示词与 skill，找出针对旧模型编写的冗余规则——如果你正试用 Fable 5.1，官方建议先跑一遍 prompt-audit 清掉过期约束。它本质是一组结构化参考文档 + 工作流指令，让模型在写代码时有准确的 API 知识。

GitHub Copilot app 并行跑多个 Agent：worktree 隔离工作流

在同一个项目里同时跑多个 AI Agent 看起来很混乱，但 GitHub Copilot app 让这些 agent session 互不干扰：每个 session 是一个独立任务，运行在各自的 git worktree 里，拥有独立上下文——就像同时开多台洗衣机，各自设好参数、互不影响，也不必等一台洗完再开下一台。实践上可以把一次大型重构拆成多个并行 agent session（一个加测试、一个改实现、一个写文档），最后统一 review 合并。

快手电商 Harness Engineering 复盘：工具提效 ≠ 组织提效

一个值得所有技术管理者警醒的数据点：快手电商商家团队 2026 年 1-4 月强推 AI 工具渗透，人均周 token 消耗达到「大几千万」，人均代码量增加 170%，但平均需求交付时长几乎没变。复盘结论是：AI 工具只放大个体，组织提效需要流程级重构，否则「个人效率翻倍、组织效率原地踏步」。他们随后把 OpenSpec（定义一次任务要做什么）、Harness（让 Agent 在工程上下文与执行约束下完成任务）、Memory（把一次任务中的工程判断沉淀到下一次）组织进同一条任务闭环，让 AI 从「写代码」升级为参与「需求→实现→验证→知识沉淀」的完整链路。想在公司推 AI Coding 的同学，值得先读这篇再决定买多少工具。
