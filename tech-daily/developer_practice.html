协议/开源

OpenAI 开源 MRC 协议：训练 ChatGPT 所用的网络协议正式对外开放

OpenAI 发布了 Multipath Reliable Connection (MRC) 协议——这是支撑其最大规模超算集群训练的关键网络层。MRC 是一种全新的开源网络协议，专为大规模 AI 超算设计，解决多路径可靠连接问题。该协议已在 OpenAI 所有最大超算集群上部署，并与 AMD、Broadcom、Intel、Microsoft、NVIDIA 等合作发布。对于基础设施工程师而言，这意味着可以借鉴 OpenAI 在万卡集群网络同步方面的工程实践，对于需要构建大规模分布式训练环境的团队极具参考价值。
📎 来源: Greg Brockman(@gdb)
AI Agent

Claude Managed Agents 四大新功能：Dreaming、Outcomes、多智能体编排、Webhooks

Anthropic 在 Code with Claude 大会上发布了 Claude Managed Agents 的重大更新。Dreaming 功能能够回顾 Agent 的历史会话，提取模式并整理记忆，使 Agent 随时间学习改进；Outcomes 允许设置质量评分标准，Agent 会迭代直到通过；Multiagent Orchestration 让主 Agent 可以并行委派给多个专业子 Agent；Webhooks 支持外部事件触发。这些功能标志着 Agent 从'单次执行'向'持续进化'的范式转变，对于构建生产级 AI Agent 系统的开发者来说，这是必须关注的里程碑。
📎 来源: Ado(@adocomplete)
IDE

Cursor 3.3 发布：Agent 上下文用量可视化 + 动态上下文减少 46.9% Token 消耗

Cursor 3.3 带来了两项核心改进：首先是 Agent 上下文用量的可视化分析面板，可以按 rules、skills、MCPs、subagents 等维度诊断上下文占用情况；其次是动态上下文（dynamic context）机制，不再将所有 MCP 工具 upfront 加载到上下文中，在使用多个 MCP 服务器时减少 46.9% 的总 Token 消耗。这是 Cursor 在 Agent 可观测性方面的重要进步，帮助开发者理解'为什么我的 Agent 突然变慢/变贵'这一常见问题。
📎 来源: 宝玉(@dotey)
API

Firecrawl 推出 Question 格式：向任意网页提问，Token 消耗降低 100 倍

Firecrawl 发布了 /scrape 端点的 Question 格式新功能——开发者可以直接向任意网页提问，获取高质量、无幻觉的 grounded answer，Token 消耗降低多达 100 倍。这直接替代了传统的 scrape → chunk → embed → retrieve 循环，特别适合需要精确答案且不膨胀上下文窗口的 AI Agent 场景。典型用例包括：从 API 文档中获取 rate limit 信息、从定价页了解公司方案、从供应商网站获取支持 SLA。
📎 来源: Firecrawl(@firecrawl_dev)

推理引擎

TokenSpeed 开源：速度级 LLM 推理引擎，Blackwell 上最快 MLA Attention Kernel

LightSeek Foundation 发布了 TokenSpeed——一个专为极速 Agent 工作负载设计的 LLM 推理引擎。它在性能上达到 TensorRT LLM 级别，在易用性上达到 vLLM 级别，由一支精干团队在两月内构建完成，采用 MIT 许可证开源。核心特性包括：先进的 KV Cache 管理、安全高效的调度器、可插拔分层内核系统（支持多厂商芯片），以及目前在 NVIDIA Blackwell 上最快的 MLA Attention Kernel。对于需要在自托管环境中追求极致推理性能的开发者，这是一个值得关注的新选择。
📎 来源: Justine Moore(@venturetwins)
推理引擎

Perplexity 开源 ROSE 推理引擎：自研 Runtime-Optimized Serving Engine 详解

Perplexity 在官方研究博客中详细介绍了其自研推理引擎 ROSE (Runtime-Optimized Serving Engine)。该引擎支撑了 Perplexity 从 embedding 到 text generation 的几乎所有生产流量。ROSE 的核心创新在于针对实际生产负载的 runtime 优化，包括高效的批处理策略、动态调度机制和内存管理优化。Perplexity 还开源了相关的研究细节，这对于想要理解'如何从零构建生产级推理服务'的开发者是一份宝贵的工程资料。

API

Gemini API File Search 支持多模态检索：单接口实现 PDF + 图像 RAG

Google Gemini API 的 File Search 工具现已支持多模态检索，开发者可以使用 gemini-embedding-2 作为 embedding 模型来构建真正的多模态 RAG 系统。流程极为简洁：创建存储库（自动处理分块和索引）→ 上传文档和图像 → 调用 file_search 工具 → API 自动完成 embedding、检索并生成 grounded response。每份响应都包含引用元数据（页码和可下载的图像引用）。值得注意的是，存储和查询时的 embedding 都是免费的，仅收取索引 embedding 和标准推理 Token 费用。

最佳实践

一个文件让 AI Coding 效率翻倍：AGENTS.md 实践指南

阿里云开发者社区分享了一个简单但极其有效的实践：在项目根目录放置 AGENTS.md 文件，向 AI 编码助手传递项目特定的上下文信息。这个文件可以包含：项目架构概述、编码规范、常用命令、测试策略、部署流程等。实践表明，一个结构良好的 AGENTS.md 能将 AI 生成代码的准确率提升 40% 以上。文件格式建议采用 Markdown，按模块组织，避免过长（建议控制在 500 行以内，配合 Cursor 3.3 的上下文分析来优化）。这是目前成本最低、见效最快的 AI 编码提效手段之一。

架构

2026 年 Subagent 的四种管理模式：主 Agent 如何有效驱动子 Agent

Philipp Schmid 总结了主 Agent 驱动子 Agent 的四种管理模式，按主 Agent 对子 Agent 的控制程度排序：(1) 直接调用模式——主 Agent 直接调用子 Agent 的函数，适合简单任务链；(2) 委托模式——主 Agent 将任务委托给子 Agent 并等待结果，适合中等复杂度；(3) 监督模式——主 Agent 持续监控子 Agent 的执行过程，可以中途干预，适合长时任务；(4) 编排模式——主 Agent 并行调度多个子 Agent，动态分配任务，适合复杂多步骤工作流。文章还讨论了每种模式的适用场景、错误处理策略和性能权衡，对于设计多 Agent 系统的开发者是极好的参考。
📎 来源: meng shao(@shao__meng) · Philipp Schmid
