# Agent 的命门是上下文：记忆工程与缓存成本工程

四篇内容指向同一个结论：当 Agent 从一次性工具走向长期开发，真正稀缺的不是"生成代码的能力"，而是"上下文与记忆的治理能力"。

成本真相：一个中等需求吃掉 2480 万 token / 202 元

  • 腾讯云开发者实测：把"给 skill 详情页加评论区"（涉及十几个文件）交给多 Agent 工作流，整条流程消耗约 2480 万 token、成本约 202 元——即使已接入 CodeGraph（代码地图，先圈出相关文件）和 RTK（终端摘要器，压缩搜索/测试/日志输出）两个优化。
  • 作者结论："关键不在少给，而在给对"——上下文工程不是压缩，而是精准路由与按需加载。

缓存经济学：一个"hi"为什么值 1 美元

  • Arena.ai 用"喝完咖啡回来说句 hi 花掉 1 美元"解释 Agent 计费陷阱：你为上一轮全部上下文付费，缓存命中约全价 10%，一旦缓存冷却（离开一小时）就按全价 prefill 重算，成本随上下文长度"平方级"增长。
  • 工程含义：长会话设计必须考虑缓存亲和——保持前缀稳定、避免频繁切换模型/思考档位、谨慎 compact。

团队记忆：从 60% 到 80% 完成率

  • 腾讯 TencentDB Agent Memory 把任务轨迹、项目知识、代码结构沉淀为"可治理的记忆资产"，在 SWE-bench 相关任务上把完成率从 60% 提升到 80%，Top 50 超长难任务成本降低 19% 且成功率提升。
  • 核心做法："前序 Case 学习、后序 Case 验证"，从 2,600 个 Session、真实研发 Case 与访谈中校正产品设计。

长期记忆产品化：让 Coding Agent "记住过去"

  • 机器之心报道 MemoraX Code，直指痛点：Agent 越来越会写代码，却常常"像第一次来到这个项目"——换模型、上下文被压缩后，会重扫代码、重复提失败方案、重新调查已排查问题。
  • 解法是把"项目经验"（为何采用当前架构、哪些历史代码不能动、哪个方案被放弃、数据库升级兼容约束）变成可复用的长期记忆资产。
实践要点：上下文治理 = 精准路由（该给什么）+ 记忆沉淀（记住了什么）+ 缓存友好（别击穿缓存）。三条腿缺一不可。

# AI 写的代码谁来看？代码审查的"死亡"与质量护栏重建

AI 生成代码占比上升后，"人逐行审阅"的旧契约正在瓦解，行业在重新设计质量护栏。

审查已死？先看数据

  • Aviator 的 Ankit Jain：超过 30% 的变更已完全无人审查，需要审查的等待时间是过去的 4 倍。典型流程变成：AI 写代码、AI 审代码、来回在 Web UI 里博弈，人类扫一眼对话就合并。
  • 他的判断："当 AI 审查且无人阅读时，我们配置错了对象"——审查的价值在于人脑的理解与判断，不是流程形式。他也修正了自己几个月前提出的"五层信任模型"，承认遗漏了关键环节。

人该盯住什么：软件工厂的取舍

  • Addy Osmani：产品意图、系统设计、质量标准（quality bar）仍需人类前置决策；审查要有选择地用在不同场景；警惕自动化"背压"（back-pressure）失效点与可维护性 trade-off。
  • 质量检查应尽可能早且持续：类型系统、自动化测试、mutation testing……不必全部靠审查兜底。

四阶段演进与五条原则

  • 京东技术拆解 AI Coding 从"补全工具 → 对话副驾 → 流程协作者 → 共生体"的四阶段，提出"需求分治"——让 AI 参与架构级拆分，把人从"写代码"顶到"定规则、做裁判"。
  • 沉淀五条可跨工具迁移的底层原则：验证成本、约束设定、置信度分流、批判性审验、知识沉淀。

QA 左移：spec 强化阶段

  • Stack Overflow 采访 Motorola Solutions 测试工程负责人：用 Cohen's kappa 评估"多个 LLM-as-judge"的一致性，并在设计阶段后加一个"spec 强化（specification enrichment）"阶段来提升需求质量——把测试思维前移到需求生成。

踩坑记录Linux

翻车复盘：把 Linux 页大小从 4KB 换成 2MB 大页，性能不升反崩

一位工程师把系统默认 4KB 页全盘替换成 2MB 大页，上线后 CPU 软中断飙升、接口随机抖动、整机内存暴涨 30%、线上崩盘，回滚排查花了一整天。根因：大页通过减少地址翻译开销、提高 TLB 命中率获益，但收益极度依赖业务场景（大内存密集、高并发访问模式）；常规线上业务保持默认 4KB 反而最稳。核心结论：所有性能参数都是 trade-off，没有万能优化，只有适配场景的优化。

Agent 安全零信任

Agent 安全护栏合集：Deno Claw Patrol / Google zero-trust ADK / Vercel / Replit

当 Agent 被授予生产权限，安全就不能靠"模型保持听话"这种 wishful thinking。四条实战路径：① Deno 的 Claw Patrol——给事故响应 Agent 生产 Postgres/K8s/ClickHouse/AWS/GitHub/Slack 读写权限后，Agent 能关闭原本要叫醒人类的 incident；但护栏不能住在 Agent 内部（Agent 是不受信任的软件），必须外置。② Google ADK 的 zero-trust 架构——数据库写入用硬件背书签名、动态代码跑在 gVisor 内核级沙箱、I/O 过确定性语义网关。③ Vercel 悬赏 100 万美元 公开测试 Sandbox 沙箱逃逸，承认"没有网络边界的沙箱只是半个沙箱"。④ Replit 上线黑盒渗透测试——按外部攻击者方式扫描，Replit Agent 一键修复。统一结论：审计 + 权限最小化 + 沙箱 + 网络隔离，缺一不可。
