社区开发者总结了一套Claude Code高效工作流，核心原则是Plan → Execute → Review循环：

/claude plan "你的需求描述"

# 2. 创建CLAUDE.md项目规范文件
- 项目架构决策
- 代码风格指南  
- 常用命令
- 过去踩过的坑

# 3. 上下文管理组合拳
/compact  # 总结关键点
/clear     # 清空上下文
# 然后把总结+必要文件粘贴回去

# 4. 复杂任务拆解
# 拆成sub-tasks，每步独立规划
# 别一次性让Claude改太多文件

🤝 AI编程的协作范式转变

从"交替协作"到"协同创作"

  • 旧范式：先想清楚需求 → 写代码 → 测试 → 发现不对 → 推倒重来
  • 新范式：想个开头 → 让AI快速做 → 看结果获取灵感 → AI输出带来新输入
关键洞察：AI打破了"信任危机"。以前想不清楚会浪费团队时间、降低信誉；现在可以用Token换验证想法，没有信任摩擦。

⚠️ AI编程的陷阱与避坑指南

  • Don't：把验证成本转嫁他人 — AI写PR自己不验证，把审查负担甩给maintainer
  • Do：Plan Mode先行 — 强制AI先规划，获得你的同意再执行
  • Do：维护CLAUDE.md — 记录项目规范、常见错误、架构决策
  • Do：定期/compact + /clear — 避免上下文爆炸导致Token浪费
  • Don't：闭眼粘贴AI输出 — 认真校对再发给客户/老板
