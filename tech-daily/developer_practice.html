🧠 GLM-5架构解析：从MoE到Agentic Engineering

技术背景 智谱GLM-5采用混合专家模型(MoE)架构，这是目前大模型的主流技术路线。与Dense模型相比，MoE通过稀疏激活大幅降低推理成本。

核心变化

  • 参数规模：355B → 744B (总参数)，32B → 40B (活跃参数)
  • 训练数据：23T → 28.5T tokens
  • 定位转变：从"Vibe Coding"到"Agentic Engineering"
  • 代码能力：SWE-Bench Verified 80.2%，接近Claude Opus 4.6

实践意义 对于开发团队，GLM-5提供了一个成本效益更高的代码助手选择。MIT许可证意味着可商用，无需担心法律风险。

迁移/使用建议：
  • 通过OpenRouter试用：openrouter.ai/z-ai/glm-5
  • 自托管：从Hugging Face下载完整权重(约1.4TB)
  • API调用：智谱官网提供标准OpenAI兼容接口
  • 注意：中文场景表现优异，英文场景建议对比测试

📎 来源：GLM-5技术博客

🤖 Claude Compaction：长对话Agent的上下文管理

技术背景 长对话Agent面临的核心挑战是上下文窗口限制。当对话历史超过模型上下文长度时，必须丢弃或压缩早期内容。

核心变化 Anthropic推出服务端Compaction功能，开发者只需设置token阈值，Claude自动处理上下文摘要。

// 伪代码示例
const response = await anthropic.messages.create({
  model: 'claude-opus-4',
  max_tokens: 4096,
  context_window_limit: 100000,  // 触发compaction的阈值
  messages: conversation_history
});
// Claude自动在服务端处理上下文压缩

实践意义 开发者无需自建复杂的摘要逻辑，降低了长对话Agent的开发门槛。

使用建议：
  • 适用于：客服机器人、代码助手、长期任务Agent
  • 阈值设置建议：设为上下文上限的80%
  • 注意：关键信息应显式保存到外部存储，不要依赖压缩

📎 来源：Claude平台文档

🔗 A2A协议：多Agent协作的技术标准

技术背景 不同框架构建的Agent通常无法直接通信，需要自定义集成。A2A(Agent2Agent)协议旨在标准化Agent的发现和通信机制。

核心变化 IBM的ACP协议正式并入A2A，Google、IBM、LangChain等共同支持。Andrew Ng推出官方课程教如何构建A2A多Agent系统。

实践意义 A2A有望成为Agent互操作的事实标准，类似于HTTP之于Web服务。

行动建议：
  • 关注A2A规范演进：github.com/google/A2A
  • 如果你正在构建Agent服务，考虑添加A2A接口
  • 学习Andrew Ng的免费课程了解最佳实践
