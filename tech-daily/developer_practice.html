AI Coding OpenAI工程师首次公开：如何榨干Codex的完整方法论
OpenAI Codex团队的Jason发布长文《Getting the most out of Codex》，系统分享了超越"写代码助手"定位的使用策略。核心要点有三：一是建立durable threads（长期线程），把重复工作沉淀为固定工作流，Codex能记住此前的决策、偏好和坑点，不用每次都重新解释项目背景；二是语音输入比打字更高效，自然语言描述需求让Codex自动拆解任务；三是把Codex放到更大的工作流里——从理解需求、查上下文、执行、预览、反馈到继续推进，形成闭环。文章强调Codex正从"帮你写一段代码"转向"帮你持续推进一个工作流"。

深度技术解读

Code-as-Agent-Harness：不碰模型，改造运行时

一篇新论文提出了"code-as-agent-harness"的核心思想：不要修改模型，而是修改包裹冻结LLM的运行时接口。将反复出现的交互失败转化为harness侧的可复用干预。实验结果显示，在7个确定性环境、126个模型-环境设置、18个backbone上，平均相对提升达88.5%。关键发现是：从一个模型轨迹学习到的harness可以泛化到17个其他backbone，说明harness捕获的是环境结构而非模型特定模式。
对生产环境部署Agent的开发者来说，这意味着你的harness工作比想象中更可迁移。与其针对不同模型调优prompt，不如投资构建一个能自动纠错、重试、转换格式的智能运行时层。
来源: elvis(@omarsar0)

SWE Atlas：AI编程基准从"补丁工"到"真工程师"的进化

Scale AI发布了SWE Atlas基准测试，首次系统评测AI在代码理解、测试编写、重构等核心工程能力上的表现。284道由资深工程师手写的考题中，前沿模型Pass@1最高仅43.49%，做三次能全对的比例骤降30%~50%。最扎心的发现：模型们写代码修bug的能力一骑绝尘，但在代码理解、测试编写、重构这些专业工程师真正在做的事情上几乎全员翻车。
这揭示了一个被忽视的问题：当前AI编程工具擅长"打补丁"，但不擅长"读代码"。真实工程工作流的起点是理解陌生代码库，而这点恰恰是现有工具最弱的环节。开发者在依赖AI生成代码的同时，更需要培养自己审阅、理解和验证AI产出代码的能力。
来源: 新智元

DeepSeek在官网、小红书、X同步放出招聘信息，组建全新的Harness团队，目标是从零开始构建对标Claude Code的代码智能体产品。招聘岗位包括"Agent Harness产品经理"和"Agent Harness研发工程师"，职位描述中明确写着公式：Model + Harness = Agent。团队定位是把DeepSeek的前沿模型能力转化为领先的Agent产品，除模型本身以外的所有工作都属于Harness范畴。这也呼应了Latent.Space的观察：所有模型实验室都在变成Agent实验室。

Codex优化网络速度：一个可复用的诊断提示词模板

社区分享了一个在Codex中优化网络速度和稳定性的提示词模板，采用"先诊断、再最小可逆修改、最后复测"的方法论。诊断阶段跑networkQuality、DNS查询、ping基准；优化阶段只做安全可逆修改（调整网络服务优先级、刷新DNS缓存、设置更快DNS）；复测阶段对比before/after数据。核心原则：需要sudo或影响VPN/远程连接的操作先说明风险，不强行执行。
来源: 向阳乔木(@vista8)

9-arm-skills：Claude Code的工程纪律模板集

GitHub上的9-arm-skills是一个小型Claude Code skill pack，聚焦工程纪律而非原始能力。包含多个实用模板：debug-mantra强制Agent在提出修复前先复现、追踪、证伪；post-mortem要求有真实复现、根因和验证修复后才写报告；scrutinize添加外部审查视角质疑变更是否必要；management-talk将工程细节翻译成管理层语言。适合团队建立AI辅助开发的规范工作流。
