AGENT-SYSTEM Agent 不只是模型：CMU/Yale 的 Harness Engineering 综述解读

CMU、Yale 等机构联合发布的 LLM Agent Harness Engineering 综述标志着行业共识的转移：Agent 的可靠性绝不能再只盯着模型本身。任何真正跑过长程任务的开发者都深有体会——Agent 崩溃往往不是逻辑推理失败，而是整个系统缺少稳定的运行时结构：

  • 遗忘当前任务主线
  • 将幻觉推理当作事实写入记忆
  • 调用破坏性工具后未同步更新世界状态
  • 致命误判后仍沿着错误因果链狂奔

这些系统级雪崩不是靠换千亿参数模型或塞进 1M Context Window 就能解决的。真正的工业级 Agent 是一个由模型、状态机、记忆流、执行沙箱、验证器、监控追踪和恢复策略共同构成的复杂操作系统。Harness Engineering 的兴起意味着 Agent 开发正在从"Prompt 工程"时代进入"系统工程"时代。

AI-DEV 为什么资深工程师反而更难构建 AI Agent？Google DeepMind 的五个范式转变

Google DeepMind 的 Philipp Schmid 提出了一个反直觉的观察：资深工程师在构建 AI Agent 时反而最容易踩坑，因为他们携带了多年的隐式上下文，而 agent 没有。他总结了五个必须接受的范式转变：

1. 文本替代结构化状态 —— agent 看不到你脑中的对象模型 2. 错误是输入而非重启触发器 —— 15分钟运行后的错误代价极高 3. 评估替代单元测试 —— 问"它有多可靠"而非"固定输入是否总产固定输出" 4. 为删除而构建 —— 更好的模型出来后你会重写整个 agent 5. deleteItem 端点对写它的人显而易见，但 agent 只能看到 schema 和 docstring

这五个转变本质上是在说：构建 agent 不是封装已有 API，而是重新设计人与系统的交互契约。
