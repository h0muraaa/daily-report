02 深度技术解读

AI Agent安全

为 AI Agent 构建一个安全的"沙盒电脑"

现代 agent 不只是调用 API，它们会写代码、运行脚本、处理文件、浏览网页，因此需要一个真正的运行时环境：文件系统、shell、已安装包、跨步骤持久化状态。但一旦赋予执行权限，模型生成的不可信代码、本地执行的可扩展性、凭证安全、成本控制和会话可重现性都会成为生产问题。

LangChain 的分享中提出了几条设计原则：把 agent 的运行环境放在隔离容器而非本地机器；使用最小权限的临时凭证，禁止长期访问令牌；为每个 agent 会话分配独立、可审计的资源配额；保留完整的执行日志以便事后复现。这些原则对任何打算把 coding agent 接入 CI/CD 或内部工具链的团队都适用。

实践要点：不要把 agent 直接跑在本地开发机或拥有长期凭证的服务器上；先用临时容器 + 短期 token 搭建最小可运行环境，并记录所有 shell 与文件操作。
来源：LangChain
AI Agent系统设计

Loop Engineering：让 Agent 在循环中持续改进

LangChain 将 "Loop Engineering" 定义为可靠 agent 系统的核心设计模式。它不只是简单的重试，而是围绕任务完成、结果验证、事件响应和自我改进构造多层循环。例如，一个代码 agent 可以先执行测试循环验证功能正确性，再进入评估循环检查性能回归，最后通过人类反馈循环修正边界情况。

实践建议是：先用 LangSmith 这类可观测性工具记录每次循环的输入输出，定位 agent 在哪个环节开始偏离目标；再把人类介入点设计在"高影响但低置信"的决策处，而不是每次循环都人工确认；最后把成功的循环路径固化为 benchmark，用于回归测试。

落地建议：从"单循环"开始——先让 agent 能可靠地完成一个小任务并自检；再逐步引入验证循环和反馈循环，避免一开始就设计过度复杂的 DAG。

AI 安全

Amazon Bedrock Guardrails 在代码生成工作流中的最佳实践

AI 编程助手通常以流式方式生成大量代码，组织需要确保不安全的代码模式被及时拦截。AWS 建议为代码生成场景单独配置 Guardrails：启用代码内容过滤器拦截漏洞模式；结合拒绝主题（denied topics）防止生成特定类别的代码（如加密绕过、社工逻辑）；在流式响应中实时评估而非等完整响应结束；最后通过 CloudWatch 和 invocation logs 持续审计误报与漏报。
