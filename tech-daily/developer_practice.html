B-Trees vs LSM Trees：数据库底层存储的两条路线

ByteByteGo 的这篇对比文章梳理了数据库在磁盘上组织数据的两种主导方案。B-Tree 家族（如 InnoDB、PostgreSQL）的核心优势是读取性能稳定和范围查询友好，每次写入都是原地更新，适合读多写少、需要强一致性的场景。LSM-Tree 家族（如 RocksDB、Cassandra）则通过顺序写入和分层合并来优化写吞吐量，代价是读取时需要合并多层数据，适合写密集型、可容忍最终一致性的场景。理解这两种存储引擎的 trade-off，是做出正确数据库选型和性能调优决策的基础。文章还提到了混合方案（如 WiredTiger 的 B-Tree + LSM 混合）以及在实际工程中的取舍考量。

深入源码：Hermes Agent 如何实现 "Self-Improving"

Hermes Agent 在 OpenRouter 排行榜上以 +204% 增速登顶 Coding Agents 榜首，GitHub Star 半年破 10 万。与 OpenClaw 的手写 Skill 不同，Hermes 的核心创新在于"自改进"机制：Agent 完成任务后，会自动把踩坑经验提炼成可复用的 Skill 文件，写入自己的知识库。这意味着系统提示词不会随着 Skill 数量线性膨胀，Agent 的能力边界可以持续扩展而不会退化。对于想要构建可持续进化的 Coding Agent 的开发者，这篇源码分析提供了具体的设计思路和实现路径。

Generic Agent：比 Hermes 省 10 倍 Token 的轻量 Agent 方案

Datawhale 开源的 Generic Agent（GA）针对当前 Coding Agent 的几个通病给出了方案：系统提示词吃掉几万 token、Skill 装多了就卡顿、教过的操作转头就忘。GA 的设计目标是用 2000 个 token 完成别人 20000 个 token 才能启动的任务。实现思路包括精简的系统提示词设计、按需加载的 Skill 机制、以及经验持久化存储。如果你在使用 Claude Code 或类似工具时被 token 账单困扰，这个项目值得一试。
