Gemini 3.5 Flash：不只是快，更是 agentic 编程的新基准

Google I/O 2026 上发布的 Gemini 3.5 Flash 可能是今年对开发者影响最大的模型更新。与 3.1 Pro 相比，它在几乎各项基准上都有提升，尤其在编程能力上进步显著，同时输出速度达到其他前沿模型的 4 倍。在 Antigravity 中进一步优化后甚至可达 12 倍速。

核心技术规格：

  • 上下文窗口：1M token，最大输出 65K token，可以一次性处理大型代码库
  • 思考层级：4 个级别（minimal / low / medium / high），medium 为新的默认值
  • 多轮对话：自动保留思考链（thought preservation），agent 可以记住之前的推理过程
  • 定价：$1.50/M input, $9/M output（OpenRouter 数据）
  • Code Arena 评分：1507 分，在 Frontend 编码任务中超越 3.1 Pro，较 3 Flash 提升 +70 分

目前已集成至 Gemini API、Google AI Studio、Android Studio、Antigravity、Gemini App 和 GitHub Copilot。开发者 Philipp Schmid 发布了迁移指南，推荐通过 npx skills add google-gemini/gemini-skills --skill gemini-interactions-api 安装 Interactions API Skill 后执行 /gemini-interactions-api migrate my app to Gemini 3.5 Flash 一键迁移。

Coding Agents 的可维护性传感器：Martin Fowler 团队的经验

Birgitta Böckeler 在 Martin Fowler 网站上发布了关于 coding agent "传感器" 的系列文章。她将 agent harness（引导 agent 输出质量的系统）类比为自动驾驶汽车的传感器网络——通过静态分析、代码 linting 等基础检查，在问题到达人类审查者之前实现自我纠正。

第一部分聚焦于基础代码 linting 作为最轻量级的质量守门人。文章提出一个核心观点：agent 生成的代码量越大，自动化质量检测的必要性就越高。这套方法不依赖特定 AI 工具，适用于 Cursor、Claude Code、Copilot 等任何 agentic 编码环境。建议将 linter 规则与团队现有代码规范对齐，避免 agent 引入风格不一致的代码。

AWS Bedrock Programmatic Tool Calling：告别串行调用的延迟噩梦

AWS 博客详细介绍了 Programmatic Tool Calling (PTC) 范式。传统 tool-calling 中，每次工具调用都需要完整的模型往返——模型调用工具、接收结果、推理、调用下一个工具，循环往复，延迟和 token 消耗随调用次数线性增长。

PTC 改变了这一模式：模型直接编写 Python 代码，在沙箱执行环境中以编程方式调用多个工具。代码可以包含循环、条件判断、过滤和聚合逻辑，中间结果无需回传模型。这种"代码即编排"的方式将多工具工作流的延迟从 O(n) 降低到 O(1)，特别适合需要多次数据查询和转换的复杂 agent 场景。

Databricks Unity Catalog：给 Agent 套上安全缰绳

随着 agentic AI 从实验走向生产，权限控制成为不可忽视的问题。Databricks 发布了 Unity Catalog 的 agent 安全能力，解决" rogue AI "（失控 agent）的风险。agent 连接到外部工具时，如果没有细粒度的访问控制，可能执行越权操作或泄露敏感数据。

Unity Catalog 的核心思路是将 agent 行为纳入统一的数据治理框架：每个 agent action 都经过权限校验，所有操作可审计追踪，敏感数据访问遵循最小权限原则。对于在企业环境中部署 agent 的开发者，这篇文章提供了一个安全 checklist 和架构参考。
