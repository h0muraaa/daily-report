Claude Cowork 重磅更新：电脑操控能力正式上线

来源: 宝玉(@dotey) | 发布时间: 2026-03-24

Anthropic 为 Claude Cowork 推出了一组重磅更新，核心能力包括电脑操控（Computer Use）、手机派任务（Dispatch）以及定时任务。Claude 现在可以像坐在你电脑前的助手一样工作：打开应用、操作浏览器、填写表格。

最实用的功能是"派活"模式：你在手机上给 Claude 布置任务，然后去忙别的，回来时电脑上已经有了完成的成果。Claude 还支持跨会话记忆，能记住你的工作习惯和偏好。定时任务功能允许设定每天早上扫邮件、每周五拉报告等自动化工作流。

关键细节：目前处于研究预览阶段，仅支持 macOS。Pro 用户（$20/月）和 Max 用户均可使用，但 Cowork 比普通聊天消耗额度更快。值得注意的是，Cowork 的对话记录存储在本地设备上，不在 Anthropic 服务器上。

Agent 授权

LangChain 详解 Agent 授权的两种模式

来源: LangChain Blog | 发布时间: 2026-03-24

LangChain 发布了关于 Agent 授权的深入文章，介绍了 LangSmith Fleet 中实现的两种授权模式：On-behalf-of（代表用户）和 As-a-service（作为服务）。

On-behalf-of 模式下，Agent 以用户的身份执行操作，权限受限于用户自身的权限范围。例如，当 Alice 与具有 Notion 和 Rippling 访问权限的入职 Agent 交互时，Agent 只能查看 Alice 在 Rippling 中的信息和她在 Notion 中有权访问的页面。

As-a-service 模式则允许 Agent 拥有独立的权限集，可以执行用户自身无法执行的操作。这种模式适用于需要跨用户边界访问数据的场景。

架构设计启示：在设计多 Agent 系统时，授权模式的选择直接影响系统的安全边界和可用性。建议在架构设计初期就明确每个 Agent 的授权模式。

Milvus 分享 RAG 优化实战经验：上游处理比换 LLM 更重要

来源: Milvus(@milvusio) | 发布时间: 2026-03-24

Milvus 团队分享了构建 Paddle-ERNIE-RAG 的实战经验，验证了在 RAG 系统中，上游文档处理比更换 LLM 更能提升效果。

关键优化点包括：使用 PP-StructureV3 输出结构化 Markdown 而非原始文本，保持表格完整性和标题语义；采用滑动窗口分块（sliding window chunking）配合重叠，避免句子在分块边界被截断；并行运行向量搜索和关键词搜索，使用 RRF（Reciprocal Rank Fusion）合并结果。

核心洞察：真正提升 RAG 效果的关键在于文档解析、分块策略、搜索和排序，而不是简单地更换更强的 LLM。

Agent 架构

Agentic RAG 工作原理深度解析

来源: ByteByteGo Newsletter | 发布时间: 2026-03-24

ByteByteGo 深入解析了 Agentic RAG 与传统 RAG 的本质区别。标准 RAG 是一个单向管道：查询 → 检索 → 响应，中间没有检查点，也没有第二次思考的机会。

而 Agentic RAG 在检索和生成之间增加了一个决策层：评估检索结果是否足够好，决定是否需要重新检索，或者采用不同的检索策略。这种"反思-行动"循环使系统能够自我纠正。

关键架构模式：

  • 查询重写（Query Rewriting）：让 Agent 优化检索查询
  • 检索评估（Retrieval Evaluation）：判断检索结果的相关性
  • 多步推理（Multi-step Reasoning）：复杂问题分解为子查询
  • 工具使用（Tool Use）：Agent 可以调用外部工具补充信息

Agent Skills 设计哲学与实战进化

来源: 宝玉(@dotey) | 发布时间: 2026-03-24

宝玉分享了其开源项目 baoyu-skills（已获 10K+ stars）的设计哲学和迭代方法论。核心观点包括：

1. 从提示词到 Skills：起步没有门槛，将已有的好用提示词、实践经验直接用 /skill-creator 变成 Skill，关键是动手。

2. 别做万能 Skill：Skill 要原子化，每个只做一件事。然后用 Skill 或 AGENTS.md 编排成工作流，让 Agent 灵活执行。

3. Skills 像随身小刀，越用越顺手：自己常用、遇到问题当场改、给 Agent 高质量对比样例让它自己优化、用 git 做版本管理。

4. 站在 Agent 角度设计：多存中间文件、先分析再执行、写清验证标准、用子 Agent 并行、脚本优先于 MCP。这些小细节决定 Skill 能否真正跑通。
