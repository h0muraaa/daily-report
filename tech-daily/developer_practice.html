今日技术热榜

Gemma 4 系列正式上架 Amazon Bedrock

Google DeepMind 的 Gemma 4 现已可在 Amazon Bedrock 调用，采用 Apache 2.0 开源权重，提供 31B Dense 以及 26B-A4B / E2B MoE 三种指令微调版本。它们支持内置推理、原生 Function Calling 以及文本+图像多模态输入，MoE 变体每次请求只激活部分参数。

对开发者来说，这意味着无需自己部署 GPU 集群，就能通过现有 Bedrock API 调用开源权重的前沿模型；在成本敏感场景下，MoE 也能提供更具性价比的推理路径。

Vercel Functions 最长运行时间延长至 30 分钟

Vercel 将 Node.js 与 Python Runtime 的 Function 最大执行时长从 800 秒提升到 30 分钟，Pro 与 Enterprise 团队可立即使用。这覆盖了长时 LLM 推理、文档/媒体处理、OCR、浏览器自动化以及复杂的 Queue/Workflow 步骤。

背后是 Vercel 自研的 Fluid Compute：代码执行时按活跃 CPU 计费，I/O 等待时暂停计费；开发者只需在 maxDuration 中显式开启即可。

[来源: Vercel News]

GitHub 发布多语言仓库开源数据集

GitHub 推出了 GitHub Multilingual Repositories Dataset，包含仓库级元数据，用于识别 README、Issue、PR 中包含非英语自然语言内容的公共仓库。数据集显示不同协作面的语言分布差异很大，例如韩语在 Issue 与 PR 中的占比高于 README。

这对训练更懂多语言开发者协作的模型、构建本地化代码助手，以及研究全球开源社区的语言习惯都有直接帮助。

AWS Strands Evals SDK 支持 Agent 故障自动定位

AWS 在 Strands Evals SDK 中新增了 Detectors，可自动扫描 Agent 执行轨迹并输出失败根因，把人工逐条看 trace 的诊断时间从小时级降到分钟级。输出是结构化结果，能指出具体失败组件和修复方向。

对运行大量 Agent 的团队来说，这提供了一条“eval + 可观测性”结合的落地路径：不仅知道分数掉了，还能快速定位是工具调用、规划还是上下文理解出了问题。

深度技术解读

Spring AI 2.0：把工具调用从模型私有循环变成可组合的 Advisor 链

在 1.x 中，每个 Chat Model 实现都内置了自己的工具执行循环，功能可用但不可观测、无法拦截，也不能与其他行为组合。Spring AI 2.0 将工具循环提升到 Advisor Chain 中，成为一等可组合组件；ChatClient 的请求会依次经过 Advisor 链，并支持循环重入。

这意味着你可以像拼装中间件一样拼装工具调用：加日志、权限检查、重试、路由、人类确认，全部可插拔。模型特有的工具循环被拆成可替换实现，Agent 的“思考-调用-观察”流程第一次成为显式的架构层。

ChatClient chatClient = ChatClient.builder(model)
    .defaultAdvisors(
        new ToolCallingAdvisor(toolCallbackResolver),
        new LoggingAdvisor(),
        new RetryAdvisor()
    )
    .build();

建议：如果你正在用 Spring Boot 构建 Agent，现在就该把工具调用从 Service 层抽出来，放到 Advisor 层统一治理，这样后续加 eval 和审计会容易得多。

[来源: Spring]

Samsung 用 AWS Lambda Response Streaming 实现电商实时定价

Samsung.com 的高流量电商页面需要从多个后端聚合实时价格，传统同步调用在高并发下产生架构性延迟，导致“加入购物车时价格已变”的信任问题。他们用 AWS Lambda Response Streaming 配合 Amazon CloudFront，把聚合结果以流式方式返回给前端。

这篇案例详细讲了遗留架构痛点、无状态流式方案、关键实现模式以及性能结果。核心启示：当 API 需要聚合多个慢后端时，与其等所有数据到齐再返回，不如先返回可缓存/可预测的部分，再流式补齐动态字段。

可复用的模式：CloudFront 做边缘缓存与连接保持 → Lambda 流式响应 → 后端并行调用 + 超时降级 → 前端按 chunk 渲染。如果你的系统也有“多源聚合 + 高并发 + 低延迟”诉求，这个模式值得直接抄。

[来源: AWS Architecture Blog]

工具推荐

GitHub Copilot CLI 常用 Slash 命令速查

GitHub Copilot CLI 支持通过 Slash 命令直接在终端里切换模型、查看 token 消耗、恢复历史会话等。对习惯在 shell 里工作的开发者来说，这减少了在 IDE 与终端之间来回切换的上下文断裂。

建议先把 /model、/usage、/resume 三个命令设成熟练操作；非交互模式下配合这些命令可以写出更可预测的自动化脚本。

[来源: The GitHub Blog]

Spring Tools 5.2.0 发布，新增 Claude Code 实验插件

新版 Spring Tools 支持 VS Code、Cursor、Eclipse、Theia 和 Claude Code，其中最值得关注的是实验性的 Claude Code 插件。它内嵌了一个 MCP Server，会把 Spring 项目的静态分析、索引信息、常见问题与修复建议暴露给 LLM。

同时提供的 Skills 能在验证与 Quick Fix 场景引导 LLM 如何使用这些信息。用 Spring + Claude Code 的同学可以先用起来，把“项目上下文喂给 Agent”这件事从手动粘贴变成自动暴露。

[来源: Spring]

Auth0 入驻 Vercel Marketplace

现在可以在 Vercel Marketplace 一键为项目开通 Auth0，自动创建应用并与 Vercel 项目关联。它自带 Auth0 Next.js SDK、托管用户管理、会话与角色管理，还能在 Development / Preview / Production 环境间同步认证配置。

对 Next.js 开发者来说，这省掉了手工创建租户、配置回调地址、同步环境变量等重复劳动，是“身份即基础设施”的又一便利集成。

云中 AI 治理：给架构师的实用指南

InfoQ 文章提出了一套可落地的 AI 治理框架：发现 Shadow AI、在数据创建时分类、通过 IAM 强制执行、用 Policy-as-Code 把规则嵌入交付流水线，并辅以运营控制。目标是在安全、合规与开发者效率之间取得平衡，而不是靠人工审批拖慢交付。
