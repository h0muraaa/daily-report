01 今日技术热榜

开源模型

Kimi-K2.7-Code 开源发布，长程 Coding Agent 的推理成本下降 30%

Moonshot 正式发布并开源 Kimi-K2.7-Code，这是 K2 系列中面向编程任务的最新模型。相比 K2.6，它在 Kimi Code Bench v2 上提升 21.8%、Program Bench 提升 11%、MLS Bench Lite 提升 31.5%，同时在长程任务中减少了约 30% 的推理 token 消耗。对于正在用 AI agent 做端到端开发的工程师来说，这意味着同样的复杂任务可以用更少的 token、更高的完成率跑完。

该模型已通过 Kimi API、Kimi Code 以及 Ollama Cloud、Fireworks 等平台上线，并预告将推出 6x High-Speed Mode。开源权重和代码已托管到 Hugging Face，社区可以直接下载、微调或私有化部署。

来源： Arena.ai、 Ollama、 Fireworks AI、 Berryxia.AI
开源模型

GLM-5.2 面向 Coding Plan 用户开放，下周开源并支持 1M 上下文

智谱发布 GLM-5.2，号称是其迄今能力最强的开源模型，支持真正可用的 1M token 上下文，并在长程任务中保持领先。该模型已率先向 GLM Coding Plan（Lite / Pro / Max / Team）用户开放，API 和 Chatbot 服务将于下周上线，模型本身也将在下周以 MIT 协议正式开源。

GLM-5.2 的发布时间点恰逢 Anthropic Fable 5 被禁，官方强调“前沿智能不应只属于少数人，也不应被少数规则随时收回”。对国内开发者而言，这意味着又多了一个可私有化、可商用的高性能 coding 模型选项，尤其适合长文档、代码库级任务。

来源： Arena.ai、 Z.ai、 智谱官方公众号
开源模型

MiniMax M3 开源：原生多模态 + 百万上下文 + Agent 操作

MiniMax 开源了 M3，官方称其为国内首个同时具备原生多模态、超长上下文和 Agent 操作三大能力的模型。M3 采用自研稀疏注意力架构 MSA（MiniMax Sparse Attention），最高支持 1M 上下文，在 100 万 token 下每 token 计算量仅为上代的 1/20，prefilling 加速超 9 倍、decoding 加速超 15 倍。

在 Coding 能力上，M3 相比 M2 在 bugfix、前后端开发、性能优化等场景接近海外闭源模型；在 Agentic 能力上，搜索、Office 办公与金融领域表现突出。同步开源了原始权重版和 MXFP8 量化版，适合显存受限的部署场景。

来源： 魔搭 ModelScope 社区
政策影响

Anthropic Fable 5 / Mythos 5 全面下架，开发者应做好模型替代预案

美国政府以国家安全为由发出出口管制指令，要求 Anthropic 暂停向所有非美国公民提供 Fable 5 和 Mythos 5 访问权限。Anthropic 表示无法按用户国籍精确区分，因此选择对全部客户禁用这两款模型，其他 Claude 模型不受影响。

这是首次以政府力量直接下架已商用的大模型。对依赖 Fable 5 做代码审查、架构设计或长程任务的团队来说，是一个明确的供应链风险信号：不要把关键工作流绑定在单一闭源旗舰模型上，建议尽快验证 Kimi-K2.7-Code、GLM-5.2、MiniMax M3 等开源替代方案，并设计可切换的模型路由。

来源： Anthropic、 浮之静、 Arena.ai
开发者工具

GitHub Copilot 桌面应用进入扩大技术预览，支持 Canvas 与独立 Git 工作树

GitHub Copilot 桌面应用在 Microsoft Build 上获得重大更新，现已向付费 Copilot 用户开放扩大技术预览。新功能包括 Canvas 交互式编码界面、语音支持、独立的 Git 工作树（worktree）以及安全沙箱，可以在保护本地环境的前提下让 agent 执行代码变更。

对日常开发的意义在于：agent 不再只能改当前分支，你可以在隔离的工作树里让 AI 完成实验性改动，确认后再合并，降低“AI 误删代码”的风险。付费用户现在即可在 GitHub 官网下载体验。

来源： GitHub、 GitHub (@github)
开发者工具

Vercel Workflow SDK 原生集成 Nitro v3，步骤与主应用同体运行

Vercel 宣布 Workflow SDK 的 Nitro v3 原生集成进入 Beta。原先 workflow 步骤运行在独立 bundle 中，现在则与应用的其余部分运行在同一个 bundled runtime 里，Nitro 的 useStorage() 等服务端 API 可以直接在 use step 函数中使用。

此外，workflow 路由现在由 Nitro 统一打包，依赖被自动追踪、未使用代码会被 tree-shake，构建更快、产物更小。开发服务器还在 /_workflow 路径提供 web UI，方便本地查看和调试 workflow 运行。

来源： Vercel News
Agent 基建

WebMCP 进入 Chrome Origin Trials，浏览器内 AI Agent 可直接调用页面工具

Google 宣布 WebMCP 标准提案进入 Chrome 149 的 Origin Trials 阶段。WebMCP 允许网站把 JavaScript 函数、HTML 表单等能力暴露给浏览器内的 AI Agent，使 Agent 能够可靠地模拟用户操作，而不是依赖昂贵且容易出错的 DOM 抓取或屏幕阅读。

如果该标准落地，前端开发者将需要新增“为 Agent 暴露结构化工具”的设计维度：哪些用户操作可以安全地暴露为 MCP 工具、权限如何控制、如何防止恶意 Agent 调用，都会成为新的安全与交互设计议题。

来源： InfoQ
Agent 基建

OpenRouter 上线 Subagent 服务器工具，大模型可动态委派给小模型

OpenRouter 发布新的服务器工具 Subagent，允许主模型在生成过程中把聚焦的子任务委派给更小、更便宜、更快的模型。主模型负责编排，子模型负责执行，子模型可以是 OpenRouter 上的任意模型。

这是一种成本与延迟优化思路：复杂任务让大模型拆分子任务，具体执行交给小模型。实际落地时要注意任务边界划分和上下文传递，否则子模型可能因为缺少全局上下文而重复调用或输出偏离。

来源： OpenRouter

02 深度技术解读

AI 编程

当最强闭源模型被禁，开源 coding 模型成为工程团队的“必需品”

过去一周，开发者社区经历了从“Fable 5 真香”到“Fable 5 没了”的快速反转。Anthropic 被迫下架 Fable 5 / Mythos 5 的事件说明：闭源旗舰模型的可用性不仅取决于技术能力，还受政策、合规和地缘政治影响。对于把核心开发工作流构建在单一模型上的团队，这是一次清晰的供应链风险提示。

好消息是，开源阵营在同一天密集出牌：Kimi-K2.7-Code 在代码能力、agent 长程任务和推理效率上全面超越前代；GLM-5.2 提供 1M 上下文并即将 MIT 开源；MiniMax M3 把原生多模态、百万上下文和 Agent 操作能力打包开源。这三款模型已经覆盖了代码生成、长文档理解、多模态输入和 Agent 执行等主流开发场景。

实践建议：在关键项目中采用“多模型路由 + 开源兜底”策略。把模型调用抽象成统一接口，优先用闭源模型处理高难度任务，同时用开源模型做本地预演、成本敏感任务和合规要求高的场景。这样即使某款模型突然不可用，工作流也能平滑切换。
来源： Anthropic、 Arena.ai、 魔搭 ModelScope 社区
工程实践

GitHub Copilot CLI 的“智能委派”改进：Agent 不是越勤快越好

GitHub 工程师 Dylan Birtolo 在一篇博客中分享了 Copilot CLI 的 agentic harness 改进：smarter subagent delegation。核心观察是——在 agent 系统里，更多委派并不等于更好。如果一个简单改动也要启动子 agent 去搜仓库、等结果，三步能完成的事会变成三步加等待，反而降低效率。

新机制让 Copilot CLI 更挑剔地决定什么时候启用子 agent：只有在探索陌生仓库、检查代码独立区域或运行长时间命令时才委派，简单任务直接处理。这对自建 agent 的开发者很有启发：delegation 策略应该显式建模，给每个子任务设定清晰的触发条件、超时和回退路径，而不是让模型自己“热情”地到处开线程。

来源： The GitHub Blog

安全

警惕 LLM 语义缓存的键碰撞攻击

港科大与复旦大学团队在 ICML 2026 发表研究，指出 LLM 语义缓存机制存在完整性漏洞。攻击者可以通过构造语义相近但意图不同的查询，让缓存命中并返回恶意响应。实验显示，在多租户和 Agent 场景下攻击成功率可达 86%，已覆盖 AWS、Azure 等主流云服务商。

如果你在自建或接入带语义缓存的 LLM 服务，建议为缓存键增加用户/会话隔离、对高敏感任务禁用缓存、并对缓存命中结果做二次校验，而不是直接返回。

来源： 机器之心
