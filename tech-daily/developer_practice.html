🔬 深度技术解读

理解 MCP "代码在工具里" vs "工具在代码里"

Armin Ronacher的实验揭示了一个反直觉的结论：当构建AI Agent的工具系统时，提供一个通用的代码执行环境（让Agent自己写代码调用API）往往比封装几十个特定函数接口效果更好。

实验1 - Google Workspace MCP（推荐模式）：

# 只暴露一个 execute 工具 { "name": "execute", "description": "执行JS/TS代码调用Google Workspace API", "parameters": { "code": "string // JS/TS代码" } }

关键优势：

  • Agent可以像程序员一样思考，灵活组合API调用
  • 不需要为每个功能预定义工具函数
  • 自然支持复杂的多步骤操作

实践建议：设计MCP Server时，优先考虑提供"可编程的运行时"而非"功能菜单"。

构建你的三层记忆系统

FelixCraftAI案例展示了如何为AI Agent设计有效的记忆系统，防止"健忘"问题。这种架构可以被复用到你自己的AI项目中。

# 三层记忆架构 # Layer 1: 会话记忆 - 当前对话上下文 ~/.claude/projects// # Layer 2: 短期记忆 - 跨会话的任务状态 ~/.codex/sessions// # Layer 3: 长期记忆 - 用户偏好和业务知识 向量数据库 + 结构化存储

关键洞察：好的记忆系统能让AI Agent从"问答工具"升级为"持续学习的协作者"。Claude Code的4% GitHub提交量证明了这一点。

💡 实践指南

让Claude Code记住项目上下文

  • 使用 ~/.claude/projects/ 目录组织不同项目的上下文
  • 在PROJECT.md中记录项目架构、技术栈、编码规范
  • 开启Copilot记忆功能后，AI会自动学习你的代码模式

构建AI友好的API设计

  • 优先提供可编程接口而非固定功能列表
  • API文档中包含代码示例，方便AI学习使用模式
  • 考虑为AI Agent提供沙箱执行环境

Vibe Coding 最佳实践

  • 清晰描述你想要的"结果"而非"实现步骤"
  • 提供足够的上下文和约束条件
  • 迭代优化：先跑通，再优化
  • 保持代码审查习惯，AI生成的代码也需要Review
