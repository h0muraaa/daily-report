# 深度技术解读 (Deep Dives)

AAgent token 成本进入精细化时代：阿里把缓存命中率拉到 80%，腾讯靠 10 个优化点降本 50%+

成本优化上下文工程缓存

两条一线生产实践同一天刷屏。阿里技术的做法借鉴 oh-my-pi、Codex CLI、Grok Build 与 Anthropic Agent 工程笔记，在百炼 qwen3.7-max 生产环境里把隐式缓存命中率从 33% 拉到 80%、显式缓存加权命中近九成，一轮 20 次的会话输入费用降到原来的十分之一。关键第一步是用数据先看清 token 花在哪：一个"帮我看下为什么报错"的模糊需求，背后是 system prompt、几十个工具的 schema、每一轮对话历史与工具查回的结果，动辄烧掉几十 M token。腾讯的做法是用 AgentLens 先把成本拆开（系统提示词、工具返回信息、历史消息是大头），再围绕"让 AI 只看到当前需要的上下文、减少无关上下文、减少重复上下文"三条原则，逐一改造架构拆分、稳定前缀、渐进式披露、代码图谱、CLI 替代 MCP、长期记忆按需索引、工具调用并行化等 10 个方向，全流程预估降本 50%~65%。两条路线互为补充：一个强调缓存与计费策略，一个强调上下文工程与架构裁剪，都值得做 Agent 工程的团队抄作业。

B从"把业务搬进 AI"到"把 AI 放进业务"：Codex Harness 的三层责任边界

架构CodexAgent 平台化

meng shao 的解读把 Codex 平台化拆成三层责任边界：业务应用（UI、业务上下文、业务规则、数据记录、审批体验）、Codex Harness（会话状态、智能体循环、流式事件、工具协调、沙箱执行、审批请求）、MCP/业务工具（查询内部数据、调用业务系统、执行受控操作）。这个边界的关键在于：Codex 不应接管整个产品——业务应用仍拥有系统记录、界面和最终控制权，Codex 负责理解情况、调查信息、提出方案并在授权后执行，产生实际业务后果的操作由宿主应用设置审批与权限边界。这与 Vercel 用 Zig 写的极简终端 Agent fx.sh 形成有趣对照：一个把 Agent 做得足够薄、更像 Unix shell 并支持 WebAssembly 集成到浏览器/其他系统，另一个把 Agent 底座开源出来塞进企业已有系统。两条路殊途同归——未来优秀的智能体应用，不是把业务搬进 AI，而是把 AI 放进业务。

# 实践指南 (Best Practices)

01大淘宝技术：SKILL 研发最佳实践——桥接器解耦、按需共享上下文、HTML 报告输出

Skill 开发架构设计

天猫技术团队以百亿补贴详情助手 Skill（bybt-detail-assistant，50+ commit）为例，从架构设计、研发效能、运行优化、呈现方式四个维度总结 Skill 研发实践。核心经验：用桥接器解耦本地 Skill 与远程 Agent，按需共享上下文（而不是把全部上下文塞进提示词），优先输出优质 HTML 报告作为交互结果。团队已基于这些方法开发 50+ Skill，覆盖补贴查询/创建/分析、舆情分析、频道巡检、代码助手等场景。对正在把 Skill 从一次性 demo 变成可持续迭代产品的团队，这是一份难得的国内一线实践。

📎 [来源: 大淘宝技术] 浅谈 SKILL 研发的最佳实践

02"AI 写的代码我完全不看"：Bob 大叔用自动化测试链给 Agent 兜底

《代码整洁之道》作者 Robert C. Martin（Bob 大叔）现在让 Agent 写代码、自己不再逐行检查。他并不是"闭着眼睛"接受 AI 代码，而是给 Agent 加了一层又一层的确定性约束：单元测试、Gherkin 测试、QA 流程、质量指标、变异测试、测试覆盖率，只有当代码通过这些自动化检查，他才对结果建立"很高的信心"。在与 Matt Pocock 的对谈里他强调：关键不是放弃软件工程，而是改变分工——与其逐行检查 Agent 写出的代码，不如建立一套确定性规则和工具让它们自动判断代码是否达标。他还点出一个行业痛点：刚入行的人可能根本识别不出 Agent 什么时候在挣扎。
