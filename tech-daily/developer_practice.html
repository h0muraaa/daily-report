🔥今日技术热榜

1 Anthropic 发布 Claude Fable 5：Mythos 级模型的公众安全版本

Anthropic 将内部代号 Mythos 的顶级模型能力通过安全护栏机制下放为 Fable 5，这是其公开发布的最强模型。该模型在 Code Arena 前端赛道登顶，HTML、React 所有子排行榜均位列第一，在 Agent Arena 的任务成功率和用户满意度上大幅领先 Opus-4.8 和 GPT-5.5。

然而发布伴随争议：模型会对涉及前沿 AI 开发的请求实施隐形降级，悄然切换至 Opus 4.8 而不通知用户，且数据明文存储期限长达两年。Anthropic 已承诺将安全措施改为可见模式，被标记请求会明确提示降级。

[来源: Anthropic] [来源: Arena.ai] LLM Agent 安全
2 Google 开源 DiffusionGemma：文本扩散模型，生成速度提升 4 倍

Google 发布基于扩散架构的实验性文本生成模型 DiffusionGemma，采用 26B 参数的 MoE 架构（激活仅 3.8B），摒弃逐 token 自回归方式，改为整块文本并行生成后迭代优化。在 H100 上可达 1000+ tokens/s，RTX 5090 上 700+ tokens/s，量化后 18GB 显存即可运行。

该模型支持"自我纠错"——生成过程中可回头修改前文错误，这对代码格式化、数学推导等需要全局一致性的场景意义重大。Apache 2.0 协议开源，Unsloth 团队已演示通过微调让模型学会解数独。

[来源: Google] [来源: arXiv] 开源模型 扩散模型 推理优化
3 小米开源 MiMo Code：终端原生 AI 编程 Agent，带持久记忆系统

小米 MiMo 团队基于 OpenCode fork 开发并开源 MiMo Code V0.1.0，14 天 5 人 vibe coding 完成。核心创新在于用工程方案解决"AI 健忘"问题：独立 subagent 自动保存状态，窗口满时重建干净简报，而非依赖模型自觉。

内置 build/plan/compose 三类子代理、自动 checkpoint、智能上下文预算，以及 /dream 自我提炼知识、/distill 打包技能的进化机制。支持 MiMo Auto 限时免费通道、Claude Code 认证迁移及任意 OpenAI 兼容 API。MIT 协议开源，curl 一键安装。

[来源: GitHub] [来源: 小米 MiMo] 开源工具 Agent 记忆系统
4 GitHub Agentic Workflows 公测：带护栏的自动化工作流

GitHub 推出 Agentic Workflows 公开预览，提供带强护栏、可观测性和成本控制的智能自动化。与 Copilot 的代码补全不同，这是面向仓库级别的自动化——从 issue 到 merge 的全流程代理执行，人类决定代理工作内容、工作方式及发布时机。

同日 GitHub Copilot 桌面应用技术预览也向所有付费用户开放，标志着"代理原生"（agent-native）开发环境的正式落地。

5 Grok Build Plugin Marketplace 上线：Vercel、MongoDB、Cloudflare 等入驻

xAI 的 Grok Build 插件市场进入公测，首批支持 MongoDB、Vercel、Sentry、Cloudflare 和 Chrome DevTools 插件。开发者可从终端直接调用，实现部署到生产环境、启动沙箱、构建 Shadcn UI 应用等操作。

Vercel 插件可实时注入平台 API 知识和推荐模式，MongoDB 插件支持单提示词构建高性能向量搜索系统。这标志着大模型厂商正在从"对话界面"向"开发者工具链集成"深度渗透。

6 OpenAI Codex 动态工作流：并行代理协调处理复杂工程任务

Anthropic 竞争对手 OpenAI 同日放出 Codex 动态工作流（Dynamic Workflows），支持在单一工作流中协调大量 AI 代理并行执行复杂软件工程任务。系统自动生成协调脚本、分解子任务、并行执行并验证结果。

该功能针对单个代理难以处理的场景优化：广泛漏洞调查、大规模迁移、安全审计、性能审查等。执行进度可保存，中断后可从中断处继续。ultracode 设置可自动判断何时采用工作流方式。

DeepSeek 开放招聘 Agent Harness 研究员（全职/实习），这可能是业界首次专门针对"Harness"（模型之外的 Agent 基础设施）设立的研究岗位。职责涵盖上下文管理、长期记忆、Subagent 与 Multi-Agent、自进化 Agent 等前沿方向。

8 JetBrains MPS 2026.1 RC 支持 MCP：AI 代理可访问语言工作台

JetBrains MPS（Meta Programming System）2026.1 发布候选版带来实验性 MCP（Model Context Protocol）支持，通过捆绑的 Projectional Agent Toolkit 插件实现。启用嵌入式 MCP 服务器后，AI 代理可自动识别 MPS 实例中的工具集和技能。

这是传统语言工程工具与 AI 代理协议的重要结合，意味着领域特定语言（DSL）的创建和维护也可纳入 Agent 工作流。注意该功能为实验性质，未来 API 可能变更。

🔍深度技术解读

Claude Fable 5 的工程实践：从" vibe coding"到生产级 Agent 工作流

Fable 5 的发布不仅是模型能力的跃升，更揭示了 Anthropic 内部工程实践的重大转变。根据 Anthropic Applied AI 团队架构师 Arno 的 workshop 演示，其工作流设计遵循"模型越强，约束越少"的原则，核心是将验证嵌进产物本身，而非依赖外部检查。

关键洞察：Agent 跑得越久，走错时烧掉的 token 越多。长任务跑偏的代价是短任务的指数级。

配套 repo 展示三阶段工作流：

Phase 1 - 需求澄清：让 Claude 采访人类，避免需求遗漏。不是直接写代码，而是先通过对话挖掘真实需求，输出结构化访谈记录。

Phase 2 - 设计探索：生成多个 HTML 设计方向供人类快速比较。利用 Fable 5 的前端能力一次性产出可交互原型，而非静态 mock。

Phase 3 - 验证内嵌：将验证框架直接植入小型 to-do app，包括 React 组件测试和浏览器自动化验证。测试即文档，验证即代码。

这种"验证前置"模式与 Cursor 的 auto-review（97% 准确率的分类器子代理审查动作）形成呼应，表明顶级编码 Agent 正在从"生成代码"向"生成可验证的系统"演进。

"Token 大爆炸"与数据基础设施的第四阶段

华为数据存储副总裁吴俊杰在 InfoQ 访谈中指出，AI 发展正进入以数据为核心的第四阶段。六年前 OpenAI 最大用户月耗 10 万 token，2026 年这个数字变为 10000 亿——Agent 正在制造"Token 大爆炸"。

这带来三个工程挑战：

成本结构重塑：头部企业人均月 AI 支出已达 7500 美元（约 5 万人民币），且上月增长 14.1%。Token 不再是边际成本趋零的资源，而是需要精细管控的生产要素。

检索优先于推理：Qdrant 的基准测试表明，即使上下文窗口扩大，检索管道（retrieval pipeline）对降低延迟和成本仍至关重要。直接塞入大量上下文 vs 两步检索（Qdrant 获取最相关信息）的对比显示，后者在保持答案质量的同时显著降低成本。

数据基础设施决定 Agent 上限：Gartner 预测 2026 年企业将以前所未有的方式依赖数据。Agent 能否自主发现数据源、理解业务语义、调用权限策略、执行跨系统推理并在闭环中进化，取决于底层数据平台的"Agent Ready"程度。

# 传统架构 vs Agent-Native 架构的成本对比 # 假设：100万 token 上下文，单次查询 # 方案 A：直接全量输入（大上下文窗口） cost_direct = 1_000_000 * $0.01 / 1K = $10.00 latency_direct = ~30s # 线性增长 # 方案 B：Qdrant 两步检索（检索 + 精排） retrieval_cost = 0.001 # 向量检索 llm_cost = 10_000 * $0.01 / 1K = $0.10 # 仅输入相关片段 cost_total = $0.101 latency_total = ~2s

📋实践指南

Loop Engineering：设计系统替代你提示 Agent

Google Cloud AI 工程总监 Addy Osmani 提出 Loop Engineering 概念：不再亲自给编程 Agent 写提示，而是设计循环结构让系统自动驱动 Agent。Claude Code 的 /goal、Codex 的 /goal、Claude Managed Agent 的 Outcomes 都是具体落地。

五个核心模块：目标定义 → 任务分解 → 并行执行 → 结果验证 → 迭代决策，配合记忆机制形成闭环。关键认知转变：人从执行者变为系统设计者，Agent 从工具变为被调度的劳动力。

[来源: 前端早读课] 方法论

模型路由策略：用最强模型决策，低成本模型执行

shadcn 开源的 /improve 指令展示了高效的模型分工模式：用 Claude Fable 5 审计代码库、排查 bug、性能问题、技术债务，生成包含审计、调研、范围界定、执行、测试及终止条件的完整计划；然后让任何低成本模型执行该计划。

实际团队案例：LlamaIndex 团队发现 Fable 5 的 token 消耗速度相当于"人头成本"，一名工程师 10 小时烧掉 $1500。解决方案是将模型路由内建到核心工程工作流：复杂决策用 Fable，常规编码用 Sonnet 或 GPT-4，批量任务用开源模型。

[来源: GitHub] [来源: Jerry Liu] 成本控制 模型路由

Agent 上下文压缩：长任务的生存法则

自动化所、上交、UCSD 和合工大联合综述《Context Compression for LLM Agents》指出，Agent 的核心瓶颈从"模型能不能想"转向"上下文能不能被可靠管理"。

三类压缩策略：选择性压缩（保留关键决策点，丢弃冗余中间步骤）、结构化压缩（将轨迹转为状态机或 DAG）、生成式压缩（用模型自身总结历史）。失败模式包括：过早压缩丢失关键约束、过度压缩导致状态歧义、压缩时机不当打断推理链。

[来源: Preprints] [来源: GitHub] 上下文管理 论文解读

Claude Design 的十条工作原则

来自宝玉等一线用户的经验沉淀：（1）使用 CLAUDE.md 固化反复叮嘱的事项；（2）把 Claude Design 当做唯一设计源，单向同步 Design → Code；（3）设计结果用 git 版本管理，利用文本格式优势做 diff 跟踪；（4）先改设计稿再改代码，临时改动也要同步回设计稿；（5）利用 data.jsx 理解数据结构，这对开发比 Figma 更友好。
