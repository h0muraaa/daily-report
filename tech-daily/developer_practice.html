用 Claude Code 把 Moebius 0.2B 图像修复模型移植到浏览器

Simon Willison 记录了他如何将一个原本依赖 PyTorch + NVIDIA CUDA 的 0.2B 参数图像修复模型 Moebius，移植到浏览器中通过 WebGPU 运行。最终成果是一个纯前端 demo，用户可以上传图片、涂抹需要修复的区域，然后由模型自动填充。

这个案例的价值不只是“在浏览器跑模型”，而是展示了 Agent 辅助下的端到端移植流程：从理解原始模型结构、选择 ONNX / Transformers.js 路径，到处理输入输出格式和 WebGPU 内存限制。对于想把小规模模型搬到前端的团队，这是一个可参考的完整路径图。

实践建议：在尝试类似移植时，先用最小模型验证 pipeline 是否可行，再处理性能优化；同时关注浏览器的 WebGPU 内存上限和精度问题。

腾讯 EdgeOne Makers：为 AI Agent 设计的云平台

腾讯低调上线了 EdgeOne Makers 平台，核心理念是“让 AI Agent 自己部署应用”。开发者只需通过自然语言或 CLI 告诉 Agent 要部署什么，系统就会自动完成 Git 推送、CI/CD 触发、边缘函数部署和预览链接生成。底层是一套标准化的 Skill 系统，覆盖边缘函数、云函数、KV 存储、中间件等能力模块，并支持 Claude Code、Cursor、CodeBuddy 直接调用。

实践建议：如果你正在用 AI Agent 做部署，可以先研究它的 Skill 文档格式和 CLI 接口，思考如何把自己的基础设施也抽象成 Agent 可调用的 Skill，而不是让 Agent 去操作网页控制台。

4. 实践指南

当 Reflection 无法修复 AI Agent 的输出时，该怎么办？

很多 AI Agent 教程把“reflection”当作解决坏输出的万能药：让第二个 LLM 审阅第一个 LLM 的输出，然后让第一个 LLM 再试一次。但作者 Manish Ramavat 从大规模生产系统经验出发指出，reflection 对结构化输出并不可靠——它可能修正语法，但难以保证字段完整、类型正确、业务规则不被违反。

更可靠的替代方案：

  • 用 schema 约束 + 输出后验证（post-validation），而不是依赖 LLM 自我纠错；
  • 对关键字段使用确定性解析或规则引擎兜底；
  • 把 LLM 当作“生成候选”而非“最终答案”，后续接强制类型转换和业务校验。

事故复盘：当问题“不是 DNS”的时候

Sean Klein 在 InfoQ 演讲中复盘了 Azure 2023 年全球 WAN outage，并指出“人为错误”是一个危险的神话。现代事故分析不应停留在“五个为什么”和追责，而要看到系统层面的缺陷：SOP 是否合理？工具是否保护了工程师免于犯错？组织文化是否鼓励上报 near-miss？

  • 设计能主动保护工程师的 resilient systems，而不是依赖“下次更小心”；
  • 在 postmortem 中关注可改变的流程与工具，而非个人责任。
