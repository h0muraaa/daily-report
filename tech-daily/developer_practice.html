🔬 深度技术解读

架构"百工具 Agent"是陷阱：Semantic Tool Router 如何破局

Prosodica 工程师在 AI Engineer 大会分享的实战洞察：把大量工具塞进系统提示词（"Fat Agent"架构）会导致延迟飙升、成本激增、工具选择准确率下降。解决方案是 Semantic Tool Router——确定性路由层，只向模型注入当前最相关的工具，实现 Just-in-Time Context Injection。

实测数据显示，在 GPT-4o 和 Gemini 2.0 上，可用工具数量直接影响首 Token 时间和选择准确率。从静态加载转向动态注入，是生产级 Agent 架构的必经之路。

# 核心思路：两层架构 Router (确定性, 轻量) → 筛选相关工具子集 Agent (LLM, 重推理) → 仅在精简上下文中选择工具
来源: AI Engineer (YouTube)
实践浏览器 Agent 的瓶颈不在模型，在"眼睛"和"手"

ARK 团队的反直觉发现：过去一年浏览器 Agent 的改进主要靠换更强模型，但基础工作流仍频繁失败。真正瓶颈是模型与浏览器的接口设计——原始 DOM dump 信息过载、单次点击调用太慢、只有最终结果反馈无法学习。

他们构建的新运行时聚焦三点：紧凑页面表示（替代原始 dump）、带稳定句柄的快速动作、每步即时反馈。相同模型下，仅改进接口就能让复杂多步执行从混乱到正确。这对正在构建浏览器自动化 Agent 的开发者有直接参考价值。
