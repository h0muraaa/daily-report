Karpathy 的 LLM Wiki：一种面向开发者的「知识库优先」工作流

Andrej Karpathy 最近在 X 上分享了他正在实践的一套工作流——「LLM Wiki」，引发超过 1700 万次浏览。核心理念是：不再把大模型主要用在写代码上，而是将绝大多数 Token 消耗转向构建一个围绕个人研究兴趣的「可演化知识库」（以 Markdown 和图片形式存储）。

从工程实现上看，这个项目并不依赖复杂的向量数据库或 RAG 框架，而是采用轻量级的文件组织 + 结构化标记 + 模型辅助检索的组合。Karpathy 完整披露了数据采集、工具选择、增量更新等技术细节，项目 gist 已公开。这种「用 LLM 做知识管理而非代码生成」的思路，对开发者个人技术成长和团队知识沉淀都有启发意义——尤其适用于研究型工程团队。

Graphify & GitNexus：代码理解从「搜索」到「知识图谱」的跃迁

AI 编程助手发展到现在，补全和改代码已经不够看了。真正进入复杂项目后，核心痛点变成了：模型知道一个函数怎么改，却不知道这个改动会影响哪些调用链；能读懂一段模块代码，却不知道这段代码在整个架构里承担什么角色。

Graphify 和 GitNexus 两个项目正在从不同角度解决这个问题。Graphify 更像一个「多模态知识图谱构建器」，把代码、文档、论文、图片、视频等材料统一转成可查询的知识网络。GitNexus 则是一个「面向工程开发的零服务代码情报引擎」，重点让 AI Agent 在真实开发中获得更可靠的结构化上下文。两者的分层思路清晰，值得在大型代码库维护或 AI 辅助重构场景中评估使用。
