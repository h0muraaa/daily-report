Cursor 如何评估 Claude Fable 5：真实开发不是 benchmark

Anthropic 最近分享了 Cursor 工程师 Nate Schmidt 评估 Claude Fable 5 的过程。与常见的代码 benchmark 不同，Cursor 的测试刻意只给半句话需求或一段报错栈，让模型在信息不完整的情况下修复问题。Fable 5 在 CursorBench 3.1 Max 档拿到 72.9%，但真正让 Cursor 敢把"最难的 1%"交给它的，是逐条翻阅执行日志、验证模型是否找对了根因。

这个案例给开发团队的启示是：评估 AI 编程助手时，分数只是入场券，更重要的是建立与自身代码库对齐的验收标准。CursorBench 的设计思路——任务来自真实用户会话、故意信息不完整、关注修复而非代码量——可以作为团队内部评估 Agent 的参考模板。

📘实践指南

Datadog 用 Claude 和 Cursor 完成测试驱动式生产环境迁移

Datadog 工程师 Arnold Wakim 分享了团队借助 AI 改造核心生产系统 Stream Router 的经历。旧系统基于键值模型，路由表扩展后单次操作最长可达 45 分钟。团队用外键取代应用代码中重建的关系逻辑，然后借助 Claude 和 Cursor 加速基于测试驱动的系统化重构。

关键经验：AI 工具不会自主生成完整可用的代码，而是需要为每个方法提供"原实现 + 新数据结构 + 失败测试用例"的三元输入。高度模块化的架构和完备的测试用例，是这次迁移能成功的前提。对于正在考虑用 AI 重构老系统的团队，这个模式比"让模型直接重写"更可控。

[来源: AI前线 / 微信公众号]

Momentic 从 PostgreSQL 迁移到 ClickHouse 支撑 200 亿缓存条目

AI 驱动测试平台 Momentic 的缓存系统数据量从 8 万条激增至 10 亿条，PostgreSQL 在高写入高读取下出现锁争用和资源飙升。迁移到 ClickHouse 后，通过稀疏主键索引和精心设计的主键字段（测试 ID、步骤 ID、平台版本、Git 分支、提交时间戳），在 90% 场景下实现了高效检索，支撑每天 200 万次查询、平均延迟约 250 毫秒。

这个案例说明：当缓存数据表从"小表"变成"海量表"时，列式数据库的稀疏索引往往比行式数据库的 B 树更合适。主键设计需要结合查询模式，而不是简单地把原有字段平移过去。

[来源: InfoQ / 微信公众号]

用 AGENTS.md 引导 Coding Agent 写自动化测试

宝玉分享了一套把自动化测试交给 Agent 的提示词工程方法：如果项目还没有测试，直接要求 Agent "请帮我初始化自动化测试"；如果已有测试，在 AGENTS.md 里加上"实现功能的同时，要同步写自动化测试代码，并且完成后要用测试代码验证"。

更进一步的实践是把 QA 拆成两层：Agent 负责自动化测试覆盖，人负责黑盒测试验证功能完整性、边界条件和安全性。配合 Codex / Claude Code Desktop 的 Computer Use 能力，可以在交付前自动跑一轮 UI 层面的回归验证。这种"人定义验收、Agent 执行覆盖"的分工，可能是当前最务实的 AI 测试落地方式。
