AI OpenAI Codex 正式发布 Subagents 功能
📅 2026-03-17 📰 OpenAI Developers

OpenAI Codex 正式推出子代理（Subagents）功能，允许开发者启动专门的代理来加速工作流程。这一功能的核心价值在于：保持主上下文窗口简洁、并行处理任务的不同部分、在工作进行过程中指导各个 Agent。

AI Agent 开发实践：从 OpenClaw 到企业级部署

背景： OpenClaw 的爆火标志着 AI Agent 从概念走向实用。但真正的挑战在于：如何将 Agent 从个人玩具转变为生产环境可用的系统？

技术架构演进： 当前 Agent 架构正经历从"单 Agent 单体"向"多 Agent 协作"的转变。OpenAI Codex 的 Subagents 和 Claude Code 的 Agent 模式都体现了这一趋势。核心设计原则包括：

  • 上下文隔离：主 Agent 保持简洁，子 Agent 处理特定任务
  • 并行执行：多个子 Agent 同时处理任务的不同部分
  • 动态编排：根据任务进展动态调整 Agent 行为

企业级部署挑战： LangChain 与 NVIDIA 的合作揭示了企业级 Agent 部署的关键要素：模型推理优化（Nemotron 3 + NIM）、安全护栏（NeMo Guardrails）、可观测性（LangSmith）和全生命周期评估。这不再是简单的 API 调用，而是一个完整的工程体系。

实践建议： 对于开发者而言，建议从具体的自动化任务入手（如代码审查、数据提取），逐步构建 Agent 能力。同时关注 Context Hub 等新兴工具，解决 Agent 的"知识更新"问题。

Attention Residuals：Transformer 架构的下一个进化方向？

问题本质： 传统 Transformer 的残差连接采用固定累加方式，导致深层网络出现信息稀释（dilution）问题，且隐藏状态随深度爆炸式增长。

Kimi 的解决方案： Attention Residuals 的核心洞察是：让每一层通过注意力机制动态选择前面哪些层的信息最相关。这类似于人类认知——当前思考时只回忆最相关的记忆，而非平均加权所有过去经验。

技术实现： 为降低计算开销，Kimi 引入了 Block AttnRes（分块注意力残差）：

# 概念性伪代码
# 传统残差：output = layer(x) + x
# Attention Residuals：
block_outputs = [layer_group_1(x), layer_group_2(x), ...]
attention_weights = softmax(query(current_layer), keys(block_outputs))
output = sum(attention_weights[i] * block_outputs[i])

性能收益： 在 Kimi Linear（48B/3B MoE）上，推理延迟仅增加 <2%，计算效率提升 1.25 倍。更重要的是，训练稳定性显著改善，梯度分布更均匀。

意义： 如果这一机制被验证可在更大规模模型上扩展，可能成为继 RoPE、SwiGLU 之后 Transformer 架构的又一项标准组件。

参考来源：GitHub - MoonshotAI/Attention-Residuals

降低 Claude Code 使用成本的 4 个技巧

根据 Milvus 团队实践，通过以下配置可将 token 消耗降低约 60%：

  1. 限制思考 token： 设置 MAX_THINKING_TOKENS=10000，相比默认 31K 可节省约 30%
  2. 默认使用 Sonnet： 日常开发使用 /model sonnet，仅在复杂问题时切换到 Opus
  3. 提前 compact： 设置 CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50，在上下文过半时自动压缩
  4. 用 Skills 替代 MCPs： MCP 服务器会注入工具描述到上下文，Skills 更轻量
