🧠 Prompt Caching：长时 AI Agent 的关键技术

随着 Claude Code 等长时间运行的 AI Agent 产品的普及，Prompt Caching（提示缓存）技术成为降低延迟和成本的核心优化手段。

核心原理：复用之前轮次的计算结果，避免重复处理相同的上下文。对于需要多轮交互的 Agent 系统，缓存命中率直接影响用户体验和运营成本。

Anthropic 团队在 Claude Code 中围绕 Prompt Caching 构建了整个架构。高缓存命中率不仅能降低成本，还能帮助创建更慷慨的订阅计划速率限制。他们甚至在缓存命中率过低时触发 SEV（Site Event）警报。

// 伪代码：Prompt Caching 在 Agent 系统中的应用 class AgentSession { constructor() { this.cache = new PromptCache(); this.contextWindow = []; // 1M tokens } async process(userInput) { // 检查缓存中是否有相似提示 const cached = await this.cache.get(userInput); if (cached) { return cached.response; // 直接返回，节省 API 调用 } // 新查询：调用 LLM 并缓存结果 const response = await llm.generate({ context: this.contextWindow, input: userInput, cache_key: this.generateCacheKey() }); this.cache.set(userInput, response); return response; } }

实践建议：

  • 对于多轮对话系统，优先设计可缓存的提示结构
  • 监控缓存命中率，低于 70% 时需要优化提示设计
  • 使用语义化缓存键，而不仅是字符串匹配
  • 结合模型 fine-tuning 减少需要缓存的上下文长度

🔗 MCP Protocol 实践：Code Mode 模式解析

Model Context Protocol (MCP) 已成为 AI Agent 使用外部工具的标准方式，但工具增多会填满模型的上下文窗口。Cloudflare 提出的 Code Mode 模式是解决这一问题的创新方案。

核心思想：让模型编写代码来调用工具，而不是为每个操作单独描述工具。代码作为紧凑的"计划"，可以探索、组合多个工具调用，只返回需要的数据。

传统 MCP 的问题：

  • 每个工具需要完整的描述和参数说明
  • N 个工具 = N 倍的上下文占用
  • 复杂操作需要多轮工具调用

Code Mode 的优势：

  • 用代码代替自然语言描述工具调用
  • 一个 SDK 可以覆盖多个操作
  • 模型可以编写复杂的工具组合逻辑
  • 代码在 Dynamic Worker 中安全执行
// 传统 MCP：每个工具单独描述 tools: [ { name: "search", params: { query: "string", top_k: "number" } }, { name: "get_user", params: { id: "string" } }, { name: "update_record", params: { ... } }, // ... 更多工具 ] // Code Mode：使用类型化 SDK const sdk = await loadSDK('my-api'); // Agent 生成代码而非多次工具调用 const code = ` const user = await sdk.users.get({ id: "123" }); const related = await sdk.search.query({ query: user.interests[0], top_k: 10 }); return related.items.map(i => i.title); `; // 在隔离 Worker 中执行 const result = await executeInSandbox(code, sdk);
注意事项：Code Mode 需要类型安全的 SDK 和可靠的沙箱执行环境。对于简单场景，传统 MCP 仍然更直观。建议根据工具复杂度和调用频率选择合适模式。
📚 参考： Cloudflare Blog - Code Mode MCP | Anthropic - Code Execution with MCP

⚡ 2026 年的开发范式转变：AI 优先工作流

随着 AI 代码生成工具的普及，开发者工作流正在经历根本性转变。以下是基于近期行业动态的观察：

1. 从"写代码"到"审代码"

Anthropic 的 Boris 自 2024 年 11 月以来没有手写过一行代码，100% 由 Claude Code 生成。同时他每天能合并 10-30 个 PR。这不是个案——Anthropic 工程师整体生产力提升了 200%。

2. Context 优先于 Control

与 AI 协作的关键是给足上下文，让它自己找出解决方案，而不是微观管理每个步骤。开发者应该：

  • 清晰描述目标，而非具体实现步骤
  • 提供相关代码、文档、架构图作为上下文
  • 接受 AI 可能比你的具体指令更聪明

3. 代码库的 Agent 优化

Thorsten Ball 提出"编码 Agent 已死"的观点——问题的瓶颈不再是 Agent 本身，而是代码库的组织方式和团队使用 Agent 的方式。建议：

  • 模块化设计，让 Agent 能独立理解和修改单元
  • 完善的测试覆盖，让 Agent 能验证修改
  • 清晰的文档和类型定义
  • 一致的代码风格（可用 AI 辅助标准化）
未来趋势：编程语言本身可能发生变化，从"如何做"(How) 转向"做什么"(What)。Cursor CEO Michael Truell 预测，未来的编程将更像高级编译器技术，而非人类助手的委托模式。

🎯 与 AI 编码 Agent 高效协作的 7 条经验

01: Context, not Control（给上下文，而非控制）
告诉 AI 你想要达成什么目标，让它自己找出实现方法。不要微观管理步骤，描述目的地即可。AI 通常比你的具体指令更聪明。
02: Push until it breaks（测试到它崩溃）
不要接受第一次结果。持续推动、要求更多、请求变体。推到它失败为止，只有那时你才真正理解它的极限。极限通常比你想象的更远。
03: Put in the reps（重复练习）
没有什么神奇的提示模板或捷径能让你突然成为专家。像其他事情一样，你需要不断重复。建得越多，直觉就越准。
04: Try everything（尝试一切）
浪费一些 token。这是学习成本。尝试疯狂的想法。最好的突破往往来自"如果……会怎样"的探索。
05: Use it for real work（用于真实工作）
不要只做玩具项目。用 AI 构建你真正需要的东西。现实约束是最好的老师。
06: Trust your taste（相信你的品味）
AI 可以生成无数选项，但你需要判断哪个是对的。培养你的品味——这是 AI 无法替代的能力。
07: Stay curious（保持好奇）
技术变化快，今天的最佳实践明天可能就过时。保持对新工具、新方法的开放态度。
📚 来源： Zara Zhang 的 7 条经验

🔧 使用 Data API Builder 实现多数据源统一 API

Microsoft 的 Data API Builder (DAB) 现在支持多源配置，让你可以用单一 REST/GraphQL 端点连接多个数据库。

// dab-config.json 示例：连接 SQL Server 和 PostgreSQL { "data-source": { "database-type": "mssql", "connection-string": "@env('MSSQL_CONN')" }, "data-sources": [ { "name": "postgres", "database-type": "postgresql", "connection-string": "@env('PG_CONN')" }, { "name": "cosmos", "database-type": "cosmosdb_nosql", "connection-string": "@env('COSMOS_CONN')" } ], "entities": { "User": { "source": "dbo.Users", "data-source": "mssql" }, "Order": { "source": "orders", "data-source": "postgres" } } }

使用场景：

  • 微服务架构中的统一数据访问层
  • 遗留系统与新系统的数据整合
  • AI Agent 的数据接口（支持 MCP 协议）
  • 快速原型开发，无需编写后端代码
