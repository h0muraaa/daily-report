Claude Opus 4.6 和 Sonnet 4.6 百万上下文窗口全面上线

Anthropic 正式将 Claude Opus 4.6 和 Sonnet 4.6 的上下文窗口提升至 100 万 token，这是 AI 编程领域的重大突破。此次更新取消了长文本溢价，在整个百万窗口内统一适用标准计费规则（Opus 4.6: $5/$25 per million tokens；Sonnet 4.6: $3/$15）。多模态处理能力提升 6 倍，单次请求最多可处理 600 张图片或 600 页 PDF。对于 Claude Code 用户，Max、Team 和 Enterprise 版本的默认模型已自动从 200k 升级到 1M，大幅减少了上下文强制压缩的次数。这意味着开发者现在可以将整个代码库、大量文档或复杂项目一次性喂给 AI，无需再为上下文长度焦虑。

Chrome 146 原生支持 Agent 浏览器控制

Chrome 146 发布了一个革命性功能：只需在 chrome://inspect/#remote-debugging 开启一个开关，任何 coding agent 就可以直接访问用户的真实浏览器会话。这不需要安装扩展、不需要无头浏览器、不需要截图、不需要单独登录。Agent 可以看到标签页、Cookie、登录状态等一切信息，通过 Chrome DevTools MCP 协议直接操控浏览器。这一功能让 Agent 能够帮用户完成真实的网页操作任务，如处理 LinkedIn 好友请求、自动填写表单、抓取需要登录才能访问的数据等。OpenClaw 创始人 Peter Steinberger 表示这是"massively more agent-friendly"的更新，将彻底改变 Agent 与浏览器的交互方式。

bb-browser：通过 CDP 直接操控真实浏览器的 CLI 工具

开发者 yan5xu 发布了 bb-browser（badboy browser），这是一个极具争议的浏览器自动化工具。它通过 Chrome 插件 + CDP（Chrome DevTools Protocol）直接操控用户的真实浏览器，而非传统的无头浏览器方案。已登录网站的 Cookie、鉴权信息可以直接使用，Agent 可以在浏览器 console 中直接执行代码。目前支持 Reddit、Twitter、GitHub、Hacker News、小红书、知乎、B站、微博、豆瓣、YouTube 等 50+ 命令。安装方式简单：npm install -g bb-browser。该项目还内置了 guide 命令，Agent 可以自动学习如何将任意网站 CLI 化。这种实现方式绕过了传统爬虫最头疼的登录态问题，但也引发了关于安全性和平台规则的讨论。

OpenViking：字节火山引擎开源的 AI Agent 上下文数据库

字节火山引擎团队开源了 OpenViking，这是一个专为 AI Agent 设计的上下文数据库系统，GitHub 上线首日即斩获 1500+ Star。OpenViking 将 Agent 的记忆、资源、技能全部按"文件系统范式"统一管理，彻底告别传统的向量碎片。核心特性包括：L0/L1/L2 三层分层上下文架构，按需加载可大幅降低 Token 消耗；支持目录递归检索和可视化轨迹；自动会话压缩和长期记忆提取；特别适配 OpenClaw 等框架。实测显示任务完成率提升 40%+，输入 token 显著降低。对于正在构建 AI Agent、RAG 或长上下文工具的开发者，这是一个值得关注的基础设施项目。

Cloudflare 用 OpenCode 和 Claude 一周内重构 Next.js

Cloudflare 工程师使用 AI 模型从零开始重构了 Next.js，推出了 vinext（读作"vee-next"），可作为 Next.js 的即插即用替代方案。该项目基于 Vite 构建，仅需一条命令即可部署到 Cloudflare Workers。初步基准测试显示，生产环境应用构建速度最高提升 4 倍，客户端打包体积最高减小 57%。整个项目仅花费约 1100 美元的 Token 费用。这一案例展示了 AI 辅助编程在大型基础设施项目中的实际效能，也证明了 Vite 生态在边缘计算场景下的潜力。vinext 解决了 Next.js 部署到无服务器生态时的适配难题，无需再依赖 OpenNext 进行复杂的构建输出改造。

Vite 8.0 正式发布：内置 Rolldown 带来 10-30 倍构建提速

Vite 8.0 正式发布，最大亮点是内置了 Rolldown —— 一个用 Rust 重写的 Rollup 兼容打包器。这一改变带来了 10-30 倍的构建速度提升，同时保持与现有 Rollup 插件生态的兼容性。Vite 8 还改进了开发体验，优化了 HMR（热模块替换）性能，并引入了新的配置选项。与此同时，尤雨溪还宣布了 Void 部署平台，这是一个 Vite 原生的部署解决方案，旨在让 Vite 项目从本地开发到生产部署更加顺畅。Void 通过 Vite 插件 + 云端能力的组合，可以自动配置数据库、存储、队列等资源，部署到 Cloudflare Edge 网络。这一系列发布标志着 Vite 生态从开发工具向全栈平台的演进。

Grab 开源 TLRU 图像缓存方案：Android 性能优化实践

Grab 工程师分享了他们在 Android 应用中的图像缓存优化实践。团队从传统的 LRU（Least Recently Used）缓存迁移到了 TLRU（Time-Aware Least Recently Used）缓存，实现了更有效的存储回收，同时不牺牲用户体验或增加服务器成本。TLRU 在 LRU 的基础上增加了时间维度考量，能够更智能地判断哪些缓存项应该被清理。对于需要处理大量图片的 Android 开发者，这一方案提供了经过生产环境验证的优化思路。文章详细阐述了迁移过程中的技术细节、性能测试数据和踩坑经验，是移动端性能优化的优质参考案例。

MCP 协议争议：Perplexity 放弃 MCP 转向 CLI

Perplexity 联合创始人和 CTO Denis Yarats 在公司内部宣布放弃 MCP（Model Context Protocol），转而使用 API 和 CLI。这一决定引发了技术社区的广泛讨论。MCP 由 Anthropic 在 2024 年 11 月推出，曾被视为主流的大模型通信标准协议，但始终面临"builder 多于 user"、"旧瓶装新酒"的质疑。

MCP 的核心问题是其模式是"全量上下文"传输，而非渐进式披露结果。当运行一个脚本时，MCP 会将整个上下文都返回，这在很多场景下是不必要的开销。相比之下，CLI 模式更加轻量，只返回结果，由调用方决定如何处理。这也解释了为什么 Skills 逐渐占据了智能体应用的主场 —— Skills 更加灵活，可以根据需要选择性地暴露功能。

对于开发者而言，这一趋势意味着在设计 Agent 工具时，应该优先考虑简单、可组合的接口，而非复杂的协议栈。Y Combinator CEO Garry Tan 更是直言"MCP sucks"。不过，MCP 的探索仍然有价值，它推动了社区对 Agent 工具标准化的思考，只是最终形态可能不是 MCP 本身。

快手智能 Code Review 系统的三阶进化之路

快手研发效能团队分享了智能代码审查系统的架构演进历程，从"纯 LLM 启发式"到"知识引擎+规则确定性"，再到"Agentic 自主决策"的三代架构。针对 AI 幻觉这一核心问题，团队通过构建上下文引擎与沉淀 1100+ 条确定性规则，辅以三层过滤与 BadCase 反例库，将评审采纳率从 7.9% 跃升至 54%，MR 评审时长 80 分位显著缩短 9.9%。

核心经验包括：1）知识工程是提升大模型准确性的关键，纯依赖 LLM 的启发式判断容易产生幻觉；2）确定性规则与 AI 能力相结合，在关键路径上使用规则兜底；3）建立 BadCase 反例库持续迭代优化。这一案例为 AI 时代如何实现"个人提效→组织提效"的传导提供了可复用的实践样本，尤其适合正在考虑引入 AI Code Review 的技术团队参考。

Reddit CLI：终端里的 Reddit 客户端

开发者 jackwener 开源了 rdt（Reddit CLI），这是一个功能完善的 Reddit 终端客户端。支持查看 feed、浏览 subreddit、搜索帖子、阅读评论树、导出结果，甚至支持 upvote/save/subscribe 等基础交互。特色功能包括：短索引操作（如 rdt show 3）、自动从浏览器提取 Cookie 登录、支持 JSON/YAML 输出方便脚本和 AI agent 集成。对于习惯在终端工作的开发者，这是一个高效浏览 Reddit 的工具。项目地址：github.com/jackwener/rdt。同系列还包括 Twitter CLI、小红书 CLI、B站 CLI、Telegram CLI、Discord CLI 等，正在构建完整的 CLI 宇宙。

Sub2API：自建 Claude Code 中转站

Sub2API 是一个开源的 API 中转方案，可以将 OpenAI、Google、Anthropic 等订阅转换为 Claude Code 可用的 API。部署简单，只需在服务器安装 Redis 和 PostgreSQL，执行一键安装脚本即可。安装后提供 Web 界面进行配置，支持多账户管理、额度控制和 API Key 生成。对于需要稳定使用 Claude Code 但受限于地区或支付方式的开发者，这是一个实用的解决方案。项目地址：github.com/Wei-Shaw/sub2api。

Kaku 0.7：现代化终端模拟器

Kaku 是一个基于 WezTerm 但经过大量重构的终端模拟器，移除了大量代码并添加了许多实用改进。0.7 版本新增了透明度和毛玻璃效果支持，界面更加精致。内置了 yazi、lazygit 等常用工具，支持亮色/暗色/自动主题切换。新增关闭窗口保护（防止 AI 编程会话中误触 cmd+w），支持 cmd+shift+t 恢复误关窗口。还集成了 AI 功能 kaku ai，支持 Antigravity 模型配置。对于追求美观和效率的开发者，Kaku 是一个值得尝试的终端选择。

OpenClaw 控制中心：Agent 监控面板

Learn Claude Code：从零实现 AI Agent 的 12 节课

这是一个开源教育项目，用 12 节课从零开始搭建一个类似 Claude Code 的 AI Agent。每节课只增加一个机制，都有可运行的 Python 代码。核心洞察是：所有 AI 编程 Agent 的底层都是同一个循环 —— 用户发消息给模型，模型决定调用工具，执行后把结果反馈，循环直到任务完成。整个 Agent 的最小实现不到 30 行代码。12 节课涵盖：核心循环、工具调用、计划能力、子 Agent、技能加载、上下文压缩、任务持久化、后台执行、多 Agent 协作等。项目配有交互式 Web 平台，支持中英日三种语言。对于想深入理解 Agent 内部原理的开发者，这是目前最好的从零到一的学习路径。

Simon Willison 谈 Agentic Engineering

Simon Willison 在 Pragmatic Summit 的分享中谈到了 AI 编程工具采用的不同阶段：从最初用 ChatGPT 提问，到使用 coding agents 写代码，再到 agent 写的代码超过自己写的代码 —— 这是一个重要的转折点。他还提到了"vibe coding"（氛围编程）的概念：开发者描述想要的效果，由 AI 来实现具体代码，开发者主要负责审阅和调整。这种范式转变正在重新定义软件工程师的角色，从"写代码的人"变成"指导 AI 写代码的人"。对于还在观望 AI 编程工具的开发者，Willison 的建议是：从实际项目开始，找一个具体的问题让 AI 帮你解决，在实践中学习如何与 AI 协作。
