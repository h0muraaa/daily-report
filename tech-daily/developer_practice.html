NEWGoogle I/O 2026 发布 Gemini 3.5 Flash：速度 4x、价格腰斩、代码能力超越上代旗舰

Google 在 I/O 2026 大会上发布了 Gemini 3.5 Flash，这是今年开发者最关心的模型更新。官方数据显示，3.5 Flash 的输出速度是其他前沿模型的 4 倍（每秒 289 token），同时 Benchmark 表现全面超越上一代旗舰 3.1 Pro。

NEWGoogle Antigravity CLI 发布：在终端里直接跑 Agent

Google 推出了 Antigravity CLI，让你可以直接从终端启动与 Antigravity 平台相同的 Agent harness。这不是一个简单的 API 客户端，而是一个完整的终端原生体验：适配你的快捷键、主题和工作流。

配合同时发布的 Antigravity SDK，开发者可以在自己的基础设施上完全自定义和部署 Agent。SDK 提供与 Gemini 优化相同的 harness，灵活性极高。此外，Google AI Studio 现在支持 "Managed Agents" —— 一个 API 调用就能获得一个完整的 Agent，包含代码执行、网页浏览和文件管理功能，运行在一个隔离的 Linux sandbox 中。

你可以在 AGENTS.md 和 SKILL.md 文件中定义自定义 Agent 行为，挂载 GitHub 仓库、GCS bucket 或内联文件到环境中。对于想要快速原型 Agent 的开发者来说，这套工具链大大降低了入门门槛。

# 安装 Antigravity CLI
npm install -g @antigravity/cli && antigravity init

# 创建一个带 sandbox 的 managed agent
curl -X POST "https://ai.google.dev/gemini-api/agents" \
  -H "Authorization: Bearer $API_KEY" \
  -d '{"model": "gemini-3.5-flash", "tools": ["code", "web", "file"]}'

NEWPerplexity 开源查询感知压缩技术：上下文减少 70%，质量反而提升

Perplexity 发布了他们的查询感知上下文压缩（Query-Aware Compression）系统的技术细节。这不是简单的截断或摘要，而是一个针对查询动态优化、保留引用、且速度足够快可用于生产编排的系统。

关键数据：上下文 token 减少最多 70%，同时回答质量提升；每片段有效内容提升 63%（通过剔除广告、导航、元数据和低价值内容）；在 SimpleQA 上达到 50 倍压缩比，同时保持前沿级性能。

技术原理上，这套系统在将内容交给回答模型之前，先根据查询语义进行智能筛选和压缩，保留与问题最相关的段落和引用信息。对于需要处理大量检索结果的 RAG 系统开发者，这是一个值得深入研究的方向。

Google I/O 2026 的 Agent 生态：从辅助工具到独立智能体

今年 Google I/O 的核心叙事非常明确：从 assistive AI（辅助式 AI）转向 independent agents（独立智能体）。这不仅仅是营销话术，而是一整套技术栈的重新定位。作为开发者，我们需要理解这个生态的层次结构：

模型层 — Gemini 3.5 Flash：这是整个生态的基石。速度 4x 的意义不仅仅是"更快"，而是让 Agent 可以在合理时间内完成多步骤任务。Terminal-Bench 76.2% 和 MCP Atlas 83.6% 意味着它在代码执行和工具调用方面已经具备了可靠的自主能力。

运行层 — Agent Executor + GKE Agent Sandbox：Google 开源了 Agent Executor，一个分布式 Agent 运行时标准，支持持久执行（断点恢复）、人机协同确认（HITL）和分布式部署。GKE Agent Sandbox 在 5 个月内增长了 16 倍，LangChain 和 Lovable 等关键客户已在生产环境部署数百万 Agent。这解决了一个长期痛点：Agent 工作流运行 hours 甚至 days 时的可靠性问题。

开发层 — Antigravity + AI Studio：Antigravity CLI/SDK 让开发者可以在终端或自己的基础设施上运行 Agent。AI Studio 的 Managed Agents 则是一个 API 调用获得完整 Agent（sandbox + 代码执行 + 网页浏览 + 文件管理）。Chrome DevTools for agents 和 WebMCP 提案则表明 Google 正在将 Agent 能力延伸到浏览器端。

对开发者的建议：如果你正在评估 Agent 平台，Google 今年的布局值得认真考虑。从模型到运行时的完整垂直整合，加上有竞争力的定价（3.5 Flash 比 Claude Sonnet 便宜 40%），构成了一个对开发者友好的完整栈。不过生态成熟度仍需观察，特别是与 LangChain、LlamaIndex 等现有框架的集成情况。

上下文压缩：RAG 系统的下一个优化前沿

Perplexity 的查询感知压缩技术值得单独拿出来分析，因为它触及了当前 RAG 系统的一个核心瓶颈：检索结果往往太长，而模型上下文窗口虽然越来越大，"更多上下文"并不总是等于"更好答案"。

Perplexity 的方案有几个技术亮点：

1. Query-aware：压缩不是静态的，而是基于具体查询动态决定保留哪些内容。这与传统的摘要方法有本质区别。

2. Citation-preserving：压缩过程中保留引用信息，确保答案的可追溯性。这对需要事实核查的场景至关重要。

3. Orchestration-ready latency：速度足够快，可以作为生产编排流水线的一环，而不是离线预处理。

从实现角度看，这套系统的效果数据很亮眼：50 倍压缩比下仍保持前沿性能，每片段有效内容提升 63%。这暗示他们的压缩算法能够精准识别并剔除低信息熵内容（广告、导航模板、重复结构）。

实践建议：如果你正在构建 RAG 系统，不要默认将所有检索结果塞进 prompt。考虑在检索层和生成层之间加入一个压缩/重排序层。Perplexity 的博客提供了很好的参考思路，但具体实现可能需要根据你的数据特征调整。

[来源: Perplexity Research Blog]

用 Manus AI 构建自动化工作流

freeCodeCamp 发布了一套完整的 Manus AI 教程。Manus 与普通聊天机器人的区别在于它是一个真正的 AI Agent：在隔离的云计算机（sandbox）中运行任务，可以浏览实时网页、编写和执行代码、与真实网站交互，并处理复杂的多步骤流程，无需你逐歩指导。

教程涵盖从免费账户设置到构建自定义自动化、程序化操作的全部内容。你将学习如何运行深度网页研究、自动化数据处理流程，以及将 Manus 集成到自己的工具链中。

Andrew Ng 新课：构建生成图像和视频的 AI Agent

吴恩达发布了新课程《Build AI agents that generate images and videos》，与 Google Cloud 合作开发。课程核心思想是：让 Agent 评估自己的输出并迭代改进质量。

三种评估技术的组合实践：图像-文本相似度评分（验证输出是否符合 prompt）、LLM Judge（按自定义标准如品牌一致性评分）、结构化评分表（将 prompt 拆解为可验证的是/否问题如"主体是否在画面中？"）。课程包含构建将品牌指南转为 UI mockup 的图像 Agent，以及视频生成 Agent 的完整项目。
