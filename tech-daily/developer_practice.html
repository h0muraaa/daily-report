Vercel 将 Hobby 用户 Blob Store 上限从 5 个提升到 100 个

对于用 Vercel Hobby 方案做 side project 的开发者来说，存储组织一直是个小痛点：原本最多只能建 5 个 Blob store，项目一多就要把不同环境或不同业务的数据挤在一起。现在上限直接放宽到 100 个，意味着可以按项目、环境或区域更细粒度地拆分数据。需要注意的是，存储容量、操作次数和流量限制仍然保持不变，只是 store 数量变多了。

来源：Vercel News

shadcn 开源 /improve skill：把「最强模型做计划、便宜模型执行」落地成代码

shadcn 发布了 improve skill，核心思路是只做「计划层」：用最强的模型深入理解代码库、发现问题并产出高质量改进方案，但 skill 本身不直接改代码，具体执行交给更便宜的模型或工具。这个思路把「智力当作可借用的资源」——趁前沿模型可用时榨取高质量计划，等到它不可用或涨价时，再用低成本方式执行。

对日常开发来说，这相当于给代码库配了一个永不疲倦的架构审查员：它先输出可执行的任务清单，你再决定让哪个 agent 或模型去改。四天拿到 3.7K star 也说明开发者对这种「plan-first」模式很买账。

来源：GitHub: shadcn/improve · 参考 Viking 的推文

Browser Use 插件正式接入 Claude Code

Browser Use 现在可以通过 Claude Code 的插件市场安装，命令是 claude plugin marketplace add browser-use/plugins。这意味着 Claude Code 里的 agent 可以直接获得更结构化的浏览器操作能力，比如把任意网页转成干净的 Markdown 或 JSON、渲染 JavaScript、绕过 Cloudflare 和机器人拦截，并支持批量抓取。

对于需要频繁从网页提取数据或做自动化测试的开发者，这减少了写一次性 scraper 的成本；同时 Browser Use 也发布了 fetch-use，一个 curl 风格的 API，可以把任意 URL 转成 clean JSON。

来源：Browser Use · fetch-use 文档

华为昇腾 950DT 与 DeepSeek V4 协同设计：国产芯片开始主动定义模型推理路径

SemiAnalysis 对华为昇腾 950DT 做了 Trace 级拆解，发现 DeepSeek V4 的部分架构是「为华为昇腾推理进行协同设计」的。这不是简单的适配，而是芯片、模型推理路径和软件栈一起打磨。报告认为，这可能会成为 DeepSeek 从英伟达底座迁移到国产昇腾底座的关键节点。

对开发者来说，这件事的意义在于：国产 AI 芯片正在从「能不能跑大模型」转向「能不能支撑顶级模型的低成本、高并发推理」。如果你在做国产算力部署或推理优化，950DT + DeepSeek V4 的组合值得持续跟踪。

来源：InfoQ

Uber 用批处理把单个账户更新能力提升到每秒 30+ 次

Uber 的财务账本平台采用复式记账，天然要求同一账户的更新严格串行。当大量调账、对账或运营修正集中落到同一个热点账户时，传统的「一次请求一次事务」会很快触顶。新方案把多次更新批量合并：先聚合请求、再做一次统一的校验和余额计算、最后持久化。

结果是在保持严格一致性和审计可追溯的前提下，单账户每秒处理超过 30 次更新。这对任何需要高并发写入同一账户或同一实体的系统——比如支付、钱包、积分、库存——都有参考价值：热点账户问题的解法不一定是分片，也可以是更聪明的批处理。

来源：InfoQ

Pyodide 轮子可以直接发布到 PyPI 了

Pyodide 314.0 支持把为 WebAssembly 编译的 Python 扩展（C/C++/Rust 等）打包成 wheel，直接上传到 PyPI，运行时再安装。这意味着浏览器端的 Python 生态不再依赖 Pyodide 维护者手动审核和构建那 300 多个包，普通包的维护者可以像发 Linux/macOS/Windows 轮子一样发 WASM 轮子。

对想做浏览器端数据工具、教育应用或无服务端 Python 交互体验的开发者，这是一个重要的基础设施变化。Simon Willison 已经做了 luau-wasm 的示例发布，完整流程见他的博客。

来源：Simon Willison's Weblog · 参考 Simon Willison 推文

鸿蒙 HarmonyOS 向 Agent 架构演进，小艺成为「长在系统里的智能体」

在 HDC 2026 上，华为展示了小艺的新能力：用户一句话就能跨日程、地图、时钟、网约车等多个应用完成复杂任务。背后是 HarmonyOS 向 Agent 架构的整体演进，基于鸿蒙智能体框架 2.0，小艺从「语音助手」变成了系统智慧大脑。

这对移动开发者有直接启示：未来的交互入口可能从「用户找应用」变成「意图即服务」。如果你的应用还没有把核心能力拆成可被系统 Agent 调用的原子化服务，未来可能会失去被调用的机会。

来源：爱范儿

Ponytail：让 AI coding agent 像「最懒的高级开发」一样写代码

Ponytail 是一个给 AI coding agent 用的插件/工作流，核心逻辑是六层 YAGNI 检查：真的需要写吗？标准库有吗？平台原生支持吗？依赖里有吗？能一行搞定吗？最后才写最小代码。据分享者给出的数据，这种模式能让 agent 产出 80–94% 更少的代码、47–77% 更便宜、3–6 倍更快。

例子很直观：agent 本来要写一个完整 date picker + wrapper + 逻辑，Ponytail 会直接让它用 <input type="date">。这其实是把「 senior review 」的价值观编码成 agent 的默认行为，对减少 AI slop 代码很有效。

Claude Fable 5 被禁：开发者应如何看待「基础设施风险」

6 月 9 日发布的 Claude Fable 5，在 6 月 12 日因美国政府出口管制指令被全面禁用，连美国境内的外籍人士和 Anthropic 自己的外籍员工都无法访问。这不是一次普通的 API 调整，而是前沿模型首次因国家安全理由被国家级召回。

对开发者最直接的教训是：不要把关键链路完全绑定在单一闭源 API 上。Fable 5 很强，但当访问权限可以被行政指令瞬间收回时，它就不是稳定的基础设施。更务实的做法是：把闭源模型当作「能力加速器」——趁可用时提取高质量计划、设计、测试用例，然后用开源模型或自有部署完成执行。shadcn 的 /improve 思路、baoyu-design 用 skill 把 Claude Design 移植到其他模型上，都是这种「智力借用」策略的具体实践。

另一个值得关注的替代是智谱 GLM-5.2，它承诺下周开源、MIT 协议、支持 1M 上下文。虽然性能还需要实测，但它至少提供了一条「不会被单方面收回」的路径。对正在选型或做架构设计的团队，现在正是评估多模型备份和本地/私有部署方案的时候。

模型层 vs Harness 层：为什么 Codex 还没有「Claude Design」

宝玉在推文中把 AI 产品拆成了两层：模型层（Claude Opus 4.8、GPT-5.5 等）和 Harness 层（Codex、Claude Design 等产品形态，包括提示词、工具链、UI 流程）。同一个 Harness，换不同模型，效果可能完全不同。Claude Design 的技术门槛不在 Harness，而在模型能否生成高精度、可交互的原型。

这个框架对开发者选型很有帮助。很多人看到 Claude Design 效果好，就以为「prompt + 工具」可以复制到任意模型；但实际上如果底层模型对空间布局、状态交互、视觉细节的理解不够，再好的 Harness 也做不出可用原型。反过来说，如果你自己的模型能力足够，完全可以复刻类似的 Harness。宝玉已经做了 baoyu-design 的概念验证，把 Claude Design 的 skill 逻辑迁移到其他模型。

📋实践指南

给 Agent 的任务必须包含「验收标准」

宝玉分享了一个一旦养成就很难改回去的习惯：给 agent 交代任务时，把「怎么验证这个结果是对的」一起说清楚。做法是先把 coding plan 写出来，反复确认后汇总成 task 列表，再进入编程阶段，并让 agent 逐项标记完成。

实践建议：在 prompt 里加入「完成标准」小节，列出可检查的输出物或测试命令。agent 会自己把中间结果对齐到这些标准，你不需要逐行盯进度。

来源：宝玉(@dotey)

2026 年建网站，什么比技术栈更重要

freeCodeCamp 的一篇文章指出，React、Vue、Svelte、Laravel、Django 这些框架之间的争论已经没那么关键了。现代网站用任何成熟框架都能跑得不错，真正决定成败的是：可发现性（SEO / AI 搜索可见性）、性能、基础设施、结构化数据和用户信任。

实践建议：新项目选型时，优先选团队最熟悉的成熟框架，把省下的时间投入到 Core Web Vitals、结构化数据、语义化 HTML 和 AI 搜索可抓取性上。

来源：freeCodeCamp

长时运行 coding agent 的经验

elvis 在一场关于自主长时运行 coding agent 的讨论中总结了几个关键点：目标要极度清晰、要有验证器（verifier）防止 reward hacking、用 /goal 和 /loop 这类命令把长期目标拆成可检查的短期目标、允许动态工作流而不是硬编码 pipeline。

实践建议：不要让 agent 一次性跑完一个宏大任务。先让它生成可验证的里程碑，每个里程碑完成后做一次人工或自动验收，再继续下一步。
