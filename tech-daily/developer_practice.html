微软开源 SkillOpt：像训练神经网络一样训练 Agent 技能文档
架构
微软本周开源了 SkillOpt，一个将 Agent 技能文档视为「可训练参数」的文本空间优化框架。核心洞察是：Agent 的技能文档就是它的「外部权重」，既然内部权重可以用梯度下降优化，外部权重也应该有系统化的训练方法。在 7 个目标模型、6 个基准测试、3 种执行环境的全部 52 个评测组合中，SkillOpt 训练出的技能文档全部达到最优或并列最优。这意味着开发者不再需要反复手调 prompt 或 skill 文件，而是让技能文档自我进化。对于大量使用 Claude Code、Codex 等工具的开发者来说，这可能会改变「教 AI 怎么干活」的工作方式。
[来源: 机器之心]
Zod 作者推出 Pullfrog：跑在 GitHub Actions 里的开源 AI 编程 Agent
工具
Colin McDonnell（Zod 验证库作者）发布了 Pullfrog，一个定位为 CodeRabbit 开源替代品的 AI 驱动 GitHub bot。与 CodeRabbit 不同，Pullfrog 完全运行在 GitHub Actions 内部，采用 BYOK（自带密钥）模式，支持 Anthropic、OpenAI、Google、Mistral、DeepSeek 和 OpenRouter 等多家 LLM 提供商。它可以监听 webhook，根据 PR、issue、CI 失败等事件触发 AI agent 运行。所有 API key 通过 GitHub Secret 管理，agent 在仓库自己的 GitHub Actions 环境中执行。对于希望在私有仓库中使用 AI Code Review 又不想把代码交给第三方 SaaS 的团队，这是一个值得关注的方案。

发布
DuckDB 正式推出了 Quack，一个全新的 HTTP 远程协议，让多个 DuckDB 实例可以通过网络连接并操作同一个数据库。这是一个重要的架构演进——DuckDB 此前主要作为本地嵌入式数据库使用，Quack 为其引入了真正的客户端-服务器能力。对于数据分析师和构建轻量级数据应用的开发者来说，这意味着可以在保持 DuckDB 高性能的同时，实现多用户协作访问。该协议设计简洁，不需要复杂的部署配置，适合在现有基础设施中快速集成。

Arm 开源 Metis：基于语义推理的 AI 安全框架，超越传统 SAST
安全
Arm 开源了 Metis，一个 agentic AI 安全框架，与传统基于模式的 SAST 工具不同，Metis 应用语义推理来分析跨组件依赖关系，并为发现的漏洞提供清晰的自然语言解释。随着 AI 生成代码的普及，传统静态分析工具在检测复杂逻辑漏洞方面的局限性越来越明显。Metis 的思路是用 AI 来审计 AI 生成的代码，通过理解代码的语义而非仅仅匹配模式来发现深层问题。对于关注 AI 代码安全性的团队，这是一个值得接入 CI/CD 流程的新选择。

安全

🔬 深度技术解读

Build Agents, Not Pipelines：LLM 程序设计的范式转移

Sean Goedecke 在一篇引人深思的文章中提出了一个核心观点：使用 LLM 的程序只有两种结构——pipeline（管道）或 agent（智能体）。Pipeline 是你用代码表达程序的控制流，比如先收集上下文、再调用 LLM 总结、再解析结果、最后发邮件。Agent 则是你给 LLM 工具，让它自己管理控制流。

两者的区别类似库和框架：使用库时你定义控制流，使用框架时框架定义控制流。作者认为 agent 架构更适合复杂任务，因为 LLM 可以动态决定调用顺序、处理异常、甚至自我修正。但在实践中，许多开发者过度使用 pipeline——把本该交给 LLM 决策的流程硬编码在代码里，导致系统僵化且难以维护。

这个框架可以帮助开发者在设计 AI 功能时做出更清晰的架构选择：简单、确定性的任务用 pipeline；复杂、需要灵活决策的任务用 agent。特别值得注意的是，作者强调不要把 agent 当作「更高级的 pipeline」来用——如果你发现自己在写大量工具调用编排代码，可能应该反过来让 agent 自己决定。

[来源: seangoedecke.com]

微软 SkillOpt：让 Skill 文档自我进化的技术原理

SkillOpt 的核心思路可以概括为「将自然语言技能文档视为可优化的外部权重」。具体来说，它使用了一种文本空间优化方法：不修改模型本身的权重，而是迭代优化指导 Agent 行为的自然语言文档。训练过程中，SkillOpt 会在多个任务上评估当前技能文档的效果，然后根据反馈信号调整文档内容——这个过程类似于 prompt 工程，但是自动化、系统化、可规模化的。

这项工作的意义在于，它把「写 skill 文件」这个当前大量消耗开发者时间的手工活，转化成了一个可自动优化的机器学习问题。在 52 个评测组合中全部达到最优或并列最优的结果表明，机器优化的 skill 文档质量至少不逊于人工精心编写的版本。对于维护大量 Claude Code、Codex skill 文件的开发者团队，这可能会显著降低维护成本。

[来源: GitHub - microsoft/SkillOpt]

📋 实践指南

用 Codex / Claude Code 调试网络请求的两种方法

开发网页应用时调试 API 交互不再需要手动复制粘贴网络请求数据。方法一：在 Chrome DevTools Network 面板导出 .har 文件，直接发给 Codex 分析。方法二：安装 Codex 官方 Chrome 扩展，在消息中 @chrome 即可让 Codex 直接使用浏览器调试、抓包。这两种方法都能让 Agent 自主获取完整的请求/响应信息，大幅缩短排查 API 问题的时间。

[来源: 宝玉 @dotey]

Sandcastle：多 Agent 编排工作流

当需要同时调度 Codex、Claude Code、Cursor、GitHub Copilot 等多个 Agent 完成同一任务时，可以使用 Matt Pocock 开源的 Sandcastle。这是一个用 TypeScript 编写的 Agent 编排框架，支持在虚拟机中运行工作流。典型场景：让多个 Agent 各出一套技术方案，再相互打分完善——俗称「赛博养蛊」。虽然对普通用户过于极客，但适合追求极致效果的复杂任务场景。

[来源: 宝玉 @dotey]

SpringBoot 树形结构从 3s 优化到 30ms 的实战经验

一个生产环境中的真实案例：15000 个分类节点的树形结构加载需要 3-5 秒，高峰期导致数据库连接池耗尽。根本原因是传统递归查询产生的 N+1 查询问题。优化方案：改用一次性查询所有节点后在内存中构建树结构，将 15000 次数据库查询降为 1 次。响应时间从 3 秒降到 30 毫秒，性能提升 100 倍。核心教训：树形结构不要递归查询数据库，先全量拉取再内存组装。

[来源: dbaplus社群]

AI Code Review 实战：Review Forge 流程

当 AI 代码产出速度超过人工 review 能力时，代码质量会迅速下降。Viking 分享了「Review Forge」流程来规范 AI 代码审查：建立标准化的 review 检查清单，让 AI 辅助进行代码审查，重点关注架构一致性、安全漏洞和性能问题。核心原则是在享受 AI 编码效率的同时，保持对代码变更的可见性和控制力，避免系统变成不可维护的黑盒。
