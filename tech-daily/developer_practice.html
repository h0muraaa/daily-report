OpenRouter 推出 Response Caching：为 Agent 测试和重试节省大量成本

OpenRouter 正式发布 Response Caching 功能，允许开发者缓存 API 响应以节省测试和 Agent 重试场景下的成本。该功能完全免费，支持通过 X-OpenRouter-Cache-TTL 头部自定义缓存生命周期（1 秒到 24 小时，默认 5 分钟），也可通过 X-OpenRouter-Cache-Clear 清除特定条目。缓存按 API key 隔离，命中缓存的请求不会计入供应商速率限制——因为请求根本不会到达上游提供商。响应头会返回 HIT/MISS 状态和 Age/TTL 信息，便于调试。

对于频繁运行测试套件或 Agent 反复调用相同提示的场景，这是一个直接降低账单的功能。当前处于 Beta 阶段。

OpenRouter 新增 "-latest" 模型别名：像 semver 一样路由到最新模型

OpenRouter 引入了语义化版本风格的模型别名机制。开发者现在可以请求 ~anthropic/claude-opus-latest 或 ~openai/gpt-latest 等别名，系统会自动路由到对应系列的最新版本。这解决了生产环境中模型版本更新的痛点——不再需要手动追踪每个提供商的模型 ID 变更。灵感来自 npm 的 semver 约定，用 ~ 前缀表示"最新补丁版本"。

对于需要紧跟模型前沿但又不想频繁修改代码的团队，这个设计非常实用。

DeepSeek-VL 多模态新论文：用空间标记（Bounding Box / Point）嵌入思维链解决视觉推理

MCP vs Skills：Agent 能力扩展的两种范式如何选择

ByteByteGo 本周深度剖析了 MCP（Model Context Protocol）与 Skills 两种 Agent 能力扩展机制的区别与适用场景。MCP 是 Anthropic 推动的开放协议，旨在标准化 AI 模型与外部工具/数据源之间的通信；Skills 则是更轻量、更内聚的功能模块概念，通常绑定在特定平台或框架内。

核心区别在于：MCP 强调互操作性——一个 MCP server 可以被任何兼容的 client 使用，适合需要跨工具、跨团队协作的场景；Skills 强调内聚性和易用性——通常带有预设的提示模板、错误处理和上下文管理，适合快速构建特定工作流。当前生态中，Claude Code 和 Codex 都在向 Skill/MCP 混合模式演进。

实践建议：如果你正在构建内部工具链，优先评估团队现有系统是否已有 MCP server 生态；如果是面向终端用户的产品功能，从 Skill 的封装性和体验一致性出发可能更高效。两者并非互斥——LangChain 已经在 deepagents 中同时支持 Browserbase 的浏览器子 agent 和 MCP 工具调用。

工具推荐

OpenAI Codex「Computer Use」—— 让 Agent 真正"看见"你的屏幕

Codex App 的 Computer Use 功能可能是近期最被低估的 Agent 能力升级。它通过 macOS 的屏幕录制（Screen Recording）和辅助功能（Accessibility）两项系统权限，让 Codex 能够直接观察 GUI、移动鼠标、敲击键盘，操作 macOS 上的图形界面应用。

什么时候用它：

  • 测试 macOS app 或 iOS 模拟器流程
  • 复现只在 GUI 中出现的 bug
  • 修改必须点 UI 才能改的应用设置
  • 查看没有 API/插件接入的数据源
  • 跨多个应用协作的复杂工作流

触发方式：在 prompt 中 @ Computer Use 或直接 @ AppName（如 @ Chrome），清晰描述目标应用、窗口和操作流程。最有价值的用法是"操作 -> 改代码 -> 再跑同一流程"的闭环：让 agent 自己验证自己的修改。

重要原则：本地开发的 Web 应用优先用 Codex 自带的 in-app browser；目标应用如果有专属 plugin/MCP server，优先走结构化集成，Computer Use 仅用于必须"视觉操作"的场景。

构建 3 层上下文系统，让 AI 不生成"垃圾"原型

Peter Yang 在即将发布的节目中分享了 Ravi 的 3 层上下文系统，解决"给 AI 一行提示就抱怨输出像 slop"的问题：

Functional Layer（功能层）：应用做什么，核心业务流程是什么
Visual Layer（视觉层）：应用长什么样，设计系统和组件规范
Data Layer（数据层）：数据结构如何工作，API 契约和状态管理

其中数据层是最被低估的。在提示中包含数据模型、API 响应结构、状态流转逻辑，能让 AI 生成的原型具备真正的灵活性——而不是只能处理硬编码的演示数据。这适用于 Codex、Claude Code、v0 等所有 AI 代码生成工具。

Simon Willison 模式：用手机 + Claude Code for Web 构建完整功能
