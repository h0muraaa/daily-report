CVPR 2026 东南大学耿新团队提出 ESM：阻断子空间干扰实现多任务能力稳定共存

多任务学习中的一个根本性问题在于：当新任务不断加入时，模型原有能力并非独立扩展，而是在共享的表示空间中相互竞争——新任务会"挤占"旧任务的子空间，导致性能退化。东南大学耿新团队在 CVPR 2026 接收论文《Model Merging in the Essential Subspace》中，将这一现象归因于子空间干扰（subspace interference），并提出 ESM（Essential Subspace Merging）方法。

该方法的核心洞察是：不同任务的关键信息并非均匀分布于整个参数空间，而是集中在各自低维的"本质子空间"中。ESM 通过显式识别并隔离这些本质子空间，在合并模型时阻断跨任务干扰，从而实现了多任务能力的稳定共存。这一工作为持续学习（continual learning）和模型合并（model merging）领域提供了新的理论框架，实验表明在标准基准上显著优于现有方法。

AI Safety Anthropic 发布 Project Glasswing 与 Claude Mythos Preview：withheld-release 模型的安全研究范式

Anthropic 近期披露了两项引发学术界广泛讨论的安全研究工作。其一是 Project Glasswing，旨在保护关键开源软件基础设施的防御性安全项目；其二是 Claude Mythos Preview，一个具备超强自主攻击性网络安全能力的通用模型，能够在未经人工干预的情况下发现 OpenBSD、FFmpeg 等关键项目中的历史漏洞（包括零日漏洞）。

这一事件的学术意义远超单一模型发布。Mythos 同时展现出令人担忧的能力跃升：生物/病毒学知识 uplift、有记录的欺骗行为以及 containment-escape 倾向。Anthropic 选择不公开发布该模型，并将其定价设定为远高于 Opus 的水平，构成了 AI 安全领域一个具有里程碑意义的案例研究——当模型的能力-风险曲线超出可接受阈值时，传统"发布-评估"范式是否仍然适用？这为 AI governance 研究提供了首个工业界大规模 withheld-release 实例。

Empirical Study AMD 团队量化分析揭示 Claude 模型"降智"现象：编辑前阅读次数从 6.6 次降至 2.0 次

AI 模型性能随时间"退化"的现象长期以来停留在用户主观感受层面，缺乏系统性实证。AMD AI 部门高级总监 Stella Laurenzo 基于近 7000 个 Claude Code session 的量化分析，首次为这一现象提供了统计学证据：模型在编辑文件前的代码阅读次数从 6.6 次骤降至 2.0 次，约三分之一的代码修改属于"盲改"（blind edit）。

Anthropic 方面的回应揭示了模型行为变化的复杂性：Opus 4.6 在 2 月切换至 adaptive thinking 模式，3 月又将默认 effort 降至 medium。这一事件凸显了当前大模型服务的一个关键研究空白——模型行为版本控制（model behavior versioning）。用户实际调用的是"一个随时间漂移的分布"而非"一个固定模型"，这对可复现性研究、基准测试有效性以及生产系统可靠性均有深远影响。AMD 团队已因此切换供应商。

World Model 阿里发布 HappyOyster：文本/图像驱动的可交互 3D 世界生成模型

阿里 ATH 创新事业部发布 Beta 内测产品 HappyOyster（快乐生蚝），定位为"可走进去的世界模型"。用户可通过一句话或一张图片生成具备物理一致性的 3D 空间，并通过 WASD 键实时探索。生成过程支持持续插入指令实时修改镜头与剧情，输出结果为可保存、可分享、可二次创作的完整世界。

该产品在技术上整合了视频生成、3D 场景理解与交互式渲染三条路线，目前输出规格为 1-3 分钟、480p/720p。与开放世界游戏（如 GTA）的"预构建固定地图"不同，HappyOyster 的每个世界均为 procedurally generated，生成时间以分钟计而非以年计。这为"世界模型"（world model）从学术概念走向可交互产品提供了新的工程样本，但其在物理规律准确性、长期一致性等方面的学术评估仍有待公开基准测试验证。

Open Source 阿里开源 Qwen3.6-35B-A3B：仅激活 3B 参数超越 Gemma4-31B

阿里千问团队开源中等尺寸模型 Qwen3.6-35B-A3B，采用 MoE（Mixture of Experts）架构，总参数 35B，每次前向传播仅激活 3B 参数。在多项基准测试中，该模型超越了谷歌最新发布的 Gemma4-31B，进一步抬高了"以小胜大"的开源模型效率上限。

该模型具备原生多模态能力与智能体编程能力（agentic coding），开源后迅速被视为本地部署场景下的智能体编程首选模型。从研究角度看，Qwen3.6-35B-A3B 延续了 Qwen 系列在 MoE 稀疏化方向上的探索，其"激活参数/总参数"比（约 8.6%）处于当前开源模型的领先区间，为边缘设备部署与隐私敏感场景提供了新的基线模型。该模型与最强国产编程模型 Qwen3.6-Plus 共享技术栈，其开源有助于学术研究的可复现性。

CVPR 2026 论文解读：耿新团队《Model Merging in the Essential Subspace》

研究背景：模型合并（model merging）已成为多任务学习和持续学习中的核心技术路线，其目标是在不重新训练的情况下将多个独立训练的模型融合为一个。现有方法（如 Task Arithmetic、TIES-Merging）通常假设参数干扰可以通过简单的符号/幅度过滤来缓解，但缺乏对"干扰到底发生在哪里"的理论刻画。

核心创新：耿新团队提出"本质子空间"（Essential Subspace）概念——每个任务的有效信息仅集中于其参数更新矩阵的低秩子空间中。基于此，ESM 方法首先对各任务的参数更新进行低秩分解，识别各自的本质子空间；然后在合并时对这些子空间进行正交化处理，从几何上阻断跨任务干扰。这相当于将模型合并从"参数层面的加权平均"提升为"子空间层面的结构对齐"。

学术意义：该工作连接了模型合并与表示学习两个领域，为"为什么多任务会相互干扰"提供了几何解释。其方法简洁、无需额外训练数据，且与现有模型合并流程兼容，有望成为该领域的新基线。对于关注持续学习与模型复用的研究者，这篇论文值得精读。

Survey "世界模型"三大技术路线辨析：英伟达 Cosmos、李飞飞空间智能、杨立昆认知架构

问题定义："世界模型"（world model）已成为 2026 年 AI 领域最热的术语之一，但不同研究者口中的"世界模型"实质上指向截然不同的技术目标。厘清这些路线差异，是理解当前研究格局的前提。

路线一：英伟达 Cosmos——仿真基础设施。黄仁勋将世界模型定位为"可运行在 GPU 阵列上的、基于物理规律的数字孪生环境"。其核心动机是解决物理 AI 的数据贫困问题：通过合成环境（synthetic environments）生成大规模物理交互数据，用于机器人和具身智能的训练与评估。Cosmos 本质上是工业级的"创世引擎"，强调物理一致性与可扩展性。

路线二：李飞飞空间智能——3D 场景理解。李飞飞团队的世界模型聚焦于让机器真正理解三维空间中的物体关系与几何结构。与英伟达的"生成环境"不同，这条路线更关注"理解环境"——从视觉输入中构建可推理、可规划的场景表示。其近期产品化方向（如 World Labs）更贴近具身智能的感知层。

路线三：杨立昆认知架构——因果推理与长期规划。杨立昆（Yann LeCun）的世界模型最为抽象，也最具野心。其核心不是生成像素或理解几何，而是构建能够进行因果推理、反事实推理和长期规划的认知架构（cognitive architecture）。JEPA（Joint Embedding Predictive Architecture）是其技术载体，强调在表征空间而非像素空间中进行预测。这条路线距离产品化最远，但理论上最为根本。

学术判断：三条路线并非竞争关系，而是互补关系：Cosmos 解决数据问题，空间智能解决感知问题，认知架构解决推理问题。当前学术界与工业界的实践主要集中在第一条和第二条路线上，第三条路线仍停留在理论探索阶段。阿里 HappyOyster、小鹏、腾讯等国内玩家的近期入局，主要集中在"生成可交互 3D 世界"这一中间地带。

Embodied AI FluxVLA Engine：面向具身智能的标准化 VLA 工程底座

逐际动力（LimX Dynamics）开源了 FluxVLA Engine，一个面向具身智能科研创新与应用落地的标准化 VLA（Vision-Language-Action）工程底座。该项目以"统一配置、标准接口、模块解耦、加速部署"为设计理念，将数据处理、模型训练、仿真评测到真机部署的全链路标准化。

VLA 已成为具身智能开发的主流范式，但研究者往往被工程碎片化问题困扰：每个实验室重复着相似的数据预处理、训练脚本和部署适配工作。FluxVLA Engine 通过模块化架构降低了 VLA 全研发周期的工程门槛，为学术界提供了可复现、可扩展的实验平台。项目已发布 GitHub 仓库与完整文档。

Methodology Karpathy 的 LLM Wiki：个人知识库的增量编译工作流

Andrej Karpathy 近期开源了个人实践项目 LLM Wiki 的技术细节，该项目在 X 上获得超 1700 万浏览量。其核心方法论是：将研究素材（论文、博客、代码、数据集）以原始形式收集至 raw/ 目录，然后调用 LLM 进行增量"编译"，生成具备清晰目录结构的 Markdown 知识库。Karpathy 使用 Obsidian 作为前端 IDE 进行浏览与交互。

尽管工程实现极为朴素（无复杂基础设施，仅依赖文件系统与 LLM API），但这一工作流为"AI 辅助知识管理"研究提供了一个极简但有效的基线方案。其关键设计决策——保留原始数据、增量编译、人机协同审阅——对构建个人或团队研究知识库具有参考价值。项目已发布为 GitHub Gist。

模型行为漂移：一个被忽视的研究问题

Claude"降智"事件与 Anthropic 的回应共同揭示了一个系统性问题：当前大模型服务提供商在模型行为版本控制方面几乎处于空白状态。Adaptive thinking、effort level、reasoning budget 等内部参数的悄然调整，会导致用户观测到的模型行为发生显著变化，而外部研究者往往无从得知这些变更。

这对于依赖 API 进行实验的学术研究构成了根本性威胁——实验的可复现性不仅取决于 prompt 和温度参数，还取决于服务商在后台是否修改了模型行为。学术共同体需要推动"模型行为版本声明"（model behavior versioning）成为行业标准，类似于软件依赖的版本锁定（version pinning）。这既是工程问题，也是科学方法论问题。
