1. 研究动态

编程基准的“意义鸿沟”

论文JetBrains Research 指出，当前主流编程基准在模型经过针对性训练的任务上得分飙升，但这些增益往往无法迁移到同一代码库的其他任务或不同基准上。该研究将发表于 Deep Learning for Code（DL4C）会议，呼吁重新对齐“可测量分数”与“真实编程能力”。

来源：JetBrains Research

Harness Engineering 驱动递归式自我改进

观点Lilian Weng 在最新博客中提出，近期递归式自我改进（RSI）不会直接表现为模型改写自身权重，而将首先体现在“harness”——围绕基座模型的运行时、工具调用、记忆与评估系统——的持续优化。她将 harness 类比为操作系统，归纳了工作流自动化、文件系统作为持久记忆等设计模式。

来源：Lilian Weng blog（经由 meng shao 推文）

来源：The GitHub Blog

2. 深度论文解读

The Benchmark Meaning Gap：编码基准到底测到了什么？

论文JetBrains Research 的这项工作指出，当前代码模型在“常见基准”上的分数提升存在严重过拟合风险：模型在训练时见过的任务类型上表现优异，但换到同仓库的其他任务或不同测试集时增益明显减弱。作者将这一现象称为“benchmark meaning gap”——即基准测量内容与研究社区真正关心的通用编程能力之间的错位。该论文将在 DL4C 2026 发表，对如何构建更鲁棒、更具迁移性的代码评估体系提出了具体方向。

学术意义：该研究提醒我们， leaderboard 单一数字不足以证明真实能力；未来应更多关注跨任务迁移、代码库级泛化、分布偏移下的稳定性，以及人类可验证的代码质量指标。这对模型训练目标与评估协议的重新设计具有重要参考价值。

来源：JetBrains Research

Harness Engineering：递归式自我改进的近期主战场

观点Lilian Weng 的最新博客将研究焦点从“模型智能”转向“运行时与软件系统”。她认为，真正的递归式自我改进（RSI）短期内不会通过模型直接重写自身权重实现，而是会通过不断改进 harness——即控制模型如何思考、规划、调用工具、感知上下文与评估结果的系统——发生。她将 harness 设计类比为操作系统：封装复杂逻辑、对外提供简洁接口，并归纳了工作流自动化、文件系统作为持久记忆等基础模式。

学术意义：该框架为自改进 agent、auto-research 和进化式程序搜索提供了一个统一的工程化视角，提示研究者应同时优化模型与 harness 层；同时，它也解释了 Claude Code、Codex 等 coding agent 成功的关键——基座能力与运行时系统的协同优化。

来源：Lilian Weng blog

4. 趋势观察

Agentic 平台从“原型”走向“生产”

Google Gemini API 的托管代理增强、AWS DevOps Agent 的发布管理、JetBrains 的团队级 AI 协调，以及 Vercel 的 eve 工具集，共同指向一个趋势：agent 开发正从“vibe coding”原型快速过渡到需要治理、安全、成本与版本控制的生产化系统。学术研究需要更多关注 agent 的可靠性、可审计性与多代理协同。

编码基准的有效性危机

JetBrains 的 benchmark meaning gap 研究揭示了 leaderboard 数字与真实能力之间的断裂。未来方向应是构建跨任务、跨代码库、难以被训练集污染的评估体系，并强调可解释性、维护性与长程工程影响，而非仅优化单一排行榜指标。

Harness 与运行时工程成为新的优化对象

Lilian Weng 的 harness engineering 框架提示，模型能力的边际提升需要与运行时系统（上下文管理、工具调用、记忆、评估）的协同进化。这可能会催生“面向 agent 的软件工程”作为新的研究方向，涉及 prompt 架构、workflow 语言、持久化记忆与自动评估的整合设计。

开源生态与开放权重模型持续扩张

GitHub Innovation Graph 的 Q1 数据与 Hy3、Kimi K2.7 Code 等开放模型共同显示，开源仍是 AI 领域创新的主通道。研究者应关注这些开放资源在真实开发场景中的可复现性、能效比与长期可维护性。
