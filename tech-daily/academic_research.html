黎曼猜想形式化证明获 Lean/Mathlib 认证，24 小时内即遭遇"无效"质疑

美国当地时间 11 月 21 日，Lean FRO 与 Mathlib Initiative 发布联合声明，对 Anthropic 数学家 Levent Alpöge 与 Claude 合作完成、约 1700 万行（分成 14 个压缩包）的 Lean 形式化证明表示"完全相信其正确"，并确认其证明的正是数学界研究 167 年的黎曼猜想。社区据以核验的四条标准全部满足：其一，命题本身正确，已收录进 Mathlib（RiemannHypothesis）并经由 Lean 与数论专家审校；其二，代码库可正确编译，数十人复现出同一份原始证明导出文件、无报错；其三，所证明的确实是该命题——社区另建只导入 Mathlib 的隔离文件，用两个相互独立的工具比对确认一致；其四，证明本身有效——经由 Lean 官方内核、con-leche、con-ron 及第三方独立检查器核验，且据称带有一套相对集合论的形式化保证"不会接受错误证明"。此次通过验证的共 5 个核心定理，包含广义黎曼猜想（GRH），整套代码仅依赖 Lean 的三条标准公理，编译覆盖约 175,187 个模块。

然而剧情在一天内出现反转。据 Datawhale 转述，数学家詹妮·洛瑞恩·尼尔森（Jenny Lorraine Nielsen）公开提交论文《Alpöge提出的黎曼猜想证明无效》，认为该证明存在一个关键漏洞：某些数学条件可能被设置为"无论输入什么，都成立"，从而使一段能通过 Lean 检查的逻辑链看似完成了推理。该论文在约 31 小时内连续更新 14 版，最新版上传于北京时间 11 月 22 日 12:31。作为对照，Hacker News 摘要还记录了另一条线：美国数学会主席 Ravi Vakil 提前公开了 Alessandro Maria Masullo 那份 940 页、历时 12 年、纯人工完成的广义黎曼猜想草稿，Brian Conrad 已审阅数月，但发布约八小时后即有读者报告论证存在问题。两件事共同指向一个超越真伪的方法学议题——形式化核验能保证"步骤无误"，却无法自动保证"命题没有被偷换"。结果有待学界进一步互相论证。

Mind2Act World：以「知行合一」诊断具身模型，把失败原因逐回合归因

面对"通用大模型以 Agent 方式在机器人操作评测中连拿高分、端到端 VLA/WAM 路线是否该继续"的争论，清华大学 mmlab@SIGS 联合远行光年等 16 家高校与机构发布通用机器人操作诊断基准 Mind2Act World，共 30 项任务、180 种配置。与传统成功率榜单不同，它先把机器人的"想"（记忆与推理）和"做"（物理执行）分开考、再合起来考，并对每一个失败回合逐一归因，汇总为模型的"诊断卡"与能力提升方向。作者用一道烹饪题说明为何成功率不足：InternW0 的 300 个回合中有 271 个是"料没下完就开火"，而 GPT-6 Astra 的 30 个回合中有 21 个"连食材罐都没抓起来"——两者同样失败，缺失的能力却截然不同。

首批评测覆盖 9 个代表性系统、共 56,700 个仿真回合，榜单持续开放参评。结果显示，表现最好的 Agent 在只考"想"的任务上成功率 52.7%，只考"做"的任务上为 39.0%，到两者缺一不可的任务上骤降至 12.0%；端到端策略在该类任务上最高仅 3.6%。结论是两条路线各有所长——端到端强在"做"，Agent 强在"想"，而真正的瓶颈恰恰在二者的衔接处。这项工作的学术价值在于把"诊断"而非"排名"作为基准的第一性目标，为具身智能提供了一张可比对的"能力谱系图"。

SO-Arena：为 System One 决策模型建立「能力谱系 + 决策可靠性」评测基准

新加坡国立大学 xML Lab 团队（第一作者 Lichen Li，通讯作者 Xinchao Wang）针对一类被主流榜单忽视的模型——System One 模型——构建了评测基准 SO-Arena。这类模型不做长链推理，而是在单次前向中输出候选结果上的概率分布，延迟低、输出结构化、下游可直接消费，广泛用于用户请求分流、下一步工具选择、任务完成判定等软件流程中的日常决策。作者提出的核心追问是：一份榜单得分高，是否就说明模型"好用且靠得住"？如果参考答案本身有争议、题目难度相近、只考单步判断，分数都可能失真。

SO-Arena 因此设计了四项机制：核验参考标签、按难度分层以区分强弱模型、在为 System One 定制的沙盒中评测长程交互、以及在选项重排与"正确选项缺席"时检验可靠性。最后一项尤为关键——它检验模型是否会在正确选项根本不在列表中时仍强行作答，还是能意识到"这里没有合适答案"。论文、项目主页、Hugging Face 与 GitHub 均已开放（arXiv:2611.15777）。它为"低延迟、单步决策"这类真实部署中最常见的模型形态，补上了一块缺失的评测拼图。

OpenAI 发布 MedChemBench：把「药物化学推理」变成 99 道可复现的考题

OpenAI 推出 MedChemBench 基准，用于评估 AI 模型在药物化学研究相关推理任务上的表现，检验其能否把分子结构与实验证据关联起来、解释实验结果、对比化合物并预测其性质。该基准基于已发表研究整理出 99 道测试题，刻意贴近真实科研中的推理链条，而非孤立的知识问答，目标是衡量模型能否可靠地"支撑这类研究"。

在超高推理模式下，GPT-6.2 Astra 得分 84.5%，GPT-6 Astra 为 83.3%，GPT-6.1 Sol 为 82.0%，GPT-5.6 Sol 为 58.2%，呈现出明显的代际跃迁。细看能力结构可以发现：GPT-6 Astra 在"重构分子结构、解读实验证据"上表现最优，但在"筛选化合物、预测数值性质"上难度更高——这提示药物化学推理并非单一能力，而是由结构重建、证据解释与定量预测等多个可分离的子能力构成。对计算化学与 AI4Science 研究者而言，这是一个可定位模型短板的细分诊断工具。

MiniMax Research：大模型自动化密码分析，把理论攻击推进到秒级可执行

MiniMax 研究团队利用其最新内部模型对现代密码方案开展系统性自动化密码分析，在测试中发掘出多处此前未知的算法构造缺陷，并将多项原本仅停留在论文理论层面的攻击，推进到秒级至分钟级的可执行破解。这项工作把现代密码学"公式公开、破绽难寻"的传统假设，第一次大规模地暴露在自动化推演之下。其历史坐标颇为清晰：2004—2005 年王小云团队攻破 MD5 与 SHA-1，正是以人类顶尖的密码分析水准推动了 NIST 启动新一代标准竞赛。

研究进展主要涵盖三个方面，分别针对历届标准与现代方案中的构造弱点展开。论文的学术意义不止于"找出了几个漏洞"，更在于示范了一种可复用的方法论：让大模型在密码分析的搜索空间中做系统化探索，而非依赖人类直觉的零星发现。这对密码学与安全评估的范式提出了直接挑战——若自动化分析能持续把理论攻击工程化，密码方案的设计与审查流程都需要相应加速。

📎 来源：MiniMax 稀宇科技

Nature：葡萄糖驱动的迷走神经电刺激，让糖尿病大鼠恢复正常血糖

据 Nature 报道，一项研究通过电刺激迷走神经实现对血糖的控制，使糖尿病大鼠成功恢复正常血糖水平。该方案的关键在于"用葡萄糖发电"——以血糖浓度本身作为调控信号与能量来源，构建闭环式的生物电子接口，而不是依赖外部的持续给药或固定参数刺激。这一设计把"感知—调控"合为一体，绕开了传统开环刺激难以匹配实时血糖波动的痛点。

这项工作属于生物电子医学与闭环控制交叉的前沿方向，其价值在于提供了一种自供能、按需响应的神经调控范式。对跨学科研究者而言，它提示"以生理信号驱动器件"的闭环思路，或可迁移到更多需要实时反馈的慢病管理场景；但从大鼠到人体仍有相当大的转化距离，疗效与长期生物相容性仍需更严格的实验检验。

Deep Dive · 01

F2G-Pose：一次前向同时预测物体位姿、尺寸与完整三维形状

NeurIPS 2026 · 复旦大学 × 上海创智学院 · arXiv:2610.31623

研究背景

机器人要拿起桌上的杯子，仅识别出"这是一个杯子"远远不够，还需判断它在哪里、朝向如何、实际多大。对于人类这些判断几乎无需刻意，但对机器人——尤其面对从未见过的物体实例时——问题并不简单：物体可能被部分遮挡，深度相机只能看到有限表面，同一类别下不同实例的形状也可能差异巨大。这正是"类别级 6D 物体位姿估计"要解决的问题：不依赖每个物体专属的 CAD 模型或参考图像，仅从视觉观测中直接推断三维位置与旋转方向。

核心创新

既往方案常需反复生成并筛选候选姿态，计算开销大、链路长。复旦大学与上海创智学院团队提出的 F2G-Pose（Geometry-Aware Foundation Feature Lifting）走了一条更直接的路线：给定一帧经过目标分割的 RGB-D 观测，通过一次前向传播，同时预测物体的姿态、尺寸与完整形状。其关键在于"几何感知的基础特征提升"——把预训练基础模型的特征与显式几何信息对齐融合，使单次推理即可覆盖原本需要多阶段完成的估计任务。

实验结果

该工作被 NeurIPS 2026 接收，在类别级 6D 位姿估计这一核心评价任务上，以"直接预测"替代"候选生成 + 筛选"的范式，在保持精度的同时显著简化了推理流程。作者已开源代码（github.com/jrryzh/F2G-Pose）并提供项目主页，便于在自有数据集与机器人平台上复现与迁移。

学术意义

  • 把"基础模型特征 + 几何先验"的融合做实。在单次前向中统一位姿、尺寸、形状三项目标，为 RGB-D 感知提供了一条更紧凑的端到端路径。
  • 直接预测 vs 候选搜索。该路线削弱了对多阶段采样与后处理的依赖，对实时机器人操作具有直接的部署价值。
  • 可复现的开放贡献。NeurIPS 接收 + 代码开源，使其成为类别级位姿估计方向少有的可对照基线。
📎 来源：机器之心 · 论文 arXiv:2610.31623 · 代码 jrryzh/F2G-Pose
Deep Dive · 02

REALCLI：任务成功不等于协作合格——把「人机协作质量」做成成对评测

北京航空航天大学 × 中国人民大学 × IQuest Research · arXiv:2610.22507

研究背景

随着 Coding Agent 能力提升，从 SWE-bench 的仓库级 Issue 修复到 Terminal-Bench 的复杂命令行工作流，Agent 已能在终端里执行越来越长的任务。但一个关键问题尚未被充分回答：当 Agent 在执行过程中需要与人协作时，它的表现如何？现实任务通常不是"接收完整需求 → 自主执行 → 交付结果"的线性流程——用户可能中途补充信息、修改需求或调整约束，高风险操作也需要授权确认。而这些人机协作能力，恰恰是许多现有 Benchmark 尚未系统覆盖的评估维度。

核心创新

REALCLI 的巧思在于采用成对评测（paired benchmark）：让同一任务在两种模式下运行，二者共享任务目标、执行环境与结果验证器，从而同时考察任务执行效果与人机协作质量。MODE A（REALCLI-EXEC）为自主执行模式，Agent 一开始便获得完整任务规格，主要评估其在明确需求下完成任务的能力；MODE B则在执行中引入人类交互，考察 Agent 能否在信息不完整、需求变动、需授权等情形下有效协作。通过"同任务、双模式"的对照设计，把"协作带来的增益或损耗"从混杂因素中剥离出来。

实验结果

论文指出，仅评估"任务能否完成"不足以判断一个 CLI Agent 是否真正可靠——两种模式之间的差异，恰恰揭示了模型在协作场景下的真实短板。这一结论对当前"以单项成功率论英雄"的评测文化构成直接补充：一个在自主模式下高分完成的 Agent，未必能在需要中途澄清需求或请求授权的真实工作流中保持同等可靠性。作者来自北航、人大与 IQuest Research，并将协作质量这一维度形式化为可测量的指标。

学术意义

  • 把"协作"从定性讨论变为可测指标。成对设计控制住任务与环境变量，使协作质量成为可归因、可对比的独立维度。
  • 修正以成功率为主导的评测偏差。它提示 Agent 研究中"能做对"与"能配合"是两种不同的能力，应分别度量。
  • 面向真实部署的评估视角。高风险操作授权、需求中途变更正是实际落地的常见情形，该基准为可靠的 CLI Agent 建立了一个更贴近生产环境的考核框架。
📎 来源：AINLP · 论文 arXiv:2610.22507
