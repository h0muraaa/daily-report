1. 研究动态

AI Agent 来源：AI Engineer

可验证的持续学习：让 AI Agent 从生产失败中稳定进化

Soheil Feizi 在 RELAI / AI Engineer 的演讲中提出“可验证的持续学习”框架，将生产失败轨迹转化为可回放、可回归测试的学习环境，以解决静态基准无法覆盖的真实失效问题。该框架强调四层能力：失败可重放、更新不遗忘、修复路由到正确层级、学习闭环足够高效以持续运行。其学术价值在于将 continual learning 的“漂移—遗忘”难题与 Agent 系统运维结合，为构建可自我改进的开放系统提供了新的问题建模。

Tool Learning 来源：Simon Willison's Weblog

“更好的模型，更差的工具”：Opus 4.8 / Sonnet 5 出现幻觉式工具参数

Armin 在开发 Pi 时发现，新版 Claude 模型（Opus 4.8、Sonnet 5）调用编辑工具时会在 edits[] 数组中捏造额外字段，导致 schema 校验失败；而旧版模型未出现此问题。该现象提示：基础模型能力增强并不必然带来工具使用（tool schema compliance）的单调提升，模型可能在“创造力”与“结构化约束”之间产生新的张力。这为 tool-calling 鲁棒性、函数调用约束学习及模型后训练目标设计提供了值得关注的实证案例。

Scaling Laws 来源：新智元 / 原博客 Scaling Laws, Honestly

OpenAI Scaling Law 原始论文被指出存在 bug

前 OpenAI 研究员 Diogo Almeida 发文称，OpenAI 2020 年《Scaling Laws for Neural Language Models》的最初版本存在计算 bug，导致对模型规模与训练数据最优配比的估计出现偏差。Sander Dieleman 等学者认为，这一错误可能使业界在后续数年中训练了“体量过大、训练不足”的模型，造成大量算力浪费。该博文虽非正式论文，但对 scaling law 的实证基础提出了重要质疑，值得学界在重新审视 scaling curves 与最优训练配置时加以验证。

Agent Engineering 来源：AINLP / Thariq on X

Claude Code 团队提出“未知盲区”方法：Fable 5 长任务前的必要检查

Anthropic 的 Thariq 将 Fable 5 在长任务中的失败来源归结为 prompt/技能/上下文（map）与真实代码库、业务约束、运行环境（territory）之间的“unknowns”。他提出在任务开始前识别已知已知、已知未知、未知已知与未知未知四类盲区，过程中记录偏离，并在完成后让模型反向解释与测试。该工作本质上是为高能力 Agent 的“自主补全”行为建立了一种前置风险管理与后验验证机制，对 Agent 软件工程的方法论具有借鉴意义。

AI Talent 来源：机器之心

清华特奖得主顾煜贤加入 DeepSeek，聚焦高效大模型研究

清华大学 2025 年研究生特等奖学金获得者、苹果博士奖学金得主顾煜贤已加入 DeepSeek，并参与 DeepSeek V4 论文工作。其研究覆盖预训练数据筛选、模型压缩与知识蒸馏、高效模型架构等方向，代表工作包括 MiniLLM、MiniPLM、PDS、Instruction Pre-training 及 Jet-Nemotron。这一人事动向反映了算法创新在算力受限背景下对模型效率与可部署性的持续重视，也预示 DeepSeek 在训练效率与压缩方向的加码。

AI × Software Engineering 来源：Simon Willison's Weblog

AI 辅助发布审查：Claude Fable 发现 sqlite-utils 4.0 五项“发布阻塞”缺陷

Simon Willison 在 sqlite-utils 4.0 稳定版发布前，使用 Claude Fable 进行最终审查，模型发现并修复了 5 项发布阻塞级问题，包括 delete_where() 未提交等语义级 bug。该案例展示了大模型在熟悉代码库的回归风险与 SemVer 兼容性审查中的潜力，同时也提示学术界需关注 AI 辅助软件发布、形式化测试与人工监督的边界。

2. 深度论文解读

Slide Generation 论文：arXiv:2606.17162 · 项目：memslides.github.io · 代码：GitHub

MemSlides：面向多轮局部修订的层次化记忆 PPT Agent 框架

研究背景：当前 PPT 生成研究多关注一次性输出的整体质量，但真实协作场景中用户更常要求局部修改，例如“仅调整第 8 页右侧模块为流程图”。现有系统往往在一次修改中波及全局，导致布局、配色、内容一致性被无意破坏，即“平均分陷阱”。

核心创新：北京邮电大学、清华大学、上海交通大学联合提出 MemSlides，引入层次化记忆机制，将用户偏好、历史约束与当前编辑上下文显式结构化，使 Agent 在每次多轮修改中只作用于目标区域，并保留非目标区域不变。该框架同时建立验证机制，确保局部修订的可审计性与一致性。

学术意义：该工作将文档生成任务从“单次生成”推进到“协作式编辑”，强调记忆、局部性与可验证性三者的结合，对多轮交互式内容生成、Agent 协作接口设计以及人类-AI 共同创作评估均具有启发。

SQLite / Python sqlite-utils

sqlite-utils 4.0 RC2：SQLite 数据操作的 Python 工具库

sqlite-utils 是 Simon Willison 维护的流行 Python 工具库，支持以编程方式创建表、插入数据、运行查询与转换。4.0 版本目前正进入 RC 阶段，近期通过 Claude Fable 完成发布前审查并修复多项关键问题。对于数据库、数据工程与小型分析 Agent 研究而言，该库仍是可复用的基础设施级开源资源。

Cloudflare Cloudflare Agents / AI SDK（相关项目）

Agentic Inbox：自托管邮件 + AI Agent 回复示例

Cloudflare 开源的 Agentic Inbox 展示了如何基于 Email Routing、Email Sending、Durable Objects、D1 与 R2 构建自托管邮件客户端与自动回复 Agent。虽然项目维护活跃度存在争议，但其架构可作为研究“边缘部署 + 事件驱动 Agent”的参考实现，尤其适合探索低延迟、无服务器环境下的 Agent 应用。

4. 趋势观察

从“能力 Scaling”到“系统可靠性”的再平衡。 今日多条线索显示，研究重心正在从单纯追求模型规模与单次性能，转向 Agent 在真实、多轮、长期运行中的可靠性问题。Fable 5 的“未知盲区”方法、Feizi 的可验证持续学习框架，以及 MemSlides 对局部修改一致性的关注，共同指向一个核心问题：高能力模型在开放环境中会因自主补全而产生不可控偏差。未来研究需要在模型能力、工具约束、记忆机制与验证方法之间建立更系统的理论框架，而非仅依赖后验评估。

Scaling Law 的实证基础需要更严格的审视。 Diogo Almeida 对 OpenAI 原始 Scaling Law 的 bug 指控提示，影响整个行业数年的关键结论可能存在计算或假设层面的缺陷。学术界应借此机会重新检验早期 scaling curves 的数据处理、拟合方法以及“最优训练 token 数”的泛化性，避免将工程经验过度外推为普适规律。

“模型越强、工具越差”的警示。 Anthropic 新模型在严格 schema 工具调用上的表现退步表明，模型能力曲线并不天然覆盖结构化约束遵循。工具学习（tool learning）与函数调用（function calling）的训练目标、后训练对齐与评估协议需要更专门化的设计，而不是默认被通用能力提升所解决。
