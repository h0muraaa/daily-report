本期导读。今日的研究信号集中在四条线上：其一，"Agent 做研究"开始被当作方法论问题处理——可复现工件、可验证的 tool-call 数据与 Harness 变量被逐一形式化；其二，智能体记忆分化出"外部记忆整理"与"参数级知识巩固"两条路线，且都给出了带成本的对照实验；其三，评测继续从静态榜单迁移到协作能力、日常任务与端到端复现，多个新基准明确以"队友出错"和"真实档案"为压力源；其四，AI 深度介入数学构造与漏洞发现，贡献归属与双用途风险同步上升。以下按学术价值与信息增量筛选，产品发布与营销类信息未纳入。

1.研究动态

ReproBridge：把"复现成功"沉淀为可复用工件，四模型复现率从 76.4% 升至 92.6%

Google 团队提出 ReproBridge，核心是把一次成功的实验复现固化为下一个 Agent 可直接复用的工件包：清洗后的代码、环境配置、逐个实验的启动脚本，以及一份书面指南；新 Agent 依据工件包重跑实验，再由独立审计器核验运行是否真实发生，从而把"声称跑通"与"确实跑通"分开。基准覆盖 36 篇论文的 1,029 个任务，每个任务配 5 个人工核验的参考分数。结果显示，精炼工件将四款模型的复现成功率从 76.4% 提升到 92.6%，API 开销下降 19.7%，模型之间最好与最差的差距由 21.6 分收窄到 3.9 分。对以 Agent 跑研究代码的团队，这项工作提示"可复现性"可以被工程化为一种可传递的中间产物，而不只是论文附录里的一句声明。[1]

📎 来源：elvis (@omarsar0)

EchoChat（NeurIPS 2026）：用级联门控奖励抑制共情推理中的阶段间误差传播

港中文与微软的 EchoChat 针对共情语音对话中的多阶段误差传播：感知、心理状态推断与回应生成彼此耦合，早期误判会成为后续推理的前提，即使最终回复措辞得体，也可能建立在错误依据之上，形成"共情模仿"（empathetic mimicry）——听起来温暖，却与说话人的真实心理状态和需求不匹配。作者把三个阶段纳入统一优化框架，用级联门控奖励约束阶段间依赖，并以步骤级信用分配把反馈落到具体步骤，而不是只对最终回复打一个整体分。其方法论价值在于为"过程可归因"的多阶段对话系统提供了一套奖励设计范式：仅评最终输出无法定位偏差，必须把监督信号沿推理链回填。[2]

📎 来源：新智元

Anthropic 公开智能体记忆架构：四层结构 + 离线 "dreaming"，检索覆盖率 53% → 61%

Anthropic 公开了智能体记忆的四层设计：会话记录保留经历，记忆笔记沉淀筛选后的经验，wiki 组织知识之间的关系，少量预载上下文告诉下一次会话去哪里找；"dreaming" 则在任务之外做离线整理，纠错、去重、补链并重组知识。作者强调记忆并非越多越好：在 CL-Bench 数据库任务中，较强模型会保存"经过验证的规则及其依据"，而限定只记失败反而削弱收益。在约 35 万份文件、4.2 亿 token、25 个评测问题的内部语料实验中，单靠检索的评分标准覆盖率为 53%，wiki 结合检索并增加整理轮次后升至 61%，每题少用约 2 万 token——但作者明确说明这一节省未扣除预先构建 wiki 的成本。对 RAG 与记忆系统的评测设计，这意味着需要同时度量覆盖、成本与维护开销，而非只报一个命中率。[3][4][5]

📎 来源：AINLP · meng shao (@shao__meng) · Anthropic (@AnthropicAI)

Stanford 协作智能基准 CIB：240 个真实任务，队友出错时所有模型掉 20–47 分

Stanford 提出 Collaborative Intelligence Benchmark，用 240 个任务覆盖 8 项团队协作技能，素材取自航空事故报告、临床病例、编程任务与谈判记录等真实档案。18 个模型中最好的得分 82.2/100；一旦队友制造问题，所有模型都掉 20 至 47 分。一个值得关注的分化是：前沿模型几乎总能拒绝不安全的捷径并报告不当行为，但在压力下坚持立场明显更难——在队友施压、制造愧疚并以退出相威胁的谈判中尤其如此。这为多智能体系统提供了一个不同于单任务准确率的评测切面：协作能力对"同伴错误"极其敏感，而现有基准几乎没有覆盖这一维度。[6]

📎 来源：elvis (@omarsar0)

Harness Leaderboard：28,849 次试验表明，换 Harness 的影响与换模型同量级

Joël Niklaus 发布 Harness Leaderboard，用 28,849 次试验比较 9 个编码智能体 Harness：固定模型、供应商与推理强度，只更换 Harness，每个任务三次尝试，在 Terminal-Bench 2.1 与 DeepSWE 上运行 GLM-5.3-Flash、DeepSeek-V4.1-Flash 与 Flint，推理总花费 4,746 美元。三个模型平均下来，仅用 bash 的 mini-swe-agent 解出 51.4% 的任务，而 openclaw 为 27.3%，差距接近两倍。结论对研究者的含义很直接：在开源模型上，Harness 是与模型权重同量级的自变量，报告结果时必须连同 Harness、尝试次数与推理成本一并披露，否则跨论文比较不成立。[7]

Airbnb 领域微调实证：20 亿参数模型达到前沿分类水平，但"1% 成本"有明确边界

Airbnb 工程团队公开了一个高频内容审核任务的对照实验：用数十万条去标识化的领域样本微调约 20 亿有效参数的 Gemma4-E2B，F1 从 0.563 提升到 0.902，与最好的专有模型相当；延迟中位数 35 ms、p99 约 85 ms，而前沿 API 在低思考模式下中位延迟约 900 ms。在高流量场景下，自托管单卡推理成本约为前沿 API 的 1%。作者明确指出成立条件是任务明确、数据充足、调用量大，且"1% 成本"不含训练、标注、开发、运维与冗余备份；当每分钟请求低于约 15–30 次时，专用 GPU 闲置成本会吞掉优势。对做领域适配的研究者，这是一个把"小模型替代前沿模型"量化到边界条件的稀缺样本。[8]

GPT-6 Cyber：948 个 Linux 提权利用、81 个未知 Firefox 高危漏洞，平均 2.5 小时一个 0-day

OpenAI 的 GPT-6 Cyber 在 Linux 内核上为 948 个漏洞生成了可用的提权利用程序（复现 1,724 个、成功 948 个），约为上一代模型的五倍，API 成本约 121 万美元、单次成功利用约 1,279 美元，其中至少 10 种利用技术此前未被公开；同一模型还在 Firefox 中发现 81 个此前未知的高危漏洞。另一个实验给出的节奏更直观：把 Linux 交给模型并只下达"提权"指令，平均 2.5 小时即可完成一个从研究、识别、测试、验证到交付的 0-day，而顶尖逆向工程师对部分案例需要数周才能理解 AI 的搜索路径。需要注意基准不可混用：GCSA 披露的 91.3% 是 CyberGym Level 1 上的已知漏洞复现率，衡量的是"能否证明风险存在"，不等于未知漏洞的发现能力。[9][10]

2.深度论文解读

Google Research · SLEEP

SLEEP：让模型在"睡眠"中把短期知识写入低秩专家参数，同时抑制灾难性遗忘

Google Research 博客 · 基座模型 Qwen3-8B · 任务：低资源语言的依次学习 [12]
研究背景

上下文学习能让模型临时掌握新信息，但这不等于"学会"：一旦离开上下文，知识随即消失。直接在序列任务上持续微调又容易学了新的、忘了旧的。SLEEP 要解决的是介于两者之间的问题——如何把在任务中积累的短期信息，巩固为可长期复用的参数化知识，而不覆盖已有能力。

核心创新

方法让模型交替"清醒"与"睡眠"：清醒时正常处理输入、积累短期信息；睡眠时暂停接收新输入，把信息巩固进更稳定的参数。巩固被称为"知识播种"——启用预留的低秩专家参数，通过蒸馏等训练把短期记忆迁移进去，再清空短期部分，为下一轮学习腾出空间。关键设计是给新知识分配新增参数，而不是改写承载旧知识的参数。随后进入"做梦"阶段：模型自行生成合成练习，筛选有价值的样本，再通过训练强化所学，因此它不仅复习已有输入，还会为自己构造练习。

实验与验证

在依次学习满语、卡拉芒语等低资源语言的实验中，Google 报告 SLEEP 能较好保留先前所学。以 Qwen3-8B 为基座，AIME 2024 的 avg@16 得分为 79.2%，对照的在线策略自蒸馏为 76.6%。代价是额外训练：同等训练步数下，计算开销约为普通监督微调的 4 倍。作者也说明这些是特定模型与任务上的结果，尚未给出跨规模、跨模态的缩放规律。

学术意义与可复用点

与 Anthropic 的 dreaming 相比，两者的分野很清楚：Anthropic 整理的是外部笔记与知识库，学习发生在上下文侧、可审计可回滚；SLEEP 则尝试把所学写进模型参数，学习是持久的但需要显式的遗忘控制与更高的算力预算。对研究者的启示是：讨论"智能体记忆"时应先区分"记得住"与"学会了"，二者需要不同的评测协议——前者看检索覆盖与成本，后者必须同时报告旧任务的保持率、新任务的迁移率与训练开销。

NeurIPS 2026

Firefly：先探索真实 API、再反向出题，为 Tool-Calling Agent 合成可验证训练数据

Firefly: Illuminating Large-Scale Verified Tool-Call Data Generation from Real APIs · NeurIPS 2026 [13]
研究问题

用强化学习训练 Tool-Calling Agent，需要大量任务，且每个任务都要带有正确的中间 tool calls 与可验证的最终答案；即使是数据效率较高的 RL 方案，通常也需要数千个任务，而主流 agent benchmark 只提供几十到几百个。让 LLM 合成任务会立刻遇到两个问题：模型想象出的任务，其 ground truth 是否真的正确；以及当任务依赖真实 API、而 API 返回随时变化时，如何在训练中反复复现同一环境。

关键洞察

作者认为关键不在"如何生成更好的任务"，而在生成任务的顺序：与其先出题、再寻找答案，不如先在真实 API 上探索，再根据已观察到的结果反向出题。这样任务的答案由真实环境的返回定义，正确性不再依赖模型的想象；同时把"环境状态"与"任务"解耦，为离线复现创造条件。

方法与规模

论文构建了从真实 MCP Server 生成可验证 tool-call 数据的 pipeline，并配套一个可离线复现的 Retrieval-Augmented Tool-Call Simulator，使得同一份任务可以在训练中被重复执行而不受线上 API 波动影响。基于该 pipeline 得到的数据覆盖 240 个真实工具环境。方法层面的贡献是把"可验证性"前置到数据生成阶段，而不是事后筛选或人工抽检。

学术意义与可复用点

这项工作把 agent 训练中的数据问题重新表述为环境建模问题：真正稀缺的不是任务文本，而是可重放、可验证、与真实系统一致的工具环境。对研究社区，它与 ReproBridge 形成互补——前者解决"训练数据从哪里来且可否验证"，后者解决"实验能否被他人复现"；两者共同指向一个趋势：可复现的环境与工件，正在成为 Agent 研究的公共基础设施。

4.趋势观察

"智能体记忆"已经分成两条互不替代的技术路线。Anthropic 的 dreaming 走外部记忆路线：知识留在文件与 wiki 中，学习发生在上下文侧，可审计、可回滚、可增量维护，代价是检索与整理开销；Google 的 SLEEP 走参数巩固路线：知识写入预留的低秩专家参数，学习是持久的，代价是约 4 倍于普通 SFT 的算力，并且必须显式设计遗忘控制。两条路线回答的是不同问题——"下次该查什么"与"模型是否真的学会了"。可以预期近期会出现混合方案：用外部记忆承担高频、易变的事实，用参数巩固承担稳定、可迁移的技能；相应地，评测也必须拆成检索覆盖、旧任务保持率与训练成本三组指标。[3][12]

RSI 的讨论正在从口号回到工程约束。Jeff Dean 在与李飞飞的对谈中给出一个朴素但关键的限制：自动化可以省掉"等到早上再看结果"的空白，但训练、计算、保存与评估仍需真实时间，因此递归自我改进不可能以无限快的速度进行；他披露新公司 Discovery Loop 已运行约 20 个自动改进循环，目标是把领域专家生产力提升 20 到 50 倍。与之对照，MIT 联合团队的"权重空间编程"实验（GPT-6 Astra 只改 Qwen3.5-0.8B 中 0.016% 的权重，把 MATH-500 从 7.9% 提到 48.1%）在传播中被解读为预训练集群的替代品，但随后被指出本质仍是模型写脚本改权重，Meta 与开源社区的研究者亦批评其标题化。两件事合起来提示：真正需要评测的是"写脚本—改权重—自我改进"这条能力阶梯上的具体位置，而不是一个笼统的 RSI 标签。[14][15][16]

Harness 正在成为可发表的一等研究对象。智能体框架的演进线索已经比较清晰：从线性提示词"链"，到基于图的显式工作流，再到以可执行代码组织的 Harness；每一次演进都是为了提高对非确定性模型的约束能力与可观测性。Harness Leaderboard 用控制变量实验给出了量化证据——同一批开源模型，仅更换 Harness，任务解决率可以从 27.3% 变到 51.4%。这意味着未来论文若不披露 Harness、尝试次数与推理预算，其结果在跨组比较中几乎不可解释；反过来，Harness 设计本身（工具接口、上下文管理、错误恢复）也具备了独立的方法论贡献空间。[17][7]

评测正在从静态榜单迁移到"真实档案 + 端到端复现"。本期的几个新基准指向同一方向：CIB 用航空事故报告、临床病例与谈判记录构造协作任务，发现队友出错会让所有模型掉 20–47 分；LifeVal 用数千名用户的真实需求定义"日常任务"；ReproBridge 直接以"能否重跑成功并由审计器确认"作为指标。与此同时，State of AI Report 2026 明确指出评测基准正在大面积失灵，智能体风险已溢出到生产系统。对学术界，这意味着基准设计的重心应从"提高难度"转向"提高生态效度"：任务来源可追溯、环境可重放、失败可归因，三者缺一不可。[6][18][1][19]
