设计趋势洞察Design Trends
趋势一 · 智能界面 Generative UI

"对话用于创造，界面用于使用"——交互范式正在从文字流迁移到生成式界面

这次变化的本质，是 AI 系统大规模地把"输出"从自然语言扩展成可操作的图形界面。它的底层矛盾，是两条 Personal Agent 路线之争：一派主张 Agent 在云端替用户驱动现有 App、把交互入口收敛成一个对话框；另一派主张"对话用于创造、界面用于使用"——用自然语言表达一次需求，AI 把它固化为一个稳定、可复用、可分享的定制应用。

Airbnb CEO Brian Chesky 的判断从侧面印证了矛盾所在：把内容塞进纯对话式消费级 Agent 体验很差，每个应用都需要比对话框丰富得多的界面。

对设计团队的直接含义有三点。其一，被生成的界面也要被"走查"：可用性、信息层级、状态一致性不再是设计师一次性交付，而是要在模型每次生成后都能被检验。其二，设计系统要能约束生成结果：design token、组件规范、可分享性要从"设计稿"升级为"给模型的约束"。其三，评估对象变了：从静态页面走查，转向"生成态"的可用性测试与一致性回归。

来源京东技术 · 智能UI时代的技术架构重构
趋势二 · 信任与可验证性

当 AI 成为信息与交易的中介，"信任"正在变成体验的新基石

今天有三条线索指向同一个命题：AI 越强，"可信"越贵。内容侧，关于"读者为什么不信任 AI 写作"的讨论指出，当 AI 能生成文字，读者要的是信任、是"真人作者"的吸引力、是人类媒体的价值。制度侧，一名 34 岁考生用微型摄像头、手机和生成式 AI，在两轮韩国税务师考试中拿下第一名，坐到第二排、两名监考在场却无人察觉，最终承认作弊——技术平权同时把"可信凭证"的门槛也打了下来。系统侧，新的评测基准暴露出另一类问题：不少 Agent 并非真的检索，而是"假装搜索、靠背答案"。

对体验设计的启发是：可验证、可追溯、可纠正，必须被设计进流程，而不是事后补丁。用户需要看到"这条结论来自哪里""我能不能改它""出错时谁来兜底"。信任不再只是文案问题，而是界面结构问题——引用来源、可编辑的记忆、失败态与回退路径，都成了体验的一等公民。

案例一 · Personal Agent

小豆：四模块结构与"关于你"的记忆设计，把"主动"做得可纠正

小豆的结构很值得拆：底部四个入口——对话、"猜你想要"、"帮你跟进"、"关于你"，并与豆包共享记忆。"关于你"页面几乎像一份职业档案：登录豆包账号后数据联通，它能记录你常做商业文案、测试 AI 产品、爱用 AI 生成可直接运行的单文件代码，甚至连你最近在折腾 Verlet 积分布料模拟和复古 UI 动效都记了下来。更关键的是，它允许用户用自然语言直接纠正记忆、主动更新偏好——这是把"错误可修复"做进产品结构，而非藏在设置里。

"主动服务"的颗粒度也做得具体：盯抖音商品降价、每周分析短视频作品给选题建议、每日汇总关注动态、到了某地直接问"附近有什么我收藏的好吃的"并帮你打电话问排队、聊天里截图说一句"记一下日程"就同时同步系统日历与飞书日历，还能连 Apple 健康做分析。生态上下文（抖音的内容/电商/本地生活、飞书的办公、日历与地理位置）被打通，呼应了"上下文就是一切"。

值得研究者警惕的是商业化与打扰边界：四档定价 68 / 200 / 500 元每月，对"中国互联网免费习惯"是巨大挑战；"帮你跟进"这类主动推送若无节流与退出机制，很容易从"贴心"滑向"打扰"。小豆能否成功，取决于它能否培养"为个人助理付费"的习惯，并守住"记忆可见、主动可关"的体验底线。

案例二 · 硬件交互

荣耀 700 背面小屏：从"拍合照每个人都想入镜"倒推的界面

这个功能的动人之处在于它解决的是一个具体的小尴尬：拍合照的人把手机翻过来用后置主摄自拍时，能不能让所有人都看见自己有没有入镜。荣耀的答案是在机身背面放一块小屏——后置自拍时全员可见；不拍照时，这块屏还能放通知、表情包和一句话生成的贴纸。配合左侧柔光环与 PPG，硬件被组织成围绕"拍照与分享"的完整体验。

更值得学习的是产品定义的方法论：三条线（Magic9 电影影像 / WIN2 电竞 / 700 潮趣影像）都先定"目标人群怎么用"，再决定功能与卖点，而不是先有技术再找场景。荣耀 700 Pro 用第五代骁龙 8、6.57 英寸屏、9000mAh 电池、IP68/69/69K 防护，四色可选。对体验设计的提醒是：好的"新硬件"往往不是技术炫技，而是解决一个人人都经历过却没人认真对待的小场景；而"第二块界面"真正的难点，是信息密度与打扰控制。

01Agent 大评测指南：把"评测"当作一门实践学科

这篇复盘基于半年多的真实评测经验（Tabbit Browser、Offloop、Persom 等通用 Agent 项目），核心观点是：评测也是测试，但 Agent 迭代的"改动不确定性"极强，来自两方面——模型输出不可预期，以及人类操控 Agent 的不可预期。作者认为这些经验同样适用于 Harness、Prompt、Skill 等子模块的迭代，并强调做 Agent 既需要懂模型、懂落地、又懂产品且有责任心的人，也需要战略层面的统筹。

02RDQA 基准：不预置索引，测 Agent 的真实检索与细节定位能力

针对"Agent 只是假装搜索"的普遍问题，得州大学阿灵顿分校、华东师范大学、佐治亚理工学院在 EMNLP 2026 主会 Oral 提出 RDQA（原始数据问答）：不预置检索索引，也不把源文件预先交给模型。它共 1350 道题，覆盖文档、视频、音频；每题都要求 Agent 自己找到原始文件、调用解析工具、定位到某一页 / 某一格 / 某一秒再作答，若答案已以纯文本出现在公开网页上则改写或删题。结果很扎心：12 个通用 Agent 经参数泄漏率调整后，最高准确率仅 24.0%。这为"研究 AI 真实能力而非记忆能力"提供了可复现的评测设计。

03B2A 研究设计：用大规模对照测试研究"AI 中介下的用户行为"

这份研究的方法论本身就很值得用户研究员借鉴：1270 个提示词 × 4 款 Agent × 11307 次测试，再叠加 YipitData 的真实消费者支出数据做外部校准——把"AI 怎么替人做决策"从主观讨论变成可量化、可复现的研究问题。它揭示的行为结论也极具分量：AI 实际考察的商品数远少于人类、不同 Agent 推荐高度重合（意味着流量更集中）；AI 更擅长计算综合购买成本（冲击依赖信息不对称的商业模式）；而平台并非想象中那么容易被颠覆，真正变化的是平台的议价能力。
