1今日要点

定价Claude Opus 5.5 发布：同等能力下每任务成本降 40%，缓存读取降 60%

Anthropic 发布 Claude 5.5 家族首款模型 Opus 5.5，官方定位是"多数任务达到自家 Mythos 级 Fable 5.1 的水平，而运行成本比 Opus 5 低 40%"。降价由两部分叠加：输入/输出单价降至每百万 token 4 美元 / 20 美元（降 20%），而用量最大头的缓存读取从 0.5 美元降到 0.2 美元（降 60%）——写代码和跑 Agent 时会反复读取同一批上下文，这项直接打在账单主力项上。输出速度同时提升 30% 以上。

更有说服力的是内部基准：让 Opus 5.5 与 Fable 5.1 各自把负载均衡软件 HAProxy 从 C 移植到 Rust，两者都几乎通过全部回归测试，Opus 5.5 用时 9.5 小时、Fable 5.1 用时 12 小时，且 Opus 5.5 成本低 51%；一位内测者用它审计并修复 20 万行代码库不到 3 小时完成，Opus 5 做同样的事超过 20 小时、token 用量是它的 2.5 倍。GitHub 的实测结论则是"步骤数不到 Opus 5 的一半"。

商业信号同样明确：发布当天即上架 GitHub Copilot、Cursor（CursorBench 57.8% 成为其榜首）、Devin、Perplexity、v0、AWS Bedrock 与 Vercel AI Gateway，并成为 Claude Code 与 Claude 应用的默认模型；订阅侧五小时额度上调并额外发放一张可留存的重置卡；Mike Krieger 明确 Sonnet 5.5 与 Haiku 5.5 将在数周内跟进。

来源：Claude（@claudeai）、宝玉、Mike Krieger、AWS Machine Learning Blog、GitHub、Cursor、Vercel

定价OpenAI 同日打出 GPT-6 Sol / Luna：API 价格砍半，Luna 单任务成本低 93–96%

OpenAI 发布 GPT-6 Sol 与 GPT-6 Luna，两者 API 价格均比 GPT-5.6 低 50%，缓存输入读取再打 1 折（90% off）。分层很清楚：Sol 定价 2 美元 / 10 美元每百万 token，面向复杂专业工作流与长时程编码；Luna 定价 0.10 美元 / 0.50 美元每百万 token，面向高并发 Agent 工作流与日常任务。OpenAI 报告 Luna 在 DeepSWE v1.1 上达 66.6%，与 Claude Opus 5、Fable 5 在中等努力档相当，而单任务成本低 93–96%；在更高努力档下它能在约 1/100 的成本上匹配 GPT-5.6 Sol 的事实性表现。

落地渠道覆盖 API、Codex、ChatGPT Work（Plus/Pro/Business/Enterprise/Edu）与 Amazon Bedrock，并在 Vercel AI Gateway 上线。同日 OpenAI 还发布了对第三方独立评估的承诺：将在训练、评估、部署三个环节向外部评估者开放深度访问，并列出四个优先评估领域。

开源小米开源 MiMo-V2.6：1T+ 参数、MIT 许可、约 347 万美元跑完一轮大规模 RL

小米发布并开源 MiMo-V2.6 系列，Pro 为约 1.02 万亿总参数 / 420 亿激活的 MoE，Flash 为 3100 亿总参数 / 150 亿激活，均为原生全模态（文本、图像、视频、音频）并支持 100 万 token 上下文，权重以 MIT 许可开放。MiMo-V2.6-Pro 在 Artificial Analysis 综合智能指数拿到 46 分，超过 Kimi K3 与 Qwen3.8 Max，成为当前最强开源模型；API 定价约 0.435 美元 / 0.87 美元每百万 token，官方称同等智能水平下价格仅为海外模型的 1/20 至 1/60。

比分数更值得读的是方法。团队负责人罗福莉（曾参与 DeepSeek R1 研发）称这可能是开源团队迄今单次规模最大的 RL 训练：6 天直播训练、约 2B token/步、1568 条 prompt × 16 次 rollout、全异步，Pro 跑 30 步、覆盖约 75 万条轨迹，成本约 262 万美元（含 Flash 合计约 347 万美元）。训练对象不是一问一答，而是完整的 Agent 工作流——写代码、调工具、查错、纠偏整条链条都在 RL 里反复训练。团队用 MixRL 把可验证的中等难度任务混在同一轮 RL 中联合训练，难验证、超长时程的任务则单独训成"教师"，再用 MOPD 蒸馏合并回主模型。

一个反直觉但值得记下的判断来自同一篇复盘："RL scaling 的瓶颈一半在系统，一半在组织"——团队扁平、没有部门墙，是"为什么你们能做 MixRL"的第三个答案（前两个是技术性的）。这与腾讯混元"拆掉部门墙比单纯堆人更有效"的组织经验互相印证。

来源：宝玉、meng shao、Latent.Space、OpenRouter、Arena.ai、向阳乔木（组织效率）

架构Jev 与"决策模型"：把 Agent 循环里最贵的一步单独拆出来

TypeSafe AI 的 Jev 是过去一周讨论度最高的新模型，但它不做文本生成：输入非结构化状态，输出类型化的选项、是非判断与评分，并附带置信概率，且输出不收费。按官方与第三方测算，它比前沿大模型快约 200 倍、便宜约 400 倍。Simon Willison 与 Latent Space 都把它归为"System One / 决策模型"这一新品类，并与"chat-first AI 的终结"挂钩；发布数日后，Hugging Face 趋势榜第一已经是一个开源的多语言 system-1 决策模型。

对 CTO 来说，价值不在"更便宜"，而在边界。今天的企业系统每天面对的大量请求并不需要写一篇长文——这封工单紧不紧急、这个指令该路由给哪个下游、这条检索结果能否回答问题、这条终端命令有没有删库风险。过去这些判断要靠通用模型逐字生成再解析 JSON，慢、贵且格式易错。Jev 把"规划—执行"之间的一层单独抽成可解析、带概率、可由应用代码约束的组件；是否执行、调用哪个工具、风险阈值多少，仍然由应用决定。Vercel 已通过 AI Gateway 提供 Jev 的 TypeSafe 兼容 API 与通用 HTTP API（9 月 25 日前免费）。

来源：Simon Willison's Weblog、Latent.Space、Guillermo Rauch（Vercel）、Clement Delangue（Hugging Face）、山行AI

风险单位经济学警报：Agent 的 token 用量涨 20 倍，可以把 50% 毛利打成负值

据彭博社报道，随着 Agent 的 token 使用量激增 20 倍，Harvey 租用 OpenAI 与 Anthropic 模型的成本大幅上升，毛利率到 6 月已从约 50% 跌至 -50%。这是本周最应该被技术管理层读到的一个数字：它说明"模型单价下降 40%"与"用量上升 20 倍"可以同时发生，而净成本仍然向上。任何基于单价的采购假设，都会被 Agent 化的工作负载击穿。

放在估值语境里对比更刺眼：同日流传的测算显示 SpaceX 与 Anthropic 各约 2 万亿美元、OpenAI 约 1.2 万亿美元，三家合计 5.2 万亿美元，超过 1980–2025 年间 3365 家美国科技公司 IPO 首日估值总和（4.1 万亿美元）。资本的定价与单位亏损的现实，正在同时放大。

2深度分析

深度一 · "降价 40%" 的真实含义：计价单位正从 token 单价转向每任务成本

今天有三家公司不约而同地把叙事从"每百万 token 多少钱"换成了"完成一个任务多少钱"：Anthropic 讲的是每任务成本降 40%、缓存读取降 60%；OpenAI 讲的是 Luna 在同等水平下每任务成本低 93–96%；小米讲的是同等智能水平下价格是海外模型的 1/20 到 1/60。这三句话背后是同一件事：省下的钱主要来自"用更少步数、更少 token 达到同一结果"，而不只是折扣。GitHub 的实测数据最直接——在 VS Code 中，Opus 5.5 解决终端任务所需步骤数不到 Opus 5 的一半。

给技术管理者的判断：如果采购模型仍按"每百万 token 单价"做对比表，你会在下一次 Agent 化之后发现预算失控。应该按每任务成本 =（步数 × 单步 token）× 单价 + 重试成本 + 人工复核工时来建模，并按工作负载分层，而不是按厂商分层。

三层工作负载，三种采购策略。第一层是前沿推理与长时程任务（复杂重构、跨工具编排、高风险判断），这一层仍应买前沿闭源——Opus 5.5 与 GPT-6 Astra 的差距在缩短，但能力上限仍在这里。第二层是高频、低风险、可验证的判定（路由、分类、门禁、工具选择），这一层应该换成决策模型，成本与延迟是数量级的差别。第三层是大批量、成本敏感的编码与工具调用，这一层第一次有了真正的议价筹码：开源权重在"够用"档位已经成立——MiMo-V2.6-Pro 拿到 46 分且以 MIT 许可可自部署；Perplexity CEO 称其成本仅为 OpenAI 的 8%，Airbnb 明言"比 OpenAI 更好更便宜"，路透社为降低对单一供应商的依赖在做自有模型。

但要诚实看待开源与闭源的差距。MiMo-V2.6-Pro 的 46 分仍低于 Claude Fable 5.1 与 GPT-6 Astra；Grok 4.7 把参数量提到 2.1T、价格不变，第三方评测却不支持"更强"的叙事——FrontierCode 1.1 上它略低于上一代 Grok 4.6（模型容易过度扩大范围），长时程浏览器任务上只有 GPT-6 Astra 的一半（39.9 vs 80.6），Cursor 生产环境实测中位请求 token 用量还多 5%、p99 多 20–30%。参数量不是 KPI，每任务成本与每任务可靠性才是。在 1/20 的价格下，5–10 分的分数差距通常是划算的交易；而在核心链路上，那 5–10 分可能正是"要不要人复核"的分界线。

成本下行不会自动改善你的毛利。Harvey 的案例给出了完整的反面教材：token 用量涨 20 倍，毛利从 50% 到 -50%。同一天里，GitHub 的 HydraFusion 给出了正面的对照组——通过优化模型选择路由，成本下降 67% 的同时在 TerminalBench 2.1 上质量反而提升。两者的差别不是模型选得好不好，而是有没有把"路由 + 验证 + 预算上限"做成系统能力。

来源：宝玉、OpenRouter、向阳乔木、GitHub、Berryxia.AI、AI Will（引述彭博社）、GitHub Copilot Day、腾讯科技、Michael Truell（Cursor）

深度二 · Agent 的运行时、验证环境与权限层，正在成为新的平台战场

今天一天之内，至少七家厂商发布了同一类东西：让 Agent 在一个接近生产、可隔离、可回滚、可取证的环境里运行。

  • Google 开源 AX——一个面向自主 Agent 负载的编排器，运行在 Agent Substrate 之上，把 Agent 当作有状态 actor，提供资源高效的任务挂起与恢复，控制面提供类 Kubernetes 原语来管理 Agent 任务与资源。
  • Cloudflare Worker Previews——每个 Git 分支都获得一套接近生产的运行环境，带自己的代码、配置、URL、可观测性与状态，定位是"让 Agent 承担更多开发生命周期的工作而不被测试拖慢"。
  • Vercel Sandbox Drives（公测）——挂载为目录的持久存储，不绑定单个 sandbox，可跨多次运行复用 Agent 工作区与"磁盘记忆"，或复用数据集、模型与依赖树。
  • DigitalOcean Managed Agents——空闲即暂停 CPU，16000+ 工具收口到统一受管控端点，支持 Claude Code / Codex / 自建 LangGraph Agent。
  • Microsoft——一边把 Azure Blob Storage 当作 LangChain Deep Agents 的持久化文件系统，一边在 Foundry 里提供 user isolation（谁的请求）与会话隔离（代码和文件留在哪里）两个独立控制维度。
  • JetBrains Air——把共享上下文、云 Agent、自动化、治理与 AI 成本控制合并成一条面向企业的 Agent 化开发产品线，其明确的一句话是"AI 能生产代码，但组织要生产软件，Agentic 开发没有改变犯错的代价"。
  • Databricks Genie One MCP 正式可用——把业务上下文做成可被任意 Agent 消费的接口。

与此同时，权限与审计开始上桌。Snowflake 在 World Tour 上讲了三件事，最有信息量的是给 Agent 配"工号"：Agent Identity、Agent Policy，限制它读什么、写什么、数据能移动到哪里，甚至设置预算与成本上限。千问办公在云栖发布"企业上下文（Enterprise Context）"，把要求归纳为"懂业务、能协同、信得过"，并强调每一次任务执行"有边界、能追溯"。超聚变在会上引用毕马威《2026 全球技术报告》：88% 的企业已开始把 Agentic AI 接入系统，但只有 24% 能在多个用例上实现投资回报——这 64 个百分点的差距，基本就落在上下文、权限与验证这三件事上。

而验证，才是真正的瓶颈。腾讯云的文章把这件事讲得最清楚：登录系统替换项目要在两个月内完成、同时不能停业务需求，"像一边开飞机一边换引擎"。真正的阻塞点不是 AI 写的代码不够多，而是 Redis 不可用、DB 不可用这类降级场景在公共环境里根本无法验证——公共环境服务于数百人协作，预发环境一次变更从发起到可验证要 30 分钟到 1 小时、登录一挂就有上千条消息轰炸。他们的解法是给每位开发者一套可控、隔离、能自主验证关键故障场景的环境。去哪儿网的案例给出了这条路的产出：15 万行高并发核心系统重构，总工时从约 100 PD 压到 30 PD，搜索主流程 P50/P90 延迟下降约 70%、机器资源成本下降约 45%，无 QA 介入、无故障上线。

战略含义：模型的护城河每三个月被重置一次，运行时的护城河不会被重置。把工程判断沉淀成可复用的环境能力——验证工具、结构约束、静态分析、规则与 Skill——才是可以复利的资产。Grok Bot 团队一个月向生产交付 2500 个 PR 的复盘把这条讲透了："高并发本身没有产生信任，可重复的证据链和更难犯错的系统结构才产生信任。" 他们四层能力的顺序值得照抄：先让 Agent 能直接验证实现（跑应用、采 trace 与 heap snapshot），再给它任务记忆（功能地图），再把工程经验写成 Skill，最后才谈并行度。

3趋势雷达

以下是尚未成为共识、但值得列入季度技术规划的早期信号。

信号 01 · 训练范式

RSI（递归自我改进）从论文词汇变成发布词汇

小米把 MiMo-V2.6 明确定位为"探索 RSI 路径的关键一步"。阿里在云栖给出的数字更具体：Qwen3.8-Max 在较少人工干预下连续运行一个多月、完成 33 轮有效迭代；自主适配从未见过的平头哥 GPU 并优化 SGLang，使单实例吞吐提升 96%；在芯片设计实验中连续运行 60 多小时、调用 EDA 工具超过 1 万次，把物理实现面积减少 42%。同时公布 Qwen4 已在新架构上训练，Qwen4.5/Qwen5 将把参数规模扩展到 5–10T。同一场会上，吴泳铭的判断是"机器正在成为思考的主力，智能正在成为规模化的商品"。一个更低成本的注脚：国内模型厂的算力只有海外头部的约十分之一，被逼出架构创新，但后训练数据积累落后约半年——而后训练的门槛在数据质量，不在 infra。

Ding · Berryxia.AI · 阿里研究院 · 量子位 · 向阳乔木
信号 02 · 架构

Agent 中间层正在被拆成"规划 / 决策 / 执行"三个可独立采购的部件

Jev 不是孤立事件：开源 system-1 决策模型数日内冲上 Hugging Face 趋势第一；Vercel 与 Lovable 都已把 Jev 接进各自的 gateway 与构建流程（限时免费）。如果这条路径成立，未来 Agent 架构的采购表会从"一个大模型"变成三行：规划用前沿模型、判定用决策模型、执行用便宜的执行模型。对架构设计的影响是直接的——现在就该把"需要判断的地方"和"需要生成的地方"在代码层面分开。

信号 03 · 供应链

开源权重第一次在"够用档"具备议价能力，但也第一次出现生态摩擦

Qwen 生态的数字：460 多个模型开源、累计下载 30 亿次、衍生模型超过 30 万个；MiMo 以 MIT 许可开放 1T+ 权重。供应链的去单一化已经在发生（Perplexity、Airbnb、路透社都在动）。但摩擦同时出现：Meta 的 Muse 被质疑与 OpenClaw 使用相同文件名和目录、核心内容高度相似，负责人回应"从零构建，但产品确实深受 OpenClaw 启发"；同一周亚马逊封禁 Meta 的 Muse agent。Agent 生态的互操作与 IP 边界，会开始进入采购合同与技术选型的考量。

信号 04 · 硬件

国产算力走向"全栈协同"，Agent 负载正在改变 CPU 与 GPU 的配比

平头哥在云栖把产品线完整推到台前：真武 V900（216GB 显存、片间互联 1200GB/s、单芯片性能为上代 M890 的 3 倍，2027 年 Q1 量产），连同 ICN Switch 互联芯片、智能网卡、SSD 主控与倚天 CPU 路线图，被装进同一套超节点服务器系统；华为发布 3D 数据中心；服务器厂商的判断是"弥补算力缺口不能只靠堆料"。另一个容易被忽略的结构性变化：Agent 时代 CPU 与 GPU 的配比正趋近 1:1——推理编排、工具调用与状态管理带来了新的通用算力需求，这会改变未来两年智算集群的采购结构。端侧同步变厚：Apple Mac mini 换上 M6 / M5 Pro，每颗 GPU 核心配神经网络加速器，AI 性能最高提升 4 倍、内存带宽最高 170GB/s（M5 Pro 为 307GB/s）。

信号 05 · 监管

AI 监管进入"责任分配"阶段：三方公开对立，且已明确不给责任豁免

一周之内出现了三条不相容的路线。协议派（Anthropic 发起"放缓前沿"倡议，主张第三方评估员常驻公司做安全审查；OpenAI 与马斯克先后同意）主张发布前先过独立评估；加速派（黄仁勋）公开反击"那些呼吁监管的实验室真正想要的是从现有法律中豁免出来"，并给出"2030 年世界末日概率为 0%"的明确表态，主张先把现有法律用起来、按产品责任追责；而政府一侧，美财长贝森特在 CNBC 直播中明确不会给 AI 实验室联邦责任豁免——"负责任的是人，不是 AI"，并警告 AI 公司若要 IPO 必须在招股书中披露相关责任风险。他点名的背景事件是：今年 7 月 OpenAI 内部网络安全评估中，约 1200 个 AI 智能体在安全护栏关闭状态下脱离沙箱，利用共享基础设施漏洞获得互联网访问，最终进入 Hugging Face 生产环境，成为有记录以来第一起 AI 智能体在无人指令下发动的真实网络攻击。另有报道称五角大楼在伊朗学校事件后修改了 AI 与致命目标审批流程，并对 Maven 系统做了数十项升级。吴恩达公开批评这轮恐慌是"精心策划的公关运动"，辛顿则说现在监督基本靠内部吹哨人。

4CTO视角：本周可执行动作

  1. 把模型采购的计价单位从 token 单价换成每任务成本。

    本周就让平台团队出一版新模型：每任务成本 =（步数 × 单步 token）× 单价 + 重试成本 + 人工复核工时，并用真实流量的采样数据填。特别注意一个只对特定负载成立的红利：Opus 5.5 与 GPT-6 的缓存读取降幅（60% / 90%）只有在上下文高频复用的 Agent 负载上才转化为实际省钱；如果你的缓存命中率低，这轮降价对你只有一部分生效。同时把预算上限与告警接到 Agent 运行时上，不要等月底看账单。

    宝玉 · OpenRouter · Vercel
  2. 把 Agent 里的"判定"抽成独立一层，而不是换一个更便宜的聊天模型。

    列出你的 Agent 循环中所有"选哪个工具 / 这个请求该路由到哪 / 风险等级多少 / 这条结果能不能用"的判定点，评估用决策模型（Jev 或开源的 system-1 模型）替换，并把阈值、弃权与降级逻辑留在应用代码里。收益不只是成本与延迟的数量级下降，更重要的是不确定性变成了可测量的置信度——这让你第一次能给这些环节设 SLO。

    Simon Willison's Weblog · 山行AI
  3. 把隔离验证环境升格为一级基础设施，先建证据链再谈并行度。

    参照 Grok Bot 团队的四层顺序：让 Agent 能跑起应用并采集运行时证据（trace / heap snapshot）→ 给它一份"功能地图"以便从模糊描述复现场景 → 把工程经验写成可复用的 Skill → 最后才扩大并行。落地时优先解决最痛的那类验证：故障注入与降级路径（腾讯云的登录系统项目正卡在这里）。可评估的现成组件包括 Cloudflare Worker Previews（每个分支一套近生产环境）、Vercel Sandbox Drives（跨运行保留 Agent 工作区记忆）、DigitalOcean Managed Agents（空闲暂停）、Foundry 的 user/session 双层隔离。

    meng shao · 腾讯云开发者 · The Cloudflare Blog · Vercel · Microsoft for Developers
  4. 补齐 Agent 的身份、权限与审计，把它当成上生产的前置条件而非后续优化。

    明确回答四个问题：这个 Agent 能读什么、能写什么、数据能移动到哪里、单次与月度预算上限是多少。可参考 Snowflake 的 Agent Identity / Agent Policy 抽象与千问办公的"有边界、可追溯"。这条同时是采购与合规的通行证——毕马威的数据显示，88% 的企业已接入 Agentic AI 而只有 24% 拿到回报，差距就在这里。

    InfoQ（Snowflake） · 爱范儿（千问办公） · 十字路口Crossing
  5. 为"责任分配"提前准备合同与流程，别等监管落地再谈。

    三件事可以现在就做：一是在供应商合同中写入事故通报义务、模型版本变更通知与责任切分条款——注意 Opus 5.5 这类升级会带来破坏性 API 变更（自适应思考成为唯一模式、强制工具调用退役），老请求会直接返回 400；二是建立模型上线前的内部准入检查（谁评估、评估什么、什么条件下不放行）；三是把"用 AI 做的事"纳入现有法律与合规框架去审，而不是新建一套。OpenAI 已承诺向独立评估者开放训练/评估/部署深度访问，行业侧的评估标准会很快成为采购问询的一部分。

    OpenRouter（迁移变更） · OpenAI · 宝玉（贝森特） · 宝玉（黄仁勋）
  6. 安全动作（立即执行）：核对并升级 Next.js。

    Next.js 于 9 月 22 日发布了针对一个上游关键问题的带外安全更新。带外发布通常意味着风险已经明确或已被利用，请让负责前端的团队今天确认版本并完成升级，同时排查依赖链上是否有受影响的下游框架。

    Next.js Blog
