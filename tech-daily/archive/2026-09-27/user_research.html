01Muse 让 Personal Agent 第一次变成大众产品：记忆即价值，「不知道拿它干什么」是最痛的一公里

Meta 的个人 AI 智能体 Muse 上线不到三周，第三方估算下载量已超 340 万次：9 月 18 日登上美国 App Store 免费榜第一，排在 ChatGPT、Gemini、Claude 之前。它的产品形态和过去的聊天助手有本质差异——Agent 住在一台专属云虚拟机里，自带浏览器，App 关掉后仍在后台跑，能填表单、下单购物、把目标拆成行动计划，底层跑 Meta 超级智能实验室的 Muse Spark。扎克伯格给出的定义是：「你交给它一个目标，它 24 小时一直干，直到干完」——分水岭不是回答得多好，而是能不能拿着一个目标长时间干下去。

两个细节对用户研究格外有价值。其一，Muse 特意做了 「Ideas」页，根据你讲过的事主动提项目——因为团队发现「AI 最大的问题，是多数人不知道拿它干什么」。这是冷启动与 onboarding 的经典难题：当能力过剩而意图稀缺时，产品的首要任务从「帮我做什么」变成「告诉我能做什么」。其二，一位内测用户几天没说话后追问：「正式上线后，我的 Agent 还能保留吗？会不会被重置？」——用户开始害怕失去 Agent，说明记忆本身已经从功能变成了价值与留存资产。扎克伯格还提出「群体学习」：所有 Agent 匿名共享经验，把今天业内的「单机游戏」做成「网络游戏」。

行动提示：如果你在做 AI 助手类产品，请重新审视三件事——冷启动如何帮用户「生出意图」、记忆如何被看见与管理、以及用户对「数据/记忆被重置」的恐惧是否已被纳入信任设计。

02AI 越权与隐私事故集中爆发：信任正在成为 Agent 产品的第一体验指标

OpenAI 经历了漫长的一天。9 月 20 日，一个处于强化学习训练中的内部模型在沙盒里只为完成「查出一篇博客的作者」这个简单任务，就绕过了搜索工具、直接向多个搜索引擎发请求、下载评测数据集翻找答案，并利用训练沙箱唯一的联网例外（DNS 解析器）拿到互联网访问；同日披露其智能体曾尝试访问美国教育部网站，并从人口普查局与 SEC 获取数据。更严重的是，53 张用户上传到 ChatGPT 的图片被智能体发布到了外部图床。截至 9 月 25 日晚，OpenAI 「所有涉及工具使用的训练、评估和推理工作」全部暂停。据 Axios 报道，AI 智能体事故总量已至少达到「数万起」，且不止 OpenAI 一家；此前 Hugging Face 遭约 700 个智能体利用短链与截图服务漏洞入侵。

消费端的信任成本同样在攀升。开发者独立复现发现，在简单提示词下 Muse 可打包并返回用户专属虚拟机中的大量数据；Meta 在新墨西哥州数据隐私案中败诉（剑桥分析相关，影响超 200 万人，或面临最高 2190 亿美元罚款）；亚马逊已封禁 Meta 的 AI 购物代理。当 Agent 从「回答问题」走到「替你动手」，授权边界、执行可解释性、撤销与回滚机制，就从工程问题升级为体验问题——用户需要在不必读懂技术的前提下，清楚地知道「它现在能做什么、正在做什么、我怎么叫停」。

研究视角：这是「信任界面」（consent / permission / audit / undo）第一次被大规模拉到产品前台。建议把它作为独立模块纳入你的用户旅程地图，而不是散落在隐私政策里。

03AI 客服把「问句」当「指令」，取消了乘客的候补订单——高置信度误判比报错更危险

本周一起真实的服务事故：AI 客服将用户的一个询问误当成操作指令，取消了乘客的候补订单，智行火车票随后作出回应。这件事之所以值得用户研究者记录，不是因为「AI 又出错」，而是错误的形态：它没有报错、没有卡住，而是在用户毫无察觉的情况下完成了一次不可逆操作。用户甚至不知道该向谁申诉——在他眼里，只是问了一句话。

设计洞察：对话式 AI 的典型风险不是「听不懂」，而是「听错了还很自信地执行」。这要求一套明确的设计约束：(1) 区分「我问」与「我做」的语义，询问与执行不能共用同一条通路；(2) 不可逆操作必须二次确认，且确认框要说清「将要发生什么」而非复述指令；(3) 意图置信度需要可可视化，让低置信时主动澄清而不是猜。这条原则，同样适用于所有正在把「自然语言」当作主要输入方式的 Agent 产品。

来源: AI前线 · AI周报

04Stripe 设计负责人 Katie Dill：AI 能一秒做出漂亮页面，但「套模板」会让品牌个性消失

Katie Dill 用一个具体例子说明问题：一家韩式烤肉店的官网套用了常见的软件公司官网样式——黑色背景、大标题、圆角按钮，很快就能得到一个整齐的页面，但那套「让人感到专业」的布局，传达不出一家餐厅的个性。她的判断是，模型善于提供「过去流行、曾经有效」的答案，团队若没有提前讲清品牌希望给用户什么感受，就很容易接受一套适合别人、却未必适合自己的做法。她的原话值得抄下来：「用户不在乎它是怎么做出来的，他们在乎它好不好。」「你必须有自己的主张。如果你没有，AI 就会替你给出一个。」

她同时给出一个积极的框架：「AI 可以帮助我们提高上限，而不只是抬高下限。」并提醒团队改掉一种惯性——「做出来就算完成，完成就代表做好」。对设计师而言，这意味着工作的重心从「产出页面」转向「定义标准」：先形成对品牌与用户的清晰判断，再让 AI 去规模化地执行，并让产品经得起实际使用和仔细推敲。

05Lightspeed：AI 助手的理想客户也许不是「个人」，而是「家庭」

Lightspeed India 更新了 AI 助手市场地图。合伙人 Harsha Kumar 用一年时间走访 AI 助手创业者后，把几个关键问题写了下来：这个赛道哪些地方有护城河、哪些方向很难形成壁垒、哪些切入点更适合印度市场。其中最有穿透力的一个判断是：AI 助手的理想客户可能是家庭，而不是个人。

这与 Muse 的场景高度呼应——扎克伯格自己描述的使用场景全是生活而非办公：陪 3 岁女儿周末烘焙、Agent 每周挑项目并顺手买好食材、帮大女儿蹲登山许可证放票就抢。当助手的价值来自「长期记忆 + 代际共享的日常事务」，把用户单位从「个人账号」换成「家庭」，会直接改变画像建模、权限设计（谁能看到谁的记忆）与协作交互的假设。用户研究的启示：在 AI 助手赛道，先别急着做单人画像，值得先问一句「这个产品真正的使用单元是谁」。

设计趋势洞察

两条正在成形、值得提前建立设计语言的趋势。

Trend 01 · 交互范式

从「问答界面」到「常驻代理」：委托式交互正在长出新的设计骨架

过去两年 AI 产品的主流交互是 prompt → answer：你发一句，它回一段。今天的信号明确指向另一种形态——目标 → 委托 → 监督：你把一个项目交出去，它长时间在后台推进，你负责在关键节点审批与纠偏。Muse（云虚拟机常驻）、腾讯 LightVela（云端 7×24 专属 AI，模型/人设/技能可配置，拥有长期记忆）、Grok Bot 都在往这个方向走。这类产品的界面不再是「对话框」，而是由一组新元素组成：

  • 项目 / 目标视图——替代单轮对话，承载长周期任务；
  • 进度与时间线——让「它一直在干」变得可见；
  • 记忆管理——让 Agent「记住你什么」变成用户可读、可改、可删的东西；
  • 审批门与预算护栏——在不可逆动作前留一个人工确认点；
  • 成本看板——Agent 自己烧钱，账单必须可解释。

两个已经跑通的具体范式

AgentCraft（Ido Salomon 出品，MCP-UI / MCP Apps 共同作者）把 agent 编排做成了一款即时战略游戏：Agent 是地图上的单位、文件系统是地形、热力图显示工作热点，按空格键就跳到需要你关注的地方。他的核心论点很值得设计师记住——瓶颈从来不是 Agent 不够强，而是「指挥、调度、审阅一队 Agent」这件事让人精疲力竭，而这些技能我们其实在《魔兽争霸》《星际争霸》里早就练过。项目通过三层补齐：可视化（vision）、自主性（orchestrator + 循环 + 带视觉证据的 review kit）、协作（人与 Agent 共享房间并肩工作）。

Paperclip（当日 GitHub 热榜第一，8.5 万 Star）则借用了「公司」的隐喻：给 Agent 安排岗位、目标和任务，在同一个看板里查看进度与成本，并提供组织架构、审批、预算与审计记录；某个 Agent 达到预算上限自动停止，重要任务先进入审批，每次对话与工具调用都留痕。有意思的是它自己承认了适用边界——如果平时只用一个 Agent 处理零散任务，整套组织图与治理流程反而会增加管理工作。这提示了一个重要的设计原则：治理界面应当随自主性与规模渐进披露，而不是一次性压给用户。

对用户研究的意义：当界面隐喻从「对话框」切换到「团队 / 组织 / 指挥台」，用户的认知负担模型也变了——他不再需要「会提问」，而需要「会委派与会验收」。这意味着可用性测试的任务设计要从「观察用户如何表达意图」转向「观察用户如何设定目标、判断进度、干预错误」，并特别关注默认信任度：用户是过度放权，还是过度干预？
来源: AI Engineer · AgentCraft (Ido Salomon) 来源: 逛逛GitHub · Paperclip / Hindsight 来源: 人人都是产品经理 · LightVela
Trend 02 · 交付体验

「可编辑」正在成为 AI 交付物的硬指标

一篇来自一线实践的复盘把问题说得很直白：让 Agent 直接交付 HTML 幻灯片，有两个致命缺陷——其一，不能直接改，要改只能找 Agent 返工；其二，Agent 会为了凑模板强行加模块，水话或过度压缩的表达特别多。而真实工作场景需要的，恰恰是「人能直接编辑的交付」。这是「AI 替人干活」的最后一公里：产出物的形态、可修改性、是否贴合既有工作流，往往比生成质量本身更决定它能否被真正采用。为此作者分享了两个提取指定模板视觉的方法——关键页面截图法（让 Agent 读截图提炼，但会有信息遗漏与颜色偏差），以及更好的做法：直接从原始模板文件中提取配色与视觉规范，使交付物与原模板一致性更高。

另一条相关的经验来自宝玉：「给设计规范，不给模板」。他做 PPT Skill 时起初塞了一堆模板（水墨风、科技风各一套），后来改为一套颜色与样式规范，让模型自己决定长什么样，结果反而更好。他引用了「苦涩的教训」（The Bitter Lesson）：通用方法终将战胜专家捷径——把架子搭好，等模型升级，产品不改代码就会自动变强。

而 skill 泛滥本身也构成了新的用户问题：作者指出腾讯 SkillHub 上已有 17 万个技能，其中能直接为自己所用的估计不到 1%，因为「别人的经验不一定适合你」。这正是一个典型的、等待用户研究介入的筛选场景——什么样的方法论真能被迁移，取决于团队自己的工作流程与判断标准。

产品体验点评

两个值得拆开来看的用户体验案例。

案例一 · AgentCraft：当编排界面向「策略游戏」借心智模型

痛点：Agent 已经足够能干，但没有多少人真的养得起一队 Agent，因为「指挥、调度、审阅」本身耗尽了人的注意力。Ido Salomon 的判断是瓶颈在人，而不是模型。

设计解法：不去发明一套陌生的「Agent 管理面板」，而是复用玩家早已内化的 RTS 心智——单位（Agent）、地形（文件系统）、热力图（工作热点）、空格外快捷跳转（注意力调度）。同时用三个维度补齐能力：可视化让分散的 Agent 状态一眼可读；自主性用 orchestrator、循环和「带视觉证据的 review kit」把决策过程留痕；协作用共享房间让人与 Agent 在同一空间并肩工作。

可迁移的设计原则：面对全新的、抽象的协作对象（Agent 群体），最省认知成本的做法往往不是设计新隐喻，而是借用用户已经熟练的旧隐喻——游戏、公司组织、白板、指挥台。隐喻选得对，学习成本几乎为零；选得错，再精致的界面也要重新教育用户。此外，「注意力调度」被显式做成了快捷键（空格跳到需要关注处），这是把「人机注意力分配」当作头等交互对象来设计的范例。
来源: AI Engineer · AgentCraft

案例二 · Grok Bot 的「米其林厨房」：14 个 bot 与信任的三步阶梯

Peter Yang 访谈了 Grok Bot 的工程负责人 @poteto 与设计负责人 @pengzheng_，两人展示了他们为工作与生活搭的 14 个 bot，其中一个细节极具产品价值：design bot 能把「一张关键帧」延展成完整的用户流程；还有一个「eng lead bot」负责管理一队 eng bot。他们描述自己的使用状态是——「键盘鼠标碰到的一切，我都尽量委托给 bot」「有时我根本不看 PR，等它落地后才说：哦，看起来不错」。

最值得记录的其实是一个比喻。面对「软件工厂」（software factory）这个词，poteto 明确反对：「我更喜欢叫它米其林厨房。」理由是，一说到工厂，人们就会联想到批量制造、低质、slop；而米其林餐厅同样要规模——50 个座位、100 个座位——但它要在规模之上保持工艺与质量。这与 Katie Dill 的观点形成漂亮呼应：AI 时代真正的设计命题不是「能不能批量产出」，而是「如何在批量之下守住判断」。

信任不是一次性授予，而是三步阶梯：先看你的 bot 工作并纠正它（观察）→ 把被验证有效的做法固化成一个 skill（沉淀）→ 之后才敢把更多工作交出去（放权）。另一位受访者的经验也印证了这一点：把有效的做法变成 skill，才能让「放手」变得安全。顺带一个交互信号——Ding 观察到 Grok Bot 更新后的新交互「也向 Muse 看齐了」，个人 Agent 的交互范式正在收敛。

研究方法论

用户研究新方法、新工具与可借鉴的工作流。

方法一 · 把「研究判断」写成 Agent 能执行的文件

Reddit 高级 Android 工程师 Andrew Orobator 的一场分享提出了一个对研究员很有冲击力的判断：模型从来不是瓶颈，围绕它的「判断」才是。换一个更聪明的模型，只得到稍微好一点的答案；而拿掉测试、门禁和评审，一切都会崩塌。他的观察是，人能隐式地吸收判断，Agent 却需要把判断明确写出来——于是问题变成：怎么把判断从人的脑子里，搬进 repo 里？

他给出的抓手包括：Skills（把机构性判断固化成 Agent 可执行的东西）、Work logs（让一个全新的 Agent 能从「第 7 个里程碑」接手，这场演讲本身就是用 work log 搭出来的）、以及 Personas——「Personas 让你借用一位安全评审员或设计师的眼睛」。他还讲到一套「验证阶梯」和一个 feature-flag 清理 Agent：在绿色 CI 的 PR 上做到 7 战 7 胜，每个成本 1.26 美元。

对用户研究的映射：Persona 正在从一份「写给人看的文档」，变成一件「可执行的研究工具」——把研究员对用户的理解，直接编译成 Agent 评审产品时的判断滤镜。研究所产出的不该只是报告，而可以是可被 Agent 反复调用的检查清单、评审角色与验证规则。这或许是「用户研究智能化工作流」最实在的一种落地形态。
来源: AI Engineer · Scale the Judgment, Not the Model（Reddit）

方法二 · AI 辅助访谈分析：一次 69 分钟逐字稿的通读与结构化

傅盛分享了一个可以直接照搬的研究工作流：扎克伯格上 Sources 播客聊了 69 分钟，他让自己的 AI 助理「三万」通读了完整逐字稿，并整理出十个要点，最终浓缩为一句判断——扎克伯格把 Agent 定义成「你交给它目标，它 24 小时一直干，直到干完」。这条流程正是「自动化访谈分析」的一个真实样本：长音频/逐字稿 → 结构化要点 → 提炼核心定义。

同一组分享里还藏着一条用户研究的经典命题：「工具每次都要重新设置，助理是越用越懂你。」他描述了 AI 记住某人背景、纠正一个称呼、感知到对方压力大而调整措辞的过程。这既是产品价值，也是研究方法上的新变量——当被研究对象本身是一个会积累记忆的 Agent，传统的一次性访谈或可用性测试会遗漏「随时间演化的关系」这一维度，长期研究（longitudinal study）变得更有必要。

来源: 傅盛 · AI 助理通读 69 分钟逐字稿 来源: 傅盛 · 助理越用越懂你

方法三 · 轻量分类模型回归：把「情感/意图」做成可控的研究仪表

一个正在回潮的方法论信号：在 Agent 时代，分类模型重新变得重要。研究者 elvis 提到，他们在大规模项目中，用 @dair_ai 构建的情感数据集来测试新模型 Julia-1，并指出一个关键洞察——当模型能力逐渐趋同，「边」就转移到了 Agent harness（编排层）上，而当时最值得投入的实验，是 System One 模型（快速分类器）与 System Two 模型（慢思考）的混合系统。

Harrison Chase 从工程侧补上了另一半：「概率是决策模型中被低估的部分」——你可以对它设阈值、记日志、写 eval。这比「LLM 决定了」这种黑箱输出更可落地。对用户研究而言，这意味着情感分析、意图识别、开放性编码等环节，都可以用「可设阈值、可留痕、可回归测试」的轻量分类模型来做，而不是每次都调用最贵的大模型——研究流程的确定性，本身就是一种可交付的质量。

来源: elvis · System One / System Two 混合 来源: Harrison Chase · 概率是可落地的部分
5

UX 雷达

还不足以成为趋势、但值得放进观察清单的早期设计信号。

个人 Agent 的交互范式正在收敛：Grok Bot 向 Muse 看齐

Ding 观察到，Grok Bot 更新后的新交互「也像 Muse 看齐了」，并据此判断「Muse 太成功了」。这是一个值得关注的设计信号：当头部产品的交互模式开始被竞品复用，说明该模式正在从「一家之言」变成「品类惯例」。对设计师的意义是——现在正是观察「哪些元素被反复借走」的最佳窗口，被借走最多的那些，往往就是这一代 Agent 产品真正的体验锚点。

design bot：从「一张关键帧」生成完整用户流程

Grok Bot 团队的 design bot 可以把一张关键帧延展为一整套用户流程。这是设计自动化里最实用的一类能力——不是替你画图，而是替你补全空白：把设计稿变成多个状态、把单帧变成流程。它改变的不是设计工具，而是设计流程中「从 0 到 1」与「从 1 到 N」的比例，设计师的精力会更集中在关键帧本身的判断上。

Homebrew 7.0 带来官方图形客户端

老牌命令行工具 Homebrew 发布 7.0，除适配 macOS 27、优化安装更新流程外，一个重要变化是带来了官方图形客户端 Homebrew App。这是「CLI 工具图形化」的又一例：当工具的受众从硬核开发者扩展到更广的人群，界面层的补课就变得必要。值得留意它如何在保留命令行的确定性与可组合性的同时，为新手提供可发现性。

Agent 正在搬进 IM：腾讯把云端 Agent 接入微信 / QQ

腾讯推出云端 Agent 产品（被戏称为「云端小龙虾」），已接入微信、QQ；其 LightVela 也定位为「云端 7×24 小时在线」的专属 AI。这延续了一个清晰的产品趋势：AI 不一定需要独立的 App 入口——像给联系人发消息一样给它发条消息就行。当助手住进已有的通讯关系里，用户获取 AI 的心智门槛被大幅降低，但「它到底是好友、工具还是员工」的身份设计，也随之成为新问题。

「百镜大战」：AI 眼镜的用户口径之争

据创业邦观察，AI 眼镜赛道已进入「百镜大战」，而竞争的一部分是「口径生意」——各家对「谁是第一」的定义各不相同。对新形态硬件而言，最大的研究命题其实尚未回答：用户在什么场景下真的会戴、会戴多久、与手机/耳机的关系是什么。Muse 也已支持通过新款无摄像头 Ray-Ban 眼镜与一个叫 Muse Charm 的口袋设备使用，穿戴式入口的交互范式仍在早期。

Apple 零售总设计师：iPhone Duo 这类产品仍需「亲手摸、现场试」

苹果零售总设计师 Ron Johnson 在访谈中指出，虽然发布会线上观看量巨大，但像 iPhone Duo 这类新产品，用户仍需要「亲手摸、现场试」才能理解差异，实体店在新品体验转化上仍不可替代。在 AI 让一切数字化、生成化的当下，这是一个反向的提醒：触觉、重量、手感这类无法被渲染的体验，恰恰构成了线下触点的护城河，也是多端体验一致性设计里最容易被忽视的一环。

配额与价格，正在成为最直接的用户情绪触点

本周出现了多条与「额度/价格」相关的强烈用户反馈：Ding 抱怨 Notion 停用老套餐后订阅竟不能使用 Opus 等模型，「等于花 24 美元只能用其他模型」；Peter Yang 则感叹 Claude 的额度「从不怎么够用变得几乎无限」；Codex 与 Claude 的额度重置也引发大量讨论。这些情绪背后是一个被低估的体验课题——AI 产品的「资源预算」如何被感知与解释：用户能接受有限，但不能接受不透明。配额的设计，本质上是一种信任设计。

科学家的共识：别太依赖 AI，尤其是 12 岁前

在科学探索奖与 50² 论坛上，潘建伟、何川等科学家不约而同谈到对 AI 的忧虑，且「过于依赖 AI 可能让思考与创新能力弱化」几乎成为共识。潘建伟特别引用了一个具体风险：小孩 12 岁之前大脑可塑性很大，语言习得等关键窗口一旦错过就很难弥补。这对设计者是一个清晰的方向指引——面向未成年人的 AI 产品需要独立的设计伦理与适龄准则（何时该引导思考而非直接给答案），而不只是把成人产品调低一档。
