战略级Anthropic Q3 营收 168 亿美元、环比增长约 45%，实现调整后盈利并冲刺 IPO

Anthropic 在 IPO 前投资者会议上披露：Q3 营收达 168 亿美元（Q1 约 48 亿、Q2 约 116 亿），环比增长约 45%，并宣布第三季度实现调整后盈利——而 2025 年全年运营亏损还超过 80 亿美元。更值得 CTO 关注的是单位经济模型：Q3 每花 1 美元算力带来 1.70 美元收入，调整后运营利润率（剔除股权激励）约 11%。同时 Anthropic 披露，"蒸馏"（竞争对手用其模型输出训练自家模型）贡献了约 5%–7% 的收入。

为什么重要：这是"前沿模型能否成为可持续生意"的关键验证点。收入增速在放缓（Q1→Q2 增约 140%，Q2→Q3 增约 45%），但毛利率转正意味着算力投入的商业化拐点正在到来；而"蒸馏收入"的存在则暴露了模型能力护城河的脆弱性——能力领先者同时也在为追赶者供血。

成本曲线开源权重模型占 71.5% 的 token 用量，却只占 23% 的支出

Vercel 基于 AI Gateway 生产流量的月度指数显示：开源权重模型已处理超过七成的网关 token，但只贡献约四分之一的支出，其支出份额自 6 月以来增长超 4 倍。9 月网关支出约为去年 12 月的 13 倍，而平均每 token 价格下降了 47%。同时，近三分之一的团队在 9 月更换了自己最常用的模型供应商——创下该指数纪录。另一个信号：9 月通过该网关的国产模型支出中，近 70% 经由美国本土基础设施完成。

为什么重要：这条数据把"开源 vs 闭源"的争论从理念之争变成了财务事实——企业生产负载正在用开源权重跑量、用闭源模型兜底复杂任务。价格年降 47%、供应商月换率约 1/3，意味着模型层的转换成本正在快速下降，"锁定单一供应商"已不再是最优解。

基础设施Modal 冲击"AI 基础设施十角兽"：ARR 破 10 亿美元、D 轮融资 7.5 亿美元

Modal 完成 7.5 亿美元 D 轮融资，投后估值 157.5 亿美元，成为纽约最新的 AI 基础设施"十角兽"。5 个月内用量与估值双双增长 3 倍，一年增长 15 倍。其核心产品 Sandboxes（2023 年推出，用于承载 LLM 生成的代码）如今已是单个 3 亿美元年化营收的产品，三年间累计拉起接近 30 亿个沙箱。客户场景覆盖后台 Agent、强化学习、vibecoding 平台等。

为什么重要：Agent 时代真正跑出规模的基础设施，不是"更快的模型"，而是安全、弹性、可编排的代码执行环境。沙箱是一个被严重低估的品类——它同时承接了 Agent 的自主执行、模型评测与 RL 训练。对于自建 Agent 平台的团队，这意味着"自研还是采购沙箱运行时"将成为一个明确的战略取舍问题。

竞争格局Meta 发布 Muse Spark Open：迄今最强的美国开源权重模型，同步登陆全云平台

Meta 发布 Muse Spark Open，定位"迄今最强的美国开源权重模型"，规格为 816B 总参数 / 42B 激活、100 万 token 上下文，原生多模态（文本、图像、视频、音频），主打编程与长程 Agent 任务。发布即同步接入 Baseten、Fireworks、Groq、Modal、Nebius、OpenRouter、Together AI 等推理平台，权重可在 SageMaker、Google Cloud Model Garden、Hugging Face、Microsoft Foundry 下载。该 816B 模型在 NVIDIA GB300 NVL72 上训练，Meta 同时产出面向 Blackwell Ultra 优化的 NVFP4 检查点，单 GPU 输出超过 5 万 tokens/秒。

为什么重要：美国厂商终于拿出了参数规模上能与开源阵营正面对抗的权重模型，且采取"权重 + 全云分发 + 宽松商用许可"的开放策略。结合上一条"开源占比七成 token"的数据，这标志着开源权重正式从追赶者变成企业生产负载的默认选项之一。

组织与工程AI 写代码太快，Anthropic 不得不替换掉 Git：合并量 12 倍增长，7 人 5 个月重建基础设施

报道称，因 Claude 生成代码量激增，Anthropic 的代码合并量从每天 2,500 次飙升至 30,000+ 次，原本为人类工程师规模设计的 Git 基础设施成为瓶颈。最终 7 名工程师用 5 个月构建了内部系统 Scion，实现基础设施减少 200 倍、代码检出速度提升 100 倍。

为什么重要：这是"AI 生产力提升"最容易被忽视的副作用——瓶颈从"写代码"转移到了版本控制、CI、评审与合并等工程基建。当 AI 让单个工程师的产出提升一个数量级时，为人类协作规模设计的工具链会率先崩溃。对 CTO 而言，这提示平台团队需要提前重估工程基建的容量假设。

深度分析

Deep Dive

深度①：AI 编码竞争已换赛道——从"能不能生成"到"能不能进工程体系"

过去一年的核心问题后移了：生成能力本身已很难构成差异化，真正的战场是 AI 产出的代码能否被工程体系接纳、验证、治理与追溯。

信号一：改造代码库以适配 Agent。Instagram Direct 将 Android UI 从传统 View 系统迁移到 Jetpack Compose，打造"AI 原生"的 UI 代码库，使 AI 编码 Agent 更易理解与维护——结果 UI 代码量减少 50%、AI Agent 单次会话的 token 成本下降 33%。代码量本身就是成本，这为"为 Agent 重构代码库"提供了明确 ROI。

信号二：把 Agent 当"工程参与者"，而非"更快的打字机"。Meta 在其新应用 Forum 中实验了 AI 原生工程方式：刻意把 Agent 当作开发流程的参与者，衡量标准不是代码量，而是"已验证、可上生产的产出"（能构建、能通过测试的变更）。Meta 并公开了哪些做法有效、哪些无效。这实质上是在重新定义"工程生产率"的度量口径。

信号三：补齐 Agent 的代码理解能力。Netflix 将 JetBrains 与 IntelliJ IDEA 同源的无头代码智能引擎接入 Claude Code 与 Codex，解决了 Agent 在 Java/Kotlin 代码库中跨 JAR 边界导航困难的问题，并做了系统化基准测试。这揭示了 Agent 效率的一大隐性瓶颈——跨编译产物边界的代码理解，正被专门的代码索引引擎补上。

信号四：方法论与信任问题。InfoQ 的行业讨论指出，vibe coding 的成本只是被"推迟"了：长会话上下文衰减、决策不可追溯、从 Demo 到生产的鸿沟，最终仍需人力补回工程化工作；AWS Kiro 给出的答案是"规范驱动开发"（spec-driven development）。另一场基于 40 万亿 token 使用数据的演讲则强调，真实的 AI 采纳取决于信任而非模型基准，并点名上下文构造、多模型路由、反馈闭环三大失败点。企业侧样本也在出现：Stripe 用 LangChain 的开源 Agent 框架 Deep Agents，1 周内搭起了全公司知识 AI 平台 Kai。

CTO 判断：竞争焦点正从"模型选型"转向"工程体系改造"。值得投入的三件事：一是代码库可 Agent 化（降低复杂度、统一风格、减少长尾依赖）；二是确定性工程护栏（规范驱动开发、测试左移、可追溯的决策记录）；三是把生产率度量从"代码量"切换到"已验证的可上生产产出"。工具与模型的领先窗口正在缩短，真正的护城河是工程体系的适配速度。

深度②：企业 AI 的成本曲线与"多模型、可控、可治理"平台化

当 token 价格一年降 47%、供应商月换率高达三分之一，"模型中立的多模型网关 + 治理"正在从可选功能变成企业 AI 基础设施的标配。

成本侧的证据。Vercel 网关数据显示，9 月平均每 token 价格同比下降 47%、当月支出为去年 12 月的 13 倍——量在暴涨、单价在暴跌。企业侧近三个月 token 用量翻了两番；OpenAI 披露 2025 年 8 月至 2026 年 6 月，非开发者 Codex 用户增长 189 倍，这类"公民开发者"（citizen developer）正在成为企业软件生产的新主力。

供给侧的定价动作。Google Gemini 4 Argon 面向全球开发者与企业开放，主打复杂编程与长流程任务，API 限时价为每百万 token 输入 2 美元 / 输出 10 美元，12 月 1 日起恢复为 4 美元 / 20 美元（涨幅 2 倍）——这提醒企业预算需按调整后价格测算。Vercel 推出的 Token Pass（30 美元/月含 80 美元额度、默认零数据留存）正是"打包多模型额度"的典型形态。

治理侧的补位。随着公民开发者用 AI 直接写应用，控制与治理变得空前困难：员工在未经批准的情况下使用 AI 工具，一个写错的登录页就可能把私有数据暴露到公网。厂商密集补位——Vercel for Enterprise、BYOC on AWS（函数代码与执行留在企业自有合规边界内）、面向 Agent 的持久化存储 Vercel Drives；Google Cloud 为 Agent 这类"非人类身份"（NHI）推出 VPC Service Controls 增强，把治理粒度从人工网络边界下沉到机器速度；Cloudflare 与 OpenAI 则用网络信号帮助 ChatGPT 更高效地发现内容（早期结果"非常正面"）。

反面视角。Perplexity CEO 提出把赌注押在"中立编排、递归式收入与本地算力"上，认为下一轮增长来自"小而强的 AI 原生公司"而非巨头，并称企业端增长已超过个人专业用户。这与 Vercel 的"多模型网关"数据互相印证：不绑定任何单一模型、芯片或客户规模，正在成为一种被验证的商业与架构策略。

CTO 判断：企业应尽快把"模型采购"升级为"模型组合管理"——建立统一网关做成本路由与可观测性、为开源权重预留主力跑量位、为高价值任务保留前沿闭源模型，并把数据留存、权限、Agent 身份治理纳入同一套平台。价格战仍在继续，但治理能力的差距会先于价格差距拉开竞争身位。

CTO 视角 · 行动建议

Action Items

面向技术高管的 6 条具体动作

  1. 把模型采购升级为"模型组合管理"。建立统一 AI 网关，做成本路由、可观测性与降级策略；为主力跑量负载配置开源权重（如 Muse Spark Open 这类美系开源，或国产开源），为高价值/长程任务保留前沿闭源模型。鉴于近三分之一团队每月更换供应商、单价年降 47%，避免任何形式的模型锁定，并把转换能力本身当作一项架构资产。
  2. 给 AI 产出的代码补上确定性工程护栏。采用规范驱动开发（spec-driven）、测试左移、把 80–90% 的测试工作揉进编码过程，确保每一次 AI 变更"能构建、能通过测试、可追溯决策"。同时把研发效能的度量口径从"代码量/提交数"切换到"已验证、可上生产的产出"。
  3. 提前重估工程基建的容量假设。Anthropic 合并量 12 倍增长、被迫替换 Git 的案例说明：当 AI 让单人产出提升一个数量级时，版本控制、CI、代码索引与评审会率先成为瓶颈。现在就该评估代码库复杂度、跨模块依赖边界与 CI 吞吐，并考虑接入专门的无头代码理解引擎（如 Netflix×JetBrains 方案）提升 Agent 的导航效率。
  4. 为 Agent 建立"非人类身份"治理体系。Agent 会自主决策、跨项目取数、以机器速度行动。参照 Google Cloud 对 NHI 的治理思路，把 Agent 的身份、最小权限、执行环境隔离（沙箱）、持久化存储与数据留存策略统一纳入平台；对"公民开发者"场景，优先采用能保证代码与数据不出合规边界的方案（如 BYOC）。
  5. 评估沙箱运行时的自建 vs 采购。沙箱已是明确的独立品类（Modal 沙箱产品年化 3 亿美元营收），同时支撑 Agent 执行、模型评测与 RL 训练。明确自研边界：除非沙箱是你的核心差异化，否则优先采购成熟的弹性/安全沙箱，把工程资源留给业务。
  6. 把 Physical AI / 具身智能纳入战略观察清单。通用模型正在侵入专用具身模型的领地（AA-Robotics 榜首为通用模型、GPT-6 Astra 可直接输出末端位姿），叠加 AMD 收购 World Labs、宇树 IPO 与地缘管制，行业或在 12–24 个月内重新洗牌。物理数据采集与安全是当前最大缺口——若业务与制造、物流、机器人相关，应尽早占位数据与合作生态。
