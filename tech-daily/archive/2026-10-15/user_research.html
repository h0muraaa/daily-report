1

AI 的 UI 设计能力“合格但不出彩”：创造力评分远低于人类

Kombaico 发布的 Design Creativity Bench 首次系统评测了 AI 模型在 UI 设计任务上的“创造力”：80 个开放式 UI 任务、跨两个产品领域共 160 份设计简报，并配 34 个模型与人类设计师参考作品。理论框架沿用“创造力 = 新颖性 + 适切性”，从原创性、创意广度、适切性三个维度打分。

结果对做 AI 辅助设计的人非常关键：最强模型 GPT-6 Astra 得分 65.5，人类设计师基线为 92.3，差距近 30 分。模型在“适切性”（满足验收标准）上甚至略胜人类（最高 99.2% vs 人类 98.0%），是出色的执行者；但原创性显著不足——模型彼此的设计相似度高达 0.592，而人机之间只有 0.764，说明模型收敛到了一种“平均审美”，彼此更像，反而与人类差异更大。

2

“所有 App 都在塞 AI，但用户已经烦了”

创业邦转载镜相工作室的报道指出，AI 功能正在无差别进入每一个 App：搜索框旁多了 AI 图标、侧栏冒出 AI 助手，有的 App 干脆把 AI 入口挪到原“首页”底部导航的位置。一位有游戏社区 AI 背景、如今在深圳做产品设计咨询的从业者直言，现在绝大多数 AI 助手都很“垃圾”。

更值得研究员注意的是数据层面：QuestMobile 显示 2025 全年内嵌 AI 插件的月人均使用频次同比增速是独立 AI App 的 2.8 倍——即用户更多是在既有 App 里被动接触 AI，而非主动下载独立 AI 应用。这提示产品团队：AI 功能的“存在感”与“使用意愿”正在脱钩，堆砌入口未必能换来留存。

内嵌 AI 插件频次增速 = 独立 App 的 2.8×

📎 来源：创业邦

3

设计工具正把“设计系统”喂给 AI Agent

Figma 在 Config India 上发布了一批以 Agent 协作与设计系统为中心的能力：Code Layers（在画布上直接构建代码驱动的原型，开放 beta）、Specs（一种承载上下文、可协作的 markdown 新媒介）、Guidelines（用规范给 Agent 提供设计系统上下文，开放 beta）与 Code Sources（封闭 beta）。

对用户研究员的意义在于：设计系统第一次成为“给 AI 看的接口”而非仅供人类查阅的文档。当 Agent 能读取品牌规范、组件约束与代码来源时，“设计一致性”的保障方式从人工 review 转向了规范前馈，这会影响未来设计评审与走查的工作内容。

4

硬件体验的新战场：把“采集”无缝接进日常工作流

极客公园对 OPPO AI 心力球的体验报道点出一个行业共识：24 小时录音硬件本身已不新鲜，真正的难题是“如何把录下来的东西自然地融入日常工作流”。心力球主机仅 9.8 克，配合 C 桥夹持结构可别在衣领或背包带，夹持力 4N 以上、IP55 防尘防水，并设了一枚“不用掏手机的重点键”。

这背后是手机厂商与独立硬件创业者的路线差异：独立团队倾向于再造一个硬件加独立 App 再收订阅，而 OPPO 直接把小硬件融进手机这一最高频入口，让它成为既有体验的延伸。对 UX 的启示是——可穿戴 AI 的胜负不在转写精度，而在“零摩擦接入既有工作流”的触点设计。

📎 来源：极客公园

5

“当软件的主要用户从人变成 Agent，UI 将被重写”

AI Breakfast 的一则判断值得产品人警惕：过去 25 年软件建立在一个假设上——点击的是人，于是有了仪表盘、表单、菜单、引导流程和按席位定价；而 Agent 不需要这些，它们要的是干净的 API 与结构化数据、清晰的权限与审计轨迹、按任务而非按席位计费。

该观点认为下一波是“human-first → agent-first”的重构，且巨头会被困住，因为它们的护城河恰是 UI 和席位授权——正是 Agent 让之过时的东西。对研究员而言，这提出了一个新命题：我们未来的“用户旅程”可能一半是人在看、一半是 Agent 在读，两者对信息密度与反馈节奏的需求截然不同。

📎 来源：AI Breakfast(@AiBreakfast)

设计趋势洞察 深度分析

趋势一：设计工具的“AI 中间层”——从画布到规范前馈

把今天 Figma 的系列发布串起来看，会发现一条清晰的战略主线：Figma 正在把自己从“人类协作画布”改造为“人机协作中枢”。Code Layers 让代码与设计在同一画布上共存（Chrome 扩展甚至能抓取网站代码直接带回 Figma 作为 code layer）；Specs 用可协作的 markdown 把上下文在设计与代码之间搬运；Guidelines 与 Code Sources 则把设计系统和代码来源作为 Agent 的上下文供给。再加上即将把 Payload 引入 Figma Make，团队可以直接用真实数据与内容创建、构建、上线网站。

深层含义：设计系统的价值锚点正在转移。过去设计系统的成功靠“人愿意查、愿意用”，现在还要靠“Agent 能读懂、能遵循”。这意味着设计系统的交付物须同时面向两类读者——人类需要可探索的可视化，Agent 需要结构化的约束与语义。团队在做组件库与 Token 治理时，值得提前为“机器可读”预留一层。

人机共用画布规范即上下文设计回写代码

趋势二：从“找需求”到“找差一点就能实现的事”——AI 产品设计的时机方法论

Google Labs / Gemini / AI Studio 负责人 Josh Woodward 在 Lenny's Podcast 中提出一个对产品设计极具操作性的概念：“What's almost possible”——今天 AI 还做不好、但已非常接近能做好的事情。Google Labs 内部维护着这样一份清单，其方法论包含三个关键思想：不找“现在 AI 能做什么”，而找“还差一点点就能做成的事”；等待技术跨越临界点（Phase Shift），因为模型某项能力哪怕只提升一点点，用户体验也可能从“几乎不可用”跃变到“非常好用”；并持续实验、提前研究可能的产品形态，一旦能力突破临界点就立即产品化。

对研究员的启示：这把“用户需求”与“技术成熟度曲线”显式耦合了起来。传统用户研究擅长回答“用户想要什么”，但面对 AI 产品，还需要回答“用户此刻能体验到什么”——同一需求在模型能力的不同刻度上会导出完全不同的产品形态。一个可落地的做法是：把“临界点观察清单”纳入研究流程，持续跟踪延迟、多模态、语言覆盖等能力指标，并同步研究用户行为随能力变化的迁移。

📎 来源：刘小排r（转述 Lenny's Podcast / Josh Woodward）

产品体验点评 案例分析

案例一：Personal Agent 的“口碑与留存”背离——好看的入口不等于留得住

“always-on 个人 Agent”成为 2026 年秋天最拥挤的赛道：OpenAI 的 dots、Meta 的 Muse（上线 12 天全平台装机约 280 万，一度冲到美区 App Store 总榜第一，直接住进 WhatsApp）、Google 的 Gemini Spark 与 Grok Bot 纷纷押注独立云电脑与后台常驻。但一位观察者的实测给出了更真实的用户体验切片：他用 ChatGPT 调研“Personal Agent 哪家好”，ChatGPT 把自己排第一，而社区对 Dots 的反馈“差评如潮”；口碑更好的是 Grok Bot 与 Mate Muse，而从一张留存图看，Muse 的留存表现更优。他自己则更偏好 Grok Bot。

体验解读：这组信息至少暴露两层问题。其一，装机量与留存出现明显背离——新鲜感驱动的下载无法预测长期黏性，评估这类产品必须看留存而非榜单。其二，用户口碑与厂商自评严重脱节，且这层偏差恰好发生在“让 AI 调研 AI”的场景里，暴露出模型作为“研究工具”时的自我偏袒风险，提醒我们不要用被测对象来评价被测对象。此外，Anthropic 至今未推出正面对标 dots / Muse 的消费级产品，其策略被解读为把“个人 AI”做成了分布式的开发者形态（如 Claude Code），而非消费入口——这是产品定位层面值得持续追踪的分野。

📎 来源：向阳乔木(@vista8) · 口碑与留存对比 · 极客公园 · 为什么 Anthropic 不做 Personal AI

案例二：主动式个人 Agent 的“信任设计”——把每次读取与操作做成看得见的授权

字节跳动技术团队分享了基于火山引擎 Managed Agents 搭建的主动式个人 Agent「Open Muse」实践。其设计目标很明确：用户无需自建“能长时间运行的 Agent 循环、关掉 App 也不中断的会话、隔离的云端电脑、长期记忆、工具接入”这一整套底座；而 Open Muse 在上层补齐了设备、主动性与账号体验，接上 iPhone、Mac 与飞书，按时间与目标主动找用户。

体验解读：最值得研究者关注的是它对“主动性”与“可控性”的平衡处理——把每一次读取和操作都做成看得见的授权。在“关掉 App 后 Agent 仍在后台干活”的场景里，用户最大的心理障碍并非能力不足，而是“我不知道它背着我做了什么”。把授权可视化，本质上是把 Agent 的隐含行为转译为可预期的用户旅程，这与隐私敏感型产品的通用原则一致：代理越主动，透明度要求越高。

📎 来源：字节跳动技术团队

研究方法论 新方法与工具推荐

① 用“设计创造力基准”量化 AI 辅助设计的边界

Design Creativity Bench 提供了一个可复用的评估范式：开放式任务 + 人类参考基线 + 多维度（原创性 / 创意广度 / 适切性）打分。团队若在引入 AI 生成设计方案，可借鉴其思路自建小规模内评——重点不是“AI 能不能做对”，而是“在多大程度上会趋同”。该基准揭示的“模型收敛到平均审美”现象，直接指向一个实践建议：把 AI 用于探索阶段的方案铺量，把差异化与品牌调性的判断留给人，或通过更强约束（Guidelines / 品牌 Context）来撬动人机相似度的提升。

📎 来源：meng shao(@shao__meng)

② 把“界面本身的形态”当作变量：文本界面如何影响多模态推理

arXiv 论文《Designing Textual Interfaces To Enhance LLM Reasoning On Audio-Visual Question Answering》研究了一个对交互设计有直接借鉴意义的问题：在音视频问答任务中，文本接口的设计方式如何影响提示优化的效果。研究对比了三种接口设计——单一全模态大模型的直接推理系统、captioner–reasoner 两段式系统、以及由主 Agent 编排多个子 Agent 的 agentic 架构，并结合 Qwen3-Omni 与 Gemini 做了实验。

方法启发：它把“界面 / 信息通路设计”提升为影响系统性能的自变量，而非事后包装。对做 AI 产品交互的研究员来说，这提示我们在设计 AI 功能时，应把“信息以何种结构呈现给模型”当作可实验的设计决策，用 A/B 或对照实验去验证——这与传统的界面可用性测试一脉相承，只是被测对象从人扩展到了模型。

📎 来源：arXiv:2610.20085 · eess.AS

③ 交互动词交给用户：把“研究提问节奏”做成可配置项

meng shao 介绍了 Matt Pocock 为 /grill-me Skill 引入 GRILL.md 配置文件的做法，其三个作用对研究方法颇有隐喻价值：用配置实现组合（取代命令变体）、可定制“拷问”的侧重点（不同团队/项目在规划阶段关心的维度不同，有人在意安全、有人在意模块划分）、以及可定制交互节奏——用户可以选择 AI 一次只问一个问题（逐条深入、对话感强），或一次性列出所有问题（整体浏览、效率优先）。

方法启发：将“交互节奏”的选择权交还给使用者，正是深度访谈与问卷两种研究手段的本质差异所在。当 AI 成为研究流程的一部分（自动追问、自动生成问卷）时，这一配置化思路可以直接迁移：让研究员按场景声明“逐条追问”还是“批量列举”，从而在“对话感”与“效率”之间做有意识的取舍，而不是被工具预设的固定套路绑架。

📎 来源：meng shao(@shao__meng)

④ 情感计算：从“硬判断”走向“连续证据”

arXiv 论文《Shared Sentiment Evidence from Frozen Multimodal Models for Continuous Sentiment Prediction》针对一个长期困扰情感分析的问题：当语言、声学、视觉线索相互矛盾时，如何估计情感的极性与强度。作者提出 SSE（Shared Sentiment Evidence）——一种在冻结主干模型间保持视角与情感选项语义一致的“输出空间接口”，用四个查询得到五选项分布，并将其概率、熵与跨视角关系构成 28 维向量，再做 CatBoost 回归；在 CH-SIMS-v2 与 CMU-MOSI 上，基于 Qwen 的接口优于纯联合监督的基线。

方法启发：“硬判断会压缩情感备选”这一洞察对用户研究同样成立——无论是访谈编码还是开放题打分，强制单选题往往丢失信息量。保留分布（概率与熵）而非只取最大类，能让研究者看到“用户有多犹豫”这一本身就有价值的信号，这与情感计算中“连续预测”的取向不谋而合，也为自动化访谈情感分析工具提供了更细粒度的输出范式。

📎 来源：arXiv:2610.19981 · cs.MM

UX 雷达 值得关注的早期设计信号

  • 表情与语气的“可表演化”：字节 OmniHuman 2.0 数字人模型上线，能读懂音轨中的语气、情感与每个词并表演出来，口型、表情与身体动作协调一致，单镜头可生成长达 5 分钟视频，价格从 $0.12/秒降到 $0.07/秒。当“情感表达”成为可批量生成的素材，UI 中的虚拟形象设计将面临“真实感阈值”的重估。（来源: 小互(@imxiaohu)）
  • 噪音场景下的语音可懂度成为对话式 AI 的体验短板：arXiv 论文提出模拟人类 Lombard 效应的噪声感知语音合成方法，指出多数现有系统在嘈杂环境下“声学迟钝”，导致人机沟通可靠性下降。这提示做语音交互的团队：真实使用场景（通勤、户外、公共空间）的可用性测试不能只在安静环境里做。（来源: arXiv:2610.20181 · cs.SD）
  • 个性化音频：从“通用音效”到“因人而异”：SPARO 用神经算子把稀疏测量的 HRTF 升采样为可任意方向查询的连续场，在 SONICOM 的 LAP24 配置下取得最优的 log-spectral distortion 与 ILD 误差。空间音频走向个性化，意味着 XR / 沉浸式产品的“听觉舒适度”将成为可设计的体验维度。（来源: arXiv:2610.20400 · cs.SD）
  • 设备寿命与可维修性被纳入设计目标：Google 在国际维修日强调“为长寿而设计”，让维修与再利用更易获得。可维修性正从合规议题变成产品体验叙事的一部分——对做硬件体验的研究员而言，这是“全生命周期用户旅程”的重要一环。（来源: Google The Keyword）
  • “无限画布”式的多模态创作界面：豆包工作上线的“无限画布”把图片与视频生成能力直接放进一块无边界面板，素材可平铺、可上传修改、可一键调用作为二次创作参考，试图解决“工具割裂”这一创作体验顽疾。这类“一块画布承载全流程”的界面范式值得交互设计师持续跟踪。（来源: AI寒武纪）
  • “物体本身即解释”的交互式科普：开源 Skill「Anatomy」把抽象原理做成可运转、可拆解、可交互的机械模型动画（如机械表、劳斯莱斯 Trent 970 发动机剖视图），核心理念是“The object is the explanation”。它为知识类产品展示“动态可探索”的替代路径。（来源: 数字生命卡兹克）
  • “一句话生成可交互作品集”：有设计师分享用 AI 生成单屏可交互个人主页的流程——鼠标平移时卡片反向滚动、点击展开项目详情，并可将页面导出为 Agent 资料包交给 Codex / Kimi / 豆包工作二次编辑。这反映出设计师的工作流正在向“描述意图—预览—导出可迭代资产”迁移。（来源: 超人的电话亭）
  • 用户反馈闭环被公开化：Philipp Schmid 就 Gemini 4 Argon 公开征集早期反馈并承诺逐条查看、改进体验。模型产品开始像消费级软件一样运营“用户之声”，值得留意这种把用户反馈机制前置到模型发布节奏里的做法。（来源: Philipp Schmid(@_philschmid)）
