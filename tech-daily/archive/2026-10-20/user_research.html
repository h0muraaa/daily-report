设计价值 / 行业判断

“模型进步不等于产品进步”：Figma CEO 给 AI 设计热泼冷水

在 All-In 播客专访中，Figma 创始人兼 CEO Dylan Field 给出一个反直觉判断：“人们很容易把模型的进步，误当成产品的进步。”这句话的背景是，Anthropic 的 Claude Design 正面进入设计工具市场，而 Figma 仍在最近一个季度交出营收同比增长 48% 的成绩单。Dylan 的核心论点是：当写代码的门槛趋近于零、应用供给指数级膨胀时，真正稀缺的不再是功能实现，而是审美、品牌调性与情感共鸣——“设计是新的底层代码”。

他也修正了自己几年前的判断：AI 并没有简单抬高创作上限。生成之后的筛选、修改与品味判断，反而成为设计师更重的工作。访谈中还提到 Figma 内部的 AI 写作标注，以及一个会随注意力流失而“退化”的网页来信，用来说明设计如何管理用户的注意力与信任。

研究启示：评估 AI 设计工具时，不应只测“能不能生成”，而要测“生成后是否可编辑、可解释、可协作”，以及用户是否愿意为最终质量反复回来修改。

交互范式 / AI 产品

OpenAI 把 ChatGPT 与 Codex 合成一个体验：AI 竞争重新回到 UI

Stack Overflow 在 OpenAI Dev Day 2026 现场采访了 OpenAI 技术人员 Andrew Ambrosino，主题就是“Don't forget about the UI for AI”。访谈透露，OpenAI 正把 ChatGPT 与 Codex 合并为统一体验，并强调桌面应用本地化电脑访问能力的优势，以及支撑实时多智能体协作的 ChatGPT Spaces 所面临的技术挑战。

研究启示：值得用日记法或会话回放研究“用户在 ChatGPT 与 Codex 之间迁移”的真实路径，观察他们如何判断该用哪个入口，以及合并后是否真的减少了上下文切换成本。

用户行为 / 健康 AI

每周 3 亿人向 ChatGPT 问健康：信任成为医疗 AI 的头号体验指标

a16z 与 OpenAI 的 Karan Singhal 对谈披露，每周有超过 3 亿人用 ChatGPT 询问健康与养生问题。OpenAI 的做法是把医疗专业知识训练进通用前沿模型，并组织数百位医学专家评估安全性与分歧案例，把 AI 定位为医生的补充而非替代，同时推进 Epic 集成与临床医生 copilot。Google 的 AMIE 则选择另一个触点：在就诊前通过对话收集患者信息，把医生的时间还给协作诊疗。

再结合 Google Health 把饮食照片、运动、睡眠数据组织成持续服务、并把 AI 教练纳入 Premium 订阅，可以看出健康 AI 的竞争已经从“答得对不对”延伸到“何时介入、如何升级、怎样建立长期信任”。用户把通用助手当作健康入口，已经是既成事实，产品设计必须正面回应这一现实。

研究启示：健康类 AI 需要显式设计不确定性表达、转诊与升级路径、数据授权与家属协同。信任应作为核心体验指标持续测量，而不是合规附录里的一句话。

研究方法 / 评测效度

真正的 Agent 使用不是单轮问答：JetBrains 用 4,782 个真实会话重写评测

JetBrains Research 分析了工程师在 JetBrains IDE 中使用 Agent 的 4,782 个真实会话，并与三组公开的 Agent 对话数据集对比，发现二者存在结构性差异：SWE-Bench Pro 等基准里的任务通常是单条用户消息，几乎总是新功能或修 Bug；真实会话则是多轮、逐步补上下文、修复与验证交替的过程。

该研究以《Coding-Agent Benchmarks Should Match Their Users' Task Flows》为题，被 NeurIPS 2026 的 Evaluation of Interactive Agents workshop 接收。它提醒所有做 AI 产品评测的人：基准的任务分布如果偏离真实任务流，分数越高，可能离用户越远。

研究启示：与其争论“哪个模型更强”，不如先问“我们的评测任务，和用户实际发起的任务是不是同一类”。这是效度问题，也是用户研究可以贡献的核心价值。

界面批评 / 汽车 HMI

特斯拉 Roadster 车机争议：视觉冲击与可用性的拉扯

设计师、开发者丁一在 X 上发布特斯拉新 Roadster 的车机界面，并公开提问：“有极致美学吗？可用性好吗？”支持者称赞其复古未来主义视觉，反对者则质疑强视觉冲击是否牺牲了行车场景下的可读性与操作效率。这场讨论很快从审美偏好转向了具体的界面评价。

争论的价值不在于站队，而在于它把“美学”与“可用性”放回同一个评价框架：车机不是展厅海报，驾驶员只有极短的注视时间，对比度、层级、触控目标大小和动效节奏都直接关系安全。对于任何“高概念”界面，越炫目的视觉越需要更严格的可用性验证。

研究启示：在概念阶段就用分心驾驶模拟、扫视时间与错误率测试，而不是等量产后由用户在社交网络上做可用性评审。美学与可用性不是二选一，但后者有否决权。

设计趋势洞察

两个正在成形的交互转向：共享式 Agent，以及可回看的创作中间物。

Trend 01 · 多人协作

从“一人一聊”到“多人共创”：个人 Agent 正在变成共享界面

Replika 联合创始人 Eugenia Kuyda 的新产品 Wabi 发布 2.0，核心主张是：“个人 Agent 过去是一人一聊，但生活中真正重要的事，往往不止一个人参与。”在 Wabi 里，伴侣、好友、幼儿园家长群都可以加入同一个线程；学校改了接送时间，Wabi 更新家庭日历，所有人同步看到；两个人想看的演出，它找出双方都有空的晚上并订票；一群人反复聊起的旅行，它直接定日期、做行程、完成预订。

Wabi 早期曾让用户用一句话“搓”一个 App 再分享，团队发现定制化确实有吸引力，于是转向由 Agent 根据邮箱、日历自动生成减重追踪器、事件日历等应用。Notion 的 Akshay Kothari 则指出，Wabi 与 Notion 都是为多人协作而设计的产品。与此同时，Conway 把 AI 助理装进用户自己的电脑，灵光、Cola 2.0 等 Personal AI 也在探索“帮人而非替人”的路线。

更底层的产品假设来自 Stanford CS146S：Grok Bot 工程师 Lee Robinson 描述的 always-on Agent 有自己的云端电脑和记忆，合上笔记本也不停，更重要的是“像同事一样知道什么时候该安静”。Grok Bot 已支持把入口设为 iPhone 动作按钮，并在 0.71.2 版本强化通知策略。

对用户研究的含义 研究对象从“单个用户的旅程”变成“一个共享线程里的多方目标”。需要重新设计：共享记忆的边界、每个成员的权限、两人同时修改计划时的冲突解决、通知 etiquette，以及“默认安静、重要才出现”的主动性阈值。
来源： Peter Yang · Wabi 2.0 · Akshay Kothari · Wabi + Notion · 白鲸出海 · Wabi 产品转向 · 深思圈 · always-on Agent · Grok Bot 0.71.2
Trend 02 · 创作工具

从画布与时间轴，转向“可对话、可回看、可修改”的中间物

前剪映、Vidu 产品负责人廖谦创办的 Pexo 获得千万美元天使轮融资，它把生成与剪辑放进同一个产品，用自然语言对话完成视频创作，而不是让用户在画布工作流里自己拼。其切入点很明确：生成一段视频不难，难的是把模糊想法变成真正能用的内容——“让生成和剪辑之间不再有 gap”。

另一条路线是“Video as Code”。Anthropic 的 Claude Motion 与国内 Fotor Agent 用代码生成 MG 动画：给网页加一条时间轴，文字、数字、动画时间都以代码表达，因此生成后仍可精确修改。NotebookLM 的 Video Overview 则把工作流显式拆成“上下文收集—审阅卡片—视频生成”，让用户能在中间阶段检查与干预；WorkRally 的 AI 电影实践、Lovart 的 vibe-design 工作坊也在探索类似路径。

这些产品的共同点不是“一句话出片”，而是：自然语言输入 + 一个可见、可编辑的中间产物 + 若干检查点。Dylan Field 所说的“生成之后怎样动手修改”，正是这条趋势里最真实的设计难题。

对用户研究的含义 研究创作类 AI 时，少问“满不满意”，多问“你在哪一步开始不信任输出”“你需要看到什么才敢改”“改完之后如何确认没有破坏别的部分”。中间产物的可读性、可追溯性与局部修复能力，比生成速度更能预测留存。
来源： 硅星人Pro · Pexo · AI产品阿颖 · Video as Code · 宝玉的分享 · NotebookLM 工作流 · 腾讯技术工程 · AI 电影实践 · Lovart · Vibe-Design 工作坊

产品体验点评

两个案例，一个关于硬件等交互，一个关于市场如何建立信任。

智能家居

苹果 HomeView：硬件等交互能力，等了两年

苹果传闻已久的家庭智能屏 HomeView 终于发布：299 美元、7 英寸屏幕，放在家里通过语音与用户互动。但这个看起来并不复杂的设备，因为新版 Siri 的 AI 能力迟迟达不到要求，前后延期近两年。它只是苹果家庭机器人计划的第一步；更早的 J595 桌面机器人项目想把 iPad 式屏幕装在机械臂上，随用户位置转动，后续还探索过自主移动机器人甚至洗碗。摩根士丹利 2025 年预测，到 2040 年苹果机器人业务年收入可能达到 1330 亿美元。

从体验角度看，HomeView 的核心价值并不在 7 英寸屏幕，而在“语音交互是否足够可靠、自然、值得每天使用”。硬件先行、交互能力滞后，会让产品停留在演示视频里；苹果接下来要证明的不是自己能做出屏幕，而是消费者真的需要一个常驻家庭、随时被唤醒的界面。

点评：常驻设备的 UX 研究应重点关注误唤醒率、隐私感知、家庭多成员共用时的身份与权限，以及远场、无屏场景下的反馈设计。这些指标比屏幕参数更能预测留存。另一个关键问题是“它替谁说话”——当家庭成员共享一台设备，助手需要明确当前是谁在提问、谁能查看历史、儿童使用时如何降级。
来源： 创业邦 · 难产的苹果机器人
AI 技能市场

美团 DeepSkill Market：把“大众点评”搬进 AI 技能商店，能否解决发现与信任？

美团 AI 团队推出 DeepSkill Market，已收录超过 35 万个 Skill，覆盖 PPT 制作、竞品分析、网页开发、短视频制作、金融数据分析等。它把美团擅长的评价体系搬进 AI 技能市场，主打安全扫描、真实任务验证和技能点评，被形容为“AI 版大众点评”。腾讯此前已上线 SkillHub，并在 7 月推出 SkillPay，探索技能付费与开发者分成。

这个案例的产品体验问题很典型：一是发现成本——35 万个技能如何让普通用户找到“此刻真正需要的那一个”；二是评价闭环——用户安装后往往在别的 Agent 里使用，未必会回到商店写评价，社会证明可能天然稀疏；三是中间层风险——当模型越来越会自己找工具、写代码甚至生成 Skill，商店是否还必要。

点评：技能商店的胜负手不是 SKU 数量，而是“任务—技能”的匹配效率与可信度。可用真实任务完成率、首次成功率、回访评价率作为核心指标，而不是收录量；同时要让评价发生在使用现场，例如在 Agent 完成任务后一键反馈，而不是要求用户回到商店。
来源： 人人都是产品经理 · 美团、腾讯想再造一个 AppStore？

研究方法论

三套可以直接迁移到 AI 产品研究中的方法：真实任务流、记忆拆解、轻量工作流。

M1

真实任务流采样法：用会话日志校正评测的生态效度

JetBrains 的方法值得复用：抓取真实 IDE 会话，只保留至少三条消息的会话，再按消息位置与请求类型标注前五条用户消息，观察“新功能—修 Bug—验证—再修改”的转移概率。结果显示，公开基准与真实会话的任务结构差异显著：基准偏向单轮、明确的功能任务，真实工作则充满上下文补全与反复验证。

  1. 从日志中抽样真实会话，而不是只访谈重度用户或只看演示。
  2. 用“请求类型转移矩阵”描述任务流，识别高频回路与断点。
  3. 把基准任务分布与真实分布做对照，标注覆盖缺口。
  4. 在评测报告中同时给出“能力分数”和“任务流覆盖度”。
来源： The JetBrains Blog · 论文摘要
M2

记忆评测的“五段拆解”：不只看答对没有，要看哪一步丢了

WorldMemArena 由 UCSB、斯坦福、ETH、JHU、CMU 与 J.P. Morgan Chase 的研究者联合提出，已被 NeurIPS 2026 接收。它不满足于“最后答对没有”，而是把失败拆成：有没有写下关键事实、新信息来了有没有覆盖旧信息、检索时有没有找出来、找出来后有没有用于行动，以及多模态细节在转成文字时是否丢失。

这套思路可以直接迁移到产品研究：当用户说“它不记得我”时，先定位是采集、更新、检索、使用还是表达环节出了问题，再决定改产品还是改预期。与之呼应的 MemT 1.0 尝试把记忆内化进模型参数，让经验积累成为模型能力的一部分，说明“持续记得并主动调用”正在从外挂功能变成基础体验。

来源： 机器之心 · WorldMemArena · 机器之心 · MemT 1.0 · 爱范儿 · MemT 1.0 与长期助理
M3

轻量研究工作流：提示语管理 Skill + NotebookLM 视频叙事

两个今天就可以试的工具。其一是开源“提示语管理.skill”，作者整理了 25 个思考类提示语（苏格拉底式提问、第一性原理、对抗性审查、双向钢人论证等），并解决了一个真实痛点——问题不在存储，而在需要的那一刻想不起来自己存过什么；Skill 会在对话中帮你选出合适提示语。其二是宝玉拆解的 NotebookLM Video Overview 系统提示，完整呈现了“上下文收集—审阅卡片—视频生成”的工作流，适合把研究结论转成给利益相关者看的短片。

建议把两者组合成研究流水线：用提示语 Skill 做访谈提纲与对抗性复盘，用 NotebookLM 工作流把洞察转成可评审的叙事材料。前者提升单次对话的质量，后者降低洞察传播的边际成本。

来源： 卡尔的AI沃茨 · 提示语管理.skill · 宝玉的分享 · NotebookLM Video Overview

UX 雷达

值得持续跟踪的早期设计信号，每一条都可能长成下一个研究议题。

CSS random() 落地：设计系统开始容纳“可控的随机”

原生 CSS random() 已进入 Safari，并将在 Chrome 156 推出。Smashing Magazine 的作者用它做了有机字体、跳动字母、散开卡片和朋克杂志风格等实验。对长期追求网格、间距和对齐一致性的设计系统来说，这是一个有趣的张力：随机性何时增加温度，何时只是制造噪音？

研究机会：测量“微随机”对感知亲和力与品牌可信度的影响边界。
来源：Smashing Magazine

可穿戴设备的“基线漂移”：孕期用户的分数焦虑

freeCodeCamp 的文章指出，智能戒指与手表依赖静息心率、HRV、体温和呼吸频率建立个人基线，但孕期会同时改变多项指标。作者以 Oura 的 Readiness Score 为例：一个低分可能让用户觉得自己“做错了什么”，而在身体经历正常变化时，这种暗示会持续数周。

设计建议：自适应基线、非评判性文案、把“变化”解释为阶段而非失败。

银发反诈：从宣传页走向“陪聊式”服务设计
