OpenClaw实战：AI Agent持续运行的5条核心经验

来自社区开发者3周连续运行OpenClaw的实战经验，这些经验对于任何构建长期运行AI Agent的开发者都具有参考价值。

1. 结构化记忆系统

平面文本文件无法扩展。必须采用Projects → Areas → Resources → Archives的层级结构，叠加语义搜索才能实现"按含义检索"而非简单的文本匹配。仅用一下午就从混乱检索升级到结构化召回。

# 推荐的文件组织结构
PROJECTS/           # 当前活跃项目
  active-task.md    # 当前任务清单
AREAS/              # 责任领域
  coding/           # 开发相关
  writing/          # 写作相关
RESOURCES/          # 参考资料
  skills/           # 技能文档
  snippets/         # 代码片段
ARCHIVES/           # 归档内容

2. 成本分层策略

不是所有任务都需要最强模型。监控、调度类任务使用廉价模型，写作、研究、判断类任务才使用顶级模型。这种分层可以将成本降低到原来的几分之一，效果相同。

3. 规则工程优于提示词

"Be helpful"完全无效。必须编写具体、可验证的规则：

  • 启动任何新任务前先检查ACTIVE-TASKS.md
  • 说"完成"前必须用工具调用验证
  • Telegram里只用项目符号列表，绝不用表格

每一次失误都要转化为一条新规则，规则会随时间复合累积。

4. 主动调度而非被动等待

通过cron定时任务实现主动推送：每天7点晨报、10点和15点业务提醒、每4小时系统健康检查。Agent会主动推送，而非被动等待指令。

5. 防御性架构

不要"请求"AI不要泄露机密，而是让泄露在技术上不可能：

  • 密钥存进macOS Keychain
  • 用pre-commit hook防Git泄露
  • 用sed管道对敏感输出脱敏

从系统架构层面构建防线，而不是寄希望于模型"听话"。正如安全工程师所言："希望不是安全策略。"

Claude设计总监：AI时代的设计流程重构

Anthropic设计负责人Jenny Wen（前Figma设计总监）分享了AI如何改变产品设计流程的深刻洞察。

传统设计流程已死

"设计师们多年来奉为圭臬的那套流程——先做研究和发现，然后发散、收敛、再发散、再收敛，做出精美的模型，交给工程师实现——这套流程，基本上死了。"

为什么传统流程失效？

当工程师可以启动7个编码Agent并在设计师完成探索前就发布可用版本时，传统的设计-开发流水线就崩溃了。设计师不是在跟AI竞争品味，而是在跟不需要等待的工程师竞争速度。

新的设计工作模式

设计工作正在分裂为两种模式：

  • 执行支持模式：与工程师协作构建，提供反馈，在代码中打磨
  • 短周期愿景模式：设定3-6个月的短期愿景，而非多年路线图

给开发者的启示

当所有人都能快速构建任何东西时，需要有人为团队指明一致的方向。这就是设计师的新价值——不是产出精美的mockup，而是确保AI生成的代码朝着正确的方向前进。

📋 实践指南

1

评估AI Agent的5个技巧

构建Agent容易，知道它是否工作正常很难。Philipp Schmid分享：1)构建前定义成功标准——将轨迹分为结果、流程、风格目标；2)从真实失败案例开始——20-50个测试用例；3)先用确定性评分器——检查文件存在、命令执行、测试通过；4)用LLM评委检查风格；5)评分Agent产出的结果而非过程。

2

让长时运行Agent产出更好结果的技巧

要求Agent在代码库中添加功能标志，条件是禁用时测试必须失败、启用时必须通过。这本质上成为红/绿测试——你需要模型先产生失败的测试，然后让它通过。这是10+小时Agent运行的有效调试策略。

3

MCP vs Agent Skills：如何选择？

MCP通过标准化服务器连接Agent到外部服务，是确定性的API调用；Skills是本地执行的Markdown行为指令，由LLM解释。关键区别：MCP用于精确操作，Skills用于行为指导。两者可以互补使用。

4

AGENTS.md的实际效果

研究人员在10个仓库124个PR上测试OpenAI Codex，发现使用AGENTS.md后，中位运行时间下降28.64%，输出token减少16.58%。但收益主要来自减少少数高成本运行的开销，而非均匀加速。AGENTS.md更像防止最坏情况失控的护栏。

5

AI时代SaaS的新机会

玉伯(Frank Wang)提出：AI是智力API，SaaS是行业最佳实践的软件表达。好的SaaS应该：1)通过API、MCP、Skills等为AI提供友好服务；2)通过合适UI为人类提供友好交互。Agent要面向人提供服务，必要的SaaS界面仍是体验提升的关键。
