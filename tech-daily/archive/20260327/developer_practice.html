OpenAI Codex 官方用例库上线：从入门到生产级的完整实践指南

New

OpenAI正式发布了Codex用例库(Codex Use Cases)，这是一个汇集编程和非编程场景实用示例的中央仓库。每个用例都配有可直接在Codex应用中打开的启动提示词，让开发者能够快速上手并复现。

为什么重要：对于正在评估或已采用Codex的团队来说，这是官方首次系统性地展示了如何将AI编码助手从"玩具"转化为生产工具。用例覆盖了iOS应用开发、数据分析、报告生成等多个实际工作流。

关键细节：用例库采用"一键打开"设计，如果你已安装Codex应用，点击用例即可直接加载对应的启动提示词。这种设计大幅降低了学习成本，也展示了OpenAI在开发者体验上的思考。

来源：Geek(@geekbb) / OpenAI Developers

钉钉CLI开源：国内首个面向AI Agent的国民级应用开放实践

重磅

钉钉宣布开源其CLI工具，首批开放AI表格、日历、日志、待办、机器人、通讯录、DING消息、考勤、开放平台文档、工作台共10项核心产品能力。原生支持Claude Code、OpenClaw等主流AI Agent执行环境。

为什么重要：这是国内首个面向AI Agent开源全产品能力的国民级应用。钉钉CLI采用三项关键设计：所有输出都是结构化JSON，内置Agent Skills自动发现机制，支持dry-run预览模式。这意味着AI Agent可以直接调用钉钉能力而无需复杂的API集成。

关键细节：安装脚本会自动将每个产品的SKILL.md文件安装到~/.agents/skills/dws目录，Claude Code等工具会自动发现并使用。这种设计思路与GitHub Copilot的Skills机制类似，但覆盖的是企业协作场景。

来源：小互(@imxiaohu) / 量子位

Chrome新增竖向标签栏：开发者效率工具的又一利器

工具

Google Chrome浏览器正式支持竖向标签栏功能。用户可通过chrome://flags/#vertical-tabs启用，重启后在标签栏空白区域选择"将标签页移到侧边"即可使用。

为什么重要：对于同时打开几十个标签页的开发者来说，竖向标签栏解决了水平标签栏空间不足、难以快速定位的问题。这是Edge等浏览器早已支持的功能，Chrome的跟进意味着开发者可以在最主流的浏览器上获得一致的体验。

关键细节：该功能目前处于实验阶段，需要通过flags页面手动开启。考虑到Chrome庞大的用户基数和扩展生态，这一功能的普及将改变很多开发者的工作习惯。

Meta发布SAM 3.1：视频对象追踪性能翻倍

AI模型

Meta发布了Segment Anything Model 3.1，引入了"对象多路复用(Object Multiplexing)"技术，允许模型在单次前向传播中追踪多达16个对象。

为什么重要：此前每个对象需要独立的前向传播，而SAM 3.1可以一次性处理所有追踪对象，消除了冗余计算和内存瓶颈。这使得视频处理速度翻倍，从16fps提升到32fps(H100单卡)。

关键细节：这是一个可直接替换SAM 3的更新，无需修改现有代码。Meta开源了模型权重和代码，帮助开发者在更轻量的硬件上实现高性能应用。

来源：AI at Meta(@AIatMeta)

IBM发布LLM Agent工作流优化研究：系统化设计Agent架构

研究

IBM研究团队发布了《Workflow Optimization for LLM Agents》论文，系统性地梳理了Agent工作流的设计空间，提出了静态模板vs动态运行时图、组件优化策略、评估信号类型等分类框架。

关键细节：论文提出了"结构感知评估"概念，将图属性、执行成本、鲁棒性和结构变化纳入评估体系。对于正在设计复杂Agent系统的架构师来说，这是难得的理论指导。

🎯 主题一：CLI vs MCP——AI Agent工具集成的范式之争

近期技术社区爆发了一场关于AI Agent工具集成方式的激烈讨论：传统的Model Context Protocol (MCP)是否会被CLI取代？这场讨论的起因是越来越多开发者发现，CLI工具在AI Agent场景下表现出更好的可用性。

为什么CLI正在赢得开发者青睐

根据社区反馈和实际使用经验，CLI相比MCP有几个显著优势：

  • 安装更简单：CLI通常只需要一个命令行安装，而MCP需要配置服务器、处理认证等复杂步骤
  • 与Agent协作更好：CLI的输出格式更可控，Agent可以更容易地解析和执行
  • 稳定性更高：MCP服务器可能因各种原因断开，而CLI命令更可靠
  • 调试更直观：开发者可以直接在终端测试CLI命令，快速验证功能

💡 核心洞察：LlamaIndex创始人Jerry Liu指出"CLI (+ filesystem) is all you need"，这也是他们将LiteParse设计为CLI优先的原因——Agent可以直接将解析命令与其他文件系统操作交错执行。

MCP的价值与局限

MCP的设计初衷是标准化AI与外部工具的交互协议，这个愿景仍然有价值。但在当前阶段，MCP的实现复杂度和生态成熟度还无法与成熟的CLI工具生态相比。有开发者甚至评论MCP"像Java一样臃肿"。

实践建议

对于正在构建Agent系统的开发者，建议采取以下策略：

  1. 优先评估目标工具是否有成熟的CLI版本
  2. 为常用CLI工具编写Agent友好的包装脚本
  3. 将CLI调用封装为Agent Skills，实现可复用
  4. 关注MCP生态发展，在标准化成熟时平滑迁移
参考来源：Jerry Liu(@jerryjliu0) / Paul Couvert(@itsPaulAi)

🧠 主题二：Agent记忆系统的工程实践——从简单缓存到分层架构

随着AI Agent从单次对话走向长期运行，记忆系统的设计成为关键工程挑战。近期字节跳动的DeerFlow项目和ByteRover的记忆插件展示了这一领域的最新实践。

DeerFlow的记忆实现：JSON文件中的结构化知识

DeerFlow采用了一种轻量但有效的记忆机制：将Agent记忆存储为JSON文件，提取结构化事实并按置信度评分，在2K token预算内异步注入上下文。这种设计的优势在于：

  • 无需外部数据库依赖，单文件即可运行
  • 人类可读的JSON格式便于调试和版本控制
  • 异步注入避免阻塞主流程

ByteRover的三层记忆架构

ByteRover为OpenClaw推出的原生记忆插件采用了更复杂的分层设计：

  • Context Tree：深度结构化知识库，存储领域知识
  • Workspace Memory：核心规则、偏好、指南
  • Daily Memory：会话笔记，记录当日工作

自动化记忆循环

ByteRover实现了一个完整的记忆管理循环：

  1. 实时注入：每次模型运行前自动将相关知识注入系统prompt
  2. 即时保存：每次运行后将新决策写回记忆树
  3. 内存兜底：监控上下文窗口，在强制压缩前自动提取保存关键信息
  4. 每日复盘：早9点cron任务自动提取昨日架构决策和模式

OpenAI Codex最佳实践：8步闭环工作流

必读

OpenAI官方发布的Codex最佳实践文档提供了一套系统化的协作流程，核心思想是将Codex视为需要配置、磨合和持续改进的团队成员。

八步实践路径

  1. 明确单次任务：使用四段式提示(Goal/Context/Constraints/Done when)将模糊意图转为可执行任务
  2. 复杂任务先规划：使用Plan mode收集上下文、澄清问题、产出方案
  3. 沉淀AGENTS.md：将反复要说的内容写入项目根目录的AGENTS.md文件
  4. 配置环境参数：将环境、权限、模型偏好等放入配置文件
  5. 建立测试闭环：让测试和审查成为自动化流程
  6. 接入外部系统：通过MCP或CLI集成必要的第三方服务
  7. 提炼Skills：将高频流程沉淀为可复用的Skills
  8. 自动化稳定流程：将验证稳定的流程转为自动化执行

⚠️ 常见误区：文档特别指出，Prompt很重要但不是最重要；Codex即使在prompt不完美时也足够有用，但在大仓库、高风险任务中，清晰的上下文会显著提高可靠性。

来源：meng shao(@shao__meng) / OpenAI Docs

Skills设计哲学：少即是多

设计原则

Prompt工程专家李继刚分享了关于Skills设计的核心观点：skills不在多，在精。过多的skills会导致同一场景下多个skills争抢执行，效果反而不好。

"精"的两个维度

  • 单一skill的结构：在该问题空间中找到漂亮的解，结构清晰、边界明确
  • 多skill协同：契合自己独特的工作习惯，使用起来丝滑流畅

💡 实践建议：不要收集收藏skills，要审视每个skill对自己有没有意义，考虑是否添加进来、替换掉之前的。定期review自己的skills库，精简合并重复或低频的技能。
