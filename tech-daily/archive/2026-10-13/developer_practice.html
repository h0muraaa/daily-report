02 深度技术解读

// deep dive 01

Harness 到底值不值这个成本？——一组可复现的对照实验 & 三条一线结论

今天信息流里，“Agent Harness”成为贯穿多个来源的高频工程话题，而且恰好凑齐了实验数据、一线经验、落地踩坑三块拼图。

① 实验数据（Martin Fowler 博客 / Naresh Jain）。同一套 API 服务，分别在有/无“行为 harness”的条件下交给 coding agent 构建：前沿模型 GPT-6 Sol 无论有无 harness 都通过了全部外部评测；而成本优化模型 GPT-6 Luna 在无 harness 时 10 次只有 3 次成功，加上 harness 后 10 次全部成功。更关键的是成本：挂了 harness 的 Luna 达到与 Sol 相同的 10/10 可靠性，同时每次运行成本低 33%（$0.273 vs $0.406）。结论很实用——harness 对强模型是“花更多 token 买不到多少收益”，对弱模型却是“用小钱买到可靠性”。

# 实验结论速览
GPT-6 Sol  + 无 harness  → 10/10 通过   (基线)
GPT-6 Sol  + harness    → 10/10 通过   (贵了，收益不明显)
GPT-6 Luna + 无 harness  → 3/10 通过    (不可靠)
GPT-6 Luna + harness    → 10/10 通过   $0.273/run，比 Sol 便宜 33%

② 一线经验（Simon Willison 引 Geoffrey Huntley）。Geoffrey 指出，靠写 AGENTS.md 去“提醒”agent 使用某内部库是没用的——“它总会漂移”。他的做法是写一个 pre-commit hook：检查 git diff 中是否有绕过自家 diagnostics 模块、直接调用 observability 模块的代码；一旦命中就直接 fail 提交，并在报错里“注入提示”告诉 agent 改用 diagnostics 库。他形容效果“突然之间就是 10 分满分”。把约束放进机器可强制的检查点，而不是放进提示词——这是今日最值得抄走的一条经验。

③ 落地踩坑（百度网盘 / 金融监管）。百度网盘团队复盘了他们放弃“一键全自动生成代码”的流水线、转向 Agentic Engineering Loop（人机多轮反馈循环）的过程，核心一句是“流程能从头跑到尾，不代表跑出来的东西是对的”。金融监管场景的中软融鑫则把 Harness 用于零容错领域：通过知识底座、数据底座、受控状态机与全链路可追溯，把 agent 改造成“宁可不答、不能答错”的严格受控系统。

实践建议：(a) 先量化你的 harness 收益——对便宜模型跑 A/B，别默认 harness 对强模型也划算；(b) 优先把关键约束做成 pre-commit / CI 检查，而不是提示词约定；(c) 不要追求端到端全自动，把不确定项“挂账”、分轮验证，成本和返工往往更低。

📎 来源：Martin Fowler — Are Harnesses Worth the Cost? · @martinfowler · Simon Willison's Weblog · 百度Geek说 · AI前线 — 金融监管 Harness 实践
// deep dive 02

“把判定从提示词里拿出来”——确定性怎么重塑 LLM 评估与推理

今天有几条新闻在讲同一件事：把不确定的生成环节，替换成确定的结构化决策，从而让结果可解释、可复现、更便宜。

评估侧（DeepEval 的 JevEval）。传统 LLM-as-a-judge 让一个生成式模型在一次调用里同时干三件事——定义评估逻辑、做判断、算分数，带来两个老大难：0.71 与 0.66 的差异无法解释、同一输入两次运行结果不稳定。JevEval 把三者拆开：逻辑由人写（显式、可审查）→ 语义判断交给 Jev（返回概率分布，不生成文本）→ 分数由 DeepEval 固定公式计算（确定）。它支持三类决策：命题真假（返回 P(true)）、有序等级（返回各等级概率后取期望）、无序行为选择（每项赋 0–1 credit，并支持“不适用”）。以 Tool Faithfulness 为例，它把“是否幻觉”拆成四个带权重的显式子问题，权重写在代码里，而不是藏在提示词里。

推理侧（Constrained Decoding Models）。scaledown 的一族模型在 OpenRouter 上线，每个只做一件事：Summarize（长文/图片/PDF → 一致性摘要，用于上下文压缩）、Extract（用自然语言描述字段 → 干净 JSON + 置信度 + 来源 span）、Classify（自定义标签 → 校准概率）。发布方一句反问点破动机：“你已经把答案给 LLM 了，为什么还要它从头把答案写出来？”——大多数生产负载并不需要“生成”，只需要“结构化决策”。

检索侧（Qdrant 实测）。同一份 Qdrant collection，在后台优化期间查询延迟 780 ms，优化完成后降到 4.3 ms。团队在 176 万向量上对比了 13 种 optimizer 配置，量化了索引、恢复时间与查询性能之间的取舍——提醒我们“把索引/优化状态纳入运行时监控与部署流程”本身就是一项可观测性工作。

实践建议：优先识别你系统里的“生成其实只是在对答案做编码”的环节，用结构化/受约束模型替换；评估管线坚持“逻辑、判断、计分”三分离，把权重与阈值落到代码而非提示词；向量库把后台优化状态纳入健康检查。

📎 来源：meng shao — JevEval · OpenRouter — scaledown CDM · Qdrant 实测

一个很接地气的开源实践。作者观察到：需求本体往往一小时就做完，但 Agent 每改完一批就“再列一批优化清单”，于是半小时的活拖成一个下午——他称之为“Agent 推荐下一步做什么”的认知陷阱。解法是不到 300 字的提示语，在每个 Agent、每轮对话结尾自动生效（不依赖 skill，靠提示语 + hook 实现）：让 Agent 明确给出“可归档 / 进行中”的信号，而不是无限往下跑。原文还附了可直接抄的提示语写法。

04 实践指南

评估把 LLM 评估的“逻辑、判断、计分”三分离

落地 JevEval 的思路，即使不用它本身也能立刻改善你的评估管线：

  • 评估逻辑由人显式编写，可审查、可 diff；不要塞进提示词。
  • 语义判断用返回概率分布的受约束模型，而非生成一段解释。
  • 计分用固定公式，保证同一输入结果可复现。
  • 把幻觉等关键失败模式设为高权重问题（原文示例中“事实是否全部来自工具输出”权重为 2），权重写进代码。
📎 来源：meng shao — JevEval

CI/CD把代码约束做成 pre-commit 检查，而不是提示词

Geoffrey Huntley 的做法值得直接抄：与其在 AGENTS.md 里反复叮嘱（它会漂移），不如写一个 pre-commit hook 检查 diff 里是否出现绕过内部模块的调用；命中就 fail，并在报错信息里带上“指向正确做法”的提示。对 agent 而言，失败信息本身就是一次强反馈。同理可推广到：目录分层约束、禁止直接依赖某底层库、必须走统一的日志/诊断/配置入口。

📎 来源：Simon Willison's Weblog

Rust为什么 Rust 适合当 AI coding agent 的目标语言

Stack Overflow 播客请到 Rust 团队 Josh Triplett，谈了一个对 agent 时代特别相关的角度：Rust 严格的编译器约束，恰恰让它成为 AI coding agent 的理想目标——编译器会替 agent 抓住大量错误，反馈闭环短、确定性高。加之借用检查器在零 GC 开销下提供编译期内存安全，以及“最受开发者喜爱语言”的长期口碑所带来的一套心理安全感，都指向同一个工程结论：给 agent 选目标语言时，“编译器能挡掉多少错”是一项被低估的考量。

安全两条安全实践：密钥检测与“不要跳过权限确认”

① 密钥扫描。GitHub 用小模型替代远程 LLM 后，接受率、速度、成本三方面同时改善；对你的启发是把“窄而确定”的检测任务从大模型调用中剥离，本地小模型往往更准也更便宜。② 一个真实事故。一名开发者为让 Claude Code 连续无人值守数小时，使用了 --dangerously-skip-permissions 跳过权限确认，随后因一次命令拼接问题，整个 C 盘数据被删除，帖子浏览破百万；万幸他设置了每日自动备份到 NAS，恢复了约 98%。教训直白：跳过权限确认意味着把破坏半径交给模型的措辞，务必配合隔离环境与自动备份。

性能MoE kernel 工程：在 Amazon SageMaker AI 上优化稀疏专家推理

MoE 是稀疏激活架构，能在保持“每 token 计算量低”的前提下扩大模型容量，但其算子占了总计算时间的很大比例，因此 kernel 级优化收益最高。核心技巧是 Fused MoE——把 token 路由、数据重排、专家网络计算合并成一次 GPU 批处理，替代原本顺序执行的独立循环；代价是 kernel 实现的复杂度上升。做大模型推理性能的同学可参考其取舍分析。

基础设施Cloudflare / AWS / Vercel 三则平台更新

Cloudflare OHTTP Gateway 进入封闭 beta：一个托管端点，为源站解密 Oblivious HTTP 请求。引人注意的设计是“拒绝”——它不会解密来自 Cloudflare Workers 或经 Cloudflare 代理主机的请求，以避免把客户端标识与请求内容交到同一双手里。AWS EventBridge 重新设计了 Custom Event Bus，针对事件驱动架构跨团队/跨账号后“事件基础设施本身碎片化”的问题。Vercel 则把仓库 checkout 与 Git LFS 下载提速：>2 vCPU 构建机上项目文件就绪时间平均降 20%，LFS 项目降 54%（约省 13 秒/次部署），无需额外操作。
