1双雄同日交锋：Gemini 4 Argon 与 Muse Wonder 把前沿差距压到 2 分

Google 于 10 月 13 日发布 Gemini 4 Argon，这是 Gemini 4 系列的首个模型，主打写代码、金融、法律、网络安全与科研等「多步骤、长链条」复杂任务。定价是引入价每百万 token 输入 2 美元、输出 10 美元，缓存命中只收 5%（0.1 美元），批量/Flex 档半价；但引入价只到 11 月 30 日，12 月 1 日起翻倍到 4 美元 / 20 美元。规格上支持 100 万 token 上下文，单次响应最长可输出 100 万 token。可用性分层明显：Pro/Ultra 会员可用 Gemini App 与搜索 AI 模式；开发者走 API 付费层（AI Studio、Google Cloud、Android Studio）；Antigravity 需 Ultra。此外开放两条申请通道：科研人员可申请 6 个月免费最高用量档（1 万个名额），网络安全防御团队可加入 Fairwind 计划拿到去掉网安护栏的版本。

评测数据指向一个「能力趋同」的判断：Argon 在 Vals Index 的金融、法律、编码、税务四项均列第一，刷新 DeepSWE v1.1 纪录，位列 Text Arena 第一、Agent Arena 前五，AA-Omniscience 基准幻觉率仅 15%，而 GPT-6 Astra 高达 51%。同期（10 月 12 日）Meta 发布 Muse Wonder / Muse Wonder Full：Artificial Analysis 智能指数分别 52 与 56 分，Wonder Full 距 Claude Opus 5.5（58 分）只差 2 分，而上一代 Muse Spark 1.3 六周前还是 48 分。这批模型在 Meta 位于俄亥俄州、超 1 吉瓦的 Prometheus 集群训练，扎克伯格透露单座 1GW 集群建设成本 500–600 亿美元、年运营约 150 亿美元，而核心研发团队仅约 100 人。

2模型经济学逆转：头部 10 个模型的开发者 token 份额从 55% 跌到 14%

《The Information》的数据揭示了一个反直觉事实：十个最高质量模型承载的开发者 token 份额已从去年的 55% 跌至 14%，靠调用体量取胜的是更便宜、「够用就好」的模型。这被 Marcus on AI 形容为「AI IPO 的最后一根钉子」—— tokenmaxxing 退潮、中国开源权重模型引发价格战，前沿实验室的估值前提正在动摇。

流量侧的证据同样醒目。OpenRouter 公开数据折算，其推理请求年化收入约 15 亿美元、约占全球推理市场 1%，本周支出结构为 Anthropic 36%、OpenAI 18%、开放权重模型 26%，平台每月处理 600 万亿以上 token。区域上，上周全球总调用 172 万亿 token，其中中国模型 86.74 万亿、环比增长 50.96%，美国 18.97 万亿、增长 17.1%，中国已连续 24 周超过美国；周调用量前五名全部是中国模型（DeepSeek V4.1 Flash 41 万亿居首、智谱 GLM 5.3 Flash、小米 MiMo-V2.6-Flash、阶跃 Step 5 Preview 等）。对 CTO 的含义是：即便能力上限仍在被刷新，真正在放量的是成本效率，采购与架构的默认假设要从「选最强」切换到「分层选最合适」。

3Harness 成为新的成本杠杆：弱模型 + 好 Harness 可 10/10 且每次便宜 33%

Martin Fowler 刊出 Naresh Jain 的对照实验，结论对预算敏感的技术负责人极具价值：让编码 Agent 构建同一个 API 服务，前沿模型 GPT-6 Sol 有无行为 Harness 都能通过全部外部评测；而成本优化模型 GPT-6 Luna 在没有 Harness 时 10 次只成功 3 次，加上 Harness 后 10 次全过。更关键的是经济学 —— Harness 虽然增加了 token 用量与运行时长，但每次运行成本从 0.406 美元降到 0.273 美元，便宜约 33%，达到与前沿模型相同的可靠性。

LangChain 给 Harness 下了清晰定义：Harness 是「不是模型本身」的一切 —— 系统提示、工具/Skills/MCP 及其描述、捆绑基础设施（文件系统、沙箱、浏览器）、编排逻辑（子 Agent 生成、交接、模型路由）以及用于确定性执行的 hooks/中间件（压缩、续跑、lint 检查）。原始模型不是 Agent，是 Harness 赋予它状态、工具执行、反馈回路与可强制约束。研究侧进一步印证：在模型所运行的 Harness 内做训练可让分数翻倍以上（elvis），而做应用的团队「要先想清楚自己的产品会不会就是一个 RL 环境」（yan5xu）。当模型本身越来越像可替换供给，可复用、可评测的 Harness 就是差异化的落点。

4企业 Agent 竞争重心转移：从「能不能做」到「能不能可靠、便宜、可控地做」

SF Tech Week 传出的最重要信号是「重心转移」：去年人人都在谈 Agent，今年真正有意思的话题变成 Agent 上岗后所需的一切 —— 路由、搜索、数据、评测、可观测性、延迟、推理成本、GPU、部署与可靠性。提问方式也从「一个 Agent 能做到吗」变成「如何让一百万个 Agent 可靠、便宜、可控地做到」。这一转向在落地案例中反复出现：WPS Comate 用「四大 Hub」打包解决企业痛点（同一指标三套系统三个数、API 密钥不敢交给模型、token 花了算不清、出问题查不到谁干的）；中软融鑫在金融监管报送场景用知识底座 + 数据底座 + 受控状态机 + 全链路可追溯，把 Agent 改造成「宁可不答、不能答错」的严格受控系统；百度网盘则公开复盘，放弃「一键全自动生成代码」，转向人机多轮的 Agentic Engineering Loop，理由是「流程能跑通，不代表结果是对的」。

信任与验证正在成为独立议题。AI Engineer 大会上的三组分享指向同一结论：一位讲者自测 2026 年会话中约四成存在有后果的错误，需要三层评审（可验证产物 + 独立 Agent 交叉核对）；技术尽调要看「70% 自动化」的分母究竟是什么（产出增长是否只是换来了更多复核与返工）；而在银行内部署 AI「不是工程问题」，缺失的是谁授权数据、谁复核错判、必须满足哪些既有控制。产品侧也随之转向 —— 腾讯开源 teamai-cli，标志 AI 赋能从「搞个工具」转向「上下文与规范的建设」。

5Anthropic 自建版本控制系统：Agent 生成的代码量级倒逼研发基础设施重构

Anthropic 工程博客披露了一个值得所有 CTO 警戒的拐点：5 月每天合并约 2,500 个代码变更，9 月已超过 30,000 个，团队随后被「按人类规模、而非 Agent 规模构建」的开发基础设施卡住。他们的应对是自建一套全新版本控制系统，并在五个月内把 monorepo 从 git 完全迁移过去。这印证了工程组织的下一场竞争不在「写得多快」，而在变更量级下的质量与可靠性控制。

模型战略

能力战与成本战正面分岔：CTO 需要在「双轨世界」里做选型

今天出现了两条方向相反、却同样真实的事实线。一条是能力线还在陡峭上升：Gemini 4 Argon 把幻觉率压到 15%（对照 GPT-6 Astra 的 51%），在金融、法律、编码、税务全线登顶；Meta 用六周把 Muse Wonder 从 48 分推到 56 分，距 Opus 5.5 只差 2 分，此前被视为「掉队」的玩家重新入局。Gavin Baker 的点评点破了格局的残酷：一年前 Gemini 如日中天，没人能想象今天它甚至不在讨论范围，而 Muse 与 Meta 在能力上大幅领先 —— 前沿席位是流动的，「多模型 / 混合模型」才是终局。

另一条是成本线正在重写默认假设：头部 10 个模型的开发者 token 份额从 55% 跌至 14%，中国模型周调用量连续 24 周超过美国且环比增长 51%，OpenRouter 上开放权重模型已占 26% 支出。当「好够用」的模型在体量上碾压「最强」，为能力榜首支付溢价这件事本身就开始被重新定价。两条线合起来说明一个结构性变化：模型正从稀缺资源变成可替换、可分层的供给。这对选型哲学的影响是根本性的 —— 问题不再是「哪个模型最好」，而是「哪一类任务该配哪一档模型」。

值得注意的是，模型层的「平」并没有让价值凭空消失，而是把它推向了两端。Patrick Collison 的「AI 如粮食」比喻很贴切：粮食是经济必不可少的投入，但大多数价值并不被粮食生产者捕获 —— 同理，模型极其重要，并不意味着所有价值都会被几家前沿实验室拿走。中间层（路由、检索、数据、评测、Harness）与贴近业务的上层因此成为价值沉淀区，这恰好对应了今日要点第 2、3 条的信号。

CTO 视角：把模型采购从「单点最优」改成「分层路由」。为高价值、高验证成本的任务（法律、金融、安全、复杂架构）保留前沿模型席位；为大批量、结果可自动验证的任务（代码生成、文档抽取、分类、检索决策）切换到成本优化模型或开放权重模型。同时在架构上把模型调用抽象成可替换接口，在合同里保留切换与议价权 —— 因为能力榜首会继续流动，而你的成本结构不该随之剧烈波动。
Harness 工程

从「换模型」到「造系统」：Harness 是弱模型追平前沿的杠杆，也是企业最大的可控变量

Naresh Jain 的实验给出了一个可量化的结论：同一个成本优化模型，加不加 Harness，是 3/10 与 10/10 的区别，且加 Harness 后每次还便宜 33%。这打破了「可靠性必须靠更强模型来买」的直觉 —— 可靠性可以由模型之外的系统结构来提供：明确的系统提示、结构化的工具与 Skills、受控的执行环境、可校验的反馈回路、以及负责压缩与续跑的中间件。当这些被工程化沉淀下来，它就成了可复用资产，而不是绑定在某个模型版本上的运气。

企业侧的实践进一步说明 Harness 不是「提示词技巧」，而是把 Agent 改造成可控生产系统的工程方法：

  • 用约束换可靠。金融监管场景的解法是「知识底座 + 数据底座 + 受控状态机 + 全链路可追溯」，核心不是让模型更聪明，而是让它在零容错场景下「照章办事」，宁可拒答也不能答错。
  • 放弃全自动，拥抱可检查的循环。百度网盘把「一键生成」改成澄清需求 → 分轮验证 → 过程可观测的 Agentic Engineering Loop；正如其复盘所言，「全自动最大的风险不是它会犯错，而是它错了还在自信地往前跑」。
  • 把上下文与规范当成基础设施。WPS 的四大 Hub、腾讯 teamai-cli 在做的是同一件事：让一个团队里不同人的 Agent 共享口径、规范与可复用的经验，而不是各自为战。
  • Harness 本身可以产品化。Kylon 主张企业需要「面向人与 Agent 的公司级 Harness」，把团队已在用的多个 Agent 接入共享协作空间 —— Harness 正从代码库内的脚手架，长成一个可采购的品类。

把这些与「模型商品化」放在一起看，逻辑就闭合了：当模型可替换、成本走低，差异化的来源从「你用了哪个模型」转移到「你围绕模型建了什么系统」。专有数据、业务上下文、以及把这些组织成可评测 Haness 的工程能力，才是难以被复制、且会随时间复利的资产。

CTO 视角：设立专门的 Harness / Agent 工程能力，而不是把 Agent 当成「订阅一个模型就完事」。优先级排序：其一，为关键场景自建基于真实业务数据的私有评测，用它而非公开榜单验收；其二，把系统提示、工具编排、受控状态机与沙箱沉淀成可复用组件，先在一两个高价值流程跑通再横向复制；其三，对「全自动」保持警惕，用分轮验证与可观测性把风险前置 —— 弱模型 + 好 Harness 往往比强模型 + 裸调用更便宜也更可靠。

AI 自我复制从科幻走进红队实验，模型安全边界成为竞争变量

CTO 视角 · 行动建议

Action Items
  1. 把模型采购从「单点最优」改成「分层路由」。

    头部 10 个模型的 token 份额已从 55% 跌至 14%，能力榜首仍在流动。为高价值、高验证成本的任务保留前沿模型席位，为大批量、结果可自动验证的任务切换到成本优化或开放权重模型。所有模型调用抽象成可替换接口，避免绑定单一供应商。

  2. 把预算重心从「订阅最强模型」转向 Harness 工程能力。

    Naresh Jain 的实验证明弱模型 + 好 Harness 可 10/10 且每次便宜 33%。优先投入系统提示、工具编排、受控状态机、沙箱与可校验反馈回路，把这些沉淀成可复用组件，而不是每次都靠换更强的模型来买可靠性。

  3. 为 Agent 生成的代码量级重建研发基础设施。

    Anthropic 从每天 2,500 个变更暴增到 30,000 个后，被人类规模的开发基础设施卡住，最终自建版本控制系统。现在就该评估自己的 CI、Code Review、可观测性与回滚能力能否承受数量级增长 —— 先补质量与可靠性控制，再谈提速。

  4. 用自己的真实数据建评测，用评测而非榜单做验收。

    企业落地显示「榜单接近满分、真实任务通过率低」是常态。参考金融监管的「宁可不答、不能答错」与百度网盘反对「全自动」的取舍，为关键流程建立可自动验证的私有评测集，让上线决策基于事实而非演示。

  5. 把 Agent 的可控性与安全当作上线闸门。

    Anthropic 红队已证明 AI 自我复制不再是纯科幻，且趋势指向年底。为每个 Agent 建立独立身份与最小权限、默认沙箱化、全程留可追溯且非模型自证的记录；对同时触碰私有数据、不可信输入与外部服务的 Agent，一律先做安全评审。

  6. 重新测算 TCO，把供应商商业模式变化纳入采购评估。

    Cursor 的第三方模型改按 API 计价、Meta 选择闭源不卖 API —— 供应商的商业化姿势会直接改变你的单位成本与供应稳定性。在续约与选型时把「长期价格演变、锁定风险、能力来源合规性」与性能分同等看待。

  7. 培养 FDE 型复合人才，并让决策层靠近前沿。

    FDE 角色正在模糊工程、产品、咨询与销售的边界，成为交付复杂 AI 系统的关键能力。为关键岗位设计「贴近业务 + 靠近前沿」的实践路径，用可复现的实测结果在组织内对齐预期，避免用榜单或演示来推演战略。
