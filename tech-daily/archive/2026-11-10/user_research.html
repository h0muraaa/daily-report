当 AI 开始「换壳」：
界面正在为角色让路

从 Google Antigravity 的知识工作布局，到 Airbnb 让 Agent 学会说「我不知道」——今天的信号指向同一件事：用户体验的竞争，正从「模型能做什么」转向「如何让人信任、理解并掌控它」。

今日要点 KEY INSIGHTS

  1. Agent 产品开始「按角色换壳」，而不只是换模型

    Google Antigravity 上线了面向研究、写作与产物（artifacts）的 Knowledge Work 界面布局：底层沿用同一套 agent harness、插件与 MCP 工具，但去掉了终端与 git 的噪音，用户可在设置中自选布局。官方同时透露，Google 内部已有大量非开发者每天使用这一产品，这意味着产品团队正在把「开发者优先」的单一面孔，扩展成面向不同角色、可并排对照的多种工作界面。对研究员而言，这是一次典型的「同一引擎、不同外壳」的设计取舍。
    📎 来源: Google Antigravity · Varun Mohan

  2. 让 AI 学会说「我不知道」，是一种信任设计

    Airbnb 的 ML 工程负责人 Pedro Rodriguez 分享了他们构建「信任类」Agent 的经验：在贷款审批、理赔等高利害场景中，一个自信但错误的答案是最坏结果，因此他们给结构化输出预留了「弃权（abstain）」选项，把不确定的案例转交人工。团队还用规则层包裹小型子 Agent、用 LangGraph 的 interrupt 处理需等待数日的案件，并用不同模型族的「检查器」核验线上运行结果。这套设计的核心不是能力，而是可解释、可中止、可追溯。
    📎 来源: LangChain / Airbnb · Should Agents Say "I Don't Know"?

  3. 设计仍是应用最大的护城河：微调比写代码更难

    设计师兼开发者 Viking 分享了自己用 AI 做落地页的方法论：即使模型很强，缺乏强约束时随手生成的页面依然「字多、配色杂、一眼 AI 味」，无法直接上线。他的做法是先用 Refero 按需求搜集真实设计——从 Styles 里提取颜色、字体、间距与组件生成 design token，落成 DESIGN.md，再把截图、PRD 与设计规范一起交给强模型出多版方案再挑，最后用小范围但精致的动效收尾。他反复强调的一句话值得写进工作流：「不要让 agent 反复迭代，而是让 agent 造出可以迭代的工具。」
    📎 来源: Viking (@vikingmute)

  4. AI 生图从「抽卡」走向「可编辑工作流」

    字节跳动发布 Seedream 5.5，主打像素级精准编辑、百轮修改不崩坏、原生 RGBA 透明背景与图层拆分，并同步接入豆包与「豆包工作」。爱范儿的实测把它从「产品图」连续改成「复古磁带播放器」再改成「黑胶唱片店」商业海报，多轮编辑后仍能保留主体结构与已确认的设计元素。对设计协作而言，关键变化不是「画得更漂亮」，而是非编辑区域的像素级保持——这让 AI 生图第一次真正具备了进入既有设计流程、被反复修订的条件。
    📎 来源: 爱范儿 · 实测 Seedream 5.5

  5. 用户旅程建模正在被大模型重写

    Pinterest 把用户旅程推理系统从多阶段聚类流水线，替换为一个微调的 40 亿参数 Qwen3 模型，并报告邮件点击率提升 1.1%、推送打开率提升 1.3%。这条新闻值得用户研究员重点关注：过去依赖人工定义与聚类的「旅程」，现在可以由语言模型直接推断，从而更细粒度地驱动触达与内容策略。它也提示我们，旅程地图的产出形态可能从静态交付物，变成可持续推理、可在线学习的信号源。
    📎 来源: InfoQ

设计趋势洞察 DESIGN TRENDS

趋势一：从「万能聊天框」到「角色化外壳」

同一个 Agent，为什么需要不同的脸？

过去一年，几乎所有 AI 产品都收敛成一个聊天框。但今天的几个产品同时给出了相反的答案：Antigravity 推出「知识工作布局」，把终端与版本控制从视野里拿掉，只留下研究、写作与产物；T3 Code 的初体验被评价为「界面设计和交互都很好」，因为它会把 Claude 与 Codex 的会话线程导入，做到无缝衔接；阿里「千问办公 2.0」则把 Personal Agent 升级为能与多人协作的 Team Agent。它们共享同一套底层能力，却在入口层做了完全不同的信息架构。

这背后的设计逻辑是「渐进式披露 + 角色化信息优先级」：非开发者不需要看见 git 提交树，但需要看见资料、草稿与可交付产物；团队协作场景不需要单人口吻的对话流，而需要分工、交接与责任可见。Antigravity 官方强调的「same agent harness, different layout」，本质上是把以前藏在设置里的「专业模式」提升为产品的一等公民。

给研究员的启示：当底层能力同质化，体验差异将越来越多地来自「外壳」——用户是谁、此刻要交付什么、愿意承受多少复杂度。做 Agent 产品评测时，应把「界面是否匹配角色任务」单列为一项，而不只看模型分数。

📎 Google Antigravity · Layout side by side · T3 Code 体验 · 千问办公 Team Agent

趋势二：生成式设计从「生成」转向「导演 / 编辑」

控制力，正在取代生成力成为新的体验标尺。

今天的设计工具新闻有一个共同关键词：控制。Seedream 5.5 用像素级保真与百轮一致性，把 AI 生图拉进「AI 版 PS」的范畴；Genspark Media Studio 让用户先确认 Story Bible，再展开场景与镜头，最后剪辑分享，把创意决策权留在人手里；Runway 的 Sightline 支持生成任意地点的 360° 全景并从任意角度取景，且环境保持一致；Kling 4.0 的评测则被概括为「把更多创作过程从剪辑转移到导演」。连 World Labs 的相机控制能力登顶，也被李飞飞评价为「对很多创意与设计工作至关重要」。

这条趋势对 UX 的意义在于交互范式的迁移：从「输入提示词 → 等待结果 → 接受或重抽」，转向「设定约束 → 在画布上局部调整 → 保留已确认部分 → 继续推进」。前者是赌博式交互，后者才是设计协作。能否让用户「只改想改的地方」，正在成为生成式工具可用性的分水岭。

设计检查清单：评估一个生成式设计工具时，问四个问题——能否锁定非编辑区域？能否回退到任意一版？能否导出可复用的结构化素材（图层/透明底）？能否把决策点显式交还用户？

📎 Seedream 5.5 · Genspark Media Studio · Runway Sightline · Kling 4.0 · Fei-Fei Li on camera control

产品体验点评 PRODUCT TEARDOWN

案例一 · 高利害场景

Airbnb：把「不确定」设计成一条正常路径

大多数 AI 产品的默认假设是「必须给出答案」，而 Airbnb 的信任类 Agent 反其道而行：当模型不确定时，它可以弃权，并把案件连同上下文转交人工。这个看似保守的设计，恰恰解决了高利害场景中最大的体验风险——用户无法分辨「自信的错误」与「可靠的正确」。

支撑这一体验的是一组可复用的模式：用一层朴素规则包裹小型子 Agent，降低黑箱感；用 LangGraph 的 interrupt 让需要等待数天的案件「挂起」而非强行推进；把 MCP 作为 Agent 访问数据的唯一路径，保证来源可查；上线后用 LLM 判官、代码检查，以及一个跑在不同模型族上的检查器做交叉验证。团队最坦诚的结论是：构建 Agent 是容易的部分，判断能否信任它才是最难的。

可解释结构化输出 + 来源可查
可中止interrupt 支持长周期挂起
可追溯跨模型族交叉核验

📎 来源: LangChain / Airbnb (Pedro Rodriguez)

案例二 · 日常工具

微信 AI 录音笔：把复杂藏进两个按钮

微信输入法上线的「AI 录音笔」没有额外硬件、也不需要付费，交互被压缩成「开始录音」和「总结」两步。爱范儿的实测显示，它会在开会过程中边听边总结，会后把散落在多人发言里的信息整理成结构化模块：设备入库生成流程图、拍摄规范单独成节、责任分工与注意事项分列，另一场会议则被整理成带时间轴的工作计划。讨论《影之刃零》与《只狼》格挡机制差异时，它还会生成对照卡片与攻防消耗逻辑图。

它的体验亮点是「认知负荷卸载」——用户不必边听边记，事后也不必从长文本里二次检索。但值得警惕的是与之呼应的另一条信号：开源录屏工具 Capwise 的作者明确表示，录制后仍需要可编辑修改，「现阶段 human in the loop 还是有必要」。自动总结提升了效率，却不能替代人对关键结论的确认。好的设计应把「AI 整理」与「人来定稿」明确分层。

📎 来源: 爱范儿 · Capwise 录屏工具

研究方法论 RESEARCH METHOD

工具 · 评测框架

g-harness-evals：把「外围设计」变成可比较的变量

Garry Tan 开源的 g-harness-evals 提供了一个难得的方法论样本：固定同一个前沿模型，只更换 agent harness——也就是系统提示、工具与记忆这些外围设计——看谁更准、谁更省钱。任务不是编程题，而是一家虚构公司的多人办公场景：搭一个模拟 Slack，让 Agent 担任团队机器人，处理权限、审批，以及他人在后续对话中提出的纠正。判分不看 Agent 自述，而是检查任务结束后的系统状态与事件日志，确认答案是否正确、是否泄密、是否越权读取。

结果本身也很有信息量：各 harness 的准确率差异并不显著（约 71%–79%，20 道题中 14 道在所有组合下同分），真正拉开差距的是成本与速度——OpenClaw 在 Opus 上约 0.44 美元/题、中位耗时约 99 秒，其余多在 0.19–0.24 美元。对用户研究员而言，这提示了一种可迁移的评测思路：当模型能力趋同，体验差异往往藏在「外壳」里，而外壳是可以被严格对照实验的。

📎 来源: meng shao (@shao__meng)

方法 · 跨模态研究

「同样的话，不同的判断」：偏好标注的模态差异

一篇 arXiv 论文做了首个基于组内相关系数（ICC）的受控跨模态研究：用 100 条提示词，比较同一语义内容在文本与音频两种模态下的人类偏好标注。结论很实用——无论哪种模态，大约都需要 9 名评分者才能达到「良好」量级的评分者一致性（音频 ICC≈.81，文本≈.74）；同时，音频评分者的决策区间更窄，即人们在听的时候判断更集中、在读的时候更分散。

这对用户研究的直接价值有两点：其一，做偏好/可用性评分时，「找几个人聊聊」远不足以支撑统计结论，样本量需要按模态与一致性目标反推；其二，同一份内容用语音还是文字呈现，可能改变用户表达偏好的方式，因此访谈或问卷的模态选择本身就是研究设计的一部分，而非执行细节。

📎 来源: arXiv · Same Words, Different Judgments

流程 · 产品判断

Tulsee Doshi 的 60/20/20 与「先自己评 5–20 条」

Google 前沿模型产品负责人 Tulsee Doshi 在 Lenny 的播客中提出一个很落地的评测方法：不必一开始就搭大评测集，先挑 5–20 条你真正关心的提示词，亲自判断结果，明确「好」的标准，再逐步扩展。她强调模型开发不像传统软件按规格实现，训练中会出现预期之外的能力，因此产品负责人必须亲自使用模型，去发现哪些任务表现突出、能否形成有价值的体验——只看排行榜容易错过真正值得产品化的变化。

她还给出一个可调的投入框架：约 60% 做当前能稳定实现的能力，20% 押注近期可能补齐的能力，20% 探索已出现苗头但尚未成熟的体验；重点不是照搬比例，而是避免只围绕今天局限设计、或把全部价值押在未来模型一定进步上。另一个易被忽视的实践是：模型升级后，系统提示、工具与技能都要重新测试，过去为弥补短板加的规则可能已经多余。

📎 来源: meng shao / Lenny's Podcast

洞察 · AI 记忆设计

Anthropic 的「做梦」：让 Agent 在闲时整理经验

Anthropic 关于 Claude 记忆系统的工程长文提供了一个很好的认知隐喻：人脑的海马体实时捕捉经历，但只有部分经历会在「离线」时被巩固进新皮层；对应到 Agent，大量工作痕迹留在日志与会话记录里，可以借「睡眠时计算」在交互间隙回顾日志、修正错误、生成新笔记——这个过程被称为「做梦（dreaming）」。有意思的对比是，写了 413 份笔记的 Agent 反而输给了只写 9 份但会整理的那一个。

对设计 AI 记忆体验的启发是：记忆产品的价值不在于「存得多」，而在于「回顾与提炼的时机」。这直接对应到用户旅程中的「回顾」触点——什么时候主动提醒、什么时候静默沉淀、如何让用户看见并纠正被记住的内容，都是可以设计的交互，而不只是后端策略。

📎 来源: AINLP（Anthropic 记忆系统译文）

UX 雷达 EARLY SIGNALS

● 语音交互时机

Emma：不等你说完就开始「回应」

基于 Nuplex 全双工视听模型的 Emma 会在用户仍在说话时做出反应，并用视觉线索提示「轮到她说了」。这种把「轮次」从隐性规则变成显性 cues 的设计，可能重新定义语音助手等待—回应的节奏感。

📎 来源: elvis (@omarsar0)

● 人格化界面

AI 面试官开始有「性格」了

一段 TikTok 视频显示 AI 面试官被赋予了明显的人格特征，引发大量传播。当 Agent 进入招聘、客服等高风险人际场景，人格设定会直接影响用户的信任与配合度，值得单独做可用性测试。

📎 来源: Justine Moore

● 动效 / 手势

/gestures：把手势的「物理感」做成技能

Emil Kowalski 发布的 /gestures 技能，教 Agent 为应用构建更自然的拖拽与手势：底部 sheet 滑动关闭带惯性、松手回弹、速度支持等。它把「丝滑感」这种难言说的设计直觉，沉淀成了可复用的规则集。

📎 来源: Viking (@vikingmute)

● 设计系统

200+ 美学风格 → Design Tokens

一个开源项目把 Y2K、Frutiger Aero、Risograph 等 200 多种美学，转化为主题、CSS 变量与组件样式化指导。它提示「风格」正在被结构化、可编程化，设计系统与品牌的边界可能因此松动。

📎 来源: Geek (@geekbb)

● 无障碍 / 包容性

给 Agent 加一个「无障碍技能」，反而更快更省

无障碍工程师 Jemima Abu 指出，96% 的头部网站仍存在无障碍问题，而 AI Agent 会复制它所学代码里的无障碍缺陷。她在实验中给 Agent 加入无障碍技能后，同样的构建反而更快、更便宜——无障碍不是成本，而是约束带来的清晰度。

📎 来源: AI Engineer / Jemima Abu (CAIS)

● 用户信任 / 隐私感知

「空房间」测试：把记忆变成可看见的恐惧

网友让 ChatGPT 用「它知道的关于你的信息」填满一间毛坯房，结果连一年前随口问过的一只虫子都被还原出来。当抽象的数据收集变成一张高清的房间图，用户对记忆功能的感受从「便利」转为「被窥探」——这是隐私沟通设计的重要一课。

📎 来源: 新智元

● 交互范式迁移

「我早就不用传统输入法了」

一位用户记录了自己从搜狗转向语音输入的过程，以及同事从抗拒（「社恐」）到主动改变的转折。习惯改变的门槛往往不是技术，而是场景中的社会心理成本；产品若想推动范式迁移，需要降低「被别人听见」的尴尬。

📎 来源: AI产品阿颖

● 桌面端性能体验

Discord 弃用 Electron：省 70% 内存、秒开

Discord 正把客户端迁移到 Rust，桌面端移除 Electron、移动端放弃 React Native，新客户端内存约 290MB，而旧版多服务器场景常达 1GB 以上。这提醒做客户端体验的人：当 AI 功能不断叠加，性能与启动速度仍是体验的地基。

📎 来源: InfoQ

反面信号 · 值得警惕

「AI 做游戏」的繁荣，暴露了「可玩性」的缺席

面对又一波「24 小时复刻某游戏」的演示热潮，Viking 提出了尖锐的质疑：这些作品大多只是一个小 demo、一个场景打几个怪，制作者往往平时并不怎么玩游戏，只是做一个看似炫酷的壳当作流量噱头。他提醒，画面永远只是一小步，真正决定产品的是「怎样让人不停玩下去」——杀戮尖塔、星露谷物语、Factorio 这些看似简单的游戏，靠的是设计而非包装。

这一批评对用户研究的价值在于：当生成成本骤降，「做出来」不再是难点，「为什么用户会持续使用」重新成为核心问题。评估 AI 生成的产品时，应把「留存动机」与「可玩/可用深度」置于「首次演示的惊艳度」之上。

📎 来源: Viking (@vikingmute)
