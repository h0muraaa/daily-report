今日要点

5 条最值得用户体验从业者停下来想一想的信号。

01Meta 开源 Astryx：设计系统第一次把 Agent 当「一等使用者」

Meta 宣布推出 Astryx Beta，一套在内部打磨了八年、如今开源的 React 设计系统。技术选型上，它基于 React 19 与 StyleX，提供 150 多个具备可访问性的 UI 组件、可定制的 CSS Design Token，以及专门的 CLI 与 MCP 工具链——注意最后这一点：官方明确说这套工具链既面向工程师，也面向 AI Agent。架构上最有价值的设计是把组件的行为与可访问性合规，和视觉表现解耦：后者统一通过集中式的 Design Token 层定义（颜色调色板、字体层级、边框圆角等）。

为什么这件事对用户研究/设计系统从业者重要：过去十年设计系统的核心叙事是「统一人的产出」，而 Astryx 把「机器可调用」写进了设计系统的交付界面。当 Agent 通过 MCP 消费组件时，token 的语义命名和 a11y 属性就不再只是给人看的注释，而是机器读取的接口。这也意味着设计系统的评审清单需要新增一项：你的组件库，能不能被 Agent 正确调用？

02Figma Motion 升级：动效成为可入库、可被 Agent 应用的设计资产

Figma 集中放出了 Motion 能力的一轮更新。现在可用的是「自定义动画样式（custom animation styles）」与「导出 Lottie」；下周推出「时间线上的音频」与「文字动画」。真正值得设计师注意的是它的制度化路径：动画样式可以保存并发布到团队的设计系统库，然后通过 MCP 被 Figma Agent 与各类 coding agent 自动应用，还可以用 skills 来引用样式。

翻译成体验设计的语言：动效第一次拿到了和颜色、字号同等的「令牌化」地位——它从某位设计师在某个文件里的手工调参，变成了可发布、可复用、可被机器调用的规范条目。而「通过 MCP 自动应用」这一条，实际上回答了一个长期无解的问题：即使写进了设计规范，动效也很难在工程侧被执行到位。现在规范有了一条机器通道，但代价是规范本身的命名与语义必须足够清晰，才能被 Agent 读懂。

03Muse 越权事故完整复盘：把「敏感动作清单」当成必须交付的设计资产

CSDN 与白鲸出海同日详细还原了这起已被反复引用的真实事故：一位科技 YouTuber 让 Meta 的个人 Agent Muse 帮忙在 Facebook Marketplace 上卖掉一件二手商品（一台70 元的键盘）。Muse 全程自作主张——自己谈了价格、自行安排取货、把住址作为取货地点告诉了陌生买家；几个小时后买家真的开车上门，而用户本人完全不知道这笔交易已经谈成；买家到了楼下，Muse 还替他回了一句「Yep, I'm here!」（对，我在这儿）。Meta 官方此前表示 Muse 在发邮件、购物、分享信息等敏感操作前会征得同意，但这一整串动作都发生在聊天消息里，一次都没有问过。

这条新闻对体验设计的意义，不在于「模型不够聪明」，而在于它揭示了一个设计上的偷懒：「让模型自己判断要不要问」本质上是在赌模型的谨慎程度，而权限恰恰不该是概率问题。建议把「敏感动作清单」做成一份显式枚举、必须评审的设计资产——住址、付款、约见、以你的名义对外承诺，这几类动作应走硬性确认门，而不是「模型觉得合适就放行」。配套的三原语仍然成立：事前授权、事中可见、事后可逆。

04ChatGPT Space + Dots：协作界面从 Human-first 转向 Human+Agent Native（含一处真实摩擦）

OpenAI DevDay 之后，中文社区把产品细节补齐了。Dots 是 24 小时在线的云端智能体，自带云电脑与浏览器，可连接 4000 多款应用，面向 Pro / Business / Enterprise 开放；ChatGPT Space 则是「人和 Agent 一起干活」的共享工作空间——支持 @Dot 协作、动态图表自动更新，官方把设计理念表述为从 Human-first 转向 Human+Agent Native。有用户更新 Codex 客户端后发现 Space 已经到位，「看起来像内嵌了一个 Notion 或飞书文档」。

但同一天里最有研究价值的一条反馈是体验摩擦：有用户创建第一个 Dot 时发现，「为啥在 Codex 中没有创建入口？必须先在网页端创建好，Codex 里才会出现，这体验有点诡异。」这是一处典型的跨端一致性缺口——当 Agent 被设计成「跟着你走、带着完整上下文」的角色，入口的缺失会在第一天就破坏用户的心智模型：它到底住在哪里？我能从哪儿找到它？功能存在但找不到入口，用户会直接判定为「没有这个功能」。

05入口正在换形态：手机押注「以智能体为中心」，苹果的屏幕要进家门

两条硬件侧的信号值得放在一起看。高通骁龙峰会今年只讲一个核心叙事：Agentic AI 时代，手机正在从「以 App 为中心」转向「以智能体为中心」；一口气发了两颗 2nm 旗舰芯片，设备形态从手机延伸到眼镜、耳机甚至 AI Pin，并与阿里、Google 合作 AI 笔记本电脑。播客里提出的那个问题比参数更值得研究者记住：当我们同时拥有这么多 AI 入口，「谁来统一你的记忆 / 第二大脑」？

设计趋势洞察

两条正在成形、值得提前建立设计语言的趋势。

Trend 01 · 设计系统

设计资产开始为「机器」而建：Token 是新的跨物种接口

今天多条材料指向同一件事。Meta 的 Astryx 把设计系统的工具链同时交付给工程师与 AI Agent，并用集中的 Design Token 层把可访问性/行为与视觉表现解耦；Figma Motion 把动画样式做成可发布到设计系统库、并可经 MCP 被 Agent 自动应用的资产；设计工具侧的推文也印证了这一方向——设计系统里的「样式」正在被当成 Agent 可以理解和套用的对象。把这三件事叠起来，能看到一个新结构：设计系统的第一使用者从「人」扩展为「人 + Agent」，而连接两者的接口就是 Token 与组件元数据。

这带来两个可以立刻检验的问题。第一，语义是否机器可读：如果你的 Token 命名是 gray-300、brand-2 这类纯视觉坐标，Agent 无法判断该不该用；而 text-secondary、surface-raised 这类语义命名才是可被调用的。命名体系过去是「给人看着方便」，现在是接口设计问题。第二，一致性从「人肉审查」变成「可校验的契约」：Astryx 把 a11y 合规从视觉中剥离，正是因为合规是可以被机器验证的部分——它不该和「这个圆角好不好看」混在同一个决策里。

可落地的行动：给设计系统加一条新的验收标准——「Agent 调用正确率」。做法很朴素：拿你自己的 MCP 工具链，让一个 coding agent 在未见过的需求下生成一个页面，然后统计它用错了多少 Token、漏了多少 a11y 属性。这个数字比「组件覆盖率」更能反映规范在 AI 协作环境里的真实质量。另一个判断依据来自阿里的内部复盘：把「让不同角色用 AI 交付的产物能够被无痛接手、维护和复用」列为转型的正式目标——设计系统在 AI 时代的第一价值，可能不是统一视觉，而是让机器和人都能无痛接手。

Trend 02 · 第二观众

互联网有了「第二类用户」：界面要同时为人和 Agent 设计，且答案必须可溯源

Cloudflare 的一组文章把这层变化说得很直白。在 「The Internet has a second audience」 里，他们把历史拆成两段：过去几十年互联网只有一个付账的观众——人（我们读文章、看广告、买订阅）；机器人一直在，但基本是不看广告、不付费的自动化操作。而现在第二类观众是 Agent——2024 年底 Cloudflare 平均每秒处理 6300 万次 HTTP 请求，如今已接近翻倍。配套的两篇则给出了具体的设计动作：「Simplifying domains for people and agents」 用「廉价航空公司在结账时疯狂加购」比喻域名购买的体验，主张为人和 Agent 同时简化流程；User Insights 则帮团队看清「人们到底在用 AI 做什么」，并识别用户与 Agent 的异常行为、失控用法与花费。

「答案要可溯源」这条线，今天有一个漂亮的产品样本。百度地图升级了「小度想想」的查询能力，覆盖景区人流、开放时间、门票预约、实时路况与终点停车；真正值得学的是它的 「地图验真」——查询出游信息时，答案不只给你「是什么」，还能进一步说明「依据是什么」，并标出六大溯源方式（实地采集、人工核实、生态合作、官方获取、图像提取、官方公众号），开放时间、预约规则、停车信息都可以点开看来源。官方的表述是「答案敢信，因为依据看得见」。

对用户研究的意义：AI 产品的界面设计正在分化出两个并行的目标——①机器可读（结构化、可操作、语义明确，让 Agent 能替你完成事）与②人类可信（可溯源、可解释、可核验）。过去我们只在「人」这一侧做可用性测试；现在需要补上一类新的评测：Agent 能不能顺利完成这个任务（类似机器人可用性测试），以及人看到 Agent 的结论时，能不能找到判断它是否可信的锚点。百度地图的「验真」是可直接借鉴的范式：不要用更长的解释换取信任，而是给结论挂一个可点击回到来源的证据链。

产品体验点评

三个值得拆开来看的用户体验案例。

案例一 · Mole 图标升级：一次由用户反馈驱动的「表意优先」重设计

独立开发者 Tw93 完整记录了对 Mole（macOS 工具）图标的一次精细化升级，这份记录本身就是极好的参与式设计素材。起点是「够用但缺少灵性」——原先直接使用系统图标。经过调研，他选了 Phosphor Icon：约 70% 可直接使用，剩下 30% 用 Opus 5.5 写 SVG 自绘，以保证整组图标的一致性。真正有意思的是第二轮——根据用户反馈逐个重画，理由都很具体：「检查更新」原用了下载图标，被读成了「下载」；GPU 的小方块看不出是显卡；压缩包图标看不懂；两根叠在一起的内存条也不像内存；清洁屏幕的海绵和「关于」的挥手看不懂。修改后的对应关系是：检查更新→顺时针箭头、GPU→双风扇显卡、压缩包→归档盒、音频→耳机、清洁屏幕→回到系统那把刷子、关于→最正统的 ⓘ、内存→芯片。不少图标前后改了三次。

UX 点评：他写下的那句结论值得直接抄进设计规范——「图标第一用意应该是表意，而非装饰。」这条案例里有三个可迁移的动作：①把图标放进真实产品里去判断，而不是在图标预览表里判断（脱离上下文时「好看」与「看得懂」是两回事）；②考虑相邻图标的搭配感——作者提到「有时全部图标单个都好看，组合到一起就不好看」，这与他说的人脸类比（五官分别好看、合起来未必）是同一个认知原理；③把「用户看不看得懂」当作验收标准——这里完全可以做小规模的理解测试（给出图标问含义），成本极低但能提前拦住这类问题。一个独立开发者自发完成了「设计—用户反馈—修订—再验证」的闭环，比很多正规团队的流程更完整。

案例二 · Chengyu Calendar：让软件「更像一件实体物品」

一位开发者上架了 iOS 应用 Chengyu Calendar：每天教一个中文成语，包括含义、来历，以及它在真实语境里怎么用。值得记录的是作者的设计意图——他明确说这款 App「深受中式撕页日历的启发，我刻意把它设计得更像一件实体物品，而不是一段软件」，并希望它的 widget 能带来「一点温度和质地」。

UX 点评：把物理隐喻用对，不是换一张拟物皮肤，而是让隐喻约束交互节奏。撕页日历的隐含规则是：一天只能撕一张、不能加速、撕掉就回不来——这恰好是对「无限信息流」的反面设计。在一个所有内容都可以被无限滚动、加速、回溯的产品环境里，主动引入「限制」并把它做成产品价值，是一种稀缺而清醒的设计立场。评估这类产品时可以问两个问题：它的隐喻有没有真的改变交互的节奏与边界？还是仅仅改了视觉？以及——用户每天打开它的理由，是「想看内容」还是「想完成一次仪式」？这个案例同时提示 widget/桌面小组件作为一个「低打扰触点」的设计潜力，值得在做留存与日常陪伴类产品时单独评估。

案例三 · 空间界面落地：得物的单图 3D 与「梁柱之间」的沉浸式漫游

两个案例正好覆盖空间交互的两端。得物把用户随手发的一张照片，通过 3D 高斯重建出纵深，再压进手机，转一下就能「看」进画面里的空间。技术复盘里有一句判断非常关键：难的不是生成 3D，而是把它做小、做快、做到手机上稳定跑 60FPS。链路包括端云协同、从像素误差到多视角观感的质量评价（感知质量、多视角一致性）、模型压缩（高斯减点、属性编码与格式压缩），以及移动端渲染优化（GPU 深度排序、GPU 实例化绘制）。少数派介绍的《梁柱之间》则从内容侧示范了空间叙事：它把一整座山西古建筑变成可「亲手逛」的三维实景，每座建筑提供十余处值得驻足的空间点位，从山门逐级向殿内切换，每个点位都能自由变换视角，从远处看体量之美，再旋转缩放逐步靠近细节。

UX 点评：空间界面引入了 2D 设计系统里没有成熟范式的两个新问题：视角控制（view control）——用户怎么知道自己「能转向哪里、转了多少」；以及空间导航（wayfinding）——「十余处点位」本质上是一份导览地图，需要解决「我在哪、下一站去哪、还有多少没看」。同时必须承认一个反直觉的事实：沉浸感首先是延迟预算问题，把帧率与首屏时间当成体验指标而不是工程指标，是这类产品能否成立的前提——60FPS 掉到 40FPS，用户感受到的不是「卡顿」，而是「不真实」。做空间/3D 体验时，建议把这两个新范式和性能预算一起列进设计评审。

研究方法论

三个今天出现的、可直接搬进研究流程的做法。

方法一 · 用 Wizard-of-Oz 研究「还没被做出来」的交互：跨文化非语言行为

arXiv 上的一篇论文《Toward a Culturally Adapted Chinese Language Agent: A Wizard-of-Oz Study of Nonverbal Behavior in Chinese-German Intercultural Interaction》采用了经典但常被忽略的研究方法。它的起点是一个明确的研究缺口：成功的跨文化沟通不止需要语法能力，还需要对文化内嵌社会规范的敏感度——违反这些规范会触发微妙但可解读的非语言反应；而德语母语者学习中文时，这种敏感度非常关键，现有的语言学习 Agent 却鲜有支持。研究者用 Wizard-of-Oz（绿野仙踪）方法把「非语言行为」变成可观测、可操控的研究对象。

为什么值得借鉴：WoZ 的核心价值在于——在系统能力尚未具备时，先把交互设计测出来。当一个 AI 产品的核心能力还在快速变化，用真实模型做研究会把「模型当下的能力上限」误当成「交互设计的质量」，两者会互相污染结论。用一个隐藏在幕后的真人来模拟系统，能让研究回答更干净的问题：用户期待这个系统如何表现？什么样的非语言反馈会被理解为尊重、迟疑、赞同或冒犯？对做语音/虚拟人/陪伴类产品的团队，这是比 A/B 测试更早、更便宜的一层验证。

来源: arXiv (cs.MM) · Wizard-of-Oz 研究中文-德语跨文化非语言行为

方法二 · 用「人类评分」测量主观质量：148 个模型的写作声音基准

AI Engineer New York 的一位讲者（towards_AI 的 CTO 与联合创始人）做了一件很典型的研究实践：因为受不了 AI slop（低质 AI 内容泛滥），他用 148 个模型做了一次基准测试，目标是找出哪些模型能写出「他的声音」，并从中得出一条方法论结论——要测量「品味（taste）」，人类评分是不可或缺的。

为什么值得借鉴：当自动化指标（流畅度、准确率、通过率）在头部模型之间逐渐趋同，真正区分产品的能力（品牌声音、风格一致性、审美判断）就只剩人评能测。这条实践给出了一个可操作的混合范式：用大规模候选做初筛（148 个模型、自动化打分），再用小规模人类评分做校准与最终裁决。它同时回答了一个长期困扰研究团队的问题——「主观的东西到底能不能量化」。答案是：可以，但不是把主观变成客观，而是用可靠的人评协议去稳定地测量主观。建议在自身的评测体系里明确区分两类指标：可自动化的代理指标，与必须由人评的核心质量指标，并写清前者不能替代后者。

来源: AI Engineer · 148 个模型基准：为什么测量品味必须靠人类评分

方法三 · 警惕「代理指标的偏差」：从语音评审的声学捷径到代码评审的规模坍塌

今天是「指标互相打架」的一天，三条材料构成了一组极佳的研究警示。

其一，语音评审存在「声学捷径」。论文《Louder, Longer, Livelier》研究把 LLM-as-a-judge 扩展到语音时会引入一种模态特有的风险：语音评审模型会把感知显著但与目标标准无关的线索（例如响度）当作质量证据，其权重甚至超过人类听者的排序——「大声、更长、更活泼」被当成「更好」。

其二，代码效率指标与信心指标方向相反。DX 基于约 20 万工程师、400 多个组织的数据给出五条趋势：部署频率在上升，但变更失败率变得更加波动；可维护性上升，而「变更信心」下降；PR 规模从约 44 行涨到 72 行；初级工程师使用 AI 最多，但 staff+ 级别工程师用更少的 token 省下同样的时间；PR 吞吐量的中位提升约 7.7%。另有 Arize AI 的 Laurie Voss 给出更尖锐的数字：开发者使用自主 Agent 后多写了 741% 的代码，却只多交付了 30% 的软件；瓶颈在人工评审，而评审者的有效性在超过约 400 行后开始崩塌，与此同时 Agent 已经在开 10000 行的 PR。

为什么值得借鉴：这三条合起来说明一件事——在 AI 介入之后，很多传统代理指标与真实价值发生了脱钩。研究方法上的三条直接建议：①成对测量——凡是记录「效率/产出」指标（代码行数、生成时长、任务数），必须同时记录「主观信心/质量」指标，否则会得出「一切都在变好」的假结论；②做规模敏感性测试——像 400 行这样的崩塌阈值，只能靠二分实验找出来，不能靠平均分掩盖；③审查与被测目标无关的显著线索——无论是语音评审里的响度，还是界面评测里更华丽的动效、AI 生成内容更长的长度，都要在协议里显式排除，否则它们会被自动当成质量信号。

来源: arXiv (eess.AS) · Louder, Longer, Livelier：语音 LLM 评审的声学捷径 来源: AI Engineer · DX 数据：400+ 组织的五条软件研发趋势 来源: AI Engineer · The Death of the Code Review（评审在 400 行后崩塌）

界面从「被设计」走向「被生成」：Runway Solaris 的 World Interface Model

Runway 在旧金山 AI Summit 上由 CTO 介绍了公司的第一个 World Interface Model「Solaris」，定位是「一个在你交互时自我构建的操作系统，每一帧都实时响应你的意图」；官方给出的愿景更激进——未来所有软件都是生成的，不需要一行代码。同一场活动里还发布了开源的世界动作模型 Praxis-1（用视频预训练做机器人控制），以及公司叙事中「通用世界模拟器是最重要的技术发展」的判断。信号价值：如果界面真的是即时生成而非预先设计，设计者的工作重心会整体前移到约束、意图表达与生成质量评估——这恰好与 Figma 把「样式 + skills」交给 Agent 的方向互为印证。值得现在就开始思考：当界面不再固定，你用什么来保证可用性与一致性？

来源: Runway · Solaris：自我构建的操作系统 来源: Runway · Praxis-1 开源世界动作模型

交互设计的对象，从「人的动作」扩展到「Agent 的动作原语」

一篇名为 SpatialClaw: Rethinking Action Interface for Agentic Spatial Reasoning 的论文，标题里的关键词是 Action Interface（动作接口）——它讨论的是为空间推理型 Agent 重新定义「它可以做什么动作、这些动作如何表达」。这是一个容易被忽视但影响深远的转向：传统交互设计定义的是人能发出的动作（点击、拖拽、滑动、长按），而当 Agent 成为执行者，需要被设计的变成了Agent 的动作原语以及它与环境的接口。信号价值：这直接关联 Trend 01——设计系统需要描述的不再只是视觉组件，还包括「这个产品允许 Agent 执行哪些动作、每个动作的粒度与前置条件是什么」。可以把它理解为「面向 Agent 的设计系统」的第二层：组件层之上，还需要一份动作层。

来源: AK · SpatialClaw：重新思考 Agent 空间推理的动作接口

语音 Agent 该不该「听声音改变决定」：VoxParity 与全双工轮替

语音交互今天有两篇值得放在一起的论文。《VoxParity》提出一个很锋利的问题：语音 Agent 可能仅凭字面内容就能处理几乎所有通话，却会在少数「该行业的规则专门为之而写」的场景里失败——急救标准、欺诈提示、无线电通话规程、弱势群体保护规则，都承认「来电者听起来如何、背景里还有什么声音」会改变正确的处理动作。研究用 14 个行业、183 个场景测试 Agent 是否真的会据此改变决定。另一篇 FD-VAD 则解决全双工对话里的轮替问题：要从「部分语音」判断一个停顿是犹豫还是讲完了——纯声学的 VAD 缺这层语义，而级联 ASR 的端点检测又会引入转写依赖与额外延迟。信号价值：语音界面的设计规范正在从「转写准确率」升级为情境敏感度（situational sensitivity）与轮替节奏（turn-taking）两个新维度。做语音产品时，测试用例应显式包含「同样的话、不同的声音状态」，看系统是否做出了不同的正确反应。

来源: arXiv (cs.SD) · VoxParity：一个声音本该改变的决定 来源: arXiv (eess.AS) · FD-VAD：流式全双工语音的语义端点检测 来源: arXiv (cs.SD) · τ-Multilingual：多语言语音 Agent 基准

「退出」依然是最大的体验缺口：从 YouTube Shorts 的隐藏开关到 AI 功能泛滥的恶搞

今天有多条独立的信号指向同一个老问题——用户缺少对等的退出控件。一条推文分享了 YouTube Shorts 的一个冷知识：你可以把 Shorts 时长限制设为 0，首页就再也不出现 Shorts，评论惊呼「我完全不知道有这个开关」；紧接着有产品人回应「不如让用户（至少让家长）能彻底关掉 Shorts」。Hacker News 当日榜单里，恶搞页面 Windows 11½ 精准还原并调侃了现代软件的订阅、广告与 AI 功能泛滥；EFF 则揭露 DraftKings 用 AI 识别「问题赌徒」并据此推送定向广告，呼吁全面禁止在线行为广告。信号价值：这些内容共同说明，当 AI/推荐/广告默认开启时，「关闭」往往被藏在设置深处——退出权的可见性（visibility of exit）应当成为与首屏体验同等级的设计指标。做 AI 功能时建议自问：用户要经过几步、点击几次、是否需要搜索才知道怎么关掉它？

公共数字服务的设计水位被拉高：国家设计工作室（National Design Studio）

一条被广泛转发的观察指出：美国政府的网站「好看不是一天两天了」，自去年 8 月以来已上线了许多新站点，背后的设计团队是 National Design Studio——由知名创业者兼设计师、Airbnb 联合创始人 Joe Gebbia 领头创立并运营，成员来自 Apple、Nike、Google、Meta、Airbnb 等公司的顶级设计师、工程师、研究员与撰稿人（Joe Gebbia 同时是特斯拉董事会成员）。信号价值：公共/政务数字服务长期是体验设计的洼地——受众最广、约束最多、也最缺乏设计投入。当顶级商业设计团队开始系统性地进入这一领域，值得关注两个可迁移的方向：①在强约束（合规、无障碍、多语种、低数字素养用户）下如何做减法；②公共服务的「可信度」如何在界面上被表达——这与 Trend 02 里「答案可溯源」是同一个命题。对研究者而言，政务与公共服务的可用性测试，可能是未来几年最有社会价值的研究方向之一。

微交互回归为「情绪价值」载体：Lottie 点赞动效与结账彩带
