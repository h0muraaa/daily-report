智能体可靠性技能—策略协同进化arXiv 2610.20845

高分可能是“技能库过拟合”：CODA 揭示协同进化陷阱，技能变动后增益回吐 52%–93%[1][2]

让 Agent 从任务经验中生成可复用“技能”、再用技能训练策略模型，是当前提升智能体能力的主流路线；随着多轮协同进化，任务分数通常持续上升。阿里巴巴 Token Foundry 团队指出，这些高分往往只对“模型 + 共同训练的技能库”这一特定组合成立：在审计的 6 组设置中，技能内容变化后最差成功率比原始搭配低约 5–13 个百分点，抵消了原技能库相对无技能基线所带来增益的 52%–93%。团队把这一现象命名为“协同进化陷阱”，并提出面向技能变化的可靠性评测协议 CODA，要求同时报告原始搭配分数与分布变化后的最差表现。该工作对技能库、工具集或提示模板会持续更新的部署场景具有直接方法学意义：只报告固定搭配上的均值，可能系统性高估智能体的真实可靠性。

关键数据：6 组设置 · 最差成功率低 5–13pp · 原增益回吐 52%–93% 来源：阿里技术（原文）

上海人工智能实验室发布通专融合智能体书生-A1.5（Sage-A1.5），相较 1.0 版本强化了智能体编排、自主验证与复杂任务解决能力。它以前导模型 Agents-A1 的长程任务能力为底座，依托书生·端砚科学发现平台，在神经科学、电化学等真实科研场景中验证 RSI 飞轮：智能体在检索资料、提出假设、编写代码、验证结果的长流程中沉淀领域知识并修正推理偏差，使通用基础能力与专业科学能力同步迭代。团队将这条路径概括为周伯文提出的“环境即数据”理念——训练信号来自真实科研进程，而非人工构造的静态题库。模型与论文已在 ModelScope 开放，但“自我改进”的增益幅度、跨领域迁移与错误累积仍需完整论文与独立复现来检验。

Recursive Flint：Eureka Machine 参与架构搜索与内核优化，40B MoE 开放权重[5]

Recursive 发布面向本地编码智能体的开源模型 Flint：总参数约 398 亿，采用 256 个路由专家、每 token 激活其中 6 个另加 1 个共享专家，实际激活约 25 亿参数，SWE-bench Pro v2 得分 89.7%，权重以 Apache 2.0 在 Hugging Face 开放。更值得研究者关注的是研发方式：从架构搜索、量化方案到 GPU 内核优化，Recursive 的 Eureka Machine 系统参与了几乎所有环节，模型在不到四个月内从零完成训练。官方展示在 48GB 内存的 Apple M4 Pro 上达到 131.22 token/s。严格说这只是“AI 参与造 AI”的早期案例，但它把可讨论的问题具体化了——自动搜索与自动优化在多大比例上替代了人工设计，以及这些选择能否被审计和复现，仍需技术报告给出细节。

语音识别说话人分离arXiv 2610.28711

Qwen-Audio-3.1-ASR：30 种语言、16 种汉语方言，支持说话人分离转写[6]

Qwen-Audio-3.1-ASR 技术报告介绍了一个音频—语言模型家族，在 3.0-ASR 基础上提升语音识别，并扩展到说话人分离转写与通用音频理解。其分离转写输出包含说话人标签、时间戳与识别文本，要求跨轮次保持说话人标签一致，并能表示重叠语音；指令控制能力包括历史上下文条件、层级热词定制与原生转写润色。模型保留 30 种语言与 16 种汉语方言支持。对语音研究者而言，这份报告的价值在于把“转写 + 说话人归属 + 重叠语音”统一进一个生成式接口，而不是级联独立模块；但摘要未给出 WER、DER 等定量结果，跨语言与重叠场景的实际表现需以论文正文为准。

生产力研究软件工程Harvard · Jellyfish

哈佛—Jellyfish 研究 718 家企业：AI 代码量上升，完成工作量未同步增长[7]

一项基于 Jellyfish 分析平台、覆盖 718 家企业的哈佛研究给出了与“AI 提效”叙事不完全一致的证据：AI 编码助手与 Agent 提高了代码产出量，但并未带来完成工作量的同比例增长。作者把原因部分归结为下游瓶颈——AI 生成的代码增加了后续阶段的负担，尤其是代码评审。这项研究的学术价值在于把度量单位从“生成代码行数/提交数”转向端到端交付，并提示任何 AI 生产力结论都必须说明统计口径与工作流阶段。其局限也明显：企业样本来自单一分析平台，因果识别与任务异质性需要更多细节；但它足以构成对“代码量即生产力”假设的反例。

KunSet：首个昆曲表演语料库，48.2 万条音节级标注与押韵检索基准[8]

昆曲是最古老的在世中国戏曲形式之一，但数字化与标注长期稀缺。KunSet 构建了首个昆曲表演语料库，共 482,164 条细粒度标注，覆盖 155.2 小时媒体、其中 106.3 小时完成标注；标注同时包含音节级歌词对齐与音韵属性（如押韵），以支持唱腔分析与发音研究。为保证质量，团队先用迭代式机器学习辅助流程预标注，再由 200 多名受训标注员校正，并配套歌词对齐与押韵检索基准。对低资源语音与音乐研究，这类“专家在环”的语料构建流程本身值得借鉴；但摘要未披露标注一致性指标与基线系统表现，复现时应优先检查这两项。

机制可解释性语音合成arXiv 2610.29345

可解码不等于可控制：VoxCPM2 中 0.970 探针精度对应 0/60 的因果干预成功率[9]

论文在连续潜空间 TTS 模型 VoxCPM2 上检验“线性可解码性是否等于因果可控性”。作者在 30 个说话人、60 个有向说话人对上做位置匹配探针与等范数干预：最终残差声学语言模型层（RALM L7）的参考音频状态探针准确率达 0.970，但对齐编辑在 60 个有向对中取得目标主导的成功数为 0；相反，在 L0 做配对对齐更新可将目标相似度提高 0.326，并在全部 60 个有向对中实现目标主导，而任何等范数方向或位置控制最多只有 1/60。这个反直觉结果说明，表征中“含有信息”与“可被因果利用”是两件事。对可解释性研究的方法论含义是：探针准确率不能单独作为控制能力的证据，必须配合干预实验与对照方向。

关键数据：30 说话人 / 60 有向对 · L7 探针 0.970 但干预 0/60 · L0 全部 60/60 来源：arXiv cs.SD / eess.AS（论文）

工具增强推理音频语言模型arXiv 2610.29060

推导深度暴露推理失败：工具给出错误结论时，五个音频语言模型仍接近 100% 跟随[10]

论文研究“在音频与模型之间插入 MIR 工具”的流水线是否真的让模型进行推导。作者固定音乐信息、只改变推导深度——即从工具输出到答案之间的推理步数——发现：当工具报告直接写出结论时，五个模型的得分接近 100%，即使结论是错的也照单全收；把答案推远一步，准确率立刻下降；在转调任务上，开源模型降到 57%–81%，尽管单独直接提问时它们能答对那一步。该结果把“工具增强”的失败定位在证据整合而非感知本身：模型倾向于复述工具报告，而不是基于中间量做多步推导。对基准设计者，这意味着评测必须同时报告推导深度、工具正确率与被误导后的行为，否则高分会掩盖脆弱的推理链。

关键数据：5 个模型 · 结论直给时近 100%（含错误）· 转调任务 57%–81% 来源：arXiv cs.SD（论文）

PAPER 01 · REASONING EFFICIENCY · DATA-EFFICIENT SFT · NEURIPS 2026

Hint Tuning：用 1000 条数据教会推理模型“看题下菜”[11][12]

方法论文 · arXiv:2605.08665 · NeurIPS 2026 · 小红书 REDtech · 代码、数据、模型均已开源

研究背景

以 o1、DeepSeek-R1 为代表的推理模型依靠长思维链在数学、代码等任务上取得明显提升，但它们对几乎所有问题采用同样的深度思考方式。作者比较同家族 Instruct 与 Thinking 模型在竞赛数学题上的输出：在两者都答对的题目上，Thinking 模型的输出长度是 Instruct 的 5–8 倍，多出来的内容大量是“wait”“let me verify”之类的重复检查。这提示推理模型存在可被削减的“过度思考”，关键是如何在不损失准确率的前提下按题目难度分配思考预算。

核心创新

作者先把 Thinking 模型自己的思维链切成片段，把开头几段作为 hint 交给同家族 Instruct 模型，发现很多题只靠这几段提示、甚至不给提示就能答对。顺着这个观察，他们构造了 1000 条数据，对推理模型做一次监督微调（SFT），训练目标不是模仿完整长链，而是学会“简单题直接答、难题再深想”。方法因此同时具备两个特点：用推理模型自身的思维链作为监督信号，以及用极小数据量诱发难度自适应的思考长度。

实验结果

在数学基准上，Hint Tuning 使推理 token 平均减少 31.5%，准确率基本持平。作者强调这是“平均”口径，意味着不同难度题目的节省幅度并不相同，简单题的压缩空间更大。论文被 NeurIPS 2026 接收，代码与训练框架 Relax、数据集 hint-tuning-1k 与模型均已公开[13]，便于复现和做对照实验。需要注意，摘要没有给出逐基准的置信区间或困难题尾部的准确率变化，阅读时应核对正文的细粒度表格。

学术意义

这项工作把“推理效率”从系统层的 KV 压缩、投机解码，推进到训练层的思考预算分配：模型可以在推理时决定想多久，而不是对所有输入一视同仁。它与 adaptive computation、length-controlled reasoning 等方向形成呼应，并给出一个强烈的数据效率信号——1000 条精心构造的样本即可改变模型的思考行为，挑战了“能力提升必须依赖更大数据”的默认假设。对资源有限的研究组，这降低了研究推理策略的门槛。

局限与追问

方法依赖同家族 Instruct 模型生成 hint，跨模型家族是否有效尚未验证；实验集中在数学基准，代码、科学推理与 Agent 长流程上的迁移性未知；平均 31.5% 的节省可能掩盖困难题上的准确率损失，需要报告分难度曲线与最差情况；hint 由模型自身思维链构造，存在评测集泄漏与污染风险；此外，“学会少想”是否会削弱模型在分布外问题上的探索能力，也值得长期跟踪。复现时应固定数据构造流程、hint 截断策略与解码参数。

PAPER 02 · LONG-CONTEXT INFERENCE · MEMORY ARCHITECTURE

EdgeRock-4B：把 KV 缓存钉在 72 MiB，长推理吞吐提升 6.42 倍[14]

模型报告 · 岩芯矩阵（岩山科技）+ 香港科技大学 + 卡内基梅隆大学 · 基于 Qwen3.5-4B 转换 · 已开源

研究背景

Coding Agent 等长程任务需要反复读代码、调工具、改程序，再根据测试结果继续，历史越长 KV 缓存越大。现有方案多是在“压缩”上做文章：4-bit KV、token 淘汰或摘要都只能让缓存增长得慢一些，无法改变其随推理增长的本质；Mamba、RWKV 等固定内存模型虽然内存恒定，却容易丢失解题所需的关键细节。问题因此变成：能否让缓存根本不增长，同时让模型学会保留真正重要的信息。

核心创新

团队提出记忆岩锚（Rock Memory Anchors，RMA）：像攀岩者在关键位置钉下岩锚一样，把推理途中的关键信息固定下来，而其余状态不再无限累积。EdgeRock-4B 由 Qwen3.5-4B 转换而来，每条序列的注意力 KV 固定为 72 MiB，与上下文长度和推理步数无关。与传统压缩的区别在于，模型在训练中学习“哪些细节值得记住”，而不是在推理后被动剪枝；这使得固定内存成为可学习的记忆策略，而非硬性丢弃。

实验结果

按团队公布的测试，在 256K 上下文下，EdgeRock-4B 每条序列的注意力 KV 比来源模型少 99.1%；在同一张 GPU 上的长推理吞吐达到来源模型的 6.42 倍；AIME 2024–2026 平均一次通过率为 82.9%，与内存随推理增长的领先小模型处于同一水平。三个数字分别对应内存、吞吐与能力，团队的核心主张是它们可以同时成立。需要说明，这些指标来自模型发布方的自测，尚未看到第三方在统一 harness 下的复现。

学术意义

EdgeRock 把长上下文研究的一个关键变量从“能装多长”改成“每步要记多少”：如果固定内存不牺牲数学推理能力，那么长程 Agent 的并发服务成本、单卡可同时服务的请求数以及上下文长度的上限都会被重新定义。方法也可被视为对“记忆是学习问题”这一假设的直接检验——模型是否能学会选择性地保留证据。对系统与算法交叉方向的研究者，它提供了可复现的对照对象：固定内存策略与压缩策略在检索、长文档问答与多轮工具调用上的差异。

局限与追问

目前只验证了 4B 规模，无法判断该方法在更大模型上是否同样成立；AIME 是数学基准，不能代表长文档检索、代码库理解与多轮对话等真正吃上下文的任务；72 MiB 的固定预算在“大海捞针”类任务上可能成为硬瓶颈；吞吐 6.42 倍依赖具体硬件、批大小与实现，需报告测量协议；此外，RMA 的选择机制、锚点数量与训练目标尚未在公开摘要中展开。后续研究应重点考察固定内存下的召回率与错误传播，而不只是平均准确率。

§ 4

趋势观察

Trends & Outlook

  1. 推理效率的战场从“压缩缓存”转向“重写记忆与思考预算”

    EdgeRock-4B 不再试图让 KV 缓存增长得慢一点，而是让它根本不增长，并用可学习的记忆岩锚决定保留什么[14]；Hint Tuning 则把同样的思路用在思考长度上，用 1000 条样本让模型按难度分配推理 token[11][12]；RubatoCodec 在语音侧提出 utterance-level 事件预算，解决变帧率编码导致生成长度漂移的问题[23]。三者共同点是：不再被动压缩既有序列，而是在训练阶段学习“哪些信息/步骤值得保留”，把资源分配变成模型能力的一部分。下一步的关键问题是统一评测——固定内存或固定 token 预算下，困难样本的尾部表现是否仍然可靠。

  2. 递归自我改进进入真实闭环，但“自我改进”的度量仍未建立

    书生-A1.5 把神经科学、电化学的真实科研流程作为训练信号，验证“环境即数据”的 RSI 飞轮[3][4]；Recursive Flint 由 Eureka Machine 参与架构搜索、量化与内核优化，把 AI 辅助研发压缩到不到四个月[5]；美团 AutoResearch 用 CyclicGraph Engine 与状态机管理长周期实验，在两个结构不同的业务建模项目中把单任务耗时分别降低约 85% 与 83%，其中一个方案已推全上线[21]；WorkSwarm 则尝试让 Agent 从任务反馈中提炼可保留的改进[22]。这些报告说明 RSI 已从玩具实验走向生产流程，但多数证据来自工程博客与厂商自述：改进是否可归因于“自我改进”而非更强的基座、更多算力或人工调参，仍缺少对照实验。一个可操作的度量应同时报告：无改进基线、改进机制的消融、跨任务迁移与长期错误累积。

  3. 评测开始覆盖“分布变化”与“因果可控性”

    CODA 把技能库变化后的最差成功率纳入协议，发现原搭配上的高分可能抵消 52%–93% 的增益[1][2]；哈佛—Jellyfish 的研究把生产力从“代码量”拉回“完成工作量”，指出评审等下游环节才是瓶颈[7]；“可解码不等于可控制”用 0.970 的探针精度与 0/60 的干预成功率说明，表征分析必须配合因果实验[9]；推导深度实验则显示，模型会盲从工具给出的错误结论，距离一步准确率就明显下降[10]；Harbor 用 microVM 隔离每个评测任务，减少环境共享带来的分数污染[19]。五条工作指向同一方法学转向：单一均值不再足够，论文至少应报告分布切片、变化条件下的最差表现与干预对照。

  4. 开放科学基础设施扩展，署名与溯源问题同步浮现

    KunSet 把 155.2 小时昆曲表演转成可计算语料[8]，AT-DIFFER 为音频—文本差异描述提供受控数据[15]，SAGE 用 105M 参数探索语义音频潜空间[16]，Spark-X2.6-4B 与 Flint 以 Apache 2.0 开放权重[17][18][5]，OlmoEarth v1.3 则把嵌入模型扩展到全球地表观测[20]。开放 artifact 的丰富程度在提升，但陶哲轩与邓煜在讨论开放数学模型时提醒了另一面：当 AI 生成的证明无法说明借鉴了哪些前人工作，学术引用与功劳归属的链条会被切断[24]。对数据集与模型发布者，这意味着许可证、数据来源与训练配方需要与 artifact 一起发布；对使用者，可复现性不仅取决于权重是否开放，还取决于这些元信息是否足以追溯。
