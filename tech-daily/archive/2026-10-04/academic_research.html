1.研究动态

验证 · AgentVeriHarness：把 rollout 的“分歧”当作可用的验证信号

Google 的一项新工作观察到，业界常用“采样多个 agent rollout、信任其中一致的答案”来做选择，但一致性可能共同掩盖错误，而分歧往往指向正确备选。VeriHarness 把同一个基础模型改造为一个 agentic verifier，承担两项任务：对 rollout 之间不一致的断言，回到 workspace 证据中做裁决；对全部 rollout 都“一致同意”的断言，主动发起挑战、搜寻所有 rollout 共同遗漏的需求。作者称其在五个长时程（long-horizon）基准上取得所比较基线中的最佳选择分数，并在“evidence-backed revision（带证据修订）”设置下，相对单次 rollout 分别提升 6.2 分（Gemini 3.5 Flash）与 6.4 分（Claude Opus 4.8）。团队同时开放约 26,000 条 rollout，为验证器与选择策略研究提供了可复现的语料。该工作把“模型是否可靠”的问题，部分转化为“如何用证据校验一组候选”的问题，验证器与选择/评审（selection & critique）方向值得关注。

📎 来源：elvis（@omarsar0，X）
Harness · 演进ScholarEvolve：用已发表研究而非自身失败日志来进化 harness

Microsoft 及合作者的新工作提出，agent harness 的改进可以由已发表的 agent 研究驱动，而非仅依赖于 agent 自身的失败日志。ScholarEvolve 把 harness 拆成工具使用、记忆管理、任务执行等模块，对近期论文做主题建模（topic modeling），为每个模块提取不同的改进策略，再实现并测试这些策略的组合；新论文可随时间持续加入。关键结果：模型权重保持不变的条件下，Qwen3.5-27B 在 AppWorld Challenge 上的目标完成率由 49.6% 升至 63.6%，GPT-5.4-mini 在 Tau2-Bench Telecom 上由 72.7% 升至 81.9%。这一范式（“读文献—改 harness—提分”）为“把文献知识编译进系统”提供了可量化的证据。

📎 来源：elvis（@omarsar0，X） · arXiv:2609.40169
Harness · 学习CMU：用 RL 训练 Proposer 改写 harness 代码，而非更新模型权重

CMU 的一项工作把“改进 agent”的对象从权重切换到harness 代码。作者用强化学习训练一个 proposer 模型：给定任务、当前 harness 与执行报告，输出一段对 harness 的代码编辑，奖励即修订后 harness 的得分；solver 模型全程不变。结果显示，一个训练过的 4B proposer 在单步修订任务上超过了它的 35B 教师模型（Reasoning Gym），其中包括训练中从未见过的任务族；在 HotpotQA 上训练的 proposer 能把 harness 改进泛化到 MuSiQue 与 2WikiMultihopQA。这为“harness 工程”提供了可训练、可泛化的形式化路径，也印证了本期另一条观察——把能力留在权重里还是留在外部系统，正在成为一个可实验的设计问题。

📎 来源：elvis（@omarsar0，X） · arXiv:2609.35738
评测 · Agent南洋理工《Finding the Right Fit》：harness 好坏取决于模型—任务组合

新加坡南洋理工大学安波教授团队发布系统研究报告，把模型与 harness 视为整体来比较，而非给出单一排行榜。实验覆盖 OpenHands、DSH、PI、openJiuwen 四套可配置 harness，并以 Codex–GPT 与 Claude Code–Claude 两组原生搭配为参照。报告的核心结论是：harness 的好坏不是固定属性，而取决于它与模型、任务之间的具体组合；一套在某类任务上突出的 harness，换到另一类未必最优，也未必不如厂商原生搭配。作者据此主张围绕真实任务对“模型 × harness”做联合评估，而非寻找“放之四海而皆准”的通用 harness。报告同时开放了代码仓与数据集，便于复现与扩展。该工作为快速膨胀的 agent 评测提供了一个可操作的实验设计模板。

📎 来源：机器之心 · arXiv:2610.00917 · GitHub · HuggingFace Dataset
开源模型 · 决策StartLux-Decision：开源决策模型在 Decision Index 上反超 Jev

成立不足五个月的上海公司 StartLux（原点星辉）发布完全开源的决策模型 StartLux-Decision。在 Decision Index 0.2.1 的 38 项基准中，它在 31 项超过热门模型 Jev，综合得分 63.88 对 57.91，领先公开榜首近 6 分；在国际象棋实战中，其 36 局赢下 Jev 35 局，响应速度不相上下。这已是该公司第二次引发关注：此前的 StartLux-27B 在中国信通院测试中超过 284B 的 DeepSeek-V4-Flash，并以约 1/60 的参数量基本打平 DeepSeek-V4-Pro。决策模型只回答带预设选项的问题（单选、打分、是非），直接返回带概率的结构化结果——其背后的定位是卡尼曼意义上的“系统一（快速直觉）”能力。基准与实战双重反超，使该方向的可复现性与第三方复测变得尤为重要。

📎 来源：极客公园 · 创业邦
开放权重 · 安全评测GLM-5.3 逼近 Claude Mythos：ExploitBench 上的开放—闭源差距

据 DeepLearning.AI 援引 Anthropic 数据，开放权重模型 GLM-5.3 在 ExploitBench 漏洞利用任务上解出 12%，而 Claude Mythos 为 14%，两者差距已很小；同时，用约 20.40 美元的 token 成本即发现了一个近期 Google Chrome 安全漏洞。Andrew Ng 在周报中给出与“能力落入坏人之手”担忧不同的判断：这是一个工程问题，防御方拥有长期优势。该组数据为“开放权重是否提升攻击面”的争论提供了可检验的基准证据，也提示安全能力的评测需要区分发现（discovery）、利用（exploit）与修复（defense）三类目标。

📎 来源：DeepLearning.AI（X）
安全 · 基准OpenAPPA：在两项企业安全基准上把注入攻击成功率压到 0%

Archestra 开源安全引擎 OpenAPPA，目标是阻断由 prompt injection 或模型幻觉导致的数据外泄。团队报告：在 Bench-Corp（20 个多步企业工作流）与 AgentThreatBench 两项安全基准上，成功攻击数为 0，同期对照为 Claude Code 自动模式约 10%、Microsoft FIDES 约 31%。该结果将“提示注入防御”从零散技巧推进到可基准化比较的阶段；不过，安全基准的构造与对抗强度决定了结论的可迁移性，研究者宜关注其攻击模型假设与自适应性攻击（adaptive attack）下的鲁棒性。

📎 来源：InfoQ（Bruno Couriol）
多智能体 · 怀疑论Noam Brown：一万个 Agent 解出世界级难题，多智能体贡献不足 10%

OpenAI 研究员、o1 及后续推理模型早期奠基者之一 Noam Brown 在与 Dwarkesh Patel 的对谈中，对“多智能体协同”的能力叙事提出降温：在“一万个 agent 协同解题”的案例里，多智能体所带来的贡献不到 10%；真正支撑突破的是一个足够强大的通用模型以及让它持续运行、并行思考的能力。他并强调，目前尚无充分实验数据能准确刻画万级规模下的协调效率——agent 数量增加并不意味着能力成倍增长，能否有效交流、共享上下文、减少重复劳动、形成分工，才是关键变量。此番论述与同期 OpenAI 将多 Agent 推向产品线（Dots、Agents API）形成耐人寻味的对照，提示研究者应把“协调开销—规模收益”作为可测量的研究对象。

2.深度论文解读

VeriHarness：以“证据校验”重估 agent rollout 的选择问题（Google）
来源：elvis（@omarsar0，X）· 相关链接见参考文献 [1]

研究背景

随着长时程 agent 任务增多，“从多次采样中选一个最可信答案”成为默认做法（self-consistency 及其变体）。其隐含假设是：多数 rollout 一致的答案更可靠。但若多个 rollout 犯下同一种系统性错误，一致性会沦为“共同的错误共识”；反之，rollout 之间的分歧，可能恰好标记出正确答案所在的位置。VeriHarness 的出发点正是对这一假设的反转。

核心创新

VeriHarness 用一个基础模型同时扮演两类验证角色：（1）裁决者——当 rollout 彼此不一致时，回到 workspace 证据中检验各方断言；（2）挑战者——当所有 rollout 一致时，主动寻找它们共同遗漏的需求或证据。二者合起来，把“原始生成”与“证据审查”解耦，使选择不再单纯依赖投票频率。

实验结果

在五个长时程基准上，VeriHarness 取得所比较基线中的最佳选择分数。在带证据修订的设置下，相对单次 rollout 提升 6.2 分（Gemini 3.5 Flash）与 6.4 分（Claude Opus 4.8）。配套发布的约 26,000 条 rollout使这一选择/验证范式可被第三方复现与再比较。

学术意义

该工作把“agent 可靠性”问题部分重构为“候选集的选择与证据校验”问题，与同期 harness/verifier 方向（见 4.1）相互印证。可继续追问的开放问题包括：验证器自身的错误率与校准、证据检索的完备性、以及“一致即正确”假设在不同任务分布下的失效边界。

Finding the Right Fit：模型—Harness 交互的系统评测（南洋理工大学 安波团队）
来源：机器之心 · arXiv:2610.00917 · github.com/liyix/finding-the-right-fit · huggingface.co/datasets/yixuanli97/finding-the-right-fit

研究背景

同一个模型接入不同 harness（工具调用、上下文管理、错误恢复方式不同）时，最终表现可能差异巨大；而厂商提供的原生 harness 也未必对自家模型总是最优。面对“该选哪套 harness”这一工程界高频困惑，现有工作多停留在单点排行榜，缺少对“模型 × harness × 任务”三者交互的系统刻画。

核心创新

报告不给出单一排名，而是把模型与 harness 作为整体来比较。实验覆盖四套可配置 harness（OpenHands、DSH、PI、openJiuwen），并以两组原生搭配（Codex–GPT、Claude Code–Claude）为参照，在真实任务上做联合评估。

实验结果

核心结论是：harness 的好坏不是固定属性，而取决于它与模型、任务之间的具体组合。一套在某类任务上表现突出的 harness，换到另一类任务未必仍是最佳选择；因此“放之四海而皆准”的通用 harness 很可能并不存在，联合评估比单维排名更有决策价值。

学术意义

该工作为快速膨胀的 agent 评测提供了一个可复现的实验设计模板（代码与数据集均已开放），也把“harness 设计”从经验技艺推进为可系统研究的变量。它与 ScholarEvolve（用文献驱动 harness 演进）、CMU 的 harness 学习共同表明：harness 正在成为与模型权重并列的一等研究对象。

4.趋势观察

4.1 Harness 正成为可学习、可进化的一等研究对象

本期最密集的线索。VeriHarness 把验证器写进 agent 循环；ScholarEvolve 用已发表文献驱动 harness 修改；CMU 用 RL 训练 proposer 改写 harness 代码（4B 超 35B 教师，并跨任务族泛化）；NTU 则从评测角度证明“harness 好坏是模型—任务组合的属性”。四者合起来给出一个清晰信号：在权重之外，harness 是可被系统研究、训练与迁移的对象。值得追踪的问题包括：harness 改进的收益是否随 base model 变强而被“吸收”（即哪些留在模型内、哪些留在外部），以及 harness 演进的奖励是否会诱发过拟合到特定基准。

4.2 “决策模型（System One）”作为独立类别与对齐层

TypeSafe 的 Jev 点燃了这一品类，本期 StartLux-Decision 以开源姿态在 Decision Index 上反超，OpenRouter 联合创始人 Alex Atallah 则提出一个更有研究意味的应用：把决策模型当作 agent 的“对齐层”——用廉价、快速、有界输出的模型去审查每一次工具调用或 agent-to-agent 通信是否符合系统提示与未告知的额外准则。若成立，则“校准（calibration）、误拒/误放代价、对抗鲁棒性”将成为这一品类的核心评测维度，而不仅是准确率。

4.3 评测效度与基准可信度：从模型能力到“指标的指标”

三组独立信号指向同一议题：(a) GLM-5.3 与 Claude Mythos 在 ExploitBench 上 12% vs 14% 的近身差距，说明开放—闭源在安全能力上已高度接近，但基准本身的有效性决定了结论强度；(b) OpenAPPA 在两项安全基准上报告 0% 攻击成功率，其价值高度依赖攻击模型假设与是否经受自适应攻击检验；(c) Qwen 团队林俊旸公开批评 HuggingFace daily papers 出现“高票但无实质讨论、甚至买票”的现象，类比 GitHub stars 的失效。三条线索共同提示：在 agent 与安全这类快速迭代方向，如何验证评测本身可信、可复现、不易被优化，正成为独立的研究议程。

4.4 蒸馏、开源与前沿的“经济学”之争
