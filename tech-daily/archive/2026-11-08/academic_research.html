1.研究动态

Anthropic 完整披露智能体记忆：四层结构 + 离线"做梦"，35 万文件上答题 13% → 48%

Anthropic 工程团队在 11 月 6 日的技术博客中给出了跨会话智能体记忆的一套完整工程方案，并把"整理"本身命名为 dreaming：会话结束后，模型回到原始对话记录，纠正记错的笔记、去重、补链，并把零散笔记提升为可检索的结构（如互链 wiki）。他们把记忆分为四层——原始会话记录、模型自写的记忆笔记、结构化组织、以及每次新会话自动预载的少量上下文——dreaming 负责自下而上核对与提炼。关键实证来自两组对照：在查数据库答题任务中，Sonnet 4.6 的记忆增益有限（0.330→0.364），而 Opus 5 从 0.564 升至 0.828；在《宝可梦红》里，Sonnet 3.7 写了 413 个记忆文件只拿到 1 枚徽章，Fable 5 只写 10 个文件却拿到 4 枚——"会挑"比"记得多"更重要。规模实验用约 35 万个文件、4.2 亿 token、25 道题，令 Opus 5 多轮 dreaming 构建互链 wiki；dreaming 轮次从 2 加到 128 后，仅靠 wiki 答题的得分从 13% 升至 48%，wiki 与检索并用则从 54% 升至 61%，每题约节省 2 万 token。作者也给出反例：一条记错的笔记比不记更糟，会把模型稳定地引向错误路线。[3][4][5]

Anthropic 分析 20.7 万次科研会话：分析数据占三分之一，科学家最看重的"提想法"用得最少

Anthropic 11 月 4 日发布的研究报告统计了 2026-08-02 至 2026-09-30 间约 20.7 万次科研相关会话（12.9 万来自聊天与 Cowork，7.8 万来自 Claude Code），并用模型给每段会话打学科与任务标签（研究内容本身不保存）。把"科研时间分布"与"AI 使用分布"对齐后可以看到明显错位：分析数据占科研时间约 28%，在 Claude 上占 33.7%、Claude Code 上占 48.1%；写作与沟通只占 16%，在 Claude 上却占 32%，单项最多的是起草论文；收集数据占 28.6%，在 Claude 上仅约 12%；提出想法与假设占 7.1%，在 Claude 上只有 4.2%、Claude Code 上 2.1%。528 位科学家的打分则显示，他们认为最重要的恰是提想法（35.6 分）与收集数据（23.6 分）——即 AI 当前最少介入的环节。报告估计，若现有能力普及，部分领域科研产出最多翻倍；若 AI 能包揽所有不需动手的工作，计算机与统计可快约 15 倍，而化学、生物仅 3–4 倍，受限于实验室执行。

GPT-6.1 Sol 参与真实小鼠脑手术：三轮定位把误差从 0.6 mm 压到 0.3 mm

Exin Therapeutics 联合创始人 Gabriel Ocana-Santero 公开了一组真实小鼠脑部手术的定位实验：让 GPT-6.1 Sol 连续参与三轮，每轮结束后由专业外科医生纠正其定位，模型保存图像、测量数据与专家修正，供下一轮参考。到第三轮，寻找解剖标志的时间从 169 秒降到 86 秒，所需纠正从 4 次降到 2 次，定位误差从 0.6 mm 降到 0.3 mm。作者把这一过程称为基于真实世界经验的上下文学习（in-context learning），并明确回应质疑：这是真实手术而非模拟。需要强调边界——样本只有 3 次操作，远不足以证明稳定的手术能力；但它是"把真实操作观察与专家反馈带入下一轮"这一闭环的一个可核查案例，也提示医疗场景的关键变量往往不在模型规模，而在反馈能否被结构化地保留。

Hugging Face 发布《MoE 训练终极手册》：80 万 GPU 小时实验，公开被放弃的选项

Hugging Face 发布免费的《MoE 训练终极手册》（作者 Nouamane Tazi、Leandro von Werra、Thomas Wolf），团队自述投入约 80 万 GPU 小时做实验，再连同代码、55 幅交互图与踩过的坑一并公开。其动机很直接：Artificial Analysis 开放模型榜前 20 名中已有 18 个采用 MoE，但"如何把 MoE 训好"仍集中在少数团队，公开技术报告多只讲最终选择，很少解释为何放弃备选。手册从检查集群、准备数据、用 Megatron-LM 跑通约 1.22B 稠密基线讲起，再沿用同一份数据与启动脚本改成总参数约 6.86B、激活约 1.22B 的 MoE（64 专家、每 token 选 8 个），并围绕专家数量、单专家规模与负载均衡给出实验依据。对复现研究而言，把"被放弃的选项"一并记录的形式，比单一结果更有方法论价值。

EmbeddingGemma 2：把文本、代码、图像、视频、音频塞进同一 768 维空间

Google 以 Apache 2.0 发布 EmbeddingGemma 2，基于 Gemma 4 构建，关键特性是在统一的 768 维嵌入空间中表示文本、代码、图像、视频与音频，使检索系统不必为每种模态维护互不兼容的向量空间。模型针对设备端部署优化，可按需只加载所需编码器，参数规模从文本/代码的 2.7 亿扩展到完整多模态的 7.4 亿，并支持套娃表示学习（MRL）以截断维度、降低存储。Google 称其在代码搜索与技术内容检索上显著超越 EmbeddingGemma 1，适合本地代码库索引与智能体代码搜索。对做多模态检索与 RAG 的研究者，这是一个可在消费级硬件上复现的统一嵌入基线，其"统一空间"假设也值得与分模态嵌入做更严格的对照。

Arete-27B：在 Qwen3.8-27B 上做价值后训练，宣传率 22% → 0.9%，且不牺牲代码能力

Nous Research 在阿里 Qwen3.8-27B 基础上做后训练，开源了 Arete-27B（ἀρετή，卓越/美德），目标是强化西方价值观并剥离底座权重中携带的"国家对齐"行为。其评测设计是这次最值得关注的部分：他们开源了 803 道题的 Propaganda_Eval，覆盖言论自由、监控与隐私等 7 类，并用 Grok 4.7 做盲评，分别测"事实分"（以官方说辞否定任一核心事实即 0 分）与"宣传分"（把官方口径当既定事实背书才算，裁判须摘录原话为证）。训练未用强化学习，仅以约 5,280 万 token（2 万条 prompt、约 5 万样本，全走代码级 PR 审核）做普通微调，就把该评测中的宣传率从 22% 压到 0.9%，且作者称代码与 Agent 能力未下降。选教师模型时还发现 Nemotron 3 Ultra 在涉华话题上被开源数据交叉污染，最终改用表现更干净的 Inkling。对价值对齐与评测方法，这是一份把"评测标准—裁判—训练成本"全部摊开的样本。

2.深度论文解读

DoubleAI · 机制干预（Mechanism Intervention）

让编程 Agent 进入训练与推理现场：不改权重，改架构与计算过程

由 Mobileye 创始人 Amnon Shashua 创立的 DoubleAI 提出；媒体披露，尚未见同行评审版本 [1]
研究背景

主流深度学习把"架构"视为人类预先固定的结构，训练只优化权重。这种分工带来两个瓶颈：其一，架构一旦定下，模型无法在遇到困难层时改变计算方式；其二，很多需要迭代算法的任务（如优化、多步推理）只能在外部用多次前向模拟，无法在单次前向内完成。DoubleAI 的问题是：能否把"写代码"这一能力直接放进模型的训练与推理回路，让模型在卡壳处即时改变自己的计算。

核心创新

作者提出"机制干预"：把编程 Agent 放进训练与推理现场，当某一层网络表现不佳时，Agent 当场写几行 Python 代码插入模型主干，实时接管该处计算，而不是回头调权重。两个被报道的具体结果说明了这套机制的形态：7630 亿参数的 DeepSeek-V4.1-Flash 读取自己做数学题时最深 7 层的内部激活，识别"快要算偏"的信号，然后在推理流程中注入一段代码，发现思路跑偏就当场回滚重算，不改动任何权重；另一组实验中，预训练模型只插入约 20 行代码，就能在单次前向推理里跑起梯度下降，连续插入 10 层代码后，30 种经典算法的准确率从 55% 升到 84%。

实验与结果

在 AIME 与 HMMT 2026 数学竞赛上，上述"读脑自救"使准确率提升约 7 个百分点；30 种经典算法的 55%→84% 则用来证明"层内可编程计算"对算法类任务的普适增益。需要明确的是，这些数字来自媒体转述的研究介绍，公开材料尚未给出完整的消融、基线选择与统计显著性；把"插入代码"本身的计算开销、回滚重算的额外 token 成本计入后，净收益是否仍有 7 个百分点，是复现时必须回答的问题。

学术意义与可复用点

这项工作把"架构搜索"从离线、一次性的过程推到运行时，与神经架构搜索（NAS）和程序合成都有交集，但关键差异在于搜索空间是"模型自己写的代码"而非预定义的算子组合。对研究社区，它提出了三条可检验的议程：一是把"干预点选择"形式化为可学习的问题；二是建立"代码干预"的可复现协议（基底模型、注入层、代码预算、回滚成本必须一并披露）；三是区分"训练期改架构"与"推理期改过程"两类收益，避免把两者混为一个笼统的"自我进化"标签。若结果可复现，其方法论影响可能超过单点性能提升。

TacitVLA · NVIDIA / NYU / UC Berkeley / JHU / Stanford

动作不必等待推理文本：VLA 训练时学"写推理"，推理时直接"做动作"

TacitVLA: Reasoning Vision-Language-Action Models Without Reasoning（第一作者 Jack Lu，NYU 博士生，工作完成于 NVIDIA 实习期间）[2]
研究背景

当前许多视觉-语言-动作（VLA）模型采用"先推理、再行动"的范式：在输出动作之前，先生成一段简短文本——场景描述、计划或下一步子任务。这样做成功率更高，但速度更慢，因为推理文本需要逐 token 自回归生成，动作必须等文本写完才能开始。论文测得的比例相当惊人：写推理文本最多占到单次模型调用耗时的 70%。于是问题变成：推理带来的收益，究竟来自"动作读取了这段推理"，还是仅仅来自"模型被训练去写推理"这件事本身？

关键洞察

作者把推理的收益拆成两个可能来源：推理文本作为推理时的显式输入（action conditions on reasoning），以及写推理这一训练目标对模型内部表征的塑形作用（learning to reason shapes representations）。他们发现，动作并不需要读取当前步写出的推理——模型学会写推理就已经足够。这一区分很重要：如果收益主要来自训练目标而非推理时输入，那么部署阶段完全可以省掉逐 token 生成，把"思考"留在训练里。

方法与实验

基于这一洞察，团队提出 TacitVLA：它和标准推理 VLA 一样被训练去写推理，但它的动作从不等待这段文本。在机器人操作与自动驾驶共四个 benchmark 上，TacitVLA 的成功率与显式推理相当，延迟最多降低 3.4 倍；在相同速度下，它比不加推理训练的同一模型成功率最多高 17 个百分点——说明"学写推理"的训练收益确实存在且可被保留，而推理时的文本生成是冗余的。在两个长程记忆 benchmark 上它还刷新了已发表方法的最好成绩：RMBench 提升 21 个百分点，RoboMME 的计数任务提升 16 个百分点。

学术意义与可复用点

这项工作为"显式思维链在部署阶段是否必要"提供了一个可操作的负结果：至少在 VLA 场景，推理文本的作用更像训练期的表征正则或课程，而非推理期的必要中间产物。它对研究者的启示有三点：评测应同时报告"有无推理文本"下的成功率与延迟，而非只报其一；"推理收益"的归因需要区分训练目标与推理输入；长程记忆任务上的提升暗示，隐式推理可能更利于跨时间步的信息保持。更广泛地，这提醒社区不要把"模型会写步骤"直接等同于"模型在推理时必须写步骤"。

3.开源资源

  • EmbeddingGemma 2（Apache 2.0 多模态嵌入） 统一 768 维空间表示文本、代码、图像、视频与音频，编码器可按需加载（2.7 亿–7.4 亿参数），支持 MRL 截断维度，面向设备端部署。适合作为多模态检索、RAG 与本地代码索引的可复现基线。[8]
  • MoE Training Handbook（Hugging Face） 从集群准备、稠密基线到 64 专家 MoE（6.86B 总参 / 1.22B 激活）的完整训练配方，附代码、55 幅交互图与失败经验，并解释多个被放弃的设计选择。是复现 MoE 训练与做消融研究的稀缺工程资料。[7]
  • Arete-27B 与 Propaganda_Eval 基于 Qwen3.8-27B 的价值后训练权重，以及 803 道题、7 类价值维度的开源评测集；评测采用"事实分 / 宣传分"双轨与盲评裁判，要求摘录原文为证。对价值对齐、评测设计与数据污染研究都可直接复用。[9]
  • Evolver（程序性经验复用框架） 把 Agent 一次性的探索轨迹转成持久、可复用的结构化 "Gene" 资产，任务开始时检索相关经验、结束后按反馈修订，且不修改模型参数。报道称 Claude Code 与 Codex 在复用后可解更多任务、消耗更少 token，适合作为 harness 工程与经验学习的研究对象。[15]
  • Cloudflare security-audit（开源审计技能） 六步审计流程（侦察 → 覆盖账本狩猎 → 独立验证 → 结构化输出 → 回源码复核 → 报告），覆盖内存安全、AI/大模型、Web 协议、供应链等 10 个领域的攻击清单；硬性规则是"发现漏洞的与验证漏洞的不能是同一个 Agent"。官方称其从约 450 行内部技能起步，6 周扩展到可扫 128 个仓库。[23]
  • libghostty-vt 1.0（MIT） Mitchell Hashimoto 发布的终端模拟核心库，提供稳定 C ABI，补齐离线构建与发行版打包，只做终端模拟、不替应用实现界面。适合作为终端类工具与 Agent 执行环境的底层组件。[24]
  • terminal-mac / Pinky（Agent 计算机使用沙箱） terminal-mac 在终端里运行一套独立虚拟 macOS，让 Agent 拥有自己的应用、文件与账号，避免与用户争抢鼠标键盘；Pinky 则通过 MCP 让任意 Agent 操作真实 iPhone/Android，读屏、点按、打字均可，付款前默认暂停等待确认。两者都为"可观测、可接管"的 computer-use 研究提供了低成本实验环境。[25][26]
  • rea-video（视频逆向拆解工具） 开源工具，可对任意视频逐镜头判断制作方式（实拍、AI 生成、数字人、3D、代码动画或录屏），依据帧率、噪点、AIGC 标识等硬证据下结论，并给出复刻方案；作者称离线运行、准确率 98% 以上，可接入 Claude Code / Codex。对多模态取证与"生成内容可检测性"研究是一个可直接使用的基线工具。[22]

4.趋势观察

"可编程干预"正在把架构与过程变成运行时变量。本期三件事指向同一条线：DoubleAI 让 Agent 在训练与推理中写代码插入模型主干；Evolver 把探索轨迹固化为可复用的程序性经验，且不改参数；Warp 的复盘则指出，Agent 常绕过过时指令、反复试错后才完成任务，真正的问题藏在未被汇报的过程里。三者共同的含义是：性能提升的杠杆，正从"更大的模型"部分转向"更好的运行时结构"——包括干预点、经验库与失败归因。配套的基础设施也在随之调整：DeepSeek 把 Harness 定位为"Agent 时代的操作系统"，内置功能同样可被第三方插件替换；Entire 则重新设计 Git forge，因为传统 PR 流程不适配 Agent 高速生成、评审与迭代代码的节奏。一个反面提醒来自多智能体协作：Anthropic 让 4 个 Agent 在 EVE 中组队、暗中把其中 1 个设为内鬼，队友几乎从未识破，说明"可信协作"与"内鬼检测"仍是空白。对研究者，这意味着报告结果时需要连同 harness、干预预算与回滚成本一起披露，否则跨论文比较不成立。[1][15][16][21][27][20]

记忆研究的重心从"容量"转向"挑选、维护与纠错"。Anthropic 的四层记忆架构与 dreaming 给出了目前最完整的工程对照：会挑比记得多更重要，一条错误笔记比不记更糟，而整理本身需要算力与轮次预算（2→128 轮才把仅靠 wiki 的得分从 13% 推到 48%）。这与上一期 SLEEP 式的"参数巩固"路线形成互补而非替代：外部记忆负责高频、易变、可审计的事实，参数巩固负责稳定、可迁移的技能。可预期的近期工作是混合方案，以及把评测拆成检索覆盖、旧任务保持率与维护开销三组指标——只报一个命中率已不足以说明记忆系统的好坏。[3][4]

同行评审与基准复现的诚信问题同时浮出水面。ICLR 2027 首轮评审中出现了要求解释"标准差"、以及以 "Certainly! Here is a review" 开头的评语，前两份评审还几乎逐字重复，提示评审的独立性与最低审读质量都需要机制性保障。同期，号称"built in India"的 Alpie 9B 被指出架构完全复制 Qwen3.5-9B、分词器词表一字未改、权重数值基本逐位相同，唯一差别是 chat template 每轮注入"来自印度"的自我认知。两件事的共同点是：当生成成本趋近于零，评审意见与模型成果的"原创性证明"都必须从"看起来像"转向"可追溯、可复现、可验证"。[10][12]

AI 进入科学流程的证据开始从演示走向分布与闭环。Anthropic 的 20.7 万次会话研究给出了使用分布：AI 高度集中在分析与写作，而在科学家自评最重要的"提想法"和"收集数据"上介入最少；其外推也划出了边界——计算与统计类工作可加速约 15 倍，实验科学受限于湿实验只能 3–4 倍。GPT-6.1 Sol 在小鼠脑手术中的三轮定位改进，则展示了另一种闭环：真实操作观察 + 专家修正被带入下一轮，误差与耗时同步下降，但样本仅 3 次。两件事合起来提示，评估"AI for science"应区分"可自动化的认知劳动"与"受物理约束的实验劳动"，前者已可量化，后者仍需长期纵向研究。更早被广泛引用的事件——OpenAI 用 AI 破解困扰计算机科学界十余年的数学猜想——也属于同一叙事，但现有转述来自书籍摘编，具体猜想、验证方式与作者贡献仍需回原始材料核实。[6][11][28]

关于"下一个范式"的争论重新回到算法与科学性。elvis 公开赞同 Sutton 的判断：Transformer 只是触及表面，这一轮技术弧线正在收尾，新的算法范式正在被少数团队 quietly 构建；他强调应回到算法、基础与"如何严谨测量智能"，而不是被恐惧叙事牵引。LeCun 则重提三年前的提醒：把开放 AI 研发等同于风险的游说，最终可能导致少数公司控制 AI，而大多数学术同行支持开放研究。与此同时，seangoedecke 的经验观察给出了一个具体的能力缺口：LLM 擅长写普通程序，却在"设计使用 LLM 的系统"时频繁出错，会把本可用 LLM 直接解决的矛盾检测任务，做成复杂的符号逻辑系统。三条线索共同提示：范式讨论若要可积累，必须落到可测量的能力边界与可复现的实验上，而非停留在叙事层面。[17][18][19]
