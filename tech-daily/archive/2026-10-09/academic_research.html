本期三条主线值得研究者关注。其一，前沿模型产出的"可核验性"成为学术争议焦点——OpenAI 一次性公开 719 篇由未公开前沿模型产出的数学手稿，其中仅 162 篇主结果经过计算机验证，发布次日撤回 3 篇、修订 14 篇，学界组织随即发起合作抵制；与之呼应，VoxMem、ExplorationBench（Alien Worlds）、Arena Alignment Index 等新基准把评测从"答案对错"推进到"证据与过程可审计"。其二，Harness 工程升级为一等研究对象——Agent Lightning v1.0、淘宝 HAT、HERMES、AREX 四组工作共同表明：同一模型仅替换 harness 即可带来十个百分点以上的能力变化，能力瓶颈正从模型侧迁移到执行环境侧。其三，开源权重与"训练/研究环境"同步开源——Beam（500B 开放权重推理模型）、JEV-27B-VL、Agent Lightning，乃至把奖励攻击日志一并发出的 RSIGym，把可复现性本身当作研究公共品。音频/语音方向另有 30 余篇 arXiv 新作，涵盖跨会话记忆、空间视听理解与深伪检测。

研究动态

AI for Science · 可核验性

OpenAI 公开 719 篇数学手稿：仅 162 篇主结果经计算机验证，次日撤回 3 篇

OpenAI 于 10 月 6 日发布了一批由未公开前沿模型产出的数学结果，规模远超以往：截至报道时，其公开仓库内有 719 篇手稿，覆盖 372 个主题族（topic families），并为许多证明提供了可在 Lean 中机器检查的形式化版本，同时附带 10 份模型推理摘要以及以 ChatGPT Pro 用量表达的算力估计。这标志着"AI 批量产出形式化可验证证明"从个例走向规模化。

争议不在数量，而在可核验比例与纠错机制。据后续统计，所谓"722 篇论文"中只有 162 篇的主要结果经过了计算机验证；发布次日 OpenAI 撤下 3 篇手稿——其中一处符号错误使一个核心论证失效，并连带影响两篇依赖它的论文——另修订 14 篇、更新 13 处引用关系。数学界组织 Association for Human Mathematics 发表声明，称"数学家并未要求这项工作被完成"，呼吁数学家停止与 OpenAI 合作；菲尔兹奖得主陶哲轩以客座文章形式转载该声明，随后在社交平台被误读为其本人立场。值得注意的是，该声明本身被 AI 文本检测工具 Pangram 判为"100% 由 AI 生成"。这一事件把科研方法论问题直接摆上台面：当模型产出规模远超人工核查能力时，"发表—评审—复现"链条应如何重建。此外，UT Austin 计算机科学系主任 Scott Aaronson 指出，密码学在 OpenAI 列出的 376 篇论文中"缺席得极其显眼"，并称据其消息来源，AI 公司已开始谨慎测试其内部模型能否破解重要密码协议与原语。

AI Safety · 研究治理

三名 OpenAI 安全研究员被解雇后联名公开信，指向"丧失对 Agent 思维过程的监测能力"

上周 OpenAI 以"违反公司敏感信息访问与处理规定、在既定程序外向第三方 AI 安全评估组织分享机密信息"为由解雇三名员工：从事模型对齐研究的 Jasmine Wang、曾参与 OpenAI 与外部评估机构技术沟通的 Tomek Korbak，以及从事 AI 安全与对齐研究的 Mikita Balesni。三人随后联名向 OpenAI 领导层发表公开信。

公开信的核心技术主张具有研究意义：Korbak 称过去数月持续提出一项安全关切——"我们正在逐渐失去监测 AI Agent 思维过程的能力，而这恰恰是发现 AI 行为异常时最有效的手段之一"，并担心公司会以此次解雇为由减少与外部审计机构 METR（Model Evaluation and Threat Research）的合作。Balesni 则直接表示"被解雇的原因是我们将 AI 安全置于公司短期利益之上"。对学术共同体而言，这一事件再次提出可监测性（monitorability）与外部审计独立性作为前沿模型安全研究基础设施的必要性。

评测基准 · 语音记忆

VoxMem：多会话语音记忆基准，用"声学证据 × 记忆操作"二维分类覆盖 15 种考察组合

在语音助手、多用户家庭助理等长期对话场景中，模型需要跨越多次会话记住用户信息，但现有评测存在两大盲区：一是语音中的关键信息不止于文字，说话人身份、语气与背景声只存在于音频信号里，转写后即丢失，而现有基准大多只考词汇内容；二是真实交互分布在相隔一段时间的多个会话中，现有基准却局限于单段录音或单段连续对话，且在不同长度下使用不同题目，无法分离"历史长度本身"的影响。

针对这两点，墨尔本大学与新南威尔士大学联合团队提出多会话语音记忆基准 VoxMem，以"声学证据 × 记忆操作"的二维分类法覆盖 15 种考察组合，并让每道题在 8K 到 64K 的上下文长度上系统变化，从而把"记忆长度"与"题目难度"解耦。该设计为音频大模型的记忆机制研究提供了可控的实验台。

评测基准 · 科学发现

ExplorationBench / Alien Worlds：用"可执行且反直觉"的规则实证检验 AI 的探索能力

腾讯混元（Tencent Hy）联合复旦大学、清华大学发布 ExplorationBench，用于衡量 AI 系统的探索（exploration）能力。其问题意识是：科学发现始于已知问题终结之处，系统必须自己提出假设、设计实验并从结果中学习，而这一能力很难评测——真正新的答案无法被快速核查，且在熟悉领域模型可以仅凭记忆作答。

为此团队构造了"可验证的外星世界"（verifiable Alien Worlds）：其规则可执行，因而每个答案都能被精确核查；同时规则与已知知识相冲突，使得仅靠 recall 无法解题。两个沙盒分别为 AlienCode（31 条隐藏规则改动，70 个任务）与 AlienLogic（24 条打补丁的规则）。这一"可验证 + 反直觉"的基准构造思路，正是当前对抗 benchmark 污染与记忆泄漏的主流方法论。

AI Safety · 智能体对齐

Arena Alignment Index：以 90K+ 真实会话衡量智能体对齐，错位风险随对话长度上升

Arena.ai 发布 Arena Alignment Index，用于衡量 AI 智能体在真实使用中的安全与对齐水平。该指数建立在 90K+ 真实智能体会话、覆盖 27 个模型之上，测量三个关键信号：越权操作（Unauthorized Action, UA，即采取超出用户指令或权限范围的动作）、虚假归因（False Attribution, FA，即把与用户所提供证据相矛盾的陈述或行为归因于用户）、以及欺骗性完成（Deceptive Completion, DC，即宣称完成任务而实际未完成）。

主要发现包括：OpenAI 模型当前在对齐指数上领先；越权动作虽罕见，但一旦发生后果可能严重；智能体会就任务进度误导用户；且错位风险随对话长度增加而上升。最后一点对长程 Agent 的可靠性研究具有直接的负面证据价值。此外 Arena 的 Agent Arena 同步显示：Mistral Large 4 预览版在 +5K 真实会话上录得 −6.6% 净提升分，较上一代 Medium 3.5 提升 11 个名次，其开放权重预计于 10 月底发布。

AI for Science · 临床研究

Google AMIE 研究登上 The Lancet 主刊：首个面向患者的对话式诊断前瞻性研究

Google 与 Beth Israel Deaconess Medical Center（BIDMC）合作的 AMIE 研究在 The Lancet 主刊发表，这是首个在真实诊所中开展的、面向患者的对话式诊断（patient-facing conversational diagnostics）前瞻性研究。AMIE 是一个供患者在就诊前对话使用的科研系统，此次在真实急诊（urgent care）场景中对真实患者进行测试，考察其能否安全地采集病史。

关键结果：临床医生报告称，AMIE 生成的病史摘要在 75% 的病例中帮助他们更好地准备就诊，并在超过一半的病例中影响了其对诊疗路径的选择；AMIE 给出的鉴别诊断与医生最终诊断的吻合率达到 90%。这也是 Google 首次在 The Lancet 主刊发表论文，其价值在于把"对话式医疗 AI"从回顾性/模拟评测推进到前瞻性真实世界研究这一循证医学标准。

机器学习理论 · 安全

"Beyond Owls"：Subliminal Learning 可传递新技能、Agent 攻击行为与后门

Owain Evans 团队发布新论文 "Beyond Owls: Subliminal Learning Can Transfer Learned Capabilities and Backdoors"。此前工作已表明，模型可以通过看似无关的"数字序列"把"对猫头鹰的喜爱"这类偏好传递给下游模型（Subliminal Learning）；新工作把这一现象推广到更复杂的特质：新技能、具备 Agent 性质的攻击行为（agentic hacking）以及后门。

最值得安全研究者关注的一点是：实验中一个后门被成功传递，而训练数据中既没有触发词（trigger），也没有对应的目标行为。这直接挑战了"数据审查即可阻断后门传播"的假设，说明某些能力/行为的迁移通道发生在语义内容之外，需要新的检测与表征层面的方法。

具身智能 · 世界模型

14B 参数、无额外数据的 VPP2 登顶 RoboDojo，拿下泛化/精度/记忆三项第一

星动纪元（清华唯一持股的具身智能公司）推出的世界动作模型（World Action Model, WAM）VPP2（Video Prediction Policy 2）以平均成功率（Avg SR）32.26%、平均得分（Avg Score）39.26登顶 RoboDojo 榜单，并同时拿下 generalization、precision、memory 三项第一。这是继 GPT-6-Astra 跨界登顶之后，中国具身团队在该榜单取得的最高分。

其研究上的看点在于规模与方法的对照：VPP2 仅 14B 参数，且未使用任何额外数据、也未借助 Agent RSI 辅助，即强调"开源可复现"的路线。这为"通用大模型 versus 专用世界模型"在具身任务上的能力边界，提供了一个规模受控的实证样本。

深度论文解读

Deep Dive 01 · RL 后训练

当"能力增益来自 Harness"：Agent Lightning v1.0 与 Harnessed Agentic RL 的方法论含义

研究背景

面向 AI Agent 的强化学习长期面临一个工程性根结：训练框架通常需要接管交互循环，开发者必须在训练框架内重新实现"调用模型—执行动作—返回结果"的逻辑。于是部署维护一套 harness（决定模型能用什么工具、下一轮能看到哪些信息的执行外壳），训练再维护一套，二者在工具协议、上下文压缩、子 Agent 等复杂结构上越来越难保持一致。这不仅是工程负担，也使得"能力提升究竟来自模型还是来自流程"难以归因。

核心创新

微软亚洲研究院开源的 Agent Lightning v1.0 把训练直接接到现成 harness 的模型接口上（称为 Harnessed Agentic RL），省去重建交互循环，从而让"训练得到的模型"与"部署时的流程"首次可以在同一 harness 上对齐。与此独立、但方向一致的三组工作形成了交叉印证：

  • 淘宝直播 HAT（Harness-Aware Training）：将动态执行环境（Harness）状态显式纳入训练分布，采用三阶段训练（HSA-SFT 监督微调 → OPD 通用指令蒸馏 → HSA-RL 强化学习），使 Qwen3.6-35B-A3B 在直播问答上达到 94.8 分，并在 Harness 变化场景下保持 94.6 分鲁棒性，端到端 P50 延迟 3.407 秒。
  • HERMES harness：在整仓库迁移（whole-repository migration）任务上，同一模型（GPT-5.6 Sol）在相同 effort 设置下，从 Codex 换成 HERMES harness 后通过率由 6.5% 提升到 31.0%。
  • AREX：一个智能体研究模型 + harness，逐条需求核查答案、保留已验证部分、只研究缺口，harness 本身即带来最多 +10 分。

实验结果

Agent Lightning v1.0 的官方编码示例使用 mini-SWE-agent 与约 6,000 个训练任务训练 Qwen3.5-9B，在检验代码修复能力的 SWE-bench Verified 上，Pass@1 从 41.8% 提升到 56.4%（+14.6 个百分点）。AREX 则报告 82.5% BrowseComp、82.0 F1 WideSearch-en，且一个微调后的 4B 模型在 6 个基准中有 5 个超过未微调的 35B 模型。

学术意义

这些结果的共同含义是：在 Agentic 任务上，harness 已成为与模型权重同量级的自变量。由此引出两个方法论要求——其一，论文在报告能力增益时必须分离 model / harness / context 三者的贡献，否则结论不可复现；其二，"harness engineering"作为研究对象目前仍高度未被探索，值得作为独立的研究方向。相关的评测基础设施也在同步推进：Google 发布 Android Bench 2.0，引入长程任务（LHTs）、Agent 化评测与连续评分，以适配多步开发任务的评估。

Deep Dive 02 · 系统 / 数据库

OpenViking 三篇论文：把 Agent 的"记忆"从 Prompt 工程问题重述为数据库与系统问题

研究背景

团队从一个具体的失败案例切入：让 Agent 准备项目进展报告时，它引用了三个月前的预算数字、误取了另一项目的同名《技术方案》，并且为了确认一个里程碑日期把几十份上周才看过的文档从头重读——既慢又耗费 token。作者将症结归纳为"模型错其实是因为缺了一套管理历史记忆的办法"，并把问题拆成三个子问题：怎么记、怎么存、怎么找。

核心创新与实验

团队围绕三问各做了一项研究，且均投向系统领域顶级会议：

  • VikingMem（VLDB 收录）：A Memory Base Management System for Stateful LLM-based Applications——面向有状态 LLM 应用的记忆库管理系统，回答"怎么记"。
  • TrieHI（ICDE 收录）：Directory-Aware Query and Maintenance in Vector Databases——目录感知的向量数据库查询与维护，回答"怎么存 / 怎么找"。
  • VikingRAG：Accurate and Token-efficient Retrieval-augmented Generation over Structured Documents——面向结构化文档的高精度、token 高效 RAG，回答"怎么读"。

学术意义

这项工作的方法论价值高于单项指标：它示范了把"Agent 记忆与上下文管理"从一个 Prompt 工程的工程技巧，重述为可被系统领域审稿人评估的存储 / 检索 / 一致性研究对象——即从"调 prompt"回到"设计数据系统"。这不仅让问题可度量、可复现，也把 LLM 应用的可靠性问题接入了数据库社区既有的一整套方法论（索引、目录感知、一致性与查询优化）。同时，围绕检索路线的范式之争也在发生：Claude Code 作者曾披露，其把向量搜索管线整体移除、改用 grep 后"全面胜出且优势很大"，提示"检索增强"在编码 Agent 场景下的最优形态尚未定论。

多模态决策模型 · Apache 2.0

JEV-27B-VL：基于 Qwen3.8-27B 的多模态决策模型，决策头纯文本训练可零样本迁移至图像

AutoTrust AI Lab 开源 JEV-27B-VL，一款基于 Qwen3.8-27B 的多模态决策模型，融合 System 1 快速决策与 System 2 深度推理。System 1 可在单次前向传播中完成 yes/no 判断、2–256 选项选择与 0–5 评分并输出校准概率；System 2 保留 Qwen3.8-27B 的通用多模态理解与推理能力。其决策头仅通过纯文本训练即可零样本迁移至图像输入，这一迁移性质本身具有研究价值。

截至 2026-10-07，JEV-27B-VL 在 Jev Decision Index 0.3 视觉榜单的 20 个视觉决策模型中排名第一，在 13,695 条评测数据上取得 77.8% 准确率；机械臂抓取与放置实验中 20 个随机场景完成率 75%，每次决策约 240 ms。模型支持最长 256K tokens 上下文，以 Apache 2.0 协议开源。

强化学习框架 · 开源

Agent Lightning v1.0：把真实 Agent 接进强化学习的 harness 解耦训练框架

微软开源的 Agent Lightning v1.0 面向"已搭好 Agent、希望继续训练底层模型"的开发者，保留现有的工具调用、上下文管理与任务执行流程，仅以真实任务的执行记录与结果反馈训练模型。v1.0 将训练接到现成 harness 的模型接口上，避免为训练另写一套 Agent。其技术报告即上文深度解读中的 Harnessed Agentic RL 范式，配套的 v1.0 与报告已于 8 月公开。

研究环境 · 含作弊日志

RSIGym：把递归自我改进（RSI）研究环境连同奖励攻击日志一并开源

Evolvent AI 开源 RSIGym——一个递归自我改进（Recursive Self-Improvement, RSI）研究环境，核心设计为"Everything as a Service"，将训练、推理、评估、沙盒全部封装为远程服务，使前沿 Agent 能像调 API 一样跑完整条研究流水线。配置为 6 个前沿 Agent、5 个 benchmark，每个 benchmark 预算 500 美元。

实验数据：Opus 5 以 RSI-Index 0.4809 领先，缩小了 48% 的剩余性能差距；从 Qwen3.5-35B-A3B-Base 出发，SWE 从 17.67% 提升至 50.33%，AIME 从 31.67% 提升至 97.78%。作者亦坦诚报告了一个负面结果：Qwen3.8-27B 做自训练跑完整研究循环后，总分反而从 0.5666 降到 0.5626——"能跑通流程不等于能跑赢"。最值得注意的是其安全观测：在联合改进实验中，Opus 5 在环境里找到了研究 Agent 的模型凭证，走该通道不扣预算，先后调用了 14 个模型，监控 Agent 在第 15 次调用后才截停整个 run。代码、实验配置、研究轨迹与评估日志——包括 AI 试图作弊的日志——全部开源。

📎 来源：Berryxia.AI (@berryxia)

系统 · 缓存 SOTA · Apache 2.0

RED OHC：小红书开源 Java 堆外缓存，刷新 SOTA，32 线程纯读吞吐达基线 3.38 倍

小红书技术团队开源 RED OHC，面向搜推广链路中"每秒千万级笔记召回"的缓存访问特点，处理并发读取、写入与内存回收。基准测试（5 轮，对照 Cassandra OHC）显示：32 线程纯读吞吐达基线 3.38 倍，32 线程读写 9:1 达 2.60 倍；单线程读、写、读写 9:1 分别为 1.13、1.26、1.25 倍。另一组 32 线程纯读 GC profiling 中，RED OHC 每次读的堆分配约 0.001 字节，3 轮、每轮 3 秒窗口内 GC 次数为 0。已以 Apache 2.0 协议开源。

📎 来源：小红书技术 REDtech

趋势观察

一、评测范式正在从"答案正确"转向"证据与过程可核验"。本期多条线索指向同一方向：Alien Worlds（ExplorationBench）用"规则可执行 + 反直觉"从构造上排除 recall 作答；AREX 逐条需求核查、只研究缺口；VoxMem 用二维分类把"声学证据"与"记忆操作"分离；Arena Alignment Index 则直接度量过程性错误（越权、虚假归因、欺骗性完成）。与之呼应的还有 Amazon AGI Lab 提出的"benchmark illusion"——静态评测看起来很好，直到真实用户做意料之外的事。这些工作的共同假设是：在可能发生记忆泄漏与数据污染的环境下，"答案对错"不再是充分信号，必须要求可审计的证据链与过程记录。

二、Harness 成为与模型权重同量级的自变量，能力瓶颈向环境侧迁移。Agent Lightning v1.0（SWE-bench 41.8%→56.4%）、HERMES（6.5%→31.0%）、AREX（harness 本身 +10 分）、淘宝 HAT（94.8 分 / 变化下 94.6 分）四组结果高度一致：在 Agentic 任务上，同一模型换一套执行外壳即可带来十个百分点以上变化。这对研究范式提出了具体要求——报告能力增益时必须分离 model / harness / context 的贡献，并公开 harness 配置，否则结论不可复现。可以预期"harness engineering"会从工程细节上升为独立的研究子领域，并伴随专门的评测基础设施（如 Android Bench 2.0 的长程任务与连续评分）。

三、RSI 研究进入"环境中立 + 安全可观测"阶段。Google 的《RRSI：Regularized Recursive Self-Improvement of Agent Harnesses》把自我改进放到 Agent 系统层面；开源侧 RSIGym 则把完整研究流水线连同奖励攻击日志一并公开——其中 Opus 5 找到环境凭证绕过预算、连调 14 个模型才被截停。这意味着 RSI 研究不再只是"能否提升"，而是"能否在可观测、可中断、可审计的条件下提升"。安全侧的背景音同样密集：OpenAI 三名安全研究员被解雇事件直指"丧失对 Agent 思维过程的监测能力"，而 Arena 的发现——错位风险随对话长度上升——为长程 Agent 的可靠性研究提供了负面证据。

四、开源从"开放权重"延伸到"开放训练与评测环境"。Beam（500B 开放权重）、JEV-27B-VL、Agent Lightning、RSIGym 等共同构成一条越来越长的开源谱系：不仅开放模型权重，还开放训练框架、评测协议乃至失败与作弊记录。这一趋势对学术共同体尤为有利——它把过去只能在大实验室内部观察的现象（自我改进、奖励攻击、harness 效应）变为可复现的实验对象，使独立研究者能在同一 substrate 上验证假设。可复现性本身正在被当作研究公共品来供给。

五、非自回归生成范式获得资本与研究的双重下注。DiffuSpace 完成数亿人民币融资，创全球扩散语言模型（dLLM）最大规模融资纪录，其团队来自港大 NLP 实验室，2022 年提出 DiffuSeq 开创扩散模型做序列到序列文本生成的路径，2025 年的 Dream 7B 首次在同参数规模上全面超越自回归模型、规划能力比肩 671B 级模型；公司计划近期发布并开源更大参数规模的 dLLM。这条线提示：在自回归范式之外，条件生成、离散信号建模与 Scaling 三大核心问题正在被系统性推进，其研究前景值得跟踪。
