📋 本期摘要

本期聚焦AI领域多项重要研究进展：Google DeepMind发布Nano Banana 2图像生成模型，在Image Arena基准测试中取得第一名；Perplexity开源两款SOTA嵌入模型并发布技术报告；Microsoft Research提出CORPGEN多任务AI代理框架；Claude Opus 4.6在搜索任务上实现突破。此外，端侧AI、函数调用、多模态生成等方向均有显著进展。

§1 研究动态

图像生成 Google DeepMind发布Nano Banana 2：实时知识驱动的SOTA图像生成模型
Google DeepMind正式推出Nano Banana 2（Gemini 3.1 Flash Image Preview），这是一款结合Pro级能力与Flash速度的图像生成与编辑模型。该模型的核心创新在于利用Gemini模型的世界知识库，并通过实时网络搜索获取信息和图像，从而更准确地渲染特定地标、位置和物体。在Image Arena基准测试中，Nano Banana 2以1279分的成绩夺得文本到图像生成任务第一名，超越GPT-Image-1.5和Nano Banana Pro；在单图编辑任务中与ChatGPT-Image-Latest并列第一（1407分）。模型支持多达5个角色和14个物体的一致性保持，API定价为$0.067/张（1024×1024），约为Pro版本的一半。
[来源: Google DeepMind Blog] [技术报告: Gemini 3.1 Flash Image Technical Report]
嵌入模型 Perplexity开源pplx-embed系列模型并发布技术论文
Perplexity发布了两款业界领先的嵌入模型系列：pplx-embed-v1和pplx-embed-context-v1，均提供0.6B和4B参数版本。据Perplexity声称，这些模型在搜索和向量数据库任务上超越了Google和Alibaba的同类型模型。研究团队还构建了内部网络规模基准测试PPLXQuery2Query和PPLXQuery2Doc，包含115K真实查询和从10亿页面中抽取的3000万文档。模型采用MIT许可证开源，已在Hugging Face和Perplexity API上可用。技术论文已发布于arXiv（abs/2602.11151），详细阐述了训练方法和评估结果。
[来源: Perplexity Technical Report] [论文: arXiv:2602.11151]
语言模型 Claude Opus 4.6登顶Search Arena排行榜
根据LMSYS Chatbot Arena最新数据，Claude Opus 4.6在Search Arena中取得第一名，得分1255，领先Grok-4.20-beta1、GPT-5.2和Gemini-3达30分。这是Claude Opus 4.6首次在文本、代码和搜索三个Arena中均排名第一。该模型支持100万token的上下文窗口（beta版），在大型代码库处理和长时间代理任务中表现更为可靠。与此同时，Claude Sonnet 4.6排名第7，与GPT-5.1持平。
[来源: LMSYS Chatbot Arena] [官方公告: Anthropic Blog]
AI代理 Microsoft Research提出CORPGEN：多任务环境下的AI代理框架
Microsoft Research发表CORPGEN研究，针对现有AI代理基准测试仅评估单一任务的局限性，提出了Multi-Horizon Task Environments（MHTE）多任务环境评估框架。研究发现，在真实工作场景中，领先的计算机使用代理在多任务负载下性能急剧下降，完成率从16.7%降至8.7%。CORPGEN引入了"数字员工"概念，采用层次化规划、记忆隔离和经验学习机制，在三个独立代理后端上实现了比基线高3.5倍的完成率。该框架具有架构无关性和模块化特点，其增益来源于系统设计而非单一基础模型。
[来源: Microsoft Research Blog]
端侧AI Google发布FunctionGemma：270M参数端侧函数调用模型
Google推出FunctionGemma，一款专为移动设备设计的270M参数模型，用于实现高效的端侧函数调用。该模型基于Google AI Edge和LiteRT-LM构建，能够在完全离线的情况下执行复杂任务，如管理日历、控制设备硬件或执行特定游戏逻辑。Google AI Edge Gallery应用已在Android和iOS平台上线，开发者可测试该模型。FunctionGemma使开发者能够构建响应迅速、具备"代理能力"的应用，无需依赖云端处理即可与物理和数字世界无缝交互。
[来源: Google Developers Blog]
代码生成 Meta发布VecGlypher：统一矢量字形生成语言模型
Meta研究团队发布VecGlypher，一种用于统一矢量字形生成的语言模型。该研究聚焦于将矢量图形（SVG格式的字体和图标）生成任务纳入语言模型框架，实现了高质量、可缩放的矢量内容生成。论文已上传至Hugging Face Papers平台，展示了在字形生成领域的最新进展。
[来源: Hugging Face Papers]
评估基准 Code Arena推出多文件React排行榜：评估复杂代理能力
LMSYS Code Arena正式上线多文件React应用排行榜。与最初仅评估单文件HTML的基准不同，新基准测试模型在复杂工作流中的表现，包括跨文件协调、组件架构设计、依赖管理、状态管理和构建可靠性等。多文件React测试比单文件HTML测试更能反映模型的代理能力（agentic capabilities）。该排行榜现已包含多种前沿模型的性能对比数据。
[来源: Code Arena Leaderboard]

§2 深度论文解读

PPLX Embeddings: Web-Scale Embedding Models for Search and RAG
Perplexity AI Research | arXiv:2602.11151 | 2026年2月

研究背景

嵌入模型（Embedding Models）是现代检索增强生成（RAG）系统和AI搜索的核心组件。然而，现有的开源嵌入模型大多针对通用语义相似度任务优化，在真实世界的网络规模搜索场景下表现不佳。Perplexity研究团队针对这一问题，开发并开源了专门面向搜索和检索任务的嵌入模型系列。

核心创新

  • 双模型架构：pplx-embed-v1针对查询-文档匹配优化，pplx-embed-context-v1针对长上下文理解优化，均提供0.6B和4B参数版本以满足不同延迟和精度需求。
  • 网络规模训练：模型在超过10亿网页的语料上训练，学习真实网络文档的分布特征。
  • 专用评估基准：构建PPLXQuery2Query（115K查询对）和PPLXQuery2Doc（30M文档池）内部基准，模拟真实搜索场景。

实验结果

在MTEB和自定义基准测试中，pplx-embed-v1-4B在检索任务上超越了Google的 Gecko 和Alibaba的 GTE 系列模型。具体而言，在BEIR基准的15个数据集上平均NDCG@10达到56.3%，领先第二名约2.1个百分点。值得注意的是，0.6B版本在保持较高精度的同时，推理速度比4B版本快4倍，为生产环境部署提供了灵活选择。

学术意义

该研究的贡献在于：1）证明了针对特定任务（搜索）定制的嵌入模型可以显著超越通用模型；2）开源了模型权重和训练方法，推动社区对搜索导向嵌入模型的研究；3）建立的专用基准为后续研究提供了评估标准。这对RAG系统、AI搜索和推荐系统的研究具有重要参考价值。

Do AGENTS.md Files Help Coding Agents? An Empirical Study
Independent Research | 2026年2月

研究动机

随着Claude Code、GitHub Copilot等编码代理工具的兴起，开发者开始在项目中添加AGENTS.md文件以提供项目上下文信息。然而，这种做法的实际效果如何尚缺乏系统评估。本研究通过大规模实验量化了AGENTS.md文件对编码代理性能的影响。

研究方法

  • 实验设计：对比三种情况——无AGENTS.md、人工编写AGENTS.md、LLM生成AGENTS.md在SWE-bench和HumanEval上的性能差异。
  • 评估指标：任务完成率、代码正确性、推理成本（token消耗）。

关键发现

研究结果出人意料：1）人工编写的AGENTS.md仅带来约4%的性能提升；2）LLM生成的AGENTS.md反而使性能下降约2%；3）无论哪种方式，推理成本都增加20%以上。深入分析表明，编码代理虽然会忠实地遵循AGENTS.md中的指令，但这种遵循并未转化为问题解决能力的提升。研究者推测，当前编码代理可能更依赖于代码本身的语义理解，而非外部文档提供的上下文。

启示与反思

这一发现对当前的"提示工程"和"上下文工程"实践提出了挑战。研究建议开发者：1）在添加AGENTS.md前评估其必要性；2）优先投资代码质量和注释而非外部文档；3）期待未来研究探索更有效的代理-人类协作模式。该研究也指出了当前评估基准的局限性，呼吁开发更能反映真实开发场景的测试集。

§4 趋势观察

端侧AI的加速落地：从文本到多模态

本期观察到端侧AI部署正在从文本模型向多模态扩展。Google的FunctionGemma（270M）实现了移动设备上的函数调用，而Nano Banana 2的端侧优化版本也在开发中。这一趋势的核心驱动力包括：1）隐私需求——敏感数据无需上传云端；2）延迟要求——实时交互场景需要毫秒级响应；3）成本考量——减少云端推理费用。技术挑战在于如何在有限算力下保持模型能力，当前主要解决方案包括模型蒸馏、量化（INT4/INT8）和专用硬件加速（NPU/TPU）。预计2026年下半年将有更多端侧多模态模型发布。

嵌入模型的专业化分化

Perplexity pplx-embed系列的发布标志着嵌入模型领域正在从"通用化"向"专业化"转变。不同于早期追求通用语义表示的模型（如BERT、SimCSE），新一代模型针对特定任务优化：搜索导向（pplx-embed）、代码检索（CodeT5+）、多语言（LaBSE）等。这种分化反映了RAG系统对嵌入质量的更高要求——在检索阶段提升1%的准确率，可能比在生成阶段优化带来更大的整体收益。研究者应关注特定领域的嵌入模型设计，以及如何将多个专用嵌入模型组合使用。

AI评估基准的演进：从单任务到多任务环境

Microsoft Research的CORPGEN研究揭示了当前AI评估基准的关键局限：大多数基准测试单个任务，而真实场景需要同时管理数十个相互依赖的任务。这催生了新一代评估框架，如MHTE（Multi-Horizon Task Environments）和Code Arena的多文件React排行榜。未来评估基准需要模拟更复杂的工作场景，包括：1）长期任务依赖和状态管理；2）多代理协作与冲突解决；3）资源受限环境下的性能表现；4）人机协作中的交互效率。基准的演进将推动AI代理从"演示级"向"生产级"迈进。

实时知识增强生成：搜索与生成模型的融合

Nano Banana 2的核心创新——实时网络搜索增强图像生成——代表了一个新的技术方向：将检索机制深度集成到生成模型中。不同于传统的RAG（检索后生成），这种"生成中检索"模式允许模型在生成过程中动态获取外部信息。类似技术已在Perplexity的搜索模型和Claude的扩展思考模式中出现。这一范式的挑战在于如何平衡检索开销与生成质量，以及如何评估生成内容的事实准确性。研究者需要开发新的训练方法和评估指标来支持这一方向。
