商业模式 · 竞争格局

SaaS 的地基正在被客户自己抽走：AI 如何改写软件公司的护城河

过去十几年习以为常的「按月订阅、数据锁在你家、增值靠功能堆叠」的软件生意，正遭遇一个结构性威胁：买方手里第一次有了能自己写代码的通用智能体。KeyBanc 第 17 届软件行业基准调研给出了刺痛的数据——在 81 家以 ARR 中位数 2200 万美元为主的 B2B 软件公司中，43% 承认已亲眼目睹客户用 AI 重写其产品，百人以下小厂这一比例高达 55%；同时仅 6% 达到「40 法则」，近半数 AI 相关成本超支。这不是需求消失，而是需求的交付方式在变。

需求端的故事同样直白：HeadshotPro 创始人 Danny Postma 宣布全面退订各类托管 SaaS，因为"每次只需要其中一小块功能"，干脆花 20 分钟让 AI 逆向重写自用。这背后是客户的议价权发生了质变——以前客户离不开你的功能完整性、集成生态与运维托管，如今这些门槛正在被"按需生成 + 数据留在本地"的偏好逐一绕过，连 MCP 都被嫌不够用。供给端的估值逻辑也在同向坍缩：Elad Gil 用 90 年代 2000 家公司 IPO 却所剩无几的历史作类比，警示"从零冲向一万亿美元"被当成基准线是危险的，而 Anthropic 上市四日破发正是资本用脚投票的注脚。

对 CTO 的战略含义是双面的：一方面，若你所在的公司是软件供给方，需要重新评估哪些能力是真壁垒（数据网络效应、合规与信任、深度集成、工作流嵌入），哪些只是"看起来完整的功能清单"；另一方面，作为技术采购方，自建 vs 采购的边界需要重算——当自建成本被 AI 压低一个数量级，过去"买比造便宜"的默认假设要逐条复核。泡沫的破裂不一定是坏事，它会把资源从"讲故事"重新分配到"真需求"。

技术架构 · 研发组织

研发基础设施的权力转移：从「人写代码的 IDE」到「AI 交付代码的流水线」

纳德拉的两句话值得每一位技术负责人抄下来：「Code went from input to output effectively. IDEs kind of faded away.」过去几十年开发工具的设计前提都是"代码主要由人来写"，语法高亮、补全、跳转、重构都是围绕这个前提优化；一旦代码成为模型的输出而非人的输入，IDE 作为研发流程中心的地位便被动摇。这不是某一家工具的兴衰，而是整个研发基础设施的坐标系在平移。

支撑这一判断的，是一批大厂正在把「AI 参与交付」变成可运营的工程系统：Meta 开源的 PyTorch GreenLight 让 AI 审阅者可以批准自家维护者的低风险 PR，与 OpenAI、Anthropic、Sonar 的自动化审批思路同源，但把"风险分数 + LLM 审阅 + 人工兜底高风险变更"做成了可复用范式（InfoQ）；Netflix 的 Quasar 用语义索引 + API 比对，精确计算库变更的"爆炸半径"并规划消费者迁移，把"改一处、崩一片"的风险量化（InfoQ）。这些都在回答同一个问题：当 AI 大批量产出代码，组织的瓶颈从"写得快不快"转向"审得准不准、改得安不安全、成本算得清不清"。

成本侧同样在重塑架构决策。Cloudflare 的故事颇具样本价值：它早期押注"模型会变小、时延为王"，结果模型反而长到万亿参数，于是果断转向做推理服务，又在 System 1 决策模型出现后用一个周末训练出自有模型、三周上线四款，在 CI 分诊任务上做到约 2 倍速度、便宜 72%、token 少 94%（AI Engineer）。Glean 则把产品里大量"有界决策"（分类、路由、排序、引用校验）从昂贵的大模型迁到专用决策模型 Jev，专家路由延迟降约 8 倍、安全分类召回率从 31.5% 升到 90.2%（AI Engineer）。阿里则把 7B 模型冷启动从 2 分半压到 12 秒，让"缩容到零"在稀疏流量下真正算得过账（阿里技术）。

把这些拼起来，一条清晰的判断浮现：架构决策的核心指标正从"功能能不能实现"转向"单位算力产出与单位任务成本"。能区分"生成任务"与"有界决策"、能为稀疏负载做真正的弹性、能用专用小模型替代通用大模型的团队，将在下一轮成本竞争中拿到结构性优势。

CTO 视角

Action Items

给技术高管的行动建议

在一个「AI 从故事回归现金流」的转折点，技术决策的评判标准正被重置。

  1. 重算自建 vs 采购的边界。当 AI 让自建成本降一个数量级，"买比造便宜"的默认假设要逐条复核。对每一个核心 SaaS，问清楚：真壁垒是功能清单，还是数据网络效应、合规信任与工作流嵌入？后者才是不可被"20 分钟重写"替代的部分。
  2. 把研发基础设施的坐标系从 IDE 换成交付流水线。参照 GreenLight / Quasar，建立"AI 审阅 + 风险分层 + 变更爆炸半径量化"的工程系统；让写代码的 AI 与查代码的 AI 分离、交叉审查，把瓶颈从产出速度转向审阅质量与上线安全。
  3. 把单位算力产出纳入架构决策。区分"生成任务"与"有界决策"，能用专用小模型/决策模型替代通用大模型的地方果断替换；对稀疏流量做真正的 scale-from-zero（参考阿里把 7B 冷启动压到 12 秒）。算力预算申报前，先回答单位任务成本是多少。
  4. 治理「提效幻觉」，建立产出闭环。警惕 Workslop 污染工作流与 AI 预算在全员铺开第二个月集体漏钱。把预算从"按人头买账号"改成"为结果买单"，明确内部沟通用真人语言的底线，让 AI 产出可追溯、可验收、可负责。
  5. 提前为 Agent 时代补安全边界。1Password 的教训说明供应链与 CI/CD 是首要攻击面。对 Agent 的权限、工具调用、数据访问做硬隔离（而非只靠系统提示词），高危操作默认需人工确认。Agent 铺得越快，边界治理的投入回报越高。
  6. 重估人才结构与招聘标尺。纳德拉的"一人 + AI 预算"不是口号而是组织实验：先算清"人机分工后的人效基线"，再决定编制。招聘从看学历转向看"做出来、交出去、卖出去"的真成果，同时为核心技术人才建立防挖角机制——Claude Code 团队被整体挖走的教训就在眼前。
