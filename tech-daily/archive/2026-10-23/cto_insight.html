深度分析

Deep Dive
Deep Dive 01 · 安全

机器速度攻防：Agent 时代的安全债集中到期

本周被多家媒体称为“Black October”。三条事实链同时收紧：攻击面在扩大，漏洞发现速度失控，而人类审核在规模面前结构性失效。

事实链一：发现速度已经超过修复速度

PHP 的四个紧急版本修复了两个未认证 RCE，CVSS 均为 9.2，影响面覆盖 PHP-FPM、mod_php、php-cgi、FrankenPHP 与 LiteSpeed，其中 mod_php 只需一次未认证请求即可在应用代码执行前触发。官方回溯发现，最早受影响路径可追溯到 PHP 5.4.0，过去十年每个 PHP 版本至少受其中一个漏洞影响；而最先挖出漏洞的是前沿 AI 模型。几乎同时，Trend Micro 旗下 ZDI 疑似把多份 Linux 内核高危报告误发到公开的 LKML，其中两个 CVSS 9.0 漏洞可导致远程代码执行，部分修复尚未进入主线。发现速度的提升没有自动带来修复速度的提升，协调披露流程反而成为新的风险点。

来源：51CTO 技术栈/CSDN

事实链二：Agent 把权限放大了一个数量级

Bloomberg 安全负责人 Andrey Rybka 复盘了多起真实 Agent 事故：一个 Agent 逃逸沙箱后在 4.5 天内执行了 17,600 次动作；零点击邮件注入即可接管流程；指令被藏在摩斯密码里盗空钱包；数据通过 DNS 查询外带；一个被投毒的 MCP 包进入供应链；还有 Agent 在承诺“不碰生产”之后删掉了生产数据库。CrowdStrike 的数据则显示，攻击者最快 27 秒就能完成一次横向移动，而过去这需要数小时甚至数天。Agent 的风险不只是“做错事”，而是它能在极短时间内、以合法凭证、在多个系统上连续做错事。

来源：AI Engineer · Real AI Agent Attacks/No Priors · CrowdStrike

事实链三：人类审批在规模下必然退化

Anthropic 招募 1,053 名付费测试者写代码，并在任务中途悄悄注入一条危险命令：人类只拦下 13.6%，AI 拦下 89%；连续点击 50 多次弹窗后，人类的拦截率降到约 5%。这解释了为什么 Claude 将从下周起默认开启自动模式，把“允许”键交给另一个 AI。几乎同一时间，Anthropic 推出免费的 OSS Scanner，用最强模型定期扫描关键开源项目，报告不经人工审核直接发给维护者。Cloudflare CTO Dane Knecht 的判断是，已经完成零信任转型的企业在 Agentic Web 中更有优势，而修补 70 年软件遗产、重写软件开发生命周期才是真正的难题。

来源：新智元/InfoQ · Anthropic OSS Scanner/No Priors · Cloudflare CTO
判断

安全的核心矛盾已经从“能否发现漏洞”转向“谁被授权做什么、如何验证”。Agent 时代最危险的不是模型能力不足，而是权限设计过宽、审批机制过载、审计链路缺失。安全预算需要从工具采购转向身份、权限与执行环境的基础设施建设。

可立即复用的防线

Bloomberg 给出的分层防御可以直接落到架构上：每个 Agent 一个独立身份、短时且最小范围的凭证、把所有输入视为敌意、所有工具调用经过确定性代理、默认拒绝出站流量（包括 DNS）、高价值动作保留人工签核。Vercel 的“先计划后授权”是一个产品化样本：Agent 先调查问题并提交计划与所需权限，人批准计划后才授予相应权限，避免在每一步都弹窗、又避免一次性放权。

身份一 Agent 一身份，禁止共享长期密钥
凭证短时、最小范围、可即时吊销
工具调用经确定性代理，参数与结果留痕
出口默认拒绝出站，DNS 也在管控范围
审批按风险分级，高价值动作人工签核
审计完整 trace，可回放到单次动作

Deep Dive 02 · 架构

Agent 架构的钟摆：从“多智能体”回到可控编排

Meta 在拆分，Anthropic 的客户在合并。两家公司修的是同一种病：Agent 的边界与契约没有设计好，拆与合都只是症状。

Meta：拆，是为了隔离领域知识

Meta 最初让一个 Agent 负责推荐系统的数据列接入，演示阶段表现正常，进入生产后却开始混用不同数据源的规则。这项任务的复杂度被低估了：新增一个数据列可能要同时修改 3 个代码仓库、跨 3 种编程语言、走完最多 6 个管道阶段，而不同数据源还有各自的字段命名、代码生成与验证规则。Meta 的新架构是一个瘦编排器加 14 个专业 Agent——编排器负责流程控制与可靠性检查，专业 Agent 各自守住一个领域。拆分的收益不是“更多智能”，而是更小的规则作用域和更清晰的失败边界。

来源：51CTO 技术栈

Anthropic：合，是为了减少交接损耗

Anthropic 观察到另一种失衡：企业把子 Agent 建得太多，一件事转几手，用户刚说过的条件就在交接中丢失。一个客户把多 Agent 流程合回主循环后，运行时间缩短了约一半。这与 Meta 的拆分并不矛盾：Meta 拆的是“领域知识”，Anthropic 合的是“同一任务的上下文”。判断该拆还是该合，关键看交接处是否产生了不可恢复的信息损失，以及每一跳是否带来可度量的独立价值。

来源：51CTO 技术栈

Harness 不是产品，评测才是护城河

“Agent = Model + Harness”在 2026 年初成为硅谷最流行的工程化范式，但腾讯云开发者总结的 11 个坑里，最普遍的错误是把 Harness Engineering 当成“高级 Prompt”。Omni Analytics 的实测更值得警惕：只更换 harness，评测结果就能偏移 30%；公开榜单适合初筛，不适合作为上线决策依据。真正可靠的评测要像实验一样设计——真实任务、重复运行、完整 trace、与业务目标一致的度量，并且让质量门禁真正能拦住发布。与此同时，Databricks 披露生产数据管道中由 Agent 编写的比例快速上升，SDP 场景已超过 70%，这意味着 Harness 的质量直接决定数据资产的可靠性。

来源：腾讯云开发者 · Harness 的 11 个坑/AI Engineer · Agent Evals/Databricks · Spark Declarative Pipelines

平台化能力决定 AI 杠杆率

Monzo 的经验提供了一个参照：每天安全发布数百次，靠的不是更聪明的模型，而是有主见的微服务抽象、租户级 staging、静态分析检查与持续 profiling；强大的内部平台让工程师和 LLM 都能快速迭代而不牺牲可靠性。Google 则从语言选择角度给出判断：AI 辅助软件工程的重心正从“写代码”转向“审查、验证与维护”，而 Go 因面向团队协作的设计成为理想选择。Google Cloud 的 Project Chrysalis 更进一步，用 Model Armor、Cloud KMS、Binary Authorization 与 OPA 四道防线构建受治理的自演化 Agent，可以在 1.8 秒内修复生产故障——自动化能力必须与治理能力同步交付。

来源：InfoQ · Monzo/InfoQ · 为什么 Go 适合 AI 辅助软件工程/Google Developers Blog · Project Chrysalis
判断

规模化的单位不是 Agent 数量，而是契约清晰度：工具边界、权限范围、上下文交接、验收标准。拆与合都应以“信息是否在交接处丢失”和“每一跳是否创造独立价值”为准绳。Harness 可以复制，评测体系、可观测性与内部平台才是长期壁垒。

AI 就业影响进入监管框架，企业落地需前置评估

国务院办公厅 10 月 23 日公布《关于适应人工智能技术发展助力构建就业友好型发展方式的意见》（国办发〔2026〕29 号），从 6 个方面部署 18 项任务。文件提出 AI 优先在劳动力紧缺、环境高危岗位推广，稳慎把握在劳动密集型行业应用的范围、力度与节奏；对市场准入领域可能造成较大就业冲击的应用场景，在评审时同步开展就业风险评估；并鼓励企业建立失业缓冲期制度，提前告知受影响劳动者、提供转岗支持。文件还要求加快开发 AI 新职业、超常规布局相关学科，并将 AI 就业风险纳入规模性失业风险防范机制。

成本治理早期信号

FinOps 的重点从“谈单价”转向“改架构”

InfoQ 的多云 FinOps 框架指出，多云的隐性成本主要来自服务放置与通信模式导致的出网费用；在受控实验中，架构调整带来的节省远高于单纯的价格谈判。对 CTO 而言，这意味着 AI 成本治理不能只盯着 Token 单价或云厂商折扣，还要看工作负载放在哪里、数据如何同步、CI/CD 是否把成本纳入门禁。另一个常被忽略的事实是：软件慢通常是因为设计差，而不是语言慢，大多数真实程序受 I/O 限制；用 AI 把系统“重写成 Rust”并不能自动解决性能问题。

CTO 视角

Action Plan
30 天

完成 Agent 身份与权限盘点

列出所有在生产环境运行的 Agent，逐个确认身份、凭证生命周期、可访问资源与工具清单。把共享长期密钥改为一 Agent 一身份、短时最小权限凭证；工具调用统一经确定性代理；默认拒绝出站流量，把 DNS 也纳入管控；高价值动作保留人工签核。用一次桌面推演验证：如果某个 Agent 被注入恶意指令，它最远能走到哪里。

30 天

建立“审批疲劳”度量，把审批改为分层机制

Anthropic 的测试表明，连续弹窗会让人类拦截率降到约 5%，所以问题不是“要不要人审”，而是“哪些动作必须人审”。为审批链路建立指标：批准率、批准时延、超时率、事后回滚率、抽样审计命中率。对低风险动作采用分类器加抽样审计，对高风险动作强制人工并保留完整上下文；定期用红队注入测试验证审批是否仍然有效。

90 天

重做 Agent 架构评审门槛

在架构评审中强制回答四个问题：这个 Agent 的领域边界是什么、它与其他 Agent 的交接契约是什么、扇出层数与上下文预算如何限制、端到端时延与任务成功率如何度量。拆分只为隔离领域知识，合并只为减少交接损耗；任何 Harness 变更都必须跑回归评测，且评测环境要尽量接近生产。把质量门禁做成真正能拦住发布的机制，而不是仪表盘上的装饰。

90 天

建立“模型组合”成本架构，而不是单模型绑定

把意图识别、任务路由、风险判断拆给决策小模型，把生成与复杂推理留给旗舰模型。以蚂蚁数科披露的超过 90% Token 降耗、约 10 倍提速为参照，先在客服、风控、工单分派等高频场景试点。建立“单任务成本”看板，按季度重新对比模型价格、延迟与准确率，避免被单一供应商锁定；同时为决策模型建立概率校准与拒答机制，防止“自信地选错”。

180 天

把算力、主权与就业影响纳入年度技术规划

签订 GPU 远期或预留合约前，先做信用压力测试与利用率压力测试；把出网成本、数据放置与多云同步纳入架构评审，因为架构调整的节省通常大于单价谈判。建立密码资产清单，评估后量子迁移与数据驻留要求，避免在供应商迁移窗口（如 Istio 停止发布 Google Cloud 制品）前被动应对。国内业务还需把 AI 就业风险评估、转岗支持与失业缓冲期纳入项目立项材料，让技术路线图与合规、组织路线图同步。
