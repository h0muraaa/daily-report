1

Claude Code 开放"界面魔改"：Agent 工作台从"统一"走向"可定制"

Anthropic 发布 Claude Code Mods，用户可写一小段 JavaScript 或 TypeScript 模块来重写或替换部分行为、甚至绘制自定义 UI，也可以直接打字让 Claude 现场生成 Mod 并热重载生效。官方三个示例都很"体验向"：Token Weather 把上下文窗口占用画成输入框上方的"天气条"（未满=晴天、81%+=暴风雨）；Blast Radius 在执行 rm -rf、git reset --hard 等高危命令前，先列出会波及哪些文件、占多少空间，等用户按键确认；Replay Theater 让用户按下 r 或 /replay 逐项回看每处改动的 diff。Claude Code 之父 Boris Cherny 的说法是："每个人的工作流都不同，没有理由让所有人都面对一模一样的 Claude。"同一天，DeepSeek Harness、Pi 1.0、Codex 插件系统都在做同一件事——让用户自己往 Agent 上叠加功能，甚至改写它的界面。

体验洞察：界面个性化正在从"产品内置的几个偏好开关"变成"用户自建的能力"。这既释放了专家的效率，也提出新问题——当每个人看到的界面都不一样，"可发现性"和"一致性"如何保证？谁来为社区分享的 Mod 的可用性负责？

📎 来源： [小互(@imxiaohu)] [AINLP] [AI寒武纪] [elvis(@omarsar0)]
2

Karpathy：执行交给 AI 之后，"读懂产出"成了新瓶颈

Karpathy 久违发帖：当 LLM 承担越来越多执行工作，人的工作会转向监督与理解，瓶颈不再是"产出"，而是"人能不能高效读懂产出"。他的建议是——主动指定输出形式，让模型把内容做成最容易理解的样子，并给出四级递进：受控语言写作（ASD-STE100，源自航空维修文档）→图示→HTML 网页（可交互、可探索）→定制讲解视频（最看好，因为复杂概念需要时间维度上的引导）。每升一级，信息密度和理解效率更高，生成成本也更高。

体验洞察：这几乎是信息设计与信息架构的核心命题被重新抬到前台。UX 的工作对象正从"用户如何操作界面"扩展到"用户如何读懂 AI 的产出"——输出形式的可理解性（legibility）本身就成了一项需要被设计的体验。Karpathy 还提醒：智能与代码变得充裕，为一个问题专门生成网页或视频变得划算，"一次性软件"的成本判断被改变。

📎 来源： [meng shao(@shao__meng)]

Griffin 首个通过"视频图灵测试"：对话交互从"回合制"走向"全双工"

Tavus 发布 Griffin，自称首个通过视频图灵测试的模型——48% 与它实时对话的人以为对面是真人，而此前同类系统的通过率不足 3%，并在 NVIDIA 全双工 AI 视频基准（VideoFDB）的感知与生成两项均排名第一。关键技术差异是全双工：传统语音 AI 是"说完才听"的回合制，Griffin 能在说话的同时持续倾听和观看，会实时笑、点头、插话提问；它强调"生成整个画面，而非只换一张脸"；视觉也实时融入对话——用户举起玩具它即兴编进故事，教魔方时看着用户的手实时指导，并在对方思考时安静等待。团队用 Sparrow-2（对话轮次理解）+ Phoenix-4.5（实时人物渲染）+ Raven-1（多模态感知）统一成一个实时交互层。

体验洞察："时机感"本身被当作智能的体现——知道什么时候该等、该打断、该回应，是对话体验里最难也最容易被忽略的部分。当拟人交互逼近真人阈值，人脸与视频界面的非语言线索设计（注视、停顿、点头节奏）将成为新的体验竞争点。

📎 来源： [meng shao(@shao__meng)]

语音 Agent 的失败点不在 STT，而在"竞争说话人"

一份与 Krisp 合作的 Voice Isolation 基准给出反直觉结论：语音 Agent 的瓶颈已经不在转写准确率，而在背景里另一个人的说话声——它在信号层面与主说话人完全同质，模型必须做"听谁"的判断，干扰由此污染转录、扭曲意图、误触发对话回合。基准覆盖 265 条真实录音、47 位说话人、办公/呼叫中心/电话三种场景，横跨 11 种 STT 配置。结果：整体 WER 从原始音频的 23.3% 降到隔离后的 6.2%，办公场景 31.8%→6.3%；而几乎不存在竞争语音的电话场景反而轻微劣化（3.5%→3.9%），说明处理本身有代价。

体验洞察：语音产品的可用性测试若只在安静环境做，会系统性高估真实表现。研究设计需要把"多说话人、串音、打断"作为标准测试条件，并区分两个独立问题：上游的信号分离与下游的意图识别。

📎 来源： [meng shao(@shao__meng)]

Cloudflare 承诺"所有功能对所有人可用"：包容性从合规走向普惠

Cloudflare 回顾一年前的承诺——让每一个功能对每一位用户、每一个团队可用。起因是平台早期形成了一个两层体系：最先进、最强大的功能只面向 Enterprise 客户开放，而小团队、开源项目与个人被挡在门外。文章明确把"关闭这条鸿沟"作为目标，并强调无论 Fortune 100 还是个人开发者，都应当能用上平台的完整能力。

体验洞察：功能分层（tiering）从来不只是定价决策，它本身就是一种体验设计——它决定了谁是"一等用户"、谁是"二等用户"。把最能解决问题的高级能力锁在高价层，短期能提客单价，长期却在制造"看得到、用不上"的挫败感。对做 B 端产品的研究员，值得把"功能可及性"作为一条体验指标去测量。

📎 来源： [The Cloudflare Blog]

设计趋势洞察

2 个值得深读的趋势
趋势一

设计系统进入"可再生"时代：护城河从"组件"转向"规范与语义"

InfoQ 一篇题为《From Reusable to Regeneratable》的文章抛出一个尖锐判断：再生（regeneration）改变了复用的经济学。当模型指向一套扎实的设计系统就能按需产出大部分标准 UI，"付费维护一个 canonical 组件包"就越来越难被论证为划算。作者的结论不是抛弃组件库，而是把重心迁移——保留设计系统、tokens、指南和测试，因为它们才是真正买来一致性的东西。同一天 Figma 发布新功能，让设计更贴近 CSS，"你交付的就是上线的"，把 handoff 从人工测量推向语义对齐。

  • 设计资产的重心迁移：从"可复用的组件实现"转向"意图、约束、语义命名与规范"——组件可以生成，规范与测试不可省。
  • 角色变化：设计师从"拼装组件"更多转向"定义生成边界与验收标准"，这与 AI 出图的"可控性"命题是同一条线。
  • 一致性的新来源：过去一致性靠"大家都用同一个组件"，未来一致性靠"大家都遵循同一套 token 与约束"。

实践建议：把 tokens、语义命名、可访问性测试与设计意图文档当作核心资产来投资；组件实现层可以接受"按需生成、用完即弃"，但规范层必须中心化、可版本化、可被模型读取。

📎 来源： [InfoQ · Daniel Curtis] [Figma(@figma)]
趋势二

AI 生成设计从"出图"走向"可编辑图层"：可控性成为新评价标准

今天的几条线索指向同一个变化：AI 设计输出的评价标准，正在从"好不好看"转向"可不可控、可不可编辑、忠不忠于意图"。inclusionAI 的 Ming Image 0.1 Design（6B 开源图片模型）登顶 AA UI/UX Design 开源第一，关键不是画得更漂亮，而是生成后真的能改——它能把一张设计稿拆成一层一层带语义的完整 RGBA Layer（人物是人物、标题是标题、贴纸是贴纸、背景是背景），继续往后修改，而不是"生成一张 PNG 然后跑路"。Black Forest Labs 的 FLUX 3 主打像素级多轮编辑，支持最多 10 张参考图、bounding box 布局与 4K 输出。国产的 MiniMax M3.1 Flash Preview 也用"同题交卷"的方式，在前端作品的视觉风格与动效编排上和 Opus 5.5 正面比较。

更能说明"新标准"的，是 Arena 的一项 reward 设计研究：他们发现人类偏好 reward 是必要的，但并不充分——偏好模型会奖励那些"看起来讨喜、却丢了细节、塞进未要求内容"的输出，即 reward hacking。因此他们改用复合 reward：约 560 万对人工投票训练的 Bradley-Terry 偏好模型 + 用视觉语言模型校验自动生成 checklist 的忠实度奖励 + 覆盖显性与隐性意图的约束奖励 + 针对乱码文字、过度写实漂移等失效模式的反 reward-hacking 规则。

  • "可编辑性"成为设计级交付物：图层化、语义化、可回改，直接决定了 AI 能否进入真实设计流程，而不只是做素材。
  • 评价维度升级：从"好看"到好看 + 忠实 + 守约束 + 不取巧——这套思维同样适用于人类设计师的评审。
  • 参考图成为规格：用参考图（含颜色、字体、材质、留白规则）而非文字描述来控制风格，稳定性更高——"参考图即设计规范"。

实践建议：在设计评审 checklist 里显式加入"忠实度"（是否丢细节）与"约束遵守"（是否夹带未要求内容）两项，而不仅看美观度；把参考图、品牌规范与反面示例一起作为生成输入。

📎 来源： [Ding(@dingyi)] [Justine Moore(@venturetwins)] [爱范儿] [Arena.ai(@arena)] [宝玉(@dotey)]

产品体验点评

1 正 1 反，两个案例
正面案例

华为 Mate 90 Pro Max：工业设计语言从"机械手表"转向"篮球鞋"

硅星人 Pro 的体验文捕捉到一个清晰的品牌体验转向：过去几代 Mate 的共同点是"标准的大尺寸、圆形影像模组、克制配色，和一种很难和'年轻'联系起来的商务旗舰气质"——像在选一块机械手表。而这一代给出的答案不是推翻 Mate，而是先让 Mate 变得更好玩，这一代"开始有点像选一双篮球鞋"。最直观的变化来自背后的相机模组：华为在星环设计基础上引入名为"钇晶宝石"的新材料，由高纯航空级原料与含钇稀土复合粉末经 1800℃ 高温、180MPa 高压烧结，再经研磨、镜面抛光、纳米光学镀膜等工艺制成。

案例解读：当手机正面差异越来越小，旗舰系列靠什么在第一眼产生新鲜感？华为选择"用材质与工艺讲故事"，把原本稳定的商务资产往"好玩、可玩味"的方向拉动。对产品与设计团队，这是一个关于品牌体验资产如何安全演化的样本——不改变核心识别（星环、Mate 气质），而是通过材料叙事注入新鲜感，既保留老用户的安全感，又争取年轻用户的注意力。

📎 来源： [硅星人Pro]
反面案例

"AI 垃圾"正在稀释信任：当"活人感"变成稀缺资产

创业邦转载的果壳文章剖析了一个平台侧的体验危机：最先拥抱 AI 的内容平台，反而最先被 AI 内容反噬。数据很具体——大众点评去年处置了 1161 万条 AI 生成评价；法国流媒体 Deezer 每天进入平台的新歌里接近一半是 AI 生成，且几乎没有真人听众；LinkedIn 上线"看起来像 AI 垃圾"举报按钮后，"AI 职场文章"浏览量因此少了四成。文章的核心判断是："互联网上 AI 垃圾越多，真人越值钱"，用户开始追问"这里面有多少是你？"——内容越完整、越顺滑，反而越需要自证不是 AI。

案例解读：这是一次典型的"增长指标"与"体验指标"背离。用 AI 拉高内容供给量，短期看是活跃度，长期却在摧毁平台最具价值的资产——可被感知为真人参与的真实感。当用户不再信任评论、歌单和推荐，所有依赖这些信号的体验（发现、决策、社交认同）都会同步崩塌。实践建议：在产品指标里为"内容真实性"设立显式的可测量项（AI 内容占比、举报量、真实互动率），并把"活人感"当作需要主动设计的体验要素，而不是事后打补丁的治理问题。

📎 来源： [创业邦]

研究方法论

新方法 · 新工具
方法

用 AI 生成的"说唱对战"辩论，支持多元视角获取与观点形成

arXiv 论文 2610.01179 研究了一个很有用户研究味道的问题：如何低成本地帮人"获取多元视角、形成有依据的观点"。传统正反方辩论虽然有效，但需要大量时间和人力资源，限制了可及性。研究者的方案是把辩论做成简短、有节奏、有韵脚的 AI 生成 rap battle——既保留了论点交锋的结构，又因为形式有吸引力而更易被接受。对研究员而言，这是一种可扩展、低成本、能激发用户表达立场与理解对立观点的研究刺激物（stimulus），尤其适合对"议题认知""态度形成"类研究，比干巴巴的问卷更能让被试投入并暴露真实倾向。

📎 来源： [arXiv:2610.01179]
方法

软硬结合产品的公开需求征集：少数派"电话辅助驾驶"问卷

少数派正在探索一套"软硬结合"的电话辅助方案：硬件磁吸在手机背面、通过蓝牙获取通话语音，本体带按键、屏幕和振动负责快捷操作与状态反馈，配套 App 用于查看实时对话、译文与资料提示。为了解需求，他们公开了一份需求问卷，参与者识别二维码填写，并从中挑选 40 份"用心回答"各送出 50 元京东卡（共 2000 元）。这是一个清晰的产品早期的用户共创案例：先用低成本的问卷验证"电话占用精力"这一痛点的分布与强度，再决定产品形态。

方法启示：硬件产品的用户研究面临"无法快速迭代原型"的约束，公开问卷 + 需求征集是低成本前置验证的合理手段；而"挑选用心回答给予激励"的设置，本身就是在激励高质量样本而非单纯的数量——这是问卷设计中常被忽视的一点。

📎 来源： [少数派]
数据

SWE-chat v2：真实场景里"人如何与 AI 协作"的行为数据

Stanford AI Lab 转发的 SWE-chat v2，是目前最大的"真实场景下人与 coding agent 交互"数据集：23 万条 prompts、1.8 万个 session，来自真实开发者在野外的使用，已开放于 HuggingFace。它的价值不在模型能力，而在行为观察——人们实际上是怎么提问、怎么纠正、怎么放弃、怎么与 agent 分工的。elvis 的观察也指向同一处：面对 Claude Code Mods、DeepSeek Harness、Pi Durable，开发者越来越需要把 agent 打磨成适合自己工作流的样子，"通用 harness 不够用"。对 HCI 与用户行为研究者，这类数据集是研究"人在环中（human-in-the-loop）"真实协作模式的难得素材。

📎 来源： [Stanford AI Lab(@StanfordAILab)] [elvis(@omarsar0)]

🦇 Notion AI Personalization：个性化成为显性卖点

Notion 用一条极简的层级路径（Preferences > Notion AI > Personalization）暗示正在上线 AI 个性化设置。信号意义在于：AI 助手正从"所有人用同一个"走向"按人定制语气、风格与行为"，个性化从隐性算法变成用户可以主动配置的产品能力。

[Notion(@NotionHQ)]

🧠 数据库做"统一记忆"：跨工具的记忆层体验

有用户把 Notion 数据库当作所有 AI 平台的统一记忆，连接 Grok Bot、Claude Code、Grok Build、Meta Muse，让它们自主写入"值得记住的事"，并知道自己在和其他 AI 共享这份记忆。这提示一个新兴体验命题：当用户同时使用多个 agent，"记忆在哪、谁能读到、如何保持一致"会成为新的用户心智负担，也可能催生"记忆管理"这一产品品类。

[Notion(@NotionHQ)]

🪆 Personal Agent 正在分化：大众低门槛 vs 专家自构建

歸藏观察到 Agent 出现两类分化：一类是面向 C 端非专业用户的 Personal Agent（如 Muse、dot），上手门槛极低、纯对话即可完成任务，还配远程虚拟机；另一类是面向专家的"极致自定义与自我构建"，用户用自然语言给自己搭工具、甚至改 Agent 界面。两者对体验设计的要求截然相反——前者要"藏起复杂度"，后者要"暴露可组合性"。这两条路线如何各自设计，是值得持续跟踪的产品问题。

[歸藏(@op7418)]

🖥 Imbue Studio：重新想象"个人计算"的样子

Imbue 发布 Studio，用一句"个人计算的未来应该是什么样？我们把它做出来了"来定义产品。虽然细节尚少，但作为对"个人计算形态"的正面提问，它是观察操作系统级交互范式如何被 AI 重写的早期信号。

[Ding(@dingyi)]

🎞 设计工作室的焦虑：3 个提示词做出动态设计

一位设计工作室创始人坦言，Opus 5.5 在动态设计和产品发布视频上的表现已经"强得惊人"，而这段让他焦虑的视频只用了 3 个提示词。对动效设计师与品牌团队，这是"AI 正在侵蚀高价值视觉产出"的直接体感信号，也倒逼设计团队重新定义自己的差异化价值（策略、审美判断与可控性）。
