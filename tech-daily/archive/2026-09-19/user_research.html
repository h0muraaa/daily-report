Key Insights

豆包座舱助手：目的地是在一屋子人的否定和改主意里长出来的

《晚点 LatePost》在发布前拿到一辆仍处于测试阶段的荣威家越 07 做了实测。流程很「不产品」：先让豆包找拍照好看的地方，随即改成文艺街区，接着问停车和吃饭，最后启动去餐厅的导航——整个过程没有一条完整的指令，目的地是在几个人的否定、补充和改主意中逐渐形成的。关键的体验证据发生在几轮插话之后：它仍然记得目的地、记得被否定过的选项，也记得还有哪件事没处理完。

能做到这一点的原因是架构选择：豆包座舱助手基于大模型「理解—执行—反馈」的闭环，而不是基于规则的槽位调用。火山引擎副总裁杨立伟给出的年底目标是「像人一样思考、基于目标持续地办事」。首款搭载车型荣威家越 07 将于 9 月 21 日开启预售。

对研究员的启示：车载助手的传统交互原则是「用户需要精确发出功能指令」——上千个功能从实体按键搬进触摸菜单后，语音和触屏并列成为主要入口，但心智模型没变。豆包这次试图把要求反过来：让汽车适应人的表达、习惯和不断变化的需求。这等于把一个全新的可用性命题推到台前——当用户可以中途改变主意时，你要测量的不再是「指令识别准确率」，而是「意图达成率」和「被放弃选项的记忆正确率」。

Hinge：不到 15% 的用户付费是刻意设计的，「免费体验是神圣的」

Hinge 首席产品与技术官 Ben Celebicic 在 Product School 的分享里把付费模型讲得非常清楚：不到 15% 的用户为任何东西付费，而这是刻意为之。第一条原则是「免费体验必须神圣」——它必须被设计成让每个人都能获得成功，付费只用来打破限制、或者让人更快获得成功。第二条是「只对不能免费给出的东西收费」：因为免费给会破坏生态，或者在稀缺性本身就是价值的情况下让这件事失去意义。

他的类比是一个好派对：每个人都想来，每个人都想跟别人说话，房间里人越多派对越好——所以破坏生态的「免费赠送」最终会伤害所有人的体验。

同一系列的另一则分享里，Celebicic 还解释了一个反直觉的组织事实：信任与安全团队占 Hinge 全公司三分之一的人力，直属他管理，长期投入于识别虚假用户和恶意行为者。而且支撑这件事的并不是生成式 AI，一直是传统的机器学习模型——因为产品的目标是让人离开平台、走进现实生活，就必须让用户尽可能真实：如果你展示的样子和真实自己完全不同，你在现实里也不会成功。

对研究员的启示：把「转化率越高越好」当作默认目标，等于悄悄把用户目标换成了平台目标。Hinge 的做法提供了一个反例框架——先定义「用户在这里成功是什么样」，再决定哪些环节可以收费。

Claude Projects 改版：Agent 的交互设计，把 Slack 的 Thread 抄了进来

Anthropic 重做了 Claude 的 Projects，先在 Claude Code 里上线测试版。旧版的 Project 是一个文件夹——放资料和指令，对话仍然是一个个分开的；新版变成一个持续的主对话：你在里面说要做什么，Claude 自己拆任务，分给多个并行的 Thread 去干，检查结果后汇总给你。关掉电脑，活儿还在云端继续跑。

宝玉用 Slack 的 Thread 来解读这个设计：主频道里一条任务只占一张卡片（比如「11 条回复」），点开右侧面板才是完整过程——查到问题、提出修复 PR、PR 合并、Thread 标记为「已解决」，需要时可以重新打开。他以 Boris Cherny 晒出的截图为例说明了这个层次感：主对话丢一张截图说「启动 cc cli 总弹这个提示」，Claude 开一个 Thread 去查，过程与结论都收在 Thread 里。

对研究员的启示：这是「把过程折叠、但不丢失」的一次标准实践。聊天式 Agent 长期缺的就是信息层次——所有内容线性堆在一条时间线上，过程细节会把主任务淹没。Thread 形态让用户始终知道「主线是什么、细节去哪找」。值得做 Agent 产品时直接借鉴，也值得在可用性测试里专门验证：用户会不会主动展开 Thread 看过程？折叠后他们对系统「是否可靠」的判断会不会变弱？

把界面的「完成感」写成 Agent 能执行的规则：Craft Design Engineering

meng shao 分享了一份由 @heyimgustavo 开源的设计工程概念集 Craft Design Engineering。它把界面「完成感」的细节——等宽数字、光学对齐、嵌套圆角、克制的 hover——提炼成精确可执行的规则（含代码与推荐值），让 coding agent 在写 UI 之前先查阅遵循。换句话说，那些过去只存在于资深设计师直觉里、只能靠评审「感觉不对」来传递的东西，第一次有了可交付的文本形态。

它的双形态架构尤其值得注意。内容源是 content/ 下按语义分组的 MDX 文件（typography、color、layout、motion、sound、craft、data），这是唯一的编辑入口；配套网站用 Next.js + Tailwind 为每个概念提供可交互的 live demo——说服力来自「你亲手感受差异」，而不是看截图；Skill 则由构建脚本从 MDX 自动生成，先降级标题层级、计算锚点，再按语义聚合成参考文件，只替换标记之间的概念索引，手工编写的「使用协议」原样保留，且只打包已上线的概念，草稿自动排除。

对研究员的启示：设计规范第一次有了「给机器执行」的交付形态，而且它的分发链路是可审计的——内容源、网站、Skill 三者同源。这意味着团队的设计判断可以被复用、被版本化、被 diff。实践建议：下一次设计系统评审时加一个检查项——你的规范里有多少是对人描述感觉的（「按钮要有呼吸感」），有多少是对机器描述约束的（间距阶梯、色彩 token、组件状态枚举、可用性规则）？前者无法被 AI 复用。

Google 用大模型生成互动练习，但把最终决定权留给了老师

Google Research 公布了一项名为「学习互动练习（learning interactives）」的研究实验：老师只需输入学科、年级和教学主题，Gemini 就自动生成一个带 5 个递进关卡、分层提示、解法和反馈的网页互动模拟。为了让生成出来的界面真正具备教学价值，研究团队把构建流程拆成四个前后衔接的阶段，在文本规划、关卡设计、代码实现与教学辅导之间筑起一道道防护栏。

更值得研究者关注的是人的位置。整套流程中教师始终主导且把关：由老师发起请求（含学科、年级、主题，可附加额外要求）→ AI 生成具体学习目标，交给老师审核并自由修改 → 针对通过的目标，系统生成 5 个候选模拟，由老师挑出最符合教学意图的一个（在 12 位教师的实测研究中，则先由内部评审挑出最佳版本再呈现给老师）→ 新生成的练习最终必须经老师审核通过，才能进入公开库。

对研究员的启示：这是一个完整的「AI 生成 + 人在环」范本。它没有把 AI 描绘成替人工作的工具，而是把人的判断设计成流程里不可跳过的节点；同时用内部评审做预筛来降低老师的评审负担——让人做他最擅长的判断（这个练习是否符合我的教学意图），而不是让他做筛选劳动。做智能问卷、访谈分析这类 AI 辅助研究工具时，这套分层把关的结构可以直接迁移。

设计趋势洞察

Design Trends

趋势一

交互正在从「聊天框 + 一次生成」走向「可打断、可操作、持续变化」

Founder Park 观察到一件很能说明阶段的事：过去几个月，一批看起来颇为相似的 Demo 密集出现。用户不再只是输入一句 Prompt、等待模型生成一段完整视频，而可以在角色说话时打断，可以点击、拖动屏幕里的物体，也可以打开摄像头让 AI 看到自己的表情和动作。生成出画面不代表着结束，它还会根据用户的下一次输入继续变化。

随之而来的是命名的混乱——交互模型、互动模型、交互视频模型、交互世界模型，各家叫法相似又不同，看起来和大众已熟悉的「视频模型」有关系，又和今年备受关注的世界模型存在路线交集。即使最终展示出的体验差不多，底层实现、模型输出和产品路线却可能完全不同。Founder Park 的判断是：混乱本身就是一种信号。当一个方向还没有统一的定义，通常意味着它刚刚从不同的路径上被同时发现。

他们把几支团队放在一起观察：Loopit、Reverie AI、SigmaZ AI 都把「实时交互」放在核心，有的直接生成音视频像素，有的把 Coding 与视觉生成结合，有的先做模型、有的先把应用推向用户。这股变化也在扩散到原本以视频生成为主的公司——Runway 在传统视频生成之外陆续推出实时角色 Characters、可交互世界 GWM Worlds，以及直接生成交互界面的 Solaris；Vidu 则在面向传统视频生成的 Q 系列之外，把 S 系列单独定义为 Real-Time Generation Model。原本散落在数字人、视频、游戏和 UI 里的「实时交互」，正在逐渐成为一条被单独命名和训练的模型能力。

对研究员的启示：交互设计的对象正在从「一次性的输出」变成「一段持续可干预的过程」。可打断性、状态保持、错误恢复、以及「用户如何知道此刻自己能做什么」——这些实时系统的经典可用性问题会重新变成核心议题。今天 Claude Projects 的 Thread、豆包座舱助手的多轮记忆，本质是同一个方向在生产力工具和车载场景里的落地。建议把「打断之后系统是否还能保持目标」列入下一代对话产品的测试清单：它测的不是识别率，而是状态一致性。

趋势二

设计规范正在「技能化」：从给人看的文档，到给 Agent 执行的规则

今天的 Craft Design Engineering（见「今日要点」第 4 条）和 Google 的学习互动练习，表面上分属设计工具与教育研究两个领域，但结构上高度同构——两者都在把「判断标准」从人的脑子里搬出来，变成流程里的显式节点。前者把界面完成感变成 agent 写 UI 前必读的规则文件，后者把教学意图变成老师必须逐关审核的目标列表与候选集。

它们还有另一个共同点：都选择让内容源与分发形态解耦。Craft 用同一份 MDX 同时生成网站 demo 和给 agent 的 Skill，只把已上线概念打包；Google 则让同一套学习目标派生多个候选模拟，再由人挑选。这意味着规范和产出之间是持续校准的关系，而不是一次写死。

给 UX 团队的实践建议：把「设计系统是否可被机器消费」当作一个独立维度来评估。可行的第一步是做一次盘点——把现有规范拆成「感觉描述」和「约束描述」两栏，后者才是可以被 agent 执行、被测试断言的部分。第二步是考虑把规范做成单一内容源、多形态分发（人看的文档 + 机器读的规则），这样改了源，两边同时更新。

要注意的风险：规范写得越死，AI 产出的同质化越严重。Craft 的做法提示了一个解法——把「使用协议」（何时该遵循、何时该打破）作为手工维护的部分原样保留，而不是让脚本一并覆盖。留给判断的空间，本身就是设计规范的一部分。

产品体验点评

Product UX Review

案例一：豆包座舱助手——当交互目标从「执行指令」变成「持续办事」

「大模型上车」已经不算新闻，但多数所谓上车，本质还是把原来的语音助手变聪明了一点。人人都是产品经理的拆解很精准：以前你说「空调调到 23 度」，它帮你调空调；现在你说「我有点冷」，大模型理解了一下，最后还是帮你调空调。体验当然变好了，但 AI 主要负责的仍然是一件事——听懂人话。

豆包座舱助手想往后走一步：不只是「听懂」，还要自己想办法完成。它直接参与汽车的「感知—决策—执行」——实时感知数百种车辆信号，再去调用车控、导航、辅助驾驶、车载娱乐等数千个整车原子能力。典型场景是：你说「孩子准备在后排睡觉了」，理论上 AI 应该自己判断要不要调后排温度、要不要降低音乐音量、要不要调整座椅、要不要关闭部分灯光。以前这是四个独立按钮，以后可能变成 AI 自己组合这些按钮。

这件事的发生有相当厚的铺垫：火山引擎今年 4 月公布的数据是，搭载豆包大模型的智能汽车已超过 700 万辆，覆盖 50 多个汽车品牌、145 个车型；特斯拉中国 7 月已通过 OTA 把豆包大模型推送到 Model 3、Model Y、Model S、Model X。所以真正的变化不是「豆包上车」，而是它从藏在车机后面当模型，开始走到前台，变成一个真正能干活的 Agent。

UX 视角的点评：这个案例的技术亮点是模型能力，但体验上的创新点其实只有一个——把「任务状态」提升为一等公民。要支持「几个人边聊边改主意」，系统必须在长会话里维护一个用户可见、可以纠正的目标状态，并且能区分「这个选项是被否决了」和「这个选项还没讨论到」。由此带来一串全新的研究问题：如何测量意图达成率而非指令准确率？用户怎样知道 AI 记住了哪些被否决的选项？当 AI 主动改变车内状态（降音量、调座椅）时，如何设计告知与撤销？这些都不是单次可用性测试能回答的，需要做长会话的任务日志分析和访谈式回溯。

案例二：Dashboard 把 iPad 变成 HomeKit 控制屏——「可定制」与「开箱即用」的取舍

少数派本期《派评》里最值得设计团队一看的是 Dashboard。它是专为 iPad 打造的 Apple Home 控制屏，同时也支持 iPhone，把家庭设备、摄像头、天气、日历集中到一个可自由排列的仪表盘上，适合放在玄关、客厅或卧室作为家里的固定控制中心。

关键在于它没有照搬 Apple「家庭」的界面：每个设备都被变成一个可以自由调整的磁贴，长按拖到面板任意位置，用右下角手柄调整大小，不同设备可以拥有完全不同的尺寸；iPad 端支持分页，iPhone 端是单页滚动布局，磁贴也可以直接隐藏。典型配置是把客厅摄像头做成最大磁贴，下面安排天气、日历和时钟，右侧摆灯光、空调和窗帘。它还能接入未加入 HomeKit 的 RTSP 摄像头（支持 H.264 与新增的 H.265，兼容海康威视、大华、Reolink、Axis 等），内置局域网摄像头搜索，对支持 ONVIF 的设备可自动寻找视频流地址。

UX 视角的点评：这是教科书式的「为单一场景重新设计界面」。Apple「家庭」为通用性优化——逐层导航、统一磁贴尺寸，任何设备上都成立；Dashboard 为「固定在墙上、被反复使用的共享控制屏」优化——一屏全览、空间位置固定。核心洞察是：当屏幕位置固定、用户反复看到同一个布局时，空间位置本身就是最强的记忆线索，你可以几乎不看屏幕就点到客厅摄像头。对比之下，「家庭」App 里每层导航都要重新寻找。

代价也清晰：可定制性与可发现性是此消彼长的。新用户面对的是一块需要自己搭建的画布，认知负担反而更高。这提示了一个通用的设计解法——为个性化产品提供「预设模板」作为首次使用的起点（如「玄关控制屏」「卧室面板」），让用户从改而不是从零开始。这个案例也值得在可用性测试里做对照：同一批用户分别用「家庭」和 Dashboard 完成同一组任务，测任务时间与空间记忆保持率。

顺带一提，本期《派评》另外几个 App 也值得体验研究关注：Adaptive Theme（更聪明的自动深浅色模式切换）、Voxt（基于 AI 的语音输入和翻译工具）、Moment Pro Camera II（慢快门、拍摄辅助与更自由的相机界面）——尤其最后一个，相机这类高度成熟的界面还能被重新设计，本身就是很好的界面创新素材。

把「洞察产出后没人行动」这个断点补上：从流失漏斗到团队行动方案的闭环

OpenAI · ChatGPT Work 演示

OpenAI 发布了一段 ChatGPT Work 的演示。工作流的起点是研究员非常熟悉的一对证据：采纳漏斗里的下跌告诉你「该往哪看」，客户反馈帮你「查为什么」。演示展示了用法数据与来自 Slack、Google Drive 的反馈如何共同支撑建议，再由 ChatGPT Work 起草一份 Slack 更新，供人工审核后发布。整个演示走的是从「一个管理层的提问」到「建议的团队行动」的路径（演示使用的是合成数据，实际效果需在自己的数据上验证）。

对研究实践的价值：用户研究最常被诟病的断点，从来不是「洞察不够深」，而是「洞察产出后没人行动」。这个工作流把观测指标 → 质化证据 → 行动草案 → 人工审核 → 发布串成了一条链，并且保留了人工审核节点。对研究员来说，值得做的不是立刻采购工具，而是先做一次自查：我们现在的洞察，是在什么环节失去动能的？是没有可量化的起点（漏斗数据），还是没有可归因的证据（用户原声），还是没有人愿意写那份「行动草案」？这三段的断裂点不同，需要的解法完全不同。

人机协作研究中的「把关者」设计：四阶段护栏 + 12 位教师实测 ⭐

Google Research · 学习互动练习（learning interactives）实验

这个实验值得研究员认真读的，不是它的生成能力，而是它如何把人的判断设计成流程的必经节点。四个阶段（文本规划、关卡设计、代码实现、教学辅导）之间设有防护栏，每一关都要过人的审核；而 12 位教师的实测研究中，最有价值的一处细节是——系统先由内部评审从 5 个候选模拟里挑出最佳版本，再呈现给老师。

这是一个典型的「降低评审负担」的设计：让人做他最擅长的判断（这个练习是否符合我的教学意图），而不是让他做筛选劳动（从 5 个差不多的版本里挑一个）。用户的注意力是最稀缺的资源，把它花在哪里，决定了协作型产品是「帮人」还是「耗人」。

给研究员的实践建议：如果你正在用 AI 生成问卷、生成访谈提纲、或做自动化访谈分析，先问一句：中间的哪些环节是我可以减少用户选择数量的？比如让模型先自评并给出 top 候选、把明显不合格的版本挡在用户面前。同时要警惕反面：预筛本身会引入评审者的偏好。Google 的做法是把预筛放在 12 人实测阶段（为了研究效率），而面向真实教师的正式流程仍是老师自己从候选中挑——这个区分很重要，值得在报告里明确写清楚。

一个新的研究命题：当 Agent 替你花钱时，「授权」如何被用户理解

硅谷101 · 2026 Inclusion·外滩大会主论坛圆桌「当 Agent 成为交易主体」

这场圆桌的阵容说明问题已经被产业界认真对待：蚂蚁集团 CEO 韩歆毅、万事达卡首席产品官 Jorn Lambert、OPPO 高级副总裁兼首席产品官刘作虎、阿里巴巴集团首席科学家周靖人。讨论的背景是 AI 交易正沿两条线同时展开：一条是 Agent 帮人完成任务（今年 6 月上线的 AI 版支付宝，一句话就能打车、点咖啡）；另一条是 Agent-to-Agent（两个月前 Mastercard 发布了专为机器间支付设计的网络服务）。

当 Agent 从对话走向办事、从推荐走向交易，「信任」成了绕不开的关键词，而圆桌把它拆成了一串具体的用户问题：它替你花出的每一分钱，真的经过你授权吗？发起交易的 Agent 究竟是谁？它的支付权限有多大？出了问题又该由谁负责？这些问题围绕授权、身份、权限、责任层层展开，决定的正是我们距离「把钱包交给 AI」还有多远。

对研究实践的价值：这是一整类目前尚缺方法论的信任研究问题。用户对「我点了同意」和「Agent 代表我同意」的心理边界在哪里？授权是一次性动作还是一种持续状态？出错之后，用户会把责任归给人、产品还是模型？做支付、订阅、自动化类产品的研究者，值得把这个议题列为下一代用户信任研究的核心——传统的信任量表（如对系统的信任度打分）捕捉不到「授权随时间衰减」这类动态过程，需要日记研究或情境实验来补。
