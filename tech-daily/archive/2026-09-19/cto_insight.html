今日要点

1Jev 上线第二天：刷新 Vercel 采用纪录，开源复刻 48 小时内落地

TypeSafe AI 的决策模型 Jev 在发布次日从"刷屏"转为"被接入"。Vercel 官方数据显示，Jev 是 AI Gateway 历史上被采用最快的模型——首日即触达约 13% 的团队，是 GPT-5.6 家族的 2 倍、Fable 5.1 的 6 倍。CEO Guillermo Rauch 给了一个比数字更重要的判断：Jev 的采用曲线"下游是'AI 太贵太慢'的集体情绪"——人们急于优化成本，并希望把 AI 放进更多地方。定价上每百万输入 token 0.042 美元、输出免费，创始人 Diogo Almeida（InstructGPT 与 RLHF 的关键参与者）的口径是 20–200 倍速度、40–400 倍成本优势。

生态信号同样密集：Latent.Space 统计发布两天内出现 6 个复刻版本（其中一个 Laya 用 421M 参数的 ModernBERT-large 编码器加两层 transformer 打分）；Bespoke Labs 发布"Open Jev" Bespoke Nimble，数据、权重、训练配方全公开，用 Qwen3.5-9B 做 LoRA（rank 16、单 epoch、约 2676 条合成样本）两天完成，在快速结构化决策任务上逼近 Jev。LangChain 的 Harrison Chase 说 Jev 引发的内部 demo 与探索"超过任何一次模型发布，而且差距很大"；OpenRouter 则用一句话定位品类："软件开发大多是决策序列，Jev 比 LLM 便宜快 10 倍。"

2OpenAI 反超 Anthropic：Astra 两周吃掉 13% 企业支出，「减速」与「踩油门」只隔七天

据路透社独家与 OpenRouter 数据，9 月 3 日发布的 GPT-6 Astra 在两周多内拿下约 13% 的企业 AI 支出份额，而 Anthropic 的 Fable 系列只有 8%；OpenRouter 的周度 token 份额显示 1–6 月 Anthropic 稳居 50% 以上，Astra 上线后 9 月第一周 OpenAI 升至约 65%、Anthropic 降至约 35%——这是两年半来 OpenAI 首次反超。Anthropic 9 月 1 日刚发 Fable 5.1 并主动把缓存读取价格砍 75%，仍未能稳住企业客户，随后被曝正考虑提前发布新模型。节奏上的反差更刺眼：9 月 12 日 Dario Amodei 发长文公开呼吁"放慢 AI 发展的速度"，七天后就传出提前发模型的消息。

第三方压力还在叠加：谷歌下一代旗舰 Gemini 4 Pro 疑似以马甲身份在 Arena 偷跑，流传的测试图显示其在 DeepSWE v1.1 得 88%、Terminal-bench 2.1 得 95.3%、OSWorld 2.0 得 86.8%，均高于 GPT-6 Astra 与 Fable 5.1（分数暂无法独立验证）。资本面同步承压，Gary Marcus 转述 WSJ：Anthropic 的 IPO 推迟到 11 月，OpenAI 推到 2027。治理侧，Anthropic 宣布与埃森哲合作做前沿 AI 独立评估、双方未来五年各投至少 10 亿美元，但被批评"把已有商业合作关系的公司选为独立评估方"恰恰削弱了可信度——同期它今年第三次公开指控 7 家中国公司实施"工业规模蒸馏"。

3算力标尺换代：从「多少 FLOPS」变成「一个机柜能跑多少个 Agent」

InfoQ 报道了英特尔 8 月白皮书中一个值得认真对待的立场：数据中心优化的关键不是提升理论参数值，而是在实际应用场景下、满足延迟承诺时能维持多少 Agent 的任务量——"去计算数据中心的实际工作量，而不是理论的性能上限"。背景是谷歌调研显示近 83% 的企业高管认为基础设施需要为 Agent 时代重新调整；2026–2027 年中国企业场景活跃 Agent 数量单年同比增长超 200%，2031 年预计达 3.5 亿个。现有数据中心基本按"大模型单次推理吞吐"设计，与 Agent 高频、突发、有状态、工具调用穿插的工作负载并不匹配。

硬件侧华为在全联接大会上给出国产答案：统一互联总线协议"灵衢"（UnifiedBus）把 CPU、NPU、DPU、DDR、SSD 统一互联，单集群可支持 100 万颗 AI 处理器，10 万卡集群的 MFU 从约 20% 提升到 35%，同期发布昇腾 960 芯片、昇腾 960 超节点与 OceanStor M900 AI 记忆存储——其判断是通信而非单颗芯片成为 Agentic AI 算力的胜负手。推理平台侧，CoreWeave 的一个观察解释了输入缓存为何远低于新 token 定价：Agentic 请求中 80%–90% 的输入与上一轮请求完全相同，而 prefill 是推理栈里最贵的部分。

4优化点从模型权重转向 Harness：智谱跑通生产级 RSI，NVIDIA 用 AI 自动找改进点

智谱披露了国内大模型厂商首个跑进生产环境的递归自我改进（RSI）案例：由 GLM-5.3 驱动的 Infra Agent 完成了 GLM-5.3-Flash 推理基础设施的设计、调试与优化，实现模型对自身运行系统的反向改进，在十万卡集群上不到两周把吞吐量提升到 3 倍。NVIDIA 的 SoL-Pi 论文把同一思路系统化——不改模型权重，而是优化 harness 层：用自动化研究流水线跑了 152 个研究方向（分六大家族）、535 个可执行训练环境、3000+ 次运行、60000+ 次智能体-环境交互，最终只有 4 个机制存活（约 40 选 1 的淘汰率），token 消耗降低近一半、EdgeBench 上 API 成本降约三分之一，并在 GPT-5.6 Sol 与 Opus 5 上匹配基线 harness。论文的关键论点是"过程性浪费与任务无关，一旦优化，收益可迁移到所有任务"。

企业侧有两个可直接借鉴的样本。LinkedIn 用 MCP 构建组织级上下文层（Contextual Agent Playbooks and Tools），向编码 Agent 直接供给流程记忆、代码检索与 runbook，带来 20% 生产力提升且可靠性零损失。小红书 Muse 则直面"AI 写代码飞快，为什么交付没有变快"这个真问题：设计规范、工程资产、跨仓上下文、安全检查与协作断点，会把编码阶段省下的时间重新消耗掉——因此必须把"会生成代码的模型"变成真正能交付、兜底和恢复的研发系统。

深度分析

一、决策层经济学：Jev 之后，Agent 的成本结构该怎么重算

用旗舰模型回答"走哪条路"这种二选一问题，是当前 Agent 架构里最普遍、也最容易修正的结构性浪费。

把决策下沉为专用原语

Jev 只做三类事：布尔判断（要不要联网、要不要退出循环）、枚举选择（走 fast 还是 plan、调哪个模型、分发给哪个 Bot）、候选打分（给多个选项打分再排序）。OpenRouter 的定位一语中的："软件开发大多是决策序列。"定价上每百万输入 token 0.042 美元、输出免费，这是把"决策"从生成式模型的计价体系里彻底剥离出来的结果——输出不计费，因为它本来就不生成任何自由文本。

「不生成字符串」是架构级选择，不是产品噱头

meng shao 对创始人演讲的拆解给出了这个设计的技术根据：奖励模型存在类似 GAN 的不对称性——模型的不自信很容易被奖励模型识别并惩罚，于是模型学会丢弃不确定的模式、假装自信，幻觉是偏好优化的内在产物。Jev 的回应是釜底抽薪：输出结构与取值预先定义，类型错误在数学上不可能发生，每个输出附带"认识论上诚实"的概率。落到产品逻辑上是一句话："如果一个模型 95% 的时候做对，且它能告诉你自己何时处于那 5%，这个任务就可以被自动化。"开发者设阈值，高置信自主执行、低置信上报人工——人在 loop 中从被迫的纠错者，变成可选的开关。这个转变对企业流程的意义，远大于成本节约本身。

48 小时内的两种复刻路径，说明了品类的护城河在哪里

Bespoke Nimble 的做法值得完整记录：在 Qwen3.5-9B 上做 LoRA 微调（rank 16、单 epoch），数据全部合成、约 2676 条、覆盖 10 个类别。其核心创新是最小差异样本对——构造近乎相同的样本对、只改一个"焦点事实"（不超过 8 个词）使正确标签翻转，迫使模型学会"哪些证据真正应该改变决策"，作者称"calibration is implicit"（校准能力是隐式获得的），从而绕开了对带概率标注数据的需求。推理侧采用并行约束解码，每个选项映射到单个 token，直接读取 logits 做 softmax，根本不"生成"文本；Mac 上用 MLX 把共享上下文预填充一次、所有字段并行打分。整个项目两天完成，未从 Jev 蒸馏，版权与学术上都干净。

对照 Laya 的做法（421M 参数、ModernBERT-large 编码器 + 两层 transformer 打分、PPO over sequence embeddings），可以看到两条复刻路线都以百 M 到十 B 级参数为起点。含义很清楚：决策模型的技术门槛低于生成式前沿模型，开源复刻能在两天内逼近。这个品类很难在模型层形成长期壁垒，价值会流向数据配方、阈值策略与 harness 集成——也就是工程侧，而不是模型侧。

为什么是现在：账单与份额同时到达拐点

成本压力已经到了必须重构架构的程度。Vercel AI Gateway 当日的数据是一个标志：开放模型占 token 总量的 78.4%，闭源仅 21.6%；按支出排名，Moonshot AI 与 DeepSeek 分列第 3、第 4，加上 Z.ai 三者合计超过 OpenAI（第 2）。需要留意口径——这是主要发生在美国的模型推理支出，不等于直接流向开源权重实验室的收入，但它清楚说明了企业侧的实际选择。FriendliAI 的实测给出了同量级的证据：同一个 coding agent、同一个建塔防游戏任务，开源权重方案便宜约 5.5 倍，且两者都达到可用水平。

Gary Marcus 转述 Gavin Baker 的观点则点出了这对产业结构的意义：开源模型持续抢占份额，如今花在开源模型上的钱已超过 OpenAI，这把利润从模型层转移到了基础设施层与应用层。Marcus 的反问同样值得记住：当生成式 AI 变成近乎零毛利的公用事业，CoreWeave、Oracle、NVIDIA 这些把身家压在算力上的公司怎么办。

对 CTO 的含义：把"每次循环都要调用旗舰模型"当作架构缺陷来修。先做一次调用画像——按循环位置统计调用量与单价，通常会发现绝大部分成本花在判断而非创造上。然后把高频结构化判断下沉到专用决策层或自建小分类器，只把生成与复杂推理留给旗舰模型。同时警惕反向风险：决策层的开源复刻只用了两天，意味着你的差异化不在"选了哪个模型"，而在数据配方与阈值策略——这两样东西必须在你自己的业务数据上长出来。

二、瓶颈从模型移到系统：Agent 交付链路的三处重构

2026 年正在形成的共识是：模型能力不再是瓶颈，围绕它的系统才是。

第一处：算力标尺与消费模型

英特尔的立场转换值得注意——从"理论参数"转向"满足延迟承诺时能维持多少 Agent 任务量"，这是一个系统级论点，而不是芯片营销话术。它对应的现实是：Agent 的工作负载是高频、突发、有状态的，工具调用穿插其间，与按单次推理吞吐设计的现有数据中心根本不同。华为用"灵衢"把答案钉在通信上（10 万卡 MFU 从 20% 到 35%，单集群支持 100 万颗处理器），CoreWeave 则把 80%–90% 的输入重复率转化为缓存定价与两种消费模型并存——serverless（按 token，含 provisioned throughput 档位避免吵闹邻居）与 dedicated（按 GPU 小时计费，客户自选引擎、决定是否 prefill/decode 分离）。

边界还在移动：AWS Lambda 把托管实例上的函数超时从 15 分钟放宽到 90 分钟，进一步模糊了 serverless 与传统服务器的界线，明显是为长时 Agent 工作负载让路；Amazon SageMaker 今年已交付 13 项推理新能力，并坚持"按实例而非按 token"的消费路径；Vercel 则把 Spend Management 扩展到 Enterprise Flexible Commitment 计划——按账单周期设预算，接近或超过时发邮件、触发 webhook、或暂停所有项目的生产部署（暂停是 opt-in，且不影响 AI Gateway 与 v0）。成本管控的粒度已经下沉到部署层。

第二处：上下文层成为企业最有价值的私有资产

Databricks 的 Ali Ghodsi 给出了本周最值得贴在 CTO 办公桌上的一段判断：前沿模型即使停止进步，多数公司也不会察觉——"模型已经足够聪明，但它们没有组织内部的上下文：没参加过每一次会议，不知道每个人脑子里想什么，不知道所有流程。每个组织总有那么几个什么都知道的员工……模型没有这种上下文。如果你把那部分融合进去，任何组织都能获得大量生产力提升。为此我们其实不需要更聪明的模型。"他同时指出，随着 Agent 在内部运行并与其他公司的 Agent 交互，产生的日志、轨迹与指纹规模比一两年前高出好几个数量级，安全与数据市场正被逼进同一个战场。

LinkedIn 是这条路径上最具体的落地样本：用 MCP 构建组织级上下文层，把流程记忆、代码检索与 runbook 直接喂给编码 Agent，20% 生产力提升、可靠性零损失。同一家公司的另一条线也值得一提——多教师蒸馏流水线把大教师模型压进 6 亿参数的排序模型，自建基于 SGLang 的框架在训练循环内直接服务教师模型，在线与离线混合把蒸馏提速 8 倍。这说明企业侧真正的"模型工作"不是训练前沿模型，而是把私有知识高效地压缩进小模型。

但质量把关的工具链本身并不可靠。谷歌两位工程师的实测发现：向基准测试工具请求 200 QPS 实际只跑 38，却照常打印结果；Python 的 GIL 让单进程 harness 卡在约 170 的实际上限；抖动客户端把延迟夸大过 58 秒，读起来像是服务端瓶颈；某份共享结果号称吞吐提升 20%，实际是把温度设成 0——确定、更快，但比任何真实工作负载（0.7）都不具代表性。Datalab 发布 OmniExtractBench 时也披露了同类现象：基准集成的兼容性 workaround 会抹掉合法表示（把允许为 null 的字段的 null 去掉），修复后同一评分器把分数推到 93.94%。如果连评测工具链都在骗人，基于公开跑分的模型选型就没有可信依据。

第三处：交付链路才是真正的瓶颈

小红书 Muse 的分享把问题讲得最直白：AI 写代码已经足够快，但从需求提出到生产上线，企业研发未必因此更快。设计规范、工程资产、跨仓上下文、安全检查与协作断点，会把编码阶段节省的时间重新消耗掉。Muse 的应对是把 Agent Team 编排、Harness 控制机制、企业知识工程与 Agent OS 组合成系统，让人从具体实现转向判断、监督与品味。NVIDIA SoL-Pi 存活下来的四个机制则可以直接当作检查清单使用：Action Fusion（编辑与测试合并为一次调用，砍掉一轮模型往返）、Online Context Compact（子任务完成时才压缩，且先算清"省下的 token 是否够付缓存重写"）、ObservationPack（重整观察结果的处理方式）、Evidence-Preserving Reducer（委派阅读时保留证据）。这四项针对的都是可测量的过程性浪费，与具体任务无关。

至于人和组织的边界，Hinge 的首席产品与技术官 Ben Celebicic 给出了保守但工程化的答案：PM 与设计师用这些工具做原型、更快判断想法是否值得做，但产品仍由工程师构建。他强调这不是因为自己的工程背景，而是要看证据证明非工程师能构建长期可扩展、可维护的技术。在一个所有人都被"AI 让交付变简单了"的叙事推着走的月份里，这种基于可维护性的保守反而更像是工程判断。

对 CTO 的含义：把预算与路线图从"追旗舰模型"转向三处系统性投入——容量规划改用"并发 Agent 数 × 延迟承诺"的标尺，而不是 FLOPS 叙事；上下文层当作核心数据资产来治理（谁维护、如何更新、如何评估新鲜度）；交付链路的验证与回滚当作一等工程而不是附属品。同时立一条纪律：模型可以给自己打分，但决策不可以——Ghodsi 说得很清楚，风险不在模型够不够聪明，而在它有没有你组织里的那份上下文。

CTO 视角 · 行动建议

01

把"决策分层"写进架构规范，而不是等账单来教育你

先做一次调用画像：按 Agent 循环的位置统计调用量与单价，区分"判断"和"创造"。绝大多数团队会发现成本主要花在前者——退出判断、路由选择、候选打分这些二选一问题被交给了旗舰模型。把这类调用下沉到专用决策层（Jev 或自建小分类器），保留生成与复杂推理给旗舰模型。同时把"置信度阈值"作为可配置的产品参数而不是硬编码逻辑，让低置信度的分支自动升级到人工——这是把人在回路从成本项变成开关的关键。

02

用三层模型组合替代对单一旗舰的依赖

当天数据已经把三条曲线画清楚了：开放模型占 Vercel AI Gateway token 总量的 78.4%；同一 coding 任务开源权重方案便宜约 5.5 倍；决策模型比 LLM 便宜快一个数量级。建议按任务性质分三层配置——生成与复杂推理走旗舰模型，批量结构化处理走开源权重，高频决策走专用决策层。更重要的是把路由能力本身当资产建设（GitHub 的 HydraFusion 就在做自动平衡质量、成本与速度的模型选择），因为模型的单价与能力每个月都在变，路由策略才是能长期复用的部分。

03

容量规划换标尺：从 FLOPS 叙事转向"并发 Agent 数 × 延迟承诺"

英特尔白皮书提出的问题值得每个基础设施负责人自问：我们的容量规划是按理论吞吐算的，还是按"满足延迟承诺时能维持多少 Agent 任务量"算的？Agent 工作负载是高频、突发、有状态的，与按单次推理吞吐设计的集群并不匹配。具体动作：把 prompt 缓存命中率（CoreWeave 观察到 80%–90% 的输入重复）作为一级指标；把长时任务（AWS Lambda 已放宽到 90 分钟）的调度与超时策略重做一遍；对成本管控建立部署级闸门（参考 Vercel 的预算触发 webhook 与暂停部署）。

04

把上下文层当作核心数据资产来治理，而不是每个 Agent 各自现搭

Ghodsi 的判断值得当作原理：模型已经不缺智力，缺的是你组织内部的会议、决策与流程——而"每个组织总有那么几个什么都知道的员工"，AI 缺的正是这种上下文。LinkedIn 用 MCP 把流程记忆、代码检索与 runbook 做成组织级上下文层，拿到 20% 生产力提升且可靠性零损失。落地路径是三件事：明确上下文层的 owner 与更新机制；用 MCP 之类的标准协议而不是每家工具各接一遍；给上下文建立新鲜度与正确性的评估，否则错误的知识会被 Agent 规模化地放大。

05

建立"AI 生成内容的事实责任链"，并收口影子 AI

CNN 报道的事件是一个完整的失败样本：AI 生成的内容因为"格式与常规情报产品一模一样"而被采信，一路推动到真实军事行动。抽象出来的规则对企业同样适用——格式的权威感不能替代事实的核验，且必须有人对事实负责。具体动作：对任何会进入决策链的 AI 生成内容建立来源标注与二次核验要求；对编码 Agent、浏览器 Agent 做一次出网审计（上传了什么、去了哪里）；对影子 AI 采用疏导而非封禁（GitHub 的观察是自购工具代表未被满足的需求，一刀切禁令通常失败）。吴恩达的提醒值得写进事故复盘的模板：把责任推给"失控的 AI Agent"之前，先问是哪个流程、哪次人类决策失灵了。
