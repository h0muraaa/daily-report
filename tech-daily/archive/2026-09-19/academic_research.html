1.1NVIDIA 发布 SoL-Pi：用自动研究循环改写 Agent 的 harness 层，token 消耗近乎减半

该工作提出一个反直觉的命题：在 coding agent 走向 7×24 无人值守（单任务 2–12 小时）之后，真正的成本瓶颈不在模型权重，而在 harness 层的过程性浪费。权重无法改动，但框架里每一处浪费都与具体任务无关，因此一旦被移除即可迁移到所有任务上——这正是递归自我改进（RSI）中成本指数放大的关键环节。

核心方法：团队没有手工调 harness，而是把自动研究循环放到 harness 层运行：跨大量从代码仓库与验证器构造的环境中并行探索候选机制，只保留能通过选择压力的少数。搜索规模为 152 个研究方向（归为上下文、进度、工具、委派、提示策略、评估方法六大家族）、535 个可执行环境（495 个由 GitHub issue–PR 对挖掘、40 个由验证器反向构造）、3000 次以上运行与 60000 次以上智能体—环境交互，最终仅 4 个机制存活，淘汰率约 40 选 1。

关键结果：存活的四个机制分别对应可测量的 token 浪费模式——Action Fusion（编辑与测试合并为一次调用，省去一轮模型往返）、上下文压缩（仅在子任务完成时压缩，且先计算“省下的 token 是否够付缓存重写成本”）、观察结果打包与保留证据的委派读取。在 51 任务的 EdgeBench 留出集上，token 流量接近减半，API 成本约降低三分之一，同时在 GPT-5.6 Sol 与 Opus 5 上与基线 harness 打平。

学术意义：该方法论层面的贡献大于四个机制本身（详见第 2.1 节）：它把“harness 是否有效”从经验判断变成带留出集与冻结验收门的可复现搜索问题。

1.2智谱披露首个进入生产环境的 RSI 案例：GLM-5.3 的 Infra Agent 优化自身推理基础设施，两周吞吐提升 3 倍

智谱创始人兼首席科学家唐杰公开披露：由 GLM-5.3 驱动的基础设施智能体（Infra Agent）完成了 GLM-5.3-Flash 推理基础设施的设计、调试与优化，实现模型对自身运行系统的反向改进，在十万卡规模集群上不到两周把吞吐量提升至 3 倍。报道称这是国内大模型厂商首次公开跑进生产环境的 RSI 案例。

学术意义：这是本窗口内 RSI 议题的第二个独立工程证据（第一个为 SoL-Pi，第三个为 Google DeepMind 的 Dream-RSI 等方向的公开讨论），其价值在于把“AI 改进 AI”从能力评测推进到可观测的生产指标。需要指出的是，当前披露口径为厂商单方声明，缺少基线配置、能耗与正确性回归的完整说明，独立复现前不宜作为比较基准。

相关脉络：同期流出的 RSI 讨论还包括 OpenAI 在 GPT-5.6 成绩单中首次单列“自我改进”科目（GPT-5.6 Sol 57.9% 对 GPT-5.5 41.7%），以及 GOSIM Shenzhen 2026 把 RSI 列为大会主线议题。

1.3FlashNorm：把 RMSNorm 的增益折叠进投影权重，norm+投影组合提速 33%–35%

该工作在 AI Engineer 会议上报告，作者 Filip Makraduli 与 Nils Graef。出发点是一个系统测量事实：RMS norm 层几乎不做 transformer 里的算术，但单次 decode step 可以触发它约 33 次；而 GPU 擅长计算、不擅长启动工作、搬数据与等待。

核心方法：结论可以用两行代数概括。其一，把 norm 的增益（gain）在离线阶段折叠进投影权重，让一次矩阵乘吸收两者；其二，推迟标量除法，使矩阵单元与向量单元并行而不是互相空等；其三，在连续做两次归一化的新架构里直接删掉其中一次——因为该操作具有尺度不变性，第二次不带来任何信息。

关键结果：在 norm 加投影这一组合操作上取得 33% 至 35% 的加速，且折叠后的 checkpoint 与前向结果保持等价。这是典型的“不换模型、改数值路径”的效率工作，方法论上值得与 MoE 稀疏化、KV cache 压缩等模型侧手段区分看待。

1.4Google 发布 Android Bench 2.0：把评测对象从“模型”改成“模型 + Agent 组合”，最高通过率仅 28%

Android Bench 2.0 的任务来自 Google Android 最佳实践文档，采用真实生产级应用（Signal、Bitwarden、Pocket Casts、WordPress、Now in Android 等）作为工程场景，并在 1.0 版 100 个短任务之外新增 30 个任务赛道，覆盖四类真实工程工作：应用转换（Flutter / React Native 迁移到原生 Android）、从零构建应用、架构迁移（XML View → Compose、Hilt → Koin、Retrofit → Ktor、Java → Kotlin，共 13 项，为最大类别）以及新功能开发（CameraX、Media3、画中画、无障碍等）。

方法学要点：评测单位是“模型 + 其专属 Coding Agent”的组合，即 GPT + Codex、Claude + Claude Code、Gemini + Antigravity、Kimi K3、Qwen 3.8 Max 等。这一点与 SoL-Pi 的结论互相印证：在长程工程任务上，harness 与模型是联合变量，单独报告模型分数会系统性高估或低估实际交付能力。

关键结果：最高通过率仅 28%；GPT 6 Astra + Codex 与 Claude Fable 5.1 + Claude Code 位列前二，包揽前四；Qwen3.8 Max + Qwen Coder、Kimi K3 + Kimi Code 分列五六名；Google 自家的 Gemini 3.8 Flash / 3.7 Flash + Antigravity 未能进入前列。需要提醒的是，该榜单由模型厂商发布，任务集与判分器虽公开（developer.android.com/bench），但尚未见第三方复现。

1.5Google 工程师的实证研究：多数 LLM 性能基准“测不准”——要 200 QPS 可能只跑了 38

Ashok Chandrasekar 与 Jason Kramberger（均在 Google）从“反复无法复现已发表数字”出发，系统性地定位了推理基准的保真度缺陷，并在 AI Engineer 会议上逐条给出证据。

具体发现：向基准 harness 请求每秒 200 次查询时，它可能悄悄只交付 38 次，却仍按 200 的口径打印结果——原因是 Python 全局解释器锁（GIL）使单进程 harness 成为 CPU 瓶颈，他们测试的 harness 大多在 170 附近封顶且不作任何提示。其次，客户端抖动会抬高其测得的延迟，其中一次偏差达 58 秒，读起来像服务端瓶颈而实际上服务端正常。第三，一份声称吞吐提升 20% 的公开结果，实际把 temperature 设为 0，这比任何真实负载（0.7）都更快且确定。第四，同一份公开数据集喂给两个 harness，产生的输入 token 数与截断方式并不相同。

学术意义：这项工作与 1.6 节的 benchmark 集成偏差、以及 MLNLP 关于“缺少统计显著性”的审稿指南共同构成本窗口评测方法论的自我审视：当模型能力差距进入个位数百分点区间时，评测链路上的工程噪声已经成为主要误差来源（见趋势 4.2）。

1.6LlamaIndex 指 Datalab OmniExtractBench 存在集成偏差：修复 null 字段后同口径得分升至 93.94%

Datalab 发布的 OmniExtractBench 将自身 ExtractBench、LongExtractBench 与多家厂商的基准合并，用于衡量结构化文档抽取质量。Jerry Liu（LlamaIndex）指出，该基准在集成环节的兼容性 workaround 会剥离允许为 null 的字段，从而抹掉了一种合法的“缺失信息”表示方式。

做法与结果：LlamaIndex 在保留 schema 结构与必填字段的前提下恢复了该选项，并在同一个判分器下把分数从受影响的水平恢复到 93.94%，略高于或至少等于已公布的最高分。

学术意义：这是一个高质量的负面案例：它说明当基准通过“适配层”拼装多个来源时，适配层本身会改变被测量的能力定义。作者同时提醒，厂商基准众多，最终仍应在自己的数据上评测。对研究者的直接建议是——引用第三方抽取基准分数时，应同时核对 schema 的可空性约束与判分器版本。

1.7LinkedIn 公开多教师蒸馏训练基础设施：6 亿参数排序模型，训练加速 8 倍

LinkedIn 公布其 AI 驱动职位搜索背后的训练基础设施：一条多教师蒸馏流水线，把大型教师模型的知识压缩进一个紧凑的 6 亿参数排序模型。作者强调贡献不在蒸馏本身，而在于让蒸馏快到足以支撑快速迭代的系统工程。

方法：系统基于 SGLang 构建定制框架，可在训练循环内直接服务教师模型，并管理张量并行与数据并行配置；训练期间的异步客户端向教师模型发送请求、处理输出并计入蒸馏损失，即在线多教师蒸馏。通过在多节点部署本地教师模型副本，蒸馏过程提速 3 倍并保持低延迟。为减少服务开销与重复计算，团队又引入离线多教师蒸馏：预先计算教师输出并存放在 HDFS 或 NFS 上，训练时直接读取。在线与离线相结合，并配合 LiGer 降低内存占用、把批次扩大至 2 倍，以及多节点训练，最终实现 8 倍训练加速。

学术意义：该案例把搜索/推荐团队共同面临的难题——“如何从关键词排序转向由大语言模型监督的统一排序器”——拆成了可复用的服务化组件。对蒸馏研究而言，它提示延迟与吞吐的工程约束会直接改变蒸馏方案的可选空间（在线/离线的取舍本质上是教师计算的复用率问题）。

1.8陶哲轩代表 SAIR Foundation 启动“开放数学模型计划”：以开放权重、可复现评测与社区治理为原则

菲尔兹奖得主陶哲轩以 SAIR Foundation 联合创始人身份，于 2026 年 9 月 18 日宣布启动“开放数学模型计划”，联合学术界与产业界为数学及科学研究构建面向科学的开放权重模型，以及便于同时使用开源与闭源大语言模型的科学开源工具。核心主张是让开放模型与可负担的算力成为数学研究的共享基石。

开放条款与治理：模型将提供开放许可的权重与代码，公开训练方法并附带可复现评测；训练数据要求可追溯来源与兼容授权；发布时须同时报告失败与局限。成果拟采用 Apache 2.0、MIT 或 CC BY 4.0 等许可，研究者保留既有成果权属，贡献数学思想与结果者获署名。算力由战略产业伙伴提供，但合作须保持社区的研究独立性；数据权归数学界，仅在用户明确同意且依据事先约定条款的前提下用于训练或改进模型。治理规则与决策公开，成员可提建议与问责。

时间与定位：基金会 2025 年由陶哲轩与科学家、投资人共同创立，为不依附大型 AI 公司的非营利机构，早期资源有限，主要做播客、短期活动与竞赛；本次因开放模型需求强烈而提前公开宣布。首阶段聚焦日常科研场景——理解艰深论证、核对文献、探索示例、编写代码、形式化证明。除成立年份与宣布日期外，公告未给出资金金额、算力规模或参数量，唯一具名支持方为资助下一轮 SAIR 竞赛的 XTX Markets。

1.9Google 内部数学推理模型曝光：代号 Mathematica，100 万 token 上下文

据爆料，Google 正基于 DeepThink V3 构建内部代号为 Mathematica 的实验模型，专门针对繁重计算与复杂符号问题求解优化，预估将成为 Google 最强的数学推理模型。

可核验的细节：API 数据显示其内部标识符为 models/deepthink-mathematica-tf-raw-thoughts，支持高达 100 万 token 的上下文窗口，输出上限为 5536 token。上下文与输出上限之间悬殊的比例，配合 raw-thoughts 命名，暗示该模型面向“长输入、短结论”的数学判定任务而非开放式生成。

学术意义：消息来源为社交媒体爆料，未经 Google 确认，仅建议作为研究方向的信号参考。但它与同日公布的 SAIR 计划、以及 OpenAI 在 GPT-5.6 中单列数学与自我改进科目，共同说明数学正在成为前沿模型能力竞争的独立赛道。

2.1　SoL-Pi：把 harness 优化变成一次带留出集的研究搜索

NVIDIA · 自动研究循环驱动的自演化 Agent Harness · arXiv:2609.20519（预印本）

研究问题
当 coding agent 进入 7×24 无人值守运行，单个任务耗时 2–12 小时，token 消耗取代模型能力成为规模化的第一瓶颈；若再叠加递归自我改进（RSI）的多轮迭代，成本被指数级放大。作者提出的核心命题是：优化对象应当是 harness 层而非模型层——权重动不了，但框架中每个环节的“过程性浪费”与任务无关，一旦被消除，收益可迁移到所有任务。
方法：自动研究流水线
团队不手工调参，而是把“提出假设—实现—评测—筛选”的研究循环自动化，并施加明确的规模与淘汰压力：
  • 152 个研究方向，归为六大家族（上下文、进度、工具、委派、提示策略、评估方法）
  • 535 个可执行训练环境，其中 495 个由 GitHub issue–PR 对挖掘、40 个由验证器反向构造
  • 3000 次以上运行、60000 次以上智能体—环境交互
  • 最终仅 4 个机制存活，淘汰率约 40 选 1
方法论设计：三条防过拟合约束
这是该工作最值得借鉴的部分，因为它把“演化搜索必然过拟合”这一常见批评直接作为设计前提：
  • 独立验证：留出集（EdgeBench 51 个任务中的 11 个）只在候选机制冻结之后评估一次，评估结果永不回流到搜索过程，用于阻断“进化过拟合”。
  • 先冻结、后评估的验收门：能力指标与容差在搜索开始前固定；候选方案必须在所有能力指标上不越界，且至少改进一项效率指标。“靠少干活省下的钱”一律不予采纳。
  • 一次性技能循环：每个实验实例化一份独立模板、用完即弃，避免候选方案之间因共享状态而产生失败耦合。
存活机制
四个机制各自针对一种可测量、可归因的 token 浪费模式：Action Fusion（把编辑与测试合并为一次调用，砍掉一轮模型往返）、Context Compact（仅在子任务完成时压缩，且先计算“节省的 token 是否足以支付缓存重写成本”）、ObservationPack（重塑观察结果的处理方式）、Evidence-Preserving Reducer（覆盖委派读取时的证据保留）。后两者在公开转述中尚缺少完整实验细节。
实验结果
在 51 任务的 EdgeBench 上，token 流量接近减半，API 成本约降低三分之一；在 GPT-5.6 Sol 与 Opus 5 两个基座模型上，自演化 harness 与基线 harness 能力持平，即效率提升未被能力回退抵消。
局限与可复现性
截至本窗口，本文为 arXiv 预印本，未经同行评审；留出集仅 11 个任务，统计功效有限，论文未报告多次运行的标准差——这一点恰好呼应了同日 MLNLP 关于“结果缺少统计显著性”的审稿指南与 Google 关于基准保真度的实证。四个机制是在 NVIDIA 自建的 535 个环境上筛选得出，向其他 harness 生态迁移时的增益幅度仍需独立验证。建议引用时同时报告 API 成本与该研究使用的 harness 版本。
对领域的影响
它把一个长期被当作工程经验的问题（“agent 框架怎么写才省”）转化为可搜索、可留出验证的研究问题，并给出了一套可直接复用的防过拟合协议。对 RSI 方向而言，其意义在于指出成本曲线的斜率由 harness 层决定，因而本轮迭代的收益可能并不来自更大的模型。

2.2　LinkedIn 多教师蒸馏基础设施：在线与离线的取舍本质是教师计算复用率

LinkedIn Engineering · 多教师蒸馏训练基础设施（工业界工程报告）

研究问题
把大型教师模型的知识压缩进一个 6 亿参数的紧凑排序模型，用于改善点击与申请等目标。难点不在蒸馏算法，而在速度：每个训练样本都需要查询一个或多个大型教师模型，对每秒需处理数十万次查询的排序系统而言，教师推理直接成为训练瓶颈。这也是许多搜索/推荐团队从关键词排序转向大语言模型监督的统一排序器时遇到的共同障碍。
方法：在线与离线两条路径
系统基于 SGLang 构建定制框架，可在训练循环内直接服务教师模型，并管理张量并行与数据并行配置；训练期间的异步客户端向教师发送请求、处理输出并计入蒸馏损失，即在线多教师蒸馏。为减少服务开销与重复计算，又引入离线多教师蒸馏：预先计算教师输出并存储于 HDFS 或 NFS，训练时直接读取。配合 LiGer 降低内存占用、把批次扩大至 2 倍，以及多节点训练。
实验结果
在多节点部署本地教师副本使蒸馏过程提速 3 倍并保持低延迟；在线与离线结合的完整方案实现8 倍训练加速。
局限
为工业界工程报告而非同行评审论文，缺少与其他蒸馏方案的受控对比，也未报告加速对最终排序质量的影响幅度。此外，离线方案的收益高度依赖训练轮次与教师输出复用率，在数据分布频繁漂移的场景下缓存命中率会显著下降。
对领域的影响
它给出了一个可迁移的判断标准：在线与离线的选择不是工程偏好，而是教师计算复用率的函数——当同一教师输出会被多个 epoch 消费时，离线缓存几乎是必选项。这一视角同样适用于当前大量“用前沿模型生成训练数据”的合成数据流水线。

3.1腾讯开源 WeVisDoc：单模型完成整页文档解析，2B / 4B 双版本

3.2Bespoke Labs 两天复刻 Jev 并全量开源：Bespoke Nimble 的数据、权重与训练配方全部公开

Bespoke Labs 把 TypeSafe Jev 的能力在“快速结构化决策”这一垂直任务上复刻为 Bespoke Nimble（称 Open Jev），模型权重、数据配方与训练配方全部公开，整个项目仅用两天“公开构建”，在 9B 规模的小模型上逼近 Jev 表现。训练未从 Jev 蒸馏，Jev 仅用作评测参照，因此在版权与学术上都较为干净。

核心创新——最小差异样本对训练：构造近乎相同的样本对，仅改动一个“焦点事实”（不超过 8 个词）就使正确标签翻转，迫使模型学会哪些证据真正应当改变决策。作者称其概率输出因此天然更可靠，即“校准是隐式的”，并且不需要带概率的标注数据。质量保障为四步流程：检查决策规则、构造样本对、验证两个样本（含逐句删除证据句以确认无泄漏）、程序化打标签。全部数据为合成，约 2676 条训练样本、覆盖 10 个类别。

训练与推理工程：在 Qwen3.5-9B 上做 LoRA（rank 16）微调，仅一个 epoch，尚未使用 RL。推理采用并行约束解码：每个选项映射到单个 token，直接读取这些 token 的 logits 做 softmax，根本不生成文本；在 Mac 上用 MLX 将共享上下文预填充一次、所有字段并行打分。

学术意义：这是一份教材级的小模型复现样本——它同时演示了合成数据构造、隐式校准、以及“把生成任务改写为受限决策任务”三条路线。对资源有限的研究组，其数据配方与评估协议可直接复用。

4趋势观察Trends & Outlook

4.1　RSI 正从叙事变成工程指标，并立刻暴露出一个自指难题

本窗口内至少三条独立证据把“AI 改进 AI”推到了可测量的位置：NVIDIA SoL-Pi 用自动化研究循环改写 harness 层（token 近半、成本降约三分之一）；智谱披露 GLM-5.3 的 Infra Agent 在生产集群上把推理吞吐提升 3 倍，被称为国内首个公开跑进生产环境的 RSI 案例；OpenAI 则在 GPT-5.6 成绩单中首次单列“自我改进”科目（GPT-5.6 Sol 57.9% 对 GPT-5.5 41.7%）。三者的共同点是把研究过程本身变成可审计的数据结构：研究方向、环境、候选机制、验收门全部显式化。

但随之而来的自指难题同样清晰。被评估的对象与被评估的工具往往是同一类系统——智谱的改进者是 GLM-5.3、被改进者是 GLM-5.3-Flash 的推理基础设施；RSI 指数由模型自己作答。这不构成方法错误，却意味着这些数字在缺少第三方复现时只能作为方向性信号。值得注意的对冲力量也在同日出现：Anthropic 与埃森哲宣布五年投入至少 10 亿美元共建独立评估能力，且 Anthropic 此前已承诺给外部评估者与内部风控团队同等的系统权限。判断标准建议落在一处——是否给外部方留出了冻结后一次性评估的留出集与可复现的 harness 配置，SoL-Pi 的三条防过拟合约束是目前最清晰的一份参考实现。

4.2　评测的“元危机”：当能力差距进入个位数区间，噪声成为主要误差来源

本窗口罕见地集中出现了三份关于“基准本身是否可信”的一手材料，且彼此独立。Google 工程师实测发现：请求 200 QPS 的 harness 可能只跑了 38 次却照常打印结果（Python GIL 导致单进程 harness 在 170 附近封顶且不作提示）；客户端抖动一次把延迟抬高 58 秒，被误读为服务端瓶颈；一份声称吞吐提升 20% 的公开结果实际把 temperature 设为 0；同一数据集喂给两个 harness 会得到不同的输入 token 与截断方式。LlamaIndex 则指出 Datalab OmniExtractBench 的集成层会剥离允许为 null 的字段，抹掉一种合法的缺失信息表示，修复后在同一判分器下得分升至 93.94%。MLNLP 的审稿指南把同一问题指向投稿侧：只跑一次实验而称“趋势明显”无法回应关于统计显著性的质疑。

三条证据共同指向一个操作层面的结论：benchmark 数字的可比性正在下降，而下降的原因是评测链路的配置而非模型能力。对研究者而言，可执行的应对是三项——报告方差、置信区间与多随机种子结果；保留冻结后才评估的留出集并声明其规模；公开 harness 版本、并发配置、采样温度与判分器版本。Android Bench 2.0 把评测单位定义为“模型 + Agent 组合”、SoL-Pi 把 harness 作为显式变量，都是在承认这一现实。

4.3　受限输出空间与 encoder 的回归：decision model 作为新的中间层

Jev 引发的讨论正在收敛出一个可检验的技术主张：不该用自由文本生成来做决策。其产品逻辑是输出结构与取值预先定义、类型错误在数学上不可能发生，每个输出附带校准过的概率，开发者设置阈值后高置信自主执行、低置信上报人工。更值得注意的是其作者对幻觉成因的论述——奖励模型存在类似 GAN 的不对称性，模型的不自信容易被识别并惩罚，于是模型学会丢弃不确定的模式并假装自信，幻觉是偏好优化的内在产物，据此提出 RLCD（而非 RLHF）路线。

这一主张在架构侧有对应物：有分析指出 BERT 式 encoder 路线当年停留在 task-specific 时代而错失 general representation model 的机会，而 Agent workload 改变了成本结构——输入越来越大、KV cache 越来越重、循环调用越来越频繁，此时“用巨大 decoder 完整 prefill 再自回归 decode 几个 token 只为做一次判断”显得昂贵。与此同时，本窗口的架构创新也大多指向稀疏与受限而非更大：Qwen3.8-LiveTranslate 的 Hybrid MoE + Interleave 流式处理、DeepSeek-V4.1-Flash 的非对称结构以缩小 KV cache、FlashNorm 在数值路径上折叠归一化。对研究者的提示是，“输出空间受限 + 概率校准 + 并行约束解码”这一组合值得作为独立方向做受控评测——Bespoke Nimble 用 2676 条合成样本在 9B 模型上复现 Jev 行为，本身就是一次低成本的概念验证。

4.4　开放权重与封闭实验室之间：人才流动仍是信息交换的主要通道

Hugging Face 被英伟达以 129.3 亿美元收购，交易方特意强调平台将继续面向整个生态开放、不要求采用英伟达计算平台——这从侧面说明该平台已承担类似 GitHub 之于软件开发的基础设施角色（1800 万开发者、300 万模型、50 万数据集、100 万应用）。同期，陶哲轩的 SAIR 开放数学模型计划明确以开放权重、可复现评测与社区治理为原则，并强调数据权归数学界、算力合作须保持研究独立性；ModelScope 的双周速递则显示开放权重的发布节奏仍在加速（两周 4202 个模型、826 个数据集）。

与之相对的是封闭实验室的信息隔离。有研究者指出，大型实验室之间处于 air-gapped 状态，但仍存在信息交换——通过研究者的“过热”与跳槽，信息以细小颗粒的形式在空气中流动。这句话没有给出可测量结论，却准确描述了一个研究治理上的结构事实：当训练配方与权重不再公开时，跨机构的能力差距将由人才流动速率而非论文发表速率决定。对学术界的现实含义是，在开放权重上构建可复现评测与教学基线（如本窗口中的 CMU 11-768、Stanford CS146S 两门课程）正在成为参与前沿研究最稳定的入口。需要提示的是，“开放”并不自动等于可复现：OmniExtractBench 的集成偏差与 Android Bench 2.0 的厂商自评属性都说明，公开任务集与公开评测能力是两件事。
