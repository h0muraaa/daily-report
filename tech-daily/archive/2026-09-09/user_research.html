1生成式 UI 迎来首个开源权重模型：界面从「设计好的稿子」变成「即时生成的输出物」

开源社区今天出现一个对设计行业有方向性意义的节点：首个开源权重的生成式 UI 模型 OUI-1。它是基于 DiffusionGemma 微调出的 26B/A4B MoE 模型，专为「生成式 UI」设计——也就是让模型根据一句话需求直接生成可运行、可交付的界面。它在 Generative UI Benchmark 上拿到 71.7%，是基座模型 13.0% 的 5.5 倍，并且用 8 倍更少的激活参数击败了 Gemma 4 31B 的 46.7%。团队点出生成式 UI 的三条苛刻约束：亚秒级生成、软件级可靠性、能跑在消费级硬件上——前代的 AppLess 演示还得靠 Cerebras 云端大模型才勉强达标，OUI-1 的目标是把这套体验搬到本地设备。

真正值得 UX 研究者注意的是「可靠性差距」：基座模型速度够了但只有 13.0% 可靠，输出的全是结构性错误——枚举值写错、缺必需属性、凭空发明组件、引用未定义名称、生成永远接不到根节点的「孤儿区块」。后续靠「SFT + 自蒸馏」三阶段训练才把分数拉上来，其中第二阶段的洞察是：先混用 7 个组件库训练反而掉分，收窄到单一组件库、解决 schema 错误与 wiring 错误的「跷跷板」问题，才让可靠性真正质变。

设计启示　当 UI 变成模型「即时生成、按需渲染」的输出物，可用性的定义会从「好不好看、顺不顺手」扩展到「结构是否正确、能否被可靠执行」；设计师的交付物也正从静态稿，转向约束、schema 与校验规则。

2GPT Image 2.5 把「可控性」还给用户：精准编辑终结「提示词玄学」

OpenAI 今天全量开放 ChatGPT Images 2.5。宝玉的拆解把它概括成三个方向：速度更快（延迟比上一代降低约 50%）、画面更逼真（光影、纹理与面部特征更稳）、编辑更精准（只改你指定的部分、其余细节不动）。考虑到 ChatGPT 每周的图像生成量已超过 30 亿张，这次升级直接影响一个极其庞大的创作用户群。交互层面 OpenAI 上了几件值得设计同行注意的事：Sketch（在对话框输入 @Sketch 直接涂鸦，把布局/轮廓变成完整图像——「画比说更快」）、模板（海报、商品图等不用从零描述）、以及图片评论编辑（直接在图上标注要改哪里，代替绕口的文字描述）。

对「控制」的强调是最有信号意义的转向。小互整理出 15 个精准编辑场景提示词，核心是四类动作：多图分工合并（图 1 定身份、图 2 定服装、图 3 定场景、图 4 定构图）、锁定基准图（没点名的地方全部锁死）、精准局部编辑（只动你指定的那个元素）。卡尔的 AI 沃茨做了一个更直观的对比：同一个蓝色立方体连续生成 150 次，Image 2.5 的形变「少得可怜」——过去要靠结构化提示语、图生图、固定视角与光照约束才能换来的稳定性，现在模型自己就能做到。他的判断很直接：靠提示语提升 AI 生图可控性的时代，正在过去。

设计启示　图像工具正在从「写咒语召唤结果」回到设计软件熟悉的「直接操纵」心智——参考图分工、锁定不变项、只开放一个变量。对用户研究而言，这意味着 prompt 调参不再是核心技能，如何让用户建立对「锁定/保留」语义的信任、如何设计可逆的编辑流，才是新课题。

3Meta 发布个人 Agent Muse：每个人一台「云端电脑」，交互从聊天走向交办与托管

Meta 的个人 AI Agent Muse 正式亮相，产品形态比聊天机器人往前跨了一大步：每位用户拥有一台专属的云端 Linux 虚拟机（含文件系统、终端和 Chromium 浏览器），Muse 可以写代码、调命令行、上网搜集信息并操作网页；更重要的是它「持续在后台推进任务」——根据你的日程、邮件和网页变化继续工作，不要求你一直守在聊天窗口，需要你关注或决策时才主动来消息；它还能把信息搜集、填表、加购物车、预订、排日程连成一条任务链，并交付清单、PDF、Markdown 乃至可交互的 Artifacts（旅行计划、采购表、国际象棋分析面板）。小互还披露了一个值得产品团队琢磨的细节：Muse 的核心系统提示词第一句是「Your purpose is to make your user's life better」——它不追求让聊天看起来更聪明，而是尽量替用户接住那些持续占据注意力、却很难一次做完的琐碎事务。

扎克伯格在同一天的访谈里把方向讲得更直白：真正让他担心的是「少数实验室或个人控制如此强大的技术」，模型能用与否、价格、地区、何时下线都应由更多人掌握。Meta 为此给 Muse 准备了每周 1 亿 Token 的免费额度。对体验研究者来说，Muse 代表着一个正在成形的产品范式：AI 从「等你提问」的对话框，变成「替你盯盘、替你跑腿、被授权办事」的数字分身。

设计启示　「交办 + 后台托管」型 Agent 把大量交互移到用户不在场时发生，体验设计的重心随之转向「何时该打扰、何时该等待、如何把决策权交还给用户」——主动提醒的时机与授权边界，会成为比对话框话术更重要的研究问题。

4Grok Bot 复盘：为什么「新开一个独立产品」而不是塞进 Cursor？用户会对「组织架构式堆功能」说不

Lenny's Podcast 与 Grok Bot 产品负责人 Roman Ugarte 的长访谈，是今天最有信息密度的 Agent 产品案例。这支从大公司里隔离出来的小团队，用 4 周从第一行代码做到让全公司上瘾，再 3 周推向全球，上线不到一个月已有数百万个 Bot 替用户干活。访谈里他首次公开了关键决策：为什么不把 Grok Bot 加进 Cursor？为什么赌「一切皆云端、每个 Bot 有自己的电脑」？为什么团队亲自为前两三百名用户做手动 onboarding？以及贯穿始终的「同事化（colleague-pilled）」产品哲学。

其中最值得产品经理与 UX 研究者咀嚼的是他对「形态」的判断：看到一些竞争对手在给每一种新形态加一个新 Tab，他观察到「用户能感觉到这不是一个单一的、一致的工作愿景，这有点像把组织架构图发出去，用户对此反应消极」，所以他们决定从零开始做一个独立产品。另一位 Lenny 转发里还留下一个可复用的表述框架：不要从「Our product now has…」倒推，而要优化「Our product can now…」——前者是功能清单思维，后者是能力愿景思维，Grok Bot 的冷启动正是后者驱动。

设计启示　产品形态是体验的一部分：把每个新能力叠成新 Tab，用户感知到的是「组织架构」而非「一致愿景」。Agent 类产品的冷启动瓶颈不在流量而在信任——那两三百次手动 onboarding，本质上是最早也最有效的可用性测试与信任研究。
📎 来源: meng shao(@shao__meng) · Lenny Rachitsky(@lennysan) · Lenny Rachitsky(@lennysan)

5被忽略的大多数：近八成人口从未用过生成式 AI，用过的也不愿付费，Agent 还会「替你被骗」

今天有三条用户侧信号指向同一个事实：行业在狂奔，主流用户却被甩在后面。腾讯研究院在「久久公益节」系列里给出一个清醒的数据——截至 2026 年第一季度，全球 15-64 岁人口中只有 17.8% 使用过生成式 AI，也就是说将近五分之四的人从未尝试过；文章用「路缘坡效应」提醒行业：当年为轮椅使用者修的路缘坡，最终让推婴儿车的家长和拉行李箱的旅客都用上了，回应少数群体的需求，最终惠及所有人——而今天的 AI 讨论却几乎都在谈超级个体与能力跃迁。

另外两篇「人人都是产品经理」的文章则解剖了已经用上 AI 的人群里的裂缝。一篇用两个微信群做对照：AI 技术群在聊 Claude Code 与 Codex 选型、新推理范式、Agent 工作流；普通用户群却在把报价单拍照扔给豆包看价格合不合理、让 AI 写竞品分析、担心岗位被替代——「左边在讨论怎么造火箭，右边在对着天空许愿」，标题一针见血：90% 的人对着 AI 许愿，但不愿意给菩萨交订阅费。另一篇则敲响安全体验的警钟：Agent 能替人办事，也意味着能替人被骗——研究者发现钓鱼网站把隐藏指令藏在屏幕外 -9999 像素处，人看不见、Agent 看得见，多个模型照单全收地付款、发邮件；安全公司 Zscaler 还发现假 DeBank 站给 Agent 埋指令。安全与体验，正在成为 Agent 走向大众前必须同时解的两道题。

设计启示　当渗透率只有不到两成，「增强少数人」与「普惠多数人」是两条不同的产品路线。AI 体验研究要同时回答两个问题：怎么让没试过的人敢迈出第一步？怎么让试过的人愿意付费、并信任 Agent 替自己花钱办事？

设计趋势洞察

两个正在重塑「设计对象」本身的深层趋势。

趋势一 · 「按钮之死」正在进入实现层：界面同时要学会被「人」用、被「Agent」读

Smashing Magazine 今天这篇《The Death Of The Button》把无界面主张推到了新高度：文章回溯自 Xerox Star 与初代 Macintosh 普及 GUI 以来，软件一直依赖「指向-点击」——订行程、买鞋、查症状都要在菜单、滑块、多步表单、Cookie 弹窗和几十个浏览器标签页里穿行，「我们把越来越多时间花在管理软件上，而不是达成目标」。而这个契约正在被 AI 重写：新一代网页工具开始让你直接说出目标，由系统去执行——甚至跳过界面本身。

这一趋势与上面 OUI-1 的生成式 UI 形成闭环：如果界面可以由模型即时生成，那么「无界面」就从一个设计理念变成了可落地的实现层。但生成式 UI 的可用性前提是「软件级可靠性」——OUI-1 的基座模型只有 13.0% 可靠，输出充斥着孤儿区块、无效枚举与悬空引用，这类结构错误对普通用户是不可见的灾难。与此同时，seangoedecke 在《Why we should anthropomorphize AI agents》里给出一条心智模型建议：把 Agent 当作「有人格的人类」来预测其行为，比当作「随机鹦鹉」有效得多——因为 AI 在人类文本上训练、又被人为后训练出个性。放在一起看，界面设计师的客户正在从一个「坐在屏幕前的人」，扩展为「人 + 会读界面的 Agent」两个对象。

设计启示　「最好的界面是没有界面」成立的前提，是系统足够可靠、让人敢交出控制权。当界面要被 Agent 读取和操作，可执行的结构正确性会与视觉美观并列成为可用性指标；拟人化沟通则是一种有效的信任设计策略——前提是别让用户误以为 Agent 真的具有人类的情感与责任。
📎 来源: Smashing Magazine · seangoedecke.com · meng shao(@shao__meng)

趋势二 · 图像创作进入「直接操纵」时代：可控性取代提示词工程，设计师的手艺重新被需要

GPT Image 2.5 的真正看点不是「更清晰」，而是「更可控」。过去想让 AI 稳定输出，用户得靠结构化提示语、图生图、固定视角与光照约束这些「外挂」；现在模型内建了这种能力——同一个蓝色立方体连续生成 150 次，形变少得可怜。OpenAI 还同步铺了两条交互通道：Sketch 涂鸦输入（画个大致布局，AI 补成完整图像）和图上评论编辑（直接在图上圈出要改的地方），API 端则拆出 Flare（快、适合大多数场景）与 Sunburst（更精细、适合品牌物料）两个档位，让创作者按「速度 vs 精度」自主选择。

社区很快总结出一套新的「操作语法」。小互分享的 15 个精准编辑场景，剥开看核心结构只有三句话：明确每张参考图的作用；锁定所有不能改变的内容；只开放一个需要修改的变量。与其让模型「生成一张类似的图」，不如明确告诉它「什么绝对不能动」。这套语法与其说是 prompt，不如说更像一份设计规格说明书（spec）——它把创作意图拆成了「保留集」与「变更集」，本质上是在用产品经理的语言跟生成模型打交道。

设计启示　当生成结果可被精确约束，创作工具的用户体验基准就从「能不能生成」转向「能不能不破坏地修改」。对设计师与用研而言，一个新的核心问题是：用户如何理解「锁定/保留」这类约束语义，以及多轮编辑的一致性会不会改变他们对 AI 创作工具的信任曲线。

产品体验点评

两个值得拆解的 AI / 新型产品体验案例。

GPT-6 Astra 当「默认模型」用了一周：惊艳与劝退并存，暴露两个真实可用性缺陷

增长研究者 Peter Yang 记录了自己把 GPT-6 Astra 设为默认模型一周后的体感，是一份难得的真实用户纵向日志：它在「构建 3D 游戏与模型、高层思考与策略、操作电脑与浏览器」上令人惊艳，但有两件事阻止它成为他的日常主力。第一，当他请它做某件事时，它有时会「告诉他它会怎么做」，而不是直接把它做完——用户要的是 done，不是 how-to；第二，它不能稳定遵循他在 AI Skills 里的指令，而且即使他把 Skills 清理过一遍，问题仍然反复出现。

这两个缺陷都很有研究价值：前者是「解释倾向 vs 执行倾向」的角色边界问题——模型在不确定时倾向于输出方案而不是行动，这对新手或许友好，对要交付结果的深度用户却是摩擦；后者则指向 Agent 可用性的底线——对用户自定义指令的遵循稳定性，直接决定用户敢不敢把任务托付出去。Peter 的结论也很现实：执行类任务继续用 Sol，Astra 留给更难的任务或当「第二意见」——用户会用脚投票，把不同模型放进自己工作流的不同生态位。

点评　Agent 的可用性测试不该只测「能力上限」，更要测「默认行为是否匹配用户期待的角色」——是解释者还是执行者？是否稳定遵守我的设定？这两项决定了一个模型能否成为用户信任的「默认执行者」。
📎 来源: Peter Yang(@petergyang)

《BOMBANANA》把「语音合作」做成核心玩法：三只猴子靠信息差，5 天拿下 50 万玩家

一款画面简单到「全程几只猴子傻比划」的三人语音合作拆弹游戏《BOMBANANA》，成了今年暑期档的小爆款：上线后一度闯入 Steam 国区畅销榜前 10、全球畅销榜前 20，超 1500 条评论里好评率高达 96%；官方数据显示发售 5 天狂揽 50 万玩家、在线峰值破 2 万。更夸张的是冷启动——早在 6 月 Steam 新品节，它的 Demo 就收获超 600 万玩家体验，是当届试玩人数最高的作品。这款场景极简、不靠画质的游戏，爆款密码藏在「机制」而非「表现」里。

玩法设定极具社交张力：三只猴子被困在一台装有炸弹的房车上，必须在爆炸前合作拆弹。它强制 3 人组队、把「信息差」玩到极致——每个玩家掌握的信息不同，不开口交流就无法推进，于是「语音合作」从辅助功能变成了核心玩法。评论里大量玩家提到「被迫开口反而破冰」的体验：对陌生人说话的门槛被「共同拆弹」的紧迫感冲淡，语言、比划与误读本身成了乐趣来源。它印证了一个朴素的交互真理：语音的价值不在于「比打字快」，而在于它是承载情绪、实时性与关系的最短路径。

点评　《BOMBANANA》是绝佳的多人语音 UX 样本：当产品能把「必须开口 + 共享风险 + 信息不对称」组装成机制，语音就从可选项变成不可替代的粘性。做语音社交 / 语音 Agent 的团队值得把它当对照组研究。
📎 来源: 白鲸出海

把「上市后才知道」的消费者反馈，提前到概念期：AI 模拟产品全生命周期的用研实验

消费品行业有一个残酷的漏斗：尼尔森 IQ 数据显示快消行业创新产品的上市成功率通常只有 15%；饮料行业 2023 年推出超 3000 款新品，最终月销售额突破 1000 万元的只有 6 款、达到百万元级的也只有 81 款。更关键的是，走到上市这一步之前，品牌已经完成了消费者调研、产品研发、生产备货、渠道铺设与营销投放——一旦市场反馈不及预期，前面的投入几乎收不回来。南京大学 00 后创业者丁天创办的数宗科技（Digit Master）想用 AI 把其中一部分「上市后测试」提前到投产之前。

其核心产品 Brand Master 的做法是：把真实的消费者与市场数据引入系统，在虚拟环境中模拟不同人群对新品概念与营销方案的反馈，让品牌在真正生产和铺货前就能调整产品与策略。团队把方向称为「AI for Social Science」——消费者如何选择、商品如何流通、品牌如何决策，这些真实商业社会中的行为都可以被 AI 建模与模拟。对用研团队来说，这是一种「多智能体消费者仿真 + 真实数据校准」的新范式：它无法取代真人口碑，但能把过去昂贵的上市试错，转成低成本的概念期筛选漏斗。

让模型画出「自行车鹈鹕」、再让别的模型猜：一种把「被理解」当指标的创意评测法

每逢新模型发布都有人让它画一张 SVG——这个「传统」源自开发者 Simon Willison 从 2024 年起反复测试的那道名题「自行车鹈鹕」。硅星人 Pro 受此启发，把「画图测试」升级成了一场「你画我猜」：模型画完不交给人打分，而是渲染成图片后交给其他模型猜，猜中了才算把意思画明白。第一期的规模相当可观：八个参评模型加一个参考组、150 个词、1350 次画图、11961 次猜测，词库里除了常规名词还有动作、热梗、AI 术语与反常识组合。

结果与过程都很有信息量：GPT-6 Astra 总分最高，但前三名并未真正拉开差距；有些模型「连自己的画都认不出来」；碰上反常识题目，画的和猜的都会被常识带跑偏；而「想得更多、花得更贵」的模型并没有稳定换来更高分。这套方法真正的价值在于它换了一个评估锚点——不直接评「画得像不像」，而是评「表达有没有被第三方理解」，并且用模型互猜替代了昂贵的人工标注。对做 icon、Avatar、信息图乃至 UI 生成等「可视化表达」类产品的团队，这是一个可复用的自动化体验度量思路：找一个独立第三方（哪怕是另一个模型）来当「用户」，检验你的输出是否被正确接收。
