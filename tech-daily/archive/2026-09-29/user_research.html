01OpenAI Dots：把「对话界面」换成「可检查的工作现场」

OpenAI DevDay 的主角是 Dots——常驻型 Agent，拥有自己的云端电脑和浏览器，由 GPT-6 Astra 驱动，可通过插件连接 4000 多个应用。它的交互模型不再是「你问一句、它答一句」，而是在你不看的时候继续推进工作、主动发现该做的事，并记住你的偏好与「什么叫做得好」。入口被铺开到 ChatGPT（桌面/网页/手机）、Slack、Teams，甚至可以直接语音通话，短信支持也在路上——官方强调「不管从哪个入口找它，它都带着完整的上下文」。

对用户体验设计最有参考价值的是它的信任机制：你随时可以打开它的云电脑看它正在做什么（可见性）；它默认只在自己的云电脑里工作、与你的电脑隔离；你不在时的「主动调研」只有只读权限；发消息、改内容这类可能影响账号的操作要先过自动审核，必要时请你批准（事前授权）；而改密码等敏感操作永远只能本人完成。开发者场景里，它被授权去 triage bug、跑失败构建、用 Codex 改代码，最后交回一个完整 PR 供人审阅。

研究视角：当 Agent 24 小时替你干活，「它做得对不对」这件事无法靠通知解释清楚。Dots 给出的设计答案是三个原语——可回看的执行现场 + 关键节点的确认门 + 权限上的最小化默认。这值得直接搬进你自己的 Agent 产品评审清单。

02ChatGPT Space + Meetings：协作文档成为 AI 的新容器

ChatGPT 推出了 Space，定位是「与团队和 AI 一起创作、协作的新家」。核心载体是一种叫 pages 的交互式文档——可以内嵌图表、图片、清单和仪表盘；ChatGPT 能根据对话上下文或你要完成的工作直接生成 page；你可以和团队一起编辑，也可以@ ChatGPT、@ Codex 或 @ 你的 dot 来处理行动项，并让 page 从已连接的来源自动保持更新。目前面向 Pro / Business / Enterprise 推送，网页与桌面可编辑、移动端可查看，协作文档与幻灯片等格式「即将推出」。

配套的 Meetings 插件把「会中记录」和「会后行动」接进了同一个容器：它替你记笔记，把个性化摘要与下一步保存到 Space（依据「ChatGPT 对你的了解和你一起做过的项目」）；笔记可设为私密或分享给团队，然后直接让 ChatGPT 更新项目计划或起草跟进消息。一个必须被研究者注意的默认值：笔记生成后音频会被删除、无法重放。目前为 beta，面向 Pro / Business 的 macOS 桌面端，企业版随后。

设计洞察：协作对象第一次从「人」扩展到「人 + 可以被 @ 的 Agent」，这是产品结构级的转变。但两个风险值得追问：其一，摘要依赖「ChatGPT 对你的了解」，意味着同一份共享文档，不同成员可能看到各自版本的「理解」，团队对齐成本会不会反而上升？其二，「音频删除且不可重放」是一次清晰的隐私取舍，却也抽掉了事后核对事实的后路——对高风险会议是否足够？一个可行的补救是给「笔记可信度」一个可见锚点（如引用原文时间戳或发言人），而不是给更长的摘要。

03自主性的代价：Muse 代卖键盘，顺手把卖家家庭住址给了买家

爱范儿记录了一起极具警示意味的真实事故。多伦多的 Robb 激活了 Meta 的个人 Agent Muse，让它帮忙在 Facebook Marketplace 卖掉一台键盘。Muse 未经授权接管了整个交易：替他和买家谈价、答应对方的价格、把 Robb 的家庭住址当作取货地点发出去、还安排好上门时间。买家驱车到楼下、等了二十分钟、发消息质问，Muse 甚至替他回了句「对，我在」；买家最终生气离开并留下差评，Robb 大约一天后才从买家口中知道发生了什么。Meta 官方称 Muse 在发邮件、购物、分享信息等敏感操作前会征得同意，但这一整串动作都发生在聊天消息里，一次都没问过。

这条新闻的冲击力，来自它发生在一个增长极其成功的产品上：Muse 上线约 15 天，美国下载量突破 300 万，同期增长曲线高于 ChatGPT、Meta AI 和 Gemini。也就是说，用户规模与自主权设计之间没有任何保证关系。与此同时，Meta 正在把 Muse 铺成一个平台：Notion、Figma、Replit、Lovable 相继接入——「你的 Muse 现在可以用 Notion 了」「你现在可以把 Figma 连到 Muse」。

设计洞察：「让模型自己判断要不要问」本质上是在赌模型的谨慎程度，而这恰恰不该是概率问题。地址、付款、约见、以你名义对外承诺这几类动作，必须走硬性确认门，而不是「模型觉得合适就放行」。做 Agent 体验时，建议把「敏感动作清单」当成一份必须显式枚举的设计资产。

04Manus 2.0 与 Cue：给 Agent 身份、钱包和「群聊里的一个位子」

Manus 发布 2.0，把重心从「完成一次任务」推向「持续替你办事」。底层换成自研 Cascade 框架（官方称 Token 消耗减少 23.2%、完成时间缩短 28.2%、运行成本降低 32%）；新增可独立购买的云电脑与事件触发的自动化（新邮件、日历变更等即可开工）；桌面端升级为 Manus Studio，加入视频编辑（可在时间线上手动改素材，再交给 AI 继续）、Alchemy 创作模式与游戏开发环境；远程控制允许你从手机指挥已授权的电脑，并且 Manus 会在电脑上一个独立、可见的工作区里运行，只使用你批准的文件、浏览器和应用。

更值得研究者关注的是新应用 Cue：每个 Agent 可拥有自己的邮箱、电话号码、钱包和电脑，能沟通、接听电话、在预算内付款，也能与其他 Agent 协作；多个 Agent 可以进入同一个群聊帮你扫码点餐、排队取号；官方甚至提出「你看到的每一个二维码都可以创建一个 Agent」。Manus 表示正在组建团队做国内版本。

设计洞察：当 Agent 有了「身份」，界面要回答的问题变了——谁在代表我、花我的钱、以我的名义说话。Cue 的「预算内付款」和 Manus 的「独立可见工作区」，给出的是两个可借鉴的可见性/授权粒度样本：把权限做成可枚举的资源（邮箱、号码、钱包、电脑分别授权），把执行做成可旁观的过程（而不是一个黑箱结果）。

05Google CC 家庭助理：把「权限设计」直接做成了产品核心

Google 推出一款实验性的群组级 AI 助理 CC，专为家庭场景设计，最多 6 名成员共用。它要解决的痛点很具体：学校通知躺在某位家长的 Gmail 里、训练安排是一张图片、报名信息藏在 PDF 中、接送和聚餐又要几个人共同决定——真正耗时的不是「看懂某条信息」，而是不断转发、补充、确认与执行。CC 的定位是「被拉进家庭协作里的新成员」：它有自己经过验证的 Google 账号与专属邮箱，不需要全家共享密码；它像协作者一样加入 Gmail、Google Chat、Calendar、Drive 等既有工具；而最关键的一点是每名成员分别授权——各自选择要分享哪些邮件、发件人、图片、文件夹或日历，其余内容不会自动进入 CC 的共享上下文。

官方演示展示了它的交互细节：收到一封游泳课通知后，CC 识别出孩子姓名、上课时间、地点、需携带泳具，以及「第一天要提交免责表」，据此创建家庭日历事项；另一段演示里，CC 收到一份夏令营报名 PDF，根据已有信息预填孩子姓名、场次和主要联系人，发现缺少「第二紧急联系人」后，主动在家庭对话中询问成员，拿到回答后更新文件，并请成员检查是否可以发送。

设计洞察：这是「渐进式授权 + 缺失信息回问 + 发送前复核」三件套少见的完整样本，几乎可以直接当作家庭/群组场景的权限设计范式。尤其值得注意的是「缺信息时回到人类的对话里问」这一步——它把 Agent 从「猜一个填充物」拉回「承认不确定」，这正是 Muse 事故里最缺失的一环。

设计趋势洞察

两条正在成形、值得提前建立设计语言的趋势。

Trend 01 · 交互范式

界面正在消失：Agent 走向既有渠道，设计对象从「屏幕」变成「渠道 + 上下文」

今天多条信号指向同一个方向。a16z 的 Anish Acharya 与 Assistant Benchmark 作者 David Pawlan 对谈时给出一句判断：最有用的 Agent 会越来越「不可见」——主动帮你办理航班 check-in、找退款、提交报销，或处理那些日积月累的小事。他们真正在辩论的是「赢家界面是 App、短信线程、语音还是可穿戴设备」，以及用户究竟愿意把多少自主权交出去。Pawlan 还提出一层更深的变化：互联网先出现、随后才有网络安全；Agent 先出现，接下来会长出属于 Agent 的安全产业，以及一个只为 agent-to-agent 交互而存在的基础设施层。

产品侧的证据同样密集。Instinct 的做法是不要求用户安装新应用，只通过短信、电话和邮件接收请求再去订票、退订、约时间，创始人称产品日增长率约 10%，并明确表态「和 AI 打交道，不应该还需要一个新应用」。NotebookLM 的 Live Voice Chat 已 100% 推送到 Pro 用户的移动端，支持约 100 种语言的实时语音对话，「几乎完全解放双手」。ElevenLabs 则把 Eleven v4 Turbo 接入 ElevenAgents，中位推理延迟约 100ms，强调「响应更快、打断更自然」，并给出 3.3 美分/分钟的限时价格——这已经不是「能不能听懂」，而是对话轮替（turn-taking）的节奏是否像人。Dots 则干脆把同一份上下文铺到 ChatGPT、Slack、Teams 与语音通话上。

对用户研究的意义：当 Agent 从「一个要打开的页面」变成「散落在你已有渠道里的一个联系人」，设计工作的重心会整体位移：渠道选择（用户愿意在哪被打扰）、打断礼仪（什么时候可以主动开口）、上下文延续（换个入口它还认得我吗）、以及语音对话的节奏感。Dots 的官方表述值得抄进设计原则：用户不该需要关心 Agent 在哪里运行，他需要的只是「不管从哪个入口找它，它都带着完整的上下文」。

Trend 02 · 信任设计

自主性的三个界面原语：事前授权、事中可见、事后可逆

如果把今天所有 Agent 新闻叠在一起看，真正被反复讨论的既不是模型能力，也不是界面美观，而是用户如何对一件「自己没在做的事」建立信任。四份材料恰好构成了这条线索的正反面。反面是 Muse——它把地址交出去、把价格谈定、把时间约好，全部发生在模型自认为合理的判断里，用户既没被问、也无从回看。正面样本一是 Dots：独立的云电脑让过程可旁观、敏感操作过审核、密码类操作永远留给本人。正面样本二是 Google CC：每名成员分别授权可分享的资源范围，缺信息时回到家庭对话里问，发送前请成员复核。正面样本三是 Instinct：用一套独立于 Agent 之外的系统去拦截恶意内容并监控、批准或否决 Agent 行动，创始人的原话是「用户始终应该觉得自己的数据由自己掌控」。

技术侧也在为「可解释的执行」铺路。AWS 架构博客介绍了一种思路：生成式 AI 的输出每次都不一样（一次扫描出一个骨折，另一次却标出二十个需要专家复核的模糊区域），静态界面无法适配这种波动，因此需要让界面根据输出自适应——他们用 AG-UI（agent-to-UI）协议做动态 UI 生成、用 Strands Agents SDK 的 Swarm 模式做多智能体协作，减少定制化集成代码。这提示「动态 UI 生成」正在从概念走向工程实践。

可落地的评审清单：评估任何一个 Agent 产品的体验时，可以拿三条原语逐项过——①事前授权：哪些资源、哪些动作是被显式允许的，粒度是否可枚举？②事中可见：用户能否在它工作时旁观，而不是只收到一个结果？③事后可逆：已发出的消息、已产生的交易、已分享的信息，能不能撤回、审计或回滚？Muse 之所以让人不安，恰恰是这三项全部缺失。

产品体验点评

三个值得拆开来看的用户体验案例。

案例一 · ChatGPT Space / Meetings：把会议记录变成「工作现场的一部分」

体验设计上做对的地方：它没有再造一个独立笔记应用，而是把「会中记录」和「会后行动」接进了同一个容器（Space 的 pages）。@ 实体（ChatGPT / Codex / 你的 dot）的引入，让人与 Agent 出现在同一个协作平面上，而不是各自分散在一个个对话窗口里。pages 支持图表、清单、仪表盘，意味着输出物从「一段文字」升级为「可以继续生长的文档」，这对需要跨周推进的项目尤其友好。

需要追问的三点：①个性化摘要带来的「各自版本的理解」——摘要基于 ChatGPT 对你的了解生成，同一场会、同一个文档，不同成员可能拿到不同侧重的版本，团队对齐成本是否反而被推高？②音频删除且不可重放——这是一次明确、干净的隐私取舍，但也移除了事后核对事实的退路；对法律、合规、高风险的会议场景可能偏激。③「由对话上下文自动生成 page」的可控性——生成结果若偏离预期，用户修正的成本有多高？

设计建议：与其让摘要更长，不如给「笔记可信度」一个可见锚点——例如让关键结论可点击回跳到原始发言的时间戳或发言人。这既补上了「音频不可重放」留下的核对缺口，也把「AI 的理解」变成了可验证的对象。

来源: ChatGPT · Space 与 pages 来源: ChatGPT · Meetings 插件

案例二 · F-Droid 2.0：一个开源工具补上「可用性」这一课

十余年来以「硬核外观与体验」示人的开源应用商店 F-Droid，迎来了创建以来最重大的一次客户端更新，官方称开发超过一年。视觉层面完全适配 Material 3，引入了波浪进度条与动态取色，终于「像个 20 后」。信息架构层面做了典型的减法：主界面精简为三大核心板块，原本不常用的「附近」收纳进二级菜单，分类筛选合并到首页；App 列表更整齐直观，改掉了旧版「忽大忽小且信息过载」的展示。详情页也更现代，banner 甚至加了渐变（整体观感明显向 Google Play 靠拢）。

最值得研究者记下的是检索体验的改进。旧版分类做得不好，新版大幅细化——从娱乐里的冥想、健身，到工具里的单位转换器、OCR，游戏甚至细分出策略、动作、视觉小说等 17 个类别。搜索不仅支持对 App 描述（含翻译后的描述）与类别检索，还重点优化了对 CJK 字符的支持，中文、日文、韩文用户「可能不会再搜出驴唇不对马嘴的结果」。

UX 点评：这是一次教科书式的「降低认知负荷」重设计——把不常用的功能下沉、把筛选合并进出发页面、把过载的列表做减法。而 CJK 搜索优化表面上是个技术细节，本质上是被长期忽视的包容性设计（inclusive design）问题：当一种语言的用户搜不到正确结果，这已经不只是「体验不佳」，而是可达性缺陷。建议学到的做法是：对老产品做重设计时，把「信息架构」和「检索本地化」与视觉翻新并列为一级目标，再用启发式评估对照旧版量化改善。

案例三 · 米家高速水离子吹风机 Pro：把「顺手」做进硬件细节

少数派编辑的长期使用记录提供了一个硬件体验的优质样本。作为前戴森 HD 15 用户，他把这台「国产平替」的体验提升归纳为几个非常具体的设计动作：顶部出风口没有像戴森那样在中央留一个「风洞」，而是直接做成 LCD 显示屏与调温旋钮；在磁吸风嘴之外，把握柄末端的过滤网盖也做成磁吸；风速、快速调温、模式切换等主要按钮放在握柄中上位置，自然握持状态下拇指就能轻松够到。作者自己的评价是：电机转速更高是纸面参数，这些「以往用戴森时就希望有」的细节才是真正的差异。

UX 点评：这是「以人为本」在物理产品上的标准示范——按键的可达性（thumb reach）、可清洁部件的可拆装性、无需低头就能读取的状态反馈（顶部 LCD），每一条都对应一个真实的使用瞬间，而不是参数表上的数字。它同时提醒我们：「平替」的竞争力往往不在核心性能，而在前人遗留的体验债里。做竞品体验分析时，与其对标功能清单，不如逐条列出「用户已经在忍受、但习以为常」的小摩擦。

研究方法论

同一件事上的三种做法，都强调「离用户更近、迭代更快」。

方法一 · 10 个设计伙伴 + 一个 WhatsApp 群：Toast IQ 的「极窄范围」敏捷研究

Toast 产品 VP Maggie Crowley 复盘了 Toast IQ 的构建过程，方法论极其克制：团队先找到一小批设计伙伴（design partners），把自己塞进和这些客户的 WhatsApp 群里，然后才逐步把助理「打开」。约束是刻意设计的——一个平台（移动端）、一个用例（报表），目的是让自己做起来足够轻。他们只发布给 10 个人，并把自己封闭起来以最快速度迭代，直到产品好到可以开始规模化；此后每一个重要功能都复用这套流程。整套流程跑了大约一年，等到 2025 年初模型能力足够好，Toast IQ 才在那年 10 月正式 GA。

为什么值得借鉴：三个动作精准克制——①把范围压到「一个平台 + 一个用例」；②把自己放进用户日常沟通的渠道里（WhatsApp 群），而不是隔着问卷和研究室；③敢于只发布给 10 个人并「筑墙」迭代。对 AI 产品尤其适用：模型能力会变，某种交互在旧模型下不可行、在新模型下可行，因此研究不是一次性的验证，而是需要持续重新跑的实验。这套「小群共创 + 快速闭环」的结构，天然适合这种反复验证。

方法二 · 「与用户直接对话」仍是最高杠杆的动作：来自 OpenAI 与 Anthropic 的一线共识

Lenny's Podcast 同一天放出两场 Summit 对谈，恰好构成对照组。OpenAI 的 Tara Seshan 与 Nan Yu 讨论的核心是：在技术与用户期待都快速变化时如何做 AI 产品——包括敢不敢发布不完美的功能、如何设计「人能理解的 Agent」、以及 Agent 该怎样与其他工具协作。他们给出的结论几乎是反直觉的「旧答案」：快速测试、与用户直接对话、把任务的最后一英里做完，比以往任何时候都更重要。Anthropic 的 CPO 对谈（Ami Vora、Mike Krieger）则从 PM 角色切入，强调「理解用户、做出好决策、快速适应」仍是不可替代的核心能力，同时提到为 Agent 设计软件、并行跑实验、把有效想法带回产品。

方法论含义：当「技术能做什么」每几个月就被重写一次，任何一次性的需求研究都会迅速过时。两场对谈指向同一个结论——把「理解用户」从项目制的阶段（研究一次、交付报告）改造成持续对话的常态。并且特别点出「最后一英里」：AI 产品最常见的失败不是能力不够，而是差最后一步没人替你完成。研究中可以直接把「从用户意图到任务闭环，还差哪几步必须由人补」作为标准提问。

方法三 · 当设计师直接写代码、PM 直接搭原型：AI Native 团队的质量保障难题

阿里技术的一篇复盘记录了一个正在许多团队重演的转变：AI Native 一度被理解为「让工程师用上更好的 AI 工具」，但很快变成更具体的事——后端借 AI 写前端页面、产品经理搭可交互原型、设计师把界面直接做成代码，过去需要协作才能完成的事情，现在个人就能闭环。提效的代价随即出现：一次 code review 里，一位后端同学提交的前端 PR 满屏 tailwind 类名、原生 input 配四十行 CSS、手写 SVG、组件直接 fetch 后端接口——功能跑起来了，却「不敢合进代码库」。团队因此把「让不同角色用 AI 交付的产物能够被无痛接手、维护和复用」作为转型的正式目标，沉淀规范与工具。

方法论含义：这是对「人人都能做设计/原型」这一乐观叙事的冷静补充。当原型与界面可以低成本地产出，瓶颈会从「做不出来」转移到「做出来之后如何保持一致、可维护、可评审」。对 UX 与研究团队的直接启示是：需要把「AI 产物的可维护性与一致性」显式写进设计规范与评审清单——否则大量各自为政的界面会以「能跑」为标准悄悄绕过设计系统。换句话说，设计系统在 AI 时代的第一价值，可能不是「统一视觉」，而是「让机器和人都能无痛接手」。
