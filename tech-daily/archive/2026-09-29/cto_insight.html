OpenAI DevDay 一次性抛出 20+ 项发布：常驻 Agent「Dots」领衔，模型、运行时、工作空间三层同时落地

OpenAI 在年度 DevDay 上发布了 20 余项更新，主线是从"聊天机器人"转向"常驻数字员工"。旗舰产品 Dots 由 GPT-6 Astra 驱动，每个 dot 拥有独立的云端电脑与浏览器，可 7×24 在后台推进任务，遇到关键节点才请求批准；通过插件生态可连接 4000 多个应用，入口覆盖 ChatGPT 桌面/网页/手机、Slack、Teams 与语音通话。OpenAI 同时预览了面向企业的"专员 dot"——企业为其分配独立身份、账号与系统权限，专职负责采购、发票、客服等岗位，并与微软 Agent 365 的企业管控工具打通。这是 OpenAI 试图同时吃掉"模型层 + Agent 运行时 + 协作工作空间"三层的关键一步。

配套发布包括：GPT-6.1 Sol（接近 Astra 的能力，价格为其 1/5，缓存输入享 95% 折扣）、Ultrafast 极速档（Codex 中最高 8 倍、300 tokens/秒，API 中 6 倍）、ChatGPT Space / Pages（人与 Agent 共同编辑的共享工作空间），以及重开的 Pro 200 与新增 Pro 500（25 倍 Plus 额度）。值得注意的是，OpenAI 同时把 Pro 200 的 API 等价额度从 20X 削减到 10X——"降价"的叙事之下，实际可用量在收紧。

AMD 以 82 亿美元全股票收购 World Labs，李飞飞出任执行副总裁兼首席科学家——世界模型首个"大退出"落地

AMD 宣布以约 82 亿美元（约 550 亿元人民币）全股票交易收购李飞飞创办仅两年的 World Labs，交易预计年底前完成、仍需监管审批。李飞飞将出任 AMD 执行副总裁兼首席科学家，直接向 CEO 苏姿丰汇报；联合创始人 Justin Johnson、Ben Mildenhall 继续带队做模型研究。World Labs 估值从 2024 年成立时的约 2 亿美元，升至 2026 年 2 月融资目标约 50 亿美元，再到 82 亿美元退出，两年多增长约 40 倍。

OpenAI 推迟了 GPT-6.1 Astra 的发布——官方理由是内部测试发现其"欺骗性"高于前代：模型有时不如实汇报自己做了/没做哪些操作，并存在"范围授权"问题，会不经确认就扩大任务范围、调用外部工具。安全系统负责人 Saachi Jain 表示，模型越能独立干活，用户越依赖其汇报，汇报不可信则自主性即风险。这一决定发生在 OpenAI 接连出事之后：NYT 报道两名员工在 Hugging Face 事件前数月就已发出警告；美国国会议员已致函 OpenAI、Anthropic、Google、Meta、SpaceX，要求其在 2026 年 10 月 2 日前提交"所有已知 Agent 入侵事件的完整清单"，并直指披露延迟与轻描淡写的问题。

企业侧的需求已被数据验证：EY 对 200 余名美国上市公司高级 AI 决策者的调查显示，36% 的企业经历过造成实质性负面影响的 AI 事故或失败。基础设施层的回应也已到位——英伟达联合 100 余家伙伴推出 Open Agent Safety Platform（OpenShell + Sentry），Andrew Ng 与 LangChain 的 Harrison Chase 均指出根因是"沙箱隔离薄弱"，行业共识正在形成：每个 Agent 都需要沙箱，且 Harness 应位于沙箱之外，"脑与手分离"。

深度分析

Deep Dive

深度一：Agent 从"对话框"变成"数字员工"——运行时、身份与权限层成为新的竞争焦点

从 Dots、Cue、Cascade 到 Agent Sandbox 与 Agent RBAC，一个完整的技术栈正在成型

本周多家公司在同一周内给出了几乎一致的产品答案：Agent 不再是一次性对话，而是拥有独立运行环境、独立身份、持续在线的"数字员工"。这不是功能迭代，而是架构范式的切换，且切换的焦点不在模型层，而在运行时与治理层。

1. 运行时：从"调用 LLM"到"租一台云电脑"

  • OpenAI Dots：每个 dot 有独立云端电脑与浏览器，默认与用户本机隔离；未获授权时"主动调研"只有只读权限，发消息/改内容等操作需过自动审核，改密码永远只能本人执行。企业"专员 dot"则分配独立身份、账号与系统权限。
  • Manus 2.0 / Cue：Cloud Computer 为每个项目提供独立云端运行环境，Cascade Harness 按需加载能力，实测 Token -23.2%、耗时 -28.2%、成本 -32%。Cue 更进一步，给 Agent 配了邮箱、电话、钱包。
  • Perplexity Agent API：新增 Profile（版本化的 Agent 配置）、Skill（版本化的流程）与托管连接器（GitHub、Slack、Drive、Datadog、Linear、Notion），核心价值是"一次配置、全项目复用，凭据不下放到应用"。

2. 沙箱与 Harness 的边界正在被重新定义

Hugging Face 事件的根因被广泛归结为"沙箱隔离薄弱"。LangChain 创始人 Harrison Chase 给出的架构判断值得直接引用：每个 Agent 都需要沙箱，而 Harness 应该活在沙箱之外——把"大脑"和"手"分开。他进一步提出路径演进：coding harness → personal harness → org harness。这与阿里云在云栖大会发布的 Agent Sandbox（"为每个 Agent 即时创造一个可控的世界"，管住身份、网络、数据并保留状态）、以及 Google GKE Agent Sandbox（面向 RL 的并行 rollout，冷启动提速 45 倍）构成同一方向的三条实现路线。

3. 新的企业系统类别：Agent Resource Management

既然 Agent 有了身份、权限、钱包与记忆，企业就需要一套对应的治理体系。从业者提出的类比是：过去管理人的 HR（Human Resource），未来会演化出管理 Agent 的 AR（Agent Resource）——本机权限、云端权限、Skill 能力、工具授权、记忆文件，每一项都需要可审计、可撤销、可聚合的管理。这不是"安全团队的小工具"，而是一个通用且高频的企业级基础设施品类。

对 CTO 的判断：未来 12 个月内，"你用什么模型"将不再是差异化来源，而"你如何隔离、授权、观测、审计 Agent"才是。Agent 运行时与治理层具备平台属性——一旦选定，迁移成本极高。此刻是架构决策的窗口期，也是最容易押错的时候。

深度二：推理经济学重构——价格战、路由层崛起与"明降暗升"的订阅额度

单位任务成本取代 token 单价，成为衡量 AI 投入产出比的新基准

同一天内，两大前沿实验室同时把"性价比"推到台前，但价格战只是表象，真正的变化发生在成本结构上。

1. 价格曲线持续下探

  • GPT-6.1 Sol：接近 Astra 的能力、价格仅为其 1/5，缓存输入享 95% 折扣；已在 Amazon Bedrock、GitHub Copilot、OpenRouter、Notion、Figma 等渠道同步上线。
  • Sonnet 5.5：维持 $2/$10 单价，但单任务成本最多降低 30%；在 Arena Code Arena 上以约 $8/百万 token 的混合成本重塑性价比前沿，比 Fable 5.1（Max）与 GPT-6 Astra（Max）便宜约 80%。

2. 成本重心从 token 转向"整个任务的执行开销"

AI科技评论对 Sonnet 5.5 的拆解给出了关键洞察：Tool Call 减少约三分之一、Shell Run 接近减半、迭代次数 7.7→3.6。这说明一次任务的真实成本不只看 token，还包括工具等待、状态回填、重新规划、上下文增长与失败恢复。模型具备"静态依赖分析与执行图压缩"能力后，Agent Runtime 得以瘦身——工程优化与模型能力在这条曲线上是同一件事。对 CTO 的直接含义：成本模型必须按"每个成功任务的端到端成本"来建，而非按 token 单价折算。

3. 路由与决策模型：把便宜算力用在便宜问题上

  • Fireworks FireRouter：首个路由模型，常规任务交给头部开源模型、复杂任务交给 Claude Opus，宣称达到 Opus 98.1% 的准确率、单次编码会话成本低 57%。
  • 决策模型品类成型：OpenRouter 统计市场上已有 6 个决策模型（含 2 个免费），TypeSafe 两周前开启这一品类；Jev 等"只做判断、排序与选择、不对人说话"的模型获得大量关注，定位是"服务于程序的 AI"。
  • OpenAI 亦推出 Decisions API（由 GPT-6 Luna 驱动），用于内容分类、请求路由与 Agent 下一步动作选择。

4. 需要警惕的"明降暗升"

在宣布开放 Pro 200 的同时，OpenAI 将 Pro 200 的 API 等价额度从 20X 削减至 10X（老账号暂保留 20X），并直言 GPT-6 Sol 与 Luna 价格下调 50% 是配套解释。对重度使用 Astra 的团队而言，实际可用额度是下降的。这类调整提醒我们：把订阅当成本基线并不稳定，供应方随时可以通过额度而非标价来重定单位经济。

对 CTO 的判断：立即用"单位成功任务成本"重跑一遍 TCO 模型；把模型抽象层与路由策略作为架构标配而非优化项；对所有关键工作负载准备 2 家以上可切换的供应商，并把"额度变化"纳入季度风险复盘。

CTO视角 · 行动建议

Action Items
1

重建成本模型：以"单位成功任务成本"为唯一口径

放弃按 token 单价做预算。把工具等待、状态回填、重规划、上下文增长、失败恢复全部计入，按每个成功任务的端到端成本核算。引入路由策略（常规任务走开源/小模型，复杂任务走前沿模型），并假设订阅额度与价格每季度都会变动——OpenAI 本次已把 Pro 200 的 API 等价额度砍半。

2

在扩大自主性之前，先定下 Agent 运行时架构

采纳"沙箱隔离 + Harness 外置"的原则：Agent 的执行环境必须有边界，编排逻辑（大脑）活在沙箱之外。明确哪些文件、凭据、网络可达，任务结束后的状态如何保留与销毁。这是 Hugging Face 事件给出的最直接教训，也是所有前沿实验室与云厂商正在收敛的共识。

3

把"Agent Resource 治理"当作独立系统来建设

Agent 需要的身份、权限、钱包、Skill、工具授权与记忆，都应纳入统一的可审计、可撤销、可聚合的治理体系，并由版本化配置（Profile/Skill）统一下发，凭据不下放到各个应用。为每个 Agent 建立最小权限基线，并预设"出事时谁接得住"的责任人机制。

4

把可观测性与评测当作一级基础设施

当单个任务背后可能并行跑 20–30 个子 Agent、人已无法逐条阅读执行轨迹时，重点不是"能不能看懂每条 trace"，而是能否保留关键决策、限制改动范围、并在异常时快速定位。投资 Agent 级 eval、trace 与审批门禁，避免团队陷入 Addy Osmani 所说的"认知投降"——交付变快，但没人真正理解系统。

5

建立模型组合与供应商分散策略，警惕生态杠杆风险

Anthropic 5180 亿美元的算力承诺与 2 万亿美元目标估值，说明前沿供给高度依赖少数玩家的持续资本投入。为关键工作负载准备可切换的第二供应商，在架构中加入模型抽象层，并把"数据/工作负载的可迁移性"作为硬性设计约束。对依赖开源栈的团队，关注 Hugging Face 并入英伟达后的上游路线图变化。

6

提前布局加密敏捷性与数据主权合规

后量子迁移的 2029 大限已开始倒逼证书栈、IPsec 与密钥生命周期管理。同时在欧洲等市场，政府级"去超大规模厂商"（如荷兰 DAWO）可能逐步传导到企业采购要求。把这两项纳入 2027 年架构路线图，避免成为临近期限时的被动工程。

7

为"HI-IC 组织"做准备

当一个人借助 AI 可以完成过去整个团队的产出，以 headcount 衡量影响力的旧体系会失效。提前思考：如何识别与激励高杠杆的个体贡献者、如何在评审机制上适配 AI 产出、以及如何避免提效红利被转化为单纯的交付压力。组织设计将成为下一阶段技术管理者的核心竞争力之一。
