01

文档的第一读者，正在从人变成 Agent

Mintlify 联合创始人兼 CTO Hahnbee Lee 在 AI Engineer 分享了一个让内容与体验团队警醒的数字： 过去一年，Mintlify 文档站点上的 Agent 流量占比从约 10% 涨到约 80%。当主要「读者」是 Agent， 页面大小、信息准确性和结构可解析性，开始比视觉设计更影响「阅读完成率」。同一场分享里， Coinbase 的 AI 产品负责人 Lincoln Murr 介绍了把整条业务链 API 化的思路，其 x402 支付标准已产生约 1 亿笔链上 Agent 交易。

这不是孤例。苹果在 Xcode 27.2 中用 JSON 项目配置格式替代传统 plist，明确目标之一就是让 AI 编码智能体更容易理解和修改项目配置，并降低合并冲突。 这提示我们：产品文档、配置文件、API，都需要增加一层「机器可读」的体验设计——它不取代人类可读性，而是与人类可读性并列成为新的验收项。

02

多 Agent 的真正瓶颈，是被低估的注意力

DeepSeek Harness 团队发布 Super-agent 架构：打破 Agent 与单次手动会话的绑定，通过双层架构、事件驱动、异步多信道交互、存算分离与外部 Watchdog， 让一个 Agent 跨会话保持上下文、同时推进多项复杂任务且互不干扰。团队指出，现有主流 Agent 设计难以支撑多任务与团队协作的规模， 多任务上限往往取决于人的注意力，而非模型能力。

这个判断对产品设计的冲击大于对架构的冲击。人类同时能跟进的活跃会话通常只有 3 到 5 个， 因此下一代 Agent 界面要解决的不是「如何展示更多并行任务」，而是「如何让用户建立可控的委托感」： 哪些任务可以放手、进行到哪一步、什么时候需要我拍板、如何一键收回。并行的前提是可观察、可中断、可追责。

03

「做出来」变便宜后，设计的价值转向「判断什么值得留下」

Shopify 产品设计工作室负责人 Marvin Schwaibold 的工作流很有代表性：他仍在 Figma 里思考布局， 但会很快转到 Codex、Claude Code，把想法做成能运行的演示，再回头修改。一个轮播动画他尝试了 91 次， 「因为 Codex 不会生我的气」；而一片草地的小问题，暴露出的是五轮对话之前的错误。

他反复强调，现在做出东西已经不是问题，更难的是严格挑选——决定继续推进什么、采用什么，以及哪些细节值得保留。 当生成成本趋近于零，设计能力的分水岭从「会不会画」转向「能不能判断」：能不能识别真问题、能不能拒绝看起来完整但体验空洞的方案、 能不能把设计决策说清楚。

04

设计系统需要一条性能预算，像无障碍一样写进验收标准

React 中文周刊 #297 介绍了 Den Odell 对 MUI、Mantine、Ant Design、React Spectrum 等十套设计系统的压测。 在 CPU 降速 4 倍的条件下打开包含 249 个国家的下拉框，不同系统表现差异明显，React Spectrum 逐个测量选项的方式尤其拖慢 UI。 作者的主张很直接：性能应该和无障碍一样，排在设计系统团队的优先级清单上。

对设计系统而言，组件规范不只是颜色、间距和状态，还应包含交互延迟与渲染成本的上限。 设计评审里可以增加三个问题：这个组件的 P95 交互延迟是多少？在低端设备与降速网络下是否仍然可用？有没有为动画和动效设置「可关闭」的降级路径？ 性能不是工程收尾工作，而是体验设计的一部分。

05

具身智能的「最后一米」，暴露了实验室与现场之间被忽略的情境差

量子位报道，某老牌便利店引入的售货机器人在实验室锤炼上万次，到了货架前仍然会摔瓶子，项目最终折戟。 CSDN 对 2026 长沙 1024 程序员节的观察也指出，具身智能真正要打通的是「能思考 → 能操作 → 能实用」的完整链路， 而最后一环往往卡在真实环境的杂乱、光照、动线与人的不可预测上。

这与用户研究的老问题完全同构：实验环境里验证的是能力，现场验证的才是体验。 情境变量不是噪声，而是需求本身。任何在受控环境里拿到漂亮数据的方案，都应该追问一句——换到用户真实的生活现场，哪些条件会变？

02

设计趋势洞察

两个正在发生的转向：交互退到情境之后，以及「反 slop」成为新的质量语言。

Trend 01 · Ambient Interaction

当界面退到身体与情境之后：Ambient Interaction 的三条线索

过去我们默认的交互路径是：打开一个 App，进入一个界面，完成一个任务，再退出。今天同时出现的三条线索，正在把这条路径拆开。

线索一：Personal Agent 开始「找身体」

硅星人Pro 的观察很准确：Personal Agent 火了以后，整个世界都在忙着给它找身体。Meta 在 Muse 之后推出 Muse Charm—— 一台带屏幕、摄像头、麦克风、扬声器和 5G 的独立硬件；MistLabs 的 Ambi 则先把 Personal AI 做成跨 iPhone、Mac 和 Apple Watch 运行的软件， 让 Agent 在现有设备里积累对用户的理解，再计划推出独立可穿戴硬件。逻辑并不复杂：纯软件 PA 再聪明，还是像住在聊天框里的幽灵， 你不把文件递给它、不开放日程，它就不知道你此刻在做什么。戒指和项链可能是它的眼睛、耳朵和皮肤；带本地算力、长期记忆和执行环境的主机， 才更接近一具真正可以让 Agent 住进去的身体。

线索二：输入方式正在被重新发明

极客公园「造物 100」第 12 期给出了几个很有代表性的样本：Sabi 做不需要手术的脑机接口帽子，想用脑电信号把「你想说的话」直接转成屏幕上的字，已拿下 5000 万美元融资； TypAir 把键盘缩小成手势识别器，让双手成为新的键盘；TRYX 的 VESTRA VISION 反过来在每个按键下面装一块屏幕，敲一下才显示字符。 与此同时，苹果发布了第一款带触控屏的 Mac——14 英寸 MacBook Pro，国行 22999 元起，11 月 6 日开售。 十四年前乔布斯曾说触屏不适合竖着摆的电脑，如今这条判断也被推翻。输入不再只有「键盘 + 鼠标」一种标准答案。

线索三：屏幕边缘成为 glanceable 的轻工作区

少数派介绍的 Dots 把 MacBook 刘海变成信息枢纽：音乐控制、待办、笔记、番茄钟、文件暂存、截长屏、格式转换、白板都可以放进去， 每个小功能有多种视图样式、可调信息密度，光标移到刘海即展开，不用时自动收起。它把「多任务」从并行窗口变成「随手可取」， 用空间复用和渐进披露替代了频繁的进入与退出。

三条线索指向同一件事：交互正在从「显式进入界面」转向「在情境里被轻量地服务」。界面没有消失，只是退到了视线边缘、身体表面和环境的背景里。

对设计团队的四个提示

  • Glanceability over navigation：信息要在视线边缘就能读取，减少进入/退出成本。设计稿里应该画出「扫一眼能获得什么」，而不只是「点进去能看到什么」。
  • Context as input：传感器、日历、位置、生理状态成为隐式输入。设计必须处理「用户没有明确告诉我」的数据，并给出纠错与覆盖的入口。
  • Progressive disclosure & reversibility：刘海下拉、按需展开、自动收起，本质上都是「不打断」与「可退出」。Ambient 不等于无处不在，而是随时可以消失。
  • Trust & consent by design：连续数据采集必须可解释、可暂停、可删除。否则「贴身」会迅速变成「侵入」，这是 ambient 产品最大的体验风险。
实践建议：下一次做多端或多设备方案时，先画出用户一天中的「情境切换点」，再决定哪些能力应该出现在锁屏、刘海、手表或耳机里。不要从「我们有几个端」出发，而要从「用户在哪个瞬间需要它」出发。

Trend 02 · Anti-Slop

反 Slop：当「看起来像成品」不再稀缺，设计判断力成为新护城河

AI 生成把「平均水平的完成度」变得极其廉价。于是用户开始用一个新的词来判断质量：这是不是 slop？ 本周有三条看似无关的信息，其实在说同一件事。

第一条来自开发者社区。Ding 推荐了一个开源的去 slop skill——Damir Sokolovsky 把自己的 unslopping 流程做成了免费的 Claude skill， 可用于 landing page、dashboard 和移动应用。它流行的原因不是技术复杂，而是它承认了一个事实：AI 生成的界面很容易「像那么回事」， 但缺少真正的信息结构与设计意图。

第二条来自 HP 总裁 Faisal Masud。他在 Product School 的访谈里说得很直接：如果你没有自己的想法、什么都依赖 AI，你不会真正重要。 他还提到团队 all-in AI 后会经历一个「slop 阶段」——你会预期它先升后降，而他仍在等「降下来」的那部分到来。

第三条来自 Karpathy 的周末项目 HackerTube。他受不了 YouTube 的推荐，于是用 Claude 把 20 年 HN 的 4300 万条评论筛成 6454 个反复被推荐的视频， 做了一个无需登录、状态只保存在本地浏览器会话里的观看页。他最得意的一个细节是：缩略图取自视频中段的代表性画面， 而不是「超级 A/B 测试优化过的」用户上传封面。无独有偶，HN 摘要提到 Vitalik Buterin 用 Firefly 绕开 X 推荐流， 并连续 100 天默认关闭蜂窝连接、依赖 Wi-Fi 与本地工具。用户对「被算法安排」的反感，正在变成具体行为。

AI 让「生成」变便宜，却没有让「判断」变便宜。反 slop 不是反 AI，而是要求团队把品味、意图和取舍重新说清楚。

一份可落地的 Slop 审查清单

  • 模板化文案：是否出现大量「赋能」「无缝」「一站式」却无法指向具体用户任务的句子？
  • 装饰性智能：动画、渐变、玻璃拟态、AI 助手气泡，是为理解服务，还是为了显得先进？
  • 假个性化：所谓「为你推荐」是否只是把同一个内容换个标题？用户能否感知到差异？
  • 可删除性测试：拿掉这个模块，用户任务是否仍然完成？如果答案是肯定的，它可能只是 slop。
  • 来源与证据：信息是否有出处、时间与可追溯的证据？这既是内容质量问题，也是信任设计问题。
实践建议：在设计评审里增加一个固定环节——「删掉什么」。让团队明确说出哪些细节值得保留、为什么；同时把「拒绝 A/B 优化过的注意力陷阱」写进设计原则。Karpathy 的缩略图选择，本质上就是一次产品级的品味声明。

03

产品体验点评

两个案例，一个关于「控制感」，一个关于「不打断」。

案例 01 · 订阅产品

ChatGPT × Codex 合并额度：一次典型的「价值感知」改版

事实

从 12 月起，ChatGPT Plus、Pro、Business 三档付费计划的用量额度将在 ChatGPT 与 Codex 之间共享。 额度统一按 token 计算，消耗取决于所选模型与任务复杂度；唯一不受影响的是 Instant 聊天，它完全不占用共享额度。 OpenAI 给出的理由是正在把 ChatGPT Work 的智能体能力并入 ChatGPT 主体验，并预计大多数用户不会受到太大影响。

背景是：过去四周 Codex 用户几乎每隔一天就收到一次额度重置，Tibo 的「28 连更」与「第 27 天：已存 1/2」成为社区梗。 合并公告发布后，Tibo 推文下骂声一片，AINLP 直接用「天怒人怨」来形容用户反应，数字生命卡兹克则写下「无限聊天的时代结束了」。

用户痛点

订阅用户的心智模型是「两个产品、两份配额、可预期」。改为共享池 + token 计量后，重度用户失去了预算确定性， 出现「普通聊天也要抢编程额度」的焦虑；Instant 例外又进一步增加了规则复杂度。 用户并不只是心疼钱，而是不知道下一次操作会花掉多少、还剩多少、什么时候重置。

设计洞察

这不是一个定价问题，而是一个控制感问题。当产品从「无限使用」转向「计量使用」，用户需要一套新的心智模型： 什么动作贵、什么动作便宜、如何提前知道、如何在超支前被提醒。如果这些信息只藏在帮助文档和设置页里， 用户就会用「被剥夺」来理解这次改版。

实践建议

  • 把用量可视化前移到决策点：在输入框旁显示本次请求的预估 token 与剩余额度，而不是只放在设置页。
  • 提供预算护栏：按项目或按天设上限、软阈值提醒、一键降级到轻量模型。
  • 变更沟通用「用户损失」而非「公司理由」叙事：明确哪些场景不受影响，给出迁移期补偿或过渡额度。
  • 把 Instant 的「免费」变成清晰的产品分层，而不是藏在文档脚注里的例外。
一句话：当 AI 从「无限聊天」走向「计费聊天」，产品设计要从「鼓励多用」切换到「帮助用户有意识地用」。

案例 02 · Ambient UI

Dots：把 Mac 刘海变成「抬眼即可用」的微工作区

事实

少数派介绍的 Dots 把 MacBook 刘海区域做成信息枢纽，可放置音乐控制、待办、笔记、番茄钟、文件暂存、截长屏、格式转换、白板等功能。 每个小功能都有多种视图样式、可调信息密度，用户只勾选自己需要的；光标移到刘海即展开，不用时自动收起，不影响正常操作。

用户痛点

高频小任务——看下一场会议、切歌、等 Agent 跑完切回终端——往往需要反复打开 App、在 Dock 里找图标。 真正被消耗的不是操作时间，而是「进入 / 退出」带来的注意力切换成本。刘海区域长期闲置，恰好是一个被浪费的体验空间。

设计洞察

Dots 的价值不在功能多，而在「空间复用 + 渐进披露」：把屏幕边缘的闲置区域变成一层轻量上下文，用 hover 代替点击进入， 用自动收起保证可退出。它把「多任务」从并行窗口变成「随手可取」，这与前文 ambient interaction 的方向一致。

风险与建议

  • 发现性：刘海区域本身不可见，需要首次引导与可发现的 affordance，例如轻微露出或快捷键提示。
  • 信息过载：可自定义是优点也是负担，建议提供「场景预设」（写作/会议/专注），而不是只给一堆开关。
  • 可访问性：hover 触发对键盘用户与运动障碍用户不友好，应提供快捷键、常驻模式与屏幕阅读器语义。
  • 跨设备一致性：若未来扩展到 iPad/iPhone，需要先定义「glance layer」的统一语义，避免每个端各做一套。
一句话：好的 ambient UI 不是把更多东西塞进边缘，而是让用户在需要的那一刻，刚好看到需要的那一点。

04

研究方法论

从「答对」到「答得出证据」，以及 AI 参与研究时必须守住的边界。

Method 01

把 Eval 思维带进用户研究：不要只看「最后答案」

AI 安全研究者 Ramakrishnan Lokanathan 在 AI Engineer 的分享「If Your AI Scores 100%, Your Eval Is Wrong」中， 给出了一套可迁移到研究流程的评估框架：先定义「最雄心勃勃的成功」；测试工作流的每一步而不只是最终答案； 自动检查、人工评审与对抗性测试结合；对「曾经有效」的能力做回归测试，防止升级破坏旧体验；把真实用户的失败案例转化为新的测试用例。 他还开源了 eSlams，让模型互相对弈国际象棋、围棋与扑克，观察推理过程。

对用户研究的启示是：访谈分析、可用性测试、问卷编码同样容易犯「只看结论」的错。可以把研究交付物拆成「证据 → 判断 → 建议」三段分别验收： 证据是否可溯源、判断是否有反例、建议是否可执行。每次产品迭代后，把上一轮的用户失败场景重新跑一遍，建立「体验回归测试集」。

  • 研究计划阶段：写下「最理想情况下，我们希望用户能完成什么」，而不只是「我们要验证什么」。
  • 执行阶段：记录任务每一步的卡点，区分「用户不会」与「界面没让人学会」。
  • 交付阶段：每条洞察附上原始片段与反例，并标注下一次迭代时要回归验证的失败场景。

Method 02

从「答对」到「答得出证据」：EvaOmni 的全模态评测给研究溯源的启示

上海交大、复旦与腾讯优图联合开源 EvaOmni 基准，包含 392 段视频、1027 道人工标注问答，覆盖 15 种细粒度能力。 它要求模型不仅选择答案，还要分别返回支撑答案的音频与视频时间区间，首创「答案 + 视听证据定位」双重评测机制。 对 24 个 Omni LLM 的评测显示，Gemini3.7-Flash 的答案准确率达到 79.4%，但双模态精确定位得分仅 35.1%， 与人类专家的 94.3% 相差 59.2 个百分点。

一个能「猜对」的系统，未必真的看见了证据。用户研究中的 AI 辅助分析也应采用同样的标准： 每条洞察附带原始访谈片段、时间戳、受访者编号与反例；区分「模型总结得像」与「证据支持得住」。 在合成用户、AI 访谈等新方法里，这直接关系到研究的可信度与伦理边界。

  • 要求 AI 分析输出「结论 + 证据 + 位置」，而不只是结论摘要。
  • 在编码与主题归纳中保留反例样本，避免模型把低频但关键的声音抹平。
  • 把「证据定位准确率」作为 AI 研究工具的内部评测指标之一。
