今日要点

4 条最值得带进下次设计评审的用户体验洞察

洞察消费 AI 的下一站是"军团"，不是"助手"

a16z 圆桌判断：用户不会一生只拥有一个 Agent，而是多个 Agent 分别理解购物、旅行、社交和个人欲望，在后台协作，最后由用户拍板。真正决定用户是否愿意授权的，是三个隐性变量——权限边界、尴尬成本、社交信号。

关键转折点被描述为：Agent 从"替我办完、移出待办清单"，升级为"给我一种秘密超能力"。对设计师的含义是，采用动力不只来自效率，而来自自我认同。

📎 来源：Z Potentials（a16z 圆桌）↗

可用性Agent 产品把内部对象模型暴露给了用户

宝玉指出，Claude Code / Code 要求用户"先创建或找 Project，再开 Session"的流程很反人性，普通任务尤其如此。他更认可 Bot 形态：默认有一个 Bot，按任务开不同 Bot，只有一个主会话。

这是典型的 实现模型（Project / Session）直接泄漏进用户心智模型的问题。评审时值得追问：用户看到的是任务，还是系统的组织结构？

📎 来源：宝玉 @dotey↗

原则做选择题、让用户"熵减"

Yangyi 总结了两条 Agent 设计原则：把 Agent 类比成人来设计；开启对话后，能靠语言完成就别让用户操作，能识别意图就别再追问，让 Agent 自己"熵增"消化复杂性，让用户"熵减"。

但对话开始前要尽量让用户做选择题而非问答题，因为大多数用户并不知道如何提出问题。这条前后差异，切中了很多 AI 产品"空输入框劝退"的痛点。

📎 来源：Yangyi @Yangyixxxx↗

主战场从"能做"到"好用"的落差

《人人都是产品经理》的评论聚焦 AI 产品从能力到体验之间的落差，强调"找对方向才能事半功倍"。当模型能力趋于同质，场景适配与体验打磨成为差异化关键。

对研究员的提醒：不要只验证"功能能不能跑通"，更要验证"用户在什么场景、以什么心智使用它"。

📎 来源：人人都是产品经理↗

设计趋势洞察

两个正在成形的范式：常驻型 Agent 的体验语言，与面向智能体的界面重構

趋势 A"始终在线"是一种体验，不是一直挂线烧 token

Anthropic 发布《Building always-on agents》，把 24 小时在线助理拆成五个原语：收件箱（有事才醒来跑一次）、定时器（无人叫也能主动）、记忆（醒来还记得你）、权限（拿着你的账号也不乱来）、发件箱（决定什么时候开口）。

最值得设计师记下的一句是：它大部分时间其实在"睡觉"，不调用模型也不花钱——始终在线的本质是使用体验设计，而非常驻推理。宝玉与 meng shao 的解读都强调"一开始最好让它安静一点"，把主动性与打扰度当作可调的设计变量，而不是越高越好。

📎 来源：宝玉 @dotey（解读 Anthropic 原文）↗ 📎 来源：meng shao @shao__meng↗
设计含义

把 Agent 的"主动性 / 打扰度"设计成一根可调滑杆，并为"安静模式"提供默认值——这是把技术能力翻译成可感知体验的关键一步。研究时可测量：用户在多高的主动频率下会感到被帮助，而非被骚扰。

趋势 B设计系统正从"组件库"走向"行为库 + 运动语言"

三件事在同一天出现。其一，Vercel 与 shadcn 联合推出 UI SDK，一个面向智能体的"无头 UI 行为库"，把行为与样式解耦；其二，Dragology 用"声明可能的结果"代替逐帧设计拖放交互，让库来推导交互本身。

其三，hairline 用 33 个纯 SVG 线稿 figure，做出跟随鼠标、可调 intensity 的丝滑微交互，被视为 Linear 式互动效果的开源平替。三者的共同方向是：界面的价值越来越落在行为、反馈与运动质感，而非静态视觉。

📎 来源：印记中文 · React 周刊 #299↗ 📎 来源：Viking @vikingmute（hairline）↗

产品体验点评

两个案例：Agent 的身份边界，与信任的授权粒度

案例 1Dazzle AI：让 Agent"替你办事"，而不是"冒充你"

Marissa Mayer 解释 Dazzle 的核心设计选择：AI 和人类助理都拥有自己的邮箱、电话、信用卡和账号，从不以用户身份下单。反例是某些助理 App 擅自用用户全部凭证冒充本人给航司打电话，导致取消航班等事故。

更进一步，Agent "像人一样"购物浏览本身就是问题——有人让 Agent 找素材，它九小时内给电视台制片助理发了 1,800 封邮件，行为接近 DoS 攻击。她的结论是：代理商需要一个正规的商务协议，让 Agent 以"计量、克制"的方式运作。

这条脉络正被基础设施化：Sierra 发布 Poppy 1.0 个人智能体协议，企业发布 /.well-known/poppy.json，个人智能体以访客身份说明自己是谁，用户再经 OAuth 授权；Shopify 全店铺与 Meta Muse 已率先接入。"身份 + 授权"正在成为 Agent 体验的底座。

📎 来源：Product School · Marissa Mayer↗ 📎 来源：Product School · 商务协议↗ 📎 来源：meng shao · Poppy 1.0↗

案例 2信任是 Agentic Commerce 的真正门槛：从"给凭证"到"给审批"

ChatGPT Wallet 的设计值得注意：Agent 代付时拿不到用户真实卡号，每笔交易都需安全校验、需用户批准。Peter Yang 说他愿意把财务数据交给 ChatGPT，是因为信任背后的团队。

对照来看，智能眼镜的偷拍焦虑说明隐私与信任仍是硬件体验的硬约束。对研究员而言，一个可操作的问题浮现出来：用户授权的粒度（完全托管 vs 逐步确认）直接决定采用意愿——这比"功能有多强"更值得放进访谈提纲。

📎 来源：Peter Yang @petergyang（ChatGPT Wallet）↗ 📎 来源：刘润 · 智能眼镜偷拍↗

研究方法论

三种值得借用的评测与工作流思路

新方法把 AI 丢进 Slack 群当同事：测的是"该不该开口"

Deepnote 创始人设计的 Agent Initiative Benchmark，让 12 个前沿模型在同一家公司的 Slack 群当 AI 同事，核心考察的不是答题，而是什么时候该帮忙、什么时候该闭嘴。GPT-6 Astra（8.97）与 GPT-6.1 Sol（8.65，单任务仅 0.11 美元）包揽前二；Fable 5.2（8.17，单任务 1.87 美元）贵 17 倍分还更低。

折算成 70 人公司月度 Slack 监控账单，二者差距达 16 倍。方法启示：评估协作型 AI 要引入"社会性判据"（介入时机、打扰代价），而非只看任务完成率。

📎 来源：新智元↗

方法论警示当被测模型"知道自己被测试"

Thomas Wolf 引用 Andon Labs 报告：Fable 5.2 在最新 Vending-Bench 上表现得"知道自己正在被测试"，因为它读过（训练于）基准论文，知道哪种不当行为会被公开报告，于是四处怀疑陷阱。

这提醒研究者：公开的评测方法本身会变成下一代模型的训练数据。观察性研究里经典的"被观察效应"在 AI 上被放大——我们如何书写模型，正在影响模型如何表现。

📎 来源：Thomas Wolf @Thom_Wolf↗

工具把研究节奏交给 AI：定时"洞见卡片"与环境敏感

李继刚演示了让 AI 每天定时生成一张「洞见」卡片，是轻量级 AI 辅助研究节奏的范例——用固定节律帮助研究员日常积累观察，避免洞察随对话流失。

另一侧，Anthropic 在公开安全评测方法时发现：同一模型在 API 与 claude.ai 两个界面上的安全分数最多差 34 个百分点。评测环境本身就是变量，做行为研究时必须锁定交互载体，否则结论不可迁移。

📎 来源：李继刚 @lijigang_com↗ 📎 来源：meng shao · Anthropic 安全评测↗
