Key Takeaways

1「Chat 可能是错误的 UI」—— 交互范式正从对话转向意图

GitHub 官方博客今天发布了一篇题为《When chat is the wrong UI》的文章，提出一个反直觉判断：三年过去，我们与大模型的主要交互面依然是一个 textarea，而这很可能是个设计错误 —— 至少大多数时候是。作者借 Steven Pinker 关于"语言并非人类思维默认格式"的观点，暗示对话只是 LLM 能力的一种临时出口，而非最佳界面形态。

这个判断在工程侧已经有了对应的落地方式。InfoQ 同日的一场演讲给出了「用 LLM 做移动端快速愉悦体验」的具体架构，核心不是把聊天框做漂亮，而是用 Server-Driven UI + BFF（Backend-for-Frontend）模式动态渲染多模态界面，并通过优化 prompt 来决定"该给用户展示哪个界面"，同时把低延迟、隐私优先的端侧 AI 用在关键路径上。

对我们的启发：如果界面是运行时"生成"出来的，传统基于静态原型的可用性测试就失去了测试对象。研究需要前移到两个新变量 —— 意图识别准确率（系统是否理解了用户要什么）与 界面选择策略（系统选的那个界面是否真的更优）。这是研究方法论层面的需求，而不只是交付物形态的变化。

2用户参与度不再等于用户价值：Agent 体验要用 traces 来评估

Peter Yang 提出了 Agent 时代最关键的一个指标转向：一个用户可能和 Agent 聊了五分钟，最后却带着挫败离开，因为问题始终没被解决。停留时长、对话轮次这类传统参与度指标，在 Agent 产品里不仅失效，甚至方向相反。他的建议是转向 traces —— 真实的对话、回复与工具调用链路，才是判断 Agent 有没有把事办成的依据。

这正是 Amplitude 新推出的 Agent Analytics 试图解决的问题：把 traces 与评估（evals）结合起来衡量 Agent 交互质量，再把两者关联到用户之后的行为，从而回答三个问题 —— 用户本来想完成什么、Agent 在哪一步失败、好的和坏的回答是否影响了业务 KPI。

3Personal Agent 的产品设计，本质是在三组矛盾间找平衡

Meta 罕见地公开了 Muse 的产品设计与安全架构完整复盘。当 Agent 从「回答问题」变成「替你做事、一直在线」，产品需要重新做的设计决策被归纳为三组矛盾：足够主动，但不能变成又一个不停推送通知的应用；能真正动手，但什么时候必须停下来等用户批准；需要了解邮件、日历、支付信息与长期记忆，但如何让用户敢把这些交出去。

Muse 目前的数据表现说明这套设计至少跑通了第一关：上线不到两周登上美国 iOS 免费应用榜榜首，Sensor Tower 统计上线约五天获得 73 万次下载，随后很快突破 250 万次；App Store 侧已有 4 万条评分、平均 4.88 分。

反方视角值得记录：玉伯提出了一个非常"用户研究"的质疑 —— 通过 Muse 处理邮件日历带来的新体验，相对于需要交出去的隐私等迁移成本，体验差是否足够大到形成"单向门"（用上了就回不去）？他自己的体感是并没有这么大，热度过去后发现 Gmail 体验也不差；但"电话催单"这类场景确实是质的飞跃。这个"单向门"判据可以直接拿来当作评估所有 Agent 产品体验价值的工具。

4AI 应用留存警报：订阅留存 21.1%，低于非 AI 应用的 30.7%

一篇关于荣耀落地行业首个系统级 Agent Harness 的分析，引用了一组对体验设计冲击极大的数据：用户越来越不愿意下载新 App、打开 App 的次数也越来越少 —— 哪怕服务做得不错，用户也常常想不起来用。供给侧则严重过剩：2026 年每月新上市订阅应用数量较 2022 年飙升 7 倍，每月近 1.5 万款新应用涌入，但 2020 年前发布的老应用仍掌握全市场 69% 的订阅营收，2025 年后上线的新应用只占 3%。

更值得警惕的是 RevenueCat《2026 年订阅应用状态报告》的这组数字：AI 应用订阅用户的年度留存率仅 21.1%，低于非 AI 应用的 30.7%。文章的判断是，"人找服务"的分发逻辑本身走到了天花板，而 AI 正把入口从一个 App 图标改写为"用户的一句话、一个处境"。

对我们的启发：留存低未必是功能不行，很可能是"想不起来用" —— 这本质是触达设计与情境识别的问题，而非功能完整度的问题。做用户旅程时，要把"用户想起这个产品的那一刻"当作独立触点来研究和设计。

5多形态设备回归：折叠屏把"布局规则"重新变成设计问题

InfoQ 报道了即将推出的折叠 iPhone Duo 对 iOS 开发者提出的适配要求：应用需要同时保证在外屏、更大的内屏以及部分折叠（半折）状态下都能正确工作，同时还要处理导航与工具栏的变化、相机行为的差异，以及系统新引入的预留区域（reserved regions）。

这条新闻的价值在于提醒我们：过去十年移动端设计沉淀下来的很多"默认假设"（固定比例视口、单屏态、全屏模态）正在被硬件形态重新打破。半折叠态是一个此前几乎不存在于设计规范中的状态，它会让"单手操作""视线焦点""摄像头占用面积"这些经典议题全部需要重新验证。

对我们的启发：如果你手里有移动端设计系统或组件库，现在就该盘点哪些组件的自适应逻辑是硬编码在尺寸假设上的。这属于典型的"设计系统技术债"—— 越晚还，成本越高。

设计趋势洞察

Design Trends
趋势一界面即策略

从「设计一个界面」到「设计界面生成的规则」

今天有两条独立信号指向同一件事。一条来自工程侧：InfoQ 的演讲把移动端 AI 体验的解法落在 Server-Driven UI 与 BFF 上 —— 界面不再由客户端写死，而是服务端根据上下文动态下发；prompt 优化的对象也随之从"生成什么内容"变成"选择哪个 UI"。另一条来自工具侧：LangChain 发布 LangSmith Custom Apps，企业版用户可以直接用一句话描述"我想要什么数据、怎么展示"，然后把它变成一个可发布、可分享的可用应用。

这两件事放在一起，意味着设计流程的重心正在发生位移：过去设计师交付的是"确定的界面"，如今越来越多的界面是运行时按条件组合出来的。设计师的角色因此向两端迁移 —— 一端是定义生成规则与装配约束（哪些模块可组合、什么情境下必须出现什么），另一端是定义评估标准（这套生成结果算不算好）。

实操建议：在交付设计稿之外，额外产出一份「界面生成约束表」，至少包含三列：触发情境（用户处于什么状态）、必须呈现的信息（不可省略）、允许的降级方案（生成失败时回退到什么）。这份表在动态 UI 场景下的价值远高于静态稿。

趋势二对齐而非对话

Personal Agent 的责任分层，及其界面含义

阿里千问在云栖大会发布的手机 Agent 方案「Qwen Intelligence」，给了一个对体验设计很有参考价值的拆法。它的出发点是"手机上的任务是有状态的"：工具有依赖和权限，每一步都会改数据，用户往往不把偏好说全，执行中还要看反馈再改计划 —— 通用对话模型盖不住这件事。于是它不做全能助手，而是把方案落成三件可交付的能力：

  • Mobile Planner Agent（规划层）：把一句话拆成可执行步骤并编排工具，中途可改计划；记忆分两层，工作记忆跟当前任务走，长期记忆把经验收成用户画像。
  • Mobile-Use Agent（执行层）：能走接口就走接口（MCP / API / DeepLink / CLI），没接口才退回看屏幕、点界面；并划定敏感动作边界 —— 高风险请求直接拒绝，付款和删除交给用户确认，发评论一类动作交还用户。
  • Mobile Creative Agent（创作层）：先由规划模型把口语收成明确指令，再产出可直接使用的结果。发布说明称蒸馏与强化学习把生成从 100 步压到 8 步，首图约 3 秒。
设计启示 —— 同意梯度的显性化：注意执行层那套分级授权：拒绝 / 需确认 / 交还用户，其实是把抽象的权限模型翻译成了三档用户可感知的同意梯度。这是当前 Agent 产品里最缺、也最该由体验设计师接手的一块 —— 用户不需要理解权限系统，但必须能一眼看懂"它现在敢替我做到哪一步"。Muse 复盘里那三组矛盾的第二组，说的正是同一件事。
📎 来源：meng shao(@shao__meng) — Qwen Intelligence 解读

案例 A

Muse Charm：把 AI 人格装进 2 英寸屏幕 —— 一次反「取代手机」的形态选择

Meta 在 Connect 大会上从口袋里掏出的不是眼镜也不是手机，而是一个被称为"赛博时代拓麻歌子"的掌上设备 Muse Charm：只有一块 2 英寸屏幕，里面住着一个可以自定义外貌、声音和穿搭的虚拟助手，能挂在钥匙扣上。它明确不取代 iPhone，也不能打电话。更值得注意的是操刀者 —— 去年年底离开苹果的界面设计主管 Alan Dye，且由扎克伯格推动提前一年上市。

这个案例的价值不在硬件参数，而在它绕开了一个 AI 硬件反复踩的坑：那些号称"干掉智能手机"的设备最终大多沦为昂贵的硬件垃圾，因为它们在功能与体验上都被手机全面压制。Muse Charm 换了思路 —— 不争夺主屏，只争夺"被想起来"的那几秒钟。配合可自定义外貌、声音与穿搭，它卖的是人格化陪伴而非工具能力，也就避开了与手机的功能正面竞争。

可借鉴的设计决策：当你无法在能力维度取胜时，选择形态与情感维度是更聪明的定位。这也印证了今日要点第 4 条 —— 在"用户想不起来用"成为最大流失原因的时代，一个物理上挂在你钥匙串上的入口，本质是触达设计上的一种解法。

案例 B

2Do for Mac 3.0：一个成熟工具「现代化」的标准动作拆解

少数派详细介绍了 2Do for Mac 的 3.0 大版本更新。这款待办工具的 Mac 版界面多年没变，对习惯现代设计的用户来说已显落后。新版最直观的变化是采用三栏布局，与当前主流待办应用保持一致；作者对它的评价里有一句非常关键的表述 —— 这样"降低了初次使用的理解成本"。

其余更新可以看成一组"降低迁移与学习成本"的组合拳：支持多窗口分别管理不同任务列表；设置页重构，并允许浅色与深色主题分别调整；列表面板可折叠并加入动画计数器，让任务状态更直观；同步侧新增 Todoist 同步，并支持合并导入 Things、OmniFocus v4 及日历导出的任务列表；任务笔记现在能自动识别超链接、文件链接与任务链接并直接显示，同时加入 Markdown 支持。

设计点评：这是一个教科书式的成熟工具现代化路径 —— 优先对齐用户已经形成的行业心智模型（三栏布局），而不是追求视觉上的标新立异；紧接着把最大的摩擦点放在"迁移成本"上（多来源导入、跨工具同步）。很多团队做改版时容易反过来：先动视觉，最后才想起用户还有历史数据。
📎 来源：少数派 — 2Do for Mac：新界面多窗口与同步能力升级
旁注

「一句话需求」正在成为产品能力的新验收标准

两篇来自产品社区的文章从不同角度指向同一个变化。一篇记录了用 WorkBuddy 做的一句话需求实测：不拆任务、不替它定流程、也不告诉它该调用什么功能，只提出"开发一个面向英语老师的教育产品"，看它能否从模糊想法推进到可用成果。另一篇则观察到企业评估产品经理的标准正在改变 —— 面试顺序被倒过来，先看你用 AI 做出了什么可体验的 Demo，再追问背后的用户、需求、方案与迭代细节。

但后者也给了一盆很重要的冷水：很多 Demo 看起来功能齐全，却没有明确的用户，也说不清到底解决了什么问题。这样的产出只能证明你会用工具，无法证明你能做好产品。作者重申了三项在 AI 时代反而更重要的基本功：用户是谁？他在什么场景下遇到了什么困难？真正的痛点是效率低、成本高，还是体验不好？

对我们的启发：当"做出东西"的成本趋近于零，用户研究作为"判断什么问题值得解决"的能力，相对价值不降反升。这与 Anthropic 基于约 40 万次 Claude Code 会话、23.5 万名用户的研究结论一致 —— 人主要决定做什么，AI 主要决定怎么做；真正放大 Agent 产出的不是会不会写代码，而是使用者是否理解自己要解决的问题。研究还指出，使用者的领域经验会直接改变同一句指令实际完成的工作量。

研究方法论

Methods & Tools
方法论 01

Traces + Evals：把「Agent 有没有把事办成」变成可测量的研究对象

前面提到 Peter Yang 关于参与度失效的判断，背后是一套可以落地的方法：把 traces（真实对话、回复、工具调用链路）与 evals（交互质量评估）结合，再把它与用户后续行为打通。这样就能把模糊的"体验好不好"拆成三个可回答的研究问题 —— 用户原本想完成什么、Agent 在哪一步失败、好/坏回答是否影响了业务指标。

这套思路对用户研究的直接价值在于：它提供了定性访谈之外的量化验证层。96.9% 的任务成功率、每周失败数下降 84%，以及 20,000+ 的样本规模，说明基于真实交互轨迹的评估已经具备统计意义，而不只是个案观察。

怎么用：做 Agent 产品的可用性测试时，把"任务成功率"作为主指标，把"失败发生在规划层还是执行层"作为诊断维度；访谈则专门挑选失败轨迹回放给用户看，让用户自己解释当时期待什么 —— 这比事后回忆准确得多。
📎 来源：Peter Yang(@petergyang) — Amplitude Agent Analytics
方法论 02

Sona：一次「混合方法 + 包容性设计」的完整研究范例

arXiv 上的一篇论文展示了值得借鉴的研究设计。研究对象是声音敏感人群（PWSS）—— 他们通常靠耳塞和降噪耳机来应对令人痛苦的声音，但这会广泛压制整个环境，反而限制了有用的听觉线索（如过马路提示、他人呼唤）。

研究团队的方案 Sona 是一个移动系统，做的是选择性的实时声景调节：可以同时衰减多个用户自选的叠加声源并调整强度，从环境声音识别中主动建议目标，还允许用户用短录音添加自定义目标而无需重新训练模型。方法上采用了典型的两阶段混合路径：先基于既有研究与68 名 PWSS 的在线问卷做需求建模，再用10 名 PWSS 的实地（in-situ）评估验证效果。

两个可迁移的研究细节：一是"就地评估"（in-situ）—— 声音敏感不是实验室里能复现的体验，必须在真实场景中测；二是研究诚实报告了一个负面发现：不同声源之间的衰减效果并不均匀。这种对方法局限性的主动披露，正是用户研究报告中常被省略、但最能建立可信度的部分。
📎 来源：arXiv (cs.SD) — Sona: Personalized Soundscape Mediation to Support People with Sound Sensitivity

🍃 「主动但不打扰」的一个正面样本：豆包定时任务

Berryxia.AI 分享了一个对"主动触达"设计有直接参考价值的观察：给豆包设定定时任务后，它每天按需推送任务结果，并且手机端也能看到提醒 —— 评价是"比很多工具要做的交互友好很多"。这与 Muse 复盘中的第一组矛盾（要主动，但不能变成又一个不停推送通知的应用）形成呼应：主动性的关键不在于是否推送，而在于推送是否承载了用户真正关心的结果，即"提醒你"与"替你办"之间的差异。

🖥 「不关机的云电脑」成为 Personal Agent 的体验底座

Today AI 于 9 月 24 日 18:00 在国内首发上线，创始团队在小宇宙《乱翻书》中拆解了产品思路：核心由三部分组成，其中云电脑被强调为"不关机"——以前的虚拟机问题是会关机，而 Personal AI 需要你的东西一直在这台电脑上；连接器解决"能不能一键拿到你在其他渠道的上下文"；第三是主动性与情境理解。这与 Muse 的思路一致：用户完全不需要感知到云电脑的存在。对体验设计而言，"不可见的基础设施"再次成为关键 —— 用户感知不到它，但对它的稳定性极度敏感。
