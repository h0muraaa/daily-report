本期摘要

本期最清晰的一条主线是强化学习后训练的重心从「算法」下移到「基础设施 + 数据策略」。DeepSeek 公开了 Agent 训练沙箱系统 DSec（梁文锋在作者名单内）：单个生产部署单元约 160 台 CPU 节点、3 万核心、250 TB 内存，典型一天处理约 300 万个沙盒，高峰约 38 万个同时在线，创建速率超过每秒 5000 个，并按任务隔离强度提供 FnCall / 容器 / microVM / 完整虚拟机四类后端。与之呼应，北大 DCAI 联合 UCAS 等发布 DataFlex-RL，把「选哪些 rollout、给多大学习权重、下批从哪些领域采样」做成同一套 RLVR/GRPO 流程中的可配置组件，登上 HuggingFace Paper 榜第二。同期一篇对 OpenAI 后训练 RL 算法 Score Centering 的解读则指出，该技巧可理解为一个直通估计器（STE）近似，而这类做法在 Sim-to-Real 的 RL 设定中早已常见。

评测方法论是第二个密集交汇点。Google 的工作研究「Agent Harness 能否被蒸馏」：以 Harness-Zero 让学生模型脱离专用 harness 后，宏观任务成功率从 23.3% 提升到 44.3%，高于基座模型挂载 harness 时的 41.7%，在知识工作、工具使用与科学三类任务的 28 种 harness 诱导行为上平均恢复 82.3%。一篇面向生产环境的论文则给出低成本回归评测方案：用 200 道题（占全量基准 38.5%）即可在 1.03 分误差内复现完整分数，难度分层固定子集可跨五个 Agent 家族迁移且无需重校准。Meta AI 则针对长上下文「context rot」，用专职记忆智能体把 Claude Sonnet 4.5 的成绩从 37.6% 提升到 45.9%。

跨学科方向，Anthropic 自建分子生物学实验室的首个成果被多家信源转述：约 950 个 Claude 智能体运行 21 小时、消耗 2.1 亿 token，从 20 余万个逆转录酶中筛出 3500 个候选、最终锁定 20 个目标，并在噬菌体 DNA 中发现带 CRISPR 样串联重复阵列的未知酶系统 ART；CRISPR 先驱张锋对预印本公开评价其为 AI Agent 推动生物学发现的案例。此外，Boltzbit 与剑桥大学的合作提出「把知识写进权重而非塞进 Prompt」的路线，用轻量超网络在潜空间中动态生成 LoRA 形式的临时权重。音频方向（cs.SD 30 条、eess.AS 28 条、cs.MM 7 条，合计 65 条）仍是当日 arXiv 密度最高的板块，端侧小模型（Mizar 159M）与递归自我改进（EvoAudio）两条路线同日出现。

R-01Anthropic 实验室首个成果：950 个智能体自主发现带 CRISPR 样重复阵列的未知酶系统 ART

Anthropic · 跨学科（AI × 分子生物学）· 21 小时 / 2.1 亿 token

Anthropic 在其自建的分子生物学实验室中完成了首个公开成果：让 Claude 在噬菌体 DNA 中识别出一类此前无人报道的酶系统，命名为 ART（Array-associated Reverse Transcriptase，阵列关联逆转录酶）。发现过程的自动化程度很高——人类科学家仅给出一个宏观提示（在海量 DNA 数据库中寻找有价值的逆转录酶），其后全部筛选与比较由约 950 个 Claude 智能体协同完成，连续运行约 21 小时、消耗约 2.1 亿 token，从 20 余万个逆转录酶中筛出约 3500 个候选系统，再收敛到 20 个最具价值目标并生成人类可读的分析报告。

关键的「发现时刻」发生在一个智能体逐段阅读巨型噬菌体原始序列时：它注意到某段 DNA 旁存在一组排列整齐的串联重复阵列，在记录中写下这看起来像 CRISPR 样结构，随后按标准科研流程推进——统计重复单元的间距与拷贝数、比对已知逆转录酶系统结构、检索文献确认是否为首次报道，最后提交假说报告。ART 由三部分组成：一个逆转录酶、一个功能未知的伴生基因，以及一段等间距排列的非编码重复序列。Anthropic 承认该系统的具体功能尚不明确，但指出同时具备这几项特征的已知系统仅寥寥数个，且全部可对 DNA 执行剪切、复制与粘贴；实验已证实 ART 的重复阵列会被转录成一组各不相同的短 RNA，暗示可能存在类似 CRISPR 的可编程机制。

学术意义 该工作的可检验价值不在于「AI 做出发现」的叙事，而在于人机分工的切分点：假设生成与候选排序被自动化，假说审核与全部湿实验验证仍由人类完成。阅读原文时值得核查三点——候选排序是否可复现、假阳性率如何度量、以及功能主张的支撑强度（序列相似性推断 vs 湿实验证据）。张锋对预印本的公开评价可作为领域认可度的参考，但不能替代对证据链本身的判断。

R-02DeepSeek 公开 Agent 训练沙箱 DSec：单日 300 万沙盒、峰值 38 万并发的强化学习底座

DeepSeek（梁文锋署名）· Agent RL 基础设施 · 31 页技术论文

DeepSeek 公开的不是新模型，而是一套面向 Agent 强化学习与评测的生产级沙箱基础设施 DSec（DeepSeek Elastic Compute）。要解决的问题很具体：训练 Agent 时不能只让模型在文本里回答「下一步做什么」，必须给它大量真实环境去改代码、装依赖、跑测试，再用执行结果判断对错。DSec 负责大规模创建这些环境、隔离任务，并保留每个 Agent 已修改的文件与运行状态，使训练任务暂停后可继续。

论文给出的规模数字值得记录：单个生产部署单元约 160 台 CPU 节点、3 万核心、250 TB 内存；典型一天处理约 300 万个沙盒，高峰约 38 万个同时在线，创建速率超过 每秒 5000 个，单个训练任务可能突然申请多达 3.2 万个环境。环境并非同一种容器换名：短小无状态的代码执行走 FnCall，改仓库/装依赖用容器，需要强隔离的安全任务用 microVM，Android 与图形界面任务用完整虚拟机；上层给训练框架统一操作接口，底层按隔离需求选择后端。调度侧，放置引擎从随机抽样节点中选负载较低者，并把「刚分配、尚未反映在集群定期快照中」的请求先计入，再由节点做最后资源压力检查，从而兼顾突发处理与负载视图的时效性。

方法学定位 这项工作把 Agent RL 的瓶颈从算法侧移到系统工程侧，也顺带指出了评测效度的前置条件——沙箱既要防止模型作弊，又要能精准复现每一步环境反馈。对做 Agent RL 复现的研究者，其四类执行后端的隔离边界与「暂停可续」的状态一致性机制，比峰值吞吐更值得核查。

R-03北大 DataFlex-RL：把强化学习的数据策略做成可插拔组件，登 HuggingFace Paper 榜第二

北大 DCAI × UCAS × 上海算法创新研究院 × 中关村学院 · RLVR/GRPO 数据策略

论文切入的问题是 RLVR（可验证奖励强化学习）中一个日益重要但难以比较的环节：每一轮训练该把哪些数据交给模型。题目初期很难、训练一段时间后可稳定答对，因此「保留哪些样本、如何调整学习权重与领域配比」需要结合模型当前训练状态动态决定。现有困难是双重的——不同数据策略各有实现，换个筛选规则就要改训练器；而比较效果时模型、奖励函数与训练预算往往不一致，即便分数提高也难以归因。

DataFlex-RL 复用 verl 的训练流程，把三类动作做成可配置组件：(1) 选择哪些 rollout 参与当前更新；(2) 给样本或 token 分配多大学习权重；(3) 决定下一批数据从哪些领域采样。这些策略直接复用 RL 循环已产生的奖励、优势、token 概率与 prompt 分组等信号，rollout、验证与策略更新代码基本保持不变。其直接价值是「少花时间改训练器，多留精力验证数据策略是否有效」——把数据策略变成可在同一 RLVR/GRPO 流程中对照实验的对象。

可复用性 该框架的价值在于把「数据课程 / 样本重加权」从工程技巧提升为受控变量。研究者可直接在其上做消融：固定模型、奖励与预算，只改数据策略，从而把此前混在一起的因素分离。需核查的是复用现有 RL 信号（优势、token 概率）作为选择依据是否引入与优化目标的循环依赖。

R-04OpenAI 后训练 RL 算法被解读为 STE 近似：Score Centering 的方法学辨析

arXiv（经「大模型智能」/青稞AI 解读）· 大模型 RL 后训练 · 训练/推理引擎分歧

一篇对 arXiv 预印本 Score Centering Stabilizes Off-Policy Reinforcement Learning 的技术解读引发关注，原因是该文被认为是 OpenAI 的后训练 RL 算法。解读的核心观点是：所谓 score centering 本质上是一个直通估计器（Straight-Through Estimator, STE）的近似实现，而这类技巧在此前涉及 Sim-to-Real 的 RL 设定中已相当常见。

解读同时把大模型 RL 与传统小模型 RL 的关键差异形式化：训练端（Megatron）与推理端（vLLM）是两套引擎，同样输入的前向 logits 存在差异，因此优化目标应被明确为最大化 vLLM 部署引擎上的推理效果，而非 Megatron 上的。从信息几何/逆强化学习式的视角出发，模型在 vLLM 上 rollout 得到轨迹与分数，进而给出最优分布，训练目标即缩小当前策略与该最优分布的 KL 距离。

阅读建议 这是一条「方法论溯源」型线索，价值在于把新算法与已有工具库建立联系，而非提出新方法。若要在自己工作中使用，应先核对原文对 STE 近似的偏差项与稳定性条件的形式化陈述，而非仅凭二手解读；同时注意训练/推理引擎 logits 不一致这一前提，对任何宣称「在 vLLM 上等价可复现」的结果都需独立验证。

R-05Boltzbit × 剑桥：把知识写进权重而非塞进 Prompt——用超网络在潜空间动态生成 LoRA

Boltzbit × 剑桥大学 · 持续学习 / 参数高效适配 · 「无限参数」路线

该工作针对当前 LLM 的一个结构性限制：训练完成后权重冻结，用户提供的最新事实、纠错或长文档只能塞进上下文窗口，每次对话都要从头重读，显存与算力开销高且会话结束即遗忘。作者提出的替代方案是不保存一组固定的专家参数，而是用轻量超网络（Hypernetwork）把实时交互数据动态编译成低秩（LoRA 形式）权重，并用一套贝叶斯机制让这套权重在对话过程中随上下文演化，作者称之为「无限参数」。

与 MoE 的对比被明确给出：传统 MoE 在固定的 64 或 128 个专家库中做离散路由，无论怎样组合都落在一个有限凸包内；而该方案不存固定专家，而是依据输入数据在连续潜空间中按需生成专属专家，因输入与潜空间连续无限，生成的权重也相应无界。直观理解即「不再把资料贴在眼前（Prompt），而是临时写进脑子（权重）」。

研究背景与开放问题 这条路线处在「上下文学习」与「在线权重更新」的交叉处，核心待验证之处是：动态生成的 LoRA 是否会在多轮交互中造成灾难性遗忘或漂移，以及推理延迟相对长上下文方案的实际增益。目前信源为社交媒体解读，尚无公开实验数据；建议以原始论文的实验设置（基准、对照方法与遗忘度量）为准。

R-06Google：Agent Harness 可被蒸馏——脱离专用 harness 后成功率反升至 44.3%

Google 及合作者（经 @omarsar0 导读）· Agent Harness 蒸馏 · 28 种诱导行为

论文研究的是「Agent 的 harness（提示、控制流、工具、记忆的编排逻辑）能否被蒸馏进模型本身」。其核心实验设定是 Harness-Zero：优化后的 harness 只在训练阶段使用。由于优化 harness 与部署 harness 的动作空间不同，作者引入一个由优化 harness 引导的「harnessing agent」，在部署动作空间中先修正学生模型的响应再执行，修正后的轨迹成为训练示范。

结果具有反直觉性：移除专用 harness 后，宏观任务成功率从 23.3% 上升到 44.3%，这一数字甚至高于基座模型挂载该 harness 时的 41.7%。在知识工作、工具使用与科学三类任务上的 28 种 harness 诱导行为中，平均 82.3% 被恢复；对使用同一演化 harness 的前沿模型，「agent-as-harness」形式同样有效。

方法学定位 这直接挑战了「harness 是能力的必要外挂」这一默认假设，把 harness 重新定位为可被吸收进权重的训练信号。关键待核查点是「harnessing agent」本身的贡献如何与数据放大效应分离，以及 82.3% 的行为恢复率是否在分布外任务上保持——这与本期 R-01/R-02 强调的评测效度问题同源。

R-07生产 Agent 的低成本重评测：200 道题（38.5%）在 1.03 分内复现完整基准分数

arXiv（经 @omarsar0 导读）· 生产评测 / 项目反应理论 · 574 次历史基准运行

该工作研究一个在工业界普遍存在但在方法上少被系统处理的问题：如何用远低于全量基准的成本，持续重评测一个在生产中服务的 Agent。研究对象是一个月活数万的分析类 Agent，作者使用 574 次历史基准运行，按日期切分为校准期与留出期，以保证评测的时序效度。

方法上比较了四种方案：随机采样、缓存结果、固定代表性子集，以及基于项目反应理论（IRT）的自适应测试。多维 2PL 自适应测试给出最高保真度，但团队最终部署的是难度分层固定子集，理由是更易运行：该类子集可用 200 道题（占全量 38.5%）在 1.03 分误差内复现完整分数，且能迁移到另外五个 Agent 家族而无需重校准，在短至一天的校准窗口下仍保持稳定。

可复用性 这是「评测也要讲究成本-效度权衡」的具体范式：方法（IRT 自适应）与部署选择（固定子集）的分离本身值得借鉴——最高保真的方案未必是可运维的方案。跨五个 Agent 家族的迁移性与一天校准窗口的结论，对需要高频回归的生产系统最具参考价值；阅读时应核查「迁移」是否指同一任务分布上的模型替换。

R-08Meta AI：用专职记忆智能体修复长上下文「context rot」，Sonnet 4.5 成绩 37.6% → 45.9%

Meta AI（经 DeepLearning.AI 转述）· Agent 记忆 / 长上下文 · 基准提升 8.3 分

该工作针对的是长上下文 Agent 的一类系统性失败：上下文过长时智能体会遗忘早期出现的错误，从而在后续步骤中重复同类失误（被概括为 context rot）。其方法是给主行动智能体配备专职的记忆智能体：记忆智能体对工具使用与过往错误维护结构化笔记，并只在关键时刻注入简短提醒，而非把全部历史持续压在上下文里。

效果以基准分数给出：该组合把 Claude Sonnet 4.5 的成绩从 37.6% 提升到 45.9%，提升 8.3 分。这一结果的关注点在于——提升并非来自更换更强的基座模型，而是来自改变 Agent 的记忆组织与注入时机这一外部结构。

学术意义 与本期 R-06（harness 可被蒸馏）形成有趣对照：两者都在处理「外部编排结构 vs 模型内在能力」的关系，但方向相反——R-06 尝试把 harness 吸收进权重，本项则证明合理的记忆结构在当下仍能带来可观增益。研究者可关注记忆智能体的笔记表示与「关键时刻」判定规则是否为学习得到，这决定该方法能否迁移到不同任务域。

D-01 · EvoAudio: Recursive Self-Improvement for Audio Understanding（arXiv:2609.27389）

音频语言模型 · 递归自我改进 · 可验证监督 · 当日 cs.SD 新品

研究背景

论文的出发点是音频语言模型（ALM）的一个能力失衡：模型对「说了什么」的理解远好于对「听起来怎样」的理解。作者认为弥合这一差距不只是数据量的问题，并明确列出三条既有路径的结构性障碍：(1) 精细声学标注成本高昂；(2) 用更强模型生成的标签会继承其错误与能力上限；(3) 固定数据集无法随学习者的进步而调整难度。

核心创新

EvoAudio 提出一个递归自我改进（recursive self-improvement）系统，作者称其为首个在单一闭环内同时演化模型、波形、问题与难度的方法。两个设计要点最关键：

  • 以当前模型的表现决定下一轮训练数据的方向与难度——即训练数据的焦点与难度由学习者的实时能力设定，从而在模型进步时自动提高要求。
  • 用「音频是如何被制造的」产生可验证监督——由一个音频工具库构造问题，其答案可以从音频的生成过程推导出来。这样无需新增人工标注即可获得可验证标签，绕开了前文列出的第 (1)(2) 条障碍。

关键设计问题

方法的核心承诺是「难度自适应 + 监督可验证」，但两者都可能被质疑：若问题由固定工具库构造，问题空间的多样性与上限由工具库决定，递归演化的收益是否会被工具库的表达能力封顶？此外，「答案可由制造过程推导」意味着监督信号与该生成过程强绑定，需核查这种监督是否偏向合成音频而非真实录音。论文摘要指出这些是相对既有评测框架（多聚焦音文跨模态对齐）留下的空白。

学术意义

该工作把音频理解的自改进问题转化为「可验证数据构造」问题，与本期 R-03（RL 数据策略）、R-06（harness 蒸馏）共享同一条方法论主线：把能力的提升从模型内部转移到数据与训练回路的设计上。「模型-波形-问题-难度」四元闭环的提法本身是可迁移的框架，值得作为自改进类研究的对照基线。

D-02 · MiMo-V3「HySparse2」：两级 KV 共享的混合稀疏注意力（arXiv:2609.26368）

小米 MiMo 团队 · 长上下文注意力架构 · 80B-A3B MoE · 1M tokens

研究背景

长上下文的注意力设计长期面对一个三方权衡：prefill 计算量、KV cache 大小与长程检索精度三者通常互相牵制——降低计算与缓存往往以牺牲检索能力为代价。HySparse2 的目标是在 80B-A3B 的 MoE 模型上同时改善这三项，而非做取舍。

核心创新

机制可分解为「两级 KV 共享」与两处粒度调整：

  • 外层 KV Bridging（借鉴 YOCO）：模型分为 self-decoder（前 25 层，混合 SWA）与 cross-decoder（后 24 层，混合稀疏注意力）；cross-decoder 中全注意力层的 K/V 不再从词嵌入独立投影，而由 self-decoder 全注意力层的隐状态投影得到，使 KV 只「物化」一次，而非每层各存一份。
  • 内层 KV Reuse：cross-decoder 的每个 hybrid 块内，稀疏注意力层直接复用前邻全注意力层的 KV cache 与 top-k 选择索引。由于全注意力层本就要计算全部 attention score，top-k 选择是其免费副产品，稀疏层复用后同时省去 KV 存储与一次独立的稀疏选择计算。
  • token 级选择取代块级选择：粒度从 HySparse 的 64-token 细化为单 token（1024 个全局 token）。消融显示这对检索类任务收益显著：RULER-v2 +6.6、MRCR-v2 +8.1、GraphWalks +5.5。
  • 强制近期窗口取代独立 SWA 分支：稀疏层不再单独维护一条 SWA 路径。

实验结果

在 80B-A3B MoE 模型、1M token 上下文下：prefill FLOPs 降至上一代 Hybrid SWA 的 1/5，KV cache 为其 1/4.5，而长程检索基准（RULER-v2、MRCR-v2）反而大幅领先。即效率与检索精度同向改善，打破了前述三方权衡。

学术意义

该工作的可复用洞见是「复用全注意力层的中间产物」这一设计原则：将 top-k 选择视为全注意力计算的副产品并向下游稀疏层共享，避免了独立稀疏选择带来的额外开销与信息损失。对做长上下文架构的研究者，token 级 vs 块级选择的消融（检索任务 +6.6/+8.1）是可直接引用的经验证据；同时需核查 1M 长度下的结果是否伴随训练长度外推，以及 KV Bridging 对表示能力的影响是否有独立评估。

04

趋势观察

4 trends

T-01 · 强化学习后训练的竞争焦点，正从「算法创新」下移到「基础设施 + 数据策略」

本期三份独立工作指向同一方向：DeepSeek 用 31 页论文描述的不是新模型而是沙箱底座 DSec，北大 DataFlex-RL 把数据选择/重加权/配比做成可插拔组件，而 OpenAI 后训练算法的解读最终收敛到「训练引擎与推理引擎 logits 不一致」这一工程事实。三者共同的潜台词是：在 RLVR/GRPO 范式基本稳定的当下，边际收益更多来自环境规模、状态一致性与数据课程设计，而非新的损失函数。

对研究者的含义是评测设计的改变：报告一项 RL 结果时，环境基础设施的规模与隔离方式、数据策略的相对贡献，都应作为可核查的变量列出，否则「分数提升」难以归因。

T-02 · Agent 评测正从「聚合分数」转向「分布外泛化 + 低成本持续评测」

本期多处证据支持这一转向：Google 的 harness 蒸馏拆解了「能力来自模型还是编排逻辑」，生产 Agent 重评测工作把基准成本压到 38.5% 而要求时序效度，Meta AI 的记忆智能体则以外部结构带来 8.3 分提升。共同点是对「分数从何而来」的追问压过了「分数有多高」。

这也解释了为何本期多个基准（TACT、OmniEchoBench、MLC-SLM）都把「真实分布覆盖」写在方法叙述里——基准的可信度取决于其覆盖的分布与分布外条件，而非单一聚合指标的绝对值。

T-03 · AI for Science 正从「辅助分析」进入「假设生成」阶段，但验证仍完全在人手里

Anthropic 的 ART 发现是本期最强信号：约 950 个智能体并行完成候选筛选与异常模式识别，人类只提供宏观方向与最终审核，湿实验全部由科学家执行。这把人机分工的边界明确地画在「假设生成可自动化、假设验证不可自动化」上。

评估这类工作时，应把「AI 提出了候选」与「候选被实验证实」严格区分。目前 ART 的功能仍属未知，序列层面的结构性相似只是假说来源；领域认可（如张锋的公开评价）可作为信号，但不能替代证据链审查。

T-04 · 音频/语音仍是 arXiv 当日最密板块，端侧小模型与自改进两条路线并行推进

当日 arXiv 音频方向合计 65 条（cs.SD 30、eess.AS 28、cs.MM 7），是收录中密度最高的板块。两条路线同日出现：向下做端侧——Mizar 以 159M 参数（CED-Small + SmolLM2-135M）追求低内存推理；向内做自改进——EvoAudio 用递归闭环同时演化模型、波形、问题与难度。评测侧则同步成熟：TACT 用意图条件化连续评分替代二值轮次判定，OmniEchoBench 把空间音频理解引入具身设定。

值得注意的还有开源模型的「细分下沉」：中国团队在 HuggingFace 的自动语音识别与翻译两个趋势榜登顶，说明开源竞争已从通用大模型铺到语音、翻译等专项能力上。
