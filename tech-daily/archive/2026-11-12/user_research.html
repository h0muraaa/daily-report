UXR 岗位在收缩，但研究能力正在向设计与传统行业外溢

Lenny Rachitsky 统计美国科技岗位：设计岗位同比下降 28%，用户研究岗位下降 45%，而 PM、工程、设计整体只增长 2%。但在 2024–25 年换工作的 2,779 名美国用户研究员中，49% 仍选择研究岗，17% 转入设计，9% 离开该领域，约 2% 成为 PM；转岗者中近一半去了非科技公司，银行、金融与保险合计约每 7 人中有 1 人。这说明研究能力并未失效，而是在更换容器——研究者需要把「洞察如何影响决策」讲得比「研究了什么」更清楚。

来源：Lenny Rachitsky · 数据整理：Orange AI
02

设计系统正在变成 AI 的「上下文接口」，而不只是组件仓库

Meta 的设计系统 Astryx 已上架 v0：选择某个设计系统后，v0 会带着它的组件、模式与模板上下文来生成界面。Vercel CEO Guillermo Rauch 进一步提出，UI SDK 像 Agent 构建界面时的 x86 指令集，把可访问性、性能与一致性打包成行为，既节省 token 与返工，又不限制界面的可能性。对设计团队而言，真正的交付物正在从「组件库」升级为「模型可读取的约束与语义」。

来源：v0 · 来源：Guillermo Rauch
03

当「什么都能做」时，「不做什么」成为产品与设计的核心能力

Cisco 总裁兼首席产品官 Jeetu Patel 的判断很直接：在可以编码任何东西的世界里，选择不构建什么，远比构建什么重要。他坦言当下充斥着大量 AI slop，呼吁产品人贡献「提炼与清晰」，而不是继续增加噪音。决定不做什么依赖判断力、品味、直觉，以及对市场与客户的切身理解——这恰好是用户研究最该提供、却常被要求去「验证已有方案」的部分。

来源：Product School

Personal Agent 的北极星指标，可能从 DAU 转向「托管事务量」

蚂蚁灵光 2.0 公布上线半个月数据：托管 300 万项事务、执行 1,100 万次任务（上线一周时为 116 万与 360 万）。「赛博禅心」据此讨论 Personal Agent 的北极星指标：门户时代看 PV、移动社交看 DAU、视频看总时长，而 Agent 时代或许应看用户愿意托付多少事务。这个视角把体验重心从「打开频次」推向「信任、可恢复性与结果可靠性」。

来源：赛博禅心

人类注意力，正在成为 Agent 体验设计里最昂贵的材料

Expo 推出 Expo Simulators：编码 Agent 可以在云端 iOS 模拟器上运行改动，先带回截图与录屏，再请求人类 review；团队里任何人也能通过链接打开构建、亲自点一遍。开发者 elvis 的评论点中要害——在 agentic coding 中，人类注意力是最稀缺的资源。好的 Agent UX，应该把「请求注意」当作一次昂贵事件来设计：先自证，再打扰。

来源：elvis

设计趋势洞察

两条正在改变设计工作方式的主线

从「组件复用」到「约束复用」：设计系统进入 Agent 工作流

今天的两条消息拼在一起看，指向同一个变化。其一是 Astryx 进入 v0：设计系统不再只是设计师在 Figma 里翻阅的组件库，而是生成工具可以直接调用的上下文，模型会依照它的组件、模式与模板产出界面。其二是 Figma 的 3D Transforms 开放 beta：支持 x、y、z 三轴旋转、透视与深度，既可由 Figma agent 协助构建与制作动画，也能通过 Figma MCP 交给编码 Agent 实现。设计工具与生成工具之间，正在形成一条双向的「约束通道」。

Rauch 对 UI SDK 的描述补上了理论部分：把可访问性、性能与一致性打包成「已封装的行为」，就像给 Agent 一套稳定的指令集。这解决的是生成式界面最大的隐忧——每次都能生成，但每次都不太一样，且难以保证无障碍与交互状态完整。设计系统的下一层价值，是让模型在正确约束内自由发挥，而不是让设计师反复修补模型的自作主张。

对用户研究者的实际含义是：需要把过去隐含在设计规范里的东西显性化、机器可读化——语义 token、焦点顺序、错误与空状态、动效节奏、无障碍规则、品牌语气。未来的设计评审，可能一半在评审人看到的界面，一半在评审模型读到的约束。

实践建议：为设计系统补一份「Agent 可读说明」，明确哪些模式可被组合、哪些状态必须出现、哪些无障碍行为不可省略；把「生成结果的约束覆盖率」纳入设计验收。
来源：v0 · 来源：Figma · 来源：Guillermo Rauch

工具的作者变成创作者：专业工作流正在反向定义 AI 产品

Google Flow 发布的五个新工具，全部由电影人和视觉艺术家参与设计：Character Poster 帮助创作者把故事概念变成海报级画面，并在信息流中保持可识别的风格；Character Arc 让同一角色跨越不同年龄与人生阶段仍保持辨识度；Pixel Machine 提供位图、ASCII、CRT、像素艺术与故障质感；Lucid Glass 模拟棱镜、光晕、折射与泛光，像一枚「不存在的镜头」；Pocket Studio 则把一段手机素材变成多机位、更高画质的成片，同时保留原始表演。

这组工具的共同点不是「生成得更漂亮」，而是解决创作者真正卡住的地方：角色连续性、风格一致性、镜头语言与后期质感。它们把控制点留在创作流程内部，而不是把一切压缩成一次性的 prompt。与此同时，Figma 的 3D Transforms 也把 3D 从独立工具拉进常规界面设计流程，并允许设计 Agent 与编码 Agent 接力完成。工具正在从「给所有人一个万能输入框」，走向「由专业用户定义可控的专业路径」。

实践建议：做 AI 创作类产品时，先画清楚「创作者在哪些节点必须保留控制权」，再决定哪些环节自动化；一致性、可回退与可解释，往往比单次生成质量更能决定留存。
来源：The Keyword · 来源：Figma

Claude Meetings：把 AI 设计成「参会者」，而不是侧边栏

Anthropic 推出 Claude Meetings 测试版：Claude 以参会者身份出现在 Google Meet 画面里，一边听讨论，一边写纪要、回答问题，还能当场起草文档、画白板，同事可以跟着一起改。提问可以说「Claude」后直接开口，也可以在会议聊天框里打字；它默认用文字回答，答案贴在会议聊天区，所有参会者都能看到。会中若需要查询公司系统里的历史数据，它会先征得同意再执行。

体验设计上最值得学的是「成果物绑定心智对象」：会后纪要（摘要加待办）、完整转录、会上创建的文档与白板，都归集到 claude.ai 中这场会议的专属页面，并给参会同事发送带链接的回顾邮件；之后还能在普通对话里追问某场会说了什么。这比把笔记散落在聊天记录或独立文档里更符合人对「一次会议」的心智模型。回答公开贴在会议聊天区、查询前先征求同意，也在降低「AI 在黑箱里做了什么」的不安。

待观察：目前仅支持 Google Meet，其他平台称「即将支持」；仅面向 Team 与 Enterprise 套餐，个人 Pro / Max / Ultra 暂不可用。会议中的注意力分配、以及多人同时指挥 Claude 时的冲突处理，会是下一阶段的关键体验问题。
来源：Claude · 来源：宝玉
隐私设计 无障碍 旁观者体验

Google 智能眼镜：把「镜头两侧的人」都当成用户

Google 公布的智能眼镜隐私设计，核心原则是同时保护佩戴者与旁观者，并称方案来自对佩戴者、旁观者与隐私专家的研究。具体设计包括：Gemini 处理图像前自动遮挡旁观者面部；定向麦克风默认聚焦佩戴者本人的声音；相机画面不存入 Gemini 历史，也不用于训练模型或定向广告；每个应用首次调用相机都需授权，且可随时撤销；每副眼镜都有物理关机开关，关掉后就是普通眼镜。

更具示范意义的是「可感知的同意」：拍摄时外置指示灯会亮起；如果指示灯被遮挡或篡改，传感器会阻止拍摄；激活前的设置流程要求用户承诺不未经允许拍摄他人、不在敏感场所拍摄、不遮挡指示灯。Google 还从生态侧封堵规避行为——购物与广告禁止销售遮挡或隐藏指示灯的产品，Google Play 禁止社交直播、实时人脸识别与修改指示灯行为。无障碍方面，Gemini 可帮助翻译标牌、朗读菜单、辅助导航，Guided Vision 能为盲人或低视力用户提供音频描述，同时明确它并非医疗设备、临床视力辅助或移动辅助，不用于安全关键任务。

体验启示：把旁观者纳入用户旅程，而不是只服务购买者；把同意做成物理上可感知的信号，而不是埋在设置里的条款；无障碍不是附加项，而是这类可穿戴设备最自然的核心场景之一。
来源：The Keyword

从「看输出」到「看使用过程」的评估转向
评估方法 行为轨迹

Interaction-as-a-Judge：让 Agent 真的去用，再判断好不好用

Arena 开源了两个数据集：ArenaWebdevPreferences（6,390 组应用对，带人类偏好标签）与 ArenaWebdevCorrectness（189 个游戏版本、362 条人工核验的需求）。其提出的 Interaction-as-a-Judge 范式，让 computer-use agent 直接操作游戏与应用，产生交互轨迹，再由 LLM judge 或训练好的奖励模型评估。偏好评估来自真实的 Code Arena 对战，正确性需求则从 Agent Arena 中真实用户投诉里挖掘。

效果数据很能说明问题：仅用交互奖励微调 Qwen-3.5-9B，胜率提升 6.7 个百分点（约 +50 Arena 分）；相比仅用代码奖励，应用成功率从 81.3% 提升到 88.5%，代码膨胀减少 35.7%。对用户研究的启发是，评估证据可以从「用户怎么说」扩展到「用户/Agent 实际怎么走」——交互轨迹、卡点、回退与错误恢复，都是比满意度评分更接近真实体验的材料。

来源：Arena.ai · 数据集公告 · 实验结果
Agent UX Eval 设计

Vercel 的 Agent Eval 框架：Agent 也是软件的用户

Vercel 的文章把 Agent 视为软件的新用户，并借用了人类用户的漏斗：Discovery（发现）、Selection（选择）、Access（接入）、Success（成功）。文章重点讨论最后一环——Agent 是否真的完成了用户的任务。难点在于「成功」很会伪装：用户要冰拿铁，Agent 却下了热拿铁，请求成功、日志正常，但体验已经失败；再加上 LLM 输出本身有波动，单看接口成功率会严重高估体验质量。

这套框架可以直接迁移到用户研究：为漏斗的每个阶段定义可观察的行为指标，而不是只测最终转化；把「任务语义是否正确」与「请求是否成功」分开评估；用一组真实任务而非单条 happy path 来覆盖波动。对做 Agent 产品的团队来说，这相当于把可用性测试从「人点界面」扩展到「人委托 Agent 办事」。

来源：Vercel News

还早，但值得放进观察列表的信号

Personal Agent 开始追求「活人感」

用户「小互」描述了一类 360 度、全功能的 Personal Agent：可以边干边聊、实时对话，需要其他角色配合时直接安排；人不在电脑前也能用手机继续，任务完成后还会主动打电话通知。他的判断是，方向在于「把 AI 当具体的人而不是工具」，目前还不完美，但体感已经接近。这类主动通知、跨设备接力与实时协作，会重新定义「中断」与「在场」的设计。

来源：小互

浏览器侧边栏成为常驻 AI 界面

Gemini 进入 Chrome 侧边栏，可在任意网页上总结文章、比较产品、解释复杂主题。它把 AI 从独立应用变成浏览上下文的一部分，用户的提问天然带着当前页面。对 UX 的挑战是：如何在不抢夺页面注意力的情况下，让辅助信息随上下文出现、又能被随时忽略。

来源：The Keyword

语音正在成为应用的一等界面

DeepLearning.AI 与 VocalBridge 推出面向 AI Agent 与应用的语音课程，用「语音互动游戏」作为案例，直接抛出问题：如果人们可以直接和你的应用说话，你会做什么？语音界面需要全新的轮次管理、打断处理、错误恢复与反馈设计，不能简单把按钮换成麦克风。

来源：DeepLearning.AI

3D 变换进入常规界面设计流程

Figma 的 3D Transforms 已开放 beta，支持三轴旋转、透视与深度，并可由 Figma agent 协助构建动画、通过 Figma MCP 交给编码 Agent 实现。这意味着 3D 不再只属于独立建模工具，而会成为界面设计系统的一部分，也要求设计规范补充深度、光照与动效降级策略。

来源：Figma
