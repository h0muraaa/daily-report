Context-Bench：评估 AI Agent 的上下文工程能力

技术背景

由 Letta AI 团队开源发布的 Context-Bench 是一个专门评估模型"自主上下文工程"能力的基准测试。它解决了当前 LLM 评估中一个被忽视的关键问题：模型如何在多文件、多步骤场景下自主检索和管理信息。

核心设计原则

  • 防数据污染：所有实体名称和关系均为虚构，从 SQL 数据库生成问题并有验证过的标准答案
  • 多跳/多轮工具调用：问题设计需要多次工具调用和策略性信息检索，单次查询无法得出答案
  • 难度可控：通过调整 SQL 查询复杂度来提升难度，避免基准被快速"刷爆"

两大评测套件

Filesystem Suite：评估 Agent 链式调用文件操作、追踪实体关系的能力，赋予 open_files 和 grep_files 两个工具。

Skills Suite：评估 Agent 利用预定义技能（如 SQL 查询、API 调用）高效解决问题的能力。

实践意义

对于正在构建 RAG 系统或 Agent 的开发者，Context-Bench 提供了一个评估框架，帮助识别模型在以下维度的能力短板：

  • 构造有效搜索查询的能力
  • 链式文件操作追踪关系的能力
  • 正确选择工具（grep vs open）的策略判断
  • 高效导航层级数据的能力

迁移/使用建议

如果你正在评估不同模型用于 Agent 场景，建议将 Context-Bench 纳入测试流程。特别适用于需要处理大量文档、代码库或知识库的 Agent 应用。

ICLR 2026 | 一行代码解决 LLM 推理过度思考

技术背景

DeepSeek-R1 引发的 RLVR（基于可验证奖励的强化学习）热潮中，研究者发现模型存在"过度思考"现象：对简单问题生成冗长、重复的推理过程。UIUC 团队提出了一种利用模型内部信号作为反馈奖励的新方法。

核心洞察

过度思考的根源在于奖励信号的粗粒度——只要答案正确，推理过程的中间步骤不会被区分。模型通过延长推理过程来最大化正确率，成为一种"理性选择"。

解决方案

研究团队利用大语言模型内部的信号构成反馈奖励，刻画推理过程的"有用与否"而不仅仅是"长短"，实现推理准确度和效率的"双赢"。具体实现仅需一行代码级别的改动。

实践意义

对于部署推理模型的开发者，这意味着：

  • 降低推理成本（减少不必要的 token 消耗）
  • 提升响应速度（缩短端到端延迟）
  • 保持或提升准确率（避免为求快而牺牲质量）

Claude vs Codex：CLI Agent 的行为差异实测

测试场景

开发者进行了一项有趣的对比测试：让 Claude Code 运行 Codex CLI，同时让 Codex 运行 Claude CLI，观察两者在交叉控制场景下的行为差异。

测试结果

  • Claude Code：拒绝执行，并尽力劝说用户放弃这个想法
  • Codex：二话不说直接执行，并对 cc 的执行结果进行总结

技术解读

这一差异反映了两款工具在安全策略和自主决策上的不同取向：

  • Claude 更保守，倾向于避免潜在的递归或循环执行风险
  • Codex 更激进，优先完成用户指定的任务

选型建议

如果你需要：

  • 高安全性、保守执行 → 选择 Claude Code
  • 最大化自动化、批量处理 → 选择 Codex

    • 实际项目中，两者可以互补使用：Claude 负责架构设计和关键决策，Codex 负责大规模代码生成和重构。
