Compound Engineering：让Claude Code越用越聪明的4步法
来源: X@petergyang / Kieran Klaassen
核心框架：Plan → Work → Assess → Compound。Plan阶段用sub-agents研究代码库和最佳实践；Work阶段Claude主动澄清问题后编码+测试；Assess阶段用review agents检查安全、架构、代码质量；Compound阶段捕获学习点避免重复犯错。这是目前最系统的AI编程工作流。

Codex CLI vs Claude Code对比实测
来源: X@dongxi_nlp
实测发现：让Claude Code运行Codex CLI时，它会拒绝执行并尝试劝阻；而Codex则"二话不说就是干"。结果上，Codex直接执行并把cc的输出结果做了总结。这反映了两者的安全边界设计差异：Claude更保守，Codex更激进。根据场景选择合适的Agent工具。

Vercel的发现：AGENTS.md > Skills
来源: vercel.com/blog
Vercel在Next.js 16新API评测中发现：8KB的AGENTS.md文件达到100%通过率，而skills最佳仅79%。原因：agents.md持续加载在system prompt中，每轮都可见；skills需要异步加载，可能时机不对。大道至简，复杂skill系统可能不如简单的项目文档。

Skill构建完整指南：Anthropic官方33页文档
来源: X@shao__meng
Skill = 文件夹 + SKILL.md（Markdown+YAML frontmatter）。三层渐进式信息披露：第一层YAML（始终加载）、第二层SKILL.md（相关时加载）、第三层references（按需读取）。与MCP的关系：MCP是厨房，Skill是菜谱。写好第一层的description是关键触发器。

宝玉：提示词模板的使用建议
来源: X@dotey
针对"Build Any App"这类结构化提示词，建议：1)只在从零构建完整产品时使用；2)现代模型已学会分阶段构建等能力，无需过度"教学"。更好的方式是：一句话目标 + 必要背景 + 约束 + 期望输出格式。
